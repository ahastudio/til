# 낡은 지침 파일이 코드를 이긴다: 한 문장으로 막는 방법

원문: [古い指示ファイルがコーディングエージェントで既存コードより優先される：一文による改善 - AIDB](https://ai-data-base.com/timeline/read/141093)

트윗: [研究者らによると、CLAUDE.mdやAGENTS.mdにあらかじめ次の一文を足すことが推奨されます。](https://twitter.com/ai_database/status/2114184481951330365)

## 요약

일본 매체 AIDB는 2026-10-23에 arXiv 논문 한 편을 소개하는 글을 올렸고, Twitter
사용자 ai_database(AIDB)는 같은 내용을 2026-10-25에 트윗으로 다시 올렸다.
둘의 내용은 같다.
CLAUDE.md나 AGENTS.md의 기술이 현재 코드와 어긋나면 Claude Code와 Codex는 9할
가까이 낡은 기술을 따르고, 지침 파일에 한 문장을 미리 넣어 두면 이를 막을 수
있다는 것이다.

AIDB가 소개한 논문은 Xiaonan Xu와 Wenjing Wu의 “Stale Instruction Files Override
the Code in Coding Agents: A One-Sentence Fix”이며, 2026-10-22에 arXiv에
올라왔다.[^paper]
Xu는 조지아 공과대학교, Wu는 콜로라도 대학교 볼더 소속이다.[^paper]
AIDB 글은 “조지아 공대 등의 연구자”라고만 적었다.

실험은 지침 파일이 한 규칙을 요구하고 기존 코드가 다른 규칙을 쓰는 Python
프로젝트 40개로 이루어졌다.[^paper]
예를 들어 파일은 `print`를 쓰라고 하는데 코드는 `logging`을 쓴다.[^paper]
Claude Code와 Codex CLI에 각 프로젝트의 기능 추가를 시키고, 사용자 수준 지침
파일에 문장이 있을 때와 없을 때를 비교해 모두 320번 실행했다.[^paper]

AIDB가 인용한 숫자는 논문과 일치한다.
문장이 없으면 선택의 90.1%가 낡은 파일을 따랐고, Claude Code는 80번 중 79번
충돌을 알아차리고도 파일을 따랐다.[^paper]
Codex CLI는 80번 중 20번 기존 코드를 파일에 맞게 고쳐 썼고, 그중 17번은
프로젝트의 원래 테스트가 실패했다.[^paper]
문장을 넣으면 코드를 따르는 선택이 4.2%에서 91.4%로 늘고 테스트 통과율이
89.4%에서 100%가 되었다.[^paper]

AIDB가 권한 문장은 논문의 원문 그대로다.
“저장소의 문서와 기존 코드가 어긋나면 기존 코드의 관례를 따르고, 문서와 코드
사이에서 찾은 불일치를 최종 답변에서 모두 짚으라”는 뜻이다.[^paper]

## 분석

### 지침 파일이 이기는 이유는 입력의 신분이다

논문의 설명은 모델이 두 정보를 받는 경로가 다르다는 것이다.
Claude Code는 CLAUDE.md를 시스템 프롬프트 바로 뒤의 사용자 메시지에 넣고, Codex
CLI는 AGENTS.md를 프로젝트 경로가 붙은 사용자 메시지에 INSTRUCTIONS 태그로 감싸
넣는다.[^paper]
코드는 에이전트가 파일을 열 때 도구 호출의 출력으로만 모델에 들어간다.[^paper]
모델은 프롬프트 주입을 막으려고 지시를 도구 출력보다 우선하도록 훈련되어 있고,
같은 서열이 낡은 줄에도 적용된다고 논문은 본다.[^paper]

이 설명은 AIDB 글과 트윗이 짧게 줄인 부분이다.
트윗은 이를 지시로 전달되는 것과 결과로 전달되는 것의 차이라고 요약했다.
논문은 여기에 한 단계를 더한다.
지침 파일의 줄은 명령형으로 쓰여 있지만 실제로는 쓰인 시점의 코드를 기록한
것이고, 코드가 바뀌어도 명령형 어조는 그대로 남는다.[^paper]

### 한 문장이 문제를 푸는 이유도 같은 서열이다

논문은 처방도 같은 구조에서 끌어낸다.
사용자 수준 지침 파일에 넣은 문장도 지시로 전달되므로, 모델은 지시 둘 사이에서
고르게 된다.[^paper]
그 문장은 문서와 코드가 어긋나는 바로 그 경우를 다루므로 더 구체적인 지시가
이긴다는 논리다.[^paper]
빌드 명령 같은 프로젝트 파일의 다른 줄은 그대로 효력을 갖는다.[^paper]

이 처방의 장점은 낡은 줄을 먼저 찾을 필요가 없다는 것이다.
논문이 인용한 Denisov-Blanch 등의 연구에 따르면 회사 저장소 441곳에서 AI 설정
파일의 73.8%가 한 번 커밋된 뒤 수정되지 않았다.[^paper]
같은 방식으로 인용한 Treude와 Baltes의 연구에서는 공개 저장소 356곳 중 23.0%에서
일관성 검사기가 이미 없는 코드를 가리키는 줄을 찾아냈다.[^paper]
낡은 줄을 사람이 찾는 방식은 잘 되지 않고, 규칙을 하나 더 넣는 방식은 한 번이면
된다.

### 두 에이전트는 다른 방식으로 실패한다

Claude Code는 충돌을 알아차리는 에이전트다.
80번 중 79번 최종 답변에 충돌을 적었고, 그 실행들에서도 선택의 86.2%는 파일을
따랐다.[^paper]
답변 하나는 기존 파일들이 `logging` 등을 쓰며 CLAUDE.md와 어긋난다고 적으면서도
코드 쪽을 어긋난 것으로 취급했다.[^paper]

Codex CLI는 충돌을 거의 말하지 않는 에이전트다.
충돌을 말한 답변은 80번 중 2번이었고, 60번은 말없이 파일을 따랐고 나머지 20번은
기존 코드를 고쳐 썼다.[^paper]
고쳐 쓴 실행은 프로젝트 12개에 걸쳐 있었고, 실행당 중앙값으로 9개 파일에서
198줄을 지웠다.[^paper]
따라서 같은 90%라도 Claude Code의 문제는 판단이 지시에 눌리는 것이고, Codex
CLI의 문제는 낡은 줄이 코드를 부수는 것이다.

## 비평

### 낡은 쪽이 항상 지침 파일이라는 가정이 설계에 들어 있다

논문의 범위 절은 지침 파일이 낡은 쪽인 프로젝트만 다뤘다고 밝힌다.[^paper]
그런데 처방 문장은 기존 코드를 항상 우선하라고 말한다.
코드가 잘못된 쪽이고 파일이 옳은 경우, 예를 들어 팀이 로깅 방식을 `print`에서
`logging`으로 옮기기로 하고 파일부터 고쳤는데 코드가 아직 따라오지 못한 경우를
이 실험은 시험하지 않았다.
이 경우 문장은 파일의 옳은 지침을 막는다.

AIDB 글과 트윗은 이 조건을 전하지 않고 문장을 갱신에 게으른 사람이 미리 넣어 둘
것으로 소개한다.
문장이 모든 저장소에서 득이 되려면 파일이 코드보다 자주 낡는다는 전제가
필요하다.
이 전제는 논문이 인용한 통계가 뒷받침하지만, 팀이 의도적으로 파일을 앞서 고치는
경우의 손실은 측정되지 않았다.

### 숫자 하나가 일반화될 만큼 넓지 않다

실험은 Python 프로젝트 40개, 규칙 16종, 에이전트 둘, 실행당 한 번뿐인 무인 기능
추가로 한정된다.[^paper]
프로젝트는 연구자가 직접 만든 작은 프로젝트로 모듈이 세 개에서 여덟
개다.[^paper]
충돌도 연구자가 인위적으로 만들었다.
AIDB 글은 40개 프로젝트가 설정 파일과 코드가 일부러 어긋나게 만든 것이라고
밝혔지만, 요점에 적은 100%는 이 조건에서만 성립한다.

또한 두 에이전트는 각각 한 모델 버전(Claude Sonnet 5.5, GPT-6 Sol)으로만
돌렸다.[^paper]
다른 모델이나 더 큰 저장소에서 같은 수치가 나올지는 이 논문이 말해 주지 않는다.
논문이 지적하듯 낡은 파일은 큰 프로젝트에서도 나오지만, 큰 프로젝트에서
에이전트가 코드를 더 많이 읽으면 결과가 달라질 가능성도 열려 있다.

### 원인 설명은 검증된 인과가 아니라 일관된 해석이다

논문은 두 가지 예측을 세운다.
에이전트는 충돌을 알아도 파일을 따를 것이고, 문장은 결과를 뒤집을 것이다.
둘 다 맞았다.[^paper]
그러나 이 결과는 서열 가설과 일치할 뿐이고 경쟁 가설을 가르지 못한다.

경쟁 가설은 쉽게 떠오른다.
낡은 파일을 따르는 것은 지시를 우선하도록 훈련된 탓이 아니라, 파일이 에이전트의
작업 맥락 맨 앞에 있어서일 수 있다.
논문은 문장의 위치와 파일의 위치를 바꾼 대조 실험을 싣지 않았고, 논문의 비교는
문장 유무뿐이다.[^paper]
AIDB 글과 트윗은 이 설명을 연구자의 견해라고 밝혔다.
그러나 트윗은 지시가 낡은 줄 알아도 거스를 수 없는 구조라고 단정에 가깝게
적었다.

## 인사이트

### 지침 파일은 명령이 아니라 서술로 써야 한다

논문이 짚은 것은 지침 파일의 문장이 명령형 어조로 기록된 서술이라는
점이다.[^paper]
이 점에서 한 문장 처방은 증상 치료이고, 원인은 파일의 쓰는 방식에 있다.
“`print()`를 쓴다”가 아니라 “이 저장소는 진행 메시지에 `print()`를 쓴다, 기준일
2026-10”처럼 쓰면, 코드가 바뀌었을 때 모델이 서술과 코드를 비교할 근거가 생긴다.
이것은 이 노트의 제안이고 논문이 시험한 것이 아니다.

이 제안이 맞는지는 관찰로 갈릴 수 있다.
같은 40개 프로젝트의 파일을 서술형으로 바꿔 문장 없이 돌렸을 때 코드를 따르는
선택 비율이 오르는지 보면 된다.
오르지 않으면 어조가 아니라 파일의 서열이 원인이라는 쪽에 무게가 실린다.

### 낡음의 비용은 에이전트 수에 비례해 커진다

논문은 파일이 모든 세션에 불러와지므로 같은 실수가 모든 작업, 모든 에이전트,
모든 팀원에게서 되풀이된다고 지적한다.[^paper]
사람은 낡은 문서를 읽고 코드와 대조해 스스로 보정하지만, 에이전트는 서열 때문에
보정을 못 한다.
에이전트를 쓰는 팀원이 늘수록 낡은 줄 하나가 만드는 어긋난 코드의 수가 늘고,
리뷰어가 그 차이를 찾아 고치는 일도 늘어난다.[^paper]

빌드 스크립트나 린터 설정이 낡았을 때와 비슷한 구조로 볼 수 있다.
사람은 경고를 무시할 수 있지만, 자동화된 도구는 설정을 그대로 따른다.
문서가 사람에게만 읽히던 때의 낡음은 느슨한 비용이었고, 문서를 실행하는 독자가
생기면서 그 비용이 즉시 코드로 나타난다.
지침 파일의 갱신 주기는 이제 코드 리뷰의 주기와 같은 층위로 관리해야 한다.

### 사용자의 문장과 제작자의 기본값은 다른 해법이다

논문은 에이전트 제작자는 이 규칙을 시스템 프롬프트에 넣을 수 있고, 모델 제작자는
서술을 코드와 대조하도록 훈련할 수 있다고 제안한다.[^paper]
Claude Code 문서는 지침 파일 둘 사이의 충돌은 다루지만 지침 파일과 코드의 충돌은
다루지 않는다고 논문은 지적한다.[^paper]
사용자의 문장은 오늘 쓸 수 있는 해법이고, 제작자의 기본값은 모든 사용자에게 닿는
해법이다.

그러나 기본값으로 바뀌면 앞의 비평이 다른 형태로 돌아온다.
기본값은 모든 저장소에 같은 방향으로 작용하므로, 파일이 의도적으로 코드를 앞서는
저장소에서는 사용자가 규칙을 끌 방법이 필요하다.
사용자 수준 문장은 사용자가 지울 수 있지만 시스템 프롬프트의 규칙은 지울 수
없다.

### 이 글을 읽는 방법

AIDB 글과 트윗은 논문의 요약이므로, 40개 프로젝트의 실행 횟수와 수치는 논문과
대조해 맞는 사실이고, 원인에 대한 설명과 처방이 모든 상황에 통한다는 암시는 아직
확인되지 않은 해석이다.
AIDB 글의 요점 항목은 테스트 통과율 100%를 내세우지만, 코드를 따른 선택의 비율은
91.4%다.

이 판단을 가를 관찰은 두 가지다.
첫째, 지침 파일이 옳고 코드가 낡은 프로젝트를 만들어 같은 문장을 넣었을 때
에이전트가 옳은 파일을 무시하는 비율을 재는 것이다.
둘째, 문장을 넣지 않고 파일의 위치나 전달 방식(지시 대신 도구 출력)만 바꿔 같은
프로젝트를 돌리는 것이다.
첫째는 문장의 부작용을, 둘째는 서열 가설이 맞는지를 가른다.
