# Krill: Electron 없이 Rust로 다시 만든 병렬 코딩 에이전트 작업 공간

<https://krill.page/>

<https://github.com/craftowen/krill>

Show GN: [Krill - 무거운 Orca가 답답해서 Rust로 다시 만들었습니다](https://news.hada.io/topic?id=36527)

## 소개

Krill은 Claude Code, Codex 같은 CLI 코딩 에이전트를 여러 개 동시에 돌리는
데스크톱 앱이다.
Apache-2.0 라이선스의 오픈소스이고 Rust와 GPUI로 처음부터 짰으며 Electron도
웹뷰도 쓰지 않는다고 만든 이가 밝힌다.
GeekNews에는 2026년 11월 3일 Show GN으로 올라왔고 글쓴이 owenkrill은 Orca가
무거워서 답답했다고 이유를 적었다.
이 문서는 홈페이지와 소개 글, GitHub의 README와 저장소 정보를 읽고 정리한
것이며 직접 설치하거나 시험하지 않았다.
측정 수치는 모두 만든 이가 자기 시스템과 경쟁 도구에 대해 한 주장이다.

2026년 11월 9일 기준 GitHub API가 보고한 저장소는 2026년 10월 15일에
만들어졌고 별 7개, 포크 0개, 열린 이슈 5개, 마지막 푸시는 같은 날이다.
언어는 Rust다.
기존 문서에 정리한 Orca가 비교 대상이다.

## 구조와 기능

작업마다 Git 워크트리로 별도 브랜치와 폴더를 열고 거기서 에이전트를 돌리는
방식이다.
입력을 기다리는 작업은 Needs You 큐에서 바로 찾을 수 있고 터미널 옆에서 변경
파일과 diff를 본다.
README가 소개하는 기능은 다음과 같다.

- 앱보다 오래 사는 세션: 앱을 닫거나 업데이트하거나 비정상 종료해도 에이전트는 백그라운드에서 계속 돌고, 다시 열면 같은 터미널에 이어진다. 보관되는 기록에는 한도가 있어서 넘치면 `Gap` 표시가 생긴다.
- 병렬 워크트리와 diff 검토: 사이드바나 CLI로 워크트리를 만들고, 저장소 설정 스크립트는 실행 전에 확인하게 한다. 변경, 파일, 검색, 검사, 이력의 검토 탭 다섯 개와 터미널 옆 인라인 diff 댓글이 있다.
- 기다리는 에이전트 우선: 수명 주기 훅이 working, waiting, done, blocked, idle, exited의 여섯 상태를 추적해 도움이 필요한 에이전트를 큐 맨 위, macOS 알림, Dock 배지로 올린다.
- 다중 에이전트 작업 그래프: 조정자 에이전트가 의존 작업을 나누고 작업자 에이전트를 별도 워크트리에서 시작하며, 서로 묻고 답하고, 사람의 결정 관문에서 멈춘다.
- 모바일 동반 앱(PWA): 설정에서 QR을 띄워 휴대폰 브라우저로 에이전트 상태를 보고 터미널을 연다. Relay나 Tailscale 위에서 ChaCha20-Poly1305로 종단간 암호화한다고 한다.
- 샌드박스 공개 링크: 에이전트가 만든 HTML 보고서와 Markdown을 `share.krill.page`의 공개 링크 하나로 게시하고 같은 주소를 갱신하거나 철회한다. 만료 기간은 설정하며 용량은 10MiB다.

그 밖에 GUI 없이 쓰는 `krill` CLI와 원격 SSH 호스트, 사용량 한도에 닿으면 계정을
자동으로 바꾸는 계정 전환, UTC 크론 기준의 예약 실행, 테마 45개와 한글 입력기
조합 상태 기계가 들어 있다고 한다.
지원하는 에이전트는 Claude Code, OpenAI Codex, Antigravity, Cursor CLI,
OpenCode이며 터미널에서 도는 것이면 무엇이든 영속 PTY 보호를 받는다고 한다.
에이전트는 따로 설치하고 인증해야 하고 Krill은 구독이나 자격 증명을 포함하지
않는다.

## 만든 이가 제시한 측정

소개 글과 README가 가장 앞세우는 것은 메모리 비교다.
2026년 10월 28일 같은 Mac에서 화면을 켠 채 Krill 0.2.20과 Orca 1.4.242를
비교했고, 앱과 데몬 프로세스를 합친 `phys_footprint`의 3회 중앙값이라고
한다.

| 측정(터미널 10개)   | Krill 0.2.20 | Orca 1.4.242 | 비율   |
| ------------------- | ------------ | ------------ | ------ |
| 메모리              | 153.3 MiB    | 1,153.6 MiB  | 약 1/7 |
| 유휴 CPU(30초 평균) | 1.9%         | 12.9%        | 약 1/7 |
| 설치 크기(`.app`)   | 95.6 MiB     | 704.7 MiB    | 약 1/7 |

터미널 20개에서는 309.4MiB 대 1,347.6MiB, 1개에서는 125.4MiB 대 853.7MiB라고
README는 적는다.
이 측정은 공용 작업 머신의 부하가 높은 상태(1분 부하 평균 11~52)에서 했다고
밝히며, 셸과 에이전트 자체는 제외했다.
README는 10월 25일의 앞선 측정도 싣는다.
화면을 잠근 상태에서 Krill 0.2.2가 85.9MiB, Orca 1.4.237이 1,274.9MiB로
15분의 1이었고 화면을 켠 이번 측정에서 비율이 줄어든 이유를 Krill 앱 자체가
화면을 켜면 약 111MiB를 쓰기 때문이라고 설명한다.

## 설치와 지원 범위

공식 지원은 Apple Silicon macOS와 Windows x64 미리보기다.
Intel Mac과 Linux는 지원하지 않고, 모바일은 앱 스토어 앱 없이 QR로 여는 PWA다.
macOS 릴리스는 Apple 공증을 받지 않았고 설치기가 내려받은 앱의 격리
속성(quarantine)을 제거한다고 README가 밝힌다.
Windows 빌드는 Authenticode 서명이 아직 없다.
설치 명령에 대해 홈페이지는 스크립트를 내려받아 바로 실행하는 `curl | bash`
한 줄을 보여 주는 반면 README는 설치기를 먼저 내려받아 확인한 뒤 실행하라고
안내한다.
Windows 데스크톱 GUI, 대화형 로그온, 절전, 재부팅 동작은 기록된 Windows Server
VM 시험 밖에서는 아직 검증이 필요하다고 README가 스스로 적는다.

사용 통계는 동의 창 없이 기본으로 켜져 있다.
무작위 설치 ID, 첫 실행, 앱 실행, 일일 상호작용, 버전, OS, 아키텍처를 수집하고
프롬프트, 터미널 출력, 명령, 프로젝트 경로, 계정 정보는 제외한다고 한다.
`krill telemetry disable`이나 `DO_NOT_TRACK=1`로 끌 수 있고, 오류 보고는 따로
기본으로 꺼져 있다.

## 비평

### 비교의 공정성은 만든 이의 조건에 달려 있다

비교는 만든 이가 경쟁 도구에 대해 직접 한 것이고 조건도 자기가 정했다.
README는 한계를 비교적 자세히 적는 편이지만, 공용 머신에서 부하가 높은 상태로
쟀고 화면을 켠 측정과 잠근 측정의 비율이 크게 다르다는 점은 수치가 조건에
민감하다는 뜻이다.
같은 조건을 독립적으로 재현한 결과는 이 문서가 읽은 자료에 없다.
메모리가 7분의 1이라는 큰 차이가 방향은 맞더라도 정확한 배율을 받아들이려면
다른 기계와 다른 작업량에서의 확인이 필요하다.

### 줄어든 메모리가 에이전트를 돌리는 비용에서 차지하는 비중은 작을 수 있다

측정은 앱과 데몬만 센다.
셸과 에이전트 프로세스는 두 도구에서 같다는 이유로 제외했다.
그러나 사용자가 실제로 쓰는 메모리에는 에이전트 프로세스가 들어가고,
그 크기는 이 글이 다루지 않는다.
앱이 1GB를 덜 쓰는 것이 의미 있는 사람은 작업을 많이 열고 메모리가 모자라는
사람이다.
이 판단은 이 문서의 추론이며 에이전트 프로세스의 크기는 이 문서가 읽은 페이지에
없다.

### 생긴 지 한 달이 안 된 프로젝트의 지속성은 알 수 없다

저장소는 2026년 10월 15일에 만들어졌고 별이 7개, 포크가 없다.
그에 비해 기능 목록은 에이전트 조율, 모바일, 공개 링크 게시, 예약 실행,
원격 호스트까지 넓다.
README가 Windows 동작이 검증 중이라고 스스로 적는 것처럼 넓은 범위가 아직
깊게 검증되지는 않았다.
설계 문서가 한국어로만 있다는 점도 기여자 범위를 좁힐 수 있다.

### 기본으로 켜진 통계와 외부 서비스가 신뢰 판단에 들어간다

사용 통계가 동의 없이 기본으로 켜져 있고, 호스팅된 릴레이를 쓰려면 데스크톱에서
Google로 로그인해야 하며, 공개 링크는 에이전트가 만든 문서를 외부 주소로
내놓는다고 README가 밝힌다.
수집 항목을 제한하고 끄는 방법을 문서화한 점은 투명하다.
그래도 에이전트가 소스 코드와 비밀 값에 닿는 환경에서 이런 기본값을 받아들일지는
사용자가 따져야 한다.

## 도입 전에 따져볼 것

- 설치 스크립트를 내려받아 읽은 뒤 실행한다. 홈페이지의 한 줄 명령보다 README의 절차를 따른다.
- 사용 통계를 쓰지 않으려면 `krill telemetry disable`을 먼저 실행하거나 `DO_NOT_TRACK=1`을 설정한다.
- macOS 릴리스가 공증되지 않았고 설치기가 격리 속성을 제거한다는 점을 보안 정책에 비춰 확인한다.
- 모바일 연결은 Relay와 Tailscale 중 어느 쪽을 쓸지 정한다. 호스팅 릴레이는 Google 로그인이 필요하다.
- 공개 링크로 게시하기 전에 문서에 소스 코드나 비밀 값이 없는지 본다. 철회는 같은 주소에서 한다.
- 메모리 이점을 자기 기계에서 확인한다. 에이전트를 포함한 전체 메모리 사용량을 두 도구에서 비교한다.
- 이 도구에 의존하기 전에 저장소의 활동과 이슈 응답을 한 번 더 확인한다. 생긴 지 한 달이 안 된다.
