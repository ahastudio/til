# The Session You Cannot Take With You

원문: [The Session You Cannot Take With You | EARENDIL](https://earendil.com/posts/session-portability/)

HN 토론: <https://news.ycombinator.com/item?id=49118781> (730점, 212개 댓글)

## 요약

이 글은 추론 API 제공자들이 사용자에게 “읽을 수 있는” 대화 기록을 제공하는
것처럼 보이지만, 실제로는 세션을 다른 곳으로 이전할 수 없게 만드는
provider-sealed state를 함께 반환함으로써 사용자를 자사 생태계에 락인시키고
있다고 주장한다.

원래 추론 API의 약속은 단순했다. 입력을 보내고 출력을 받으며, 그 대화
기록을 사용자가 소유한다는 것이었다. 그러나 지금의 제공자들은 사용자에게
과금되지만 암호화된 블롭 형태로만 반환되는 reasoning token, 모델은 접근했지만
사용자는 접근할 수 없는 웹 검색 결과, 원래 제공자만 복호화할 수 있는
압축된 컨텍스트, 암호화된 페이로드에 숨겨진 서브에이전트 지시문, 제공자
서버에서만 해석 가능한 참조 등을 세션에 끼워 넣는다.

저자는 세션 소유권을 판별하는 다섯 가지 실용적 기준을 제시한다.
검사(inspection, 모델이 무엇을 보았고 에이전트끼리 무엇을 주고받았는지 볼 수
있는가), 내보내기(export, 다운로드 가능한 아티팩트를 제외하면 세션이
자기완결적인가), 재현(replay, 다른 구현체가 의미적으로 동등한 컨텍스트를
재구성할 수 있는가), 감사(audit, 사람이 사후에 시스템 행동을 설명할 수
있는가), 삭제(deletion, 사용자가 서버 측 모든 사본을 식별하고 제거할 수
있는가)이다.

구체적으로 저자는 암호화가 실제로는 제공자로부터 데이터를 숨기는 것이
아니라 사용자로부터 숨기는 역할을 한다고 지적한다. OpenAI와 Google은 기본
설정으로 응답을 30일 이상 저장하여 대화 기록을 사용자가 독립적으로 접근할
수 없는 데이터베이스 포인터로 바꾸어 놓는다. 제공자들은 비공개 툴 호출
루프를 실행하면서 모델이 실제로 받은 정확한 텍스트가 아니라 인용과 URL만
노출하여, 다른 플랫폼에서의 정확한 재현을 막는다. 서버 측 압축은 읽을 수
없는 암호화된 항목을 반환하는데, Anthropic의 방식은 그나마 검사 가능한
요약을 제공한다고 언급된다. 서브에이전트 지시문과 에이전트 간 통신도
암호화되어 사용자조차 감사 추적을 할 수 없다.

저자는 이식 가능한 추론 API가 갖춰야 할 표준으로, 로컬 이벤트 로그를
정본(canonical)으로 취급할 것, 저장을 명시적이고 선택적으로 만들 것,
암호화된 최적화 기능과 함께 읽을 수 있는 핸드오프 표현을 포함할 것,
호스팅된 툴 기록을 완전한 충실도로 로깅할 것, 감사 가능한 서브에이전트
통신을 보존할 것, 검사 가능한 압축 요약을 반환할 것, 콘텐츠 주소 지정
아카이브로 아티팩트를 내보낼 수 있게 할 것을 제안한다. 또한 대형 랩들이
공개 인터넷 콘텐츠와 자사 모델 계층에서 지식을 추출하면서도, 외부에서
자사 출력물을 distillation하는 것은 상업 약관 위반으로 금지하는 비대칭을
지적한다. 결론적으로 “사용자는 계정을 닫고, 세션을 유지한 채, 그것을 다른
모델에 넘길 수 있어야 한다”고 주장한다.

## 분석

### 락인의 메커니즘이 기술적 필연이 아니라 설계 선택이라는 주장

이 글의 핵심 논증 구조는 “암호화된 상태가 필요하다”는 제공자들의 암묵적
전제를 반박하는 데 있다. 저자는 reasoning token 암호화, 압축 컨텍스트,
서브에이전트 통신 암호화가 모두 기술적으로 불가피한 것이 아니라, 경쟁
모델 학습을 막기 위한 비즈니스 결정이라고 프레이밍한다. 이 프레이밍이
성립하려면 “암호화 없이도 모델 사고 과정을 노출하지 않을 방법이
있다”거나 “노출해도 경쟁상 문제가 없다”는 전제가 필요한데, 글은 이
전제를 논증하기보다 당연한 것으로 받아들인다. Anthropic이 “그나마
검사 가능한 요약”을 제공한다는 언급이 유일한 반례이자 비교 기준으로
쓰이는데, 이는 완전한 대안이 존재함을 보여주는 증거라기보다는 정도의
차이를 보여줄 뿐이다.

### API 계약의 역사적 변화가 무엇을 의미하는지

“보내고 받고 소유한다”는 원래의 API 계약은 사실 완결된 요청-응답
모델(stateless completion)의 시대에나 자연스러운 것이었다. 초기 GPT-3
API는 그야말로 텍스트를 보내고 텍스트를 받는 것이었고, 그 안에 숨길
것이 별로 없었다. 지금의 문제는 에이전틱 워크플로가 다단계, 다중 도구
호출, 서브에이전트 오케스트레이션으로 진화하면서 세션이라는 개념 자체가
복잡해졌기 때문에 발생한다. 즉 이 글이 다루는 문제는 “제공자가
갑자기 불투명해졌다”기보다 “API가 감당하는 상태의 종류가 늘어나면서
투명성을 유지할 유인이 구조적으로 줄었다”는 데 가깝다. 저자는 이
전환을 악의적 설계로 서술하지만, 실제로는 상태 관리의 복잡도 증가가
자연스럽게 불투명성을 만들어내는 측면도 크다.

### 소프트웨어 산업의 반복되는 패턴과의 연결

이 글이 묘사하는 구조는 클라우드 컴퓨팅, 소셜 미디어 데이터 이식성,
문서 포맷 전쟁에서 이미 여러 번 반복된 패턴이다. 초기에는 개방형
표준으로 시작해 사용자를 끌어들이고, 사용량이 락인 수준에 도달하면
독점적 확장(proprietary extension)을 통해 이탈 비용을 높이는 것이다.
추론 API에서 이 패턴이 새로운 점은, 데이터가 사용자의 것이 아니라
“모델의 사고 과정”이라는 점에서 소유권 자체가 모호하다는 것이다.
사용자가 프롬프트를 보냈다고 해서 모델의 reasoning trace를 소유할
권리가 자명하게 있는가? 저자는 이를 당연시하지만, 이는 신용카드
거래 내역이나 이메일처럼 명확한 개인 데이터의 이식성과는 성격이 다른
주장이다.

### 규제된 API가 여전히 완전한 투명성을 제공하는 반례

HN 댓글 중에는 저자의 주장이 이론적 우려가 아니라 이미 실무에서 회피
가능하다는 반례도 있었다. `bob1029`는 OpenAI가 최근 Chat Completions
API 대신 Responses API로 사용자를 유도하는 이유가 바로 추론 과정을
암호화된 형태로 잠글 수 있기 때문이라고 지적하면서, Chat Completions의
의미론은 근본적으로 투명하며 토큰의 100%가 사용자에게 보인다고
설명했다. 즉 인내심과 약간의 불편을 감수할 의지만 있다면 최신 모델을
쓰면서도 추론 과정 전체에 대한 자율성을 유지할 수 있지만, 그 대가로
사용자가 전적으로 책임을 떠안게 된다는 것이다[^bob1029]. 이는 저자의
논증에서 빠진 지점, 즉 불투명성이 기술적 필연이 아니라 API 선택의
문제라는 점을 실증적으로 뒷받침한다.

한편 `vintagedave`는 자신들이 만든 Delphi용 AI 에이전트 CodeBot에서는
전체 세션 데이터가 클라이언트로 스트리밍되고, 저자가 암호화된
reasoning이라고 지적한 재작성된 텍스트도 자신들의 경우 평문으로
제공된다고 소개하며, 이 글을 읽고 나서야 비로소 업계에 얼마나 많은
문제적 관행이 당연시되고 있는지 깨달았다고 밝혔다[^vintagedave]. 이는
불투명성이 대형 제공자들의 공통 관행일 뿐, 모든 추론 API 설계에
내재된 속성이 아님을 보여주는 사례다.

### 저자가 당연시하는 “감사 가능성”의 비용

글은 검사·재현·감사 가능성을 무조건적 선(善)으로 제시하지만, 이런
투명성에는 실질적인 비용이 따른다는 점을 언급하지 않는다. reasoning
token을 평문으로 노출하면 프롬프트 인젝션이나 탈옥(jailbreak) 시도가
모델의 내부 추론 과정을 학습해 방어를 우회하는 데 활용될 수 있다.
또한 검색 결과의 원문을 그대로 재노출하면 저작권이나 라이선스 문제가
제공자에게 전가된다. 저자가 제시하는 표준은 이러한 트레이드오프를
암묵적으로 “제공자의 편의”로만 처리하고, 사용자 투명성이 야기할 수
있는 새로운 위험은 다루지 않는다.

## 비평

### 세션은 애초에 사용자 단독 소유물이 아니라는 반론

HN에서 가장 논쟁적이었던 반박은 `glitchc`의 지적이었다. 세션은 모델과
사용자가 공동으로 소유하는 것이며, reasoning token처럼 세션의 일부는
전적으로 모델이 생성한 것이라는 주장이다. 그러나 그 생성물의 소유와
활용은 사용자가 서비스 이용 전에 동의한 서비스 제공자의 약관(T&Cs)에
종속된다. 프롬프트를 어떻게 다룰 수 있는지부터 검색과 추론 컨텍스트를
어떻게 관리하는지까지, 언급된 모든 항목에 대한 제공자의 권리가 이미
약관에 명시되어 있으리라는 것이다[^glitchc]. 이 반론이 날카로운
이유는, 저자의 논증 전체가 “세션은 당연히 사용자의 것”이라는 전제
위에 서 있는데, 실제로는 그 전제 자체가 이미 사용자가 서명한
계약으로 반박되고 있을 가능성이 높다는 점을 지적하기 때문이다. 이는
앞서 분석에서 짚은 “소유권 자체가 모호하다”는 문제의식과 정확히
같은 지점을 겨냥하지만, 훨씬 구체적인 근거(실제 약관의 존재)로
뒷받침된다.

### 다섯 가지 기준이 서로 다른 종류의 요구를 하나로 뭉뚱그린다

검사, 내보내기, 재현, 감사, 삭제라는 다섯 기준은 언뜻 일관된
프레임워크처럼 보이지만, 실제로는 성격이 전혀 다른 요구들이다. 삭제는
법적·규제적 요구(GDPR 등)와 맞닿아 있고 이미 상당 부분 제도화되어
있다. 반면 재현(replay)은 사실상 모델 간 완전한 상호운용성을 요구하는
것으로, 이는 각 제공자의 핵심 경쟁력인 모델 아키텍처와 최적화 기법을
사실상 무력화하라는 요구에 가깝다. 저자는 이 다섯 기준을 “세션
소유권”이라는 하나의 개념으로 묶어 제시하지만, 삭제 권리를 요구하는
것과 재현 가능성을 요구하는 것은 정치적으로도 기술적으로도 완전히
다른 무게의 주장이다. 이렇게 뭉뚱그리면 상대적으로 온건하고 정당한
요구(삭제)가 훨씬 급진적인 요구(재현)의 정당성을 함께 업고 가는
수사적 효과를 낳는다.

### distillation 금지 비대칭 논증은 스스로의 논리와 충돌한다

저자는 대형 랩들이 공개 인터넷과 자사 모델 계층에서 지식을 추출하면서
외부의 distillation은 금지하는 것을 비대칭이라고 비판한다. 그러나 이
비판은 글 전체의 논지, 즉 “제공자가 세션 데이터에 대한 배타적 통제권을
가져서는 안 된다”는 주장과 묘하게 어긋난다. distillation 금지는 결국
제공자가 자신의 모델 출력물(정확히는 그로부터 파생된 학습 신호)에 대해
일정한 지적재산권적 통제를 주장하는 것인데, 세션 이식성 주장은 그
반대로 출력물에 대한 사용자의 통제권을 극대화하자는 것이다. 저자는 두
주장을 모두 “사용자/경쟁자에게 유리한 방향”이라는 결과만 보고
동일선상에 놓았을 뿐, 통제권의 소재를 묻는 근본 질문에는 일관된
답을 제시하지 않는다. 즉 이 글은 “누가 무엇을 통제해야 하는가”라는
핵심 질문에서 편의적으로 입장을 바꾼다.

### 재현 가능성 요구는 사실상 모델 아키텍처 표준화를 요구하는 것과 같다

“다른 구현체가 의미적으로 동등한 컨텍스트를 재구성할 수 있어야
한다”는 재현 기준은 언뜻 합리적으로 들리지만, 실제로 실현하려면
모델들이 컨텍스트를 소비하는 방식 자체가 수렴해야 한다. 예를 들어
한 모델의 reasoning trace를 다른 모델이 “의미적으로 동등하게” 이어받아
쓰려면, 두 모델이 유사한 토큰화 방식, 유사한 컨텍스트 윈도우 활용
전략, 유사한 도구 호출 프로토콜을 가져야 한다. 이것은 세션 데이터
포맷의 문제가 아니라 모델 아키텍처 다양성 자체를 제약하는 문제다.
저자는 이를 마치 데이터 포맷 표준화(JSON vs XML 같은) 문제인 것처럼
서술하지만, 실제로는 모델 발전의 다양성과 정면으로 충돌할 수 있는
훨씬 무거운 요구다.

### 사용자 다수는 이 문제에 무관심하다는 사실이 논증에서 빠져 있다

글 전체는 “사용자가 마땅히 원해야 할 권리”를 전제로 서술되지만, 실제
대다수 API 사용자(특히 소비자용 챗봇 이용자)는 세션 이식성에 대한
수요를 표출한 적이 없다. 이 요구는 주로 에이전틱 개발자, 즉 여러
모델을 오케스트레이션하며 벤더 락인을 피하고 싶어하는 소수의 기술적
이해관계자에게서 나온다. 저자는 이 요구를 마치 보편적 사용자 권리인
것처럼 서술하지만, 실제로는 특정 이해관계자 집단(멀티모델 에이전트
개발자)의 이익을 대변하는 주장이라는 점을 명시하지 않는다. 이는
논증의 설득력을 인위적으로 높이는 수사적 장치로 기능한다.

## 인사이트

### 세션 이식성 표준이 실현되면 오히려 새로운 형태의 락인이 등장할 것이다

만약 저자의 제안대로 모든 제공자가 검사 가능하고 재현 가능한 세션
포맷을 채택한다면, 그 표준 포맷 자체가 새로운 병목이 된다. 표준을
먼저 정의하고 생태계를 구축하는 주체(예: 오픈소스 에이전트 프레임워크,
혹은 특정 대형 제공자)가 사실상 “세션 이식성의 기준점”을 쥐게 되고,
그 포맷에 맞추지 못하는 신생 모델 제공자는 시장 진입 장벽을 새로
마주하게 된다. 이는 웹 표준의 역사에서 반복된 패턴과 동일하다. HTML,
RSS, OAuth 같은 “개방형” 표준들도 초기 채택자의 구현 세부사항이
사실상의 표준이 되면서, 그 표준을 정의한 자가 새로운 형태의 권력을
갖게 된 사례가 많다. 즉 이 글이 해결책으로 제시하는 이식성 표준화는
락인의 형태를 제공자 단위에서 표준 단위로 옮길 뿐, 락인이라는 현상
자체를 소거하지 않을 가능성이 크다.

### 이 논쟁은 1990년대 문서 포맷 전쟁의 재판이며, 승자는 표준이 아니라 변환 계층이었다

MS Word의 .doc 포맷이 사실상 표준이 되었을 때, 실제로 사용자의
자유를 되찾아준 것은 경쟁 제공자의 “완전 호환 표준” 채택이 아니라
Pandoc 같은 범용 변환 도구, 그리고 ODF-OOXML 간의 상호 변환 계층이었다.
추론 API 세션 이식성 문제에서도 유사한 경로가 예상된다. 즉 제공자들이
자발적으로 검사 가능한 포맷을 채택하기를 기다리기보다, 서드파티가
각 제공자의 opaque state를 역공학하거나 표준화된 중간 표현(예: 로컬
이벤트 로그를 정본으로 삼는 저자의 제안 1번)으로 변환하는 어댑터
계층이 실질적 해법으로 자리잡을 가능성이 높다. 실제로 LangChain,
LlamaIndex 같은 에이전트 프레임워크들이 이미 이런 추상화 계층 역할을
일부 수행하고 있으며, 이 글의 문제의식은 결국 그런 프레임워크 계층의
중요성을 강화하는 방향으로 귀결될 가능성이 크다.

### 세션 자체가 잘못된 보존 단위일 수 있다

HN에서 `vamsiraju`가 제기한 반론은 이 글의 문제 설정 자체를 뒤집는다.
애초에 세션을 보존하고 이전해야 할 대상으로 삼는 것 자체가 잘못된
접근일 수 있다는 것이다. 세션은 압축을 거쳐도 시간이 지나면 잡음이
쌓이고, 완전히 검사 가능했던 적도 없으며, 언제 세션을 버리고 새로
시작해야 하는지에 대한 명확한 기준도 없고, 실제로 수행된 작업과
깔끔하게 대응하지도 않는다. 따라서 세션을 아카이브하려 애쓰기보다는,
에이전트나 모델이 작업의 근거(basis)를 세션 바깥의 별도 구조로
기록하게 만들고 그것을 보존해야 한다는 것이다[^vamsiraju]. 이는
`skybrian`의 경험과도 맞닿는데, 그는 저장소에 노트 디렉터리를 두고
AI가 무엇을 배웠고 어떤 작업이 남았는지를 마크다운으로 적게 한 뒤,
다음 대화에서 다른 모델이 그 노트에서 이어받게 한다고 소개하며 이
문제를 실무에서는 그렇게 심각하게 여기지 않는다고 말했다. 대화에는
어차피 잡다한 내용이 많이 섞여 있어서 컨텍스트에서 빼는 편이 대체로
낫다는 것이다[^skybrian]. 두 댓글을 종합하면, 저자가 전제하는
“세션 자체를 이식 가능하게 만들어야 한다”는 목표 자체가 잘못된
질문일 수 있으며, 실무자들은 이미 세션을 우회하는 방식으로 이
문제를 해결하고 있다는 뜻이 된다. 이는 인사이트에서 다룬 “제3의
변환 계층이 실질적 해법이 된다”는 예측을 한층 강하게 뒷받침하는
동시에, 그 계층이 세션 포맷 변환이 아니라 애초에 세션을 우회하는
형태(외부 노트, 별도 basis 기록)로 나타날 수 있음을 보여준다.

### 규제가 개입하는 순간 이 논쟁은 “AI 세션도 개인정보인가”라는 전혀 다른 법적 질문으로 바뀐다

저자가 제시한 삭제 권리는 표면적으로 GDPR의 삭제권(right to erasure)과
유사해 보이지만, 실제로 여기서 삭제 대상이 되는 것은 사용자 개인정보가
아니라 “모델이 생성한 추론 과정”이다. 이는 저작권법상 누구의 저작물인가
(사용자의 프롬프트가 유발했지만 모델이 생성한 텍스트), 그리고 규제상
누구의 데이터인가(사용자가 비용을 지불했지만 제공자의 인프라에서
생성된 파생 데이터)라는 두 가지 미해결 법적 질문과 얽혀 있다. 향후
AI 규제가 성숙하면서 “추론 세션”이 개인정보, 저작물, 영업비밀 중
무엇으로 분류되느냐에 따라 이 글이 요구하는 이식성 권리의 법적 기반이
완전히 달라질 것이다. 즉 지금 이 논쟁은 기술 표준의 문제로 보이지만,
몇 년 내로 법적 분류 문제로 재구성될 가능성이 높고, 그때는 지금
제시된 다섯 가지 실용적 기준과는 다른 기준(누구의 재산권인가)이
논의의 중심에 설 것이다.
