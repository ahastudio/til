# Offrun: 여러 코딩 에이전트와 여러 계정을 한 Mac 앱에서 돌린다

<https://offrun.dev/>

HN 토론: <https://news.ycombinator.com/item?id=49942434> (76점, 64개 댓글)

GN 토론: <https://news.hada.io/topic?id=34783>

## 소개

Offrun은 Claude Code, Codex, AGY, Grok Build를 나란히 돌리는 macOS 앱이다.
홈페이지의 한 줄 소개는 모든 코딩 에이전트를 하나의 작업 공간에서 관리하라는
것이고, 누가 일하는 중인지, 누가 사람을 기다리는지, 각 계정에 사용량이 얼마나
남았는지를 보여 준다고 설명한다.
AGY는 Google의 Antigravity CLI(`agy`)다.
Pi와 OpenCode는 곧 지원한다고 적혀 있다.

Offrun은 에이전트를 대신하지 않는다.
FAQ는 Claude Code나 Codex를 대체하느냐는 질문에 아니라고 답하고,
그것들을 실행하며 함께 지낼 자리를 줄 뿐이라고 설명한다.
에이전트 CLI는 사용자 Mac에서 사용자 본인 계정으로 로그인한 채 돌아가고, 새
계정이나 API 키가 필요 없다고 한다.

가격은 무료이고 기능 제한이 없다고 한다.
에이전트, 프로젝트, 받아쓰기,
연결할 에이전트 계정 수가 모두 무제한이며 카드도 받지 않는다.
대신 각 에이전트의 구독료는 사용자가 지금처럼 따로 낸다.
요구 사항은 Apple Silicon(M1 이상) Mac과 macOS 14 Sonoma 이상,
그리고 이미 쓰는 에이전트 CLI 하나 이상이다.
운영사는 페이지 하단 표기상 Founderly, Inc.다.

체인지로그를 보면 이 앱은 원래 Offloop라는 이름이었고,
6.0.0(2026년 9월 25일)에서 Offrun으로 바뀌었다.
HN에는 같은 게시자가 Offloop를 개발자용 온디바이스 받아쓰기 에이전트로 소개한
Show HN이 따로 있다.
받아쓰기와 회의 기능이 앱에 남아 있는 이유가 여기서 보인다.
이 문서의 내용은 홈페이지, Conductor 비교 페이지, 다중 계정 가이드,
체인지로그에서 확인한 것이며, 나는 이 앱을 직접 실행하지 않았다.

## 동작 방식

### 에이전트마다 git 워크트리 하나

프로젝트 안의 에이전트는 각자 git 워크트리와 브랜치를 받는다.
같은 저장소에서 두 에이전트가 일해도 같은 파일을 건드리지 않으므로,
리팩터링과 버그 수정을 동시에 돌리고 원하는 때에 병합하면 된다.
워크트리는 저장소의 `.worktrees` 아래, 채팅과 메모리는 `.offrun` 아래에 놓이고,
저장소의 로컬 exclude 파일을 통해 git이 둘 다 무시한다.
작업 결과가 평범한 git 브랜치로 남기 때문에 Offrun을 쓰다가 다른 도구로 옮겨도
묶이지 않는다고 비교 페이지는 설명한다.

### 두 번째 에이전트의 리뷰

리뷰어 에이전트를 고르면 작업이 아직 커밋되지 않은 상태에서
그 결과가 채팅에 올라온다.
Claude Code의 작업을 Codex가 검토하거나 그 반대로 할 수 있다.
수정을 요청하면 그 내용이 사용자의 메시지 입력창에 들어오고,
사람이 읽기 전에는 아무것도 전송되지 않는다.
리뷰어는 diff를 읽고 결과를 남길 뿐 코드를 바꾸지 못하며,
저절로 병합되는 것도 없다.
리뷰는 사용자 자신의 에이전트 계정으로 돌기 때문에
별도 구독이나 풀 리퀘스트에 붙는 봇이 필요 없다.

홈페이지 예시가 이 기능의 쓰임을 잘 보여 준다.
재시도 백오프 상한을 30초로 잡은 코드에 대해 Codex 리뷰어가 게이트웨이
타임아웃이 25초라서 마지막 재시도가 잘린다고 경고한다.
작성한 에이전트가 놓치기 쉬운, 저장소 밖의 제약을 다른 모델이 짚는 장면이다.

### 사용량 한도와 계정 넘기기

Claude Code는 로그인을 `~/.claude` 한 폴더에 두기 때문에
두 번째 계정에는 두 번째 폴더가 필요하다.
수동으로 하려면 `CLAUDE_CONFIG_DIR`을,
Codex는 `CODEX_HOME`을 다른 폴더로 지정하면 된다.
다중 계정 가이드는 이 방식의 두 가지 빈틈을 짚는다.
폴더마다 기록이 따로라서 한 계정의 대화를 다른 계정에서 이어 갈 수 없고,
한도에 가까워져도 경고가 없어서 Claude Code가 멈춘 뒤에야 알게 된다.

Offrun은 같은 폴더 방식을 쓰되 관리를 대신한다.
설정의 에이전트 화면에서 계정을 추가하면 로그인마다 폴더가 생기고,
Offrun은 CLI를 그 폴더로 지정해 실행한다.
토큰은 읽지도, 복사하지도, 저장하지도 않는다고 한다.
AGY에는 그런 환경 변수가 없어서 로그인마다 별도 홈 폴더를 만들고, git 신원과 SSH
키를 그 안에 링크해 커밋과 푸시가 되게 한다.

홈 화면은 로그인별 사용량과 리셋 시각을 보여 준다.
Claude Code는 세션과 주간 한도를,
Codex는 플랜의 윈도를, AGY는 모델별 버킷을 보여 주며,
Claude Code의 경우 모델을 호출하지 않는 `/usage` 명령으로 값을 받는다.
한 로그인이 한도에 닿으면 채팅이 같은 에이전트의 다음 로그인으로 옮겨 가고
그 사실을 채팅에 남긴다.
사용자가 메시지를 다시 보내면 새 로그인이 새 스레드를 열고
기존 대화를 넘겨받는다.
소진된 로그인은 한 시간 동안 건너뛰고, 모든 로그인이 바닥나면 로그인해 둔 다른
에이전트로 대화 전체를 넘기자고 제안한다.

### 프로젝트 메모리

Offrun은 저장소 전체 규칙과 에이전트별 목표, 계획, 막다른 길을 나누어 보관한다.
예시 화면에는 모든 에이전트가 읽는 `conventions.md`, 기능별 접근을 담는
`plan.md`, 시도했다가 실패한 것을 적는 `dead-ends.md`가 나온다.
에이전트는 세션을 시작할 때 이 문맥을 읽고 일하면서 다시 써 넣으므로, 네 번째
세션이 첫 번째 세션의 시도를 안다는 것이 홈페이지의 설명이다.
메모리는 프로젝트 폴더의 평범한 파일이어서 열고, 고치고, 커밋할 수 있다.
체인지로그 6.0.5는 약 35MB짜리 작은 검색 모델을 내려받아 노트를 단어 일치가
아닌 의미로 찾는다고 적고,
6.0.9는 `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`에 적은 규칙과
스킬을 모든 에이전트가 따르고 리뷰어도 그 기준으로 검사한다고 적는다.

### 미리보기와 받아쓰기

채팅 옆에서 변경 파일, 줄 번호가 붙은 diff, 렌더링된 마크다운과 표, 이미지, PDF,
주소창이 있는 작은 브라우저를 볼 수 있다.
6.0.8부터는 에이전트가 이 미리보기 패널의 페이지를 열고 조작할 수 있고,
사용자가 언제든 넘겨받을 수 있다.
받아쓰기는 키를 누른 채 말하면 기기 안에서 텍스트로 바꾸고,
코드의 식별자 표기를 지켜 커서 위치에 넣는다.
예시에서는 “retry backoff helper”를 `retryBackoffHelper`로,
“jason”을 JSON으로 적는다.
처음 설정할 때만 네트워크가 필요하다고 한다.

## 데이터 경계

홈페이지는 사용자의 Mac이 경계라고 설명한다.
받아쓰기는 기기 안에서 처리하고 녹음을 남기거나 보내지 않는다.
채팅, 메모리, 워크트리는 저장소 안의 폴더이고 Offrun은 사본을 두지 않는다.
프롬프트와 코드는 사용자의 로그인으로 Anthropic, OpenAI, Google,
xAI에 바로 가며, Offrun 서버는 그 경로에 없고 키도 다루지 않는다고 한다.

다만 이 경계에는 예외가 있다.
무료 플랜에는 100개가 넘는 커넥터의 무료 크레딧이 들어 있고,
에이전트가 이메일을 찾거나 GitHub 이슈를 만들거나 Slack에 글을 올릴 수 있다.
체인지로그 6.0.8은 커넥터가 Composio를 통해 연결된다고 적는다.
커넥터를 쓰는 순간 데이터가 제3자 서비스를 거치게 되며, 프롬프트 경로에 서버가
없다는 문장은 커넥터 경로까지 보증하지 않는다고 나는 읽었다.

## 시작하기

홈페이지의 안내에 다중 계정 가이드의 설명을 더하면 순서는 이렇다.

1. Offrun을 내려받아 응용 프로그램 폴더로 옮긴다.
2. 설정, 에이전트 화면에서 쓰던 하네스 계정을 연결하고, 두 번째 계정이 있으면 추가한다.
3. 계정 하나를 눌러 새 에이전트의 기본 로그인으로 정한다. 채팅은 시작한 로그인에 머물므로 업무 저장소는 회사 좌석, 사이드 프로젝트는 개인 플랜으로 나눌 수 있다.
4. 프로젝트를 고르고 작업을 준다.

Offrun 없이 계정 분리만 먼저 해 보려면 다중 계정 가이드의
수동 방식이 그대로 쓸 만하다.

```bash
# Claude Code: 빈 설정 폴더로 시작한 뒤 안에서 /login으로 업무 계정에 로그인
CLAUDE_CONFIG_DIR=~/.claude-work claude
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'

# Codex: 폴더가 먼저 있어야 한다
mkdir -p ~/.codex-work
CODEX_HOME=~/.codex-work codex login
```

## Conductor와의 차이

Offrun이 직접 비교 페이지를 둔 상대는 Conductor다.
둘 다 Mac에서 에이전트를 각자의 git 워크트리로 병렬 실행하고 사용자 구독을 쓴다.
아래 표는 Offrun이 2026년 10월 4일 Conductor의 사이트와 문서를 확인해
만든 비교를 옮긴 것이다.

| 항목        | Offrun                                     | Conductor                                     |
| ----------- | ------------------------------------------ | --------------------------------------------- |
| 실행 환경   | Apple Silicon Mac, macOS 14 이상           | Mac, 유료 플랜에서 클라우드 작업 공간         |
| 에이전트    | Claude Code, Codex, Antigravity            | Claude Code, Codex, Cursor, OpenCode          |
| 격리 단위   | 채팅마다 워크트리와 브랜치                 | 작업 공간마다 워크트리와 브랜치               |
| 구독        | 에이전트당 여러 로그인, 한도에서 자동 이동 | 자기 구독과 키 사용                           |
| 리뷰        | 다른 제공사 모델도 가능한 리뷰어 에이전트  | diff 뷰어 코멘트와 에이전트 Review 동작       |
| 풀 리퀘스트 | 사용자가 자기 git 도구로 병합              | PR 생성, 체크 표시, 병합                      |
| 팀          | 한 사람, 한 Mac                            | Pro의 멀티플레이어, Teams와 Enterprise 플랜   |
| 가격        | 무료                                       | 무료, Pro 월 50달러, Teams 사용자당 월 60달러 |

비교 페이지가 스스로 인정하는 차이는 분명하다.
PR 흐름, 더 많은 에이전트, 클라우드와 팀 기능을 원하면 Conductor이고,
여러 로그인과 한도 이동, 직접 고르는 리뷰어,
Antigravity를 원하면 Offrun이라는 것이다.
이 저장소에는 같은 범주의 Herdr(`agentic-coding/herdr.md`),
Paseo(`agentic-coding/paseo.md`),
Orca(`agentic-coding/orca-agent-orchestrator.md`),
Superset(`agentic-coding/superset.md`) 문서도 있다.

## 트레이드오프

### 계정 넘기기는 한도를 없애지 않고 비용과 약관 문제로 옮긴다

한도에 닿으면 다음 로그인으로 넘어가는 기능은 Offrun이 가장 앞세우는 차별점이다.
그러나 이 기능이 의미 있으려면 같은 에이전트의
유료 계정을 둘 이상 갖고 있어야 한다.
가이드도 FAQ에서 각 계정은 사용자 소유이고 각자의 약관을 따르므로 제공사가 계정
사용을 어떻게 기대하는지 확인하라고 적는다.
회사 좌석과 개인 플랜을 섞어 쓰는 시나리오는 편리하지만, 회사 코드가 개인
계정으로 넘어가는 순간 어느 계정의 약관과 데이터 정책이 적용되는지가 바뀐다.
채팅에 계정 이동이 기록된다는 점은 도움이 되지만, 그 이동을 막아야 하는 저장소를
지정하는 방법은 홈페이지에서 확인하지 못했다.

넘겨받는 방식에도 비용이 있다.
새 로그인은 자기 스레드를 새로 열고 기존 대화를 통째로 받으므로, 긴 대화일수록
넘어가는 순간 입력 토큰이 크게 든다.
에이전트까지 바뀌면 Claude Code의 도구 호출 맥락을 Codex가 대화 텍스트로만
이어받게 되고, 이것이 얼마나 매끄러운지는 홈페이지에 수치가 없다.

### 워크트리 격리는 충돌을 없애지 않고 병합 시점으로 미룬다

에이전트마다 워크트리를 주면 작업 중에는 같은 파일을 건드리지 않는다.
하지만 두 에이전트가 같은 모듈을 고쳤다면 충돌은
사용자가 병합할 때 그대로 나타난다.
Offrun은 PR 생성이나 병합을 하지 않고 사용자의 git 도구에 맡기므로,
병렬로 돌린 작업이 많을수록 정리 부담이 사람에게 돌아온다.
Conductor가 PR 흐름을 앱 안에 넣은 것과 반대의 선택이다.

### 무료 앱의 수익 모델이 보이지 않는다

모든 기능이 무료이고 카드도 받지 않는다고
하지만 수익 구조는 페이지에 적혀 있지 않다.
게시자 arunbhatia는 HN에서 클라우드와 모바일 앱을 곧 내놓겠다고
밝혔다.[^arunbhatia-philosophy]
나중에 클라우드 쪽이 유료가 될 수 있고,
그때 사용자 Mac이 경계라는 현재의 설명이 어떻게 바뀔지는 지금 알 수 없다.
이 판단은 홈페이지에 없는 해석이다.

## 함정

### 지원 플랫폼 설명이 서로 맞지 않는다

홈페이지와 다운로드 안내는 Apple Silicon(M1 이상) 전용이라고 적는다.
그런데 HN에서 SyneRyder가 Apple Silicon 전용이라 Linux,
Windows, Intel Mac이 모두 빠진다고 지적하자, arunbhatia는 지금은 Mac용만,
그것도 Apple Silicon과 Intel 모두로 냈고 Windows와 Linux를 곧 낸다고
답했다.[^arunbhatia-platform]
Intel Mac 사용자는 홈페이지 문구를 기준으로 판단하는 편이 안전하다.
SyneRyder는 사용자 정의 하네스와 통합되는지,
직접 바이브 코딩으로 만들 수 없는 무엇을 주는지도 물었다.[^SyneRyder]
arunbhatia는 Herdr, Pi, OpenCode 통합과 사용자 정의 하네스
추가 기능을 준비 중이라고 했다.

### 사용량 표시는 디스패치 전 판단에 쓰기 어렵다

hn3ufz62f7은 작업 도중 막힌 뒤가 아니라 작업을 보내기 전에 계정별 한도 여유를
보고 싶다고 했다.[^hn3ufz62f7]
arunbhatia는 사용자가 한 번의 클릭으로 다른 계정으로 바꿔 이어 가면 되므로
한도 때문에 막히지 않는다고 답했다.[^arunbhatia-limit]
홈 화면에 로그인별 사용량이 보이기는 하지만,
답변은 사전 판단보다 사후 전환에 무게를 둔다.
긴 작업을 맡기기 전에 남은 세션 비율을 직접 확인하는 습관이 여전히 필요하다.

### 대화 기록 중심 화면

phildenhoff는 이런 도구들이 하나같이 에이전트의 일을 대화 기록으로 보여 주는
점을 꼬집었다.[^phildenhoff]
문맥 창이 하나라는 것은 구현 세부일 뿐이고, 자신이 만든 도구는 질문, 계획, 발견,
가정을 별도 UI 요소로 보여 주고 대화를 숨긴다고 했다.
Offrun도 계획 카드와 리뷰 결과를 따로 띄우지만 기본 단위는 여전히 채팅이다.
여러 에이전트가 동시에 질문을 던질 때 열다섯 번의 도구 호출 뒤에 묻힌 마지막
질문을 찾으려 스크롤하는 문제는 남는다.

## 비평

### 차별점이 기능이 아니라 철학으로 설명된다

mr-karan이 Paseo나 Orca와 무엇이 다르냐고 묻자 arunbhatia는
다른 메타 하네스가 에이전트 인 더 루프에 집중하는
반면 Offrun은 휴먼 인 더 루프에 집중한다고 답했다.[^arunbhatia-philosophy]
다른 답글에서는 여러 에이전트를 관리하면 승인 피로가 생기니 사람의 주의를
지키는 데 집중한다고 했다.[^arunbhatia-attention]
그러나 홈페이지에서 그 철학이 구체적인 기능으로 드러나는 곳은 기다리는
에이전트 수 표시, 알림, 리뷰어 정도다.
승인 피로를 줄이는 장치, 예컨대 묻지 않아도 되는 질문을 걸러 내는 규칙이나
질문만 모아 보는 화면은 확인하지 못했다.
같은 답글에서 그는 가장 큰 차별점이 에이전트가 도는 동안 들을 수 있는 내장
라디오라고 농담처럼 덧붙였다.

petesergeant는 Herdr에 없는 무엇을 주느냐가 답해야 할 핵심 질문이라고
했고,[^petesergeant] arunbhatia는 Herdr는 에이전트를 어디서든 돌리게 하고
Offrun은 관리를 돕는다며 Herdr 통합을 곧 넣겠다고 답했다.[^arunbhatia-herdr]
경쟁 제품을 통합 대상으로 끌어들이는 답은 차별점에 대한 답이 아니다.

### 시장은 붐비고 비교 축이 아직 없다

manume은 이런 도구 68개를 비교하는 사이트를 만들었고 Offrun도
추가했다고 했다.[^manume]
maxloh는 Goose, Paseo, T3 Code를 들었고,[^maxloh] KronisLV는 Conductor,
Superset, JetBrains Air 등 아홉 개를 더 보탰다.[^KronisLV]
KronisLV는 몇 개를 써 봤지만 하나같이 견고하지 않다는 데 놀랐고,
5년쯤 뒤 이 중 절반이 사라질지 궁금하다고 했다.
hmokiguess는 이 영역이 아직 아무도 차지하지 못했고 시장과 틈새를 이해하는
사람조차 없다고 봤다.[^hmokiguess]

이런 환경에서 Offrun의 무료 정책과 다중 계정 기능은 눈에 띄는 출발점이지만
지속 가능성의 근거는 아니다.
비교 페이지를 직접 만들어 Conductor와 차이를 정직하게 적은 점은
이 범주에서 드문 태도다.
그러나 그 비교에서 Offrun만의 칸은 계정 이동, 리뷰어 선택,
Antigravity 지원 세 가지이고, 리뷰어 선택은 다른 도구가 따라 하기 쉬운 기능이다.

### 직접 만드는 비용이 기준선이 됐다

eranation은 에이전트를 둘 이상 쓰는 사람은 누구나 이런 것을 한 번씩 만들어
봤다고 했다.[^eranation]
그는 Claude Opus 5.5를 운전자로 두고 다른 에이전트를 띄우게 한 뒤,
백로그를 DAG로 나누고 입력이 필요한 것과 막힌 것을 HTML 페이지로 계속 갱신하게
하는 것으로 충분하다고 했다.
해법이 Claude에게 20분 만에 만들게 할 수 있는 것보다 확실히 나아야
한다는 것이 그의 기준이다.
ithkuil도 여러 도구를 써 봤지만
세션을 모두 잃을 수 있는 도구에 작업 흐름을 맡기는 것이 불안해서,
Herdr 위에 직접 키운 오케스트레이터를 쓴다고 했다.[^ithkuil]

이 기준에서 Offrun이 직접 만들기 어려운 부분은 로그인별 사용량 수집, 한도 이동,
기기 안 받아쓰기 정도다.
워크트리 관리, 메모리 파일,
리뷰어 호출은 스킬이나 스크립트 몇 개로 흉내 낼 수 있다.
Mac 전용 바이너리로 묶을 이유가 무엇이냐는 eranation의 질문에
홈페이지는 답하지 않는다.

## 기억할 원칙

### 에이전트 관리 도구의 가치는 상태를 어디에 남기느냐로 판단한다

Offrun이 워크트리, 채팅, 메모리를 모두 저장소 안의 평범한 폴더에 둔다는 점은 이
범주에서 가장 쓸모 있는 설계다.
도구가 사라지거나 다른 도구로 옮겨도 브랜치와 메모리 파일이 남기 때문이다.
이 범주의 도구는 몇 달 사이에 이름이 바뀌고, 기능이 붙고, 사라질 수 있다.
Offrun 자신도 9월 말에 Offloop에서 이름을 바꿨다.
그러니 어떤 오케스트레이터를 고르든 기능 목록보다 먼저,
그만두었을 때 내 작업 상태가 어디에 어떤 형식으로 남는지를 확인해야 한다.
