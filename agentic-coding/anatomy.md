# Anatomy: 기술 개념을 실제로 움직이는 물건으로 지어 설명하는 에이전트 스킬

<https://skills.wheresryan.sh/anatomy>

<https://github.com/wheresryan22/anatomy>

GN 토론: <https://news.hada.io/topic?id=35670>

## 소개

Anatomy는 기술 개념을 설명하는 그림을 요청하면
그 개념이 곧 작동 원리가 되는 실물을 에이전트가 고안해 만들게 하는 스킬이다.
저장소는 `SKILL.md`가 루트에 있는 표준 Agent Skill 폴더 그 자체다.
Claude Code용으로 쓰였지만 Antigravity,
OpenCode, Codex, MiniMax Code에서도 읽힌다.
README의 첫 문장이 이 스킬의 방식을 요약한다.
기술 개념을 설명하는 그림을 부탁하면
Anatomy가 개념의 작동 방식 자체인 물리적 물건을 만들어 낸다는 것이다.

README가 드는 대응은 이렇다.
변경이 없으면
일을 건너뛰는 캐시 키는 모든 핀이 맞을 때만 돌아가는 핀 텀블러 자물쇠가 되고,
하나의 GPU 컨텍스트가 여러 캔버스를 맡는 구조는 인쇄
헤드 하나가 16개의 우물을 도는 갠트리 플로터가 된다.
그다음 에이전트는 이 물건을 수십 개의 작고 단단하고
음영이 들어간 부품으로 지어 제목과 힌트와
실시간 수치가 있는 프레임 카드에 넣는다.
포인터와 키보드에 차분하게 반응하게 만들고 모든 이음매를 확대해 스스로 점검한다.
그림에 나오는 모든 숫자는 부품을 움직이는 같은 작은 모델에서 나온다.

| 항목        | 내용                                                        |
| ----------- | ----------------------------------------------------------- |
| 형태        | Agent Skill 폴더(`SKILL.md`), 의존성 없음                   |
| 필요 환경   | Node.js 20.10 이상, 점검용으로 Chrome 또는 Chromium         |
| 라이선스    | MIT                                                         |
| 저장소 생성 | 2026년 10월 8일                                             |
| 스타와 포크 | 스타 16,963, 포크 1,293 (2026년 10월 20일 확인)             |
| 산출물      | 독립 실행 HTML, 단독 `.svg`, React/Next.js 컴포넌트, A4 PDF |

## 만들어 내는 것

세 가지 종류의 그림이 같은 키트와 같은 카메라와 같은 제작 규칙을 공유한다.

| 종류        | 설명                                                                                                | 예시                                                            |
| ----------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| SVG         | 핵심이다. 네 톤 음영의 등각 입체 부품을 뒤에서 앞으로 칠하고 실시간 수치와 부드러운 움직임을 넣는다 | `dial-indicator`, `desk-computer`, `arcade-cabinet`, `test-rig` |
| SVG와 WebGL | 선으로 그릴 수 없는 불꽃, 배기, 물, 빛, 증기를 같은 등각 카메라 안에서 셰이더로 그린다              | `raptor-engine`, `ripple-tank`                                  |
| 3D(베타)    | 다이얼, 턴테이블처럼 진짜 3D로 도는 부품을 매 프레임 다시 투영하고 음영을 입힌다                    | `turning-dial`                                                  |

모든 그림은 밝은 테마와 어두운 테마가 있고 스킬은 밝은 테마를 먼저 설계한다.
셰이더가 없어도 SVG만으로 읽히고 움직임을 줄이는 설정에서는 모든 그림이 멈춘다.

## 동작 방식

### 스킬이 에이전트에게 요구하는 작업 순서

`SKILL.md`는 에이전트가 따르는 순서를 열 단계로 정한다.
크기 정하기, 진짜 숫자 모으기, 물건 고안하기, 부품 목록 쓰기, 세계 계획하기,
기하를 키트로 한 번 만들기, 뒤에서 앞으로 칠하기,
카드로 프레이밍하기, 움직임 넣기, 비평가처럼 검증하기다.

첫 단계의 크기 규칙이 눈에 띈다.
Figure는 한 가지 메커니즘에 부품 40~80개이며
묻지 않고 만들고 시간은 사용자에게 말하지 않는다.
Hero는 촘촘한 물건에 부품 80~150개로 약 2~4시간이 걸린다고 알린 뒤 만든다.
Epic은 차량이나 건물 전체처럼 여섯 시간 이상 걸리는 것이어서
시작하지 않고 견적과 Hero 버전 제안을 먼저 낸다.
어떤 크기든 첫 한 시간 안에 브라우저에서
열리는 페이지를 만들고 거기서부터 깊이 다듬으라는 규칙이 있다.

물건을 고안하는 단계에서는 이 스킬이 막으려는 두 가지 실패를 명시한다.
너무 추상적이면
쌓인 판이나 떠 있는 슬랩이나 라벨 붙은 상자가 아무것도 읽히지 않고,
너무 납작하고 밋밋하면 부피도 부품도 발견할 것도 없다.
둘 다 알아볼 수 있는 기계를 작고 정밀하고
목적 있는 많은 부품으로 짓는 것으로 푼다는 것이다.

### 키트와 검증이 품질을 기계적으로 보증한다

`kit/`은 그림을 짓는 라이브러리다.
등각 카메라와 입체와 부품 라이브러리(`iso-kit`),
어느 축에서든 둥근 부품(`lathe.mjs`), 파이프와 케이블(`tube.mjs`),
WebGL 층(`gl.mjs`), 3D 런타임,
React 컴포넌트로 이루어지고 React를 제외하면 의존성이 없다.

검증은 두 갈래로 이루어진다.
`kit/audit.mjs`는 기하를 증명한다.
어떤 것도 다른 것을 관통하지 않고, 모든 끝이 마운트에 놓이고,
모든 겹침이 깊이 순서대로 그려졌는지 확인하고 `node build.mjs --audit`로 돌린다.
헤드리스 Chrome에서
`scripts/capture.mjs`와 `scripts/drive.mjs`는 스크린샷과 확대와 느린 접촉 시트를
찍고, `scripts/lines.mjs`는 허공에서 끝나는 선을 하나라도 발견하면 실패한다.
스킬은 에이전트에게 자신이 만든 모든 PNG를 읽으라고 지시한다.

README는 예제들이 Node 20.19와 22.11에서
바이트까지 똑같이 다시 빌드되었다고 밝힌다.

## 설치하기

가장 짧은 경로는 skills CLI다.

```sh
npx skills add wheresryan22/anatomy -g -a claude-code
```

`-g`는 사용자 전체에 설치하고, 빼면 현재 프로젝트에 설치한다.
`-a`에는 `claude-code`, `antigravity`, `opencode`, `codex`,
`minimax-code` 가운데 하나를 쓰고 생략하면
어느 에이전트를 설정할지 CLI가 묻는다.
CLI는 예제를 포함해 저장소 전체를 약 10MB 복사한다. 1.7.1 버전의 CLI는 Node
22.20 이상을 요구한다. git으로 설치하려면
에이전트의 스킬 폴더에 저장소를 복제해 `SKILL.md`가
`<스킬 폴더>/anatomy/SKILL.md`에 놓이게 한다.

설치한 뒤에는 에이전트에게 무엇을 설명할지 말한다.

```text
/anatomy explain how a token bucket rate limiter works, interactive
```

Codex에서는 `$anatomy`를 쓴다.
스킬 이름을 부르지 않아도
등각 일러스트나 문서와 블로그용 설명 그림이나 인터랙티브 설명을 부탁하면
에이전트가 스킬을 읽는다.

## 쓰는 법

README는 좋은 그림을 얻는 세 가지 습관을 든다.
첫째, 그림이 아니라 아이디어를 말하고 실제 수치(크기,
개수, 속도, 임계값)를 준다.
둘째, 이미 원하는 기계가 있으면 그 기계 이름과 무엇이 움직여야 하는지를 말한다.
셋째, 그림이 놓일 곳을 말한다.
독립 HTML 페이지인지 단독 SVG인지 React/Next.js 컴포넌트인지,
밝은지 어두운지에 따라 빌드가 다르다.

결과는 직접 소유하는 소스로 온다.
Node 빌드 스크립트와 그것이 쓰는 페이지,
또는 React의 경우 기하 모듈과 정적 그림용 서버 컴포넌트와
움직임용 클라이언트 컴포넌트이고, 키트가 함께 온다.

## 트레이드오프

### 일부러 느리게 만드는 스킬이다

README는 이 스킬이 일부러 느리다고 쓴다.
부품 목록과 기하와 감사와 모든 이음매의 확대 점검이 긴 세션이고,
Raptor 엔진 예제는 빌드에 몇 분이 걸리며
30개 부품의 3D 궤도 감사만 15~20분이 걸린다.
그 대가는 그림에서 선이 허공에서
끝나거나 파이프가 부품을 관통하는 일이 감사로 걸러진다는 점이다.
빠른 개념도가 필요한 사람에게는 이 속도가 맞지 않는다.

### 기계를 그리는 도구이지 차트 도구가 아니다

축과 계열과 데이터 플롯은 없고
숫자는 모델이 움직이는 실시간 수치와 부품의 참 크기와 개수로만 나온다.
사람이나 정확한 지도도 그리지 않으며,
지을 메커니즘이 없는 아이디어는 약해진다는 것이 README가 직접 적은 한계다.
따라서
흐름도나 아키텍처 박스 도표처럼 원래 기계가 없는
대상에는 고안하는 단계가 억지가 될 수 있다.

### 3D 모드는 아직 베타다

3D는 하나의 예제와 시험용 그림 하나에서만 증명되었고
실제 제품의 그림에서는 검증되지 않았다.
작은 3D 그림은 60fps로 돌지만 380개 부품의 스트레스 손은 1440px 너비에서
약 20fps였고 스로틀된 폰 프로필에서는 13~15fps였다.
README는 이를 부하가 큰 기계에서 잰 값이라고 밝힌다.

## 함정

Codex의 샌드박스는 점검용 Chrome의 실행을 막을 수 있다.
그림은 만들어지지만 점검이 실패한다.
README는 명령마다 샌드박스 밖 실행을 승인하거나 `~/.codex/config.toml`에서
허용하거나 일반 터미널에서 직접 점검하는 세 가지 길을 안내한다.
`--sandbox danger-full-access`도 되지만
그 세션의 모든 제한을 풀므로 신뢰하는 프로젝트에만 쓰라고 한다.

Node 20에서는
브라우저 스크립트가 `--experimental-websocket`로 스스로 다시 시작한다.
Chrome이 표준 위치에 없으면 `CHROME_PATH`로 경로를 알려야 한다.

셰이더는 WebGL이 있어야 보이고 없으면 SVG만 읽힌다.

저장소 기여에는 규칙이 있다.
CONTRIBUTING은 코드에 주석을 쓰지 않는다는 규칙과 키트를 바꿀 때 기존
예제가 바이트 단위로 같아야 한다는 규칙을 든다고 README가 밝힌다.

## 확인하기

가장 작은 예제로 설치 없이 동작을 본다.
저장소를 내려받아 `node examples/dial-indicator/build.mjs`를 실행하면
독립 HTML 페이지가 스크립트 옆에 쓰인다.
`--light`를 붙이면 밝은 테마다.
이 문서는 이 명령을 직접 실행하지 않았다.
README의 설명만 읽고 정리한 것이므로,
실제 출력의 품질은 `examples/`에 커밋된 페이지를 열어 확인해야 한다.

자기 프로젝트에서는
에이전트에게 `/anatomy`로 아이디어와 실제 수치와 출력 형식을 주고
만들어진 빌드 스크립트에서
`node build.mjs --audit`가 `audit passed`로 끝나는지와
`node scripts/lines.mjs page.html`이 `line ends: 0`을 출력하는지를 본다.

## 체크리스트

- 설명할 대상에 물리적 메커니즘으로 옮길 수 있는 작동 원리가 있는가.
- 그림에 넣을 실제 수치(크기, 개수, 임계값)를 미리 모았는가.
- 출력 형식(독립 HTML, SVG, React)과 테마를 먼저 정했는가.
- Node 20.10 이상과 Chrome이 있고, Codex라면 샌드박스 설정을 확인했는가.
- 감사와 선 검사가 모두 0으로 끝났는가.
- 몇 시간 걸릴 수 있는 크기의 그림을 의도한 것인가.

## 기억할 원칙

### 그림의 신뢰는 모델 하나가 부품과 숫자를 함께 움직이는 데서 나온다

Anatomy는 그림마다 모든 숫자를 부품을 움직이는 같은 작은 모델에서
뽑으라고 요구한다.
이 구조에서는 수치와 움직임과 캡션이 서로 어긋날 수 없다.
이 문서가 보기에 이 스킬의 값어치는 등각 그림의 예쁨보다 이 구조에 있다.
설명 그림이 읽는 사람을 속이는 방식은 대개
그림과 숫자가 따로 놀 때 생기기 때문이다.
