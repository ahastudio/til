# Hide: 에이전트 10개를 띄우되 사람은 판단만 하게 하는 멀티 에이전트 IDE

<https://withhide.dev/>

<https://github.com/with-hide/hide>

## 소개

Hide는 Claude Code, Codex 같은 코딩 에이전트 여러 개를 한 화면에서
돌리고 지켜보는 데스크톱 앱이다.
홈페이지의 문구는 에이전트 100개 이상을 돌리되
사람이 봐야 할 것만 보여 준다는 것이다.
저장소 README는 같은 것을 멀티 에이전트 IDE라고 부른다.
만든 사람은 LinkedIn 소개글에서 Hide를 ADE(에이전트 개발 환경)의
다음 단계라고 부르고,
Orca와 Herdr 같은 도구를 쓰면서 탭 인터페이스가 에이전트 여러 개를 다루는
부담을 사람에게 떠넘긴다고 느껴서 직접 만들었다고 밝혔다.[^post]
Herdr는 이 저장소에도 별도 문서가 있다.

소개글이 짚는 문제는 이렇다.
탭 10개가 모두 같은 무게로 떠 있으니
어느 탭이 답을 기다리는지, 어느 탭이 끝났는지 열어 봐야 안다는 것이다.
밀도 있는 작업을 서너 개만 돌려도 인지 부하가 크다고 한다.[^post]
이 문서는 Hide를 직접 실행해 보지 않았고,
홈페이지, 저장소 README와 LICENSE, 소개글과 그 댓글에서 읽은 내용만 정리했다.

## 주요 기능

README와 홈페이지가 내세우는 기능을 묶으면 네 가지다.
모두 만든 쪽의 주장이다.

### 사람에게 필요한 것만 올려 주는 Hide AI

Hide AI가 각 세션이 한 일을 읽고 제목, 멈춘 이유, 사람이 물은 것을 적는다.
에이전트는 Needs You, Unread, Working, Seen으로 나뉘고
사람을 기다리는 것이 맨 위에 온다.
Hide AI는 이미 로그인해 둔 에이전트 CLI로 돌아가며,
끄더라도 상태 표시는 그대로 동작한다고 README는 밝힌다.
소개글도 같은 이야기를 한다.
에이전트가 하위 에이전트에게 일을 맡기면 부모만 화면에 남고
사람은 결과와 결정만 받는다는 것이다.[^post]
홈페이지는 이를 부모 터미널 안으로 자식이 접힌다고 설명한다.

### 여러 머신에 걸친 미션

미션을 주면 Conductor 에이전트가 계획을 세우고,
맥, 원격 Windows, Linux 머신에 맞는 에이전트를 배치해 일을 나눈다.
홈페이지의 설명대로면 각 단계는 풀 리퀘스트로 끝난다.
README에는 머신을 SSH 별칭으로 추가하는 명령이 있다.

```sh
hide device add workbox
hide mission help
```

위 두 줄은 README에 있는 명령을 옮긴 것이다.
에이전트가 같은 CLI로 다른 에이전트를 띄우고 편지를 보낼 수도 있다고 한다.

### 에이전트와 무관한 메모리

세션에서 내린 결정이 카드가 되어 다음 에이전트가 시작할 때 들어간다.
README는 어느 벤더의 에이전트든 받는다고 쓰고,
소개글은 Claude Code에서 배운 것을 Codex가 이어받는다고 설명한다.[^post]
README는 카드가 저장소와 대조되고,
남길 만한 규칙은 문서에 대한 풀 리퀘스트 하나로 돌아온다고 덧붙인다.

### IDE로서의 기본기

진짜 터미널 패널, 파일 탐색기와 diff, 작업마다 워크트리 하나,
풀 리퀘스트 목록, 기준 브랜치와 위험한 Git 명령을 지키는 가드레일이 있다.
각 에이전트의 주간 한도와 프로젝트의 최근 7일 비용(API 가격 기준)도 보여 준다.
에이전트가 브라우저를 열어 클릭하고 결과를 읽는 `hide browser` 명령도 있다.

## 설치와 요금

지원 대상은 Apple Silicon의 macOS 14 이상, Windows x64, Linux x64다.
macOS 앱은 서명과 공증을 거쳤고,
Windows 설치 파일과 Linux 패키지는 서명되지 않아서
SHA-256 파일을 확인하라고 홈페이지가 안내한다.
홈페이지는 에이전트 CLI를 먼저 설치하고 로그인해 두라고 한다.
Hide는 에이전트의 인증 정보를 요구하지 않는다고 README는 말한다.

가격은 지금 무료다.
홈페이지는 앱, 모든 에이전트, 모든 머신, 폰까지 무료이고
새 API 키가 필요 없다고 적는다.
소개글도 세 운영체제를 모두 지원하며 무료라고 말한다.[^post]
기업용은 문의로 받으며 팀 공유 미션과 팀 공유 메모리가 들어간다고 한다.
이슈를 통째로 맡기고 풀 리퀘스트만 검토하는 Software Factory는
아직 공개 전이고 대기 목록을 받는다.

라이선스는 FSL-1.1-ALv2다.
LICENSE에 따르면 경쟁 용도를 뺀 모든 목적에 쓸 수 있고,
공개 후 2년이 지나면 Apache 2.0으로도 쓸 수 있다.
홈페이지는 이를 오픈소스 대신 fair source라고 부른다.

## 데이터가 지나가는 곳

README의 설명은 호스팅 서비스가 없다는 것이다.
앱, 코어, Hide AI가 사용자의 머신에서 돌아서
코드는 에이전트 CLI가 원래 보내던 곳으로만 간다고 한다.
다만 한 가지 예외가 적혀 있다.
Hide가 Codex의 `auth.json`에서 접근 토큰과 계정 ID를 읽어
Codex의 사용량 주소로 보낸다는 것이다.

폰 연결은 문서가 서로 다르다.
README는 폰이 사용자의 Tailscale 안에서 머신에 닿는다고 쓴다.
홈페이지는 QR만 스캔하면 되고 계정도 Tailscale도 필요 없으며,
메시지를 종단간 암호화해 도쿄에 있는 Hide의 중계 서버로 보낸다고 쓴다.
중계 서버는 내용을 읽지 못하지만 접속 시각, 트래픽 크기,
기기를 잇는 식별자는 본다고 홈페이지가 직접 밝힌다.
Tailscale은 고급 직접 연결 방식으로 남아 있다고 한다.
어느 쪽이 현재 동작인지는 이 문서가 실행으로 확인하지 못했다.
README가 이전 방식을 말하고 있을 가능성은 있지만, 이는 추측이다.

## 소개글과 문서 사이

소개글은 세 가지를 앞세운다.
사람은 판단만 한다, 여러 머신의 에이전트 팀을 지휘한다,
쓸수록 똑똑해지는 메모리다.[^post]
세 가지 모두 홈페이지와 README에 대응하는 기능이 있다.
소개글은 더 가볍고 빠르다고도 말하지만
이 문장에 수치는 붙어 있지 않다.[^post]
README에는 성능 항목이 있다.
M4 Pro 맥에서 키 입력 후 터미널 버퍼에 아홉 글자가 반영될 때까지
p95 16.3ms, 유휴 시 프로세스 전체 549MiB를 쟀다고 한다.
다만 README 스스로 이 숫자가 한 대의 측정이고,
다른 앱과 같은 작업으로 비교한 것이 아니어서
상대적 속도에 대해서는 아무것도 주장하지 않는다고 적는다.
그러니 더 빠르다는 소개글의 문장은 근거가 공개된 주장이 아니다.

소개글의 규모도 다르다.
글은 에이전트 10개를 말하고,
홈페이지는 100개 이상과 36개가 도는 예시 화면을 보여 준다.
소개글 댓글에는 이미 몇 주 써 봤다는 사람과 일주일째라는 사람의
호평이 올라와 있다.
댓글 대부분은 만든 이의 지인으로 보이는 환영과 축하이고,
불편한 점이나 실패 사례를 적은 글은 읽은 범위에 없었다.[^post]

## 비평

### 사람의 주의력이 병목이라는 진단은 도구가 풀어야 할 몫을 도구에 맡긴다

소개글의 핵심은 병목이 모델이 아니라 사람의 주의력으로 옮겨 왔고
이를 시스템이 맡아야 한다는 것이다.[^post]
이 진단 자체는 설득력이 있다.
그런데 Hide AI가 올려 줄 것을 고르는 일은 다시 모델의 판단이다.
무엇이 사람이 볼 일이고 무엇이 아닌지를 틀리게 가려내면,
가장 위험한 것은 올라오지 않은 쪽이다.
홈페이지는 이를 끌 수 있다고 하고 README도 상태 표시는 그대로라고 하지만,
Hide AI가 놓친 비율을 재는 방법은 어디에도 없다.
주의력을 아끼는 도구일수록 놓친 것을 어떻게 알아챌지가 설계에 들어가야 한다.

### 무료와 fair source 사이에는 시간표가 있다

지금은 모두 무료이고 기업 요금은 문의다.
LICENSE는 경쟁 용도를 막고 2년 뒤 Apache 2.0으로 바꾼다.
이 구조에서 Hide를 사내 도구로 쓰는 것은 문제가 없어 보인다.
반면 Hide 위에 비슷한 제품을 만들려는 쪽은 막힌다.
또 README의 기여 안내는 풀 리퀘스트를 관리자와 승인된 기여자만 열 수 있다고 한다.
저장소는 열려 있어도 개발은 닫힌 쪽에 가깝다.
무료 기간이 언제까지인지는 어디에도 쓰여 있지 않다.

### 문서가 서로 어긋난 곳이 있다

폰 연결이 그 예다.
빠르게 바뀌는 제품이라 문서의 한쪽이 뒤처졌을 수 있다.
그러나 데이터가 어디로 가는지에 대한 설명은
처음 쓰는 사람이 가장 먼저 읽는 부분이다.
어긋남이 남아 있으면 보안 검토를 하는 쪽에서는 낮은 쪽을 기준으로 삼는다.

## 도입 전에 따져볼 것

- 에이전트 CLI를 이미 쓰고 있는가. Hide는 CLI를 대신하지 않고 그 위에 얹힌다고 홈페이지가 말한다. 기존 설정과 구독이 그대로 유지된다는 점이 장점이자 전제다.
- 폰 연결을 켤 것인가. 켜면 도쿄 중계 서버를 지난다. 접속 메타데이터가 거기 보인다는 점을 보안 기준과 맞춰 본다.
- Codex 접근 토큰을 앱이 읽는 것을 받아들일 수 있는가. README가 밝힌 유일한 예외다.
- Windows와 Linux 패키지는 서명되지 않았다. SHA-256 확인을 절차에 넣는다.
- 한 프로젝트에서 에이전트 서너 개로 먼저 시험한다. 소개글이 말한 인지 부하가 줄어드는지는 자기 작업으로만 알 수 있고, Hide AI가 올리지 않은 세션을 가끔 직접 열어 놓친 것이 없는지 대조한다.
