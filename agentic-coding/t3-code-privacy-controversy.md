# T3 Code 개인정보 논란과 Theo의 창업 이력

트윗: [把 T3 Code 这次隐私争议，放进 Theo 过去五年的创业经历里看，还挺有意思。](https://twitter.com/zujingpgg/status/2125421142471319788)

## 요약

Jenzin(`@zujingpgg`)이 2026년 11월 25일에 올린 중국어 트윗이다.
T3 Code의 개인정보 논란을, 이 제품을 만든 Theo의 지난 5년 창업 경력에 놓고 보면
흥미롭다는 말로 시작한다.

트윗은 먼저 이력을 짚는다.
Theo는 Twitch에서 엔지니어로 일했고,
2021년에 동료와 Ping Labs를 세워 다음 해 YC W22에 들어갔다.
첫 제품은 스트리머의 연결 방송 도구인 Ping.gg였다.
2023년에는 파일 업로드 때문에 고생한 경험에서 UploadThing을 만들었다.

그다음 트윗이 보는 Theo의 강점은 코드 실력이 아니라 창업 방식이다.
그 방식은 다음 세 가지다.

- 날카로운 YouTube 영상으로 개발자의 관심을 끈다
- 문제가 보이면 빠르게 제품을 만든다
- 자기 콘텐츠의 영향력으로 초기 사용자를 모아 고객 확보 비용을 줄인다

트윗은 이 방식이 가벼운 개발 도구에는 잘 맞는다고 인정한다.

문제는 T3 Code가 Claude Code와 Codex를 부르고
개발 환경을 원격으로 조종할 수도 있는 제품이라는 점이다.
트윗은 논란이 된 세 가지를 든다.
- 기본으로 켜진 텔레메트리(telemetry)
- 로컬 인증 설정을 읽어 사용자 식별자를 만드는 동작
- 원격 연결의 신뢰 경계

결론은 이렇다.
콘텐츠 제작자는 속도와 관점으로 주목을 얻을 수 있지만,
파일을 읽고 명령을 실행하는 에이전트 도구는 속도와 사용 경험만으로 부족하다.
사용자가 개발 환경을 맡길 때 믿는 것은 코드 실력만이 아니라는 말로 끝난다.

게시 시점의 조회수는 6,144이다.
트윗 아래 답글 하나(`@GaoXiaoxiao2022`)는 영상으로 쌓은 관심은
개인정보 논란이 터지면 의심을 오히려 키우고, 이번에는 속도가 도움이 되지
않는다고 적었다.

## 분석

### 트윗의 논증 구조

트윗은 두 개의 전제를 이어 결론을 낸다.

첫째 전제는 Theo의 방식, 곧 콘텐츠로 신뢰와 관심을 먼저 얻고
제품을 빨리 내는 방식이 UploadThing 같은 가벼운 도구에서 효과를 냈다는 것이다.

둘째 전제는 T3 Code가 다루는 권한의 종류가 다르다는 것이다.
파일 읽기와 명령 실행, 원격 제어가 가능한 도구는 잘못 만들었을 때의 피해가 크다.
결론은 같은 방식이 이 종류의 제품에서는 통하지 않는다는 것이다.

트윗이 암묵적으로 놓은 기준은 신뢰의 근거가 제품마다 다르다는 점이다.
파일 업로드 서비스는 기능이 맞으면 되지만,
에이전트 도구는 사용자의 인증 정보와 작업 환경에 닿으므로
만든 사람이 무엇을 수집하는지가 선택 기준이 된다.

### 논란의 실제 내용

트윗은 논란의 세 항목만 이름으로 부르고 근거를 달지 않는다.
이 저장소의 [T3 Code](t3-code.md) 문서가 정리한 코드 분석은 이 중 일부와
맞닿는다.
서버 코드의 텔레메트리 환경 변수 기본값이 켜짐이고,
설치 수를 세려고 로그인한 OpenAI와 Claude 계정을 해시해서 보낸다는 내용이다.
같은 문서는 꺼도 브라우저 웹 앱의 연결 추적이 남을 수 있다고 적는다.

Hacker News의 한 사용자는 v0.1.11을 새로 설치하고 mitmproxy로 트래픽을 보았다.
실행하고 약 10초 뒤, 아무것도 하지 않았는데
OpenAI와 Claude 계정 ID의 해시가 `ingest.t3.codes`로 전송되었고,
자기 계정 ID를 해시해 비교하니 일치해서 솔트(salt)가 없다고 했다.[^devhouse]
프롬프트, 코드, 파일 이름이나 경로는 보내지 않았고,
`T3CODE_TELEMETRY_ENABLED=false`를 설정하면 사용 통계는 멈췄지만
식별자 없는 추적 요청 하나는 Axiom으로 남았다고 한다.[^devhouse]
이 사용자는 뒤에 T3 Code 쪽이 문제를 알고 로그인 정보를 읽지 않는
임의의 설치 ID로 바꾸려 한다고도 적었다.[^devhouse-reply]

GitHub 기록이 이 관찰을 뒷받침한다.
계정 ID를 읽는 동작은 10월에 병합된 PR #21506으로 들어왔고,[^pr21506gh]
트윗이 올라온 11월 24일에 병합된 PR #42299로 제거되었다.
제거한 PR의 설명은 사용자가 그 제공자에 로그인한 것은 T3 Code가 식별하라고 한
것이 아니었고
해시에 솔트도 없었다고 인정한다.[^pr42299gh]
이 논란의 최초 글로 보이는 11월 24일의 트윗과 GitHub 기록을 항목별로
대조한 결과는
[T3 Code 텔레메트리 소스 조사](t3-code-telemetry.md)에 있다.

## 비평

### 트윗이 제시하지 않은 것

트윗은 논란의 내용을 요약할 뿐 출처를 달지 않는다.
읽는 사람은 세 항목이 실제로 어떤 동작인지, 어느 버전에서 그랬는지,
이후 고쳐졌는지를 트윗만으로는 알 수 없다.
같은 시기 Hacker News의 관찰은 해시 전송은 확인했지만
읽은 정보가 해시된 계정 ID에 그쳤다는 점도 함께 적었다.[^devhouse]
트윗이 말하는 신뢰 경계 문제는 이 관찰이 다루지 않은 별개의 주제다.

### 전기적 이력에서 보안으로 가는 비약

트윗은 창업 방식의 성격에서 제품의 신뢰성 한계로 건너간다.
그러나 텔레메트리 기본값이나 식별자 설계가 제품의 결정이라면,
그 원인을 창업자의 콘텐츠 중심 방식에서 찾는 것은 추론이다.
트윗은 이 연결을 증거로 보이지 않는다.
검색에서 확인한 범위는 Ping Labs가 2021년에 세워져 YC W22에 참여했고
Twitch 경력이 있다는 이력 정도이며, 이 문서는 해당 페이지를 직접 열어 대조하지
않았다.

### 논란을 보는 다른 시각

Hacker News의 다른 사용자는 해시된 계정 ID는 고유 사용자를 세려는 것이니
앱 사용 횟수를 세는 정도이고 무엇이 문제인지 되물었다.[^jiveturkey]
이에 대해 위 실험자는 기기 사이에서 사용자를 세려는 의도는 이해하지만,
다른 서비스의 로그인 정보로 식별자를 만드는 방식이 이상하다고
답했다.[^devhouse-reply]
논란의 핵심은 수집량보다 다른 서비스의 인증 정보를 식별자의 재료로 쓴
선택이었다.
트윗은 이 구분을 하지 않고 로컬 인증 설정을 읽는다는 한 줄로 묶는다.

## 인사이트

### 식별자의 재료

에이전트 도구의 개인정보 평가는 수집 항목만이 아니라
식별자를 무엇으로 만드는지를 본다.
임의의 설치 ID와 로그인 계정의 해시는 같은 횟수를 세어도 다른 위험을 만든다.

### 끄기 스위치의 범위

텔레메트리를 끄는 스위치가 모든 클라이언트를 끄는지 확인한다.
Hacker News에서 안드로이드 앱을 포크해 텔레메트리를 없앤 사용자는
Little Snitch로 보면 끌 방법이 없는 것처럼 보였다고 적었다.[^iloveyoutwo]
이 저장소 문서가 정리한 대로 서버, 웹, 모바일의 끄는 범위가 다르다.

### 트윗의 성격

이 트윗은 사실 보도가 아니라 논평이다.
논란을 판단하려면 트윗이 아닌 코드와 트래픽 관찰, 그리고 이후 릴리스 변경을 직접
확인한다.

### 임의 설치 ID 전환의 범위

임의 설치 ID로의 전환은 현재 main에서 PR #42299로 확인된다.
이 문서가 확인하지 못한 것은 정식 릴리스에 이 변경이 들어갔는지,
그리고 서버 환경 변수를 꺼도 남는 요청이 있는지다.
기본값을 켜짐으로 둔 정책 자체는 그대로여서 쟁점은 남아 있다.

### 함께 읽을 문서

[T3 Code와 Happy 비교](t3-code-vs-happy.md)는 데이터가 나가는 곳을 비교해 정리했다.
