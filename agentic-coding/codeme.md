# codeme: 에이전트 작업 공간 앱

<https://codeme.team/>

Show GN: [Claude Code와 Codex를 한 화면에서 관리하는 macOS 개발 도구를 만들었습니다](https://news.hada.io/topic?id=37400)

## 소개

codeme는 여러 Claude Code와 Codex 에이전트를 나란히 돌리는 데스크톱 앱이다. 사이트는 Git 워크트리, diff, 터미널, 테스트, Docker, 데이터베이스 보기, 디버거, 에이전트 세션을 한 창에 모은다고 소개한다.
이 문서는 사이트의 첫 화면, 내려받기, 릴리스 페이지와 GeekNews Show GN 글을 읽었다. 직접 설치해 써 보지 않았고 GitHub 저장소는 연결되어 있지 않아 소스는 보지 못했다. 릴리스 페이지는 길이 때문에 일부가 잘려 최신 부분(v1.7.2부터 1.2.x)만 원문대로 읽었다.
설명은 모두 제작자의 주장이다.

Show GN 글에서 제작자는 에이전트마다 자기 Git 워크트리를 주고 진행 상황과 코드 변경을 한 창에서 보여 준다고 적는다. 기능으로 여러 에이전트 실행, 워크트리 생성과 관리, 에이전트가 바꾼 것만 보기, 터미널과 테스트와 Docker와 DB 연동, GitHub와 Jira 연결, 계정과 서버 없는 로컬 동작을 든다. 기존 IDE와 함께 쓰는 것을 전제하고 의견을 구한다.

사이트와 릴리스 페이지가 적은 내용은 다음과 같다.

- 기술: Tauri 2로 만든 데스크톱 앱이고 로컬 우선이다. 외부 호출은 「내 작업」 패널을 위한 GitHub, Forgejo, Jira, Bitbucket API뿐이다.
- 에이전트: Claude Code와 Codex가 중심이고 v1.3.0부터 Kiro도 있다. 에이전트 CLI는 `PATH`에 이미 있어야 한다.
- 플랫폼: macOS 13 이상(Apple Silicon과 Intel)과 Linux x86_64 AppImage(Ubuntu 22.04 이상)이다. Windows는 아직 없다고 내려받기 페이지가 적는다. Git이 필요하다.
- 버전: 현재 v1.7.2(2026년 11월 17일)이고 첫 공개 빌드 1.0.1은 2026년 7월 18일이다. 11월에는 한 주에 여러 번 릴리스한다.
- 라이선스와 가격: 어떤 페이지에도 없다. 푸터에는 저작권 표시만 있다.

## 분석

### 중심 주장은 에이전트 병렬 작업을 워크트리로 격리한다는 것이다

에이전트마다 별도 워크트리를 주는 구성은 여러 에이전트의 변경이 섞이지 않게 하려는 설계이다. 같은 문제를 다루는 도구들이 여럿 있다.
이는 글의 서술을 이 문서가 정리한 것이다.

### 기존 IDE 옆에 두는 위치를 택했다

제작자는 IDE를 대체하지 않고 함께 쓴다고 한다. 편집 기능을 새로 만들지 않고 에이전트 관리와 검토에 집중하는 범위 설정으로 읽힌다. 이는 이 문서의 해석이다.

## 비평

### 차별점이 불분명하다는 지적이 있다

GeekNews의 유일한 댓글은 이미 많은 에이전트 개발 환경이 있어서 차별점이 필요해 보인다고 했다.[^choyongjoon]
사이트는 비교표나 다른 도구와의 차이를 싣지 않는다. 이 문서는 같은 영역의 다른 도구를 비교하지 않았다.

### 오픈소스 여부와 가격이 확인되지 않는다

저장소가 없고 라이선스와 요금이 적혀 있지 않아 어떤 조건으로 쓰는지 알 수 없다. 로컬 우선과 계정 없음은 사이트의 주장이고 이 문서가 검증하지 못했다.
에이전트 CLI의 인증 정보와 코드가 앱을 거치는 방식에 대한 보안 설명도 읽은 범위에 없다.

### 빠른 릴리스의 안정성은 알 수 없다

2026년 7월 이후 1.7까지 빠르게 올라왔고 최근엔 주마다 여러 번 릴리스하는데, 변경 내용의 품질과 호환성은 읽은 범위에서 판단할 수 없다.

### 외부 반응

Show GN 글에는 댓글이 하나 있다. HN과 Lobste.rs에는 `codeme.team` 주소로 올라온 글이 없었다(HN 대조 쿼리는 정상이었고 Lobste.rs 도메인은 404였다).

## 인사이트

### 가져갈 것은 에이전트마다 워크트리를 주는 격리 방식이다

여러 에이전트를 병렬로 돌릴 때 작업 디렉터리를 나누면 변경과 테스트가 섞이지 않는다. 도구 없이도 `git worktree`로 시험할 수 있는 습관이다. 이는 이 문서의 적용이다.

### 도입 전에 조건을 확인한다

라이선스, 가격, 코드가 외부로 나가는 경로, 지원 플랫폼(Windows 없음)을 먼저 확인한다.

### 확인할 관찰

이 도구의 주장을 가를 관찰은 세 가지이다.
같은 영역의 다른 도구와의 기능 차이,
소스 공개와 라이선스 조건,
에이전트 CLI 버전이 바뀔 때의 호환 유지이다.
셋 모두 이 문서가 확인하지 못했다.
