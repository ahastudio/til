## 요약

ConvAI Innovations의 창업자 Nandakishor Mukkunnoth가 쓴 글이며,
두 가지를 동시에 한다.
자기가 1년 먼저 같은 개념을 만들었다는 우선권 주장과, 그것을 다시 만든 오픈 모델 Laya의 공개다.

주장의 뼈대는 이렇다.
2025년 3월에 arXiv 논문(2503.23303)을 냈고,
Hugging Face에 모델 가중치를 올렸고, 공개 데이터셋을 냈고, PyPI 패키지를 만들었고,
r/LocalLLaMA에 접근법 전체를 올렸다.
2025년 9월에는 강화학습으로 유도되는 스키마 기반 결정을 형식화한 두 번째 논문(2510.01237)을 냈다.

그리고 2026년 9월, 자금이 넉넉한 프런티어 연구소 TypeSafe AI가 Jev를 내놓으면서
정확히 같은 비자기회귀 결정 개념을 완전히 새로운 과학적 돌파구인 것처럼 제시했다는 것이다.
기술 논문도, 공개 가중치도, 공개 학습 데이터셋도 없이 출시했다고 저자는 적는다.

자신의 옛 모델은 PPO를 시퀀스 표현 위에 적용해
수직적 영업 대화에서 턴 단위 전환 확률을 출력했고,
Jev는 병렬 샘플링을 일반화해 신뢰도 분포와 스키마 선택을 수평으로 출력하며
입력 100만 토큰당 0.042달러에 응답 시간은 150밀리초 안팎이라고 정리한다.

씁쓸함에 머무르는 대신 옛 접근의 구조적 한계를 전부 고쳐
완전히 열린 수평적 System 1 결정 모델군을 만들었다는 것이 Laya다.
양방향 인코더 위에 제대로 올렸기 때문에 단일 GPU에서 32.8밀리초,
배치 시 질문당 7.2밀리초로 동작하며 Jev보다 6~8배 빠르고,
100개 이상 언어를 지원하며, API 구독료가 없고, Apache 2.0 가중치를 공개한다고 적는다.

## 세 가지 결정 원시 타입

Laya는 임의의 상태에 대해 타입이 붙은 질문을 단일 순전파로 평가한다.
상태는 원시 텍스트든 이메일이든 티켓이든 JSON 문서든 된다.

| 원시 타입 | 동작                                                                         |
| --------- | ---------------------------------------------------------------------------- |
| `choice`  | 기준 사전에서 하나를 고른다. 선택된 키와 전체 분포, 보정된 신뢰도를 돌려준다 |
| `score`   | 순서 척도 위에 놓는다. 기대 수준과 등급별 분포, 신뢰도를 돌려준다            |
| `noul`    | 참 거짓 질문에 보정된 P(true)를 돌려준다. P(false)는 구성상 1에서 뺀 값이다  |

출력 공간이 확률과 숫자뿐이므로 모델은 텍스트를 생성하지 않고,
환각을 일으킬 수 없으며, 스키마 위반이나 깨진 JSON이 물리적으로 불가능하다는 것이 저자의 설명이다.

## 세 개의 체크포인트

| 체크포인트                               | 백본                   | 파라미터 | 컨텍스트      | 주 용도                                    |
| ---------------------------------------- | ---------------------- | -------- | ------------- | ------------------------------------------ |
| `convaiinnovations/laya`                 | ModernBERT-large       | 421M     | 512           | 영어 분류, 가드레일, 이메일 분류           |
| `convaiinnovations/laya-multilingual`    | mmBERT-base(256k 어휘) | 322M     | 1024(최대 8k) | 100개 이상 언어, 2.2배 빠름, 교차 언어 NLI |
| `convaiinnovations/laya-typed-decisions` | ModernBERT-large       | 421M     | 1024          | 에이전트 관측, 고객 응대, 보안 알림        |

세 체크포인트를 하나의 저장소에 묶고 Hugging Face의 `allow_patterns`로
필요한 하위 폴더만 내려받게 한 점이 실무적 배려다.
2.5기가바이트 전부가 아니라 영어 모델이면 약 808메가바이트,
다국어면 약 647메가바이트만 받는다.

## 라우팅이 필요한 이유

이 글에서 가장 값진 실증은 51개 언어 MASSIVE 벤치마크 결과다.
선택지 20개이므로 무작위 기준선이 0.050인데, 영어 모델이 라틴 문자 밖에서 어떻게 무너지는지를 보여 준다.

| 언어       | 정확도 | 평균 신뢰도 |
| ---------- | ------ | ----------- |
| 크메르     | 0.000  | 0.952       |
| 아르메니아 | 0.050  | 0.885       |
| 히브리     | 0.060  | 0.964       |
| 벵골       | 0.080  | 0.945       |
| 힌디       | 0.100  | 0.941       |

크메르어에서는 100문제 중 하나도 맞히지 못하면서 신뢰도 95퍼센트를 보고한다.
51개 언어에 걸쳐 영어 체크포인트의 평균 신뢰도는 정확도가 82퍼센트든 0퍼센트든 0.885 아래로 내려가지 않는다.

저자가 끌어내는 결론이 중요하다.
모델 자신의 신뢰도는 입력을 읽지 못할 때 아무 경고도 주지 않으므로 신뢰도 게이팅으로는 보호할 수 없다.
어느 모델을 쓸지는 순전파 이전에 결정되어야 한다.

그래서 Laya는 순수 파이썬 라우터를 내장한다.
22개 문자 체계의 유니코드 스크립트를 살피고 라틴 문자의 불용어 분포를 분석하는데,
영어 텍스트 0.09밀리초, 인도계 문자 0.54밀리초,
200행짜리 중첩 JSON 문서 0.73밀리초의 오버헤드가 든다.
33밀리초 순전파에 비하면 2퍼센트 미만이다.
`Router(preload=True)`로 모델을 메모리에 상주시키면
언어가 번갈아 들어올 때 생기는 7~10초의 콜드 스왑 벌점도 사라진다.

## Jev와의 직접 비교

저자는 Laya 수치는 직접 측정했고 Jev 수치는 제3자 독립 연구와 TypeSafe AI가 공개한 값이라고 밝힌다.

| 항목                    | Jev 1.13.0       | Laya(라우팅)       |
| ----------------------- | ---------------- | ------------------ |
| typed-decisions 2,000건 | 0.727            | 0.766              |
| AG News 4개 레이블      | 0.910            | 0.950              |
| DAIR Emotion 6개 레이블 | 0.480            | 0.595              |
| 보정 오차(ECE)          | 0.246            | 0.081              |
| 지연 P50 질문 1개       | 236~276ms        | 32.8ms             |
| 지연 P50 질문 10개 배치 | 약 1,500ms(직렬) | 72.3ms             |
| 100만 토큰당 비용       | 0.042달러        | 0달러(자체 호스팅) |
| 가중치                  | 비공개 API       | 공개 safetensors   |

실제 업무 흐름 아홉 가지에 대한 수치도 함께 낸다.
Enron 스팸 분류 0.993, 피싱 탐지 0.980,
ToxicChat 가드레일 0.755~0.762이며 선택적 커버리지 50퍼센트에서는 0.931에 이른다.
RAG 구절 관련성 0.657, 10방향 지원 티켓 라우팅 0.522다.

## 저자가 스스로 밝힌 한계

글에는 솔직한 한계 절이 있고, 이것이 나중에 논쟁의 중심이 된다.

선택지가 20개를 넘으면 `choice` 질문의 품질이 떨어진다.
Banking77처럼 레이블이 77개인 스트레스 시험에서 Laya는 0.425를 기록했고 Jev는 0.870이었다.
선택지들이 192~256 토큰의 헤드 예산을 나눠 쓰기 때문에
77개에서는 후보당 3~4 토큰만 남는다는 구조적 제약이다.
저자는 선택지를 20개 아래로 두거나 두 단계 계층을 쓰라고 권한다.

더 중요한 한계는 미세 조정이다.
기본 모델을 그대로 쓰면 typed-decisions 벤치마크에서 약 0.35로 거의 무작위 수준이며,
0.766은 그 벤치마크의 학습 분할로 미세 조정해 얻은 값이다.
저자는 Laya를 전지적 제로샷 신탁이 아니라 특화시킬 빠른 기반 모델로 다루라고 적는다.

온도 보정도 직접 해야 한다.
기본 가중치는 원시 온도 로짓으로 배포되며,
질문 유형별로 스칼라 하나를 자기 도메인 분포에 맞추면 기대 보정 오차가 0.466에서 0.081로 떨어진다.

## 분석

### 우선권 주장과 제품 발표가 한 글에 섞여 있다

이 글의 구조적 특이점은 두 목적이 하나의 문서에 들어 있다는 것이다.
전반부는 누가 먼저였는지를 다투고, 후반부는 오픈 모델의 사양과 벤치마크를 제시한다.

두 부분의 증명 기준이 다르다는 점이 문제를 만든다.
우선권 주장은 개념의 동일성을 보여야 하고, 제품 발표는 성능의 우위를 보여야 한다.
그런데 저자 자신이 밝힌 옛 작업의 성격, 즉 고정된 시퀀스 임베딩과 별도의 PPO 가치망을 쓴
턴 단위 영업 예측이었고 종단 간이 아니었으며
런타임에 새 질문을 처리할 수 없었다는 서술이 전반부의 주장과 충돌한다.

Lobste.rs에서 sunshine이 정확히 이 대목을 인용하며 물었다.
런타임에 동적으로 새 질문을 받는 것이 Jev의 핵심 판매 포인트 아니냐는 것이고,
그렇다면 저자의 모델은 전통적 분류기에 더 가까운 것 아니냐는 지적이다.
제목이 다소 오해를 부른다고 느꼈다고 적었다.[^sunshine]

### 브랜딩이 기술만큼 중요했다는 진단

HN에서 가장 많이 추천받은 반응은 기술 비교가 아니라 전달의 문제를 짚었다.

johnfn은 사람들이 마케팅과 브랜딩이 제품만큼, 어쩌면 그보다 중요하다는 것을 이해하지 못하는 일이 반복된다고 적었다.
Jev는 웹페이지를 보는 누구나 무엇이고 무엇을 뜻하는지 즉시 이해할 만큼 브랜딩이 탁월한 반면,
저자의 마케팅은 “순수 강화학습으로 대화에서 판매 전환 확률 예측하기”라는
레딧 글 하나가 전부였다는 것이다.
그리고 그 제목이 무슨 뜻인지, Jev와 같은 함의를 갖는지 자신도 모르겠다고 덧붙였다.
Jev가 그냥 BERT라는 말은 드롭박스가 curlftpfs로 마운트한 FTP 계정일 뿐이라는 말과 같다고도 적었다.[^johnfn]

calebkaiser는 이것이 머신러닝에서 특히 흔한 현상이라며
슈미트후버가 당신의 아이디어를 37년 전에 어느 일본 언어학 저널에서 제안했다고 알리는 일을 농담으로 부른다고 적었다.[^calebkaiser]

mixedbit는 더 실질적인 지점을 짚는다.
arXiv에 논문을 올리는 것만으로 인정과 인용을 기대할 수 있느냐면 그렇지 않으며,
arXiv는 심사받지 않은 논문이 대량으로 쌓이는 공개 저장소라
머신러닝 같은 인기 분야에서 전문가가 우연히 발견해 가치를 알아보기를 바라는 것은 희망 사항이라는 것이다.[^mixedbit]

### Jev가 판 것은 모델이 아니라 사용 방식이었다

여러 댓글이 같은 결론에 독립적으로 도달했다.
Jev의 기여가 아키텍처가 아니라 인터페이스와 운영 모델이었다는 것이다.

hmokiguess는 Jev가 System One이라는 용어를 만들고
표준 응용 인터페이스와 핵심 원시 타입을 정의해
지금의 소프트웨어 개발 패러다임에 안착시킨 점을 잘했다고 평했다.
Cursor가 자동 완성을 다른 사용자 경험으로 재발명하자 모두가 쓰게 된 것과 비슷하다는 비유다.[^hmokiguess]

soerxpso는 더 실무적으로 말한다.
Jev는 미세 조정을 요구하지 않으며,
작은 라우팅이나 분류 문제가 생길 때마다 데이터셋을 만들고 모델을 미세 조정하고
인프라를 세우는 데 일주일을 쓰고 싶지 않다는 것이다.
임의의 분류 문제를 일주일이 아니라 몇 분 만에 처리할 수 있다는 것이 큰 차이라고 적었다.[^soerxpso]

ianbutler는 같은 말을 더 날카롭게 한다.
요점은 저자의 머신러닝 실력이 아니라 개발자가 제품에 얼마나 쉽게 끼워 넣을 수 있는가이며,
자신은 2019년에 이미 수많은 커스텀 BERT를 학습시켜
하루 수억 건의 문서에 돌렸지만
이제는 GPU를 관리하고 말뭉치를 유지하고 데이터 분포가 바뀔 때마다 재학습하고 싶지 않다는 것이다.[^ianbutler]

## 비평

### 미세 조정 요구는 한계 절이 아니라 첫 문단에 있어야 했다

여러 댓글이 같은 문장을 인용했다.
기본 모델이 0.35로 거의 무작위이고 0.766은 미세 조정 후 값이라는 서술이다.

cjalmeida는 이것이 글의 훨씬 위쪽에 있어야 하며,
좋은 결과를 내기 위해 미세 조정이 필요하다는 점이 Laya를 Jev와 완전히 다른 범주에 놓는다고 적었다.[^cjalmeida]
woah는 이것을 거대한 누락이라고 불렀다.[^woah]

이 비판이 정당한 이유는 글의 비교표가 그 조건을 표시하지 않기 때문이다.
typed-decisions에서 0.766 대 0.727로 이겼다는 행은
한쪽은 그 벤치마크의 학습 분할로 미세 조정했고 다른 쪽은 하지 않았다는 사실을 담지 않는다.
같은 표의 지연 시간과 비용 비교는 유효하지만 정확도 비교는 조건이 다르다.

저자가 한계를 정직하게 밝힌 것은 미덕이지만,
그 정직함이 표 아래 일곱 번째 절에 놓이면 표를 읽고 지나간 독자에게는 전달되지 않는다.
정직함의 위치가 정직함의 내용만큼 중요하다는 사례다.

### 컨텍스트 길이 차이를 비교표에서 빼놓았다

cube2222는 체크포인트가 512~1024 토큰 컨텍스트인 반면
Jev는 32k로 보인다는 점을 지적하며,
꽤 큰 제약인데 비교에서 더 눈에 띄게 다뤄지지 않은 것이 놀랍다고 적었다.[^cube2222]
druskacik은 Laya의 기반인 ModernBERT가 8192 컨텍스트를 지원하는데도 그렇다는 점이 이상하다고 덧붙였다.[^druskacik]

이 지적은 앞의 것과 같은 성격이다.
비교표가 유리한 축만 담고 있다.
지연과 비용과 보정 오차는 실려 있지만 컨텍스트 길이와 미세 조정 필요 여부는 없다.

baobabKoodaa는 여기서 한 걸음 더 나가 Laya가 Jev의 오픈소스 버전이라는 규정 자체를 문제 삼는다.
작은 오픈 가중치 모델에 작은 컨텍스트 창을 쓰면서
프런티어 지능을 표방하는 Jev의 오픈소스 판이라고 부르는 것은 타당하지 않으며,
저자가 인용하는 논문도 범용 분류기가 아니라 하나의 구체적 사업 문제를 위한 맞춤 해법을 서술한다는 것이다.[^baobabKoodaa]

다만 hbrn의 반론도 같은 자리에 있다.
Jev가 프런티어 지능이라는 증거는 있느냐며,
딸기의 r 개수를 틀리고, 주사위나 동전 던지기 결과에 확률을 제대로 매기지 못하고,
LLM으로 쓰면 자신이 Qwen이라고 생각하고,
선택지 순서를 바꾸면 확률이 최대 20퍼센트까지 달라진다는 관찰을 나열했다.[^hbrn]

### 선행 연구 주장에 또 다른 선행 연구가 겹친다

kamranjon의 댓글이 이 논쟁의 구조를 가장 잘 보여 준다.
현재의 통설은 TypeSafe가 GLiNER의 작업을 다시 포장한 것이라는 쪽이었고,
GLiNER 쪽이 더 가까운 일치이며 그 원논문은 저자의 것보다 몇 해 앞선다는 것이다.
저자가 그것을 알고 있었는지 궁금하다고 물었다.[^kamranjon]

우선권 주장에 대해 또 다른 우선권 주장이 제기되는 이 구도는
개념의 최초 제안자를 특정하려는 시도가 대개 도달하는 지점이다.
lhl도 GLiNER와 GLiFormer 같은 범용 분류기가 이미 있었고
Laya 자신이 ModernBERT 기반이라는 점을 지적했다.[^lhl]

그러므로 이 글의 우선권 주장은 참이든 거짓이든 결정적이지 않다.
결정적인 것은 dcow가 적은 대로다.
Jev와 Laya 모두 수많은 선행 논문과 연구자들의 작업 위에 서 있으며,
Diogo는 그 개념으로 제품을 만들기로 했고 저자는 그러지 않았다는 것이다.
논문과 가중치를 공개하는 일은 학술적으로 느껴지며,
저자의 이력이 의료 분야 AI 적용에 집중되어 있다는 점도 짚었다.[^dcow]

돌파구, 우리 연구는 다른 방향으로 갔다, 2년간 스텔스,

자신은 몇 해 전 BERT 변형으로 같은 기능을 구현했으며,

역량이 이렇게 쉽게 복제되는데 2년을 스텔스로 개발하는 것이 이해되지 않으며,
공개 연구의 유인과 비공개 개발의 유인이 둘 다 침식되는 이상한 시대라고 적었다.[^wren6991]

## 인사이트

### 신뢰도가 읽지 못함을 알려 주지 않는다는 발견이 이 글의 진짜 기여다

우선권 논쟁과 벤치마크 비교를 걷어내면,
51개 언어 실측에서 나온 관찰 하나가 남는다.
크메르어에서 정확도 0에 신뢰도 0.952라는 조합이다.

이 결과가 중요한 이유는 보정된 확률을 내세우는 모델군 전체에 대한 경고이기 때문이다.
보정은 모델이 학습한 분포 안에서 성립하며, 분포 밖에서는 신뢰도가 아무것도 보장하지 않는다.
그러므로 신뢰도 임계값으로 나쁜 출력을 거르는 설계는
분포 안의 애매한 입력은 걸러도 분포 밖의 입력은 그대로 통과시킨다.

실무적 결론은 저자의 것과 같다.
어느 모델을 쓸지는 순전파 이전에 정해져야 한다.
스크립트 판별, 언어 감지, 도메인 판별처럼 모델 바깥의 값싼 검사가
모델 내부의 신뢰도보다 신뢰할 만하며,
이 사례에서 그 비용은 순전파의 2퍼센트 미만이었다.

### 제로샷이 아니면 다른 제품이다

이 논쟁에서 가장 자주 반복된 실무자의 목소리는 정확도 숫자가 아니라 운영 비용에 대한 것이었다.
미세 조정이 필요하면 데이터셋, 학습 파이프라인, GPU, 분포 이동에 따른 재학습이 따라온다.

그래서 같은 정확도를 내는 두 모델이라도
하나가 제로샷이고 다른 하나가 미세 조정을 요구하면 두 제품은 경쟁 관계가 아니다.
전자는 API 호출이고 후자는 프로젝트다.
Laya가 Jev보다 몇 퍼센트 높은 정확도를 보여도
그 수치가 미세 조정 후의 값이라면 비교 대상이 아니게 된다.

이 구분은 오픈 가중치 모델을 평가할 때 일반적으로 적용된다.
가중치가 공개되어 있다는 사실은 총소유비용의 한 항목을 0으로 만들 뿐이고,
다른 항목들, 즉 운영, 학습, 유지의 비용을 사용자에게 옮긴다.
그 이전이 이득인지는 조직의 역량과 규모에 달려 있으며,
0달러라는 표기는 그 이전을 보이지 않게 만든다.

### 같은 개념을 먼저 발표하는 것과 먼저 쓰이게 만드는 것은 다른 일이다

이 사건의 교훈은 저자가 억울한가 아닌가에 있지 않다.
같은 개념이 논문, 가중치, 데이터셋, 레딧 글로 이미 공개되어 있었는데도
아무도 그것을 쓸 수 있는 형태로 인식하지 못했다는 사실에 있다.

차이를 만든 것은 이름과 원시 타입과 API였다.
System One이라는 이름이 무엇을 대체하는지를 한 단어로 설명했고,
`choice`와 `score`와 `noul`이라는 세 원시 타입이 적용 범위를 코드 수준에서 확정했다.
개념이 아니라 이 인터페이스가 채택을 만들었다.

여기서 나오는 실천적 함의는 공개 연구자에게 불리하지만 분명하다.
어떤 작업이 쓰이기를 바란다면 무엇을 만들었는지가 아니라
그것으로 무엇을 할 수 있는지를 호출 가능한 형태로 제시해야 한다.
논문은 기여를 기록하고, 인터페이스는 채택을 만든다.
두 가지는 서로를 대신하지 못한다.
