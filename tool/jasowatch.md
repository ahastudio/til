# Mytory Jaso Watch: Mac에서 온 분해된 한글 파일명을 Windows에서 자동으로 합치는 트레이 앱

Show GN: [맥에서 분해된 자소를 결합. 실시간 폴더 감시, 자동 변환 (윈도우 앱스토어)](https://news.hada.io/topic?id=34261)

## 소개

Mytory Jaso Watch는 Mac에서 만든 파일이 Windows로 넘어왔을 때 자소가 분리돼 보이는 한글 파일명을 자동으로 합쳐 주는 Windows 트레이 유틸리티다.
작성자는 맥과 윈도우를 섞어 쓰는 사무실에서 윈도우를 쓰는데, 맥에서 편집한 파일을 받을 때마다 자소가 분리돼 있어 귀찮았다고 소개한다.
드래그 앤 드롭으로 해결하는 프로그램도, 커맨드라인도, 폴더를 감시하는 프로그램도 있었지만 모두 귀찮아서 AI에게 만들게 했다는 것이다.

Microsoft Store에서 받아 실행하면 다운로드 폴더를 감시하며 자동으로 파일명을 고친다.
GitHub의 `mytory/JasoWatch` 저장소에는 C# 소스와 포터블 EXE 릴리스가 MIT 라이선스로 올라와 있다.
저장소는 2026년 9월 22일에 만들어졌다.

작성자는 만드는 과정의 대부분을 AI에게 맡겼다고 밝힌다.
Microsoft Store의 정보 입력은 ChatGPT Computer Use로 했고, 아이콘도 생성하게 했으며, GitHub 업로드도 AI가 `gh` 명령으로 했다.
스크린샷까지 생성하려 하길래 그것만은 직접 찍겠다고 말렸다고 한다.

## 주요 기능

- 감시 폴더에 새로 들어오는 파일과 폴더의 이름을 확인해, 분해된 이름이면 자동으로 합친다. 기본 감시 폴더는 다운로드 폴더이고 바꿀 수 있다.
- 하위 폴더까지 감시할지 고를 수 있다.
- `.crdownload`, `.part`, `.tmp` 파일과 `~$`로 시작하는 파일은 기본으로 건너뛰고, 제외 규칙은 설정에서 바꿀 수 있다.
- 트레이 메뉴에서 감시를 일시 중지하거나, 이미 폴더에 있던 파일을 한 번에 정리할 수 있다.
- Windows 시작 때 자동 실행이 기본으로 켜져 있다.
- 파일의 내용은 건드리지 않고 이름만 바꾼다.

README가 밝힌 제약은 다음과 같다.
Windows 10과 11의 64비트용이고, 네트워크 공유 폴더와 ARM64나 32비트 Windows는 지원하지 않는다.
같은 이름이 이미 있으면 덮어쓰지 않고 `이름 1.ext`처럼 번호를 붙인다.
호환 자모(`ㅎㅏㄴㄱㅡㄹ`)를 한글로 조합하지는 않고, Unicode 표준 NFC 정규화만 적용한다.
GitHub 릴리스의 EXE는 코드 서명이 없어 SmartScreen 경고가 뜰 수 있다.

## 동작 방식

### 자소가 분리되는 이유

한글 음절 “한”은 Unicode에서 두 가지로 적을 수 있다.
완성형 음절 하나(U+D55C)로 적는 NFC 형태와, 초성 ㅎ, 중성 ㅏ, 종성 ㄴ의 조합용 자모 세 개로 적는 NFD 형태다.
macOS는 파일명을 NFD 형태로 만드는 경우가 많고, Windows는 대부분 NFC를 쓴다.
Windows의 파일 탐색기가 NFD 이름을 조합하지 않고 자모 그대로 보여 주면, 사용자에게는 자소가 분리된 것처럼 보인다.

### 정상화 판정과 이름 바꾸기

판정은 한 줄이다.
`FilenameNormalizer.NeedsNormalization`은 이름을 NFC로 정규화한 결과가 원래 이름과 바이트 단위로 다르면 대상으로 본다.

```csharp
public static bool NeedsNormalization(string name) =>
    !StringComparer.Ordinal.Equals(name, name.Normalize(NormalizationForm.FormC));
```

이름을 바꾸기 전에 `FindAvailableName`이 같은 이름의 파일이나 폴더가 있는지 확인하고, 있으면 번호를 붙인다.
같은 폴더 안의 이름 바꾸기는 폴더별 세마포어로 한 번에 하나씩만 하므로, 두 파일이 동시에 같은 이름을 차지하려는 경합을 막는다.

### 내려받는 중인 파일을 건드리지 않는 방법

감시 폴더에서 이벤트가 오면 `FileNormalizationService`는 바로 이름을 바꾸지 않는다.
1초 동안 같은 경로에 이벤트가 더 오지 않을 때까지 기다리고(디바운스), 그 뒤 파일 크기와 수정 시각을 500ms 간격으로 두 번 재서 같아야 안정된 것으로 본다.
마지막으로 `FileShare.None`으로 파일을 열어 보아, 다른 프로그램이 쥐고 있지 않은지 확인한다.

이 검사를 통과하지 못하면 500ms에서 시작해 두 배씩, 최대 15초 간격으로 다시 시도한다.
10분 안에 끝내지 못하면 실패로 기록하고, 다른 파일의 감시는 계속한다.
기존 파일 일괄 정리는 가장 깊은 경로부터 처리하고, 같은 깊이에서는 파일을 폴더보다 먼저 처리한다.
폴더 이름을 먼저 바꾸면 그 안의 파일 경로가 모두 바뀌기 때문이다.
하위 폴더를 뒤질 때는 재분석 지점(reparse point), 곧 심볼릭 링크나 정션이 가리키는 곳으로는 들어가지 않는다.

## 분석

### 오래된 문제에 같은 해법이 계속 새로 나온다

Mac과 Windows 사이의 한글 자소 분리는 한국 개발자와 사무직이 수십 년 겪어 온 문제다.
GeekNews의 이 글 아래 “함께 보면 좋은 글”에도 윈도우용 C++ 자소 결합 프로그램, 맥에서 자소 분리를 막는 메뉴바 앱, 웹과 CLI로 된 자소 결합 도구가 나란히 걸려 있다.
문제를 푸는 방식은 대부분 같다.
파일명을 NFC로 정규화하고 이름을 바꾸는 것이다.

그런데도 새 도구가 계속 나오는 것은, 차이가 알고리즘이 아니라 “언제, 어디서, 누가 실행하느냐”에 있기 때문이다.
작성자가 기존 도구를 거절한 이유를 보면 이 점이 분명하다.
드래그 앤 드롭은 매번 손이 가고, 커맨드라인은 매번 쳐야 하고, 폴더 감시 도구는 직접 빌드해야 했다.
Mytory Jaso Watch는 정규화가 아니라 이 “귀찮음”을 없애는 데 설계의 무게를 뒀다.

### 이 앱의 코드 대부분은 정규화가 아니라 기다림이다

정규화 자체는 .NET의 `String.Normalize` 한 번이면 끝난다.
그런데 `FileNormalizationService`의 대부분은 디바운스, 크기와 수정 시각의 안정성 검사, 파일 잠금 확인, 지수 백오프 재시도, 폴더별 잠금에 쓰인다.
다운로드 폴더를 자동으로 감시한다는 요구가, 이름 한 줄 바꾸는 일을 동시성 문제로 바꿔 놓았다.

브라우저는 내려받는 동안 `.crdownload`나 `.part` 같은 임시 이름을 쓰고, 끝나면 최종 이름으로 바꾼다.
압축 해제 도구는 많은 파일을 빠르게 쏟아 내고, Office는 `~$`로 시작하는 잠금 파일을 만든다.
이런 순간에 이름을 바꾸면 쓰는 중인 파일을 빼앗거나, 다른 프로그램이 찾던 파일이 사라지는 일이 생긴다.
기본 제외 규칙과 안정성 검사는 이 모든 경우를 “다른 프로그램의 일이 끝날 때까지 손대지 않는다”는 한 원칙으로 다룬다.

### 도메인 언어 문서가 AI가 만든 코드의 품질을 떠받친다

저장소의 `CONTEXT.md`는 코드가 아니라 용어를 정의한다.
감시 폴더, 감시 범위, 분해된 파일명, 정상화 대기, 정상화 실패, 기존 파일명 정리, 이벤트 복구 검사 같은 말마다 정의와 함께 피해야 할 표현까지 적었다.
예를 들어 “분해된 파일명”은 NFC 결과가 원래 이름과 다른 항목으로 정의하고, “깨진 파일명”이나 “호환 자모 파일명”이라는 말은 피하라고 적는다.

작성자가 AI에게 대부분을 맡겼다고 밝힌 점을 떠올리면, 이 문서의 역할이 보인다.
AI 에이전트는 같은 개념을 여러 이름으로 부르거나, 비슷한 개념을 하나로 뭉치기 쉽다.
용어를 먼저 고정해 두면 코드의 이름, 알림 문구, README가 같은 개념을 같은 말로 부르게 되고, 호환 자모를 조합하지 않는다는 범위의 경계도 흐려지지 않는다.

## 비평

### NFC 정규화만으로는 분리된 한글을 모두 합치지 못한다

README는 호환 자모를 조합하지 않고 NFC 정규화만 적용한다고 분명히 밝힌다.
이 경계는 정직하지만, 사용자가 겪는 “자소 분리”가 모두 NFD라는 가정 위에 있다.
어떤 프로그램이 파일명을 조합용 자모(U+1100 영역)가 아니라 호환 자모(U+3131 영역)로 적었다면, 겉보기에는 똑같이 분리된 이름이지만 NFC로는 합쳐지지 않는다.

이 경우 앱은 아무 일도 하지 않고, 사용자는 앱이 동작하지 않는다고 느낄 것이다.
판정 함수는 NFC 결과가 같으면 대상이 아니라고 보므로, 실패로 기록되지도 않는다.
범위를 좁힌 것은 옳은 선택일 수 있지만, 그렇다면 “이 파일은 대상이 아니다”라는 신호를 사용자에게 줄 방법이 필요하다.

### 이름을 바꾸는 쪽이 한 곳만이 아닐 때 충돌이 생길 수 있다

이 앱은 Windows 쪽에서 NFD 이름을 NFC로 바꾼다.
그런데 Mac과 Windows를 섞어 쓰는 사무실에서 파일은 대개 한 번 건너오고 끝나지 않는다.
동기화 폴더나 공유 드라이브를 통해 양쪽이 같은 파일을 계속 주고받는다면, Windows에서 바꾼 이름이 다시 Mac으로 가고, Mac 쪽에서 새 파일로 인식되거나 다른 이름으로 다시 돌아올 수 있다.

README가 네트워크 공유 폴더를 지원하지 않는다고 밝힌 것은 이 위험을 피하는 한 방법이다.
그러나 감시 폴더를 사용자가 바꿀 수 있으므로, OneDrive나 Dropbox 같은 동기화 폴더를 지정하는 것을 막지는 못한다.
동기화 클라이언트가 이름 변경을 어떻게 다루는지는 서비스마다 다르고, 최악의 경우 같은 파일이 두 벌로 늘어나거나 이름이 오가는 일이 생길 수 있다.
다운로드 폴더를 기본값으로 둔 것은 이런 위험이 가장 적은 자리를 고른 것이지만, 감시 폴더를 바꿀 때의 주의점은 README에 적어 둘 만하다.

### 서명 없는 EXE와 Store 배포가 서로 다른 신뢰를 요구한다

작성자는 널리 배포하려고 Microsoft Store에 올렸다고 밝혔다.
반면 GitHub README는 코드 서명에 비용이 들어 서명된 실행 파일을 제공하지 못한다며, SmartScreen 경고가 뜨면 저장소에서 직접 받은 파일인지 확인하고 실행하라고 안내한다.
같은 앱이 한쪽에서는 Store의 심사와 서명을 거쳐 배포되고, 다른 쪽에서는 사용자가 경고를 넘겨 실행해야 한다.

다운로드 폴더 전체의 파일 이름을 바꾸고 Windows 시작 때 자동으로 뜨는 앱이라면, 사용자가 이 앱에 주는 권한은 작지 않다.
Store 경로를 기본으로 안내하고, 포터블 EXE는 Store를 쓸 수 없는 사람을 위한 대안으로 두는 편이 사용자의 신뢰를 덜 요구한다.
README가 두 경로의 차이를 한곳에서 설명하지 않는 것은 아쉬운 부분이다.

## 인사이트

### AI가 “귀찮음의 문턱”을 낮추면 개인용 도구가 공개 배포물이 된다

작성자가 이 앱을 만든 동기는 문제가 어려워서가 아니라 기존 해법이 귀찮아서였다.
예전이라면 이런 사람은 커맨드라인 한 줄을 외우거나, 남이 만든 도구를 참고 썼을 것이다.
AI가 코드 작성, 아이콘 제작, Store 정보 입력, GitHub 업로드까지 맡으면서, 자기 한 사람의 귀찮음을 없애는 도구가 Store에 올라간 공개 배포물이 됐다.

이 변화는 같은 문제를 푸는 도구가 늘어나는 결과로 이어진다.
GeekNews에 비슷한 자소 결합 도구가 여러 개 쌓여 있는 것도 이 흐름의 일부다.
각 도구는 알고리즘이 아니라 “누구의 어떤 귀찮음을 없애느냐”로 갈리고, 사용자는 자기 작업 방식에 맞는 하나를 고르게 된다.

### 정규화 문제는 결국 “어느 쪽이 기준이냐”의 문제다

Unicode 정규화 문제는 기술적으로는 오래전에 풀렸다.
NFC와 NFD는 정의가 분명하고, 모든 주요 언어의 표준 라이브러리가 변환 함수를 제공한다.
그런데도 문제가 남는 것은, 파일을 만드는 쪽과 받는 쪽이 서로 다른 기준을 쓰고, 어느 쪽도 상대에 맞추지 않기 때문이다.

Mytory Jaso Watch는 받는 쪽이 맞추는 해법이다.
Mac에서 자소 분리를 막는 메뉴바 앱은 보내는 쪽이 맞추는 해법이다.
두 방식 모두 한쪽의 운영체제가 기준을 바꾸지 않는 한 필요하고, 결국 사용자는 자기가 통제할 수 있는 쪽에 도구를 설치하게 된다.
사무실에서 Windows를 쓰는 작성자가 Windows 쪽 도구를 만든 것은, 이 구조에서 자연스러운 선택이다.

### 파일 시스템을 감시하는 도구의 신뢰는 “하지 않는 일”에서 나온다

이 앱의 설계에서 가장 눈에 띄는 것은 하지 않는 일의 목록이다.
파일의 내용은 건드리지 않고, 기존 파일을 덮어쓰지 않고, 내려받는 중인 파일과 잠긴 파일은 기다리고, 임시 파일은 건너뛰고, 심볼릭 링크를 따라가지 않고, 개별 파일명 변경마다 알림을 띄우지 않는다.
사용자가 신경 쓰지 않아도 되는 도구가 되려면, 무엇을 하느냐보다 무엇을 하지 않느냐가 더 분명해야 한다.

다운로드 폴더를 늘 감시하는 앱은 사용자가 보지 않는 사이에 파일 이름을 바꾼다.
그 앱을 믿고 켜 둘 수 있는 이유는, 최악의 경우에도 파일을 잃지 않는다는 보장이다.
Mytory Jaso Watch가 이름 충돌 때 번호를 붙이고 10분 동안 재시도한 뒤 실패로만 기록하는 설계는, 편의보다 안전을 먼저 둔 선택이다.
