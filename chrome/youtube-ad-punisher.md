# YouTube Ad Punisher

<https://georgeanton.com/youtube-ad-punisher.html>

<https://github.com/antonpictures/youtube-punisher>

HN 토론: <https://news.ycombinator.com/item?id=50657530> (451점, 532개 댓글)

GN 토론: <https://news.hada.io/topic?id=37921>

## 소개

YouTube Ad Punisher는 YouTube에서 광고가 재생되면
재생 위치를 저장하고 페이지를 새로 고쳐 광고 없이 이어 보게 하려는
Chrome 확장 프로그램(Manifest V3)이다.
만든 사람은 README와 공식 사이트에서 George Anton으로 소개된다.
README는 Alice(SIFTA)라는 프로젝트로 만들었다고 적는다.
이 확장은 광고 차단기가 아니라 광고를 만나면 새로 고쳐 피하는 방식이다.

공식 사이트는 저장소의 `homepage` 필드가 가리키는 주소이며
읽은 시점(2026년 11월 27일)에 본문을 끝까지 읽었다.
사이트는 Chrome 웹 스토어 등록이 구글 심사 중이라서 아직 게시되지 않았고,
당분간 압축 파일을 받아 직접 올려 쓰라고 안내한다.
저장소와 사이트의 설명은 모두 만든 사람의 주장이다.

GitHub API가 보고한 저장소 현황은 다음과 같다.

| 항목        | 값                       |
| ----------- | ------------------------ |
| 생성        | 2026년 11월 23일         |
| 마지막 푸시 | 2026년 11월 26일         |
| 스타        | 226                      |
| 포크        | 3                        |
| 열린 이슈   | 1(풀 리퀘스트 포함 집계) |
| 라이선스    | MIT                      |
| 버전        | 1.8.2(`manifest.json`)   |

저장소가 만들어진 지 나흘밖에 되지 않았고 릴리스는 없다.
최근 커밋은 모두 2026년 11월 26일에 나왔다.

## 동작 방식

README가 설명하는 순서는 다음과 같다.

1. 광고를 감지한다. 광고 표시 클래스와 건너뛰기 버튼, 광고 오버레이를 본다.
2. 재생 위치를 `sessionStorage`에 저장한다.
3. `location.replace()`로 주소에 `&t=초`를 붙여 새로 고친다.
4. YouTube가 그 위치로 이동해 재생을 이어 간다.
5. 새로 고침이 반복되지 않도록 쿨다운을 둔다.

`content.js`를 읽어 보면 쿨다운은 1.2초이고 새로 고침은 최대 3번이다.
세 번 모두 실패하면 확장이 백그라운드 서비스 워커에 요청해
빈 탭을 4초 동안 열었다 닫으며 원래 탭을 다시 앞으로 가져오는 동작을 한 번 한다.
README는 크롬이 백그라운드 탭의 실행을 제한하는 점을 이용한 것이라고 설명한다.
그래도 광고가 남으면 `yout-ube.com`이라는 주소로 이동시킨다.
README는 이를 광고 없는 YouTube 미러(mirror)라고 부른다.

광고 기록은 광고주 이름, 영상 제목, 영상 시간, 광고 길이를
`chrome.storage.local`에 쌓고
팝업에서 JSON이나 CSV로 내보낼 수 있다.
사이트는 데이터가 전송되지 않는다고 적는다.
`content.js`에서 네트워크 요청을 찾아 보았고 위의 미러 주소 외에는 없었으며,
`background.js`에는 탭을 조작하는 코드만 있었다.
`popup.js`와 나머지 파일은 열어 보지 않았다.

권한은 `storage`와 `tabs`, 그리고 YouTube 도메인 접근이다.

## 설치

README는 세 가지를 안내한다.

| 방법              | 내용                                               |
| ----------------- | -------------------------------------------------- |
| 압축 해제 후 로드 | 저장소를 받아 `chrome://extensions`에서 로드한다   |
| Safari(실험적)    | 셸 스크립트와 AppleScript로 감시한다               |
| 압축 파일         | Releases의 압축 파일을 받아 같은 방식으로 로드한다 |

Chrome, Brave, Edge, Opera에서 쓸 수 있고 Safari는 실험 단계라고 한다.
이 문서는 확장을 설치하거나 실행하지 않았다.

## 분석

### 광고를 막지 않고 피하는 설계

광고 차단기는 광고 서버로 가는 요청을 막고,
YouTube는 차단기를 감지하는 장치로 맞선다.
이 확장은 요청을 건드리지 않고 광고가 뜬 뒤 페이지를 새로 고쳐
광고가 다시 배정되지 않기를 기대한다.
README는 YouTube가 새로 고침마다 광고 제공 여부를 다시 판단하므로
한두 번 뒤에는 광고 슬롯이 빈다고 설명한다.
이것은 README의 주장이고, 이 문서는 확장을 실행해 그 확률을 재지 않았다.

### 도구의 위치는 보조다

README의 비교표는 uBlock Origin, SponsorBlock과 같이 쓰라고 권한다.
HN 답글에서도 이 점이 드러난다.
글을 올린 iantongeorge는 uBlock이 잘 되는 Firefox에서는
이 확장이 필요 없다고 인정했다.[^iantongeorge]
Chromebook이나 Safari처럼 차단기가 감지되거나
돌아가지 않는 환경이 대상이라는 설명이다.
Waraqa는 크롬북에서는 광고 차단기를 쓰면
YouTube가 동작하지 않는다고 썼다.[^Waraqa]
그렇다면 이 확장이 겨냥하는 사용자는 제한된 환경의 소수다.

### 비판에 대한 빠른 수정이 저장소에 남아 있다

HN에서 JackFener는 README의 문구를 인용하며
이 저장소는 새로 고침만 하고 실패하면 미러로 보낼 뿐이라고 비판했다.[^JackFener]
같은 스레드에서 iantongeorge는 광고 밀도가 채널마다 다르다고 인정하고
README를 고치겠다고 답했다.[^iantongeorge]
커밋 기록에는 같은 날 광고 밀도 표현을 바로잡은 커밋이 있다.
읽은 시점의 README는 광고 밀도가 채널에 따라 달라진다고 적고 있다.

## 비평

### 미러 주소로 보내는 마지막 단계는 근거가 없다

`yout-ube.com`은 YouTube의 도메인이 아니라 하이픈이 들어간 별도 주소다.
README는 이를 광고 없는 미러로 소개하지만 누가 운영하는지,
어떤 데이터를 받는지는 말하지 않는다.
확장은 영상 ID와 재생 위치를 이 주소의 주소창에 실어 사용자를 옮긴다.
이 문서는 해당 사이트를 열어 보지 않았고 내용은 확인하지 못했다.
HN에서 pocksuppet은 영상을 미러링하는 사이트를 만들면 어떠냐고 농담조로 말했지만
이 확장의 기본 동작은 이미 그런 방향에 있다.[^pocksuppet]
YouTube와 닮은 주소에서 사용자가 로그인하거나 정보를 입력하는 일이 생기지 않도록
주의하라고 문서에 적혀 있지 않다.

### README의 설명과 코드가 완전히 같지는 않다

README의 순서도는 새로 고침을 세 번 시도한 뒤 미러로 이동한다고 그린다.
같은 README의 팁은 세 번 뒤에 탭 전환을 자동으로 한다고 적는다.
코드는 새로 고침 세 번, 탭 전환 한 번, 그다음 미러 이동 순서다.
설명이 서로 다른 것이 아니라 단계가 하나 빠진 그림이라는 점은 사소하지만,
미러 이동이 실제로 일어나는 조건이 README만으로는 분명하지 않다.

### 광고 수익 문제에 대한 입장이 없다

README의 끝에는 새로 고침 하나하나가 광고를 보지 않겠다는 투표라는 문장이 있다.
bemtevi는 자신이 YouTube 광고로 생활비 일부를 버는 소규모 창작자라고 밝히며
차단을 비난하지는 않지만 구독을 고려해 달라고 썼다.[^bemtevi]
Grombobulous는 구독료가 한 달 9달러 정도이고
학생 요금제와 저렴한 요금제도 있다고 짚었다.[^Grombobulous]
이 확장이 광고를 피하는 것을 넘어
수익 모델에 항의하는 도구라고 스스로 말하는 만큼,
창작자에게 돌아가는 영향에 대한 생각은 README에 없다.

### 비교가 한쪽으로 기울어 있다

비교표의 항목은 새로 고침 여부와 데이터 수집 여부뿐이다.
광고가 실제로 사라지는 비율이나 되감기까지 걸리는 시간 같은 항목은 없다.
noitpmeder는 Firefox와 uBlock Origin, SponsorBlock을 쓰면
몇 년 동안 광고를 본 적이 없다고 말했다.[^noitpmeder]
이 증언은 개인 경험이다.

## 인사이트

### 광고 감지 방식은 얼마든지 되돌려질 수 있다

이 확장은 광고가 이미 재생된 뒤 반응하므로
광고 표시 클래스와 같은 페이지 구조에 의존한다.
README의 한계 항목도 YouTube가 클래스 이름을 바꾸면
감지가 깨질 수 있다고 인정한다.
광고를 피하는 방식은 서비스가 바꾸는 순간 바로 무력해지고,
사용자가 얻는 것은 그동안의 편의뿐이다.
이는 저장소의 구조에서 끌어낸 추론이며 이 문서가 시험한 것은 아니다.

### 빠르게 고치는 개발 방식과 검증의 간격

저장소는 만든 지 나흘 사이에 버전 1.8.2까지 올라갔고
커밋 메시지에는 새로 고침을 더 빨리 하는 변경이 들어 있다.
HN에서 받은 비판이 몇 시간 안에 문구 수정으로 이어진 점은 좋은 신호다.
다만 미러 이동처럼 사용자의 신뢰에 걸린 동작은
빠른 수정보다 설명과 점검이 먼저 필요한 영역이다.

### 확인할 것

이 문서는 확장을 설치하거나 실행하지 않았고 `yout-ube.com`도 열지 않았다.
새로 고침이 광고를 실제로 없애는 비율, 미러의 운영 주체,
`popup.js`의 데이터 처리는 확인하지 못했다.
Chrome 웹 스토어 심사 결과는 이후에 확인해야 한다.
