# Phone Harness: 휴대폰 제어 에이전트 도구

<https://phone-harness.com/>

<https://github.com/phone-harness/phone-harness>

Show HN: [Show HN: Phone-harness – let your agent control your phone](https://news.ycombinator.com/item?id=49346652) (2점, 0개 댓글)

## 소개

Claude Code, Codex 같은 코딩 에이전트가 사용자의 실제 휴대폰을 쓰게 하는 오픈소스 도구이다.
이 문서는 `README.md` 전문과 저장소 목록, GitHub API 수치, 저장소가 홈페이지로 등록한 `phone-harness.com`의 첫 화면, HN 검색 결과를 읽었다.
`SKILL.md`, `install.md`, `setup/`, 소스 코드, 사이트의 문서와 요금 페이지는 열지 않았고 직접 설치해 써 보지도 않았다.
설명과 한계는 모두 저장소가 밝힌 것이다.

GitHub API로 읽은 시점(2026년 11월 18일)의 수치는 별 5,081개, 포크 526개, 열린 이슈 100개, 라이선스 MIT, 주 언어 Python, 생성일 2026년 8월 7일, 마지막 푸시 2026년 11월 9일이다.
제작자 개인 계정(`ShawnPana`)의 저장소로 시작해 조직 계정(`phone-harness`)으로 옮겨 온 것으로 보인다. HN의 Show HN 글이 옛 주소를 가리키는 점이 그 근거이다.

핵심 설명은 이렇다.
에이전트가 탈옥(jailbreak), Xcode, 휴대폰에 설치하는 앱 없이 사용자의 휴대폰을 스크롤, 탭, 입력, 읽기를 할 수 있다고 한다.

지원 대상은 세 가지이다.

- iPhone: Mac의 iPhone 미러링(iPhone Mirroring) 창을 통해 쓴다. macOS 15 이상, iOS 18 이상의 iPhone과 짝지은 미러링, 손쉬운 사용과 화면 기록 권한이 필요하다.
- Android: macOS, Linux, Windows에서 adb로 쓴다. adb와 USB 디버깅이 필요하다.
- Phone Harness Cloud: 제작자가 호스팅하는 Android(adb)와 iPhone(HTTPS)이다. 계정이 필요하고 클라우드 Android도 adb가 필요하다.

설치는 설정 프롬프트를 에이전트에 보내는 방식이다. 프롬프트는 `uv`와 파이썬 3.12로 CLI를 설치하거나 업그레이드하고, `phone-harness skill`로 스킬을 등록하고, `onboarding.md`를 읽으며 안내하게 한다. 에이전트가 어떤 휴대폰을 쓸지 묻고 사람 손이 필요한 단계를 안내한다고 한다.
`phone-harness doctor`가 설정을 점검한다. MCP 클라이언트에는 `https://mcp.phone-harness.com/mcp`를 추가할 수 있으나 지금은 클라우드 Android와 iPhone만 지원한다. Hermes Agent와 OpenClaw용 플러그인도 있다.

사용법은 셸에서 파이썬 조각을 실행하는 방식이다.
`phone-harness`에 `open_app`, `tap_text`, `type_text`, `screen` 같은 미리 가져온 도우미를 쓰는 스크립트를 넣는다.
에이전트는 자신이 만든 도우미를 `~/.phone-harness/agent-workspace`에 저장한다.

동작 방식은 모든 휴대폰이 같은 도우미 뒤에 있어 한 휴대폰용 스크립트가 다른 휴대폰에서도 돈다는 것이다.

- iPhone: 미러링 창을 캡처하고, Apple의 Vision OCR로 읽고, 탭과 스와이프와 입력을 입력 이벤트로 보낸다.
- Android: 스크린샷과 입력은 adb로, 텍스트는 접근성 트리로 얻는다. USB나 Wi-Fi를 쓴다.
- 클라우드 Android: 호스팅된 휴대폰에 adb로 같은 방식을 쓴다.
- 클라우드 iPhone: HTTPS로 작업을 보낸다.

클라우드 쪽 명령은 `phone-harness cloud login`, `ls`, `start`(기본 15분, `--for`로 조정), `stop`이다.
호스팅 서비스는 요청 시 새 Android(세션마다 새로 만들거나 앱과 로그인이 유지되는 저장된 휴대폰), 전용 실제 iPhone, 에이전트가 일하는 동안 브라우저로 보는 실시간 화면을 제공한다고 한다. 소개 문구에는 스텔스, 실제 번호, 2FA, 무제한 기기가 있다고 적혀 있다.

저장소가 직접 적은 한계는 다음과 같다.

- iPhone을 잠금 해제하면 미러링이 멈춘다. PIN으로 잠긴 Android는 사용자가 풀어야 한다.
- OCR은 텍스트만 보고 아이콘은 보지 못한다. 이름 없는 컨트롤은 스크린샷과 비전 가능 모델이 필요하다.
- 멀티터치, 카메라, Face ID 흐름은 안 된다. DRM 영상은 검게 렌더링된다.
- 휴대폰을 연결하는 일은 항상 사용자의 몫이다.

데모는 실제 iPhone에서 에이전트가 현재 위치에서 어느 카페까지 Waymo를 부르는 영상이다(GIF는 열지 않았고 README의 서술만 읽었다).
README의 후원 문구에 따르면 이 도구는 무료이고 제작자가 자기 시간으로 유지한다.

## 분석

### 중심 주장은 설치 없이 실제 휴대폰을 에이전트에게 연결한다는 것이다

iPhone은 사용자의 Mac이 가진 iPhone 미러링 기능을 입출력 통로로 삼는다.
이 덕분에 탈옥도, Xcode 서명도, 휴대폰의 앱 설치도 필요 없다는 것이 저장소의 강조점이다.
대신 화면을 OCR로 읽고 입력 이벤트를 보내는 구조라서, 접근성 트리를 읽는 Android보다 읽는 정보가 적다.
이는 저장소의 서술을 이 문서가 정리한 것이다.

### 같은 도우미를 여러 휴대폰에 쓰게 한 추상화이다

`tap_text`, `screen`, `type_text` 같은 도우미가 iPhone, Android, 클라우드에서 같게 동작하도록 한 것이 구조의 중심이다.
에이전트가 자기 도우미를 작업 공간에 저장하게 해, 쓸수록 도구가 늘어나는 구성이다.
이 저장소는 에이전트가 이 도구를 파이썬 한 조각으로 호출하는 방식이어서, 앞서 읽은 마크다운 지침 모음 형태의 휴대폰 하네스와 구조가 다르다. 이 문서는 두 도구를 같은 기준으로 비교하지 않았다.

### 무료 저장소가 호스팅 서비스의 입구이기도 하다

홈페이지는 이 도구를 Y Combinator의 지원을 받는 오픈소스 휴대폰 제어 도구라고 소개하고, 클라우드(공개 베타)의 요금을 안내한다. 새 계정에 5달러 크레딧을 주고 Android 에뮬레이터는 분당 5센트, 실제 iPhone은 정액 구독이라고 한다. 이 요금 서술은 홈페이지의 것이며 이 문서가 요금 페이지를 열어 확인하지는 않았다.
README 상단의 버튼과 문구는 클라우드 서비스(무료 체험 안내 포함)를 가리키고, 일부 기능(실제 번호, 2FA, 스텔스, 무제한 기기)은 호스팅 서비스의 것이다.
로컬 사용은 무료이지만, 저장소가 제작자의 상용 서비스를 홍보하는 구조라는 점은 알고 읽어야 한다. 이는 이 문서의 관찰이다.

## 비평

### 효과를 보인 근거가 데모 하나이다

README가 내세운 성능 자료는 Waymo 호출 데모 하나이다.
성공률, 속도, 실패 사례를 다룬 평가는 이 문서가 읽은 범위에 없다.
별 5,000개 이상이라는 관심은 있지만 이는 사용 후기가 아니다.
HN에는 이 도구의 글이 두 건 있고(Show HN, 그리고 제품 사이트 링크) 모두 2점에 댓글이 없어서 독립적인 반응을 읽을 수 없었다.

### 보안과 개인정보 서술이 거의 없다

에이전트가 사용자의 실제 휴대폰을 읽고 누를 수 있다는 것은 메시지, 은행 앱, 인증 앱에 접근할 수 있다는 뜻이다.
README는 휴대폰 연결을 사용자의 일로 규정하지만, 에이전트가 어떤 앱과 화면에 접근해도 되는지, 결제나 비밀 정보 화면에서 멈추는 규칙이 있는지, 화면의 텍스트가 에이전트를 속이는 공격(프롬프트 주입)에 어떻게 대응하는지는 이 문서가 읽은 README에 나오지 않는다.
이 문서는 `SKILL.md`와 `onboarding.md`를 열지 않았으므로, 그곳에 있을 수 있다. 같은 목적의 다른 하네스는 이런 규칙을 지침의 앞쪽에 둔다.
홈페이지는 클라우드의 장점으로 실제 하드웨어라서 앱이 사람으로 본다는 스텔스, 실제 전화번호로 SMS와 2FA 처리를 내세운다. 이런 기능은 서비스 약관과 오용 가능성 문제가 따르지만 README와 홈페이지 첫 화면은 그 부분을 설명하지 않는다.

### iPhone 경로의 한계가 구조에서 나온다

OCR이 텍스트만 읽고 아이콘을 읽지 못하며, 잠금 해제가 미러링을 멈추고, 멀티터치와 카메라와 Face ID 흐름이 안 되는 것은 모두 화면 미러링 방식의 한계이다.
저장소는 이를 한계 절에 솔직하게 적었다.
다만 macOS 15와 iOS 18, 짝지은 미러링이 필요하다는 조건은 일반 사용자가 쓰기에 좁다. 이 문서는 지원 조건이 앞으로 바뀌는지 확인하지 못했다.

### 후원 안내와 클라우드 홍보가 섞인 첫 화면

README는 도구 소개 직후부터 클라우드 가입 버튼과 무료 체험 문구를 여러 번 배치한다.
도구 자체의 설치와 동작 서술은 그 아래에 있다.
이 구성이 잘못이라는 뜻은 아니지만, 저장소 소개와 상용 서비스 홍보가 구분되지 않는다.

### 외부 반응

HN에서는 이 도구를 다룬 글이 두 건이고 둘 다 2점에 댓글이 없다.
Lobste.rs에서는 `phone-harness`, `ShawnPana`로 검색한 결과 이 도구의 글이 없었다(`phone-harness` 검색에 걸린 두 건은 postmarketOS 글이라 무관했다. 대조 쿼리는 정상이었다).
GeekNews에서는 도구 이름과 설명 표현으로 검색했으나 이 도구의 토픽이 없었다(대조 쿼리는 정상이었다).
그래서 이 도구의 주장은 독자의 검토를 거의 거치지 않았다.

## 인사이트

### 가져갈 것은 기기 접근을 읽기와 입력 도우미로 추상화하는 구성이다

화면 읽기(OCR이나 접근성 트리)와 입력(탭, 스와이프, 타이핑)이라는 작은 공통 도우미 집합을 두고 기기 종류를 그 뒤로 숨기면, 같은 에이전트 스크립트가 여러 기기에서 돈다.
기기 제어를 에이전트에 붙이려는 다른 프로젝트에도 쓸 수 있는 구성이다.
이는 이 문서의 적용이며 이 문서가 시험하지 못했다.

### 실제 휴대폰을 에이전트에게 줄 때는 별도 기기와 계정으로 시작한다

저장소는 사용자의 실제 휴대폰을 쓴다고 하지만, 처음에는 개인 계정이 없는 별도 기기나 클라우드의 임시 Android로 시험하는 편이 위험을 줄인다.
어떤 앱을 열고 어떤 화면에서 멈추게 할지를 먼저 정한 뒤 개인 휴대폰에 쓰는 순서가 안전하다.

### 확인할 관찰

이 도구의 주장을 가를 관찰은 세 가지이다.
여러 과제에서의 성공률과 실패 유형을 독립적으로 잰 결과,
비밀 정보와 결제 화면, 프롬프트 주입에 대한 방어가 실제로 있는지,
iPhone 미러링 방식이 OS 업데이트 뒤에도 유지되는지이다.
셋 모두 이 문서가 확인하지 못했다.
