# claude-mem: 에이전트 세션의 작업 기록을 압축해 다음 세션에 되돌려 주는 플러그인

<https://github.com/thedotmack/claude-mem>

HN 토론: <https://news.ycombinator.com/item?id=47558167> (2점, 1개 댓글)

GN 토론: <https://news.hada.io/topic?id=25824>

## 소개

claude-mem은 코딩 에이전트가 세션 중에 한 일을 자동으로 기록하고,
그 기록을 AI로 요약한 뒤 다음 세션이 시작될 때 관련 부분만 다시 넣어 주는
도구다.
저장소 설명은 이를 세션을 넘나드는 지속적 컨텍스트(persistent context)라고
부르고, 처음에는 Claude Code 전용 플러그인으로 만들어졌다.
README 첫머리의 안내문은 지금도 Claude Code용 영속 메모리 압축 시스템이라고
소개한다.

GitHub API로 확인한 저장소의 상태는 다음과 같다.
2026년 10월 31일 기준으로 별은 105,665개, 포크는 9,311개다.
저장소는 2025년 8월 31일에 만들어졌고, 언어는 TypeScript이며, 라이선스는
Apache-2.0이다.
받아 본 `main`의 `package.json` 버전은 15.7.0이고, `CHANGELOG.md`는 9,131줄이다.
`.ts` 파일은 1,844개다.

README가 말하는 구성 요소는 여섯 가지다.

| 구성 요소           | README의 설명                                              |
| ------------------- | ---------------------------------------------------------- |
| 수명주기 훅(hook)   | SessionStart, UserPromptSubmit, PreToolUse 등 여섯 시점    |
| 스마트 설치         | 의존성을 캐시해 확인하는 Setup 훅과 `install`, `repair`    |
| 워커 서비스         | 웹 뷰어와 검색 엔드포인트를 가진 로컬 HTTP API, Bun이 관리 |
| SQLite 데이터베이스 | 세션, 관찰(observation), 요약을 저장                       |
| mem-search 스킬     | 자연어로 묻는 점진적 공개(progressive disclosure) 검색     |
| Chroma 벡터 DB      | 의미 검색과 키워드 검색을 섞은 하이브리드 검색             |

README의 소개문은 이 도구가 일반적인 메모 파일이 아니라 도구 사용 기록을
관찰로 쌓는 방식이라고 설명한다.
에이전트가 파일을 읽거나 명령을 실행할 때마다 그 결과가 관찰 후보가 되고,
세션이 끝나면 요약이 만들어진다.

## 설치와 사용

설치 명령은 한 줄이다.

```bash
npx claude-mem install
```

설치 프로그램은 먼저 모든 설정을 끝낸 뒤, 브라우저에서 claude-mem 계정에
로그인하라고 안내한다.
README는 로그인하면 30일 무료 체험이 열리고, 그동안 메모리 처리가 구독 한도와
별도로 돌아가 플랜 사용량을 최대 100% 더 쓸 수 있다고 말한다.
체험이 끝나면 구독하지 않는 한 메모리 처리는 Anthropic 플랜으로 돌아간다.
로그인을 건너뛰려면 `--provider` 플래그를 주거나
`CLAUDE_MEM_ONLINE_OPTIN=false`를 설정하면 된다.

Claude Code 안에서는 플러그인 마켓플레이스로도 설치한다.

```bash
/plugin marketplace add thedotmack/claude-mem

/plugin install claude-mem
```

설치 뒤에는 Claude Code를 다시 시작해야 하고, 이후 새 세션에는 이전 세션의
맥락이 자동으로 나타난다.
`npm install -g claude-mem`은 SDK와 라이브러리만 깔 뿐 훅과 워커를 등록하지
않는다고 README가 따로 경고한다.

검색은 MCP 도구 세 개로 이루어진 3단계 흐름이다.

| 단계 | 도구               | 돌려주는 것                  | README의 토큰 추정       |
| ---- | ------------------ | ---------------------------- | ------------------------ |
| 1    | `search`           | ID가 붙은 간결한 색인        | 결과당 약 50~100 토큰    |
| 2    | `timeline`         | 관심 항목 앞뒤의 시간순 맥락 | 명시 없음                |
| 3    | `get_observations` | 걸러낸 ID의 전체 내용        | 결과당 약 500~1,000 토큰 |

README는 상세를 가져오기 전에 먼저 거르기 때문에 토큰이 약 10배 절약된다고
말한다.
이 수치는 README의 주장이며, 측정 방법이나 비교 대상은 README에 나와 있지
않다.

설정은 `~/.claude-mem/settings.json`에 있다.
`CLAUDE_MEM_MODE`로 동작 방식과 관찰 기록의 언어를 정하고, 기본값은 영어
모드인 `code`다.
중국어(`code--zh`)와 일본어(`code--ja`) 모드가 있고, 한국어 전용 모드는 README의
모드 표에 없다.
README 상단의 언어 링크에는 한국어 문서(`docs/i18n/README.ko.md`)가 있다.

## 분석

### 훅 11개가 세션의 모든 단계에 붙는다

`plugin/hooks/hooks.json`을 읽으면 훅 항목은 11개이고, 이벤트 이름은 아홉
가지다.
Setup, SessionStart, UserPromptSubmit, PostToolUse, PostToolUseFailure,
PreToolUse, Stop, SubagentStop, SessionEnd다.
README가 말한 여섯 시점보다 실제 파일의 이벤트가 더 많다.

SessionStart에는 항목이 세 개다.
하나는 워커를 시작하고, 하나는 이전 맥락을 주입하며,
하나는 시작 시점에만 런처(launcher)를 확인한다.
맥락 주입은 `startup|clear|compact`일 때만 돌고 `resume`에서는 돌지 않는다.
워커 시작 항목은 `resume`까지 포함하고 `async`로 표시되어 있다.

관찰을 모으는 PostToolUse와 PostToolUseFailure는 매처가 `*`이므로 모든 도구
호출 뒤에 실행된다.
두 항목 모두 `async: true`이고 제한 시간은 120초다.
도구 호출을 막지 않고 뒤에서 처리한다는 뜻이다.
반대로 PreToolUse의 `file-context` 훅은 `async`가 아니고 제한 시간이 15초이며,
`Read`, `Bash`, `Grep`, `Glob`과 메모리 검색 도구에만 걸린다.
이 훅은 이전 세션의 파일 관련 맥락을 읽기 전에 끼워 넣는 용도로 읽히지만,
이 글은 훅의 내부 동작을 실행해 확인하지 않았다.

### 개인정보 보호는 훅 층의 태그 제거로 시작한다

`src/utils/tag-stripping.ts`는 여섯 가지 태그를 제거 대상으로 정한다.
`private`, `claude-mem-context`, `system_instruction`, `system-instruction`,
`persisted-output`, `system-reminder`다.
`SECURITY.md`는 이 태그가 훅 층에서 제거되어 워커나 데이터베이스에 닿기 전에
사라진다고 설명한다.

코드의 주석은 중첩된 태그와 닫히지 않은 태그를 어떻게 다루는지도 적어 두었다.
닫는 태그가 실제로 있을 때만 제거하므로, 본문에 우연히 적힌 `<private>`은
그대로 남는다.
짝이 어긋난 닫는 태그는 가장 먼저 열린 같은 이름의 태그와 짝지어지고 그 사이를
지우므로, 태그 순서로 비공개 내용을 살릴 수 없다고 주석은 말한다.

### 데이터는 로컬에 저장되지만 로컬에만 머물지 않는다

`SECURITY.md`는 데이터베이스, 벡터 저장소, 로그, 설정이 모두
`~/.claude-mem/` 아래에 쓰인다고 말한다.
같은 문서가 곧바로 로컬 저장이 데이터가 기기를 떠나지 않는다는 뜻은 아니라고
덧붙이고, 나가는 경로를 나열한다.

| 경로                            | 보내는 내용                                   |
| ------------------------------- | --------------------------------------------- |
| PostHog 텔레메트리              | 사용 통계와 가려진 오류 메시지, 스택 트레이스 |
| 클라우드 동기화(선택)           | 관찰, 세션 요약, 사용자 프롬프트, 할 일 목록  |
| Claude Agent SDK(기본 경로)     | 프롬프트와 대화 기록 맥락을 Anthropic API로   |
| 대체 제공자(Gemini, OpenRouter) | 같은 맥락을 해당 제공자로                     |
| `openai-compatible` 제공자      | 설정한 엔드포인트로                           |
| Chroma MCP                      | 설정에 따라 원격 임베딩 API로                 |

텔레메트리는 기본으로 켜져 있고 끄는 방법은 두 가지다.
`npx claude-mem telemetry disable`을 실행하거나 `DO_NOT_TRACK=1`을 설정한다.
관찰과 요약을 만드는 기본 경로가 대화 기록 맥락을 Anthropic API로 보낸다는
점은, 기록 내용 자체가 모델 호출의 입력이라는 뜻이다.

### 설치 때 열리는 브라우저 설정은 최근 30일의 프롬프트를 올린다

위 표에는 `SECURITY.md`가 나열하지 않은 경로가 하나 더 있다.
`CHANGELOG.md`의 15.2.0 항목은 새로 설치하면 브라우저 설정 흐름이 열린다고
적는다.
이 흐름의 두 번째 단계는 지원하는 로컬 에이전트의 최근 30일 기록을 읽는
스캔(scan)이다.
세 번째 단계는 걸러낸 사용자 프롬프트를 gzip으로 압축해 CMEM Cloud로 올려
호스팅 방식의 의도 추출(intent extraction)을 맡기는 것이다.
변경 이력은 사전에 체크된 제품 개선 상자가 `improveProduct` 값만 바꾼다고
적는다.

받아 본 코드도 같은 흐름이다.
`src/services/prompt-import/index.ts`는 스캔 기간을 30일로 정하고,
`src/services/work-view/hosted-intent.ts`는 JSON을 gzip으로 압축해
`/api/pro/intent` 주소로 POST한다.
업로드 크기에는 2MiB 상한이 있고, 넘으면 잘라 올리지 않고 오류를 낸다.
`setup-scan.ts`에서 `improveProduct`의 초깃값은 `true`다.
이 글은 설치와 업로드를 직접 실행해 보지 않았고, 위 내용은 코드와 변경 이력을
읽은 결과다.

GitHub 이슈 사용자 saltenasl은 이 흐름이 사용자에게 명시적으로 묻지 않고
프롬프트를 올리며, 설정 화면의 상자를 해제해도 업로드가 멈추지 않는다고
보고했다.
이 사용자는 cmem.ai가 업로드된 프롬프트를 OpenRouter를 거쳐
`deepseek/deepseek-v4-flash-0731` 모델에 보냈다고 이메일로 확인받았다고 적었다.
요청에는 데이터 보존 금지 설정이 없었고, 어느 제공자가 처리했는지는 cmem.ai의
기록에 남아 있지 않다고도 적었다.
이 이슈는 2026년 10월 30일에도 갱신 중이고 cmem.ai가 계정 수준 설정을
확인하는 중이라고 했으므로, 이 부분은 보고자의 주장이며 개발사 쪽 확정 답변은
이 글이 확인하지 못했다.[^issue-5176]

## 비평

### 토큰 10배 절약은 측정이 공개되지 않은 주장이다

가장 강하게 읽으면 이 도구의 핵심 주장은 이렇다.
색인을 먼저 보고 필요한 항목만 상세로 가져오면, 같은 정보를 훨씬 적은 토큰으로
얻는다.
이 주장을 받치는 것은 결과당 50~100 토큰과 500~1,000 토큰이라는 추정치다.
두 수치의 비율이 곧 10배이고, 그 이상의 측정은 README에 없다.

이 방식의 절약은 필터링이 정확할 때만 성립한다.
색인 단계에서 필요한 항목을 놓치면 에이전트는 기록이 없다고 판단해 같은 탐색을
처음부터 반복한다.
이때 드는 비용은 절약한 토큰이 아니라 다시 한 작업이다.
README는 이 실패율을 밝히지 않는다.
저장소에는 `evals` 디렉터리가 있지만, 이 글은 그 내용을 읽지 않았으므로
평가가 이 주장을 얼마나 뒷받침하는지는 확인하지 못했다.
검색 정확도를 직접 재 본 결과가 나오면 이 평가는 바뀐다.

### 이름은 Claude Code인데 소개의 중심은 다른 곳에 있다

README의 Quick Start는 Claude Code가 아니라 Grok Bot 설치 명령으로 시작한다.
그 뒤로 OpenCode, T3 Code, Antigravity CLI, OMP, Pi, DeepSeek Harness 설치가
이어지고, Claude Code 마켓플레이스 설치는 그 목록의 끝에 나온다.
Grok Bot 항목은 훅이 없어서 채팅 로그 파일을 감시한다고 적고, 기본값이 호스팅
메모리인 CMEM Pro라고 밝힌다.

설치 흐름도 상업 서비스와 맞물려 있다.
로그인하면 30일 체험이 열리고, 끝나면 구독하지 않는 한 사용자의 Anthropic
플랜으로 돌아간다.
README 말미에는 개발자가 공식적으로 받아들인 제3자의 토큰인 CMEM 설명도 있다.
이 구조에서 기본 경로를 고르는 사람은 로컬 도구를 쓰는 것인지 호스팅 서비스의
입구를 지나는 것인지 설치 시점에 직접 확인해야 한다.
README는 로그인을 건너뛰는 방법을 적어 두었으므로 선택권 자체가 없는 것은
아니다.

### 모든 도구 호출에 붙는 훅의 비용은 문서에 없다

PostToolUse가 `*` 매처로 모든 도구 호출에 걸리고, 매번 `claude-mem hook`
명령을 실행한다.
`async`이므로 에이전트의 응답을 막지 않지만, 호출마다 프로세스를 띄우는 비용과
관찰을 모델로 요약하는 비용은 쌓인다.
README는 후자를 플랜 사용량의 일부라고만 말하고, 세션당 평균 호출 수나 요약에
쓰이는 토큰은 제시하지 않는다.
이 글은 설치해서 실행하지 않았으므로 실제 지연이나 비용은 측정하지 못했다.

## 인사이트

### 색인, 시간순 맥락, 상세로 나누는 구조는 다른 검색 도구에도 쓸 수 있다

세 단계 설계의 값어치는 이 플러그인이 아니라 구조에 있다.
먼저 ID가 붙은 짧은 목록을 주고, 그 주변의 흐름을 따로 열고, 마지막에 필요한
항목만 전체를 연다.
에이전트용 검색 도구를 직접 만든다면 한 번에 본문까지 돌려주는 대신 이 순서를
따를 수 있다.
검증 방법은 같은 질문에 대해 단계별 호출 횟수와 총 토큰을 한 번에 가져오는
방식과 비교해 보는 것이다.

### 쓰기 전에 정할 것은 무엇이 밖으로 나가는지다

기록 내용은 모델 호출의 입력이다.
그래서 비밀 값이 있는 저장소에서 쓰려면 세 가지를 먼저 정해야 한다.
요약을 어느 제공자가 맡을지, 텔레메트리를 끌지, 클라우드 동기화를 켤지다.
여기에 설치 때 열리는 브라우저 설정을 그대로 진행해도 되는지가 더해진다.
이 설정은 코드상 최근 30일의 프롬프트를 올리므로, 민감한 작업 기록이 남은
기기에서는
설치 전에 이 단계의 동작을 먼저 확인해야 한다.
`<private>` 태그는 사용자가 직접 감싼 구간만 가리므로, 환경 변수나 명령 출력에
섞여 들어오는 비밀 값은 이 태그만으로 막을 수 없다고 보는 것이 안전하다.
이 판단은 태그 제거 코드가 감싼 구간만 지운다는 읽기에서 나온 추론이며,
`redaction` 모듈이 별도로 값을 가리는지는 이 글이 확인하지 못했다.

### 오래된 기록이 현재 상태와 어긋나는 경우가 실패 조건이다

세션 시작 때 이전 기록을 주입하는 방식은 기록이 현재 코드와 맞을 때만 이득이다.
리팩터링으로 파일 구조가 바뀐 뒤에도 옛 요약이 계속 주입되면 에이전트는 낡은
정보를 사실로 다룰 수 있다.
README는 기록의 유효기간이나 폐기 방식을 설명하지 않는다.
쓰기 시작한 뒤 몇 주 지나면 주입된 맥락 가운데 현재 코드와 어긋난 항목이 있는지
표본으로 확인해 보는 편이 좋다.
