# Anthropic의 Agent Skills 소개 글

원문: [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

HN 토론: <https://news.ycombinator.com/item?id=45607205> (4점, 0개 댓글)

## 요약

Anthropic 엔지니어링 팀이 2025년 10월 16일에 올린 글이다.
Agent Skills를 지침, 스크립트, 자원을 담은 폴더로 소개하고, 에이전트가
이를 동적으로 찾아 로드해 특정 작업을 더 잘하게 하는 방식이라고 설명한다.
글은 스킬 만들기를 신입 사원용 온보딩 안내서를 만드는 일에 견준다.
이 글에는 2025년 12월 18일에 덧붙인 갱신 문구가 있고, Agent Skills를
플랫폼 간 이식을 위한 공개 표준으로 냈다고 밝힌다.

### 스킬의 구조

스킬은 `SKILL.md` 파일이 든 디렉터리다.
이 파일은 YAML 머리말(frontmatter)로 시작해야 하고 `name`과
`description`이 필수다.
에이전트는 시작할 때 설치된 모든 스킬의 이름과 설명을 시스템 프롬프트에
미리 올린다.

글은 이를 점진적 공개(progressive disclosure)의 세 단계로 나눈다.

| 단계 | 내용                                 | 로드되는 시점                  |
| ---- | ------------------------------------ | ------------------------------ |
| 1    | `SKILL.md`의 이름과 설명             | 시작할 때 항상                 |
| 2    | `SKILL.md` 본문                      | Claude가 관련 있다고 판단할 때 |
| 3    | 본문이 이름으로 가리키는 추가 파일들 | 필요할 때만 Claude가 찾아 읽음 |

글이 드는 예는 PDF 스킬이다.
본문은 `reference.md`와 `forms.md`를 가리키고, 양식을 채우는 지침은
`forms.md`로 나눠 두어 본문을 가볍게 유지한다.
글은 이 원칙을 목차, 개별 장, 부록이 차례로 있는 잘 정리된 매뉴얼에
견주고, 파일시스템과 코드 실행 도구를 가진 에이전트는 스킬 전체를
컨텍스트에 읽을 필요가 없어 스킬에 담을 수 있는 컨텍스트가 사실상
무제한이라고 말한다.

### 코드와 보안

스킬은 Claude가 도구처럼 실행할 코드도 담을 수 있다.
글은 목록 정렬을 토큰 생성으로 하는 것이 정렬 알고리즘을 실행하는 것보다
훨씬 비싸고, 결정론적 신뢰성이 필요한 응용이 많다고 설명한다.
PDF 스킬에는 양식 필드를 추출하는 Python 스크립트가 있고, Claude는 이
스크립트나 PDF를 컨텍스트에 올리지 않고 실행할 수 있다.

글은 악성 스킬이 환경에 취약점을 들이거나 데이터를 빼돌리도록 Claude를
이끌 수 있다고 경고한다.
신뢰할 수 있는 출처의 스킬만 설치하고, 덜 믿는 출처라면 번들된 파일의
내용, 코드 의존성, 외부 네트워크 연결 지시를 먼저 감사하라고 권한다.

### 작성 지침

글이 제시하는 지침은 네 가지다.

첫째는 평가에서 시작하는 것이다.
대표 작업을 돌려 에이전트가 어디서 막히는지 보고, 그 틈을 메우는 스킬을
차례로 만든다.

둘째는 규모에 맞게 구조를 나누는 것이다.
`SKILL.md`가 커지면 파일로 쪼개고, 서로 배타적이거나 함께 쓰이지 않는
맥락은 경로를 분리해 토큰을 줄인다.
스크립트를 실행할지 참고용으로 읽을지도 분명히 한다.

셋째는 Claude의 관점에서 생각하는 것이다.
실제 사용을 관찰하고, 특히 이름과 설명에 신경 쓴다.
Claude가 이 둘로 스킬을 쓸지 정하기 때문이다.

넷째는 Claude와 반복하는 것이다.
성공한 접근과 흔한 실수를 스킬로 정리하게 하고, 궤도를 벗어나면 스스로
되짚게 한다.

글은 Claude.ai, Claude Code, Claude Agent SDK, Claude Developer
Platform에서 스킬이 지원된다고 밝히고, 스킬이 MCP 서버를 보완하는 방식도
살펴보겠다고 적는다.

## 분석

### 세 단계가 수치로 정해진 것은 명세다

이 글은 단계를 설명하지만 크기를 적지 않는다.
공개 표준 명세는 크기를 적는다.
메타데이터는 약 100토큰, `SKILL.md` 본문은 5,000토큰 미만을 권장하고,
본문은 500줄 아래로 유지하며, 자세한 참조는 별도 파일로 옮기고 파일
참조는 `SKILL.md`에서 한 단계 깊이로 둔다고 쓴다.[^spec]
Claude의 작성 모범 사례 문서도 500줄 한도와 한 단계 깊이 참조를
같게 적고, 이유로 중첩된 참조는 일부만 미리 읽혀 불완전한 정보가 될 수
있다는 점을 든다.[^bp]

### 무제한이라는 말의 조건

컨텍스트가 사실상 무제한이라는 주장은 조건부다.
에이전트에게 파일시스템과 코드 실행 도구가 있어야 한다.
글은 이를 같은 문장에 적지만, 스킬을 읽는 일이 에이전트의 한 턴과
토큰을 쓴다는 점과 균형을 맞춰 설명하지는 않는다.

### 설명이 라우팅을 맡는다

스킬이 쓰일지는 시작할 때 올라온 이름과 설명으로 정해진다.
글이 이름과 설명에 특히 신경 쓰라고 하는 이유가 여기 있다.
본문이 아무리 좋아도 설명이 작업과 맞지 않으면 읽히지 않는다.

## 비평

### 측정이 없다

글은 토큰이나 정확도의 수치를 싣지 않는다.
점진적 공개가 비용과 신뢰성에 어떤 영향을 주는지 말하지만 근거는 설명과
예시다.
뒤에 나온 Workday의 보고서는 모델과 라이브러리 크기에 따라 결과가 갈리고
지연 시간이 늘어난다고 보고한다.[^wd]
이 글에는 지연이나 실패 사례가 없다.

### 보안은 권고에 머문다

보안 단락은 출처를 믿고 감사하라는 권고이며 장치를 설명하지 않는다.
점진적 공개에서는 사용자가 항상 보는 것이 설명뿐이고 실행되는 것은
활성화 이후의 본문 전체라는 구조가 위험을 키울 수 있다.
이 지점은 글이 다루지 않는다.
이는 이 문서의 추론이다.

### 평가 지침의 빈칸

평가에서 시작하라고 하지만, 스킬이 트리거되었는지와 트리거된 뒤에 도움이
되었는지를 어떻게 구분해 재는지는 적지 않는다.

## 인사이트

### 정보 구조

스킬은 폴더이므로 설계는 정보 구조를 정하는 일이다.
항상 필요한 것은 설명에, 작업이 요구할 때 필요한 것은 본문에, 특정
분기에만 필요한 것은 참조 파일에 둔다.
실행할 코드는 컨텍스트 밖에 둘 수 있다는 점이 스킬을 단순한 프롬프트
템플릿과 가른다.
결정론이 필요한 부분은 스크립트로 넘기고 본문에는 호출 방법만 적는다.

### 설명 문장의 품질

라이브러리가 커질수록 설명 문장의 품질이 전체 성능을 좌우할 것이다.
이는 이 문서의 추론이다.
Workday 보고서에서 가장 큰 모델도 어려운 방해 스킬에는 약했지만, 그
결과는 모든 스킬을 미리 올린 조건의 것이어서 설명 품질의 영향을 직접
보여 주지는 않는다.[^wd]
