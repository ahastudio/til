# Translate Book: arXiv, PDF가 아니라 LaTeX 원본으로 논문을 번역하는 스킬

<https://github.com/kcy4334-lgtm/translate-book-arxiv>

Show GN: [Translate Book: arXiv - arXiv 논문을 원문 구조 그대로 번역본으로 변환해 주는 Claude Code 스킬](https://news.hada.io/topic?id=36087)

## 소개

arXiv 논문을 번역한 인쇄용 책으로 바꾸는 에이전트 스킬이다.
Claude Code, Codex, OpenClaw에서 쓴다.
핵심 선택은 PDF를 번역하지 않고 논문의 LaTeX 원본을 받아 번역한다는 것이다.
README는 PDF 번역기가 PDF 리더가 복원할 수 있는 것만 얻고, 수식은 그 과정에서 살아남지 못한다고 설명한다.
`pdftohtml`이 수식을 위치가 붙은 글자 조각으로 흩어 놓고, 어떤 옵션으로도 되돌릴 수 없다는 것이다.

LaTeX에서 시작하면 절 구성과 번호, 수식과 식 번호, 표, 캡션이 달린 그림, 인용과 참고문헌이 원문 구조대로 남는다.
“식 (3) 참고”나 “그림 2” 같은 상호 참조도 따라온다.
결과물은 PDF, DOCX, EPUB, HTML이다.
Calibre를 거치면 PDF, DOCX, EPUB 형태의 일반 책도 번역한다.
번역 언어는 옵션이며 `zh`, `en`, `ja`, `ko`, `fr`, `de`, `es` 등을 받고, 인쇄 레이아웃은 한국어를 기준으로 맞췄다고 한다.

GN에 올린 작성자의 글에 따르면 이 저장소는 `deusyu/translate-book`을 포크해서 시작했다.
작성자가 새로 만든 부분은 arXiv LaTeX 원본으로 번역하는 경로와 결과를 검사하는 부분이다.
작성자는 물리, 정수론, 양자컴퓨팅 등 분야가 다른 논문 26편으로 돌려 보았고 26편 모두 책으로 나온다고 적었다.
샘플로 논문 한 편을 전체 번역한 31쪽 PDF를 릴리스에 올려 두었다.
이 문서는 직접 실행해 본 것이 아니라 README와 GN 글을 읽고 정리한 것이다.

## 동작 방식

### 파이프라인

README가 그린 흐름을 풀면 다음과 같다.

| 단계      | 하는 일                                                                                                                                                                                                   |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 변환      | 첫 쪽의 arXiv 도장으로 논문을 알아보고, 동의를 받은 뒤 LaTeX 원본을 받아 하나로 펼친다. 논문이 가져온 `.sty`의 매크로를 풀고, 수식과 절의 번호를 원본에서 읽고, 그림은 원본 벡터 PDF에서 래스터로 만든다. |
| 조각내기  | Markdown을 약 6,000자 조각으로 나눈다. `manifest.json`이 조각마다 SHA-256 해시를 적는다. 참고문헌은 번역하지 않고 복사하는 별도 조각이 된다.                                                              |
| 용어집    | 처음, 끝, 고르게 벌린 세 곳의 조각 다섯 개를 표본으로 고유명사와 반복 용어의 번역어를 정해 `glossary.json`에 적는다.                                                                                      |
| 병렬 번역 | 하위 에이전트 여덟 개가 한 번에 한 조각씩 맡는다. 각자 새 컨텍스트에서 읽고 번역한다.                                                                                                                     |
| 검증      | 조각마다 원문, 받은 용어집, 인용한 조각과 대조한다. 매니페스트 해시와 원문-결과 1:1 대응도 확인한다.                                                                                                      |
| 빌드      | 합친 뒤 Pandoc으로 HTML(목차 포함), DOCX를 만들고 Calibre로 EPUB, 헤드리스 Chromium으로 PDF를 만든다.                                                                                                     |

조각마다 새 컨텍스트의 하위 에이전트에게 맡기므로 긴 책이 한 세션을 채우거나 끝에서 잘리지 않는다고 README는 설명한다.
GN 글에서 작성자도 한 번에 너무 길게 맡기면 실수가 늘어서 나눈다고 쓴다.

### 수식과 인용을 번역에서 빼는 장치

`math_guard.py`가 번역하는 동안 수식과 인용을 `⟦M0042⟧` 같은 자리표시자로 바꾸고 나중에 되돌린다.
그래서 번역 모델이 수식을 건드릴 여지가 없다.
표의 `97.9 ± 0.4`에서 `±`가 조용히 빠지는 문제는 GN 글이 든 대표 사고이고, `verify_tables.py`가 표를 번역하기 전후로 숫자, 행, 칸, 병합을 비교한다.

### 용어를 일관되게 하는 장치

각 조각이 서로 다른 에이전트에게 가므로 같은 단어가 조각마다 다르게 번역될 수 있다.
GN 글의 예는 앞 장에서 “attention”을 “어텐션”으로 옮기고 뒷장에서 “주의”로 옮기는 일이다.
용어집은 조각마다 해당하는 용어 표를 만들어 프롬프트에 강한 제약으로 넣고, 이웃 조각의 짧은 발췌도 이름과 대명사를 위해 준다.
`run_state.py`가 어느 조각이 어느 용어를 썼는지 기록해, 용어집을 고치면 영향받은 조각만 다시 번역한다.

## 사용하기

### 설치

```bash
npx skills add kcy4334-lgtm/translate-book-arxiv -a claude-code -g
```

Codex와 OpenClaw는 `-a codex`, `-a openclaw`로 바꾼다.
손으로 설치하려면 저장소를 에이전트의 스킬 디렉터리(Claude Code는 `~/.claude/skills/translate-book`)에 복제한다.

### 번역

설치 뒤 에이전트에게 번역할 논문을 말한다.

```text
translate /path/to/paper.pdf to Korean
```

스킬은 첫 쪽에서 arXiv 논문임을 알아보고 원본을 내려받기 전에 묻는다.
결과는 현재 디렉터리의 `{book_name}_temp/`에 `output.md`, `book.html`, `book.docx`, `book.epub`, `book.pdf`로 쌓인다.

### 필요한 것

- Python 3.8 이상
- Pandoc
- Chromium, Chrome, Edge 중 하나
- PyMuPDF와 pypandoc (`pip install pymupdf pypandoc`)
- EPUB까지 받으려면 Calibre

시작 전에 `python scripts/doctor.py --strict`가 무엇이 빠졌는지 알려 준다.
GN 글은 빠진 것이 있으면 설치할 것을 알려 준다고 적었다.

## 트레이드오프

### 사용량과 정확도를 맞바꾼다

논문 전체를 여러 에이전트가 번역하므로 Claude 사용량이 꽤 든다고 작성자가 직접 적었다.
조각을 작게 나눌수록 실수는 줄지만 조각마다 용어 표, 이웃 발췌, 검증이 따라붙어 호출 수가 늘어난다.
조각을 키우면 사용량은 줄지만 같은 글이 길게 한 번에 번역되어 수식과 용어의 오류가 늘어난다고 작성자가 판단했다.
둘을 함께 줄이는 방법은 README에 없고, 작성자는 지속적으로 최적화하겠다고만 했다.

### 원본이 LaTeX일 때만 얻는 이점이다

PDF 경로에서는 수식이 깨지므로, 수식이 많은 논문에서는 LaTeX 경로가 사실상 전제다.
arXiv에는 논문마다 원본이 있어도 매크로를 정의한 `.sty`가 외부 파일이거나 TikZ로 그린 그림이 있으면 구조가 어려워지고, README는 이를 하나씩 따로 다루는 스크립트로 풀었다.
이것이 이 스킬의 강점이자 유지보수 부담이다.
README는 새 논문마다 새 LaTeX 구성이 나오고, 만난 구성은 다음 번에 처리되도록 저장소(`KNOWLEDGE.md`, `corpus/shapes.json`)에 쌓는다고 설명한다.
처음 보는 구성이 나오는 논문에서는 실패할 수 있다는 뜻이다.

### 번역본의 재배포는 논문의 라이선스가 정한다

README는 번역한 책을 릴리스에 붙이는 것은 논문의 라이선스가 허락할 때만 하며, 데모 PDF는 CC BY 4.0 논문에서 나왔다고 밝힌다.
arXiv 기본 라이선스의 논문은 번역본의 재배포를 허락하지 않는다고도 적는다.
개인이 읽으려고 번역하는 것과 번역본을 공유하는 것은 다른 일이다.

## 함정

### 서브에이전트가 맡기 전에 스킬이 허락을 요구한다

스킬은 arXiv 원본을 내려받기 전에 묻는다.
사용자가 허락한 요청에만 네트워크 접근을 쓰고, 나머지는 로컬 도구가 처리한다는 설계다.
README는 네트워크에서 받는 것은 `https://arxiv.org/e-print/<id>` 하나뿐이고, 원격으로 보내는 정보나 텔레메트리는 없다고 적는다.
이 노트는 이 주장을 코드로 확인하지 않았다.

### 글꼴이 다르면 같은 쪽이 나오지 않는다

README는 글꼴이 같은 쪽 구성을 결정한다고 경고한다.
Chromium이 CFF나 가변 글꼴을 Type3로 인쇄하기 때문에 Noto Serif KR, Noto Serif CJK는 설치되어 있어도 쓸 수 없다고 한다.
`doctor.py`가 빌드에 실제로 쓸 글꼴을 확인한다.

### 도구가 쓰는 위치에 주의한다

스킬은 작업 파일을 현재 디렉터리의 `<book>_temp/`에 쓰고, 배운 것은 스킬 폴더 안의 로그(`KNOWLEDGE.md` 등)에 덧붙인다.
스킬 폴더를 읽기 전용으로 두거나 여러 사용자가 공유하면 로그 쓰기가 막히거나 섞일 수 있다.
README는 `scripts/install_advisors.py`가 에이전트 정의를 `~/.claude/agents/`에 복사하지만 사용자가 직접 실행할 때만 그렇다고 밝힌다.

### 완료는 검증이 아니라 책이 나왔다는 뜻이다

GN 글의 26편 모두 책으로 나온다는 말은 빌드가 끝났다는 보고이고, 번역 품질을 사람이 평가했다는 보고가 아니다.
README의 검증은 수식, 숫자, 표의 구조, 용어 일관성 같은 기계적으로 비교 가능한 항목이며 문장이 자연스러운지는 이 검사가 보지 않는다.

## 확인하기

직접 써 보기 전에 해 볼 수 있는 확인이다.

1. `python scripts/doctor.py --strict`를 돌려 필요한 도구와 글꼴을 확인한다.
2. 데모 PDF(릴리스의 `looped-flows_ko.pdf`)를 열어 원논문 표 1과 번역본의 같은 표를 맞대어 본다. README의 대표 사례다.
3. 자기 분야의 짧은 논문 하나로 돌려 `python tests/dry_run.py <temp_dir> --lang ko`를 먼저 실행한다. README는 이것이 API 호출 없이 전체 파이프라인을 돌린다고 설명한다.
4. 결과가 나오면 `python scripts/verify_chunk.py <temp_dir> --lang ko --strict`와 `python tests/consistency_probe.py <temp_dir> --lang ko --strict`로 조각 검증과 용어 흔들림을 본다.

이 노트는 위 명령을 실행하지 않았다.

## 체크리스트

- 번역할 논문이 arXiv에 있고 LaTeX 원본을 제공하는가.
- Python, Pandoc, Chromium 계열 브라우저, PyMuPDF가 설치되어 있고 `doctor.py`가 통과하는가.
- 한국어 글꼴이 README가 말한 계열로 설치되어 있는가.
- 원본을 내려받기 전에 스킬이 묻는 것을 확인했는가.
- 사용량을 감당할 수 있는가, 아니면 짧은 논문으로 먼저 시험했는가.
- 결과의 수식과 표의 숫자를 원논문과 몇 곳 맞대어 보았는가.
- 번역본을 공유하려는 논문의 라이선스가 재배포를 허락하는가.

## 비평

### 검증의 폭과 번역의 질을 구분해서 읽어야 한다

README는 2,705개의 테스트와 열 개가 넘는 점검 스크립트를 내세운다.
이것은 수식, 숫자, 구조 같은 기계적 항목이 번역을 거쳐 보존되는지에 대한 근거이고, 번역된 문장이 독자에게 읽히는지에 대한 근거가 아니다.
작성자 스스로 깨지는 논문이 있으면 이슈로 알려 달라고 쓴 것은 현재의 보증이 작성자가 돌려 본 논문의 범위에 묶여 있음을 보여 준다.
26편이나 28편이라는 수는 이 범위의 크기를 알려 주며, 분야를 다양하게 했다는 설명이 있어도 모든 논문 형식을 대표한다고 읽을 수는 없다.

### 포크의 위치가 새 프로젝트의 성숙도를 알려 준다

GitHub API로 보면 이 저장소는 2026-09-02에 만들어졌고 별이 30개, 마지막 푸시가 2026-10-23이며 열린 이슈가 0개다.
원본인 `deusyu/translate-book`은 2026-03-15에 만들어졌고 별이 2,153개, 열린 이슈가 33개다.[^upstream]
이슈가 0개라는 것은 문제가 없다는 뜻이기보다 아직 쓰는 사람이 적다는 뜻에 가깝다.
GN 글에 쓰인 대로 Anthropic 공식 플러그인 디렉터리에도 올라 있지만 업데이트가 심사 중이라 최신 버전은 GitHub에서 받으라고 한다.
이 수치는 이 문서를 쓴 시점의 스냅샷이다.

## 기억할 원칙

### 번역의 원료는 렌더링된 결과가 아니라 저자가 쓴 원고다

PDF에서 수식을 되살리려는 시도는 이미 잃어버린 구조를 추정하는 일이다.
원본이 있으면 원본에서 출발하는 편이 이후 모든 검증을 단순하게 만든다.
이 원칙은 번역뿐 아니라 렌더링된 결과를 다시 읽어야 하는 모든 파이프라인에 적용된다.

### 조각마다 다른 에이전트에게 맡기면 일관성은 따로 만들어야 한다

병렬 번역은 속도를 주지만 용어와 대명사의 일관성을 공짜로 주지 않는다.
이 스킬이 용어집, 조각별 용어 표, 이웃 발췌, 검증을 따로 두는 것은 그 값이다.
병렬 에이전트를 설계할 때는 무엇이 조각 사이에 공유되어야 하는지를 먼저 적는다.
