# Agent Sprite Forge: 승인한 스틸 한 장에서 게임용 스프라이트 세트 전체를 뽑는 에이전트 스킬

<https://github.com/0x0funky/agent-sprite-forge>

Show HN: [Sprite sheets from prompts (Codex skill)](https://news.ycombinator.com/item?id=47884666)

## 소개

Agent Sprite Forge는 에이전트에게 게임용 2D 그래픽 리소스를 만들게 하는 스킬
묶음이다.
저장소 설명은 프롬프트로 2D 스프라이트 시트와 맵, 투명 PNG 프레임,
애니메이션 GIF를 만드는 에이전트 스킬이라고 한다.
Claude Code(플러그인), Codex, Grok에 설치할 수 있다.

README의 요지는 승인한 스틸 한 장에서 캐릭터의 모든 동작을
엔진에 넣을 수 있는 형태로 뽑는다는 것이다.
에이전트가 가진 가장 좋은 이미지 경로로 마스터 스틸을 만들고,
동작마다 그 스틸에서 이미지 투 비디오(image-to-video) 클립을 하나씩 만든 뒤,
결정적인 Python 도구가 검사, 키잉, 정렬, 루프 선택, 재타이밍, 마감,
패키징을 맡는다.
0.4 이전에는 이미지 생성기가 그린 시트를 잘라 쓰거나 클립 하나를 손으로
키잉했는데,
0.4가 이 과정을 측정 기반 파이프라인으로 바꿨다고 설명한다.

2026년 11월 6일 기준 GitHub 정보는 다음과 같다.
MIT 라이선스, Python, 2026년 4월 23일 생성,
스타 5,249개, 포크 512개, 열린 이슈 14개다.
마지막 푸시가 2026년 11월 5일이다.
토픽은 `agent-skills`, `codex`, `pixel-art`, `sprite-generator`이다.

포함된 스킬은 다섯 개이고, 서로의 스크립트를 상대 경로로 부르므로 함께
두어야 한다.

| 스킬               | 용도                                                       |
| ------------------ | ---------------------------------------------------------- |
| `generate2dsprite` | 마스터 스틸, 캐릭터, 생물, 소품, 아이콘, FX, 시트 후처리   |
| `video2dsprite`    | 마스터 스틸 한 장에서 동작 세트 전체를 만드는 비디오 경로  |
| `generate2dmap`    | 탑다운과 횡스크롤 맵, 타일, 소품 묶음, 시차 배경           |
| `generate2dmedia`  | 모든 이미지와 클립 생성의 경로 선택, 제공자, 용량 확인     |
| `codeart2d`        | 이미지 모델 없이 코드로 그리는 픽셀 스프라이트와 벡터 아트 |

## 설치와 시작

Claude Code는 플러그인으로 설치한다.

```bash
claude plugin marketplace add 0x0funky/agent-sprite-forge --sparse .claude-plugin skills
claude plugin install agent-sprite-forge@agent-sprite-forge
python -m pip install "numpy>=1.26" "Pillow>=10.1" "scipy>=1.11"
```

Codex와 Grok은 저장소를 받아 설치 도구를 쓴다.

```bash
git clone https://github.com/0x0funky/agent-sprite-forge.git
cd agent-sprite-forge
python -m pip install -r requirements.txt
python tools/install_skills.py --apply --host codex   # Grok은 --host grok
```

영상 처리에는 ffmpeg 5.1 이상이 필요하다.
이미지와 영상 생성에는 OpenAI, Gemini, xAI, BytePlus,
fal.ai 중 하나의 API 키가 있거나
로그인된 Codex 또는 Grok CLI가 있어야 한다.
설치한 뒤 새 에이전트 세션을 열어야 스킬이 로드된다.

사용은 프롬프트 두 번이다.

```text
Use $generate2dsprite to make a master still of a fox ranger for a 2D platformer.
Show me three takes.
```

```text
Use $video2dsprite to turn the approved fox master into idle, run, attack and hurt,
pixel finish in 48x64 cells at 80 ms, and export it for Godot and Aseprite.
```

## 파이프라인

흐름은 마스터, 세트, 마감, 내보내기 순이다.

마스터 단계에서 `master_still.py`가 여러 테이크를 만들고,
모자란 부분은 편집으로 고친 뒤 하나를 승인한다.
승인된 스틸은 키잉되고 캐릭터 등급에 맞는 구도로 패딩되어 `master.json`에
기록된다.
이 승인은 사람이 한다.

세트 단계에서 `sprite_set.py`가 동작마다 클립 하나를 만든다.
각 테이크는 면적, 발, 정체성, 확대, 뒤돌기, 가장자리, 배경, 불필요한 물체,
움직임, 끝 포즈, 색 번짐, 타이밍을 검사하는 관문을 통과해야 하고,
최대 세 번까지 수정 지시를 붙여 다시 뽑는다.
통과한 클립은 소프트 매트로 배경을 지우고,
기록된 변환의 역변환으로 정렬하며,
걷기, 달리기, 대기는 측정으로 루프를 고르고,
한 번만 재생되는 동작은 게임 속도로 재타이밍한다.

마감은 HD가 기본이고 요청하면 픽셀 마감을 한다.
픽셀 마감은 날카로운 다운스케일, 최대 32색의 팔레트, 선택적 외곽선,
이진 알파를 쓴다.
모든 동작에는 디자인 색을 마스터의 색에 고정하는 색 잠금(colour lock)이 걸린다.

내보내기 대상은 다음과 같다.

| 대상                   | 산출물                                                              |
| ---------------------- | ------------------------------------------------------------------- |
| 웹과 모든 엔진         | `animation.json` 3.0, PNG 아틀라스, VP9 알파 WebM, 알파 포장 MP4    |
| Godot 4                | SpriteFrames `.tres`와 AnimatedSprite2D 씬, AnimatedSprite3D 패키지 |
| Aseprite, Phaser, Pixi | Aseprite JSON 아틀라스(프레임 태그, 이벤트, 피벗)                   |
| 맵                     | Tiled 1.10, Godot 4.3 이상, LDtk 1.5.3                              |

맵 스킬은 지면만 있는 기본 맵, 꾸민 참고 맵, 소품 묶음을 만든 뒤
소품을 투명 배경에 고정해 겹치고,
충돌과 도달 가능성과 출구는 데이터에서 계산한다.

## 모델 경로와 비용 기록

모든 이미지와 클립은 `route_media.py` 한 명령을 거친다.
순서는 사용자가 설정한 API 키, 로그인된 로컬 Codex 또는 Grok CLI,
마지막으로 코드 아트다.
키를 설정한 것이 동의로 취급되므로 호출마다 묻지 않는다.
검열에 걸려 거절된 요청이나 돈이 들었을 수 있는 결과는
다른 경로로 다시 시도하지 않는다고 한다.
키는 환경 변수나 사용자 설정 폴더의 JSON 파일에서 프로세스 안으로만 읽고
출력, 기록, 명령줄 전달을 하지 않는다고 README는 밝힌다.

모든 호출은 프로젝트의 `.forge/ledger.jsonl`에 추정 비용, 제공자의 작업 ID,
산출물의 sha256과 함께 한 줄씩 남는다.
상한은 기본값이 없고 `--budget-usd`, `--max-calls`,
`FORGE_MAX_PAID_REQUESTS` 같은 옵션으로 직접 정해야 한다.

## 개발자가 밝힌 한계

이 문서는 README가 링크한 한계 문서와 검증 기록도 읽었다.

개발과 모든 측정은 Windows 11에서 했고,
테스트는 로컬에서만 돌렸으며 리눅스와 macOS는 실행하지 않았다.[^limits]
저장소에 CI가 없다.[^validation]
Godot, LDtk, Aseprite 등의 가져오기는 구문 분석 수준에서만 확인했고
편집기에서 열어 보지 않았다.[^limits]
키잉과 루프의 임계값은 만화풍 클립 하나에서 얻은 것이고,
초록이나 파랑 키, 외곽선 없는 그림, 빠른 움직임은 합성 테스트로만
다뤘다.[^limits]
수치 점검은 해부학, 정체성, 움직임의 품질을 승인하지 않으며,
이런 항목은 모든 점검 결과의 `notProven`에 적힌다.[^limits]
검증 기간에 실제 API 제공자를 호출한 적이 없고
다섯 개의 어댑터는 문서 대조와 모의 계약 테스트로만 확인했다.[^validation]

검증 기록은 2026년 10월 6일의 실제 실행 두 번을 담는다.
Aria(HD)의 여섯 동작은 클립 44개가 들었다.
생성 성공이 34개, 요청 실패가 8개, 다시 키잉한 것이 2개였다.
달리기는 10번째, 공격은 9번째, 점프는 11번째 테이크를 받아들였고,
피격은 10번 중 6번째를 받아들였다.[^validation]
Grok은 요청한 시작과 끝 정지 구간을 따르지 않았고
마지막 프레임을 고정하지 못했으며,
모든 한 번짜리 동작을 슬로 모션으로 재생했다.[^validation]
픽셀 여우의 달리기는 세트 자체의 재시도 흐름에서는 반복되는 걸음이 나오지 않아,
프롬프트를 고쳐 손으로 돌린 실행에서 얻은 주기의 프레임을 직접 골라
마감했다.[^validation]

## 비평

### 측정은 개발자 한 사람의 실행 한 번이다

README의 이전과 이후 표는 캐릭터 둘(Aria와 여우)과 클립 하나의 결과다.
키잉 임계값이 만화풍 클립 하나에서 나왔다고 개발자 스스로 적었으므로,[^limits]
다른 화풍과 다른 키 색에서 같은 숫자가 나오는지는 알 수 없다.
`bench` 테스트가 숫자를 재현하지만 그 입력은 소유자의 증거 클립이고
경로를 환경 변수로 줘야 한다.[^validation]
CI가 없어서 숫자는 소유자의 로컬 환경에서만 확인된다.[^validation]
표의 숫자가 거짓이라는 근거는 없지만,
다른 사람이 같은 숫자를 얻을 수 있다는 근거도 아직 없다.

### 품질 점검은 같은 표본에서 보정되고 평가됐다

README는 좋은 테이크의 오탈락이 24개 중 18개에서 0개로 줄었다고 한다.
검증 기록에 따르면 이 점검은 라이브 실행의 라벨 붙은 테이크 42개로
보정되었다.[^validation]
같은 기록에서 보정 뒤의 관문은 나쁜 테이크 18개 중 9개만 걸러 내
정밀도는 1.00이지만 재현율은 0.50이다.[^validation]
이 문서의 해석으로는 0개라는 숫자가 보정에 쓴 표본에서 잰 값이어서
새 캐릭터에서의 성능을 보증하지 않는다.
나쁜 테이크의 절반이 통과하므로 마지막 판단은 에이전트가 검토 시트를
보고 하는데,
README도 숫자는 바뀐 무기나 가려진 얼굴을 보지 못한다고 적는다.
결국 모델이 만든 출력을 모델이 눈으로 검수하는 단계가 품질의 마지막 관문이다.

### 몇 번 돌려야 하는지가 비용의 핵심인데 기본 상한이 없다

여섯 동작에 클립 44개가 들었고 달리기 하나가 10번이었다.[^validation]
검증은 API 키 없이 구독 할당량으로 돌려 API 지출은 0달러였다고
기록한다.[^validation]
비용이 없어진 것이 아니라 구독 할당량으로 옮겨 간 것이다.
기본 상한이 없으므로 재시도가 많은 캐릭터는 할당량이나 요금을 빠르게 쓴다.
원장이 모든 호출을 남기는 것은 장점이지만 상한은 사용자가 직접 걸어야 한다.

### 핵심 생성 단계가 외부 CLI의 동작에 묶여 있다

로컬 경로는 Codex CLI의 `image_gen`과 ACP 모드의 Grok 이미지 투 비디오를 부른다.
검증은 특정 버전(codex-cli 0.155.1, grok 1.0.40)에서 했고,
Grok에는 읽기 전용 로그인 상태 확인 명령이 없다.[^limits]
Grok이 6초나 10초 클립만 만들 수 있다는 점은 실행 중에 발견된
제약이었다.[^validation]
제공자가 동작을 바꾸면 경로가 깨질 수 있고,
모델이 그린 움직임 자체(슬로 모션, 색 번짐)는 후처리로 보정만 될 뿐
고쳐지지 않는다.

### 게임용이라는 말의 마지막 구간이 검증되지 않았다

엔진으로 내보내는 파일은 구문 분석까지만 확인되었다.[^limits]
WebGL 합성기는 헤드리스 브라우저의 소프트웨어 렌더러에서만 돌았고
실제 GPU나 Safari, iPhone에서는 돌려 보지 않았다.[^limits]
README의 쇼케이스 게임들은 이전 릴리스로 만든 것이라고 적혀 있어
0.4 출력의 엔진 통합 증거는 아니다.

### 생성물의 권리는 저장소의 라이선스와 별개다

MIT는 저장소의 코드와 문서에만 적용된다.
이미지와 영상은 해당 제공자의 약관을 따르고,
소유하지 않은 캐릭터나 사람을 따라 그리거나 프롬프트하지 말라고 README가
경고한다.
상업 프로젝트에는 직접 통제하는 원작 캐릭터나 지적재산을 쓰라고 한다.
게임에 넣을 자산이라면 어떤 제공자 경로로 만들었는지가 곧 권리의 조건이 된다.

## 인사이트

### 생성은 모델에게, 측정은 코드에게 맡기고 사람의 승인은 한 곳에만 둔다

이 스킬의 구조는 역할을 셋으로 가른다.
모델이 이미지와 클립을 만들고,
결정적인 도구가 색 수, 알파, 테두리, 루프 이음매처럼 잴 수 있는 것을 검사하며,
잴 수 없는 정체성은 마스터 스틸을 사람이 승인하는 한 지점에서 고정한다.
README의 문장대로 스크립트는 창작의 두뇌가 아니다.
이 문서의 해석으로는 이 분업이 에셋을 만드는 스킬 전반에 옮겨 갈 수 있는 틀이다.
승인이 한 번이면 이후 단계는 마스터와의 거리를 재는 문제로 바뀌고,
거리를 잴 수 없는 항목만 에이전트의 눈 검수와 사람의 확인에 남는다.

### 시트를 자르던 방식에서 영상을 측정하는 방식으로 옮겨 갔다

이전에는 한 장에 그려진 동작 격자를 잘라 썼다.
격자 안의 프레임은 서로 어긋나 정렬 문제를 일으켰다.
0.4는 동작마다 클립을 만들고 정렬을 기록된 변환의 역변환으로 풀며,
걷기와 달리기의 루프를 접지 발에서 잰 속도로 고른다.
이 방식은 정렬 문제를 줄이지만 재시도라는 새 비용을 만든다.
검증 기록의 44개 클립은 이 교환의 값이다.
어느 쪽이 나은지는 동작당 받아들인 프레임 하나의 총비용으로 비교해야 한다.

### 무엇을 믿고 시작할지는 작은 시험으로 정한다

이 스킬을 쓰려는 사람은 README의 숫자 대신 자기 캐릭터로 시험하는 편이 안전하다.
`forge_doctor.py`로 설정된 키와 경로 순서를 확인하고,
`--budget-usd`나 `--max-calls`로 상한을 먼저 걸고,
동작 하나(대기)부터 돌려 재시도 횟수와 비용을 본 뒤,
나머지 동작을 확장한다.
내보낸 파일은 쓸 엔진의 편집기에서 직접 열어 확인한다.
README가 아직 검증하지 못했다고 밝힌 부분이 바로 그곳이다.

### 결론을 바꿀 관찰

다른 화풍과 키 색, 다른 운영 체제에서 독립된 사람이 같은 측정을 재현하면
이 스킬의 숫자가 일반화된다.
Godot과 Aseprite에서 내보낸 파일이 열린다는 확인이 나오면 게임용이라는 말이
완성된다.
캐릭터 하나를 세트까지 끝내는 데 든 총 클립 수와 비용이 여러 사례로 공개되면
이 방식의 경제성을 판단할 수 있다.
반대로 새 캐릭터에서 보정된 품질 점검이 좋은 테이크를 자주 놓친다는
사례가 나오면
README의 오탈락 0개는 표본 안의 값으로 읽어야 한다.
