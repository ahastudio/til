# AVA: 에이전트용 AI 네이티브 시각 분석 프레임워크

<https://ava.antv.vision/>

<https://github.com/antvis/AVA>

GN 토론: <https://news.hada.io/topic?id=37317>

## 소개

Ant Group의 데이터 시각화 팀 AntV가 만드는 TypeScript 라이브러리이다.
코드를 설치하거나 실행하지 않았고 벤치마크 결과(이미지)와 문서 사이트는 열지 않았다.
성능과 정확도 주장은 모두 프로젝트의 서술이다.

GitHub API 기준으로 2026년 11월 17일 현재 별 1,649개, 포크 171개, 열린 이슈 16개이고 MIT 라이선스이다.
저장소는 2020년 1월에 만들어졌고 최신 릴리스는 2026년 11월 13일의 v4.0.3이며, 설명문은 에이전트를 위해 만든 AI 네이티브 시각 분석 프레임워크이다.
저장소의 기본 브랜치 이름이 `master`가 아니라 `ai`이고, 이 브랜치 이전의 README(`master`)는 자동화된 시각 분석 프레임워크를 이렇게 소개한다.
데이터 처리, 자동 인사이트, 차트 지식 베이스, 차트 추천의 네 모듈과 이를 쓰는 React 컴포넌트(NarrativeTextVis, InsightCard, AutoChart)로 이루어진 패키지 둘이었다.
현재 README는 이를 에이전트와 자연어 중심으로 다시 쓴 모습이다.

현재 README의 핵심 문구는 이렇다.
AVA를 JavaScript용 PandasAI라고 생각하라는 것이다. 자연어 데이터 분석과 시각화를 앱과 AI 에이전트에 가져온다고 한다.

저장소가 홈페이지로 등록한 주소는 ava.antv.vision이다.
읽은 시점(2026년 11월 18일)에 열어
첫 화면 제목이 “AVA - AI-Native Visual Analytics | AntV”임을 확인했다.
사이트 본문은 읽지 않았고, 사이트의 설명은 제작자의 주장이다.

## 주요 기능

README가 내세우는 여섯 가지 이점은 다음과 같다.

- 데이터 원천을 가로지르는 분석: 파일과 데이터베이스의 데이터를 하나의 질의로 합친다.
- 근거가 있는 답: 각 답 뒤의 질의와 결과를 확인할 수 있다.
- 똑똑한 시각화: 질문과 데이터에 맞춰 차트를 안내한다.
- 로컬 실행: 분석이 어디서 돌고 어떤 모델 엔드포인트를 쓸지 고른다.
- 공개된 벤치마크: 공개된 시험 조건에서 기준 답에 대한 정확도를 확인한다.
- 에이전트 통합: 에이전트가 추론하고 AVA가 데이터 작업 흐름을 실행한다.

지원하는 데이터 원천은 CSV, JSON, Parquet, Excel, 텍스트, Feishu Bitable, Tencent Docs, GitHub, SQLite, MySQL, PostgreSQL, SQL Server, MongoDB, Supabase, ClickHouse, Snowflake이다.
저장소는 빠진 원천을 이슈나 PR로 요청하라고 한다.

## 사용법

설치는 Node.js 22.13 이상에서 `npm install @antv/ava`이다.
사용 흐름은 다섯 단계로 제시된다.

1. 불러오기: 모델 설정(모델 이름과 API 키, 선택적으로 공급자 URL)을 넣고 `ava.source`로 CSV 같은 원천을 읽는다.
2. 탐색: `ava.schema`와 `ava.profile`로 구조와 데이터 품질을 확인하고, `ava.semantic`으로 비즈니스 정의(예: sales 열은 할인 후 금액)를 덧붙인다.
3. 제안: `ava.suggest(3)`이 데이터에 맞는 질문 세 개를 제안한다.
4. 분석: `ava.analyze('1월과 2월 제품별 매출을 비교하라')` 같은 자연어 질의에 답과 데이터를 돌려준다. 예시 출력은 총 매출이 43.94% 줄었고 노트북 매출 감소가 가장 컸다는 것이다.
5. 시각화: `ava.visualize`가 질의와 분석 결과 데이터로 차트를 만든다(GPT-Vis 기반).

에이전트에게는 `npx skills add antvis/AVA`로 스킬을 설치하게 할 수 있고, 터미널에서는 `ava source`와 `ava analyze` 명령을 쓴다.
평가 조건과 보고서는 문서 사이트의 벤치마크 페이지에 있고 README는 DataBench와 Spider2-Lite에서 원본 데이터, 스키마와 프로파일, 의미 맥락을 비교한 결과를 이미지로 싣는다.

## 분석

### 중심 주장은 에이전트는 추론하고 데이터 작업은 라이브러리가 실행한다는 것이다

README의 흐름(불러오기, 탐색, 제안, 분석, 시각화)은 모두 데이터 작업을 결정적인 함수 호출로 묶고 언어 모델은 질의를 만드는 쪽에 둔다.
정확도 주장을 스키마와 프로파일과 의미 맥락을 더할수록 오르는 벤치마크로 보여 주려는 구성이다.

### 의미 계층이 중심 설계이다

`ava.semantic`으로 사람이 비즈니스 정의를 덧붙이게 하는 단계가 흐름에 있다.
자연어 분석의 흔한 실패(열의 의미를 오해함)를 사람이 쓴 정의로 막으려는 설계로 읽힌다. 이는 이 문서의 해석이다.

### 프로젝트의 방향이 바뀌었다

README의 이전 버전은 자동 인사이트와 차트 추천을 하는 알고리즘 라이브러리였고, 현재는 LLM 중심의 에이전트 도구이다.
기본 브랜치 이름의 변화가 이 전환을 반영한다.

## 비평

### 정확도 주장의 근거는 프로젝트가 낸 벤치마크이다

DataBench와 Spider2-Lite 결과를 자체 평가 조건으로 보여 주고, README는 수치를 본문이 아니라 이미지로 둔다.
같은 이유로 다른 도구와의 비교도 알 수 없다.

### 모델과 비용에 대한 설명이 적다

사용 예시는 모델 이름과 API 키를 넣는 것으로 끝나고, 어떤 모델에서 어느 정도의 정확도와 비용이 나오는지는 README에 없다.
로컬 실행이 분석이 도는 위치를 고르는 것이라고 하나 모델 호출이 외부 API인지 로컬 모델인지는 설정에 달려 있다.

### 보안과 데이터 노출에 대한 서술이 없다

데이터베이스 연결 정보와 모델 API 키를 같은 설정에 두고, 질의가 자연어에서 SQL로 바뀌어 실행된다.
README는 질의 결과를 확인하게 하지만 생성된 SQL의 권한 제한이나 데이터가 모델 공급자에게 가는 범위는 다루지 않는다.

### 외부 반응

HN에서 이 저장소의 주소로 올라온 스레드는 검색되지 않았고, Lobste.rs 검색(AntV와 저장소 이름)에서는 같은 조직의 다른 저장소(gatsby-theme-antv)만 나왔다.
GeekNews에는 토픽이 있고 사용자 댓글이 하나 있었다. 하네스 에이전트를 구현하며 DuckDB를 도구로 썼는데 이 프로젝트를 보고 배우겠다는 짧은 반응이어서 본문에 엮지 않았다.

## 인사이트

### 가져갈 것은 의미 맥락을 데이터 분석 에이전트의 입력으로 두는 방식이다

열 이름만 주면 에이전트가 틀리기 쉬운 곳(할인 후 금액인지, 월 비교의 기준 열이 무엇인지)에 사람이 쓴 정의를 덧붙이는 단계는 이 라이브러리를 쓰지 않아도 데이터 에이전트 설계에 쓸 수 있다.
이는 이 문서의 정리이다.

### 확인할 관찰

이 프로젝트의 주장을 가를 관찰은 세 가지이다.
공개 벤치마크의 정확도가 독립적으로 재현되는지,
v4 이후의 방향(에이전트 중심)이 안정적으로 유지되는지,
데이터 노출과 SQL 권한에 대한 문서가 추가되는지이다.
