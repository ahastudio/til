# CARTO: 데이터 웨어하우스 안에서 도는 “에이전트형 GIS” 플랫폼

<https://carto.com/>

## 소개

CARTO는 스스로를 “Agentic GIS Platform”이라고 부르는 클라우드 공간 분석 플랫폼이다.
홈페이지는 전통적인 GIS를 넘어 모든 팀이 확장 가능한 공간 분석을 하되, 데이터는 BigQuery 같은 고객의 데이터 웨어하우스를 떠나지 않는다고 소개한다.
그리고 사일로도 ETL도 거버넌스 타협도 없는 “유일한 100% 클라우드 네이티브 GIS 플랫폼”이라고 주장한다.
연결 대상으로는 Google Cloud, AWS, Azure, Snowflake, Databricks, Oracle을 든다.

CARTO의 뿌리는 오픈소스 지도 서비스 CartoDB다.
Hacker News에는 2012년 무렵부터 CartoDB와 `blog.cartodb.com`의 글이 올라왔고, 2016년에는 CARTO라는 이름으로 지도 분석 도구 Builder를 소개하는 글이 올라왔다.
지금의 CARTO는 그 지도 서비스에서 기업용 공간 분석 플랫폼으로 옮겨 간 모습이다.

## 주요 기능

홈페이지는 제품을 네 갈래로 소개한다.

| 영역            | 홈페이지의 설명                                                                   |
| --------------- | --------------------------------------------------------------------------------- |
| Analytics       | 드래그 앤 드롭 로우코드 분석, ML과 AI가 통합된 100개 넘는 분석 구성 요소          |
| Visualization   | 수십억 개 데이터 포인트 시각화, 자연어로 지도 만들기                              |
| AI Agents       | 자연어 프롬프트로 앱을 만들고 AI 에이전트로 다듬기, 고객의 모델과 엔드포인트 사용 |
| App Development | 백엔드 ETL 없이 레이크하우스에서 도는 앱, deck.gl과 WebGL과 GPU 기반 시각화       |

제품 이름으로는 지도를 만드는 Builder, 분석 과정을 흐름으로 짜는 Workflows, 웨어하우스 안에서 공간 함수를 돌리는 Analytics Toolbox, 데이터를 보강하는 Data Observatory가 페이지 곳곳에 나온다.
고객 사례로는 보험, 부동산, 투자, 전자상거래, 자동차 판매망의 담당자들이 등장하며, 보험 인수 담당자가 데이터 관리 대신 판단에 시간을 쓰게 됐다거나 누구나 “어느 동네가 가장 빨리 성장할까” 같은 질문을 던져 곧바로 답을 얻는다는 증언을 싣는다.
산업별로는 보험, 통신, 금융, 소매, 마케팅, 물류를, 용도별로는 네트워크 배치, 재해 모델링, 사기 탐지, 입지 선정, 공급망 최적화 같은 항목을 든다.

## 에이전트와의 연결

CARTO의 에이전트 기능은 두 방향이다.
하나는 CARTO AI Agents로, Builder 지도나 앱 안에 만드는 대화형 에이전트다.
분석가가 에이전트가 쓸 수 있는 도구와 범위를 정하고, 에이전트는 레이어를 더하거나 스타일을 바꾸는 일부터 쿼리나 Workflows를 실행하는 일까지 한다.
AI 에이전트 페이지는 고객이 검증한 자기 LLM과 엔드포인트를 쓰고 도구를 웨어하우스 안에서 실행한다고 강조한다.

다른 하나는 2026년 2분기에 내놓은 CARTO for Agents다.
방향이 반대라서, Claude, ChatGPT, Copilot, Codex, Cursor 같은 외부 에이전트 플랫폼이 CARTO 자체를 조작해 지도를 만들고, Workflows를 돌리고, 웨어하우스를 조회하게 한다.
구성 요소는 셋이다.

| 구성 요소          | 역할                                                             |
| ------------------ | ---------------------------------------------------------------- |
| CARTO CLI          | 사람과 에이전트가 플랫폼을 프로그램으로 다루는 명령행 인터페이스 |
| CARTO MCP Server   | CARTO 기능을 MCP 클라이언트에 연결하는 호스팅 MCP 서버           |
| CARTO Agent Skills | 에이전트가 CARTO를 잘 쓰도록 돕는 공개 스킬 모음                 |

FAQ에 따르면 MCP 서버를 연결하는 데는 설치가 필요 없고, CLI와 Agent Skills를 쓰는 코딩 에이전트는 로컬 설치가 필요하다.
모든 쿼리는 BigQuery, Snowflake, Databricks, Redshift, Oracle, PostgreSQL 가운데 고객의 웨어하우스 안에서 기존 권한과 행 수준 보안 아래 돈다고 한다.
지원하는 에이전트 플랫폼은 MCP를 지원하는 모든 플랫폼이며, Claude, ChatGPT, Microsoft Copilot, Gemini Enterprise, Snowflake Cowork, Databricks Agents, Oracle AI Factory를 예로 든다.

같은 분기 업데이트에는 AI 에이전트 도구 추적, OpenAI 호환 제공자와 최신 모델 지원, Workflows 버전 기록, Oracle과 Databricks용 Analytics Toolbox 함수, Builder 레이어 그룹과 Google Photorealistic 3D Tiles, 프로젝트와 폴더, 기업용 AI 사용 통제가 함께 들어갔다.

## 가격

가격 페이지는 네 가지 요금제를 둔다.
새로 생긴 Pay As You Go는 사용한 만큼 내는 방식이지만 12개월 계약에 월 청구이며, SaaS로만 쓸 수 있고 사용자 정의 브랜딩과 감사 로그가 없다.
Enterprise, Strategic, Custom은 연간 할당량을 약정하는 방식으로, 위로 갈수록 할당량이 커지고, 자체 호스팅이 가능해지며, API 접근과 토큰 제한이 풀리고, 지원 등급이 오른다.
네 요금제 모두 가격은 공개하지 않고 상담이나 견적을 요구한다.

지도 배경 타일 서비스 CARTO Basemaps에도 변화가 있었다.
Basemaps 안내 페이지에 따르면 이제 타일 URL에 API 키가 필요하며, 키 없이 쓰면 타일에 “API key required” 워터마크가 뜬다.
비상업 용도는 월 500만 요청까지, 상업 용도는 월 100만 요청까지 무료이고, 그 이상은 월 500달러 또는 연 5,000달러에 월 1,000만 요청까지 쓰는 Basemaps Commercial이 있으며, CARTO 고객은 모든 요금제에 포함된다.
2026년 9월 23일 이전에 등록한 키는 11월 30일까지 그대로 동작한다.
페이지는 요금제와 할당량, 출처 표기 문구, URL 템플릿을 JSON으로도 공개해 AI 도우미가 읽을 수 있게 했다.

## 분석

### “에이전트형 GIS”의 실체는 데이터를 옮기지 않는 구조에 있다

홈페이지의 수식어 가운데 가장 구체적인 약속은 “에이전트형”이 아니라 “데이터가 웨어하우스를 떠나지 않는다”는 것이다.
전통적인 GIS는 공간 데이터를 자기 서버나 파일로 옮겨 분석했고, 그 과정에서 ETL과 복사본과 권한 관리의 문제가 생겼다.
CARTO는 BigQuery, Snowflake, Databricks 같은 웨어하우스가 공간 함수를 갖추게 되자, 분석을 웨어하우스 안으로 밀어 넣고 자신은 그 위의 분석 도구와 시각화 계층이 되는 쪽을 택했다.

이 구조가 에이전트와 결합할 때 의미가 커진다.
에이전트가 데이터를 외부로 끌어내지 않고 웨어하우스 안에서 쿼리를 돌리면, 기업이 이미 설정한 권한과 행 수준 보안이 그대로 적용된다.
CARTO for Agents가 강조하는 것도 새 에이전트 기능보다, 외부 에이전트가 들어와도 거버넌스가 흔들리지 않는다는 점이다.

### 채팅봇의 쿼리를 “승인된 워크플로”로 바꾸는 설계

CARTO for Agents 페이지에서 가장 흥미로운 대목은 신뢰에 관한 것이다.
요청마다 새 쿼리를 쓰는 채팅봇은 실행할 때마다 다른 답을 내고 감사 기록도 없지만, CARTO for Agents는 그 요청을 승인되고 재사용 가능한 Workflow로 바꿔, 다음에는 분석을 새로 만들지 않고 그대로 돌린다고 설명한다.
이것은 LLM 기반 분석의 가장 큰 약점, 곧 같은 질문에 다른 답이 나오는 비결정성을 정면으로 다룬다.

에이전트가 분석을 설계하고, 사람이 그것을 워크플로로 승인하고, 이후에는 결정론적으로 실행된다.
[[harness-engineering]]에서 반복되는 판단, 곧 LLM에게는 탐색과 설계를 맡기고 반복 실행은 결정론적 장치에 맡긴다는 원칙이 공간 분석 제품에 들어간 모습이다.
Workflows 버전 기록과 AI 에이전트 도구 추적이 같은 분기에 함께 들어간 것도 이 설계와 맞물린다.

### 무료로 쓰이던 기반 서비스에 계량을 붙였다

Basemaps의 API 키 도입은 제품 홍보와 결이 다른 변화다.
CARTO의 배경 지도 타일은 Leaflet이나 MapLibre를 쓰는 수많은 웹 지도에서 키 없이 쓰이던 공공재에 가까웠다.
이제는 키가 없으면 워터마크가 뜨고, 상업 용도는 월 100만 요청을 넘으면 돈을 내야 한다.

Basemaps 페이지는 키가 필요한 이유로, 누가 얼마나 쓰는지 알고, 한도 전에 경고하고, 대부분의 지도에서 무료로 유지하기 위해서라고 설명한다.
OpenStreetMap 기반 타일을 무료로 제공하는 일은 비용이 많이 들고, 사용자가 누구인지 모르는 무료 서비스는 지속하기 어렵다.
그래서 이 변화는 CARTO가 자기 플랫폼 고객에게는 Basemaps를 포함시키면서, 플랫폼 밖의 무료 사용자에게는 등록과 한도를 요구하는 방식으로 무료 서비스의 비용을 관리하려는 선택으로 읽힌다.

## 비평

### 홈페이지의 주장 대부분은 확인할 수 없는 형용사다

“유일한 100% 클라우드 네이티브 GIS 플랫폼”, “비교할 수 없는 시각화 능력”, “수십억 개 데이터 포인트를 쉽게” 같은 문구는 비교 대상도 측정 기준도 없다.
경쟁 제품, 곧 Esri의 클라우드 제품이나 웨어하우스 제공사가 직접 내놓는 공간 기능과 무엇이 다른지, 어떤 조건에서 얼마나 빠른지는 홈페이지에 없다.
고객 증언은 생산성과 의사결정이 나아졌다고 말하지만, 수치는 거의 없다.

마케팅 페이지가 그렇다는 것은 놀랍지 않지만, 이 문서의 독자가 CARTO를 평가하려 한다면 홈페이지는 출발점일 뿐이다.
실제로 판단하려면 Analytics Toolbox의 함수 목록, 웨어하우스별 지원 범위, 가격 견적을 따로 확인해야 한다.

### 가격을 공개하지 않는 “예측 가능한 가격”

가격 페이지의 제목은 “엔터프라이즈 공간 분석을 위한 예측 가능한 가격”이고, 부제는 “숨은 부가 요금 없는 단순한 가격”이다.
그러나 네 요금제 가운데 어느 것도 금액을 밝히지 않는다.
Pay As You Go는 “사용한 만큼만 낸다”면서도 12개월 계약을 요구하고, 단위 가격은 상담해야 알 수 있다.

이것은 기업용 소프트웨어의 흔한 관행이지만, “예측 가능한”이라는 약속과는 어긋난다.
대조적으로 Basemaps는 무료 한도와 유료 요금을 숫자로 공개하고 JSON으로까지 내놓았다.
같은 회사가 기반 서비스에서는 가격을 투명하게 밝히면서 주력 플랫폼에서는 숨기는 것은, 주력 제품의 가격이 고객마다 협상으로 정해진다는 뜻이다.

### 웨어하우스 안에서 돈다는 것은 비용도 웨어하우스로 간다는 뜻이다

데이터가 웨어하우스를 떠나지 않는다는 약속은 거버넌스에는 좋지만, 비용 구조를 바꾼다.
공간 분석의 연산은 고객의 BigQuery나 Snowflake에서 일어나고, 그 연산 비용은 고객의 웨어하우스 청구서에 찍힌다.
에이전트가 자연어 질문 하나에 여러 쿼리를 탐색적으로 돌린다면, CARTO 요금과 별개로 웨어하우스 비용이 늘어난다.

홈페이지와 에이전트 페이지는 이 점을 다루지 않는다.
CARTO for Agents가 요청을 재사용 가능한 워크플로로 바꾼다고 강조하는 것은 신뢰의 문제이면서 비용의 문제이기도 하지만, 페이지는 그것을 신뢰의 언어로만 설명한다.
에이전트가 분석을 “계획하고, 만들고, 전달한다”는 약속을 평가하려면, 그 과정에서 웨어하우스에 얼마나 많은 쿼리가 나가는지도 함께 봐야 한다.

## 인사이트

### 공간 분석이 웨어하우스로 흡수되면 GIS 업체는 인터페이스 회사가 된다

웨어하우스가 공간 데이터 타입과 함수를 기본으로 갖추면서, 공간 분석의 연산은 GIS 소프트웨어에서 데이터 플랫폼으로 옮겨 갔다.
CARTO는 이 흐름을 거스르지 않고 올라탔고, 그 결과 CARTO의 가치는 연산 엔진이 아니라 그 위의 인터페이스, 곧 지도 편집기, 분석 흐름 도구, 시각화 라이브러리, 이제는 에이전트 연결로 옮겨 갔다.

이 위치는 강점이자 위험이다.
여러 웨어하우스를 한 인터페이스로 묶어 준다는 점에서는 가치가 있지만, 웨어하우스 제공사가 자기 공간 기능과 자기 에이전트를 직접 내놓으면 중간 계층의 자리가 좁아진다.
CARTO for Agents가 Snowflake Cowork, Databricks Agents, Oracle AI Factory를 지원 플랫폼으로 든 것은, 웨어하우스 제공사의 에이전트와 경쟁하기보다 그 안으로 들어가는 쪽을 택했다는 뜻이다.

### MCP가 기업용 소프트웨어의 새 판매 채널이 되고 있다

CARTO for Agents의 구조, 곧 CLI, MCP 서버, 공개 스킬 모음은 이 저장소가 다룬 여러 제품과 닮았다.
[[stripe-kai]]가 사내 에이전트 플랫폼에 1,000개가 넘는 도구와 스킬을 연결했듯, 기업용 소프트웨어는 이제 자기 기능을 외부 에이전트가 부를 수 있는 도구로 내놓는다.
사용자가 CARTO의 화면을 열지 않고 Claude나 Copilot에서 공간 질문을 던지게 되면, CARTO의 경쟁 상대는 다른 GIS가 아니라 에이전트가 선택할 수 있는 다른 도구가 된다.

이 변화는 제품의 발견 방식을 바꾼다.
사람이 기능 목록을 보고 제품을 고르던 시대에서, 에이전트가 MCP 서버의 도구 설명을 보고 부를 도구를 고르는 시대로 옮겨 간다.
Basemaps 페이지가 요금제와 URL 템플릿을 JSON으로 공개하고 “AI 도우미가 읽을 수 있게” 한 것도, 제품 문서의 독자에 에이전트가 포함되기 시작했다는 신호다.

### 무료 지도 인프라의 시대가 끝나 가고 있다

CARTO Basemaps의 API 키 도입은 한 회사의 정책 변화를 넘어선다.
웹 지도의 배경 타일은 오랫동안 여러 회사가 무료로, 또는 거의 무료로 제공해 왔고, 수많은 개인 프로젝트와 연구와 비영리 지도가 그 위에서 만들어졌다.
그런 무료 인프라는 제공하는 회사의 다른 사업이 비용을 떠받칠 때만 유지된다.

키를 요구하고 한도를 두는 것은 무료 사용자를 없애는 것이 아니라 보이게 만드는 것이다.
비상업 월 500만 요청이라는 한도는 대부분의 개인 지도에는 넉넉하지만, 키를 발급받고 출처를 표기하고 한도를 지켜야 한다는 절차가 생긴다.
AI 에이전트가 지도를 대량으로 생성하는 시대에는 이런 기반 서비스의 요청량이 예측하기 어렵게 늘어날 수 있고, 누가 얼마나 쓰는지 아는 것이 서비스를 지키는 최소한의 조건이 된다.
무료 지도 타일을 당연하게 여기던 웹 개발자는 이제 기반 지도의 공급자와 약관을 한 번 더 확인해야 한다.
