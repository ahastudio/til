# 숫자로 보는 Prime Day 2026과 작고 싸고 제약이 많아진 AWS의 한 주

원문: [AWS 주간 소식 모음: 숫자로 보는 Prime Day 2026, Claude Haiku 5.5, Amazon Nova 2.5 Sonic 등](https://aws.amazon.com/ko/blogs/korea/aws-weekly-roundup-prime-day-2026-by-the-numbers-claude-haiku-5-5-amazon-nova-2-5-sonic-and-more-october-13-2026/)

## 요약

AWS의 Daniel Abib이 쓴 2026년 10월 13일 주간 소식 모음의 한국어판이다.
글은 두 갈래로 시작한다.
하나는 6월에 열린 Prime Day 2026의 인프라 수치이고,
다른 하나는
“규모는 더 작아지고, 비용은 더 저렴해지고, 제약은 더 많아진”
이번 주의 출시 소식이다.

Prime Day 수치에서 가장 눈에 띈 것은
이벤트 기간 Amazon ElastiCache의 최대 일일 요청량 2,300조 건이다.
4일 동안 Amazon DynamoDB는 초당 최대 1억 9,200만 건,
총 59조 건이 넘는 요청을 처리하며
한 자릿수 밀리초 응답 시간을 유지했다.
AWS Lambda는 하루 2조 3,000억 건 이상의 간접 호출을,
Amazon EBS는 최대 24조 8,000억 건의 I/O와
하루 1엑사바이트 이상의 전송을 처리했다.
Amazon ECS는 AWS Fargate에서 하루 평균 1억 5,830만
건의 태스크를 실행해 전년보다 47.7% 늘었고,
AWS Graviton은 Amazon.com이 쓴 EC2 컴퓨팅 용량의 최대 49%를 차지했다.
저자가 가장 곱씹는 수치는 처리량이 아니라,
이벤트에 앞서 AWS Fault Injection Service 실험을
4만 4,000회 넘게 수행했다는 것이다.
2025년의 6배가 넘는다.

출시 소식은 다섯 가지다.

| 출시                                 | 핵심                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| Claude Haiku 5.5 on AWS              | Bedrock과 Claude Platform on AWS에서 사용. Haiku 4.5보다 약 75% 저렴, 작업별 추론 수준 조절 |
| Amazon Nova 2.5 Sonic                | 음성 간 변환 모델. 추론·지시 이행·도구 호출 정확도 향상, 7개 언어, 256K 컨텍스트            |
| GuardDuty RDS Protection 데이터 활동 | Aurora PostgreSQL과 RDS for PostgreSQL의 실제 쿼리를 분석해 데이터 유출과 파괴를 탐지       |
| Lambda Kafka OAuth                   | 자체 관리형 Kafka 이벤트 소스를 Cognito나 Okta 같은 ID 제공업체로 인증                      |
| Redshift Iceberg 구체화된 뷰         | 조인·집계 결과를 S3의 Iceberg 테이블로 저장하고 Glue Data Catalog에 등록                    |

기타 소식으로는 OS 수준 격리와 Dogwood 정책을
결합한 오픈소스 에이전트 샌드박스 Strands Box(Apache 2.0, 개발자 프리뷰),
CI/CD 파이프라인에 침투 테스트를 넣는
AWS Continuum for Penetration Testing 퍼블릭 프리뷰,
Postman이 Bedrock에서 4,000만 명의 개발자에게
Agent Mode를 제공하는 아키텍처가 소개된다.
re:Invent는 11월 30일부터 12월 4일까지 라스베이거스에서 열린다.

## 분석

### 처리량 기록보다 장애 주입 횟수를 앞세운 이유

글은 수조 단위의 처리량을 나열한 뒤 그것이
아니라 Fault Injection Service 실험 횟수를 곱씹는다고 말한다.
수치가 독자에게 닿을 즈음에는
“아무 문제도 발생하지 않았다는 사실만이 유일한 증거”라는
문장이 이 선택을 설명한다.
대형 이벤트의 성공은 사고가 없었다는 부재로만 드러나고,
그 부재를 만든 것은 처리 용량이
아니라 몇 달 전부터 의도적으로 장애를 일으켜 본 준비다.
1년 사이 실험을 6배 넘게 늘렸다는 것은
AWS가 신뢰성을 용량이 아니라 검증의 양으로 설명하기 시작했다는 신호다.

### 같은 주제로 묶인 출시: 싸게, 그리고 경계 안에서

이번 주 출시는 저자의 표현대로
“더 작고, 더 싸고, 제약이 더 많은” 방향으로 모인다.
Haiku 5.5는 비용을 약 75% 낮추고 작업별로 추론 수준을 고르게 해,
Opus가 계획하고 여러 Haiku 하위 에이전트가 라우팅,
분류, 작은 코드 변경을 병렬로 처리하는 구성을 제안한다.
Strands Box는 에이전트가 이미 한 일에 따라 권한을 바꾸는 정책,
예컨대 “10분마다 최대 3회까지만 인시던트 채널에 게시”를
에이전트 프로세스 밖에서 강제하고,
실제 자격 증명은 송신 게이트웨이에서만 붙여 실행 환경에 노출하지 않는다.
GuardDuty의 데이터 활동 탐지는 유효한 자격 증명을 가진 공격자의 쿼리가
애플리케이션의 쿼리와 구분되지 않는다는 공백을 겨냥한다.
세 출시 모두 에이전트와 자동화가 늘어난 환경에서
“무엇을 할 수 있게 하느냐”보다 “어디까지만 하게 하느냐”를 다룬다.

### 표준 ID 체계로 들어오는 남은 구멍들

Lambda의 Kafka OAuth 지원은 작아 보이지만 이유가 분명하다.
이전에는 이벤트 소스 매핑이 SASL/PLAIN, SASL/SCRAM, mTLS만 지원해
규제 산업의 팀은 Kafka 이벤트 소스 매핑을 전혀 쓸 수 없었다.
이제 다른 곳과 같은 ID 거버넌스를 유지하면서 자동 확장과 일괄 처리를 쓸 수 있다.
Redshift가 결과를 Iceberg 테이블로 저장해 Athena,
Spark, Trino, Snowflake에서 바로 읽게 한 것도
특정 엔진에 묶이지 않는 공용 형식으로 데이터를 내놓는 같은 흐름이다.

## 비평

### Prime Day 수치는 비교 기준 없이 크기만 보여 준다

2,300조, 59조, 1엑사바이트 같은 숫자는 크다는 것 외에는 아무것도 말하지 않는다.
작년 대비 증가율이 붙은 것은 ECS 태스크(47.7%)와
Fault Injection 실험 횟수(6배)뿐이고,
나머지는 전년 값이 없어 성장인지 정체인지 알 수 없다.
ElastiCache의 2,300조가 일일 요청인지 최대치인지도 문장이 모호하다.
또 이 수치는 Amazon.com이라는 한 고객이 자사 인프라에서 낸 결과이므로
일반 고객이 같은 서비스에서 기대할 수 있는 성능의 근거가 되지 않는다.
Graviton 49%도 Amazon.com 내부 비중이지 시장 점유율이 아니다.

### 장애 주입 횟수는 품질의 지표가 아니다

실험을 6배 늘렸다는 것은 노력의 양을 보여 줄 뿐,
그 실험이 무엇을 찾아냈고 무엇을 고쳤는지는 말하지 않는다.
쉽게 통과하는 실험을 많이 돌려도 횟수는 늘어난다.
저자가 처리량 대신 이 숫자를 고른 판단은 옳지만,
발견한 결함 수나 실험 뒤 바뀐 설계 같은 결과 지표가 함께 있어야
“아무 일도 없었다”를 준비의 결과로 읽을 수 있다.
글 끝의 AWS Countdown Premium 소개가 이 숫자를
상품 홍보로 잇는 것도 신뢰를 조금 깎는다.

### 75% 저렴하다는 비교는 무엇과의 비교인가

Haiku 5.5가
Haiku 4.5보다 “대부분의 작업을 약 75% 저렴한 비용으로” 지원한다는 말은
토큰 단가인지, 같은 작업을 마치는 데 드는 총비용인지 밝히지 않는다.
작업별 추론 수준을 올리면 출력 토큰이 늘어 비용 우위가 줄어들 수 있다.
Opus와 Haiku 하위 에이전트를 함께 쓰는 구성도
하위 에이전트가 틀렸을 때 Opus가 다시 확인하는
비용까지 셈해야 실제 절감액이 나온다.
모델 자체의 평가는 이
저장소의 [Claude Haiku 5.5](../llm/claude-haiku-5-5.md) 문서에 따로 있다.

## 인사이트

### 신뢰성의 언어가 용량에서 실험으로 옮겨 간다

클라우드 사업자는 오랫동안 초당 요청 수와 처리량으로 신뢰성을 말해 왔다.
이번 글은 같은 지면에서 장애 주입 실험 횟수를 더 중요한 숫자로 내세운다.
넷플릭스의 Chaos Monkey가 “장애는 반드시 온다”는 전제로 운영 문화를 바꿨듯,
대형 이벤트를 준비하는 표준 절차가 용량 예측에서 실패 리허설로 옮겨 가고 있다.
이 흐름은 고객에게도 같은 질문을 던진다.
내 서비스의 최대 부하를 아는 것보다,
내가 마지막으로 장애를 일부러 일으켜 본 것이 언제인지가 더 중요하다.

### 에이전트 시대의 보안 제품은 행동 이력으로 권한을 정한다

Strands Box의 “이미 한 일에 따라 권한을 다르게” 주는 정책과
GuardDuty의 “행동 기준과 다른 데이터 접근 탐지”는 같은 생각에서 나온다.
누가 접근하느냐(자격 증명)만으로는 더 이상 정상과 비정상을 가를 수 없고,
무엇을 얼마나 했느냐(행동)를 봐야 한다는 것이다.
에이전트는 유효한 자격 증명을 가지고 사람보다 훨씬 많은 일을 하므로,
자격 증명 중심의 접근 제어는 에이전트가 늘수록 약해진다.
앞으로의 권한 설계는 정적인 역할보다 속도 제한, 누적 횟수,
직전 행동 같은 동적 조건을 더 많이 다루게 될 것이다.

### 싼 모델이 늘어날수록 오케스트레이션 비용이 드러난다

Opus가 계획하고 Haiku 여러 개가 실행하는 구성은 단가만 보면 싸다.
그러나 하위 에이전트가 많아질수록 작업 분할,
결과 취합, 실패 재시도라는 조율 비용이 커진다.
작은 모델의 가격 인하는 모델 호출 비용을 줄이는 대신
그 비용을 시스템 설계와 검증 쪽으로 옮긴다.
“75% 저렴”이 실제 절감으로 이어지는지는 모델이 아니라 하네스가 결정한다.
