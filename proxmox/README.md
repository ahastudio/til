## Proxmox VE

### 개념

Debian 기반 하이퍼바이저다.
KVM과 QEMU로 가상 머신(VM)을, LXC로 컨테이너를 돌린다.
Ceph로 스토리지 클러스터를 구성하고, 이 모두를 하나의 웹 관리 화면으로
묶는다.[^reg]
Proxmox는 Debian을 그대로 쓰지 않고 기능을 더하도록 바꿔서 쓴다.[^reg]
소스 코드는 GNU Affero General Public License 3판으로 공개되어 있다.[^intro]

### 구성 요소

공식 소개 문서가 꼽는 기능은 다음과 같다.[^intro]

| 영역     | 내용                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 관리 API | 전체 API가 JSON Schema로 정의되어 있어 외부 관리 도구가 붙기 쉽다                                                              |
| 권한     | 사용자나 그룹에 역할을 경로 단위로 주는 ACL 방식                                                                               |
| 인증     | Active Directory, LDAP, Linux PAM, 내장 인증 서버                                                                              |
| 스토리지 | 로컬 LVM, 디렉터리, ZFS와 NFS, CIFS, iSCSI, Ceph RBD, CephFS, Proxmox Backup Server                                            |
| 백업     | `vzdump`가 실행 중인 컨테이너와 KVM 게스트의 일관된 스냅샷 백업을 만든다                                                       |
| 고가용성 | 감시 타이머(watchdog) 기반 펜싱으로 노드 고장을 감지해 다른 노드에서 서비스를 재시작한다. Pacemaker 같은 외부 도구가 필요 없다 |
| 네트워크 | 브리지 모델, VLAN, 본딩, 존 단위 격리와 VXLAN, EVPN을 지원하는 SDN                                                             |
| 방화벽   | VM이나 컨테이너 인터페이스 단위 패킷 필터, 보안 그룹                                                                           |

공유 스토리지에 VM을 두면 모든 노드가 디스크 이미지에 직접 접근하므로 실행 중인
VM을 중단 없이 라이브 마이그레이션할 수 있다.[^intro]
소개 문서는 이런 통합을 하이퍼컨버지드 인프라(HCI)로 설명하고, 장점으로 확장성,
낮은 비용, 데이터 보호, 단순함, 벤더 종속 없음을 든다.[^intro]
Ceph와 ZFS는 웹 화면만으로 배포하고 관리할 수 있다고 한다.[^intro]

### 8.x에서 쌓인 기능

Roadmap 위키의 8.x 릴리스별 하이라이트는 다음과 같다.

| 버전 | 주요 기능                                                                                                                          |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 8.1  | Secure Boot, SDN 핵심의 지원 단계 승격, DHCP IPAM 플러그인(기술 미리보기), 새 알림 시스템                                          |
| 8.2  | 가져오기 마법사(첫 구현은 VMware ESXi용), 무인 설치 ISO 준비 도구, 백업 펜싱(fleecing), nftables 기반 방화벽(opt-in 기술 미리보기) |
| 8.3  | 태그별 Tag View, SDN과 방화벽의 IP 집합 연동, OVF와 OVA 가져오기 개선, 웹훅 알림 대상, 컨테이너 백업의 변경 감지 모드              |
| 8.4  | 중개 장치를 쓰는 VM의 라이브 마이그레이션, 백업 제공자 플러그인 API, virtiofs 호스트 디렉터리 공유                                 |

8.1의 Secure Boot는 Proxmox가 서명한 shim 부트로더를 쓰며, 기존 설치도 재설치
없이 전환할 수 있다.[^road]
8.2의 가져오기 마법사는 데이터를 백그라운드로 옮기는 동안 Proxmox VE에서
게스트를 먼저 시작할 수 있고, 백업 펜싱은 백업 대상이 느릴 때 게스트 IO 영향을
줄인다.[^road]
8.4의 라이브 마이그레이션은 NVIDIA vGPU 같은 중개 장치를 쓰는 VM이 대상이고,
백업 제공자 플러그인 API는 외부 백업 솔루션용이다.[^road]
8.3은 태그별로 게스트를 묶어 보는 Tag View와 웹훅 알림 대상, OVF와 OVA 가져오기
개선을 더했고,
SDN이 만든 IP 집합을 방화벽 규칙에서 쓸 수 있게 했다.[^road]

### 9.2 arm64 (2026-08-05)

x86-64가 아닌 CPU 아키텍처를 지원하는 첫 Proxmox VE 릴리스다.
NVIDIA Grace와 Vera 같은 엔터프라이즈 arm64 시스템을 공식 지원하고, 그 밖의 UEFI
기반 ARMv9-A 이상 하드웨어는 최선 노력 방식이다.[^road]

코드베이스, 저장소, 릴리스 주기는 x86-64와 같다.
호스트는 UEFI로 부팅하고 ACPI로 하드웨어를 설명해야 하며, Raspberry Pi 같은
디바이스 트리 전용 보드는 지원하지 않는다.[^road]
VM의 SeaBIOS, AMD SEV, Intel GVT-g는 쓸 수 없고, 라이브 마이그레이션은 같은
아키텍처의 노드 사이에서만 된다.[^road]

## Proxmox Backup Server

### 개념

VM, 컨테이너, 물리 호스트를 백업하는 클라이언트-서버 방식의 백업 솔루션이다.
Proxmox VE에 맞춰 최적화되었고, 중복 제거, 압축, 인증된 암호화를 지원한다.
구현 언어는 Rust이고, 클라이언트와 서버 사이 통신은 모두 TLS다.[^pbs]

### 구조

서버가 백업 데이터를 저장하고 데이터스토어를 만들고 관리하는 API를 제공한다.
백업 클라이언트는 이 API로 접근하며, `proxmox-backup-client` 명령줄 도구로 파일
백업을 만들고 복원한다.
QEMU와 LXC에는 Proxmox VE에 통합된 클라이언트가 있다.
하나의 백업은 여러 아카이브를 담을 수 있다. VM을 백업하면 디스크마다 별도
아카이브가 되고 VM 설정은 별도 파일이다.
덕분에 백업 전체를 훑지 않고 필요한 부분만 복원할 수 있다.[^pbs]

### 주요 기능

| 기능          | 설명                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 중복 제거     | 주기적 백업의 중복 데이터를 걸러 저장 공간을 줄인다                          |
| 증분 백업     | 바뀐 부분만 읽고 보낸다                                                      |
| 무결성        | SHA-256 체크섬                                                               |
| 원격 동기화   | 새 데이터를 담은 차이만 원격지로 전송한다                                    |
| 압축          | Zstandard                                                                    |
| 암호화        | 클라이언트 측 AES-256 GCM                                                    |
| 테이프 백업   | 장기 보관용 테이프 라이브러리 관리                                           |
| 랜섬웨어 대응 | 세밀한 접근 제어, 무결성 검증, 원격 동기화와 테이프를 이용한 오프사이트 백업 |
| 제한 없음     | 백업 저장 공간이나 클라이언트 수에 인위적 제한이 없다                        |

소스 코드는 AGPLv3이고, 구독 등급과 관계없이 엔터프라이즈 저장소를 쓸 수 있으며
Basic 이상에서는 고객 포털도 쓴다고 문서는 밝힌다.[^pbs]
Proxmox VE 쪽 통합 문서는 전체 백업과 중복 제거, 클라이언트 측 암호화, 테이프나
S3 백업, 다른 PBS와의 동기화를 이 통합의 이점으로 든다.[^intro]

### 4.0

Debian 13 기반이고 커널 6.14와 OpenZFS 2.3.3을 쓴다.
이동식 데이터스토어를 마운트하면 자동으로 동기화하도록 설정할 수 있다.
S3 스토리지 지원이 기술 미리보기로 들어왔다. S3 버킷에 백업을 두면 서버가
고장나도 백업은 영향을 받지 않아, 새 서버를 올려 원격 백업을 되찾을 수
있다.[^reg]
공식 문서 목차에는 랜섬웨어 보호, 3-2-1 규칙, 테이프 백업, 동기화 작업(push 방향
포함), 알림 대상 같은 항목이 있다.[^pbs]

## Proxmox Datacenter Manager

### 개념

떨어진 위치에 있는 Proxmox VE와 PBS를 한곳에서 보는 중앙 관리 플랫폼이다.
등록된 인스턴스를 remote라 부르고, 노드, VM, 컨테이너, 스토리지, 백업
데이터스토어를 하나의 목록으로 보여 준다.
단일 노드와 클러스터를 모두 다룬다.[^pdm]
개별 remote의 웹 화면으로 건너가는 통로(escape hatch)가 있고, 중앙 관리자가
병목이나 단일 장애점이 되지 않는 느슨한 결합 구조를 목표로 한다.[^pdm]

### 핵심 기능

PDM이 하는 일은 다음과 같다.

- 중앙 인벤토리와 통합 자원 모니터링을 바탕으로 문제를 강조하는 전역 대시보드
- 전체 인프라의 작업 로그를 한곳에 모아 보여 주는 화면
- 노드와 게스트의 시작, 정지, 재부팅, 종료
- 서버 전체의 업데이트와 보안 패치 확인
- 같은 클러스터 안 또는 다른 클러스터 사이의 게스트 라이브 마이그레이션
- LDAP, Active Directory, OpenID Connect 인증과 세밀한 권한
- ACME(Let's Encrypt) 인증서 관리

문서 목차에는 이 밖에 자동 설치(prepared answers를 쓰는 ISO 준비), Ceph 클러스터
개요, EVPN을 포함한 SDN 연동, 사용자 정의 뷰와 대시보드 위젯, 구독 키 관리가
있다.[^pdm]

### 기술 구성

백엔드는 Rust로 쓰인 JSON REST API이고, Proxmox 프로젝트의 표준인 두 데몬
구조를 따른다.
외부 요청은 권한 없는 사용자로 도는 주 API 데몬이 받고, 시스템 작업은 root로
도는 특권 데몬이 로컬 유닉스 소켓으로만 받는다.
통신은 TCP 443(HTTPS)이다.
프런트엔드는 Rust와 Yew로 쓴 단일 페이지 앱으로, WebAssembly로 컴파일된다.[^pdm]

### 출시와 보안 주의

heise 기사(2025-12-05)는 PDM 1.0과 PBS 4.1이 Proxmox VE 9.1처럼 Debian 13.2,
사용자 지정 커널 6.17.2, OpenZFS 2.3.4를 기반으로 한다고 전한다.[^search]
같은 기사는 PDM이 모든 인프라의 단일 진입점이라 침해되면 노드와 클러스터는 물론
백업까지 위험해진다고 지적한다.
권고는 불필요한 인바운드 트래픽 차단, 백업의 클라이언트 측 암호화, 안전하지 않은
망에서는 VPN 사용이다.
PDM이 VE와 PBS에 접속하는 방향이지 그 반대가 아니라는 점이 부담을 줄인다고 하며,
Proxmox는 중기적으로 추가 보안 수단을 내놓을 계획이라고 한다.[^search]
기사는 PDM의 기능으로 오프라인에서도 마지막 상태를 보여 주는 로컬 캐시, 역할
기반 사용자 지정 뷰, 여러 remote에 걸친 EVPN 존과 VNet 설정, 모든 remote로의
통합 셸 접근도 꼽는다.[^search]

### 라이선스와 지원

공식 문서의 라이선스 문단은 AGPL 3판 이상이라고 적고, heise 기사도 Proxmox VE,
PBS와 같은 AGPLv3라고 쓴다.[^pdm][^search]
세 제품 모두 무료로 내려받아 쓸 수 있고 엔터프라이즈 저장소 접근에 소액의
구독료를 받는다.[^search]
PDM 1.0의 엔터프라이즈 저장소 접근은 연 540유로(세전)이고 추가 지원은 연
1,080~4,320유로라고 heise는 전한다.[^search]

## 구독과 저장소

PBS와 PDM 공식 문서는 Basic, Standard, Premium 구독으로 엔터프라이즈 저장소와
기술 지원을 제공한다고 적는다.[^pbs][^pdm]
PBS 문서에는 구독 없이 쓰는 No-Subscription 저장소 항목이 있다.[^pbs]
Proxmox VE 9.0은 테스트 저장소 이름을 `pve-test`로 바꿨다.[^road]
PDM 1.0의 가격은 위 heise 기사에서 옮겼고, VE와 PBS의 가격은 확인하지 않았다.

## 한계

Roadmap 위키의 변경 내역은 각 릴리스의 하이라이트와 목차를 읽은 것이며,
수백 개 항목으로 된 전체 변경 내역과 알려진 문제의 세부는 읽지 않았다.
버전 표는 릴리스 헤더의 값이므로 실제 설치본의 패키지 버전은 이후 업데이트로
달라진다.
VE 8.4의 지원 종료 시점은 검색 결과 요약에서만 보았고,
heise 기사의 PDM 가격과 구독 조건은 2025년 12월 시점의 값이다.

다루지 않은 것도 있다.
PBS의 성능과 용량 수치, VE와 PBS의 구독 가격이 그렇고,
Hacker News, Lobste.rs, GeekNews의 커뮤니티 반응도 아직 모으지 않았다.
