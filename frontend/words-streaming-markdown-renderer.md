# Words 스트리밍 Markdown 렌더러

<https://diffs.com/words>

GN 토론: <https://news.hada.io/topic?id=37676>

## 소개

Words는 The Pierre Computer Co.의 Diffs 사이트에 올라온 스트리밍 Markdown 렌더러(`@pierre/words`)이다.
회사는 WebAssembly Text로 쓴 매우 빠르고 가벼운 렌더러라고 소개하며 베타 단계라고 표시한다.
Markdown을 직접 HTML로 그리고 GitHub Flavored Markdown을 지원하며
구문 강조용 `@pierre/highlights`와 함께 쓴다.
증분 업데이트, HTML 렌더 훅, 선택형 토큰 페이드 효과가 있고
기본 React 렌더러가 Streamdown보다 gzip 기준 65% 작다고 한다.
이 문서는 제품 첫 화면의 설명과 벤치마크 요약을 읽고 썼으며 문서와 소스는 열지 않았다.
아래 수치는 모두 회사가 공개한 측정이며 이 문서가 재현하지 못했다.

## 벤치마크

회사는 2026년 11월 16일, Node v24.11.0, Apple M4 Pro, 메모리 48GiB에서 잰 결과를 싣는다.
문서는 짧은 Markdown, AI 응답, 기술 명세 다섯 종류이다.

| 항목                             | Words      | 비교 대상             |
| -------------------------------- | ---------- | --------------------- |
| HTML 처리량(AI 코드 리뷰 5.4KiB) | 449.2MiB/s | md4x(NAPI) 234.9MiB/s |
| HTML 처리량, markdown-it         | 449.2MiB/s | 26.1MiB/s             |
| 스트리밍 작업(구문 강조 포함)    | 11.6ms     | Streamdown 70.2ms     |
| 스트리밍 뒤 JavaScript 메모리    | 0.5MB      | Streamdown 11MB       |
| 148개 언어 포함 gzip 내려받기    | 253.6KB    | Streamdown 1,057.8KB  |

표의 배율은 이 문서가 사이트의 숫자에서 계산한 것이다.
처리량은 markdown-it의 약 17배, md4x(NAPI)의 약 1.9배이다.
스트리밍 작업 시간은 Streamdown의 약 1/6이고 메모리는 약 1/22, 내려받기 크기는 약 1/4이다.

측정 방법도 적혀 있다.

- 브라우저 시험은 Chromium에서 같은 문서를 256 UTF-16 코드 단위씩 보내고
  각 커밋 40ms 뒤 다음 조각을 보내며, 새 브라우저로 3번 돌린 중앙값이다.
- 스트리밍 작업은 상태 갱신부터 DOM에 쓰기까지 모든 업데이트 시간의 합이며
  레이아웃과 페인트는 포함하지 않는다.
- 메모리는 강제 가비지 컬렉션 뒤 V8 힙 증가이며 네이티브 DOM, Wasm, 그래픽 메모리는 제외한다.
- 내려받기는 React를 외부로 두고 파일별 gzip한 값이다. Words는 내장 언어 152개를 모두 포함하고
  Streamdown은 언어를 필요할 때 불러온다.
  회사도 언어가 적은 페이지에서는 Streamdown이 이 합계보다 적게 받는다고 인정한다.
- 일부 측정은 커밋 f318c354에 커밋되지 않은 변경이 있는 상태에서 돌렸다고 밝힌다.

## 분석

### 무엇을 파는가

이 제품이 겨냥하는 상황은 AI 응답처럼 Markdown이 조각조각 도착하는 화면이다.
매번 전체를 다시 파싱하지 않고 증분으로 갱신하고, 도착한 텍스트를 서서히 나타내는 페이드를 제공한다.
사이트의 데모는 한 번에 몇 글자씩 오는 응답에서 강조, 링크, 코드가 형태를 갖추는 모습을 보여 준다.

### 수치가 말하는 범위

회사의 시험은 같은 다섯 문서와 같은 조각 크기에서 한 비교이다.
구문 강조를 켠 경우와 끈 경우가 나뉘어 있고 레이아웃과 페인트는 빠져 있다.
따라서 이 수치는 파싱과 DOM 쓰기의 비용이며 사용자가 체감하는 렌더링 시간은 아니다.
Streamdown의 설정이나 버전(2.7.1)이 기본값에서 달라지면 결과도 달라질 수 있다.

## 비평

### 비교의 공정성

내려받기 크기는 Words가 모든 언어를 번들하고 Streamdown이 필요할 때 불러오는 구조 차이를 회사가 직접 적었다.
같은 조건의 비교가 아니라는 점을 알면서도 큰 숫자가 앞에 나온다.
처리량에서 가장 가까운 비교 대상은 md4x(NAPI)이며 그 격차는 두 배 안쪽이다.
기본 React 렌더러가 65% 작다는 문구는 별도로 표시된 수치이며 이 문서는 해당 값을 표에서 찾지 못했다.

### 성숙도와 독립 검증

제품은 베타이며 소스와 원자료가 공개되어 있다고 하지만 이 문서는 열어 보지 못했다.
GeekNews의 글에는 댓글이 없었고 HN과 Lobste.rs에서도 독립적인 후기나 비교를 찾지 못했다.
그래서 이 문서가 인용할 외부 사용 경험은 없다.

## 인사이트

### 도입 전에 확인할 것

Markdown 스트리밍이 병목인 화면이라면 자기 응답 길이와 구문 강조 설정으로 직접 재 보는 것이 가장 확실하다.
공개된 벤치마크 소스로 같은 조건을 재현한 뒤 자기 데이터로 바꿔 돌릴 수 있다고 한다.
번들 크기를 중시한다면 필요한 언어 수를 맞춘 조건에서 비교해야 한다.

### 실패 조건

실제 화면에서 레이아웃과 페인트가 비용의 대부분이면 파서 차이는 체감되지 않는다.
베타의 API가 바뀌거나 GFM 호환성에서 문제가 나오면 교체 비용이 이득보다 클 수 있다.

### 확인할 관찰

1. 독립 재현에서도 회사의 배율이 유지되는지.
2. 정식 출시와 API 안정성.
3. 긴 응답과 표, 수식 같은 복잡한 Markdown에서의 정확성.

위 셋 모두 이 문서가 확인하지 못했다.
