# caffeinate: 긴 작업 동안 Mac을 깨워 두는 내장 명령

원문: [Caffeinate your Mac to prevent it from sleeping – Nikola Brežnjak blog](https://nikola-breznjak.com/blog/quick-tips/caffeinate-your-mac-to-prevent-it-from-sleeping/)

## 소개

Nikola Brežnjak의 짧은 팁 글이다.
긴 다운로드, `rsync` 백업, Docker 빌드, 영상 내보내기, 금방 끝날 줄 알았던 마이그레이션을 돌려 놓고 돌아왔더니 Mac이 잠들어 있던 경험에서 출발한다.
해법은 별도 앱이 아니라 macOS에 처음부터 들어 있는 `caffeinate` 명령이다.
글은 이 명령으로 Mac을 멈출 때까지, 정해진 시간 동안, 또는 특정 명령이 도는 동안에만 깨워 두는 방법을 보여 준다.

글이 소개하는 사용법은 다섯 가지다.

| 목적                         | 명령                          |
| ---------------------------- | ----------------------------- |
| 멈출 때까지 유휴 잠자기 방지 | `caffeinate`                  |
| 정해진 시간만                | `caffeinate -t 7200`          |
| 화면도 켜 두기               | `caffeinate -d`               |
| 명령이 도는 동안만           | `caffeinate -i npm run build` |
| 백그라운드로                 | `caffeinate -d -i &`          |

저자가 가장 좋은 방법으로 꼽는 것은 세 번째, 긴 명령을 `caffeinate -i`로 감싸는 방식이다.
명령이 끝나면 `caffeinate`도 저절로 끝나므로, 밤새 켜 두고 잊는 일이 없다.
글은 자주 쓴다면 `alias awake='caffeinate -d -i'`를 셸 설정에 넣으라는 제안으로 끝난다.

## 동작 방식

### caffeinate는 잠자기를 막는 것이 아니라 전원 assertion을 잡는다

`man caffeinate`는 이 명령이 시스템 잠자기 동작을 바꾸는 assertion을 만든다고 설명한다.
assertion은 전원 관리자에게 이 조건이 유지되는 동안 특정 종류의 잠자기를 하지 말라고 요청하는 표시다.
플래그가 없으면 유휴 잠자기를 막는 assertion 하나를 만든다.

| 플래그 | assertion                    | 비고                                  |
| ------ | ---------------------------- | ------------------------------------- |
| 없음   | 유휴 시스템 잠자기 방지      | `-i`와 같다                           |
| `-i`   | 유휴 시스템 잠자기 방지      |                                       |
| `-d`   | 화면 잠자기 방지             | 화면이 켜져 있으니 시스템도 깨어 있다 |
| `-m`   | 디스크 유휴 잠자기 방지      |                                       |
| `-s`   | 시스템 잠자기 방지           | AC 전원일 때만 유효                   |
| `-u`   | 사용자가 활동 중이라고 선언  | 꺼진 화면을 켠다, 기본 5초            |
| `-t N` | N초 뒤 assertion 해제        | man은 명령을 감쌀 때 무시된다고 적음  |
| `-w P` | PID P 프로세스가 끝나면 해제 | 명령을 감쌀 때는 무시된다             |

명령을 인자로 주면 `caffeinate`는 프로세스를 포크해 그 명령을 실행하고, 그 프로세스가 도는 동안 assertion을 유지한다.
명령이 없으면 `caffeinate` 자신이 끝날 때까지 유지한다.

### 누가 잠자기를 막고 있는지 확인할 수 있다

assertion은 `pmset`으로 볼 수 있다.

```bash
caffeinate -i sleep 30 &
pmset -g assertions | grep -A1 caffeinate
```

출력에는 `PreventUserIdleSystemSleep` 종류의 assertion과 `caffeinate asserting on behalf of Process ID ...`처럼 누구를 대신해 잡고 있는지가 나온다.
직접 확인해 보면 사용자가 띄운 적 없는 `caffeinate` 프로세스가 이미 몇 개 떠 있을 수 있다.
다른 도구가 긴 작업을 하는 동안 같은 방식으로 잠자기를 막는 경우다.
Mac이 도무지 잠들지 않을 때도 이 명령이 첫 진단 수단이다.

## 사용하기

### 긴 명령을 감싸기

```bash
# 명령이 끝나면 assertion도 함께 풀린다
caffeinate -i rsync -av ~/Pictures/ /Volumes/Backup/Pictures/
caffeinate -i npm run build
caffeinate -i ./run-tests.sh
```

가장 안전한 형태다.
해제 조건이 명령의 수명에 묶이므로 끄는 것을 잊을 수 없다.

### 이미 돌고 있는 프로세스에 붙이기

원문에는 없지만, 이미 시작한 긴 작업이 있다면 `-w`로 그 PID에 붙일 수 있다.

```bash
# 이미 실행 중인 빌드의 PID를 찾아 그 프로세스가 끝날 때까지만 깨워 둔다
pgrep -fl "npm run build"
caffeinate -i -w <PID>
```

작업을 다시 시작하지 않아도 되고, 작업이 끝나면 `caffeinate`도 끝난다.

### 시간 정하기

`-t`는 초 단위다.

| 시간  | 값      |
| ----- | ------- |
| 30분  | `1800`  |
| 1시간 | `3600`  |
| 2시간 | `7200`  |
| 4시간 | `14400` |

셸 산술을 쓰면 계산을 틀릴 일이 줄어든다.

```bash
caffeinate -i -t $((2 * 60 * 60))
```

### 백그라운드로 돌리고 끄기

```bash
caffeinate -d -i &
pgrep -l caffeinate   # ps aux | grep 과 달리 grep 자신이 섞이지 않는다
kill <PID>            # 또는 fg 후 Ctrl + C
```

## 트레이드오프

### 명령을 감쌀지, 따로 띄울지

명령을 감싸면 해제가 자동이지만, 이미 시작한 작업에는 쓸 수 없고 파이프라인 전체를 감싸려면 `caffeinate -i sh -c '...'` 같은 형태가 필요하다.
따로 띄우면 어떤 작업에도 쓸 수 있지만, 해제는 사람의 기억에 달린다.
그 중간이 `-w`다.
작업의 PID만 알면 감싸기의 자동 해제와 따로 띄우기의 유연함을 함께 얻는다.

### `-d`를 쓸지

원문의 alias는 `-d -i`로 화면까지 켜 둔다.
화면을 켜 두면 발표나 모니터링 대시보드에는 좋지만, 자리를 비운 동안 화면이 잠기지 않는다.
macOS의 화면 잠금은 화면 보호기나 화면 잠자기와 함께 걸리는 경우가 많으므로, `-d`는 보안 설정과 맞물린다.
빌드나 백업처럼 결과만 필요하다면 `-i`로 충분하고, 화면은 평소대로 꺼지고 잠기게 두는 편이 낫다.

### `-s`를 쓸지

`-i`는 유휴 잠자기만 막는다.
`-s`는 시스템 잠자기 자체를 막지만, man 페이지가 밝히듯 AC 전원일 때만 유효하다.
배터리로 도는 노트북에서 `-s`를 믿고 긴 작업을 걸면 기대와 다르게 동작할 수 있다.
전원 어댑터를 연결한 상태인지가 이 플래그를 고르는 기준이다.

## 함정

### 명령을 감쌀 때 `-t`는 man 페이지와 다르게 동작한다

`man caffeinate`는 명령을 인자로 주면 timeout 값을 쓰지 않는다고 적는다.
그런데 macOS 26.5에서 직접 확인해 보면 결과가 다르다.

```bash
caffeinate -t 3 sleep 8 &
sleep 1; pmset -g assertions | grep -A1 "(caffeinate)"   # 'sleep'을 대신한 assertion이 보인다
sleep 4; pmset -g assertions | grep -A1 "(caffeinate)"   # 3초가 지나자 사라졌다
```

5초 시점에 `sleep 8`은 아직 돌고 있었지만, 그 명령을 대신한 assertion은 이미 풀려 있었다.
즉 `caffeinate -t 3600 ./long-job.sh`는 작업이 3시간 걸려도 1시간 뒤에는 잠자기를 허용한다.
문서를 믿고 작업 전체를 보호한다고 생각하면 한 시간 뒤에 잠들고, 반대로 이 동작을 믿고 시간 제한 용도로 쓰면 man 페이지가 약속하지 않은 동작에 기대는 셈이다.
명령을 감쌀 때는 `-t`를 섞지 않고, 시간 제한이 필요하면 따로 띄운 `caffeinate -t`나 `-w`를 쓰는 편이 어느 쪽으로도 안전하다.

`-w`는 man 페이지대로 명령을 감쌀 때 무시되므로, 둘 다 쓰지 않는 것이 명령 감싸기의 기본형이다.

### 덮개를 닫으면 이야기가 달라진다

`caffeinate`가 막는 것은 유휴 상태에서 일어나는 잠자기와 조건부 시스템 잠자기다.
노트북 덮개를 닫는 것은 사용자의 명시적 동작이라, 외부 모니터와 전원에 연결한 클램셸 구성이 아니라면 대개 잠자기로 이어진다.
긴 작업을 걸고 노트북을 닫아 가방에 넣는 시나리오는 원문의 해법이 다루지 않는 경우다.
실제 환경에서 한 번 닫아 보고 작업이 이어지는지 확인하는 편이 안전하다.

### 백그라운드 `caffeinate`는 터미널과 수명이 얽힌다

`caffeinate -d -i &`로 띄운 작업은 셸의 작업이다.
셸 설정에 따라 터미널 창을 닫으면 끊기기도 하고, 반대로 창을 닫아도 남아 계속 잠자기를 막기도 한다.
원문이 말한 밤새 켜 두는 걱정은 명령을 감싸는 방식에서는 사라지지만, 백그라운드 방식에서는 그대로 남는다.
`pgrep -l caffeinate`로 남은 프로세스를 확인하는 습관이 필요하다.

### alias가 명령 인자를 받는 방식

원문의 `alias awake='caffeinate -d -i'`는 뒤에 명령을 붙이면 감싸기로, 붙이지 않으면 무기한 실행으로 동작한다.
같은 이름이 두 가지 전혀 다른 수명을 가지는 셈이다.
인자 없이 `awake`를 치고 창을 최소화하면, 그것이 바로 원문이 피하자고 한 무기한 실행이다.

## 체크리스트

- 긴 명령을 `caffeinate -i`로 감쌌거나, 이미 도는 작업에 `-w <PID>`로 붙였는가?
- 명령을 감싸면서 `-t`를 함께 붙여, 작업 도중에 잠자기가 허용되게 만들지는 않았는가?
- 결과만 필요한 작업에 불필요하게 `-d`를 붙여 화면 잠금을 막고 있지 않은가?
- `-s`를 쓴다면 전원 어댑터가 연결되어 있는가?
- 노트북 덮개를 닫아도 작업이 이어지는지 확인했는가?
- 작업이 끝난 뒤 `pgrep -l caffeinate`에 남은 프로세스가 없는가?

## 기억할 원칙

### 자원을 잡는 코드는 해제를 수명에 묶는다

`caffeinate`의 가장 좋은 사용법이 명령을 감싸는 형태인 이유는, 잠자기 방지라는 자원의 해제를 사람이 아니라 프로세스의 수명에 맡기기 때문이다.
이는 프로그래밍에서 파일 핸들이나 락을 `with` 블록이나 RAII로 다루는 것과 같은 원리다.
해제를 기억에 맡기는 순간 언젠가는 잊는다.

그래서 무기한 실행이나 백그라운드 실행을 쓸 때도, 해제 조건을 `-w`나 `-t`처럼 도구 안에 먼저 적어 두는 편이 낫다.
끄는 것을 잊어도 도구가 대신 꺼 주는 구조가, 주의를 기울이겠다는 다짐보다 믿을 만하다.
