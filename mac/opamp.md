# OP!Amp: 드라이버 없이 Mac 전체 소리를 다듬는 무료 시스템 이퀄라이저

> OP!Amp — System-wide equalizer for macOS

<https://opamp.giveit2.me/>

Show GN: [OP!Amp - macOS 시스템 오디오 이퀄라이저](https://news.hada.io/topic?id=34696)

## 소개

2026년 10월 3일 mse9000이 GeekNews에 Show GN으로 올린 개인 프로젝트다.
작성자는 Show가 처음이라 어색하다며,
혼자 개발하고 있는 macOS용 이퀄라이저 OP!Amp를 소개했다.
음악 앱, 브라우저 등 Mac에서 나오는 모든 소리를 한곳에서 조절할 수 있고,
기능 제한 없이 무료로 쓸 수 있다.
개발하면서 Mac으로 음악을 들을 때마다 2% 부족하다고 느꼈는데, EQ 앱은 많지만
대부분 유료여서 직접 만들게 되었다고 한다.

배포 사이트는 `opamp.giveit2.me`이고 한국어와 영어로 볼 수 있다.
사이트는 GitHub 저장소 `aftergain/OP.Amp`에서 GitHub Pages로 게시된다.
이 저장소의 README는 저장소에 앱 소스 코드가 아니라 랜딩 페이지 결과물과
내려받을 릴리스만 들어 있다고 밝힌다.
게시글의 표현대로 소스 코드를 공개하지 않는 프리웨어이며,
저장소는 앱에 오픈소스 라이선스를 부여하지 않는다.
저장소는 2026년 9월 26일 만들어졌고, 이 문서를 쓰는 시점의 최신 릴리스는
10월 3일 올라온 0.2.28이다.

지원 환경은 macOS 14.2 이상의 Apple Silicon Mac이다.
나는 이 앱을 설치하거나 실행하지 않았다.
아래 내용은 게시글, 배포 사이트의 사용법 문구, 저장소 README와 릴리스 노트,
Homebrew Cask 파일에서 확인한 것이다.

## 주요 기능

게시글이 꼽은 기능은 다음과 같다.

- 그래픽 EQ와 파라메트릭 EQ
- 헤드룸, 컴프레서, 리미터
- 프리셋 저장과 출력 기기별 프리셋 자동 적용
- 실시간 스펙트럼 분석과 L/R 레벨 미터
- 6가지 컬러 테마

배포 사이트의 사용법 안내가 각 기능을 더 자세히 설명한다.

### 이퀄라이저

그래픽 EQ는 왼쪽이 저음, 오른쪽이 고음인 슬라이더 배열이고,
5·10·31·32밴드 등 9가지 구성 중에서 고른다.
사이트는 처음에는 1~2 dB씩만 바꿔 들어 보라고, 그리고 부족한 대역을 올리기보다
과한 대역을 살짝 낮추는 쪽이 더 자연스러울 때가 많다고 권한다.

파라메트릭 EQ는 고정된 밴드 사이의 주파수도 직접 골라 조절한다.
그래프의 점을 끌어 주파수와 이득을 바꾸고, Q 값을 높이면 좁은 대역만,
낮추면 주변 대역까지 넓게 바뀐다.
특정 대역은 Peaking 필터로, 저음이나 고음 전체는 Shelf 필터로 다룬다.
0.2.28 릴리스는 주파수, 이득, Q를 정확한 값으로 입력할 때 Done과 Return 모두
값이 적용되도록 고쳤다.

### 헤드룸, 컴프레서, 리미터

EQ로 음량을 키우면 디지털 한계를 넘어 소리가 깨질 수 있다.
헤드룸은 전체 음량을 미리 낮춰 그만큼 여유를 둔다.
Auto는 현재 설정에 맞춰 감쇄량을 계산하고 Safety Margin으로 여유를 더 늘릴 수
있으며, Manual은 감쇄량을 직접 지정하고, Off는 적용하지 않는다.
사이트는 Auto라고 해서 모든 순간의 피크까지 보장하지는 않으며,
실제로 치솟는 피크는 리미터가 막는다고 설명한다.
0.2.27 릴리스는 Auto에서 Manual로 바꿀 때 0 dB로 초기화하지 않고
현재 엔진이 적용 중인 감쇄량에서 시작하게 했고,
헤드룸을 끌 때는 소리가 커지거나 깨질 수 있다며 확인을 받게 했다.

컴프레서는 기준을 넘는 소리를 눌러 큰 소리와 작은 소리의 편차를 줄인다.
사이트의 예시로는 2:1이면 기준을 넘은 입력이 2 dB 커질 때
출력은 약 1 dB만 커진다.
Attack과 Release로 압축을 시작하고 푸는 속도를,
Gain으로 압축 뒤의 음량을 정한다.

리미터는 평소 음색은 건드리지 않고 출력 끝에서 유독 큰 순간 피크만 잡는다.
Ceiling은 출력 피크의 목표 상한이며 −1 dBTP보다 −2 dBTP가 더 낮은 상한이고,
Release는 처음에는 Auto로 두라고 안내한다.

### 프리셋과 기기별 자동 적용

팩토리 프리셋에는 아무 대역도 건드리지 않은 Flat, 저음을 강조하는 Bass,
음성 대역을 또렷하게 하는 Vocal, 그리고 Jazz, Rock 같은 장르별 설정이 있다.
내 프리셋은 EQ, 톤, 프리앰프와 함께 헤드룸, 컴프레서,
리미터 설정까지 한꺼번에 저장하고, 팩토리 원본은 덮어쓰지 않는다.
테마와 아날라이저 설정은 프리셋과 따로 전역 설정으로 유지된다.

기기별 프리셋은 이 앱이 가장 내세우는 기능이다.
프리셋을 고른 뒤 Set for [기기 이름]을 누르면 그 프리셋이 현재 출력 기기의
기본값이 되고, 그 기기에 다시 연결될 때 자동으로 적용된다.
헤드폰과 스피커에 서로 다른 프리셋을 지정해 두면 출력 기기를 바꿀 때마다
다시 고를 필요가 없다.
사이트는 기기 지정과 저장이 별개라서,
저장하지 않은 변경(Modified 표시)이 있다면 먼저 저장하라고 주의를 준다.

컬러 테마는 Carbon Cyan, Ivory Crimson, Graphite Violet, Slate Cobalt,
Carbon Emerald, Onyx Scarlet의 여섯 가지다.

## 동작 방식

### 두 가지 출력 경로

OP!Amp는 소리를 가로채는 경로를 두 가지로 제공한다.
어느 쪽이든 같은 EQ, 컴프레서, 리미터가 적용된다.

| 경로           | 설치                                        | 처리 지연 보고                     |
| -------------- | ------------------------------------------- | ---------------------------------- |
| Driverless     | 드라이버 없음, 시스템 오디오 캡처 권한 필요 | 재생 앱에 전달하지 못함            |
| Virtual Output | 앱 안에서 별도 설치, 관리자 인증 필요       | macOS에 전달, 지원 플레이어가 보정 |

기본값인 Driverless 모드는 별도의 오디오 드라이버 없이 macOS의 시스템 오디오
캡처 권한만으로 동작한다.
대신 OP!Amp가 소리를 처리하면서 생기는 지연을 재생 앱에 알려 줄 방법이 없다.

Virtual Output은 영상과 소리의 싱크가 중요한 사람을 위한 선택지다.
처리 지연을 macOS에 보고하므로, 이 정보를 반영하는 플레이어는
영상 타이밍을 맞출 수 있다.
같은 출력 연결 중에는 컴프레서나 리미터를 켜고 꺼도
전체 지연이 일정하게 유지된다.
설치는 앱 안에서 Devices → Routing → Install Virtual Output…으로 하며,
관리자 인증이 필요하고 macOS 오디오 서비스가 재시작될 수 있다.
사이트는 이것이 더 빠른 출력 모드가 아니며 영상 싱크 보정 여부는 플레이어마다
다르다고 분명히 적어 두었다.

드라이버 없이 시스템 전체 소리를 가로챌 수 있는 이유를 문서는 설명하지 않는다.
macOS 14.2부터 Core Audio에 다른 프로세스의 오디오를 캡처하는 탭 API가 생겼고,
최소 지원 버전이 정확히 14.2라는 점에서 Driverless 모드가
이 API를 쓴다고 추정한다.
이것은 내 추정이며 작성자가 밝힌 내용은 아니다.

### 설치하기

DMG를 내려받아 OP!Amp.app을 응용 프로그램 폴더로 옮기거나, Homebrew로 설치한다.

```bash
# 설치
brew install --cask aftergain/tap/opamp

# 이미 Homebrew로 설치한 경우 업데이트
brew update
brew upgrade --cask aftergain/tap/opamp
```

이 빌드는 Apple Developer ID 서명이나 공증 없이 애드혹(ad-hoc) 서명만 되어 있다.
직접 내려받아 설치하면 처음 실행할 때 시스템 설정 → 개인정보 보호 및 보안 →
그래도 열기를 눌러야 할 수 있다.
Homebrew Cask는 설치 뒤에 `xattr -dr com.apple.quarantine`으로
OP!Amp.app에서만 격리 속성을 지우며,
Gatekeeper 전체 설정이나 SIP는 바꾸지 않는다고 탭 README가 밝힌다.
탭 README에 따르면 Cask는 DMG를 릴리스 버전과 SHA-256 체크섬에 고정하고,
별도 네트워크 위치에서 설치 스크립트를 받아 실행하지 않는다.

Virtual Output 드라이버는 Cask가 설치하지 않는다.
앱을 업데이트한 뒤에는 기존 Virtual Output 사용자가
앱 안에서 다시 설치 메뉴를 실행해 구성 요소를 갱신해야 하고,
Cask를 지워도 드라이버는 앱이 제공하는 제거 도구로 따로 지워야 한다.
업데이트 뒤에는 macOS가 오디오 캡처 권한을 다시 물을 수 있다.
README와 Cask 모두 새 EQ나 다이내믹스 설정을 시험할 때는 낮은 음량에서
시작하라고 반복해서 권한다.

## 분석

### 기기별 프리셋이 시스템 EQ의 실제 사용 패턴을 겨냥한다

시스템 전체 EQ를 쓰는 이유는 대개 음원보다 재생 장치에 있다.
같은 곡도 노트북 스피커, 헤드폰, 외부 스피커에서 전혀 다르게 들리고,
사람이 고치고 싶은 것은 곡마다의 취향보다 장치마다의 버릇이다.
OP!Amp가 출력 기기가 바뀔 때 프리셋을 자동으로 불러오는 기능을 앞세운 것은
이 사용 패턴을 정확히 짚은 선택이다.

이 관점에서 보면 프리셋이 무엇을 담는지도 일관된다.
내 프리셋은 EQ뿐 아니라 헤드룸, 컴프레서, 리미터까지 저장하고,
테마와 아날라이저는 전역으로 뺐다.
곧 프리셋은 소리의 모양 전체를 뜻하고, 화면 설정은 사람에게 붙는다.
기기에 붙는 것과 사람에게 붙는 것을 나눈 설계라고 읽힌다.

### 지연 문제를 숨기지 않고 선택지로 드러냈다

시스템 오디오를 가로채 가공하면 반드시 지연이 생긴다.
음악만 들을 때는 문제가 되지 않지만, 영상을 볼 때는 입 모양과 소리가 어긋난다.
OP!Amp는 이 문제를 기본 모드에서 해결하지 않는 대신,
해결하려면 무엇을 감수해야 하는지를 분명히 적었다.
드라이버 설치, 관리자 인증, 오디오 서비스 재시작, 그리고 플레이어의 협조다.

특히 Virtual Output이 더 빠른 모드가 아니라고 적은 대목이 눈에 띈다.
사용자는 가상 드라이버라는 말에서 지연이 줄어든다고 기대하기 쉽지만,
실제로 바뀌는 것은 지연의 크기가 아니라 지연을 운영체제에 알리느냐 여부다.
컴프레서와 리미터를 켜고 꺼도 전체 지연을 일정하게 유지한다는
설명도 같은 맥락이다.
지연이 변하면 플레이어가 보정할 수 없기 때문에,
가장 긴 경우에 맞춰 고정해 두는 방식으로 보인다.

### 오픈소스가 아닌 무료 앱이 신뢰를 얻는 방식

소스를 공개하지 않고, 공증도 받지 않았으며,
시스템 오디오 캡처 권한을 요구하는 앱은 사용자에게 큰 신뢰를 요구한다.
OP!Amp는 이 부담을 배포 과정의 투명성으로 메우려 한다.
릴리스마다 SHA-256을 적고, Cask가 하는 일을 격리 속성 해제 한 가지로 한정해
문서화하고, 원격 설치 스크립트를 쓰지 않는다고 밝혔다.
README는 설치 전에 릴리스와 Cask를 직접 검토하라고까지 권한다.

이것은 오픈소스의 대안이라기보다 최소한의 감사 가능성이다.
사용자는 앱 내부를 볼 수 없지만,
무엇이 설치되고 무엇이 바뀌는지는 확인할 수 있다.
개인 개발자가 연 99달러의 Apple Developer Program 비용을 들이지 않고 낼 수 있는
신뢰 신호로는 꽤 성실한 편이다.
다만 그 비용이 공증을 받지 않은 이유인지는 작성자가 밝히지 않았다.

## 비평

### 공증 없는 배포와 격리 해제는 사용자에게 보안 판단을 떠넘긴다

Cask가 격리 속성을 OP!Amp.app에서만 지운다는 설명은 사실이고,
범위를 좁힌 점도 성실하다.
그러나 격리 속성은 Gatekeeper가 처음 실행 전에 앱을 검사하게 만드는 장치이고,
이를 지우는 것은 곧 그 검사를 건너뛴다는 뜻이다.
범위가 한 앱으로 좁더라도 그 앱이 시스템 오디오 전체를 캡처할 권한을 받는다면,
건너뛴 검사의 무게는 가볍지 않다.

수동 설치 쪽도 마찬가지다.
그래도 열기를 누르라는 안내는 macOS가 사용자를 보호하려고 세운 단계를
사용자가 직접 넘게 만든다.
이 습관이 굳으면 다른 출처의 앱에도 같은 버튼을 누르게 된다는 것이
공증 없는 배포가 생태계 전체에 남기는 비용이다.
1.0 이전 빌드라는 단서가 붙어 있지만,
공증을 받을 계획이 있는지는 문서 어디에도 없다.

### 무료라는 차별점은 지속 가능성의 질문을 남긴다

작성자는 EQ 앱이 대부분 유료여서 직접 만들었다고 했다.
그런데 시스템 오디오를 다루는 앱은 macOS가 업데이트될 때마다
깨지기 쉬운 영역이다.
릴리스 노트도 업데이트 뒤 오디오 캡처 권한을 다시 줘야 할 수 있고,
Virtual Output 사용자는 구성 요소를 따로 갱신해야 한다고 적었다.
유료 앱의 가격에는 이런 유지보수 비용이 들어 있다.

OP!Amp의 수입원은 Buy Me a Coffee 후원 링크 하나다.
소스가 닫혀 있으므로 작성자가 손을 놓으면 다른 사람이 이어받을 수도 없다.
오픈소스 무료 앱은 버려져도 포크될 수 있고 유료 앱은 수입으로 유지되지만,
닫힌 무료 앱은 두 안전망이 모두 없다.
이 위험은 사용자가 기기별 프리셋을 공들여 쌓을수록 커진다.

### 게시글은 대상 사용자를 넓게 말하지만 문서는 이미 오디오를 아는 사람을 전제한다

게시글은 Mac에서 나오는 모든 소리를 조절하고 싶은 사람에게 말을 건다.
그러나 기능 목록은 헤드룸, dBTP 단위의 리미터 Ceiling,
컴프레서의 Ratio와 Attack, Release, 파라메트릭 EQ의 Q 값으로 이어진다.
사이트가 각 항목에 친절한 설명을 붙였지만, 저음이 부족하다고 느끼는
일반 사용자가 이 화면에서 무엇을 먼저 만져야 할지는 여전히 분명하지 않다.

팩토리 프리셋이 그 간극을 메우는 장치인데, 이름이 Bass, Vocal, Jazz,
Rock처럼 장르와 취향 중심이다.
앞서 분석한 대로 이 앱의 핵심이 장치마다의 버릇을 고치는 데 있다면,
정작 필요한 출발점은 장르 프리셋이 아니라 장치 보정이다.
특정 헤드폰 모델의 측정값에 맞춘 보정 곡선을 불러오는 기능은
문서에서 확인되지 않는다.

### 성능과 안정성을 판단할 수치가 없다

문서와 릴리스 노트는 모두 작성자 쪽 설명이다.
처리 지연이 실제로 몇 밀리초인지, CPU 사용량이 어느 정도인지,
블루투스 기기를 오갈 때 프리셋 전환이 얼마나 안정적인지는 어디에도 수치가 없다.
작성자 스스로 출력 기기를 연결하거나 전환하다 문제가 생기면
macOS 버전과 기기 모델을 함께 알려 달라고 한 것을 보면,
기기 전환이 아직 가장 불안한 부분으로 보인다.
이 앱의 대표 기능이 바로 그 기기 전환이라는 점이 아이러니다.

## 인사이트

### 운영체제가 오디오 탭을 열자 시스템 EQ가 개인 프로젝트의 크기로 내려왔다

예전 macOS에서 시스템 전체 소리를 가로채려면 가상 오디오 드라이버를 설치해
그것을 기본 출력으로 지정하는 수밖에 없었다.
BlackHole 같은 루프백 드라이버나 이런 드라이버를 품은 EQ 앱들이 그 방식을 썼고,
드라이버는 운영체제 업데이트마다 깨지기 쉬운 부분이었다.
드라이버를 만들고 유지하는 일은 혼자 하는 무료 프로젝트가 감당하기에는 무거웠다.

OP!Amp의 기본 모드가 드라이버 없이 동작한다는 것,
그리고 최소 버전이 14.2라는 것은 이 지형이 바뀌었음을 보여 준다고 나는 해석한다.
운영체제가 공식 캡처 경로를 제공하면 가장 어려운 부분이 플랫폼으로 넘어가고,
개발자는 DSP와 사용자 경험에 집중할 수 있다.
이 앱이 1.0 이전 단계에서 그래픽 EQ, 파라메트릭 EQ, 다이내믹스,
기기별 프리셋을 한꺼번에 갖출 수 있었던 배경도 거기에 있을 것이다.

같은 구조는 다른 곳에서도 반복되어 왔다고 나는 본다.
화면 캡처가 운영체제 API로 열리면 녹화 도구가 늘고,
브라우저가 미디어 API를 갖추면 웹 기반 편집기가 는다.
플랫폼이 낮은 층을 공식화할 때마다 그 위의 유료 유틸리티 시장은
무료 대안의 압박을 받는다.

### 드라이버 방식은 사라지지 않고 정확도가 필요한 쪽으로 물러난다

그런데 OP!Amp는 드라이버를 완전히 버리지 못했다.
지연을 운영체제에 보고하려면 여전히 가상 출력 장치가 필요하기 때문이다.
캡처 API는 소리를 가져오는 길만 열었고,
가공된 소리가 얼마나 늦게 나가는지를 시스템에 알리는 길은 장치의 몫으로 남았다.

이 분리는 앞으로 오디오 유틸리티의 기본 구도가 될 가능성이 높다.
대부분의 사용자는 드라이버 없는 간편한 경로를 쓰고, 영상 편집자나 화상 회의를
오래 하는 사람처럼 싱크가 중요한 사용자만 드라이버를 설치한다.
설치 비용과 정확도 사이의 선택을 사용자에게 명시적으로 넘기는 OP!Amp의
두 경로 구조는 그 구도를 미리 보여 준다.

### 닫힌 무료 앱의 신뢰는 코드가 아니라 배포 파이프라인에서 만들어진다

오픈소스는 코드를 보여 줌으로써 신뢰를 얻고,
상용 앱은 회사와 공증으로 신뢰를 얻는다.
OP!Amp는 둘 다 아닌 위치에서 배포 파이프라인을 공개하는 쪽을 택했다.
버전과 체크섬에 고정된 Cask, 범위를 문서화한 격리 해제,
원격 스크립트 없는 설치가 그 재료다.

이 방식은 Homebrew 탭이 개인 개발자의 사실상 배포 채널이 된 흐름과 맞닿아 있다.
App Store와 공증을 거치지 않는 앱이 늘수록,
사용자가 확인할 수 있는 것은 Cask 파일 몇 줄이 된다.
그 몇 줄을 읽는 습관이 사용자 쪽에 자리 잡느냐가,
이런 앱들이 신뢰를 얻는 실제 경로가 될 것이다.

반대로 그 습관이 자리 잡지 않으면,
성실하게 문서화한 탭과 악의적인 탭이 사용자에게는 똑같아 보인다.
OP!Amp가 보여 준 투명성은 좋은 선례지만,
그것이 작동하려면 읽는 사람이 있어야 한다.
