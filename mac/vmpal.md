# VMPal: AI 에이전트에게 Mac 안의 별도 컴퓨터를 내주는 가상 머신 앱

<https://vmpal.com/>

HN 토론: <https://news.ycombinator.com/item?id=49977434> (4점, 0개 댓글)

## 소개

VMPal은 Apple silicon Mac에서 macOS, Windows, Linux 가상 머신을 돌리는 앱이다.
홈페이지 제목은 Apple silicon과 AI 에이전트를 위해 만든 가상 머신이고,
가볍고 아름답고 버터처럼 부드럽다는 문구가 이어진다.
만든 곳은 데이터베이스 클라이언트 TablePlus를 만든 TablePlus Inc.이며,
주소는 캐나다 토론토다.
macOS 26 이상의 Apple silicon Mac이 필요하다.

변경 이력을 보면 2026년 10월 6일 하루에 0.36, 0.37, 0.38 빌드가 연달아 나왔다.
0.37은 Windows 소리 문제를 고치고 새 VM 설치를 취소하는 버튼과 VM 저장 위치
옵션을 더했고, 0.38은 충돌과 VM 메뉴 막대가 사라지는 문제를 고쳤다.
버그 제보는 GitHub의 `TablePlus/VMPal-issue-tracker` 저장소로 받는데,
이 저장소는 10월 2일에 만들어졌다.
같은 날 블로그에 첫 글 Give your AI agent a whole computer가 올라왔다.
버전 번호와 날짜로 보면 막 공개를 시작한 단계의 제품이다.

## 주요 기능

### 세 가지 운영체제

| 운영체제       | 실행 엔진                      | 홈페이지가 밝힌 특징                                        |
| -------------- | ------------------------------ | ----------------------------------------------------------- |
| macOS          | Apple Virtualization framework | Apple에서 바로 받아 몇 분 만에 설치, Mac GPU의 Metal 사용   |
| Windows 11     | VMPal 자체 엔진                | 최대 5K Retina, TPM 2.0, USB 장치, Direct3D 11과 OpenGL 4.1 |
| Ubuntu, Fedora | Apple Virtualization framework | OpenGL 4.1, Intel 프로그램용 Rosetta, 중첩 가상화           |

macOS에는 클립보드와 드래그 앤 드롭을 더하는 VMPal Tools가 들어가고,
macOS 27에서는 이 설정이 클릭 없이 끝난다고 한다.
설치할 운영체제는 최신판이나 이전 판을 고르거나 가지고 있는 IPSW,
ISO 파일을 쓸 수 있다.
VMPal이 이미지를 내려받아 VM 창 안에서 설치하고 사용자 계정과 VMPal Tools까지
넣으며, 준비가 끝날 때까지 덮개를 씌워 엉뚱한 클릭을 막는다.

### 디스크와 스냅숏

VM 디스크는 실제로 담긴 만큼만 공간을 차지하고,
파일 하나로 다른 Mac에 옮길 수 있다.
복제본과 스냅숏은 바뀐 만큼만 공간을 쓴다.
스냅숏은 VM이 실행 중이든 아니든 찍을 수 있고 몇 초 만에 되돌린다.
Parallels에서 쓰던 VM을 몇 번의 클릭으로 가져올 수도 있다.

### 공유와 연결

클립보드는 파일까지 양방향으로 오가고, 모든 VM에 드래그 앤 드롭으로 넣고 뺄 수
있다.
Mac 폴더를 Finder, 탐색기, Files에서 열 수 있게 공유하고,
VM 안의 웹 서버나 SSH에는 Mac의 포트를 거쳐 접속하는 포트 포워딩을 지원한다.
이름, 디스크, 공유 폴더, 네트워크는 VM이 실행 중일 때도 바꿀 수 있다.
소리와 마이크는 VM마다 허용한 것만 쓰며, 마이크가 쓰이면 초록 표시등이 켜진다.
VM은 각자 독립된 앱으로 Dock 아이콘을 가지므로, 하나가 충돌해도 그 VM만 멈춘다.

## 에이전트에게 주는 컴퓨터

### 문제: 에이전트는 권한 대화상자에서 멈춘다

VMPal이 다른 가상화 앱과 다르게 내세우는 부분은 AI 에이전트다.
블로그 글은 에이전트가 터미널에서 코드를 쓰고 테스트를 돌리는 것은 잘하지만,
실제 컴퓨터를 쓰려 하면 권한 벽에 막힌다고 설명한다.
클릭하고 입력하려면 손쉬운 사용 권한이, 화면을 보려면 화면 기록 권한이,
관리 작업에는 `sudo` 비밀번호나 Windows 사용자 계정 컨트롤 승인이 필요하고,
사람만 누를 수 있는 대화상자도 있다.
글은 Mac이 프로그램에 전체 제어권을 넘기지 않는 것은 옳다고 인정하면서,
그 때문에 사람이 기계 앞에서 권한을 승인하고 비밀번호를 치며 에이전트를 지켜봐야
한다고 말한다.

### 해법: VM의 키보드와 마우스를 쥐여 준다

VMPal에서 에이전트 제어를 켜면 에이전트는 VM의 화면을 직접 보고,
VM의 키보드와 마우스로 클릭하고 입력하며,
사용자나 관리자 권한으로 명령을 실행한다.
운영체제 입장에서는 앱이 권한을 요청하는 것이 아니라 사람이 앉아 있는 것처럼
보이므로 손쉬운 사용이나 화면 기록 권한이 필요 없고,
`sudo` 비밀번호나 UAC 승인도 없다.
연결은 VMPal을 거치므로 SSH, VNC, 원격 데스크톱을 따로 설정하지 않는다.

설정은 VM의 Settings › AI Agents에서 Allow agent control of this VM을 켜고,
에이전트를 어디서 돌릴지 고르는 것이다.

| 위치                | 설명                                                     |
| ------------------- | -------------------------------------------------------- |
| Agent on This Mac   | 에이전트는 Mac에 있고 실행 중인 VM 여러 대를 조작한다    |
| Agent Inside the VM | 에이전트를 VM 안에 설치하고 그 안의 파일과 도구로 일한다 |

그다음 Claude Code, Codex, Grok CLI, Gemini CLI 중 하나의 추가 버튼을 누르면
내장 MCP 서버가 등록된다.
macOS VM에서는 첫 에이전트를 연결할 때 VM의 관리자 비밀번호를 한 번 묻는다.
홈페이지는 에이전트가 설치 프로그램을 돌리고, 대화상자에 답하고,
직접 로그인까지 할 수 있다고 적는다.

### 안전장치

블로그 글은 전체 제어권을 주어도 안전한 이유를 그것이 사용자의 Mac이 아니기
때문이라고 설명한다.
에이전트는 자기 VM만 다루고 Mac의 화면, 마우스, 키보드에는 닿지 않으며,
폴더를 공유하지 않는 한 Mac의 파일도 보지 못한다.
에이전트 제어는 VM마다 직접 켜야 하고, 끄면 즉시 멈춘다.
큰 작업 전에 스냅숏을 찍어 두면 잘못되었을 때 기계 전체를 되돌릴 수 있고,
에이전트가 닿는 네트워크와 폴더는 사용자가 VM에 준 범위로 제한된다.

| ---------- | ------------ | ------------- | ---------------------------- |
| Individual | $69/라이선스 | $34.50        | Mac 1대, 1년 업데이트와 지원 |
| Team       | $99/좌석     | $49.50        | 3좌석부터, 좌석당 Mac 1대    |

제한할 예정이라고 밝힌다.
TablePlus의 교육 플랜 안내로도 연결된다.

## 트레이드오프

### 권한을 우회하는 것이 아니라 권한의 경계를 옮긴다

VMPal의 설계는 운영체제의 권한 모델을 깨는 것이 아니라,
에이전트를 사람 자리에 앉혀 권한 모델이 적용되지 않게 하는 것이다.
VM 안에서 에이전트는 키보드와 마우스를 가진 관리자이므로,
그 안에서는 사실상 모든 일을 할 수 있다.
보호선은 운영체제 안의 권한 대화상자에서 VM과 호스트 사이의 가상화 경계로 옮겨
간다.
이 선택은 에이전트가 사람의 개입 없이 끝까지 일하게 해 주지만,
VM 안에서 일어나는 일에는 더 이상 중간 확인이 없다는 뜻이기도 하다.

그래서 VM 안에 무엇을 넣느냐가 보안의 핵심이 된다.
VM 안에서 개인 계정으로 로그인하거나, API 키를 넣거나,
회사 네트워크에 연결하면 에이전트는 그 모든 것을 사람과 같은 권한으로 쓴다.
공유 폴더와 네트워크 범위를 사용자가 정한다는 설명은 맞지만,
실제로 얼마나 좁게 정할지는 사용자 몫이다.

### 화면을 보고 클릭하는 방식은 느리고 비싸다

에이전트가 VM의 화면을 보고 마우스로 조작하는 방식은 사람이 쓰는 모든 GUI 앱을
다룰 수 있다는 장점이 있다.
그러나 같은 작업을 명령줄이나 API로 할 수 있다면,
화면을 읽고 클릭하는 쪽이 훨씬 느리고 토큰도 많이 든다.
VMPal의 MCP가 명령 실행도 함께 지원하는 것은 이 때문으로 읽힌다.
GUI 조작은 설치 프로그램, 로그인 화면, 대화상자처럼 다른 방법이 없는 곳에만 쓰는
편이 효율적이다.

### 초기 제품의 안정성

같은 날 세 번의 빌드, 충돌과 메뉴 막대 문제를 고친 변경 이력,
생긴 지 며칠 된 이슈 저장소는 이 제품이 아직 초기 단계라는 것을 보여 준다.
에이전트에게 긴 무인 작업을 맡기려면 VM 자체가 안정적이어야 하는데,
그 신뢰는 아직 쌓이는 중이다.
Windows는 Apple의 프레임워크가 아니라 VMPal 자체 엔진으로 돌린다는 점도,
성숙한 가상화 제품과 비교해 검증이 더 필요한 부분이다.

## 함정

- 무료 체험판은 지금은 제한이 없지만 앞으로 일부 기능이 제한될 예정이다. 체험판으로 자동화 흐름을 짜 두었다면 이후 바뀔 수 있다.
- 라이선스는 Mac 1대당 1좌석이다. 여러 Mac에서 에이전트 VM을 돌리려면 좌석을 늘려야 한다.
- macOS 26 이상, Apple silicon이 필수다. Intel Mac이나 이전 macOS에서는 쓸 수 없다.
- 에이전트 제어를 켠 VM 안에서 개인 계정에 로그인해 두면, 에이전트가 그 계정을 사람과 똑같이 쓸 수 있다.
- 스냅숏으로 VM은 되돌릴 수 있지만, 에이전트가 VM 밖으로 보낸 요청이나 공유 폴더에 쓴 파일은 되돌릴 수 없다.

## 기억할 원칙

### 에이전트의 권한은 사람의 권한과 다른 층에서 줘야 한다

운영체제의 권한 대화상자는 앞에 사람이 앉아 있다는 가정으로 설계되었다.
에이전트를 그 체계 안에 넣으면 사람이 계속 승인 버튼을 눌러야 하고,
그 체계를 끄면 사람의 컴퓨터 전체가 위험해진다.
VMPal은 그 사이에서 에이전트에게 사람의 자리를 통째로 주되,
그 자리를 별도의 기계로 떼어 내는 방법을 택했다.
에이전트에게 얼마나 많은 권한을 줄지보다,
그 권한이 미치는 경계를 어디에 그을지를 먼저 정하는 것이 이 접근의 핵심이다.
