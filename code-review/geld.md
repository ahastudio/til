# Geld: GitHub 코드 리뷰에서 테스트와 생성 파일을 접어 주는 브라우저 확장

<https://www.geld.sh/>

## 소개

Geld는 개발자 Brandon McConnell이 만든 브라우저 확장이고,
GitHub의 코드 리뷰 화면을 바꾼다.
홈페이지는 “Code review is broken. Geld fixes it.”이라는 문구로 소개하면서,
이슈 답글과 해결 처리와 반응과 병합은 계속 GitHub를 통해 이뤄진다고 설명한다.
Chrome, Edge, Firefox는 스토어 링크로,
Safari는 GitHub에서 직접 내려받아 설치하라고 안내하며, 현재 버전은 0.1.2다.
라이선스는 AGPL-3.0이고, 홈페이지 맨 아래에는 GitHub와 제휴 관계가 없다고 적혀
있다.

저장소 README는 이 도구의 출발점이 더 좁았음을 보여 준다.
README의 첫 문장은 GitHub diff에서 테스트 파일을 숨기는 확장이라는
설명이다.[^readme]
저장소 설명도 GitHub PR을 리뷰할 때 테스트를 숨기는 브라우저 확장이라고
적는다.[^readme]
홈페이지는 같은 도구를 리뷰 전체를 다루는 것으로 소개하므로,
도구의 범위가 테스트 숨기기에서 넓어지는 중으로 읽힌다.
저장소는 2026-09-04에 만들어졌고,
이 문서를 쓴 2026-11-05에도 푸시가 있었으며, 별은 97개다.[^readme]

## 기능

홈페이지는 기능을 두 묶음으로 보여 준다.
첫 묶음은 리뷰와 무관한 변경(noise)을 치우는 기능이고,
둘째 묶음은 대화와 상태를 한곳에 모으는 기능이다.
홈페이지의 화면 시연은 가상의 저장소 `acme/widgets`의 풀 리퀘스트(PR) 하나를
쓰므로, 시연에 나온 숫자는 측정값이 아니라 예시다.

### 노이즈를 접는 기능

- 테스트, 생성 파일, 락 파일, 문서를 diff 맨 아래 한 줄 뒤로 옮긴다. 삭제하지 않고 한 번 눌러 제자리에 되돌릴 수 있다고 한다.
- 헤더와 파일 목록의 줄 수에서 숨긴 파일을 빼고, 어디로 몇 줄이 갔는지 내역을 보여 준다.
- 테스트 파일은 각 테스트를 한 줄짜리 제목으로 보여 주고, 워크플로 파일 안의 여러 줄 셸 스크립트에는 구문 강조를 입힌다.
- 긴 PR 설명은 제목 아래로 접는다.

### 대화와 상태를 모으는 기능

- 다이제스트(digest) 패널이 리뷰, 봇의 판정, CI, 미리보기를 한곳에 보여 주고, 푸시마다 리뷰 라운드가 만들어지며, 스레드는 채팅처럼 열린다.
- Flow는 바뀐 파일을 카드로 그리고, 파일끼리의 import 관계를 선으로 잇는다.
- 리뷰 봇에게 리뷰를 다시 요청할 수 있다.
- 승인, 변경 요청, 댓글을 어느 탭에서든 보낼 수 있고, 상태 라벨 메뉴에서 병합이나 초안 전환 같은 상태 변경을 한다.

### 숨기는 범주

저장소 README는 숨길 파일을 범주(category)로 나눈다.
테스트 범주만 기본으로 켜져 있고 나머지는 직접 켜야 한다.[^faq]

| 범주                 | README가 드는 예                                                 |
| -------------------- | ---------------------------------------------------------------- |
| Tests                | `*.test.*`, `*_test.go`, `e2e/`, `__tests__/`, `*.snap`[^readme] |
| Generated            | `pnpm-lock.yaml`, `Cargo.lock`, `*.min.js`, `dist/`[^readme]     |
| Vendored             | `vendor/`, `node_modules/`, `third_party/`[^readme]              |
| Agent config         | `CLAUDE.md`, `AGENTS.md`, `.cursor/`, `.claude/`[^readme]        |
| Docs                 | `*.md`, `docs/`, `CHANGELOG*`, `LICENSE*`[^readme]               |
| Tooling & CI         | `.github/workflows/`, `Dockerfile*`, `tsconfig*.json`[^readme]   |
| Stories, fixtures 등 | `*.stories.*`, `__fixtures__/`, `locales/`[^readme]              |

## 동작 방식과 데이터 흐름

Geld는 GitHub가 그린 DOM 노드를 지우거나 옮기지 않는다.
숨긴 항목에 더 큰 flex `order`와 숨김용 data 속성을 붙이고,
헤더의 숫자는 원래 값을 기억해 둔 채 고쳐 쓴다.[^faq]
그래서 확장을 끄면 화면이 원래대로 돌아온다고 한다.[^faq]
검사하는 것은 파일 경로뿐이고 파일 내용은 보지 않는다.[^readme]

줄 수는 페이지에 파일별 diff가 그려져 있으면 페이지에서 읽는다.[^faq]
그렇지 않은 곳(PR 대화 탭, PR 목록,
점진적으로 불러오는 큰 PR)에서는 배경 스크립트가 PR 주소 뒤에 `.diff`를 붙인
파일을 받아 온다.[^faq]
FAQ는 이것이 GitHub API 호출이 아니라 일반 페이지 요청이라서 토큰도 API 할당량도
쓰지 않는다고 설명한다.[^faq]
파싱한 diff는 PR의 head 커밋을 키로 확장 저장소에 캐시되고,
목록 행은 화면 근처로 스크롤될 때 최대 네 개씩 받으며,
GitHub가 429로 답하면 1분간 멈춘다.[^faq]

네트워크 요청은 GitHub와 사용자가 추가한 Enterprise 호스트로만 간다고
한다.[^faq]
확장은 서명된 패턴 목록을 GitHub에서 내려받는다.[^privacy]
기기에 저장되는 diff 줄 수에는 파일 경로가 들어갈 수 있다.[^privacy]

## 설정

패턴은 `.gitignore`와 같은 문법이고,
범주마다 내장 패턴 묶음을 끄거나 패턴을 더하거나 범주를 직접 만들 수 있다.[^faq]
저장소 단위 규칙도 같은 문법이어서,
`acme/widgets`는 그 저장소에서 끄고,
`acme`는 조직 전체에서 끄고, `!acme/widgets`는 예외로 다시 켠다.[^faq]
Alt+Shift+T는 설정을 바꾸지 않고 그 페이지에서만 숨긴 파일을 보여 준다.[^faq]
GitHub Enterprise Server는 옵션에서 호스트 이름을 추가하고 브라우저의 권한
요청을 허용해야 한다.[^faq]
홈페이지는 팀이 함께 쓰는 `.github/geld.yml`도 설정으로 소개한다.

## 도입 전에 정할 것

| 결정                | 선택지                                        | 판단 근거                                                                                                           |
| ------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 숨길 범주           | 테스트만(기본) / 나머지 범주를 하나씩 추가    | 숨긴 파일의 변경이 리뷰 대상인지가 기준이다. 아래 비평의 첫 항목이 이유를 설명한다                                  |
| 설정 동기화         | 브라우저 sync / JSON 내보내기 / GitHub 로그인 | 로그인하면 설정이 본인 계정의 secret gist에 저장되는데, 목록에 안 보일 뿐 링크를 아는 사람은 읽을 수 있다[^privacy] |
| 숨긴 파일 열람 표시 | 끄기(권장) / 켜기                             | 켜면 열어 보지 않은 숨긴 파일에도 GitHub의 Viewed 표시가 붙는다[^readme]                                            |
| Safari 설치         | 저장소 zip을 변환해 직접 설치                 | 서명되지 않은 확장이라 개발자 메뉴에서 허용 설정이 필요하다[^readme]                                                |
| Enterprise Server   | 호스트 추가                                   | GHES의 화면은 github.com보다 몇 버전 뒤여서 어긋날 수 있다[^faq]                                                    |

## 비평

### 숨기는 파일이 리뷰 대상일 수 있다

README는 숨긴 파일 모두에 GitHub의 Viewed 체크를 한 번에 표시해,
열어 보지 않고도 리뷰 진행률이 100%에 이르게 하는 옵션을 설명한다.[^readme]
화면의 숫자가 “다 봤다”고 말하는 것과 실제로 읽은 것이 갈라질 수 있다는 뜻이다.
기본값은 테스트 범주뿐이지만, 다른 범주에는 락 파일과 워크플로 파일과 에이전트
지침 파일(`AGENTS.md`, `CLAUDE.md`)이 들어 있다.[^readme]
이 파일들은 의존성 변경, CI 권한, 에이전트의 행동을 바꾸는 파일이어서,
줄 수가 작아도 리뷰에서 가장 먼저 봐야 할 수 있다.
이 위험은 저자도 알고 있다.
FAQ는 OpenAPI 문서가 `api.spec.yaml`처럼 불리므로,
스키마 변경을 조용히 숨기는 것이 테스트를 보여 주는 것보다 훨씬 나쁘다는 이유로
`*.spec.*`를 코드 확장자에만 적용한다고 설명한다.[^faq]
같은 논리를 락 파일과 워크플로 파일과 지침 파일에도 적용하면,
이 범주들은 기본으로 끄고 하나씩 켜는 것이 맞다.
이는 이 문서의 판단이고, Geld가 숨겨서 실제 사고가 났다는 보고를 찾은 것은
아니다.

### 홈페이지의 소개와 방침이 가리키는 범위가 다르다

홈페이지가 소개하는 것은 브라우저 확장이다.
그런데 개인정보 처리방침은 확장 말고도 대시보드, 계정, 팀, 결제,
AI 가이드와 크레딧을 다루고, 호스팅에 Vercel과 Neon과 Stripe와 PostHog를 쓴다고
적는다.[^privacy]
FAQ는 확장의 설정 동기화에 Geld 서버나 데이터베이스가 없다고 설명한다.[^faq]
방침이 말하는 호스팅 서비스와 FAQ의 서버 없는 확장이 서로 다른 제품 부분인
것으로 읽히지만, 홈페이지는 이 둘의 관계를 설명하지 않는다.

권한 범위도 구분해서 읽어야 한다.
FAQ는 GitHub 로그인의 유일한 범위가 `gist`라고 한다.[^faq]
방침은 선택 사항인 GitHub OAuth가 `repo` 범위를 쓰고,
이는 계정이 닿는 모든 저장소의 읽기와 쓰기 권한이라고 적는다.[^privacy]
두 문서가 말하는 로그인이 같은 것인지 이 문서는 확인하지 못했다.
방침은 GitHub 신원 앱이 저장소 앱과 별개라고 적으므로 서로 다른 경로일 가능성이
크지만, 로그인 화면에서 요청하는 범위를 직접 읽고 판단해야 한다.[^privacy]

문서끼리 어긋나는 곳도 있다.
홈페이지는 팀이 공유하는 `.github/geld.yml`을 설정 기능으로 소개하는데,
README의 로드맵은 이것을 앞으로 할 일로 적는다.[^readme]
README가 낡았는지 홈페이지가 앞서 가는지는 확인하지 못했다.

### 사용처 로고와 전제는 근거가 보이지 않는다

홈페이지는 “Used by founders and engineers at” 아래에 OpenAI, Vercel,
Mercury, CodeRabbit를 포함한 열세 곳의 이름을 나열한다.
각 회사의 도입 규모나 인용은 없고,
회사 이름 옆의 문구도 창업자와 엔지니어가 쓴다는 것이지 회사가 채택했다는 뜻이
아니다.
이 문서는 이 목록을 확인하지 못했다.
저장소의 별 97개는 널리 퍼진 도구의 숫자는 아니다.[^readme]

“리뷰가 망가졌다”는 전제도 증거 없이 주어진다.
Geld가 바꾸는 것은 화면에 보이는 양과 배치이고,
리뷰어가 코드를 이해하는 데 드는 시간이나 놓치는 결함의 비율을 줄였다는 측정은
홈페이지에도 README에도 없다.
이 도구가 리뷰의 질을 높이는지는 숨긴 범주에서 나중에 결함이 발견된 비율을 도입
전후로 비교해야 알 수 있다.

## 확인하기

- README가 예로 드는 `https://github.com/wxt-dev/wxt/pull/2544/files`를 열어 헤더의 “N tests” 표시에 마우스를 올려 테스트 제외, 포함, 테스트만의 줄 수가 모두 나오는지 본다.[^readme]
- 브라우저 개발자 도구의 네트워크 탭에서 요청이 github.com으로만 가는지 본다. FAQ가 약속하는 내용이다.[^faq]
- 락 파일, 워크플로 파일, 에이전트 지침 파일은 켜기 전에 팀에서 열람 규칙을 정한다.
- 숨긴 파일 열람 표시 옵션이 꺼져 있는지 확인한다.
- GitHub 로그인을 쓴다면 요청하는 권한 범위를 승인 화면에서 직접 읽는다.
