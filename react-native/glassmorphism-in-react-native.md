# Glassmorphism in React Native

동영상: [Glassmorphism in React Native - YouTube](https://www.youtube.com/watch?v=ao2i_sOD-z0)

## 요약

이 영상은 William Candillon이 React Native Skia를 이용해 glassmorphism
UI를 구현하는 방법을 시연하는 튜토리얼이다.
그는 Raphael Almeida가 트위터에서 제안한 Calmeria 앱을 예시로 삼아,
`backdrop blur`를 사용해 흐릿하게 반투명한 유리 질감의 UI를 만드는
과정을 보여준다.

핵심 개념은 필터를 대상 요소 자체에 적용하는 것이 아니라, 클리핑
영역(clipping area)을 정의하고 그 영역 뒤에 있는 배경에만 필터를
적용한다는 점이다.
예를 들어 원이나 둥근 사각형(rounded rectangle)을 클리핑 영역으로
삼아 `backdrop blur`의 `intensity` 값을 조절하면, 해당 영역 뒤의
배경만 블러 처리되고 요소 자체는 그대로 유지된다.
카드 예제에서는 반투명한 흰색 사각형 위에 낮은 opacity를 적용해
카드를 움직여도 배경이 실시간으로 블러 처리되는 모습을 시연한다.

영상의 두 번째 부분에서는 `backdrop blur`가 사실
`backdrop filter`라는 더 일반적인 기능의 축약형이라는 점을 설명한다.
`backdrop filter`의 첫 번째 자식으로 원하는 필터를 지정할 수 있는데,
블러 대신 컬러 매트릭스(color matrix)를 적용하면 흑백이나 세피아 같은
효과를 배경에만 적용할 수 있다.
더 나아가 Perlin noise 셰이더를 변위 맵(displacement map)으로 사용해
바다 위에 비치는 햇빛 반사 같은 효과를 만드는 예제도 보여준다.
이때 x축과 y축 각각에 어떤 색상 채널을 변위 계산에 사용할지, 스케일
값을 얼마로 줄지, 그리고 `offset` 필터로 위치를 미세 조정하는 과정을
함께 설명한다.

영상은 클리핑 영역이 사각형뿐 아니라 SVG path로도 지정될 수 있다는
점, 그리고 이런 필터들이 무한히 조합 가능(composable)하다는 점을
강조하며 마무리된다.
Candillon은 React Native Skia의 렌더러가 이런 필터 조합을 자동으로
이해하고, 어떤 필터가 한 번만 실행되어야 하는지 아니면 렌더링 루프의
일부가 되어야 하는지도 자동으로 판단한다고 설명한다.
그는 React Native 개발자들이 그동안 새로운 디자인 트렌드에서 소외되어
왔지만, 이제 React Native Skia 덕분에 이런 트렌드를 실험할 수 있게
되었다는 점에 대한 기대감을 드러내며 영상을 마친다.

## 분석

### 클리핑 영역과 필터의 분리가 만드는 표현력

이 영상의 핵심 통찰은 필터를 “무엇에 적용하는가”와 “어디에 적용하는가”를
분리한 데 있다.
일반적인 블러 함수는 대상 요소 자체를 흐리게 만들지만, `backdrop
filter`는 클리핑 영역이라는 별도의 개념을 도입해 그 영역 뒤에 있는
임의의 배경 콘텐츠에 필터를 적용한다.
이 분리는 단순한 API 편의가 아니라, 유리·서리·물 같은 실제 물리적
재질이 빛을 다루는 방식, 즉 재질 자체가 아니라 그 뒤의 빛을 왜곡한다는
방식을 컴퓨터 그래픽스 언어로 재현한 것이다.
그렇기 때문에 이 API 하나로 glassmorphism뿐 아니라 물 위의 굴절, 서리
낀 유리 같은 완전히 다른 시각 효과를 같은 개념적 틀 안에서 표현할 수
있다.

### React의 선언적 합성이 셰이더 프로그래밍의 진입장벽을 낮춘다

Perlin noise, displacement map, color matrix 같은 개념은 원래 셰이더
프로그래밍이나 그래픽스 엔진(Unity, After Effects 등)에서 다뤄지던
영역이다.
Candillon이 강조하듯, 이 영상에서 흥미로운 지점은 Skia 자체가 이런
필터들을 지원한다는 사실이 아니라, React가 이 필터들을 컴포넌트처럼
선언적으로 조합할 수 있게 해 준다는 점이다.
렌더러가 필터 트리를 분석해 어떤 연산이 정적(한 번만 계산)이고 어떤
연산이 매 프레임 다시 계산되어야 하는지 자동으로 판단한다는 설명은,
명령형 그래픽스 API가 요구하던 수동 최적화 부담을 선언적 컴포넌트
모델이 대신 떠맡는다는 구조적 전환을 보여준다.

### 트위터발 디자인 트렌드가 즉시 구현 가능한 근거

이 영상이 “Raphael Almeida가 트위터에서 제안한 Calmeria 앱”이라는
구체적인 출처에서 시작한다는 점은 우연이 아니다.
React Native Skia 이전에는 새로운 디자인 트렌드가 등장해도 이를
구현하려면 네이티브 코드나 커스텀 렌더링 파이프라인을 새로 짜야
했기 때문에, 트렌드가 SNS에서 확산되는 속도와 실제 앱에 반영되는
속도 사이에 큰 시차가 있었다.
Candillon이 몇 분 만에 트위터에 올라온 스크린샷을 재현해 보이는
장면은, 그 시차가 거의 사라졌다는 것을 실연으로 증명하는 행위이며,
이는 영상 자체가 “React Native Skia의 표현력”이라는 주장을 뒷받침하는
증거로 기능한다.

## 비평

### “몇 분 만에 재현했다”는 인상이 실제 프로덕션 적용 난이도를 가린다

영상은 라이브 코딩 형식으로 빠르게 진행되며, 시청자에게 glassmorphism이
매우 간단하게 구현된다는 인상을 준다.
그러나 실제로 프로덕션 앱에서 이 기법을 쓰려면 스크롤이나 애니메이션
중에도 배경 블러가 실시간으로 재계산되어야 하는데, 이는 GPU 부담이 큰
연산이다.
영상은 데모용 원 하나, 카드 하나를 움직이는 수준에서만 시연할 뿐, 리스트
안에 여러 개의 유리 카드가 동시에 존재하거나 복잡한 배경 위에서 이
효과를 겹겹이 쌓았을 때의 성능에 대해서는 전혀 언급하지 않는다.
결과적으로 시청자는 “쉽게 구현된다”는 인상만 얻고, 실제 적용 시 마주칠
성능 최적화 문제는 스스로 발견해야 한다.

### 플랫폼별 렌더링 차이가 다뤄지지 않는다

React Native Skia는 iOS와 Android 양쪽에서 동작하도록 설계된
라이브러리이지만, 영상은 시연 내내 어느 플랫폼에서 녹화되었는지,
또는 두 플랫폼에서 동일한 결과가 나오는지에 대한 언급이 없다.
`backdrop blur`나 displacement map 같은 GPU 셰이더 연산은 플랫폼별
그래픽스 드라이버나 GPU 아키텍처에 따라 성능과 정밀도 차이가 발생할
가능성이 있는데, 영상은 이를 단일 플랫폼에서의 결과만으로 일반화해서
보여준다.
크로스플랫폼을 표방하는 라이브러리를 다루면서 플랫폼 간 차이를 검증하지
않은 채 시연하는 것은, 시청자가 안드로이드에서도 동일한 결과를 기대하게
만드는 근거 없는 일반화다.

### “무한히 조합 가능하다”는 주장이 실패 사례 없이 제시된다

Candillon은 필터들이 “infinitely composable”하다고 표현하지만, 이는
이론적 조합 가능성일 뿐 실질적인 합성 결과가 항상 시각적으로 유의미하다는
뜻은 아니다.
영상 안에서도 그는 SVG path를 클리핑 마스크로 쓰는 예제를 보여주며 “이걸
왜 쓰고 싶어 할지는 모르겠지만”이라고 스스로 인정하는데, 이는 조합
가능성의 이론적 크기와 실제로 쓸모 있는 조합의 크기 사이에 큰 간극이
있음을 그 자신도 알고 있다는 뜻이다.
그럼에도 영상 전체의 결론은 “무한한 조합 가능성”을 강점으로만
제시하고, 그 조합 공간에서 실제로 유용한 지점을 찾는 것이 얼마나
어려운 작업인지에 대해서는 다루지 않는다.

## 인사이트

### 셰이더 API의 노출이 디자이너와 개발자의 협업 방식을 바꾼다

이 영상이 보여주는 것은 단순히 새 API 하나가 아니라, 셰이더 수준의
그래픽스 조작이 React 컴포넌트 트리 안으로 들어왔다는 구조적 변화다.
이전에는 디자이너가 Figma나 After Effects에서 만든 이펙트를 개발자가
네이티브 코드로 재구현해야 했고, 그 과정에서 디자인 의도가 손실되거나
근사치로 타협되는 일이 흔했다.
필터가 React 컴포넌트로 선언 가능해지면, 디자이너가 만든 SVG 필터나
셰이더 코드를 개발자가 거의 그대로 컴포넌트 트리에 삽입할 수 있게 되고,
이는 디자인-개발 핸드오프의 병목을 근본적으로 줄이는 방향으로 작용한다.
영상 속에서 Candillon이 외부 SVG 필터 갤러리 사이트를 참고 자료로
소개하는 장면은, 이런 협업 방식의 변화가 이미 실무에서 시작되고
있음을 보여주는 단서다.

### 디자인 트렌드의 수명 주기가 구현 비용에 따라 결정되어 왔다는 역사적 패턴

Candillon이 “React Native 개발자들은 그동안 디자인 트렌드에서 소외되어
왔다”고 말하는 대목은, 사실 모바일 UI 역사 전반에 걸쳐 반복되어 온
패턴을 가리킨다.
스큐어모피즘에서 플랫 디자인으로, 다시 뉴모피즘으로 넘어가는 각 전환은
언제나 “이 스타일을 구현하는 데 드는 비용”과 밀접하게 연동되어 있었고,
구현 비용이 낮아질수록 그 트렌드가 대중적으로 확산되는 속도도 빨라졌다.
글래스모피즘이 React Native 생태계에서 이렇게 빠르게 채택 가능해진
것은, 디자인 트렌드의 수명과 확산 속도가 심미적 유행이 아니라 그
시대의 렌더링 기술이 허용하는 구현 난이도에 의해 결정된다는 더 오래된
패턴의 최신 사례일 뿐이다.

### 배경 콘텐츠에 대한 필터가 개인정보와 접근성 문제를 새로 만들 가능성

`backdrop filter`가 클리핑 영역 뒤의 임의 콘텐츠를 실시간으로
변형한다는 것은, 개발자가 그 배경에 무엇이 있을지 예측할 수 없는
상황에서도 필터가 적용된다는 뜻이다.
예를 들어 사용자가 스크롤하는 리스트 위에 유리 패널을 올려두면, 그
뒤에 지나가는 텍스트나 이미지의 명암 대비가 필터 강도에 따라 계속
바뀌는데, 이는 저시력 사용자나 색맹 사용자에게 예측 불가능한 가독성
저하를 초래할 수 있다.
영상은 순전히 미적 효과의 관점에서만 이 기법을 다루고 있어, 배경
콘텐츠의 접근성이 필터 강도에 따라 실시간으로 훼손될 수 있다는
문제는 전혀 논의되지 않는다.
디자인 트렌드가 구현하기 쉬워질수록 이런 접근성 검토 없이 프로덕션에
바로 적용될 위험도 함께 커진다.
