# Tesseract NPU: LLM 추론용 오픈소스 NPU

<https://github.com/jwkim04/tesseract-npu>

Show GN: [Tesseract NPU - LLM 추론을 위한 풀스택 오픈소스 NPU](https://news.hada.io/topic?id=37399)

## 소개

Tesseract NPU는 LLM 추론을 위한 풀스택 오픈소스 NPU(신경망 처리 장치) 프로젝트이다. 저장소 설명은 LLM 추론을 위한 풀스택 오픈소스 NPU라고 한다.
이 문서는 저장소 README와 GitHub API 수치, GeekNews Show GN 글을 읽었다. 직접 합성하거나 시뮬레이터를 돌려 보지 않았고 CHANGELOG, 문서, 라이선스 파일은 열지 못했다. 저장소의 홈페이지 필드가 비어 있고 README에서 별도 프로젝트 사이트를 확인하지 못해 저장소 주소만 적었다.
설명은 모두 제작자의 주장이다.

GitHub API로 읽은 시점(2026년 11월 19일)의 수치는 별 23개, 포크 3개, 열린 이슈 0개, 라이선스 Apache-2.0, 언어 C++, 생성일 2026년 10월 23일, 마지막 푸시 2026년 11월 18일이다. 커밋은 295개이고 버전은 Tesseract Basis 1.6.0과 Tesseract Core 1.2.1(둘 다 2026년 11월 18일)이다.

README와 Show GN 글이 소개하는 내용은 다음과 같다.

- 구성: SystemVerilog로 쓴 NPU 코어 RTL과 RISC-V 제어 코어, Basis 펌웨어와 커널 SDK(C++20), llama.cpp 백엔드(`-ngl`)와 PyTorch 백엔드(`torch.compile(..., backend="tesseract")`), 비트 단위로 일치하는 시뮬레이터이다.
- 설계: 커널 기반의 그래프 실행 모델이며 GPU와 TPU 사이쯤에서 스크래치패드와 큰 메모리 관리 장치(MMU)를 두고 RISC-V 제어 코어가 C++ 커널을 돌린다. 제작자는 디코드 때 이론상 최대 메모리 대역폭의 90%까지 쓴다고 한다.
- 구현된 것: Alveo U200 FPGA 빌드(클러스터 4개), 비용 기반 그래프 최적화기, llama.cpp와 PyTorch 백엔드이다.
- 지원: 32B까지의 대부분의 양자화 LLM, GGUF와 PyTorch 모델, 지원하지 않는 연산의 자동 CPU 대체, 네이티브 Q8_0과 Q4_K_M, MoE와 GDN과 MTP 구조, 융합 어텐션 경로이다. README는 llama.cpp가 배포한 그대로의 GGUF 모델을 돌린다고 한다.
- 성능(README): U200 한 장에서 디코드가 Qwen3.8 27B Q8_0의 2.32 tok/s부터 Gemma 4 E2B Q8_0의 24.42 tok/s이다.
- 아직 없는 것: llama.cpp와 PyTorch 업스트림 백엔드 등록, 멀티 칩 클러스터링, Q6와 NVFP4 형식, 더 많은 벤치마크, ASIC이다.
- 하드웨어와 설치: AMD Alveo U200 FPGA(XRT 필요)이고 시뮬레이터는 FPGA 없이 Linux x86-64에서 돈다. `git clone --recurse-submodules ... && cd tesseract`에 이어 `./quickstart.sh`가 스택을 빌드하고 0.7GB의 Qwen2.5 0.5B Q8_0 모델을 받아 시뮬레이터에서 돌린다. 16 CPU 데스크톱에서 첫 실행이 약 121초라고 한다.

## 분석

### 중심 주장은 소프트웨어 스택까지 포함한 NPU이다

RTL만이 아니라 펌웨어, 커널 SDK, 컴파일러에 해당하는 그래프 최적화기, llama.cpp와 PyTorch 연결까지 한 저장소에 담았다는 것이 풀스택이라는 말의 뜻이다.
시뮬레이터가 있어 FPGA 없이 스택 전체를 시험할 수 있다는 점이 진입 장벽을 낮춘다. 이는 README의 서술을 이 문서가 정리한 것이다.

### 성능 수치가 FPGA의 한계를 보여 준다

Alveo U200 한 장에서 27B Q8_0 모델이 초당 2.3 토큰이고 가장 빠른 작은 모델도 초당 24 토큰이다. 이 수치가 현재 FPGA 프로토타입의 위치를 가리키고, 제작자가 ASIC을 앞으로의 과제로 적는 이유로 읽힌다. 이는 이 문서의 해석이다.

## 비평

### 수치가 제작자의 것이고 비교가 없다

디코드 때 이론 대역폭의 90%라는 주장과 tok/s 수치에 GPU나 CPU 같은 기준 비교가 없다. 측정 조건(배치, 문맥 길이, 양자화)도 README의 표 밖에서는 확인되지 않는다. 독립 재현을 읽지 못했다.

### 프로젝트가 아주 초기이다

별 23개, 생성한 지 한 달 남짓, 업스트림 백엔드 미등록, 멀티 칩과 ASIC 미구현이다.
295개 커밋이 한 달에 쌓였고 최근 푸시가 하루 전이라 개발은 활발하나 유지 구조(제작자 한 명인지)는 읽은 범위에서 알 수 없다.

### 지원 범위의 경계가 구체적이지 않다

32B까지의 대부분의 양자화 LLM이라고 하지만 어떤 모델과 형식이 실제로 통과하는지의 목록은 이 문서가 읽은 범위에 없다. Q6와 NVFP4가 빠져 있다고 제작자 스스로 적는다.

## 인사이트

### 가져갈 것은 하드웨어 프로젝트의 시뮬레이터 우선 접근이다

FPGA 없이 비트 단위로 일치하는 시뮬레이터로 전체 스택을 돌려 볼 수 있게 한 것은 하드웨어 프로젝트에 기여자가 접근하는 길을 넓힌다. 이는 이 문서의 적용이다.

### 업스트림 등록이 채택의 분기점이다

llama.cpp와 PyTorch의 공식 백엔드로 들어가는지가 사용자 저변을 정한다. 쓰려는 사람은 현재의 포크나 외부 백엔드 상태를 확인하고 시험한다.

### 확인할 관찰

이 프로젝트의 주장을 가를 관찰은 세 가지이다.
GPU와 CPU 대비 같은 조건의 성능과 대역폭 이용률,
업스트림 백엔드 등록과 지원 모델 범위의 확대,
FPGA에서 ASIC으로 가는 일정이다.
셋 모두 이 문서가 확인하지 못했다.
