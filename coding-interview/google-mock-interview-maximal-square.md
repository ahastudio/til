# Google 모의 코딩 면접: 최대 정사각형 문제를 브루트 포스에서 동적 계획법까지 말로 풀어 간다

영상: [How to solve a Google coding interview question](https://www.youtube.com/watch?v=Ti5vfu9arXQ)

## 소개

Google의 채용 채널 Life at Google이 2025-02-10에 올린 약 26분짜리 영상이다.
Google의 소프트웨어 엔지니어 두 명이 모의 면접을 연기한다.
지원자 역은 Google Research의 연구 과학자 Sami이고, 면접관 역은 YouTube의
소프트웨어 엔지니어 Juliana이다.
영상 첫머리에서 채용 담당자는 이 문제가 실제 면접에 그대로 나오지는 않지만
가정을 말하고, 풀이를 개선하고, 열린 형태여서 사고방식을 보여 줄 수 있는 유형을
대표한다고 말한다.

이 문서는 영어 자동 자막을 읽고 썼다.
화면의 코드와 표는 자막에 없으므로, 두 사람이 말로 한 내용만 반영했고 마지막
코드는 설명을 바탕으로 다시 적은 것이다.
설명란에 있는 장 구분은 소개, 준비 안내, 문제, 명확화 질문, 생각 설명, 브루트
포스, 최적 접근, 재귀, 동적 계획법, 구현, 마무리이다.

## 면접 진행 방식

영상 앞뒤로 채용 담당자와 면접관이 지원자에게 주는 조언은 다음과 같다.

- 실제 면접에는 컴파일러나 IDE가 없다. 집에서 Google Docs에 코드를 써 보고, 테스트까지 해서 연습한다.
- 사소한 문법 오류(부분 문자열 메서드가 시작과 끝을 받는지, 시작과 길이를 받는지 같은 것)는 걱정하지 말고, 하나를 골라 면접관에게 알린다.
- 가능한 한 명확화 질문을 한다. 문제는 일부러 열려 있는 경우가 많다.
- 생각 과정을 소리 내어 말한다. 면접관은 기술 능력만이 아니라 문제를 푸는 방식을 평가한다.
- 가정을 명시적으로 말하고 면접관과 확인한다.
- 마지막에는 설명하기, 명확히 하기, 답을 개선할 방법을 생각하기, 미리 연습하기를 다시 당부한다.

## 문제

농부가 땅을 경작하려 한다.
땅은 1과 0으로 된 행렬이고, 1은 좋은 땅, 0은 나쁜 땅이다.
농부는 좋은 땅으로만 이루어진 정사각형 하나를 경작하려 하며, 그 정사각형의 최대
넓이를 구하는 문제이다.

지원자는 먼저 정사각형이어야 하는지 직사각형도 되는지 묻고, 정사각형만 반환하면
된다는 답을 듣는다.
이 질문이 영상이 말하는 명확화 질문의 예이다.
구현 도중에는 행렬의 가로와 세로가 다를 수 있고, 그래도 답은 정사각형이어야
한다는 점도 면접관이 확인해 준다.

## 풀이 단계

### 브루트 포스를 먼저 말한다

지원자는 “하지 말아야 할지도 모르지만 말해 보겠다”며 단순한 풀이를 먼저
제시한다.
모든 위치 `(i, j)`에서 시작해 오른쪽과 아래로 한 칸씩 정사각형을 키우며 전부
1인지 확인하고, 지금까지 가장 컸던 변의 길이를 기록한다.
정사각형이 `n × n`이면 최소 `n^4`이라고 지원자가 말하고, 효율적인 풀이를 원하는
것으로 이해한다고 확인한다.
면접관은 이 대목을 설명을 잘한 예로 칭찬하고, 예시를 놓고 이 풀이를 그려 달라고
요청한다.

지원자는 예시 행렬에서 한 위치를 잡고 1×1, 2×2, 3×3으로 키우는 과정을 보여 준다.
면접관은 브루트 포스 풀이도 이웃 값으로 정사각형 크기를 알아내는 방향이 옳다고
말하고, 구현은 건너뛰고 더 나은 풀이로 넘어가자고 한다.

### 재귀로 이웃에게 묻는다

지원자는 재귀(recursion) 풀이를 소리 내어 생각한다.
위치가 0이면 0을 반환한다.
1이면 오른쪽, 아래, 대각선 아래 오른쪽 이웃이 만들 수 있는 정사각형의 크기를
재귀로 물어, 그중 최솟값에 1을 더한 값을 반환한다.
면접관은 대각선이 0이면 이 위치의 최대 정사각형이 1이라는 점 등을 유도 질문으로
확인한다.

지원자는 예시를 바꿔 가며 최솟값을 취하는 것이 충분한지 검증한다.
세 이웃이 모두 3이면 현재 위치는 4가 된다는 사례로 규칙을 확인한다.
이 재귀는 같은 부분 문제를 여러 번 풀므로 메모이제이션(memoization)을 붙이면 각
호출이 한 번만 일어나 최대 `n^2`번이 된다고 말한다.

### 동적 계획법으로 아래에서 위로 쌓는다

지원자는 메모이제이션으로 풀 수 있는 문제에는 아래에서 위로 쌓는 동적
계획법(dynamic programming)이 있다고 말하고, 면접관은 코드를 쓰기 전에 그 생각을
먼저 듣고 싶다고 한다.
지원자는 면접관의 이전 힌트(“대각선도 3×3이 되는지 보라”)를 이용한다고 밝힌다.

입력과 같은 크기의 DP 배열을 0으로 채워 만든다.
입력 칸이 0이면 DP 값도 0이다.
입력 칸이 1이면 위, 왼쪽, 대각선 왼쪽 위 DP 값 중 최솟값에 1을 더해 적는다.
답은 DP 배열의 최댓값이다.
면접관은 DP 배열이 담는 값이 넓이가 아니라 정사각형의 변 길이임을 짚고, 지원자는
정사각형이므로 변 길이가 맞다고 답한다.

## 구현

지원자는 Python으로 구현하고, 함수 시그니처에 타입 힌트(`list[list[int]]` 같은
정수 이차원 배열)를 붙일지 면접관에게 묻고, 이차원 정수 배열이라는 답을 듣는다.
면접관은 구현 중에 두 가지를 묻고, 지원자는 두 가지 모두 개선한다.

첫째, 경계 처리를 루프 안에 `if` 문으로 두지 말고 밖에서 하면 어떻겠느냐는
질문이다.
면접관은 루프 안에서도 할 수 있다고 말하고, 지원자는 인덱스가 0보다 큰지를
조건으로 두는 안을 설명한다.

둘째, 세 이웃 값이 모두 0보다 큰지 확인하는 `if` 문이 필요한지 묻는 질문이다.
지원자는 입력이 1인 칸에서 이웃 중 하나가 0이면 최솟값이 0이고 결과가 1이 되므로
이 검사가 필요 없고 오히려 버그를 만들 수 있다고 인정하고 지운다.

마지막으로 최댓값을 구하는 방법을 묻는다.
지원자는 처음에 행별 최댓값을 구한 뒤 그중 최댓값을 구했다.
면접관이 루프 안에서 최댓값을 추적할 수 있느냐고 묻자, 갱신할 때마다 최댓값을
읽어 두는 방식으로 고친다.

다음은 영상의 설명을 바탕으로 다시 적은 최종 풀이이다.

```python
def largest_square(grid: list[list[int]]) -> int:
    n, m = len(grid), len(grid[0])
    dp = [[0] * m for _ in range(n)]
    best = 0
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 0:
                continue
            up = dp[i - 1][j] if i > 0 else 0
            left = dp[i][j - 1] if j > 0 else 0
            diag = dp[i - 1][j - 1] if i > 0 and j > 0 else 0
            dp[i][j] = min(up, left, diag) + 1
            best = max(best, dp[i][j])
    return best * best
```

면접관은 이 풀이가 좋다고 평가하며, 지원자가 면접관의 교정을 받아들이며 더 나은
풀이로 이동했다는 점을 칭찬한다.

## 비평

### 영상은 쉬운 길을 보여 준다

두 사람은 같은 회사의 동료이고 연기를 한다.
면접관은 풀이로 이어지는 힌트를 여러 번 직접 말하고(대각선 확인, 최솟값 취하기의
방향), 지원자도 이를 힌트라고 밝힌다.
실제 면접에서 힌트가 이만큼 주어지는지, 지원자가 막힌 구간이 이만큼 짧은지는
영상으로 알 수 없다.
영상은 모범 사례이며, 평가 기준이나 합격 선은 말하지 않는다.

### 구현이 문제의 요구와 어긋난 채 끝난다

문제는 최대 넓이를 반환하라고 했다.
면접관이 DP 값은 변 길이라고 지적했고 지원자가 동의했지만, 영상에서 들리는
마지막 반환문은 DP 값의 최댓값이다.
자막으로는 최종 코드에서 변 길이를 제곱하는 단계가 확인되지 않고, 최댓값을 담는
변수의 초깃값도 자막만으로는 알 수 없다.
화면 코드를 보지 못해서 이를 확정하지 못한다. 위 코드는 변 길이를 제곱해 넓이를
반환하도록 고쳐 적은 것이다.
영상이 이 불일치를 짚지 않고 풀이가 좋다고 끝내는 점은 모의 면접에서도 검증
단계가 빠졌다는 신호이다.

### 시간 복잡도를 끝까지 명시하지 않는다

지원자는 브루트 포스가 `n^4`이고 메모이제이션 재귀가 `n^2`번 호출된다고 말한다.
동적 계획법의 복잡도는 “같은 복잡도 안에서”라고만 말하고, 공간 복잡도도 말하지
않는다.
이 영상이 가르치려는 것이 설명하기라면 최종 풀이의 시간과 공간 복잡도 설명이
빠진 것이 아쉽다.

### 테스트가 없다

채용 담당자는 영상 첫머리에서 코드를 쓰고 테스트까지 연습하라고 말한다.
영상의 구현 단계에서는 예시로 코드를 따라가 보는 과정이 없다.
0만 있는 입력이나 한 행짜리 입력 같은 경계 사례를 확인하지 않은 채 끝난다.

## 기억할 원칙

- 풀이는 단계로 말한다. 브루트 포스를 먼저 말하고 복잡도를 밝힌 뒤 재귀, 메모이제이션, 동적 계획법 순으로 개선한다.
- 문제를 읽으면 먼저 요구 사항을 확인한다. 이 영상에서는 정사각형만 반환하는지, 가로와 세로가 다를 수 있는지가 그 예였다.
- 면접관의 질문은 대개 개선 방향의 힌트이므로 방어하지 말고 받아들여 풀이에 반영한다. 지원자는 불필요한 `if` 문 삭제와 최댓값 추적 위치 변경을 이렇게 받아들였다.
- 끝낼 때는 반환값이 문제가 요구한 것(이 문제에서는 넓이)인지, 경계 사례가 되는지를 직접 확인한다. 영상에서는 이 단계가 빠져 있었다.
