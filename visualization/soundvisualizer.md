## 소개

SoundVisualizer는 농인과 청각장애인을 위해 만든 오픈소스 앱이다.
자막은 대사를 알려 주지만 소리가 어느 쪽에서 났는지, 얼마나 큰지,
사이렌인지 누가 부르는 소리인지는 알려 주지 않는다는 문제의식에서 출발한다.
기기에서 재생되는 소리를 지금 보는 화면의 테두리에 빛으로 그려 주며,
영상, 음악, 게임 등 앱을 가리지 않는다.
동국대 학생 세 명(SOVIS)이 만들었고, 글 정리에는 AI의 도움을 받았다고
소개글에 적혀 있다.

## 동작 방식

다른 앱 위에 터치가 통과하는 오버레이를 띄우고 소리가 나는 쪽 테두리를 더 크게
그린다.
휴대폰은 좌우를, Windows는 5.1 또는 7.1 출력이면 앞뒤까지 보여 준다.
소리의 종류는 YAMNet(ONNX Runtime)으로 환경음, 사람 소리, 위협음으로 나눠 색을
바꾸고, 말소리는 Silero VAD로 더 빨리 잡는다.
추론은 모두 기기 안에서 하고 소리는 저장하거나 보내지 않으며,
Android 앱에는 인터넷 권한이 없다고 한다.

두 플랫폼은 구현이 다르다.

| 플랫폼  | 기술                      | 소리 수집                                            | 부가 기능                                                 |
| ------- | ------------------------- | ---------------------------------------------------- | --------------------------------------------------------- |
| Android | Kotlin, Compose, C++(NDK) | AudioPlaybackCapture, 좌우 채널 크기를 버퍼마다 측정 | 진동 알림, 마이크로 주변 소리 듣기, 잠금 화면 위협음 알림 |
| Windows | C#, WPF                   | NAudio의 WASAPI 루프백                               | 게임은 창 모드나 테두리 없는 창 모드에서 사용             |

설치는 Android가 원스토어와 GitHub 릴리스, Windows가 Microsoft Store와 GitHub
릴리스다.
요구 사양은 Android 10 이상, Windows 10/11 64비트다.

## 주요 기능

README와 프로젝트 사이트가 소개하는 기능은 다음과 같다.
Android 앱은 Apache 2.0 라이선스다.

| 기능            | 내용                                                                                                      |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| 표시 모드 4가지 | 화면 가장자리에 파형을 그리는 Wave, 중앙 고리가 부푸는 Circle, 가장자리 8곳의 Pad, 얇은 선만 남긴 Outline |
| 소리 분류       | YAMNet이 아는 521가지 소리를 환경음, 사람 소리, 위협음으로 나누고 사용자가 분류를 바꿀 수 있음            |
| 위협음 규칙     | 사이렌, 경보, 폭발음, 깨지는 유리 등이 상위 5개 후보에 5% 이상 나오면 위협음으로 취급                     |
| 색 안정화       | 위협음은 첫 판정에서, 사람 소리와 환경음은 연속 두 번 나와야 색이 바뀜                                    |
| 진동            | 유형마다 끔, 느림, 중간, 빠름, 연속과 10~100% 세기를 고르고, 잠금 화면에서 위협음 알림                    |
| 외부 소리 모드  | 기기 소리 대신 마이크로 주변 소리를 듣고 화재경보, 사이렌, 부르는 소리를 알림. 마이크 감도 16단계         |
| 다국어          | 한국어, 영어 등 18개 언어                                                                                 |

Android 폰의 소리는 두 채널이라 좌우는 알 수 있어도 앞뒤는 알 수 없고,
화면 위아래의 그래픽은 양쪽에서 같은 크기로 들리는 소리와 공간감을 보여 준다고
README가 설명한다.
설계 면에서는 프레임마다 메모리를 할당하지 않는 Compose 캔버스 렌더러,
버퍼마다 C++로 재는 좌우 최대 크기,
250ms마다 최근 0.975초를 16kHz 모노로 바꿔 분류하는 추론 파이프라인이 있다.
모델 파일은 불러올 때 고정된 크기와 SHA-256으로 검사한다.
프레임은 120Hz 화면에서도 60FPS로 제한한다.

프로젝트 사이트의 소식에 따르면 2026년 11월 10일 장애인 해커톤 디지털 포용 부문
결선에서 장려상을 받았고,
11월 19일 게임 매체 Game Chosun에 소개 기사가 실렸으며,
11월 26일과 27일 사이 Android 1.10.0, Windows 2.3.4 등 릴리스가 이어졌다.
GitHub 릴리스 기준 누적 다운로드는 사이트 표기로 362회(Android 215, Windows
147)다.

## 사용자 시험

개발팀은 국립서울농학교 청각장애 학생들과 세 번 시험하며 기능을 정했다.
학생들이 가장 원한 정보는 소리의 방향이었고,
가장 걱정한 것은 오버레이가 시선을 빼앗는 일이었다.
시험 뒤에는 글 대신 그림으로 선택하는 쉬운 설정을 더했다.
개발팀이 받고 싶은 의견은 세 가지다.
테두리 표시가 보는 내용을 방해하는지,
소리 종류 분류가 틀리는 경우가 어떤 소리인지,
기기나 앱에 따라 소리를 못 받는 경우가 있는지다.

## 분석

### 자막이 비워 둔 정보

이 앱이 겨냥하는 정보는 방향, 크기, 종류다.
특히 게임이나 영상에서 소리의 방향은 자막에 담기지 않는다.
시험에서 학생들이 방향을 가장 원했다는 서술은 이 선택이 사용자 요구에서 나왔음을
보여 준다.
다만 이 서술은 소개글에 있는 것이고 시험의 규모나 방법은 공개되어 있지 않다.

### 기기 안 추론이라는 선택

소리를 저장하거나 전송하지 않고 인터넷 권한도 두지 않았다는 점은
접근성 도구가 사용자의 소리 전부를 다루므로 중요한 설계다.
Android의 인터넷 권한 부재는 앱 정보에서 확인할 수 있는 항목이라 검증이 쉽다.

## 비평

### 분류 정확도의 근거

README는 위협음 판정의 규칙은 자세히 밝히지만 정확도 수치는 싣지 않는다.

환경음, 사람 소리, 위협음으로 나누는 분류가 얼마나 맞는지는 소개글에 수치가
없다.
개발팀도 분류가 틀리는 경우를 의견으로 요청하고 있어서, 정확도는 아직 열린
질문이다.
위협음 알림은 놓치는 것도 틀리게 알리는 것도 비용이 크므로,
공개된 평가 결과가 있어야 판단할 수 있다.

### 플랫폼별 제약

Windows는 게임을 창 모드나 테두리 없는 창 모드에서만 쓸 수 있고,
Android는 기기나 앱에 따라 소리를 못 받을 수 있다고 개발팀이 밝힌다.
전체 화면 독점 게임이나 오디오 캡처를 막은 앱에서는 쓸 수 없다는 뜻이다.

## 인사이트

### 사용자와 함께 시험한 개발 과정

세 명의 학생 개발팀이 실제 사용자와 세 번 시험하고 설정까지 바꾼 과정이
이 프로젝트의 가장 믿을 만한 부분이다.
접근성 도구는 만드는 사람의 상상보다 사용자의 걱정에서 요구가 나온다는 점을
오버레이의 시선 문제가 보여 준다.
