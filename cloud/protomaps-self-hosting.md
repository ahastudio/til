# Protomaps로 지도 타일 직접 호스팅하기

원문: [Protomaps: Self-hosting map tiles has gotten cheap and easy](https://bruceroettgers.eu/blog/protomaps/)

HN 토론: <https://news.ycombinator.com/item?id=50509837> (403점, 71개 댓글)

GN 토론: <https://news.hada.io/topic?id=37239>

## 소개

ETH Zurich의 컴퓨터 과학 학생 Bruce가 개인 블로그에 2026년 11월 15일 올린 4분짜리 안내 글이다.
글의 방법을 실행해 보거나 가격을 확인하지는 않았고, 숫자는 모두 글의 서술이다.
글은 필자의 프로젝트 Mapboard(여행 계획용으로 지도 위에 그리는 도구)를 만들며 찾은 방법이라고 한다.
이 문서는 사용자가 바로 따라 할 수 있는 순서와 판단 기준에 맞춰 정리했다.
글에서 Bunny.net 링크는 제휴 링크로 표시되어 있다.

## 동작 방식

PMTiles는 Protomaps 생태계의 타일 형식으로, 타일 전체를 파일 하나에 담고 HTTP Range 요청으로 필요한 부분만 읽는다.
그래서 타일 서버를 따로 돌리지 않고 파일 하나를 저장소 버킷에 올려 두면 된다.
Range 요청을 큰 파일에서 캐시할 수 있는 CDN이면 올리는 것 말고는 할 일이 없고, Cloudflare 같은 곳에서는 전통적인 x/y/z 경로를 Range 요청으로 바꿔 주는 엣지 함수를 쓴다고 글은 쓴다.
필자가 이 방법을 찾은 이유는 상용 API의 비용이다. Mapbox는 무료 구간을 넘으면 지도 1,000번 로드당 5달러를 받아, 비상업 프로젝트가 인기를 얻으면 감당하기 어렵다고 한다.

## 설정하기

글의 순서는 다섯 단계이다.

1. 지도 받기: 세계 지도만 필요하면 빌드 페이지에서 최신 일일 빌드를 내려받는다. CLI로 경계 상자나 특정 확대 수준만 추출하면 파일이 훨씬 작아진다.
2. 저장소 고르기: 필자는 Bunny.net을 쓴다. Range 요청을 지원하고, 기본적으로 개인정보를 수집하지 않으며(IP 주소 마지막 옥텟은 버림, 개인정보를 CDN으로 보내면 처리된다는 단서가 붙는다), 본사가 EU에 있고, 값이 싸다는 이유이다.
3. 파일 올리기: S3 호환을 켠 저장소 영역을 만든다. HTTP API로 올리면 15분 만에 시간 초과가 났기 때문이다. rclone을 설치해 내려받으면서 곧바로 저장소 영역에 스트리밍하고, 연결이 나쁘면 tmux나 임시 VPS에서 한다. 청크 크기는 256M로 두었다.
4. 풀 존 설정: 저장소 영역을 원본으로 하는 풀 존을 만든다. 허용 참조자를 설정해 다른 사이트가 타일을 끼워 넣지 못하게 하고, 큰 객체 전달 최적화를 켜서 Range 요청이 캐시되게 한다. 전체 파일을 내려받아 대금을 키우는 사람을 막으려면 한 요청에서 10MB가 넘으면 속도를 10kB/s로 제한하고, 초당 요청 수와 월 대역폭 제한을 둘 수 있다. 정상 사용은 이 한계에 닿지 않아야 하고, 정상 사용도 요청 수가 높아질 수 있다는 단서가 붙는다.
5. 지도 끼워 넣기: MapLibre GL에 pmtiles npm 패키지를 설치하고 프로토콜과 스타일을 공식 설치 안내대로 추가한다.

## 값 정하기

가격 계산의 근거는 이렇다.

- 대역폭: 유럽과 북미에서 GB당 0.01달러(작은 볼륨 네트워크는 0.005달러)이다.
- 저장: 복제 없음에서 최대 복제까지 GB당 월 0.01~0.055달러이다. 복제가 많을수록 캐시가 비었을 때의 지연이 줄어든다.
- 사례: 139GB 세계 지도를 5배 복제로 저장하면 월 약 5달러이다. 노트북에서 유럽 지도를 열고 도시로 확대하면 약 5MB가 전송되어 0.00005달러이고, 1,000번 로드가 0.05달러라면 Mapbox보다 100배 저렴하다고 한다. 다만 실제 대역폭은 달라서, 바로 떠나는 방문자는 덜 쓰고 많이 쓰는 방문자는 수십 MB를 쓸 수 있으며 Mapbox는 방문마다 고정 요금이라고 글이 단서를 붙인다.

## 함정

글이 직접 다루지 않고 HN 스레드에서 드러난 함정들이다.

- Range 요청이 깨지는 환경: 한 댓글은 회사의 악성코드 차단 프록시가 Range 헤더를 지우고 파일 전체를 요청해, 해당 고객을 위해 전통적인 타일 요청 방식(WMTS)의 프록시를 따로 만들어야 했다고 했다.[^gorayobi] 답글은 Cloudflare Workers로 /z/x/y 요청을 Range 요청으로 바꾸는 방식이 흔히 권장되고 공식 문서가 있다고 했다.[^wcedmisten]
- 위성 영상은 다르다: 한 댓글은 지도 바탕은 작아서 싸게 저장하지만 고해상도 위성 영상은 확대할수록 크기가 급증한다고 했다. 북미 위성 모자이크를 직접 만들었고 저장 용량 때문에 z17에서 멈췄으며 전 세계 고해상도는 수백 TB에 이른다고 했다.[^motoroco]
- 호스팅하면 손볼 일이 생긴다: 한 댓글은 Maptiler에 월 150유로가 빨리 나와 Protomaps로 옮겼고 호스팅 비용은 거의 없지만, 타일을 직접 호스팅하면 Tilemaker의 처리 스크립트와 지도 스타일을 끝없이 다듬게 된다고 했다.[^maelito] 답글은 호스팅 서비스가 푸는 핵심 문제는 타일을 최신으로 유지하는 일이라고 했다.[^omnimus]
- 지출 한도: 한 댓글은 Mapbox가 지출을 제한할 방법이 없어 공개 키가 남용되면 큰 청구서가 나올 수 있다는 점이 문제라고 했다.[^perks_12] 이는 글이 말하는 상용 API 비용 걱정과 같은 맥락이다.

## 대안과 비교

한 댓글은 OpenFreeMap이 비슷한 프로젝트라고 소개했다. 공개 인스턴스에 요청 수 제한이 없고 가입도 필요 없다는 것이다.[^boramalper]
답글들은 둘이 같지 않다고 했다. OpenFreeMap은 OpenMapTiles를 써서 출처 표시 요건이 더 엄격하고 MapTiler의 홍보가 따라붙으며,[^cube00] Protomaps는 어떤 지도 데이터 집합에도 쓸 수 있는 반면 OpenFreeMap은 OpenStreetMap 전용이라고 했다.[^oshawaconnectio]
한 사용자는 OpenFreeMap이 매주 공개하는 행성 전체 PMTiles 파일을 R2에 복사하고 작은 Worker로 서비스한다고 했다.[^bitbuilder]
또 다른 댓글은 VersaTiles도 함께 알아보라고 했다.[^sarkarghya]

## 비평

### 비용 비교는 단위가 다르다

글은 Mapbox의 방문당 고정 요금과 자신의 방식의 사용 대역폭 요금을 비교한다.
1,000번 로드가 5GB라는 계산은 한 방문이 5MB라는 가정 위에 서 있고, 글이 스스로 방문자마다 크게 달라진다고 밝힌다.
저장 비용 월 5달러도 일일 빌드를 얼마나 자주 다시 올리는지에 따라 달라지는데, 갱신을 어떻게 하는지는 글에 없다.
제휴 링크가 표시되어 있다는 점은 필자가 이 CDN을 추천하는 맥락으로 읽을 필요가 있다.

### 빠진 것은 갱신과 지원 범위다

글은 한 번 올리는 과정만 다루고 타일을 최신으로 유지하는 운영, Range 요청이 막히는 네트워크, 확대 수준과 위성 영상 같은 요구는 다루지 않는다.
스레드의 증언이 이 빈칸을 채운다.

### 외부 반응

Lobste.rs에는 도메인(`bruceroettgers.eu`)이 올라온 적이 없고, GeekNews 토픽의 유일한 댓글은 HN 의견을 다시 모은 요약이어서 GN 사용자의 반응은 없었다.

## 기억할 원칙

파일 하나를 저장소에 올리고 Range 요청으로 읽는 구조는 서버 없는 지도 서비스를 만든다.
그러나 이 구조의 비용은 전송량에 비례하고, 갱신과 방화벽 환경과 확대 수준 같은 운영 쪽 요구가 숫자로 드러나지 않는다.
따라 하기 전에 확인할 것은 세 가지이다.
지도를 얼마나 자주 갱신할지,
사용자 중 Range 요청을 막는 네트워크가 있는지,
위성 영상이 필요한지이다.
