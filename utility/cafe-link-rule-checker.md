# 카페 링크 규정 검사기: 맘카페·커뮤니티 32곳에 이 쇼핑몰 링크를 올려도 되는지 판정

## 소개

스튜디오 다해의 자료실이 무료로 연 웹 도구다.
카페나 커뮤니티 이름과 쇼핑몰 링크(또는 쇼핑몰 이름)를 넣으면, 그 카페에 그 링크를 올려도 되는지 알려 준다.
같은 쿠팡 링크라도 어떤 카페는 그대로 올릴 수 있고, 어떤 카페는 링크는 안 되지만 상품번호는 되고, 어떤 카페는 둘 다 안 되어 검색 안내 문구만 써야 한다.
카페마다 막아 둔 쇼핑몰이 달라서 매번 공지를 찾아봐야 하는 일을 줄이려는 도구다.

가입과 로그인이 필요 없고, 맘카페 17곳과 커뮤니티 15곳, 모두 32곳의 규정을 담았다.
이 규정 파일은 같은 곳에서 만드는 유료 도구 「원고도우미」가 쓰는 것과 같고, 그 가운데 링크 판정 부분만 떼어 무료로 열었다고 제작자가 소개했다.[^geeknews]
페이지에는 「원고도우미」 소개가 함께 붙어 있다.

도구가 알려 주는 것은 다음 여섯 가지다.

| 알려 주는 것        | 내용                                              |
| ------------------- | ------------------------------------------------- |
| 링크 그대로 올리기  | 카페에서 허용하는지                               |
| 상품번호로 바꾸기   | 링크에서 상품번호를 뽑아 줌                       |
| 검색 안내로만 쓰기  | 「OO에서 상품명 검색하면 나와요」 문구            |
| 올릴 수 없는 조합   | 예: 핫딜언니의 패밀리세일처럼 게시 자체가 막힌 곳 |
| 규정 출처와 확인일  | 공지 주소 또는 운영자 확인, 마지막 확인 날짜      |
| 피해야 할 말과 형식 | 금칙어, 줄인 주소·제휴 링크 경고, 제목·본문 형식  |

## 동작 방식

### 판정은 브라우저 안에서 규정 파일로 한다

페이지는 `링크규칙.js`라는 규정 파일을 불러와 판정한다.
이 파일은 사이트에서 그대로 내려받아 읽을 수 있고, 게시처 목록과 쇼핑몰 별칭, 판정 함수가 들어 있다.[^rules]
판정은 (카페, 쇼핑몰)의 두 가지 조합으로 정해진다.
같은 카페라도 카카오는 링크가 되고 쿠팡은 안 되는 식이다.

판정 함수는 위에서 아래로 다섯 가지를 차례로 본다.
먼저 모르는 카페나 빈 쇼핑몰이면 「모름」으로 돌려준다.
다음으로 게시불가 목록에 있는 조합이면 상품번호와 검색 안내로도 올릴 수 없다고 답한다.
그다음 카페의 금지 목록에 그 쇼핑몰이 있는지 본다.
금지가 아니면 허용이다.
금지인데 카카오, 알리, 오늘의집처럼 상품번호로 검색이 안 되는 쇼핑몰이면 검색 안내만, 나머지는 상품번호만 쓰라고 답한다.[^rules]

### 커뮤니티는 기본이 허용이고 맘카페는 목록에 따른다

커뮤니티는 링크를 그대로 넣는 것이 기본이고, 금지표에 적힌 개별 금지만 예외로 적용한다.
디시인사이드에서 쿠팡은 링크가 안 되고 상품번호만 된다.[^rules]
맘카페는 금지 목록에 적힌 쇼핑몰만 막힌다.
창원줌마렐라는 모든 링크를 금지하지만 상품번호는 허용하는 곳이라, 쿠팡은 상품번호로, 카카오는 검색 안내로 판정된다.[^rules]

### 입력한 링크는 판정에 쓰이고 서버로 가지 않는다

페이지 스크립트를 읽어 보면 판정을 위한 네트워크 요청이 없다.
`sendBeacon`이 호출되는 곳은 두 곳이다.
하나는 판정이나 「가기」 버튼을 누를 때 횟수만 세는 요청이고, 주소에 링크가 실리지 않는다.
다른 하나는 「규정이 바뀌었나요? 알려 주세요」 양식을 보낼 때이고, 여기에는 카페 이름과 적은 내용이 실린다.
제작자의 말대로 링크는 서버로 보내지 않고 사용 횟수만 센다는 설명이 코드와 맞는다.

## 확인하기

규정 파일은 공개되어 있으므로 판정 함수를 로컬에서 직접 돌려 볼 수 있다.
아래는 규정 파일을 내려받아 Node에서 같은 함수를 호출하는 스크립트다.
파일은 브라우저 전역 `window`와 `localStorage`를 쓰므로 최소한의 가짜 객체만 준다.

```bash
# 규정 파일을 별도 디렉터리에 받는다 (파일명은 한글이므로 퍼센트 인코딩)
mkdir -p cafe-check && cd cafe-check
curl -sL "https://wongo-personal.pages.dev/%EB%A7%81%ED%81%AC%EA%B7%9C%EC%B9%99.js" \
  -o rules.js
```

```javascript
const fs = require('fs'), vm = require('vm');
const store = {};
const win = {
  localStorage: { getItem: k => store[k] ?? null, setItem: (k, v) => { store[k] = v; } },
  addEventListener() {}, document: {},
};
win.window = win;
vm.runInNewContext(fs.readFileSync('rules.js', 'utf8'), win);
const R = win.링크규칙;

const L = R.목록();
console.log('게시처', L.length,
  '맘카페', L.filter(g => g.종류 === '맘카페').length,
  '커뮤니티', L.filter(g => g.종류 === '커뮤니티').length);

for (const [카페, 쇼핑몰] of [['맘홀', '쿠팡'], ['맘홀', '카카오'], ['맘홀', '네이버'],
    ['창원줌마렐라', '쿠팡'], ['핫딜언니', '패밀리세일'], ['디시', '쿠팡'],
    ['디시', '네이버'], ['없는카페', '쿠팡']]) {
  console.log(카페, '+', 쇼핑몰, '→', R.판정(카페, 쇼핑몰).결과);
}
console.log(R.상품번호뽑기('https://www.coupang.com/vp/products/1234567890?itemId=1'));
console.log(R.검색문구('카카오', '시그니앙 물티슈'));
```

이 스크립트를 실제로 돌린 출력은 다음과 같았다.

```text
게시처 32 맘카페 17 커뮤니티 15
맘홀 + 쿠팡 → 상품번호
맘홀 + 카카오 → 검색안내
맘홀 + 네이버 → 허용
창원줌마렐라 + 쿠팡 → 상품번호
핫딜언니 + 패밀리세일 → 게시불가
디시 + 쿠팡 → 상품번호
디시 + 네이버 → 허용
없는카페 + 쿠팡 → 모름
1234567890
카카오에서 시그니앙 물티슈 검색하면 나와요
```

게시처 32곳이 맘카페 17곳과 커뮤니티 15곳이라는 소개 글의 수치와 맞는다.
판정 결과도 위에서 설명한 규칙 순서와 같았다.
이 실험은 규정 파일의 함수가 위 입력에서 어떻게 답하는지를 보여 줄 뿐이고, 카페의 실제 공지가 그렇다는 것을 보여 주지는 않는다.

## 트레이드오프

### 한 곳에서 보는 편리함과 규정의 낡음은 맞바꾼다

이 도구는 카페마다 공지를 찾아보는 일을 한 화면으로 줄인다.
대가는 규정이 그 시점의 사본이라는 점이다.
규정 파일에는 게시처마다 출처와 확인 날짜가 적혀 있는데, 2026-10-27을 기준으로 계산하면 32곳 가운데 17곳은 확인 날짜가 비어 있고, 날짜가 있는 곳 중 4곳(맘홀, 몰테일, 핫딜언니, 정가거부)은 확인한 지 60일이 넘었다.
금지 규칙이 적힌 곳은 맘홀, 몰테일, 핫딜언니, 맘이베베, 짠돌이카페, 정가거부, 창원줌마렐라, 디시인사이드의 여덟 곳뿐이고, 맘카페 17곳 중 10곳은 금지가 없는 곳으로 적혀 있다.
금지가 없다는 기록과 규정을 확인하지 못했다는 기록은 이 파일에서 같은 모양이다.

### 맘카페 공지가 닫혀 있어서 운영자 확인에 기댄다

소개 글은 맘카페 공지가 회원에게만 보여서 실무에서 확인한 기준이라고 밝힌다.
그래서 이 규정은 공개된 공지로 검증할 수 없는 곳이 많다.
공개 공지가 있는 커뮤니티(뽐뿌, 디시인사이드 등)는 출처에 주소가 달려 있어 확인할 수 있다.
같은 도구 안에서 검증 가능한 규정과 검증할 수 없는 규정이 섞여 있다는 뜻이다.

## 함정

### 「허용」은 올려도 된다는 보증이 아니다

판정이 허용이면 이 도구의 규정에 금지가 적혀 있지 않다는 뜻이다.
페이지도 올리기 전에 그 카페 공지를 한 번 더 확인하라고 안내한다.
특히 위의 날짜 없는 17곳에서는 허용이 확인 결과가 아니라 기본값일 가능성이 있다.
이는 규정 파일의 구조에서 읽은 해석이고, 개별 카페에서 실제로 검증한 것은 아니다.

### 줄인 주소와 제휴 링크는 막지 않고 경고만 한다

규정 파일에는 줄인 주소, 수익 링크, 라이브 방송 상품 링크를 공지가 금지하는 곳에 경고 표시가 달려 있다.
이 경고는 판정 결과를 바꾸지 않고 주의 문구만 띄운다는 주석이 있다.
링크를 넣어도 된다는 판정과 이 경고가 함께 나올 수 있으므로 둘을 같이 읽어야 한다.

### 상품번호로 바꿀 수 있는지는 쇼핑몰마다 다르다

카카오, 알리, 오늘의집은 상품번호로 검색이 안 된다고 규정 파일에 적혀 있고, 이 세 곳은 금지되면 검색 안내 문구만 쓴다.
상품번호를 뽑는 함수가 모든 쇼핑몰의 링크를 알아본다는 보장은 이 노트가 확인하지 못했다.
위 실험에서는 쿠팡 링크만 시험했다.

## 비평

이 도구는 규정이 맞다는 가정 위에서만 쓸모가 있다.
소개 글은 규정이 자주 바뀌고 모르는 카페가 많다고 스스로 밝히고, 변경 제보를 받는 양식을 둔다.
그러나 제보는 제작자가 확인한 뒤 반영하는 구조라서, 사용자는 지금 판정이 최신인지 결과 화면의 확인 날짜로만 짐작할 수 있다.
날짜가 비어 있는 곳이 절반이 넘는다는 점은, 이 도구의 가장 중요한 값인 허용 판정이 가장 약한 근거 위에 있다는 뜻이다.

또 한 가지는 무료 도구와 유료 제품의 관계다.
같은 규정 파일을 쓰므로 무료 판정이 유료 제품의 품질을 대신 보여 주는 장점이 있다.
반면 규정을 고치는 일은 유료 제품의 필요에 따라 우선순위가 정해질 수 있다.
이 노트는 제작자의 갱신 습관을 관찰하지 못했고, 그런 일이 실제로 있는지는 판단하지 못한다.

## 체크리스트

- 카페 이름과 쇼핑몰이 규정 파일의 별칭에 있는가(모름이 나오면 공지를 직접 본다).
- 결과 화면의 확인 날짜가 있고 60일 이내인가.
- 허용 판정이어도 그 카페의 최신 공지를 올리기 전에 한 번 더 봤는가.
- 줄인 주소, 제휴 링크, 라이브 상품 경고가 함께 나왔는가.
- 검색 안내 판정이면 링크와 상품번호를 모두 뺐는가.
- 게시불가 판정이면 원고를 만들지 않았는가.
- 금칙어와 제목·본문 형식을 함께 확인했는가.

## 기억할 원칙

### 규정 판정기의 신뢰는 출처와 확인 날짜에서 나온다

판정 결과 자체보다 그 판정이 어디서, 언제 확인된 것인지가 쓸모를 정한다.
이 도구는 출처와 날짜를 결과에 같이 보여 주도록 만든 점이 장점이고, 그 칸이 비어 있는 곳에서는 판정을 참고로만 읽는다.

### 허용은 금지가 적혀 있지 않다는 뜻일 뿐이다

규정 목록에서 빠진 것은 허용되어서일 수도, 확인하지 못해서일 수도 있다.
두 경우를 가르는 것은 확인 날짜뿐이다.
