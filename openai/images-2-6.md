# Images 2.6: 생성 속도를 50% 높이고 GIF와 SVG와 복잡도 옵션을 더했다는 OpenAI의 이미지 모델 발표

원문: [Introducing Images 2.6 | OpenAI](https://openai.com/index/introducing-images-2-6/)

HN 토론: <https://news.ycombinator.com/item?id=50372945> (376점, 223개 댓글)

GN 토론: <https://news.hada.io/topic?id=36635>

## 요약

OpenAI가 2026년 11월 4일에 올린 제품 발표입니다.
Images 2.6을 ChatGPT, Codex, API에 내놓는다고 하며, 이미지를 더 빨리 만들고
편집을 거듭해도 인물과 제품과 브랜드의 세부를 일관되게 유지한다는 점,
GIF로 움직임을 더한다는 점을 앞세웁니다.
이 문서가 말하는 모든 성능은 OpenAI의 주장입니다.
같은 제품군의 앞선 발표는 [ChatGPT Images 2.5](chatgpt-images-2-5.md) 문서에
있습니다.

발표가 내세우는 내용은 다음과 같습니다.

- **규모**: 전 세계 사람들이 ChatGPT, Codex, API에서 매주 40억 장의 이미지를 만들고, 하루 평균 5억 장이 넘는다고 합니다.
- **속도와 모델**: 이전보다 50% 빠르게 만든다고 합니다. API에서는 GPT-Image-2.6 Flare와 Sunburst 중 고를 수 있습니다. Flare는 품질을 낮음으로 두면 6초 만에 만들 수 있고 포스터와 제품 이미지의 레이아웃 품질도 나아졌다고 하며, Sunburst는 품질을 중간이나 높음으로 두었을 때 더 높은 화질과 편집 사이의 일관성을 낸다고 합니다.
- **GIF**: 브랜드 마스코트, 소셜 반응과 밈, 영상 제작 전의 애니메이션 스토리보드에 쓸 수 있다고 하고, 손으로 그린 스케치에서 애니메이션 캐릭터를 만든 예를 보입니다. 예시 프롬프트는 6프레임을 3열 2행 격자로 배열한 단일 스프라이트 시트를 만들어 매끄럽게 반복되는 GIF로 쓰라는 내용입니다.
- **API 기능**: ChatGPT에 이미 있던 이미지 마크업(고칠 위치를 짚는 기능)이 API로 들어오고, 웹과 앱과 인쇄에 쓸 수 있는 SVG 내보내기가 추가됩니다. 새 `complexity` 매개변수는 모델이 요청을 맞추려고 하는 계획의 양을 조절하며, 품질 설정은 시각적 세부와 충실도를, 복잡도 설정은 장면에 얼마나 담을지를 가른다고 설명합니다. 대부분의 편집에는 낮은 복잡도를 권하고, 요소와 제약이 많은 장면에는 중간이나 높은 복잡도를 권합니다.
- **제공 범위**: ChatGPT와 Codex는 모든 구독 등급에서 데스크톱, 모바일, 웹으로 오늘부터 쓸 수 있고, API에는 Sunburst와 Flare가 있습니다. 가격과 안전 평가는 별도의 가격 페이지와 시스템 카드에 있다고 안내합니다. 이 문서는 가격 페이지와 API 문서를 열어 아래 절에서 대조했고, 시스템 카드는 열지 않았습니다.
- **인용된 사례**: OpenArt(GIF 예시와 CEO의 말), Town(업무 비서의 입력 중 표시 캐릭터), Figma Weave의 크리에이티브 디렉터, Picsart의 GTM 이사의 말이 실려 있고, 초기 접근 고객으로 Picsart, fal, Sable, Higgsfield가 언급됩니다.

## 공식 문서로 확인한 내용

이 절부터 분석 앞까지는 발표 글이 아니라 OpenAI의 개발자 문서를 대조한
결과입니다.
2026년 11월 6일에 이미지 생성 가이드[^guide-gen]와 이미지 프롬프트
가이드[^guide-prompt], 이미지 생성 API 레퍼런스[^ref-gen]와 이미지 편집 API
레퍼런스[^ref-edit], 두 모델 페이지[^flare][^sunburst],
가격 페이지[^pricing]를 열어 읽었습니다.
두 가이드는 길어서 일부를 요약본으로만 읽었고,
가이드의 비용 계산기 위젯과 예시 결과 이미지는 읽지 못했습니다.
`platform.openai.com`의 레퍼런스 주소는 403으로 열리지 않아
`developers.openai.com` 주소로 읽었습니다.
문서끼리 어긋나는 곳은 마지막 소절의 표에 모았습니다.

### 모델과 엔드포인트

두 모델의 이름은 `gpt-image-2.6-sunburst`와
`gpt-image-2.6-flare`입니다.[^flare][^sunburst]
모델 페이지는 Flare를 빠른 반복용 이미지 생성과 편집으로,
Sunburst를 세부가 중요한 시각 작업과 편집으로 소개합니다.[^flare][^sunburst]
입력은 텍스트와 이미지, 출력은 이미지이고,
기본 스냅샷은 모델 이름 자체이며 다른 스냅샷은 없습니다.[^flare][^sunburst]
2.5 두 모델에는 `2026-09-08` 날짜가 붙은 스냅샷 이름이 따로 있지만 2.6에는
없습니다.[^ref-gen]

모델 페이지는 엔드포인트 중 `v1/images/generations`와 `v1/images/edits`만
지원으로 표시합니다.[^flare][^sunburst]
`v1/responses`, Chat Completions, Batch,
Realtime은 지원하지 않음으로 표시됩니다.[^flare][^sunburst]
그런데 이미지 생성 가이드는 Responses API에서 이미지 생성 도구의 `model` 필드에
이미지 모델을 적는 방식을 설명하고, 그 예시는 2.5 모델 이름을
씁니다.[^guide-gen]
이 문서는 2.6 모델을 Responses API의 이미지 생성 도구에서 쓸 수 있는지 어느
페이지에서도 확인하지 못했습니다.
여러 번에 걸친 편집(multi-turn)은 가이드가 Responses API 기능으로 설명하므로,
2.6에서 이 방식이 되는지도 같은 이유로 확인되지 않습니다.[^guide-gen]

모델 페이지에는 컨텍스트 창, 최대 출력 토큰, 지식 기준일,
출시일이 없습니다.[^flare][^sunburst]
속도 제한은 사용 등급과 계정에 따라 다르다는 문장과 조직 한도 페이지 링크만 있고
표는 없습니다.[^flare][^sunburst]
가이드는 GPT Image 모델을 쓰려면 개발자 콘솔에서 API 조직 인증을 마쳐야 할 수
있다고 안내합니다.[^guide-gen]

갈아탈 때 걸리는 기본값이 둘 있습니다.
이미지 편집 레퍼런스에서 `model`을 생략하면 기본값은
`gpt-image-2.5-sunburst`입니다.[^ref-edit]
생성 레퍼런스는 모델을 명시적으로 지정하라고 적습니다.[^ref-gen]
2.6 모델에서 `complexity`를 생략하면 `high`가
적용됩니다.[^guide-gen][^guide-prompt]

`gpt-image-1`은 2026년 10월 23일에 종료되었다고 레퍼런스가 밝히고 후속으로 2.5
모델을 안내합니다.[^ref-gen]

### 요청 매개변수

두 엔드포인트의 요청 본문은 JSON으로 적혀 있습니다.[^ref-gen][^ref-edit]
아래 표는 레퍼런스의 값과 기본값, 가이드의 설명을 함께 정리한 것입니다.
한 곳에서만 확인된 값은 그 출처만 붙였습니다.

| 매개변수                   | 값과 기본값                                                                                 | 비고                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `prompt`                   | 필수, 최대 32,000자[^ref-gen][^ref-edit]                                                    | 편집에서는 최소 1자[^ref-edit]                                                                          |
| `n`                        | 1에서 10, 기본 1[^ref-gen][^ref-edit]                                                       | SVG는 `n`이 1이어야 함[^ref-gen]                                                                        |
| `size`                     | 기본 `auto`, 생성은 `1024x1024`, `1536x1024`, `1024x1536` 외에 레거시 크기도 열거[^ref-gen] | 편집의 열거는 앞의 세 개뿐[^ref-edit]                                                                   |
| 임의 `WIDTHxHEIGHT`        | 양 변이 16의 배수, 가로세로 비율 1:3에서 3:1, 최대 3840x2160[^ref-gen]                      | 가이드가 2.5 모델에 적은 총 픽셀은 655,360에서 8,294,400[^guide-gen], 2560x1440 초과는 실험적[^ref-gen] |
| `quality`                  | 기본 `auto`, `low`, `medium`, `high`, `xhigh`, `max`[^ref-gen][^guide-prompt]               | 생성의 열거에는 레거시 `standard`, `hd`도 있고 편집에는 없음[^ref-gen][^ref-edit]                       |
| `complexity`               | `low`, `medium`, `high`, 2.6 두 모델은 생략하면 `high`[^guide-gen]                          | 품질과 별개인 계획의 양[^ref-gen], 추가 요금 없음[^guide-gen]                                           |
| `background`               | `transparent`, `opaque`, `auto`, 기본 `auto`[^ref-gen]                                      | `transparent`는 `png`나 `webp`에서만[^ref-gen]                                                          |
| `output_format`            | `png`(기본), `webp`, `jpeg`, `gif`, `svg`[^ref-gen][^ref-edit]                              | `output_compression`은 `jpeg`와 `webp`에서만, 편집 레퍼런스는 0에서 100[^ref-edit]                      |
| `moderation`               | `auto`(기본), `low`[^ref-gen]                                                               | 오류 처리는 아래 한계 절 참조[^guide-gen]                                                               |
| `stream`, `partial_images` | `stream` 기본 false, `partial_images`는 0에서 3, 기본 0[^ref-gen]                           | 부분 이미지 하나마다 이미지 출력 토큰 100개가 더 듦[^guide-gen]                                         |
| `frame_count`              | GIF 전용, 2에서 16, 기본 9[^ref-gen]                                                        | GIF 미리보기 접근이 필요하다고 적혀 있음[^ref-gen]                                                      |
| `frame_duration_ms`        | GIF 전용, 최소 20, 기본 200, 10ms 단위로 반올림[^ref-gen]                                   | 가이드 표는 20에서 2000[^guide-gen]                                                                     |
| `svg`                      | `{ model, reasoning }` 객체, `output_format`이 `svg`일 때 씀[^ref-gen]                      | `svg.reasoning.effort`는 `none`부터 `max`까지의 값을 받음[^ref-gen]                                     |
| `images`(편집)             | 객체 배열, 1개에서 16개, 각각 `file_id` 또는 `image_url`[^ref-edit]                         | `image_url`은 URL이나 base64 데이터 URL[^ref-edit]                                                      |
| `markup`(편집)             | 첫 번째 이미지 위에 겹치는 투명 PNG, `mask`와 함께 못 씀[^ref-edit]                         | 첫 이미지와 크기가 같아야 함[^ref-edit]                                                                 |
| `mask`(편집)               | `image_url`과 `file_id` 중 정확히 하나[^ref-edit]                                           | 알파 채널이 필요하고 첫 이미지에 적용됨[^guide-gen]                                                     |
| `input_fidelity`(편집)     | 2.6 편집에서는 생략하라고 안내[^guide-prompt]                                               | 레퍼런스는 `gpt-image-2`에서 생략하라고 적음[^ref-edit]                                                 |
| `safety_identifier`        | 128자 이하, 사용자 단위의 안정적인 식별자[^ref-gen]                                         | 폐기된 `user`보다 우선함[^ref-gen][^guide-gen]                                                          |

응답에서 GPT 이미지 모델은 항상 base64를 돌려주므로 `response_format`과 `style`
같은 옛 매개변수는 쓸 수 없습니다.[^ref-gen]
응답 객체에는 `usage`(입력 토큰과 출력 토큰,
이미지와 텍스트 토큰의 세부)와 SVG 작성에 쓴 토큰을 따로 담는 `svg_usage`가
있습니다.[^ref-gen]
스트리밍에서는 생성이 `image_generation.partial_image`와
`image_generation.completed` 이벤트를, 편집이 `image_edit.partial_image`와
`image_edit.completed` 이벤트를 보냅니다.[^ref-gen][^ref-edit]
`revised_prompt`는 GPT 이미지 모델이 돌려주지 않습니다.[^ref-gen]

### 가격

모델 페이지와 가격 페이지의 표준 요금은 두 2.6 모델에서
같습니다.[^flare][^sunburst][^pricing]
이미지 입력은 100만 토큰당 8달러, 캐시된 이미지 입력은 2달러,
이미지 출력은 30달러입니다.[^pricing]
텍스트 입력은 5달러, 캐시된 텍스트 입력은 1.25달러입니다.[^pricing]
같은 표에서 2.5 두 모델과 `gpt-image-2`도 단가가 같습니다.[^pricing]
Batch 요금표에는 `gpt-image-2`와 2.5 두 모델의 행만 있고 2.6 행은
없습니다.[^pricing]

가이드는 같은 토큰 단가가 같은 이미지당 비용을 뜻하지 않으니 응답의 `usage`로
직접 재라고 안내합니다.[^guide-gen]
복잡도 조절에는 별도 요금이 없고, 마크업 편집은 다른 편집과 같은 토큰 요금이며
추가 요금이 없습니다.[^guide-gen]
SVG는 기준 이미지에 이미지 모델의 요금을 내고,
SVG를 쓰는 작성 모델이 쓴 토큰에는 그 모델의 요금을 냅니다.[^guide-gen]
캐시된 입력 단가는 GPT Image 2와 2.5의 경우 Responses API의 이미지 생성 도구에만
적용되고 `/v1/images/edits`를 포함한 Images API 직접 요청에는 적용되지 않는다고
합니다.[^guide-gen][^pricing]
2.6에 대해서는 이 문장이 따로 적혀 있지 않습니다.

이미지당 비용은 출력 토큰 수에 100만 토큰당 30달러를 곱하면 나옵니다.[^pricing]
아래 표는 사용자 보고와 블로그 작성자의 측정에서 읽은 토큰 수에 이 문서가 단가를
곱한 값이며, 1024x1024 이미지 한 장의 출력 비용입니다.

| 모델과 설정    | 출력 토큰   | 계산한 출력 비용 | 토큰 수의 출처                                  |
| -------------- | ----------- | ---------------- | ----------------------------------------------- |
| 2.5, 품질 낮음 | 196         | 약 0.0059달러    | HN 사용자의 보고[^bsboxe]                       |
| 2.5, 품질 중간 | 439         | 약 0.0132달러    | HN 사용자의 보고[^bsboxe]                       |
| 2.6, 품질 낮음 | 823에서 824 | 약 0.0247달러    | HN 사용자의 보고[^bsboxe][^bnmathm]             |
| 2.6, 품질 중간 | 1,449       | 약 0.0435달러    | HN 사용자의 보고[^bsboxe], 블로그의 측정[^suji] |
| 2.6, 품질 높음 | 1,756       | 약 0.0527달러    | 블로그의 측정[^suji]                            |
| 2.6, 품질 max  | 7,024       | 약 0.2107달러    | 블로그의 측정[^suji]                            |

계산한 값은 사용자가 가격 계산기에서 읽었다는 0.006달러, 0.013달러, 0.025달러,
0.043달러와 반올림 범위에서 맞습니다.[^bsboxe]
토큰 수는 모두 한 사람의 측정이고 공식 계산기는 읽지 못했으므로,
같은 설정에서 다른 토큰 수가 나올 수 있습니다.
2.5와 2.6의 단가가 같은데 이미지당 비용이 3배에서 4배가량 달라지는 원인은 토큰
수라는 점이 이 계산에서 드러납니다.
품질 `max`는 같은 크기에서 중간 품질의 5배 가까운 토큰을 쓴다고 블로그 작성자는
적었습니다.[^suji]
다만 레퍼런스는 `xhigh`와 `max`를 2.5 모델에만 지원한다고 적어서 2.6에서의
지원은 문서끼리 어긋납니다.[^ref-gen]

### GIF, SVG, 마크업

세 기능은 모두 Image API의 기능이며 Responses API가 아닙니다.[^guide-gen]

GIF는 `output_format`을 `gif`로 두면 생성과 편집에서 모두 만들 수 있다고
가이드가 설명합니다.[^guide-gen]
프롬프트에 움직임을 쓰고, 정지 이미지를 기준으로 삼으려면 편집 엔드포인트를
쓰라고 합니다.[^guide-gen]
`size`는 완성된 프레임 하나의 크기입니다.[^guide-gen]
프레임 수, 프레임 크기, 애니메이션 개수가 모델의 크기 한도와 요청 전체의 픽셀
예산에 들어와야 하고, 넘으면 `frame_count`나 프레임 크기나 `n`을 줄이라고
합니다.[^guide-gen]
이 한도의 숫자는 적혀 있지 않습니다.
스트리밍, 부분 이미지, 사용자 지정 압축,
`prompt_rewriter`와는 함께 쓸 수 없습니다.[^guide-gen]
레퍼런스는 마스크도 GIF와 함께 쓸 수 없다고 적습니다.[^ref-gen]
가이드의 표를 따르면 프레임 길이의 상한은 2000ms이므로,
16프레임에 2000ms면 32초가 이 문서가 계산한 이론상 최대 길이입니다.[^guide-gen]
기본값인 9프레임과 200ms면 1.8초입니다.[^ref-gen]
프롬프트 가이드의 GIF 예시는 9프레임, 프레임당 200ms, 512x512 크기,
높은 품질로 1.8초 길이이고, 출발 자세로 돌아오게 쓰고 카메라가 움직이는지
말하라는 조언이 붙어 있습니다.[^guide-prompt]

SVG는 생성 엔드포인트에서 `output_format`을 `svg`로 두고 `n`을 1로
둡니다.[^guide-gen]
가이드는 API가 먼저 기준 이미지를 만들고 그것으로 SVG를 만들며,
품질 설정이 그 기준 이미지를 조절한다고 설명합니다.[^guide-gen]
결과에는 스크립트, 외부 자원, 내장된 래스터 이미지가 없는 정적 벡터만 들어
있다고 합니다.[^guide-gen]
스트리밍, 부분 이미지, `output_compression`,
`prompt_rewriter`는 쓸 수 없습니다.[^guide-gen]
가이드는 편집 엔드포인트가 SVG 출력을 지원하지 않는다고 적지만,
편집 레퍼런스에는 `svg` 형식과 `svg` 객체가 있습니다.[^guide-gen][^ref-edit]
`svg.model`은 SVG 모델 선택 접근이 켜진 프로젝트에서 필수이고 아니면 객체를
생략합니다.[^ref-gen]

마크업은 편집 엔드포인트에서 원본 이미지를 첫 번째 입력으로 두고,
동그라미나 스케치를 담은 투명 PNG를 `markup`으로 보냅니다.[^guide-gen]
방향을 맞춘 뒤 두 이미지의 가로세로가 같아야 하고, 투명 픽셀이 있어야 하며,
원본 위에 합쳐 평평하게 만들면 안 됩니다.[^guide-gen]
첫 이미지와 주석 PNG는 각각 최대 16,777,216 픽셀이고 주석 파일은 50MB 한도가
있습니다.[^guide-gen]
`mask`나 `prompt_rewriter`와는 함께 쓰지 못합니다.[^guide-gen]
영역 편집이 필요한 Responses API에서는 마스크를 쓰라고 합니다.[^guide-gen]
마스크는 모델이 모양을 정밀하게 따르지 않을 수 있는 프롬프트 기반
안내입니다.[^guide-gen]

### 프롬프트 가이드가 말하는 쓰는 법

프롬프트 가이드의 기본 절차는 필요한 이미지에서 출발해 대상과 구도와 스타일과
제약을 쓰고, 편집에서는 바꿀 것과 지킬 것을 나누고,
한 번에 하나씩 다듬어 결과를 보라는 것입니다.[^guide-prompt]

#### 모델 고르기와 옮기기

응답 시간이 가장 중요하면 Flare로, 세부와 레이아웃과 편집 정확도에 까다로운
요구가 있으면 Sunburst로 시작하라고 합니다.[^guide-prompt]
이미 `gpt-image-2`나 2.5 Flare를 쓰고 품질이 충분하면 2.6 Flare를 시험하고,
`gpt-image-2`가 복잡한 작업에서 모자라거나 2.5 Sunburst를 쓰고 있으면 2.6
Sunburst를 시험하라고 합니다.[^guide-prompt]
Sunburst가 요구를 채우면 같은 프롬프트와 참조 이미지와 크기와 품질로 Flare를
다시 시험하라고 합니다.[^guide-prompt]
옮기는 절차는 여섯 단계입니다.[^guide-prompt]

1. 대표 프롬프트와 참조 이미지와 현재 모델의 출력을 기준선으로 저장합니다.
어려운 편집, 정확한 글자, 제품 형상, 투명 자산을 포함합니다.
2. 대응하는 모델을 먼저 시험합니다.
3. 첫 비교에서는 프롬프트, 참조 이미지, 크기, 품질,
출력 형식을 같게 두고 복잡도는 기본값으로 둡니다.
4. 글자, 레이아웃, 인물과 사물의 동일성,
편집에서 살아남아야 할 세부를 검사합니다. 연속 편집은 마지막 결과와 중간 결과를
모두 봅니다.
5. 품질과 복잡도 중 하나만 바꾸고, 각 요청을 반복해 합격 빈도와 시간을
비교합니다.
6. 새 모델이 기준을 만족하면 워크플로 단위로 일부 트래픽만 옮기고,
응답 시간과 실패와 재시도와 합격한 이미지당 비용을 추적합니다.

#### 프롬프트 기본 원칙 여덟 가지

가이드의 여덟 원칙을 이 문서의 말로 줄이면 다음과 같습니다.[^guide-prompt]

| 원칙                | 요지                                                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 결과를 정의한다     | 대상과 용도를 먼저 쓰고, 복잡한 요청은 장면, 대상, 세부, 제약의 라벨이 붙은 구역으로 나눈다[^guide-prompt]                       |
| 유지하기 쉬운 형식  | 짧은 글, 문단, JSON 비슷한 구조 중 요구를 읽고 고치기 쉬운 형식을 고르며 특별한 문법에 기대지 않는다[^guide-prompt]              |
| 눈에 보이는 세부    | 재질, 조명, 색, 매체를 쓰고 카메라 사양은 외관의 단서일 뿐 물리 시뮬레이션이 아니라고 본다[^guide-prompt]                        |
| 인물과 동작         | 몸이 어디까지 보이는지, 시선, 손이 사물과 맺는 관계를 구체적으로 쓴다[^guide-prompt]                                             |
| 정확한 글자         | 문구는 따옴표로 묶고 위치와 서체를 쓰고, 낯선 단어는 철자를 하나씩 쓰고, 불필요한 글자는 금지하고 결과를 검사한다[^guide-prompt] |
| 바꿀 것과 지킬 것   | 편집은 바꿀 한 가지를 말하고 지킬 세부를 나열하며, 워터마크 같은 제외 항목도 적는다[^guide-prompt]                               |
| 참조에 역할을 준다  | 입력마다 번호와 목적(대상, 스타일, 의상, 배경)을 붙이고 어떻게 합칠지 쓴다[^guide-prompt]                                        |
| 의도적으로 반복한다 | 이전 출력을 다음 편집의 입력으로 넣고 한 가지만 바꾸며, 지킬 세부를 다시 적는다[^guide-prompt]                                   |

복잡도에 대해 가이드는 설계 결정이 열려 있는 프롬프트에서는 높은 복잡도가 구도를
더 계획할 여지를 준다고 설명합니다.[^guide-prompt]
종이 공예풍 축구 팀 예시에서는 낮은 복잡도에서 트로피에 왕관이 올라가고,
높은 복잡도에서는 큰 배너가 관중석으로 옮겨 가 전경이 선수들에게 비워진다고
적습니다.[^guide-prompt]
레이아웃과 글자와 스타일이 이미 정해진 프롬프트에서는 복잡도를 올려도 눈에 띄는
차이가 적을 수 있고, 한 부분만 바꾸는 편집은 낮은 복잡도에서 시작하라고
합니다.[^guide-prompt]
복잡도를 비교할 때는 품질을 고정하고, 레이아웃은 맞는데 작은 글자가 읽기
어려우면 같은 복잡도에서 품질을 비교하라고 합니다.[^guide-prompt]
품질은 결과가 모자라면 올려 보고 충족하면 낮춰 보되,
`xhigh`와 `max`는 지연 예산 안에서 채워지지 않은 요구가 있을 때만 쓰라고
합니다.[^guide-prompt]

투명 자산에는 `background`를 `transparent`로 두고 `png`나 `webp`로 받고,
디코딩한 파일의 알파 채널을 머리카락과 유리와 그림자 가장자리까지 확인하라고
합니다.[^guide-prompt]
체커보드 무늬를 그린 이미지는 투명이 아니라고 짚습니다.[^guide-prompt]
일부 영역이 픽셀 단위로 같아야 하면 승인한 편집을 원본에 합성하라고
합니다.[^guide-prompt]

#### 공식 한계와 결과 검사

이미지 생성 가이드가 밝힌 한계는 네 가지입니다.[^guide-gen]
복잡한 프롬프트는 처리에 최대 2분이 걸릴 수 있습니다.
글자는 크게 나아졌지만 정확한 위치와 선명도에서 여전히 어려움이 있습니다.
반복 생성에서 인물이나 브랜드 요소의 일관성이 흔들릴 수 있습니다.
구조적이거나 레이아웃에 민감한 구성에서 요소를 정밀하게 놓기 어려울 수 있습니다.

콘텐츠 검열에 걸려 실패한 요청은 `error.type`이 `image_generation_user_error`일
수 있고, 프롬프트나 입력 이미지를 바꾸지 않은 채 자동으로 재시도하지 말라고
합니다.[^guide-gen]
프로그램에서는 `error.code`를 기준으로 가르고,
예시 코드는 `moderation_blocked`이며 검열 단계(`input`, `output`,
`unknown`)와 대분류 범주가 함께 옵니다.[^guide-gen]
일시적인 속도 제한과 서버 실패는 백오프로 재시도하고,
쿼터 오류는 재시도하지 않습니다.[^guide-gen]

결과를 쓰기 전의 검사 항목은 네 가지입니다.[^guide-prompt]
모든 글자를 읽을 수 있고 요청한 문구와 같은지,
다이어그램의 라벨과 관계가 맞는지 봅니다.
인물과 제품 형상과 라벨과 참조의 세부가 그대로인지 봅니다.
편집이 요청한 것만 바꾸었는지 봅니다.
투명이 필요하면 디코딩한 파일에 투명 픽셀이 있는지 봅니다.

### 문서끼리 어긋나는 곳

문서 일곱 곳을 대조하면서 서로 다르게 적힌 항목을 모았습니다.
어느 쪽이 맞는지는 이 문서가 API를 호출해 확인하지 않았으므로 정하지 않습니다.

| 항목                    | 한쪽의 서술                                                                      | 다른 쪽의 서술                                                                         | 이 문서의 판단                                                 |
| ----------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 편집의 SVG 출력         | 가이드는 편집 엔드포인트가 SVG 출력을 지원하지 않는다고 함[^guide-gen]           | 편집 레퍼런스의 `output_format`에 `svg`와 `svg` 객체가 있음[^ref-edit]                 | 가이드와 레퍼런스가 충돌함, 호출해 봐야 앎                     |
| 2.6의 `xhigh`와 `max`   | 프롬프트 가이드의 2.6 표는 품질 값에 이 둘을 포함함[^guide-prompt]               | 레퍼런스는 이 둘을 2.5 두 모델과 그 스냅샷에만 지원한다고 적음[^ref-gen]               | 레퍼런스 목록이 2.6을 아직 담지 못한 것일 수 있음              |
| 2.6의 임의 크기         | 프롬프트 가이드가 2.6 예시에서 `1536x864`와 16의 배수 규칙을 말함[^guide-prompt] | 레퍼런스가 임의 크기를 허용하는 모델로 `gpt-image-2`와 2.5 모델만 나열함[^ref-gen]     | 2.6에도 적용될 가능성이 높으나 레퍼런스에는 없음               |
| 마크업을 지원하는 모델  | 이미지 생성 가이드는 2.5와 2.6 모델이라고 하고 예시도 2.6 Flare를 씀[^guide-gen] | 편집 레퍼런스는 GPT Image 2.5를 지원한다고만 적음[^ref-edit]                           | 2.6에서 쓸 수 있다는 가이드 예시가 더 구체적임                 |
| GIF 프레임 길이의 상한  | 가이드 표는 20에서 2000밀리초[^guide-gen]                                        | 레퍼런스는 최소 20이고 인코딩된 지연의 상한을 65만 5,350밀리초로 적음[^ref-gen]        | 가이드의 범위가 사용 지침이고 레퍼런스는 인코딩 한계일 수 있음 |
| Responses API에서의 2.6 | 모델 페이지는 `v1/responses`를 지원하지 않음으로 표시함[^flare][^sunburst]       | 가이드는 이미지 생성 도구의 `model` 필드로 이미지 모델을 지정한다고 설명함[^guide-gen] | 2.6이 도구 모델로 되는지는 확인되지 않음                       |
| 편집의 기본 모델        | 편집 레퍼런스의 `model` 기본값은 `gpt-image-2.5-sunburst`임[^ref-edit]           | 발표와 가이드는 2.6을 최신으로 소개함[^guide-gen]                                      | `model`을 생략한 편집은 2.6이 아님                             |

### 문서의 매개변수로 구성한 요청 예시

아래 예시는 위의 매개변수 표에 맞추어 이 문서가 구성한 것이고,
실행해 보지 않았습니다.
프롬프트 문장은 이 문서가 새로 쓴 것이며 공식 예시가 아닙니다.
`$OPENAI_API_KEY`와 파일 이름은 자리 표시입니다.

GIF는 JSON 본문으로 생성 엔드포인트에 보냅니다.
이 요청은 GIF 미리보기 접근이 있어야 하고,
9프레임에 프레임당 200ms이므로 1.8초 길이입니다.

```bash
curl https://api.openai.com/v1/images/generations \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2.6-sunburst",
    "prompt": "작은 로봇이 화분에 물을 주고 처음 자세로 돌아온다. 카메라는 고정하고 매끄럽게 반복되게 한다.",
    "output_format": "gif",
    "size": "512x512",
    "quality": "high",
    "frame_count": 9,
    "frame_duration_ms": 200
  }' | jq -er '.data[0].b64_json' | base64 --decode > robot.gif
```

마크업 편집은 원본과 같은 크기의 투명 PNG를 `markup`으로 함께 보냅니다.
`mask`나 `prompt_rewriter`는 보내지 않습니다.

```bash
curl https://api.openai.com/v1/images/edits \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -F model=gpt-image-2.6-flare \
  -F quality=medium \
  -F 'image=@room.webp;type=image/webp' \
  -F 'markup=@circle-overlay.png;type=image/png' \
  -F 'prompt=원 안의 의자만 같은 모양의 나무 의자로 바꾸고 나머지는 그대로 둔다. 원은 결과에서 지운다.' \
  | jq -er '.data[0].b64_json' | base64 --decode > room-edited.png
```

SVG는 `n`을 1로 두고 `svg` 객체를 함께 보냅니다.
`svg.model`에 넣을 값은 계정이 SVG 모델 선택 접근을 받았을 때 알려지므로 자리
표시로 두었습니다.

```json
{
  "model": "gpt-image-2.6-flare",
  "prompt": "동네 서점의 단순한 로고. 책 한 권과 나뭇잎을 쓰고 평평한 색 두 가지만 쓴다.",
  "output_format": "svg",
  "n": 1,
  "quality": "medium",
  "svg": { "model": "<SVG를 작성할 모델 이름>" }
}
```

모델을 옮길 때의 비교 실험은 다음 표 같은 기록지로 시작할 수 있습니다.
프롬프트와 크기와 품질은 고정하고 복잡도만 바꿉니다.
출력 토큰은 응답의 `usage`에서 옮겨 적습니다.

| 실험 | 모델                     | 크기      | 품질   | 복잡도 | 시간(초) | 출력 토큰 | 합격 |
| ---- | ------------------------ | --------- | ------ | ------ | -------- | --------- | ---- |
| E1   | `gpt-image-2.6-flare`    | 1024x1024 | medium | low    |          |           |      |
| E2   | `gpt-image-2.6-flare`    | 1024x1024 | medium | medium |          |           |      |
| E3   | `gpt-image-2.6-flare`    | 1024x1024 | medium | high   |          |           |      |
| E4   | `gpt-image-2.6-sunburst` | 1024x1024 | medium | low    |          |           |      |
| E5   | `gpt-image-2.6-sunburst` | 1024x1024 | medium | medium |          |           |      |
| E6   | `gpt-image-2.6-sunburst` | 1024x1024 | medium | high   |          |           |      |

합격한 이미지당 비용은 시도한 모든 요청의 비용을 합격한 장 수로 나눈 값입니다.
예를 들어 높은 품질(1,756토큰)로 10번 시도해 3장이 합격하면 비용은 약
0.527달러이고 합격당 약 0.176달러입니다.[^suji]
중간 품질(1,449토큰)로 10번 시도해 2장만 합격하면 비용은 약 0.435달러이고 합격당
약 0.217달러입니다.[^suji]
합격 장 수는 이 문서가 든 가정이며 측정값이 아닙니다.
이 계산은 합격률이 낮은 설정이 단가가 낮아도 더 비쌀 수 있다는 점을 보여 줍니다.


## 분석

### GIF는 한 장의 이미지 안의 프레임들로 만들어지는 것으로 읽힌다

예시 프롬프트는 정확히 6개의 연속 프레임을 3열 2행 격자에 같은 크기로 배치한
단일 스프라이트
시트를 요구하고, 마지막 프레임이 첫 프레임으로 매끄럽게 이어지게 하라고 합니다.
이는 이 문서의 추정이지만, 이 방식이면 GIF의 길이와 프레임 수가 한 장의
이미지에 담기는
칸 수로 제한되고 영상 모델이 아니라 이미지 모델이 만드는 움직임입니다.
발표 페이지는 GIF의 길이, 프레임 수, 해상도, 파일 크기 한도를 적지 않습니다.
API 문서는 프레임 수와 프레임 길이의 범위를 정해 두었지만,
프레임이 어떤 방식으로 만들어지는지는 적지 않았습니다.[^ref-gen][^guide-gen]
파일 크기 한도는 어느 문서에도 없었습니다.

Hacker News의 사용자 minimaxir는 격자로 프레임을 만드는 방식이 ChatGPT만의 것이
아니고 이미 알려진 방법이라고 적었습니다.[^minimaxir]
같은 사용자는 프레임 사이의 일관성을 맞추기가 대체로 어렵고,
발표의 예시에서도 프레임 사이에 잡음이 보인다고 보고했습니다.[^minimaxir]
이것은 발표의 주장이 아니라 사용자의 관찰이며,
그는 잡음이 압축 때문일 수도 있다고 덧붙였습니다.[^minimaxir]

vunderba는 GIF 기능을 직접 써 보고 기대는 높지 않았지만
만들어 낼 수 있다는 것 자체가 놀라웠다고 적었습니다.
그래도 영상 모델로 첫 프레임과 마지막 프레임을 주는 방식이
더 나은 결과를 낼 것이라고 보았고,
마지막 예시는 눈 속에 든 허스키 사진을 움직이는 GIF로 바꾼 것이었습니다.[^vunderba-gif]
minimaxir는 단순한 체스 애니메이션에도 얼룩이 보여서
이 GIF 기능은 쓸 수 없다고 답했습니다.[^minimaxir-2]
둘 다 한 사람의 시험이며 발표의 주장과 겹치지 않는 관찰입니다.

### 품질과 복잡도가 서로 다른 두 조절 장치다

발표는 품질을 시각적 세부와 충실도, 복잡도를 모델이 쓰는 계획의 양으로
구분합니다.
낮은 복잡도로 빠르게 편집하고 품질은 작업에 필요한 만큼 두라는 권고는,
속도와 정확도를 한
축에서 고르지 않고 두 축에서 따로 고르게 한 설계를 보여 줍니다.
모델도 Flare와 Sunburst로 속도 쪽과 정확도 쪽으로 나뉘어 있어,
개발자는 모델 선택과 두
매개변수의 조합으로 비용과 지연을 맞추게 됩니다.

API 문서가 덧붙이는 사실이 둘 있습니다.
두 모델 모두 `complexity`를 생략하면 `high`가 적용되고, 이 설정에는 별도 요금이 없습니다.[^guide-gen]
발표가 편집에 권하는 낮은 복잡도는 기본값이 아니어서 직접 골라야 합니다.[^guide-gen]
문서는 높은 복잡도가 지연을 늘리고 원치 않는 변경을 낳을 수 있으니 작업별로 비교하라고 안내합니다.[^guide-gen]

### 사용 규모와 사용처가 마케팅과 제작 흐름을 겨냥한다

앞선 2.5 발표 문서가 주당 30억 장 이상을 적었으므로 이번 40억 장은 두 달 사이의
증가로 제시됩니다. 2.5 발표는 9월 8일이었습니다. 두 숫자는 서로 다른 발표의 자체
집계이고 정의가 같은지는 알 수 없습니다.
GIF의 사용처로 든 마케터와 창작자, 마스코트, 소셜 반응,
스토리보드와 파트너 인용(OpenArt,
Figma Weave, Picsart)은 이 모델이 제작 도구의 한 단계로 쓰이도록 겨냥되었음을
보여 줍니다.

### 이미지 모델이 따로 있는 이유

bananaflag는 GPT-6 계열이 멀티모달이면 왜 이미지 모델이 따로 있느냐고
물었습니다.
armcat은 멀티모달이 맞지만 효율의 문제이며,
이미지 생성만 훈련한 모델은 범용 멀티모달 모델보다 작고 빠르고
고유한 최적화 기법이 있다고 답했습니다.
음성 모델도 마찬가지라고 덧붙였습니다.[^armcat]
tredre3은 GPT-6가 입력만 멀티모달이고 출력은 아니며,
이미지는 스스로 이미지 모델을 불러서 만든다고 적었습니다.[^tredre3]
두 설명 모두 사용자의 답이며 발표에는 이 구조에 대한 말이 없습니다.
발표가 제품 이름을 Images 2.6이라는 독립된 모델로 낸 것은
이 설명과 맞지만, 이 문서는 내부 구조를 확인하지 못했습니다.

## 비평

### 속도 수치의 기준이 없다

50% 빠르다는 말은 이전 무엇보다 빠른지를 적지 않았고,
6초는 품질을 낮음으로 둔 Flare의
가장 짧은 경우를 가리키는 표현입니다.
비교 영상도 8배속 재생과 사치 여행 광고라는 단일 프롬프트 한 건입니다.
품질별, 해상도별, 복잡도별 지연 분포는 발표에 없습니다.

사용자 bnmathm은 자기 작업 흐름에서 1024x1024 이미지를 직접 재어 표로
올렸습니다.[^bnmathm]
이 보고에서 2.5 중간 품질은 12.0초, 2.6 낮은 품질은 6.7초,
2.6 중간 품질은 7.9초, 2.6 높은 품질은 8.9초가 걸렸습니다.[^bnmathm]
6초대라는 발표의 숫자는 낮은 품질에서 나오지만,
같은 보고에서 2.6 낮은 품질은 토큰이 824개이고 이미지당 비용이 0.025달러로 2.5
중간 품질의 439개와 0.014달러보다 큽니다.[^bnmathm]
이것은 한 사용자의 측정이므로 일반적인 지연 분포로 읽을 수 없습니다.

공식 문서는 지연에 대해 복잡한 프롬프트가 처리에 최대 2분이 걸릴 수 있다는 말 외에 숫자를 주지 않습니다.[^guide-gen]
두 모델 페이지에도 지연 수치나 속도 제한 표가 없습니다.[^flare][^sunburst]
블로그 오늘도 공부의 작성자는 같은 프롬프트를 세 번씩 돌린 결과를 적었습니다.[^suji]
Flare의 평균은 9.9초(중앙값 11.1초), Sunburst의 평균은 26.2초(중앙값 26.6초)였고, 작성자는 이를 공식 성능 수치가 아니라고 밝혔습니다.[^suji]
앞의 bnmathm 보고는 모델을 밝히지 않은 채 2.6의 품질별 시간으로 6.7초에서 8.9초를 적어,
두 측정은 모델과 프롬프트와 크기가 같다고 볼 수 없어 서로 맞출 수 없습니다.[^bnmathm][^suji]

### 일관성과 정확도의 측정이 없다

인물과 제품과 브랜드의 세부를 편집 사이에 일관되게 유지한다는 핵심 주장에는
수치도 평가
방법도 없고, 근거는 고객의 인용과 데모입니다.
인용을 한 회사는 모두 이 모델을 서비스에 붙이는 제휴 업체입니다.
OpenAI는 안전 평가를 시스템 카드로 돌리지만,
성능과 일관성의 비교 평가는 안내하지
않습니다.

### 시연이 요구하는 프롬프트가 매우 조밀하다

예시 프롬프트는 프레임 수, 격자 배치, 같은 크기, 카메라 고정,
문자와 로고와 말풍선과
테두리의 금지까지 길게 명시합니다.
이 정도 제약을 쓴 프롬프트가 안정적으로 같은 결과를 내는지,
보통의 짧은 프롬프트에서는
얼마나 어긋나는지는 발표에서 알 수 없습니다.

사용자 nashadelic은 발표 영상에서 복잡도를 설명하는 대목의 고양이 이미지가 낮은
복잡도와 중간 복잡도에서 팔다리가 더 많게 나온다고 지적했습니다.[^nashadelic]
이것은 영상을 본 사용자의 지적이며, 발표가 그 결과를 어떻게 골랐는지는 이
문서에서 확인할 수 없습니다.

### SVG와 가격은 설명이 비어 있다

SVG 내보내기가 인쇄에도 쓸 수 있다고 하지만,
이미지 모델이 벡터를 직접 만드는지 래스터
이미지를 벡터화하는지, 복잡한 이미지에서 품질이 어떤지는 적지 않았습니다.
API 가격은 링크로만 안내되어 있어서 Flare와 Sunburst와 복잡도 설정에 따른
비용 차이는
이 발표만으로 알 수 없습니다.

사용자 minimaxir는 OpenAI 문서를 인용해,
SVG 출력이 이미지 모델이 벡터를 직접 만드는 방식이 아니라 먼저 기준
이미지(reference image)를 만들고 그것으로 SVG를 만드는 방식이라고
적었습니다.[^minimaxir]
품질 설정이 그 기준 이미지를 조절한다는 설명도 같은 인용에 있습니다.[^minimaxir]
이는 위에서 발표가 비워 둔 질문에 대한 사용자의 답이고,
이 문서가 연 이미지 생성 가이드에도 같은 설명이 있습니다.[^guide-gen]
사용자 vunderba는 SVG를 만들 때 `svg.model` 매개변수로 별도의 언어
모델을 지정해야 하며, 없으면 400 오류가 난다고 보고했습니다.[^vunderba]
그는 이 매개변수가 문서에 없다고 보았지만, 이 문서가 연 API 레퍼런스에는 있습니다.[^ref-gen]
레퍼런스는 SVG 모델 선택 접근이 켜진 프로젝트에서 이 값이 필수이고, 켜지지 않았다면 객체를 생략하라고 적습니다.[^ref-gen]
그는 Sunburst에 gpt-5.5와 gpt-5.6-sol을 각각 지정해 시험했고 결과가 대단하지
않았으며, ChatGPT에서 기존 이미지를 SVG로 바꿔 달라고 하면 되던 수준이라고
평가했습니다.[^vunderba]
가격에 대해서는 사용자 bsboxe가 토큰당 단가는 2.5와 같지만 OpenAI의 이미지 가격
계산기에서 1024x1024 낮은 품질이 196개에서 823개 토큰으로,
중간 품질이 439개에서 1449개 토큰으로 늘어난다고 보고했습니다.[^bsboxe]
같은 보고에서 이미지당 비용은 낮은 품질이 0.006달러에서 0.025달러로,
중간 품질이 0.013달러에서 0.043달러로 오르고,
높은 품질은 토큰 수가 달라지지 않습니다.[^bsboxe]
이 숫자는 사용자가 가격 계산기에서 읽은 값입니다.
이 문서는 계산기를 읽지 못했지만, 가격 페이지의 이미지 출력 단가(100만 토큰당 30달러)에 토큰 수를 곱하면 같은 값이 나옵니다.[^pricing]
자세한 계산은 위의 가격 절에 있습니다.

### 사용자들이 보고한 결과와 한계

아래는 발표의 주장이 아니라 Hacker News에서 사용자들이 직접 써 보고 남긴
보고입니다.
각 보고는 한 사람의 시험이며, 이 문서가 재현한 것은 없습니다.

사용자 jjcm은 프롬프트로 디자인을 만드는 자기 사이트에서 2.6 Flare를 한 시간쯤
시험한 뒤 2.5 Flare로 되돌렸다고 적었습니다.[^jjcm]
그는 2.6 Flare가 접근을 지나치게 단순하게 하거나 결과물이 깨지는 경우가 있었고,
2.6 Sunburst는 괜찮았다고 보고했습니다.[^jjcm]
이는 발표의 속도와 레이아웃 개선 주장과 반대되는 방향의 사용 경험입니다.
사용자 neom은 시계 수리공의 손과 물방울과 굴절을 길게 지정한 자신의 표준
프롬프트로 시험해, 이미지 생성 2.0보다 결과가 훨씬 나빴다고 보고했습니다.[^neom]
같은 보고에서 ChatGPT 웹 앱이 어떤 이미지 모델과 노력 수준을 쓰는지는 표시되지
않는다는 점은 다른 사용자 minimaxir의 지적이므로,
웹 앱 시험의 모델 조건은 불확실합니다.[^minimaxir]
편집 사이의 일관성에 대해서는 사용자 p0larboy가 일관된 스프라이트 시트(sprite
sheet) 그림을 만들려고 4시간을 썼지만 성과가 없었다고 적었습니다.[^p0larboy]
이는 일관성 개선이라는 발표의 주장을 한 건의 실패 사례로 시험한 보고입니다.

제공 범위에 대해서는 사용자 dllu가 codex-cli를 최신으로 올렸는데도 GIF를 만들 수
없었다고 보고했습니다.[^dllu]
사용자 schneehertz는 codex-cli가 쓰는 모델이 아직 gpt-image-2라고 적고 저장소의
코드 위치를 링크했습니다.[^schneehertz]
발표는 Codex에서 오늘부터 쓸 수 있다고 하지만,
이 두 보고는 그 시점에 Codex 명령줄 도구에서 되지 않았음을 보여 줍니다.

### 화풍에 대한 불만은 발표가 다루지 않는다

E-Reverance는 결과물이 여전히 눈에 거슬린다며
제품을 만드는 엔지니어들이 그것을 알아채지 못하는지 궁금하다고 적었습니다.[^E-Reverance]
samuria는 이런 결정이 HN 사용자를 만족시키려는 것이 아니고,
수치상 평균 사용자는 사람이 만든 것과 AI가 만든 것을 구별하지 못해
인공지능 특유의 화풍을 신경 쓰지 않는다고 반박했습니다.[^samuria]
이 수치는 댓글 작성자의 주장이고 근거가 제시되지 않았습니다.
발표는 속도, 일관성, 편집을 말할 뿐 화풍을 개선했다고는 말하지 않으므로,
이 논쟁은 발표의 주장과 직접 부딪치지 않고 발표가 말하지 않은 영역에 있습니다.

### 진전의 크기를 두고 의견이 갈린다

preommr은 이미지 생성이 정체했다고 느끼며,
코딩은 크게 나아졌는데 이미지는 오히려 뒷걸음쳤다고 적었습니다.
초기 Midjourney와 Stable Diffusion과 편집용 Nano Banana 계열에서
정점을 찍었다는 것이 그의 인상입니다.[^preommr]
JohnQPulp은 Nano Banana Pro 이후 진전이 비교적 평평하다고 볼 수 있지만,
그 모델이 복잡한 편집에서도 시각적 일관성을 온전히 유지한 첫 모델이었고
GPT 쪽도 화풍은 아쉬워도 꾸준히 나아지고 있다고 반박했습니다.[^JohnQPulp]
일관성을 앞세운 발표의 핵심 주장이 이미 다른 모델에서 달성된 것이라는 주장이므로,
이 문서가 확인하지 못한 경쟁 모델과의 비교가 이 주장을 가르는 근거가 됩니다.

## 인사이트

### 1. 자기 작업 몇 개로 지연과 비용을 직접 잰다

발표의 속도 수치는 조건이 좁아서, 쓰려는 작업 대여섯 개를 품질 낮음,
중간, 높음과
복잡도 낮음, 중간, 높음의 조합으로 돌려 지연과 비용과 결과를 비교하는 것이
가장 빠른
판단 방법입니다.
단가는 위의 가격 절에 정리했으므로, 이미지당 비용은 응답의 `usage` 토큰 수에 단가를 곱해 직접 재 봅니다.[^pricing]

### 2. 편집 사이의 일관성은 여러 회차로 시험한다

핵심 주장이 일관성이므로, 같은 캐릭터나 제품을 다섯 번 이상 연속으로
편집해 세부가
유지되는지 눈으로 확인합니다.
브랜드 자산에 쓸 계획이라면 이 시험을 도입 전에 합니다.

### 3. GIF가 필요하면 스프라이트 시트 방식의 한계를 먼저 본다

발표의 예시를 따라 격자 프레임을 요구하는 프롬프트로 시험하고,
반복 이음매와 프레임 수의
한계, 파일 크기를 확인한 뒤 영상 도구와 비교합니다.

### 4. 기본값이 새 모델을 가리키지 않는 곳을 먼저 찾는다

이미지 편집 레퍼런스에서 `model`의 기본값은 2.5 Sunburst입니다.[^ref-edit]
그러므로 모델 이름을 적지 않은 편집 요청을 두고 2.6으로 옮겼다고 말할 수 없습니다.
2.6에서 `complexity`의 기본값은 `high`이고, 발표가 편집에 권하는 `low`는 직접 지정해야 합니다.[^guide-gen]
레퍼런스의 응답 객체 필드 목록에는 `quality`, `size`, `output_format`은 있지만 `model`과 `complexity`는 없습니다.[^ref-gen]
따라서 어떤 설정으로 돌았는지는 응답에서 되짚을 수 없고, 요청에 쓴 값을 호출한 쪽이 기록해 두어야 합니다.
갈아타는 호출은 모델, 복잡도, 품질, 크기를 모두 명시하고 그 값을 결과와 함께 남기는 것이 가장 간단한 안전장치입니다.

### 5. 합격한 이미지당 비용으로 모델과 설정을 비교한다

프롬프트 가이드가 옮길 때 추적하라고 한 것은 응답 시간과 실패와 재시도와 합격한 이미지당 비용입니다.[^guide-prompt]
이미지당 단가는 모델과 품질에 따라 토큰 수가 달라져 정해지고, 2.5와 2.6의 토큰 단가가 같아도 이미지당 비용은 3배에서 4배 달라질 수 있습니다.[^pricing][^bsboxe]
그래서 단가가 낮은 설정이 항상 싸지는 않습니다.
합격률이 낮으면 같은 합격 한 장을 얻는 데 더 많은 시도가 들기 때문입니다.
위의 비교 기록지에서 시간과 출력 토큰과 합격 여부를 같이 적고, 합격 장 수로 총 비용을 나누어 보면 모델 선택이 취향이 아니라 숫자가 됩니다.

### 6. 이 발표에 대한 판단을 바꿀 관찰

모델 간 비교 평가나 독립 기관의 일관성 측정이 공개되거나,
가격이 확인되어 같은 품질당 비용이
경쟁 모델과 비교되면 주장이 강해지거나 약해집니다.
GIF의 길이와 해상도 한도가 공개되면 쓸 수 있는 범위가 정해집니다.
문서끼리 어긋나는 일곱 항목이 해소되고, 모델 페이지가 Responses API 지원 여부와 컨텍스트와 속도 제한을 채우면
이 문서의 정리 중 확인되지 않은 부분이 줄어듭니다.
