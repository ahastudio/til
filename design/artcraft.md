# ArtCraft: 프롬프트 대신 장면을 구성해 AI 이미지와 영상을 만드는 스튜디오

<https://getartcraft.com/>

<https://github.com/storytold/artcraft>

Show HN: [ArtCraft AI crafting engine, written in Rust](https://news.ycombinator.com/item?id=46857596) (2점, 2개 댓글)

## 소개

ArtCraft는 AI 이미지와 영상 생성을 위한 데스크톱 스튜디오다.
홈페이지는 Controllable AI for Artists라는 제목 아래 아티스트를 위한 쓸 만한
도구를 표방하고, 저장소의 README는 스스로를 아티스트를 위한 IDE라고 부른다.
핵심 주장은 텍스트 프롬프트만으로는 아티스트가 원하는 통제를 얻을 수 없으니,
사용자가 장면을 직접 구성하고 모델은 그것을 렌더링하게 하자는 것이다.
홈페이지의 문구로는 말로는 살 수 없는 통제를 준다는 것이다.

같은 팀이 2026년 10월 초에 내놓은 Crafting Apps는 Adobe 제품을 Rust로 다시
만드는 별개의 제품군이다.
이 저장소의 `design/artcraft-apps.md`가 그쪽을 다루고,
이 문서는 회사 이름이기도 한 본체 ArtCraft를 다룬다.

| 항목                 | 내용                                                   |
| -------------------- | ------------------------------------------------------ |
| 플랫폼               | macOS 12 이상, Windows 10 64비트 이상, 웹 앱           |
| 최소 사양            | 권장 RAM 8GB, 저장 공간 2GB                            |
| 최신 릴리스          | v0.41.0, 2026년 9월 26일                               |
| 언어                 | Rust와 TypeScript, 데스크톱은 Tauri                    |
| 저장소 생성          | 2022년 3월                                             |
| 2026년 10월 7일 스타 | 3,698                                                  |
| 라이선스             | 자체 작성한 페어 소스(fair source) 라이선스, 초안 상태 |

저장소에는 데스크톱 앱, 서버, 웹사이트 코드가 함께 들어 있는 모노레포라고
개발자는 설명한다.
채용 공고에 따르면 서비스와 데스크톱 앱은 Rust로 작성되었고,
데스크톱 셸은 지금 Tauri를 쓰지만 Bevy로 완전한 네이티브 UX를 만드는 데 관심이
있다.[^echelon-hiring]
서비스는 Actix Web과 SQLx를 쓴다.

## 주요 기능

### 장면을 먼저 만들고 생성한다

README는 기능을 두 부류로 나눈다.
첫째는 Show, Don't Tell이라는 이름의 고급 구성 기능이고,
둘째는 빠른 프롬프트 기능이다.

| 기능                 | 하는 일                                                       |
| -------------------- | ------------------------------------------------------------- |
| Image to Location    | 가상 배우를 일관된 환경에 두고 같은 방에서 여러 숏을 계획한다 |
| 3D Image Compositing | 배경, 전경, 소품을 3D로 겹쳐 깊이가 있는 구성을 만든다        |
| 2D Image Compositing | 이미지 레이어, 배경 제거, 그리기 도구로 장면을 구성한다       |
| Image to 3D Mesh     | 이미지를 3D 오브젝트로 바꿔 위치와 각도를 정확히 잡는다       |
| Character Posing     | 최종 생성 전에 캐릭터 포즈와 카메라를 정한다                  |
| Scene Blocking       | 3D 에셋 키트를 조합해 카메라 각도, 배치, 깊이를 통제한다      |
| Character Identity   | 포즈를 잡은 마네킹으로 캐릭터의 위치와 자세를 이끈다          |
| Background Removal   | 피사체를 떼어 2D와 3D 장면의 소품이나 배경으로 쓴다           |
| Mixed Asset Crafting | 이미지 조각, 월드, 3D 메시를 한 장면에 섞는다                 |

빠른 프롬프트 쪽에는 텍스트로 이미지 만들기, 프롬프트로 이미지 고치기,
캔버스에서 마스크와 인페인팅으로 고치기, 이미지로 영상 만들기가 있다.
FAQ의 안내서도 2D 캔버스, 3D 에디터, 인페인팅,
이미지에서 영상 만들기 순서로 같은 흐름을 다룬다.

개발자 echelon은 Show HN 글에서 3D 부분이 이미지 대 이미지(I2I)와 이미지 대
영상(I2V) 작업에서 강력하고 직관적인 ControlNet 역할을 한다고 설명했다.
거의 WYSIWYG 편집기에 가깝고, 전문 창작자를 위한 기술은 텍스트 중심 프롬프트가
아니라 이 방향으로 갈 것이라고 확신한다고도 적었다.
ComfyUI는 훌륭하지만 함께 일하는 사람들이 노드 그래프를 직관적으로 이해하지
못하거나, VRAM이 충분한 그래픽 카드가 없거나,
Python 의존성을 관리하지 못한다는 것이 이 도구를 만든 이유다.

그 Show HN 스레드에서 hummel은 Storyboarder를 출처 표시 없이 포크한 것 같다고
지적했다.[^hummel]
echelon은 커밋 기록을 보라며 강하게 부인했다.[^echelon-storyboarder]
Storyboarder라는 프로젝트는 처음 듣는다고 했고,
3D 조작 부분은 storyteller.ai라는 이름으로 만들었던 초기 AI 타임라인 애니메이션
실험에서 가져왔다고 설명했다.

### 모델을 모으는 계층

ArtCraft는 모델을 직접 만들지 않고 여러 회사의 모델을 한 화면에 모은다.
README의 카탈로그는 ArtCraft를 통해 쓸 수 있는 모델을 62개로 센다.

| 분류          | 개수 | 주요 계열                                       |
| ------------- | ---- | ----------------------------------------------- |
| 이미지        | 16   | Nano Banana, GPT Image, FLUX, Seedream          |
| 영상          | 25   | Seedance, Kling, Veo, Sora, Vidu, MiniMax, Flux |
| 음악과 효과음 | 5    | Suno, Seed Audio                                |
| 3D 메시       | 11   | Hunyuan 3D, Tripo3D, Meshy, Rodin               |
| 월드와 스플랫 | 5    | Marble, TripoSplat                              |

이와 별도로 Grok, Midjourney, Sora, World Labs 계정으로는
직접 로그인해 쓸 수 있다.
Kling, Google, Runway, Luma 연동이 계획되어 있고,
OpenArt와 Freepik 같은 다른 모음 서비스의 구독을 그대로 쓰게 하는 데도 관심이
있다고 README는 적는다.
개발자는 2025년 11월에 이를 가장 싼 모델 모음 서비스라고
불렀다.[^echelon-aggregator]
사용자가 Sora, Midjourney, Grok 계정으로 직접 로그인하면 자신에게 아무것도 내지
않고 도구를 쓸 수 있다는 이유에서다.

## 요금과 크레딧

ArtCraft 자체는 무료로 내려받아 쓸 수 있다.
요금제 페이지의 각주는 자기 컴퓨팅 자원과 외부 구독을 가져와 구독 없이 쓸 수
있다고 밝히면서, 구독이 개발 속도를 높이니 구독해 주기를 바란다고 덧붙인다.
유료 요금제는 ArtCraft를 통해 모델을 호출할 크레딧을 판다.

| 요금제     | 월 요금(정가) | 월 크레딧 | Nano Banana 이미지 | Seedance 2.0 영상 |
| ---------- | ------------- | --------- | ------------------ | ----------------- |
| Basic      | 10달러        | 1,000     | 약 250장           | 약 63초           |
| Pro        | 35달러        | 3,750     | 약 938장           | 약 234초          |
| Max        | 60달러        | 6,600     | 약 1,650장         | 약 413초          |
| Enterprise | 별도 협의     | 별도 할당 | -                  | -                 |

이 글을 쓴 2026년 10월 7일에는 모든 요금제를 20% 할인한다는 기간 한정 안내가
붙어 있었다.
표의 환산치로 계산하면 Nano Banana 이미지 한 장은 약 4크레딧,
Seedance 2.0 영상 1초는 약 16크레딧이다.
요금제와 별도로 만료되지 않는 일회성 크레딧 팩을 팔고,
생성이 실패하면 크레딧을 돌려준다.

## 분석

### 경쟁 대상은 모델이 아니라 모델 위의 작업 화면이다

ArtCraft는 모델을 하나도 학습하지 않았다.
README의 카탈로그는 Google, OpenAI, ByteDance, Kuaishou,
Tencent 등이 만든 모델의 목록이다.
그러니 이 제품이 파는 것은 생성 능력이 아니라 생성 능력을 다루는 작업 화면이다.

echelon은 기반 모델들이 모두 꽤 경쟁력 있고 점점 통제 가능해지고 있으며,
바로 그 통제가 중요하다고 썼다.
그래서 자신은 UI와 UX의 통제 계층을 만들고 있다는 것이다.
모델이 범용화되면 차별화는 모델을 어떻게 다루게 하느냐로 옮겨 간다는 판단이다.
로드맵이 2026년의 첫 번째 목표로 모델 모음 웹사이트보다 더 낫고 쓸모 있는 도구가
되는 것을 꼽은 것도 같은 맥락이다.

이 판단은 영상 편집 소프트웨어의 역사와 닮았다.
카메라와 코덱이 범용화된 뒤 가치는 편집 타임라인으로 옮겨 갔다.
echelon이 AI를 영화의 개인용 컴퓨터 순간이자 DAW라고 부른 것도,
생성 모델을 녹음 장비로 보고 자신의 도구를 그 위의 작업 환경으로 보는 시각이다.

### 장면 구성은 프롬프트의 불확실성을 줄이는 장치다

텍스트로 영상을 만들면 같은 프롬프트로도 매번 다른 결과가 나온다.
영화를 만드는 사람에게 이것은 치명적이다.
같은 방에서 찍은 여러 숏에서 소품이 사라지거나 배우의 위치가 바뀌면 관객은 바로
알아챈다.

ArtCraft의 3D 기능은 이 문제를 생성 이전 단계에서 다룬다.
이미지를 3D 메시나 가우시안 스플랫(Gaussian splat) 월드로 바꾸고,
그 안에 마네킹을 세우고 카메라를 놓은 뒤, 그 결과를 모델의 입력으로 넘긴다.
개발자의 글은 이를 사전 시각화(previz) 장면을 일종의 ControlNet으로 쓰는
방식이라고 설명한다.
영화 제작이 원래 쓰던 블로킹과 프리비즈 관행을 AI 생성의 앞단에 붙인 셈이다.

### 무료 도구와 크레딧 판매가 한 몸이다

ArtCraft의 수익 구조는 단순하다.
도구는 무료로 주고, 도구 안에서 쓰는 모델 호출을 크레딧으로 판다.
사용자가 외부 계정이나 자기 API 키를 쓰면 회사는 돈을 벌지 못한다.

그런데도 외부 계정을 허용하는 이유를 개발자는 매출을 직접 잡는 것보다 레일과
UX를 만들고 관심을 얻는 것이 중요하기 때문이라고 설명해 왔다.
2026년 8월 HN 댓글에서 ArtCraft를 만든다고 밝힌 possibilistic은 연환산 매출이
500만 달러이고 입소문으로 매달 65%씩 성장하고 있다고 적었다.[^possibilistic-arr]
7월의 같은 계정 글은 300만 달러였다.[^possibilistic-july]
echelon은 비슷한 시기에 고객의 30%가 매달 수천 달러를 쓰고,
3개월 차 유지율이 89%이며, 올해 극장에 걸릴 영화 두 편이 ArtCraft를 썼다고
적었다.[^echelon-metrics]
모두 회사 쪽의 자기 보고이고 외부에서 검증된 수치는 아니다.

## 비평

### 오픈소스라는 말과 실제 라이선스가 다르다

홈페이지는 Free & open source라는 제목 아래 GitHub에 전체 스튜디오가 공개되어
있으니 읽고, 포크하고, 자기 것으로 만들라고 말한다.
그러나 저장소의 `LICENSE.md`는 스스로를 초안(WIP)이라고 밝히고,
아직 법률 용어를 제대로 갖춘 진짜 라이선스가 아니라고 경고한다.
내용도 오픈소스가 아니다.
상업적으로 판매할 수 없고, 경쟁 사업이나 제품,
예컨대 AI 이미지와 영상 도구를 파는 데 코드를 쓸 수 없다.
포크하더라도 ArtCraft 커뮤니티, 후원 링크, 유료 모델 서비스를 제거할 수 없다.

라이선스 자신도 이를 페어 소스라고 부르고,
왜 OSI 오픈소스가 아닌지를 길게 설명한다.
OSI가 하이퍼스케일러가 이끄는 업계 단체라는 철학적 이유와,
OSI 라이선스로는 상업적으로 크게 성장하기가 매우 어렵다는 현실적 이유다.
그러니 회사는 자기 라이선스가 오픈소스가 아님을 알고 있다.
그런데도 홈페이지는 오픈소스라고 쓰고, 개발자는 채용 공고에서는 소스 공개(source
available)라고 쓰면서[^echelon-hiring] 다른 댓글에서는 데스크톱 앱과 서버가
완전한 오픈소스라고 쓴다.[^echelon-metrics]

Crafting Apps를 다룬 HN 스레드에서 kmeisthax는 이 라이선스를 직접 인용하며,
특정 회사 한 곳만 수익화 권한을 갖는 이런 라이선스가 FOSS와 독점 소프트웨어의
나쁜 점만 섞는다고 비판했다.[^kmeisthax]
같은 스레드에서 echelon은 구독이 무엇을 위한 것이냐는 질문에,
그것은 웹 기능이자 별도의 오픈소스 앱이며 오픈소스판 Higgsfield라고
답했다.[^echelon-higgsfield]
라이선스 파일을 읽지 않은 사람은 이 답을 문자 그대로 받아들일 것이다.
경쟁 제품 개발을 금지하는 라이선스를 오픈소스라고 부르는 것은 단순한 표현 차이가
아니다.
포크해서 다른 서비스를 만들 수 있다고 믿은 사람에게는 법적 위험이 된다.

### 영원히 소유한다는 약속은 크레딧 구조와 맞지 않는다

요금제 페이지는 모든 요금제에 ArtCraft를 영원히 소유한다는 항목을 넣고,
홈페이지는 웹사이트에서 빌려 쓰는 것을 그만두라고 말한다.
구독도, 중개자도, 임대료도 없다는 것이다.
그러나 ArtCraft가 하는 일의 거의 전부는 외부 모델 호출이다.
소유할 수 있는 것은 작업 화면이고, 결과물을 만드는 능력은 여전히 매달 크레딧이나
외부 구독으로 빌린다.

로드맵은 ArtCraft가 운영하는 서비스에 대한 의존을 없애겠다는 목표를 아키텍처
항목에 올려 두었다.
이것이 이루어지면 소유한다는 말에 더 가까워진다.
하지만 그 목표는 크레딧 판매라는 지금의 수익원과 정면으로 부딪친다.
라이선스가 포크에서 유료 모델 서비스를 제거하지 못하게 막아 둔 것도,
결국 이 수익원을 지키는 장치다.

### 사이트의 모델 정보가 서로 맞지 않는다

홈페이지 상단은 Seedance 2.5와 Nano Banana 2를 내세운다.
그러나 README의 62개 모델 카탈로그에 Seedance는 2.0까지만 있고,
요금제 페이지의 환산표도 Seedance 2.0 기준이다.
요금제 페이지는 Kling 3.0 Pro 영상의 초 수를 제시하지만,
README 카탈로그는 Kling 3.0 Pro에 지금 비활성화되었다는 표시를 달아 두었다.

크레딧을 사는 사람에게는 어떤 모델을 쓸 수 있는지가 곧 상품 설명이다.
환산표의 기준 모델이 실제로 꺼져 있다면 그 표는 구매 판단의 근거가 되지 못한다.
모델이 매달 바뀌는 시장에서 이런 어긋남은 피하기 어렵지만,
그렇다면 환산표에 기준일을 적어야 한다.

### 결과물의 품질은 이 도구가 답할 수 없는 질문이다

ArtCraft는 통제를 팔지만, 최종 픽셀은 외부 모델이 만든다.
HN의 No AI Fridays 스레드에서 PKop은 echelon의 홍보에 답하며 영상과 홈페이지의 결과물이 전혀 좋아 보이지 않는다고 했다.[^pkop]
극장에 걸린다는 두 편이 무엇이냐고 묻기도 했다.

이 비판은 도구 쪽에서 해결할 수 있는 범위를 넘는다.
장면 구성은 일관성을 높여 주지만 결과물의 질감과 연기는 모델의 몫이다.
ArtCraft가 아무리 좋은 통제 계층을 만들어도,
사용자가 느끼는 품질의 상한은 그 순간 가장 좋은 외부 모델이 정한다.
반대로 말하면, 모델이 좋아지는 만큼 ArtCraft도 공짜로 좋아진다.

## 인사이트

### 모델 모음 서비스의 경쟁은 결국 IDE 경쟁이 된다

ArtCraft가 스스로를 IDE라고 부르는 것은 우연이 아니다.
코딩 도구 시장에서 모델이 범용화되자 경쟁은 모델을 다루는 편집기와 에이전트
하네스로 옮겨 갔다.
이미지와 영상 쪽도 같은 길을 가고 있다.
Higgsfield나 OpenArt 같은 모음 서비스가 모델 접근을 팔았다면,
ArtCraft는 그 위의 작업 환경을 판다.

이 구도에서 승부를 가르는 것은 모델 목록의 길이가 아니라 작업 데이터가 어디에
쌓이느냐다.
장면, 에셋, 포즈, 카메라 설정이 ArtCraft의 형식으로 쌓이면 사용자는 모델을
바꿔도 도구를 바꾸기 어렵다.
외부 계정을 허용하는 넉넉함은 그 자체로 잠금 전략이 될 수 있다.
모델 공급자 쪽을 열어 둘수록 작업 화면 쪽의 결속은 강해진다.

### 페어 소스는 신뢰를 사려는 장치지만 말을 바꾸면 신뢰를 잃는다

ArtCraft의 라이선스는 회사가 문을 닫으면 OSI 승인 라이선스로 전환하고,
인수되거나 바뀌어도 도구가 같은 방식으로 계속 동작하게 하겠다고 약속한다.
러그 풀(rug pull)을 하지 않겠다는 약속이다.
라이선스가 영감을 받았다고 밝힌 Fair Source(fair.io)와 Fair Code의 전형적인
거래로, 사용 제한을 받아들이는 대신 코드를 볼 권리와 미래의 보장을 얻는 구조다.

문제는 이 거래가 정직한 표기를 전제로 한다는 점이다.
페어 소스는 오픈소스가 아니라고 스스로 밝힘으로써 신뢰를 얻는 모델이다.
같은 제품을 어떤 자리에서는 오픈소스, 어떤 자리에서는 소스 공개라고 부르면,
사용자는 라이선스의 다른 약속도 같은 정도로만 믿게 된다.
같은 회사가 Crafting Apps에는 MIT와 Apache를 쓰면서 본체에는 페어 소스를 쓰는
지금, 두 제품을 같은 오픈소스라는 말로 묶으면 혼란은 더 커진다.

### 일관성을 3D로 푸는 접근은 월드 모델과 경쟁하게 된다

ArtCraft의 차별화는 3D 장면을 사람이 직접 만들어 모델에 넘기는 데 있다.
이 접근은 모델이 공간을 기억하지 못한다는 전제 위에 서 있다.
그런데 README의 카탈로그에는 이미 World Labs의 Marble 같은 월드 생성 모델이 들어
있고, 개발자 자신도 Google이 비슷한 3D 도구를 선보일 것이라는 소식을 듣고 서둘러
Show HN을 올린 적이 있다.

모델이 스스로 일관된 공간을 유지하게 되면,
사람이 3D로 블로킹하는 단계는 일부 줄어들 것이다.
그때 남는 가치는 감독이 의도를 정확히 전달하는 인터페이스, 즉 카메라 위치,
배우 동선, 소품 배치를 지정하는 언어다.
ArtCraft가 오래 살아남으려면 지금의 3D 우회로가 아니라 그 의도 지정 언어를 자기
것으로 만들어야 한다.

### 오픈 코드와 유료 크레딧 사이의 긴장은 성장할수록 커진다

지금 ArtCraft는 무료 도구가 사용자를 모으고 크레딧이 돈을 버는 구조로 빠르게
자라고 있다고 말한다.
이 구조는 사용자가 회사의 크레딧을 쓰는 동안만 성립한다.
로드맵의 호스팅 서비스 의존 제거, 로컬 모델 지원,
외부 컴퓨팅 연결은 모두 사용자를 회사의 크레딧 밖으로 데려가는 방향이다.

회사는 이 긴장을 라이선스로 묶어 두었다.
포크에서 유료 모델 서비스를 빼지 못하게 한 조항이 그것이다.
규모가 커질수록 이 조항은 더 중요해지고,
사용자가 원하는 자유와 회사가 지켜야 할 매출 사이의 간격도 커진다.
Stability AI가 돈을 벌 방법이 없어 무너졌다는 라이선스 속 문장은,
이 회사가 그 간격을 얼마나 의식하고 있는지 보여 준다.
