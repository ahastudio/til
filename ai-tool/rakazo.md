# Rakazo: 내 컴퓨터와 모델로 돌리는 오픈소스 상시 AI 팀원

<https://rakazo.com/>

<https://github.com/elie222/rakazo>

GN 토론: <https://news.hada.io/topic?id=35894>

## 소개

Rakazo는 지속적으로 일하는 AI 팀원(bot)을 만드는 오픈소스 에이전트이자, 내
컴퓨터에서 돌릴 수 있는 셀프 호스팅 AI 비서다.
저장소 설명은 Grok Bot의 오픈소스 대안이고 모델과 샌드박스를 직접 고른다는
것이며, 라이선스는 Apache-2.0이다.
웹과 Electron 데스크톱 앱, iPhone 앱, Android APK로 쓴다.
README는 Grok Bot, Meta Muse, OpenAI Dots, Instinct, OpenClaw, Hermes Agent,
Claude Duet의 오픈소스 셀프 호스팅 대안이라고 자신을 규정하고 베타 단계라고
밝힌다.
이 문서가 쓰인 날 저장소는 스타 5,452개, 포크 959개이며 2026년 8월 13일에
만들어졌고 최신 릴리스는 v0.3.3(2026년 10월 22일)이다.
같은 날 마지막 푸시가 있었다.
10월 27일에 다시 확인하니 스타 5,937개, 포크 1,048개, 열린 이슈 93개였고 마지막
푸시는 같은 날이었다.
홈페이지의 푸터는 Inbox Zero Inc.의 서비스라고 밝히고, README의 감사 목록에도
Inbox Zero가 있다.

홈페이지의 약속은 봇에게 일을 맡기고 어느 기기에서든 확인한다는 것이다.
데모는 봇 목록(Chief of Staff, Sales Outbound, Inbox Manager, Account Manager,
Talent Scout, Expense Manager, Bug Triage)과 Inbox Manager가 Gmail을 정리하는
장면을 보인다.
받은 편지함 41통을 읽고 26통을 보관하고 9통에 답하고 6통은 사용자 말투로 초안을
써서 보류하고 1통(계약 질문)은 표시해 두었다는 식이다.
봇은 루틴(평일 오전 6시 정리, 매시간 답장 확인)으로 일정에 따라 돌고, 승인이
필요한 동작은 사용자가 정하며, 사용자는 직접 개입(Take control)할 수 있다.
템플릿은 Sales Outbound, Inbox Manager, Talent Scout, Expense Manager, Coding
Agent, Account Manager, Paid Media, Chief of Staff다.

## 동작 방식

### 봇은 대화와 기억과 컴퓨터를 따로 가진다

README의 기능 목록은 봇마다 자기 대화, 기억, 루틴, 기록이 있고, 팀이 공유하는
컴퓨터와 격리된 개인 컴퓨터를 나눠 쓸 수 있으며, 브라우저와 터미널과 파일과
그래픽 데스크톱을 쓸 수 있다고 한다.
봇은 동료 봇이나 수명이 짧은 하위 에이전트에게 일을 넘길 수 있다.
앱 연동은 Composio나 Pipedream Connect, 그리고 사용자가 설치하는 Treg와 원격
MCP와 OpenAPI 도구 소스를 통한다.
음성은 말하기와 받아쓰기와 봇에게 전화하기를 지원하며 ElevenLabs, OpenAI,
Cartesia, Fish Audio 키를 직접 가져온다.

### 모델은 구독이나 키나 로컬 서버로 연결한다

홈페이지의 FAQ는 Claude Pro/Max나 ChatGPT Plus/Pro 구독으로 로그인하거나,
Anthropic, OpenAI, OpenRouter, Grok의 API 키를 쓰거나, Ollama와 LM Studio 같은
로컬 OpenAI 호환 서버를 연결할 수 있다고 답한다.
Rakazo는 모델 요금을 대신 내지 않고, 봇마다 다른 모델을 고를 수 있다.

### 컴퓨터는 Docker와 원격 샌드박스 공급자 중에서 고른다

지원 환경은 Docker, E2B, Daytona, CreateOS, Boat, 신뢰하는 로컬 컴퓨터이고
Railway도 선택 사항이다.
게시된 이미지로 설치하는 경로는 Docker Engine과 Compose 플러그인과 curl과
OpenSSL만 필요하다고 한다.
설치 스크립트가 Compose 파일을 받고 무작위 비밀 값이 든 `.env`를 만들고 서비스를
시작하며, 주소 `http://127.0.0.1:5173`에서 계정을 만들고 모델을 연결한다.
서버에서 상시로 돌리려면 같은 설치 스크립트를 VPS에서 쓰고 포트 5173 앞에
HTTPS를 두라고 한다.
기술 스택은 TypeScript, React 19, Vite, Electron, Expo, Hono, oRPC, PostgreSQL,
Prisma, Better Auth, Graphile Worker, 그리고 모델 연결을 맡는 Pi다.

```bash
mkdir -p rakazo && cd rakazo &&
curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh &&
bash install-images.sh
```

위 명령은 README의 빠른 시작이며 이 문서가 실행해 보지는 않았다.

### 비밀 값과 데이터베이스 권한이 분리돼 있다

README는 앱이 행 수준 보안이 적용되는 별도의 `rakazo_app` 로그인으로
데이터베이스에 연결하고 마이그레이션은 소유자로 실행한다고 설명한다.
커넥터 자격 증명은 서버에서 암호화되고 API가 돌려주지 않는다고 한다.
Docker 샌드박스에는 전용 토큰(`SANDBOX_SUPERVISOR_TOKEN`)이 따로 필요하다.

## 비평

### 후기는 홈페이지가 고른 것이다

홈페이지의 후기 여섯 개는 Grok Bot에서 옮겨 왔다는 사용자, 사설 GPU에서 Qwen으로
돌리는 CTO, eBay에서 싼 서버를 찾는 용도, Hermes보다 설정이 쉽다는 평, Claude
OAuth로 한 달 썼다는 평, Expo 설정을 안내받았다는 평이다.
선별 기준이 없고 모두 호의적이며, 비교 대상인 Hermes와의 우열은 다른 자료로
확인해야 한다.
이 저장소의 `ai-tool/hermes-agent.md`가 다룬 Hermes Agent와 직접 비교한 자료는
이번에 보지 못했다.

### 구독을 연결하는 방식은 약관 위험을 사용자에게 넘긴다

FAQ는 Claude Pro/Max나 ChatGPT Plus/Pro 구독으로 로그인해 쓸 수 있고 Rakazo는
모델 요금을 내지 않는다고 한다.
구독 계정을 서드파티 에이전트에서 쓰는 것이 각 서비스의 약관과 사용 한도
정책에서 허용되는지는 서비스마다 다르며, 홈페이지는 이를 다루지 않는다.
이 문서도 두 서비스의 약관을 확인하지 못했다.

### 에이전트에게 메일과 컴퓨터를 맡기는 구조의 권한 모델이 짧다

Inbox Manager 예시는 Gmail을 정리하고 보관하고 답장하고 초안을 쓴다.
홈페이지는 승인이 필요한 동작을 사용자가 정한다고 하며 Approve와 Deny 화면을
보인다.
기본으로 어떤 동작에 승인이 요구되는지, 외부에서 온 메일 내용이 봇에게 지시로
읽히는 문제(프롬프트 주입)를 어떻게 다루는지는 홈페이지와 README에서 확인되지
않는다.
읽기 권한이 있는 에이전트가 외부 입력을 받는 구조에서는 이것이 가장 먼저 묻는
질문이다.
메일과 샌드박스 컴퓨터를 함께 가지는 에이전트는 권한 범위가 곧 위험의 범위다.

### 여러 봇이 서로의 일을 아는지가 실제 병목이라는 사용자 경험

GeekNews에서 dkkim1110은 봇마다 대화와 기억과 작업 이력을 따로 둔다는 점이
반갑다고 적었다.
영업 업무를 에이전트에 나눠 메일, 콜드메일, 글쓰기를 방마다 따로 돌리는데 가장
자주 생기는 문제가 방끼리 서로 한 일을 모른다는 것이었고, 지금은 공용 메모 파일
하나에 방마다 끝낸 일을 몇 줄씩 남기게 해 겨우 이어 붙인다고 했다.
그래서 공유 컴퓨터에서 파일을 같이 쓰는 구조가 어떻게 도는지 궁금하다고 물었고,
메일 발송처럼 되돌릴 수 없는 일에만 사람 승인을 걸어 두었더니 사고가 크게
줄었다고 했다.[^dkkim1110]
이 서술은 한 사용자의 경험이며 이 문서가 같은 설정을 시험하지 않았다.
이 문서가 읽은 README와 홈페이지는 봇 사이 맥락 공유의 방식(공유 컴퓨터의 파일
외에 무엇이 있는지)을 다루지 않고, 승인 기본값에 대한 위 비평과 맞물리는
질문이다.

### 베타이며 비교 대상이 많다

README는 베타라고 밝히고 일곱 제품의 대안이라고 쓴다.
비교 페이지가 따로 있지만 비교 항목이나 기준은 이 문서가 읽지 않았다.
`ai-tool/grok-bot.md`와 `ai-tool/meta-muse.md`가 다룬 제품들은 상용 서비스인
반면 Rakazo는 셀프 호스팅이라는 점에서 같은 범주의 선택지가 아닐 수 있다.

## 인사이트

### 상시 에이전트의 경쟁축은 모델이 아니라 소유권으로 옮겨 가고 있다

상시 동작하는 비서형 AI 제품군이 늘어나는 사이 Rakazo가 내세우는 차별점은 기능이
아니라 내 키, 내 모델, 내 컴퓨터다.
이는 상용 서비스가 기억과 연결된 앱과 맥락을 쌓아 전환 비용을 만드는 구조의
반대편에 서 있다.
Rakazo에서 맥락(대화, 기억, 루틴)은 사용자의 데이터베이스에 있으므로 이론적으로
가져갈 수 있다.
이 이점이 실제가 되려면 데이터 형식이 공개돼 있고 내보내기가 되는지가 조건인데,
이 문서는 그 부분을 확인하지 못했다.

### 셀프 호스팅 에이전트의 비용은 서버 운영자가 사용자에게 옮겨 온다

설치는 Docker Compose 한 줄이지만, 상시로 돌리려면 VPS와 HTTPS와 백업과
업그레이드와 샌드박스 공급자 키를 직접 관리해야 한다.
README가 환경 변수 항목을 길게 적는 것(Railway 토큰 범위, 리전, 파일 크기 한도
등)이 그 운영 부담의 크기를 보여 준다.
상용 서비스는 이 부담을 요금에 포함한다.
Rakazo는 요금 대신 설정을 받는 모델이라, 대상 사용자는 서버를 운영할 수 있는
개인과 소규모 팀에 가깝다.

### 이 문서를 읽는 방법

도입을 검토한다면 메일 같은 민감한 계정을 연결하기 전에 두 가지를 확인할 수
있다.
격리된 로컬 Docker 컴퓨터와 별도의 테스트 계정으로 한 봇만 돌려 보고, 승인 필요
동작의 기본값이 어떻게 설정되는지 설정 화면에서 읽는 것이다.
이 프로젝트의 주장을 가를 관찰은 두 가지다.
베타 이후 외부 입력에 의한 오작동(프롬프트 주입)에 대한 설계가 문서화되는지,
구독 연결이 모델 서비스의 정책 변경에도 계속 유지되는지다.
둘 다 현재 자료로는 확인되지 않는다.
