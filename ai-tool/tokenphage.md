## 소개

Claude Code, Codex, opencode의 토큰 사용량을 모아 GitHub README에 붙이는 배지로
만들어 주는 도구다.
소개 문구는 “먹어치운 토큰, 이젠 README에 기록하세요!”이고, 이름의 phage(파지)도
그 은유에서 왔다.

만든 사람은 GeekNews에 “재미로 만들어본 건데 생각보다 배지 디자인이 잘 뽑혀서
홍보 겸 작성해 본다”고 밝혔다.
배지에는 누적 토큰, 최근 30일 히트맵, 모델별 사용량이 들어간다.
토큰을 많이 쓸수록 카드 안의 마스코트가 Lv.1부터 Lv.5까지 진화하고, 레벨이 오르면
생김새와 이펙트가 함께 바뀐다.

프로젝트는 조직 계정 아래 여러 저장소로 나뉘어 있다.
`tokenphage-cli`(JavaScript, MIT)가 파서·토큰 집계·동기화를 맡고,
`tokenphage-api`(Java, 라이선스 미표기)가 백엔드 서버다.
CLI는 2026년 6월 13일에 만들어졌고 npm에는 7월 4일 처음 올라와 8월 2일까지
네 번의 버전이 나왔다.

## 사용법

Node.js 20.17 이상, macOS 또는 Windows(자동 동기화 사용 시), GitHub 계정이
필요하다.

```bash
npm install -g tokenphage@latest

tokenphage                       # 대화형 화면 실행
tokenphage login <github-id>     # GitHub 계정 인증
tokenphage sync                  # 지금 사용량 동기화
tokenphage install-hook          # 매일 04:00 자동 동기화 켜기
```

README에는 한 줄만 넣으면 된다.

```markdown
[![TokenPhage](https://api.tokenphage.com/badge/kobenlys)](https://github.com/TOKENPHAGE)
```

URL 뒤에 옵션을 붙일 수 있다. 테마는 `?theme=gpu`(기본)와 `?theme=claude`,
색상은 `?mode=light`(기본)와 `?mode=dark`다.
GeekNews 글에서는 `grass-claude`를 포함해 테마가 세 개뿐이며 계속 추가할
예정이라고 밝혔다.

자동 동기화는 매일 오전 4시에 돈다. 컴퓨터를 거의 안 쓰는 시간대라 작업을 방해하지
않는다는 설명이다.
실행 기록은 `~/.tokenphage/logs/sync.log`에 남는다.

## 인증 방식

비밀번호 없이 공개 Gist로 계정 소유를 증명한다.

1. 화면에 인증용 문자열이 표시된다
2. `https://gist.github.com/new`에서 `tokenphage.txt`라는 이름의 공개 Gist를 만들고
   그 문자열을 넣는다
3. 만들어진 Gist의 주소나 ID를 붙여넣는다

OAuth 앱 등록 없이 “이 GitHub 계정으로 공개 Gist를 만들 수 있다”는 사실만으로
소유를 확인하는 방식이다.

## deviceId와 중복 집계

로그인 정보와 설정은 `~/.tokenphage/config.json`에 저장된다.
로그인 토큰(JWT), 기기 식별자(deviceId), 마지막 동기화 날짜, 자동 동기화 설정이
들어 있다.

README는 이 파일을 임의로 지우지 말라고 경고하며 그 이유를 상세히 설명한다.
`config.json`이 사라지면 재인증이 필요하고, 새 `deviceId`가 발급되며, 마지막 동기화
기록도 사라져 다음 `sync`가 전체 히스토리를 처음부터 다시 올린다.
서버는 같은 사용량이라도 `deviceId`가 다르면 별도 행으로 저장하고 배지의 누적
토큰은 모든 `deviceId`를 합산하므로, 같은 기록이 이중 집계되어 누적 토큰이 실제보다
부풀려진다.

해결책은 전체 초기화다. Advanced settings → Reset all data에서 본인 GitHub 아이디를
직접 입력하면 서버에 쌓인 토큰 사용량 전체를 지우고 처음부터 다시 동기화한다.
로컬 기록은 건드리지 않으며 남용 방지를 위해 24시간에 한 번만 가능하다.

## Claude Code 보존 기간 변경

README의 “유의사항”에 이 도구에서 가장 중요한 동작이 들어 있다.

Claude Code는 오래된 세션 기록(트랜스크립트)을 자동으로 삭제한다.
보존 기간은 `cleanupPeriodDays` 설정으로 정해지고 기본값은 30일이라, 30일이 지난
세션은 사라진다. 삭제된 기록의 토큰은 다시 집계할 수 없다.

그래서 로그인 직후 CLI가 “기록을 계속 보관할지” 한 번 물어본다.
Yes를 고르면 `~/.claude/settings.json`의 `cleanupPeriodDays`를 **99999**(사실상
영구)로 바꾼다.
설정 파일이 손상돼 있으면 건드리지 않고 수동으로 넣는 방법을 안내한다.

## 분석

### 배지의 진짜 기능은 정보 전달이 아니라 정체성 표시다

README 배지는 원래 정보를 전달하는 장치였다.
빌드 통과 여부, 테스트 커버리지, 최신 버전, 라이선스 — 프로젝트를 쓸지 판단하는
데 필요한 것들이다.

TokenPhage 배지가 전하는 정보는 성격이 다르다.
누적 토큰 수와 모델별 사용량은 그 저장소를 쓰려는 사람에게 아무 쓸모가 없다.
저장소에 대한 정보가 아니라 저장소 주인에 대한 정보이고, 심지어 그 저장소와 무관한
활동의 총량이다.

이건 프로필 README라는 맥락에서 이해해야 한다.
GitHub이 사용자 이름과 같은 저장소의 README를 프로필에 노출하기 시작한 뒤로,
그 공간은 기술 문서가 아니라 자기표현의 공간이 됐다.
잔디밭 스타일 통계 카드, 사용 언어 비율, 스트릭 카운터 같은 것들이 그 자리를
채웠다.
저자가 “프로필 README 꾸미시는 분들한테 쓸 만할 것 같아서 공유한다”고 쓴 것은
이 계보를 정확히 인식한 것이다.

마스코트가 Lv.1에서 Lv.5까지 진화한다는 설정은 그래서 부수적인 재미가 아니라
핵심 기능이다.
숫자만으로는 비교 우위가 잘 드러나지 않지만 레벨은 즉시 읽힌다.
소비량을 성취로 번역하는 장치이고, 이 번역이 이 도구가 파는 것이다.

### Gist 인증은 OAuth를 피하려는 실용적 선택이다

계정 소유 확인에 공개 Gist를 쓰는 방식은 익숙한 패턴의 변형이다.
DNS TXT 레코드로 도메인 소유를 증명하거나, 특정 파일을 웹 루트에 올려 인증하는
것과 같은 구조다.

이 선택의 실질적 이점은 GitHub OAuth 앱을 등록하지 않아도 된다는 것이다.
OAuth를 쓰면 사용자에게 권한 승인 화면이 뜨고, 그 화면에는 이 앱이 무엇에 접근할
수 있는지가 나열된다.
읽기 전용 최소 권한으로 설정해도 사용자는 낯선 앱에 GitHub 계정을 연결하는 것을
망설인다.

Gist 방식은 그 마찰을 없앤다. 사용자가 직접 Gist를 만들고 그 URL만 알려주므로
어떤 권한도 넘기지 않는다.
개인 프로젝트가 신뢰를 요구하지 않고 인증을 구현하는 방법으로는 영리하다.

다만 이 방식에는 특유의 결과가 따른다.
인증 과정에서 만든 Gist는 공개 상태로 남고, 그 계정이 TokenPhage를 쓴다는 사실이
GitHub에 공개 기록으로 남는다.
지워도 되는지, 지우면 인증이 유지되는지는 README에 나오지 않는다.

### deviceId 문제를 문서로 처리한 것 자체가 설계를 드러낸다

README에서 가장 긴 설명이 붙은 부분이 `config.json` 삭제 시의 중복 집계다.
네 단계로 나눠 왜 누적 토큰이 부풀려지는지 설명하고, 초기화 절차를 안내하고,
24시간 제한까지 명시한다.

이 정성스러운 설명은 역으로 서버 설계를 드러낸다.
서버가 `deviceId`별로 행을 나눠 저장하고 배지에서 전부 합산한다는 것은, 같은
데이터가 두 번 올라와도 걸러낼 방법이 없다는 뜻이다.
세션 ID나 타임스탬프 해시 같은 자연 키로 중복을 제거했다면 `deviceId`가 바뀌어도
문제가 없었을 것이다.

즉 중복 제거를 서버에서 하지 않기로 하고, 그 결과를 사용자에게 “이 파일을 지우지
마세요”라는 규칙으로 전가한 구조다.
개인 프로젝트에서 흔한 선택이고 비난할 일은 아니지만, 이 도구가 “매일 자동으로
갱신되니 신경 쓸 것 없다”고 약속하는 것과는 어긋난다.
사용자가 재설치를 하거나 새 노트북으로 옮기면 배지 숫자가 조용히 부풀어 오른다.

## 비평

### 30일 보존 기간을 99999일로 바꾸는 것은 배지값 이상의 대가다

이 도구의 가장 문제적인 동작은 로그인 직후 물어보는 그 질문이다.
`~/.claude/settings.json`의 `cleanupPeriodDays`를 99999로 바꾸겠다는 것.

그 설정이 무엇을 보관하는지 짚어야 한다.
Claude Code 트랜스크립트는 토큰 카운터가 아니다. 프롬프트 전문, 모델 응답 전문,
읽은 파일 내용, 실행한 명령과 그 출력이 담긴 대화 기록이다.
사내 코드, API 키가 섞인 설정 파일, 디버깅 중 붙여넣은 로그가 그 안에 있다.

기본값 30일은 Anthropic이 정한 것이고, 오래된 대화 기록을 무한정 쌓아두지 않는
것이 합리적이라는 판단이 반영돼 있다.
그 설정을 사실상 영구로 바꾸는 것은 로컬 디스크에 민감한 개발 기록을 계속 축적하기로
결정하는 일이다.
디스크 용량 문제이기도 하지만, 노트북 분실이나 침해 사고 시 노출되는 범위의 문제이고,
회사에 따라서는 데이터 보존 정책 위반이 될 수도 있다.

README는 이 변경을 “토큰이 누락되지 않게 하기”라는 제목 아래 설명한다.
설명 자체는 정직하다. 무엇을 바꾸는지, 왜 바꾸는지, 손으로 넣는 방법까지 알려준다.
문제는 프레이밍이다. 이 항목은 데이터 보존 정책 변경인데 집계 정확도 문제로
제시된다.
사용자가 Yes를 누를 때 판단하는 것은 “배지 숫자가 정확했으면 좋겠다”이지 “내 개발
대화 기록을 영구 보관하겠다”가 아니다.

교환의 비대칭이 크다.
얻는 것은 README 배지의 숫자 정확도이고, 내주는 것은 다른 도구의 데이터 보존
설정이다.
재미로 만든 장식품이 요구하기에는 무거운 대가이고, 최소한 이 질문은 기본값이
No여야 하며 무엇이 보관되는지가 함께 설명되어야 한다.

### 로컬 로그만 읽는다는 설명과 실제 데이터 흐름

저자는 GeekNews에서 “로컬 로그에서 날짜, 모델명, 토큰 수만 읽어서 올리는 방식”이라고
밝혔다.
이 서술은 안심시키는 효과가 있지만 확인하기는 쉽지 않다.

CLI는 MIT 라이선스로 공개돼 있어 파서가 무엇을 읽는지 검증할 수 있다.
그런데 `tokenphage-api`는 Java로 공개돼 있지만 라이선스 표기가 없다.
라이선스 없는 저장소는 읽기는 되지만 법적으로 사용·수정·배포 권한이 없다.
서버에 무엇이 저장되고 얼마나 보관되는지에 대한 문서는 없고, 개인정보처리방침도
없다.

수집되는 것이 날짜와 모델명과 토큰 수뿐이라 해도 그 조합은 생각보다 많은 것을
말한다.
매일의 AI 사용 패턴은 근무 시간, 휴가 기간, 야근 빈도, 어떤 모델을 주로 쓰는지를
드러낸다.
배지에 30일 히트맵이 들어간다는 것은 이 정보가 이미 공개적으로 표시된다는
뜻이기도 하다. 잔디밭이 커밋 시각을 드러내듯 이 히트맵은 AI 사용 시각을 드러낸다.

`api.tokenphage.com`이라는 개인 도메인 하나에 이 데이터가 모인다는 점도
짚어둘 만하다.
서비스가 언제까지 유지되는지, 중단되면 데이터가 어떻게 되는지, 삭제 요청 경로가
무엇인지가 정해져 있지 않다.
Reset all data가 있지만 그건 “다시 동기화하기 위해 지우는” 기능이지 탈퇴 기능이
아니다.

### 재미로 만든 도구가 매일 도는 백그라운드 작업이 된다

`install-hook`은 매일 오전 4시에 도는 스케줄 작업을 등록한다.
macOS에서는 자동화 권한을, Windows에서는 관리자 권한 터미널을 요구한다.

권한 요구 수준이 도구의 성격과 어긋난다.
프로필 꾸미기용 배지를 위해 시스템 스케줄러에 항목을 하나 추가하고, 그것이
매일 로컬 파일을 읽어 외부 서버로 전송한다.
사용자가 이 도구를 잊어버려도 작업은 계속 돈다.

`uninstall-hook`이 있으니 끌 수는 있다. 문제는 기억하느냐다.
재미로 설치한 도구는 재미가 식으면 방치되고, 방치된 백그라운드 작업은 존재 자체가
잊힌다.
npm 패키지가 4개 버전을 거치는 동안 이 작업은 계속 최신 코드를 실행하는 것도
아니다. 설치된 버전이 그대로 돈다.

여기에 자동 업데이트 안내까지 있다는 점이 겹친다.
대시보드에서 “⬆ Update to …”를 고르면 최신 버전이 자동 설치된다.
편의 기능이지만, 로컬 파일을 읽어 서버로 보내는 도구가 스스로를 갱신하는 경로를
갖고 있다는 뜻이기도 하다.
공급망 관점에서는 신뢰 범위가 “지금 이 코드”에서 “앞으로 이 계정이 배포할 모든
코드”로 넓어진다.

## 인사이트

### 소비량을 성취로 표시하는 지표는 행동을 바꾼다

이 배지가 표시하는 것은 산출물이 아니라 투입량이다.
얼마나 좋은 코드를 썼는지가 아니라 토큰을 얼마나 썼는지이고, 레벨은 그 소비량에
비례해 올라간다.

지표가 공개되면 그 지표를 향한 행동이 생긴다는 것은 오래된 관찰이다.
GitHub 잔디밭이 그 사례다. 매일 커밋하는 습관을 만든 긍정적 효과도 있었지만,
잔디를 채우기 위한 의미 없는 커밋과 자동 커밋 스크립트도 함께 나왔다.
스트릭이 끊기는 것을 피하려고 휴가 중에도 커밋하는 사람들이 생겼다.

토큰 소비량은 잔디밭보다 왜곡되기 쉬운 지표다.
커밋은 최소한 무언가를 만든 흔적이지만, 토큰은 순수한 비용이다.
같은 결과를 적은 토큰으로 얻는 것이 실력인데, 이 배지에서는 그것이 낮은 레벨로
표시된다.
효율을 역인센티브화하는 구조다.

이 왜곡이 개인 프로필 장식에 머무는 동안은 무해하다.
문제는 이런 지표가 조직으로 올라갈 때다.
AI 도구 도입 성과를 측정하려는 조직은 측정하기 쉬운 것을 측정하려 하고, 토큰
사용량은 가장 측정하기 쉬운 숫자다.
[아마존의 토큰맥싱 압박](../ai/amazon-tokenmaxxing-ai-pressure.md)처럼 사용량 자체가
목표가 되는 상황이 이미 보고되고 있다.
개인이 재미로 다는 배지와 조직이 대시보드에 거는 지표는 같은 숫자이고, 같은 왜곡을
공유한다.

### AI 도구 사용 기록이 새로운 개인 데이터 범주가 되고 있다

TokenPhage가 다루는 데이터 — 날짜별 토큰 사용량, 모델별 분포 — 는 몇 년 전에는
존재하지 않던 종류의 기록이다.
그리고 이 기록에 대한 규범은 아직 없다.

무엇이 드러나는지 생각해 보면 가볍지 않다.
사용 시각의 분포는 근무 패턴을 드러내고, 총량의 급증과 급감은 프로젝트 주기나
번아웃을 드러내며, 모델 선택은 어떤 종류의 작업을 하는지를 시사한다.
Opus를 주로 쓰는 사람과 Haiku를 주로 쓰는 사람은 다른 일을 하고 있을 가능성이 높다.

커밋 기록과 비교하면 차이가 보인다.
커밋은 원래 공개를 전제로 만들어진 기록이고, 무엇을 공개할지 개발자가 통제한다.
AI 대화 기록은 반대다. 로컬에 남는 사적 작업 기록이고, 공개를 전제로 만들어지지
않았다.
그 기록에서 추출한 통계를 공개하는 것은 새로운 종류의 노출이다.

이 범주가 자리를 잡으면 따라올 문제들이 예상된다.
채용에서 이 배지를 보게 될 것인가. 회사가 직원의 사용량을 이런 형태로 집계하는
것은 어디까지 허용되는가. 사내 코드를 다룬 세션의 토큰 수가 외부 서버로 나가는
것은 정보 유출인가.
지금은 아무도 이 질문을 하지 않는다. 재미로 만든 배지이기 때문이다.
새로운 데이터 범주에 대한 규범은 대체로 그것이 사소해 보일 때 형성되고, 사소하지
않아졌을 때는 이미 굳어 있다.

### 데이터를 원하는 도구는 다른 도구의 설정을 바꾸려 한다

TokenPhage가 `cleanupPeriodDays`를 99999로 바꾸겠다고 제안하는 장면은 작지만
구조적으로 흥미롭다.
자기 기능을 위해 다른 프로그램의 데이터 보존 정책을 변경하는 것이다.

이런 일이 가능한 이유는 로컬 AI 도구들이 설정과 데이터를 평범한 파일로 두기
때문이다.
`~/.claude/settings.json`은 그냥 JSON 파일이고 누구나 쓸 수 있다.
이 개방성은 생태계를 풍성하게 만든 조건이기도 하다. 세션 탐색기, 사용량 분석기,
프롬프트 관리 도구가 모두 이 접근성 위에 서 있다.

동시에 이 개방성은 경계가 없다는 뜻이기도 하다.
브라우저 확장이나 모바일 앱은 샌드박스와 권한 모델 안에서 동작하고, 다른 앱의
설정을 바꾸려면 명시적 권한이 필요하다.
CLI 도구에는 그런 층이 없다. `npm install -g` 한 번이면 홈 디렉터리 전체에 대한
읽기·쓰기 권한을 갖는다.

이 비대칭이 앞으로 문제가 될 지점이 보인다.
AI 코딩 도구 주변 생태계가 커질수록 로컬 대화 기록을 읽으려는 도구가 늘어난다.
사용량 분석, 프롬프트 재사용, 세션 검색, 팀 대시보드 — 모두 같은 파일을 본다.
그중 하나라도 악의적이거나 침해되면 그 안에 축적된 모든 것이 나간다.
그리고 지금 이 도구들은 사용자에게 보존 기간을 늘리라고 권하고 있다.
축적을 권하는 도구와 축적된 것을 읽는 도구가 같은 생태계에서 함께 자라는 중이다.
