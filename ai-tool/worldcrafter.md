# WorldCrafter: 시선을 돌렸다 돌아와도 같은 장면을 기억하는 영상 월드 모델

<https://drexubery.github.io/WorldCrafter/>

<https://github.com/TencentARC/WorldCrafter>

HN 토론: <https://news.ycombinator.com/item?id=49884125> (1점, 0개 댓글)

GN 토론: <https://news.hada.io/topic?id=34977>

## 소개

WorldCrafter는 Tencent IEG 산하 ARC Lab과 베이징대학교 연구진이 만든
영상 월드 모델(video world model)이다.
이미지 한 장이나 텍스트 설명에서 시작해,
사용자가 카메라를 움직이는 대로 다음 장면을 영상으로 이어서 만든다.
논문 제목은
[WorldCrafter: Consistent Video World Model with Implicit 3D-aware Memory](https://arxiv.org/abs/2609.24984)이고,
2026년 9월 21일 arXiv에 올라왔다.
저자는 Wangbo Yu, Kunhao Liu 등 11명이며, Wenbo Hu가 교신 저자다.

풀려는 문제는 프로젝트 페이지 첫 문장에 그대로 나온다.
생성된 세계를 탐색하다가 고개를 돌렸다고
그 세계를 잃어버려서는 안 된다는 것이다.
영상 월드 모델은 최근 몇 프레임만 보고 다음 장면을 만들기 때문에,
한참 다른 곳을 보다가 처음 자리로 돌아오면
건물 모양이나 사물 배치가 바뀌어 있기 쉽다.
WorldCrafter는 지나간 장면을 따로 기억해 두었다가,
지금 카메라가 볼 시점에 맞춰 필요한 부분만 꺼내 생성기에 넘기는 방식으로
이 문제를 다룬다.

공개된 것은 두 모델의 가중치와 추론 코드,
키보드로 카메라를 움직이는 브라우저 데모와 그 서버 코드다.
저장소는 9월 14일에 만들어졌고, Hugging Face 가중치는 9월 21일에 올라왔다.
10월 8일 기준 GitHub 별은 461개, 포크는 17개, 열린 이슈는 2개다.
Hugging Face 오픈소스 팀의 Apolinario가 ZeroGPU 위에 데모 Space를 만들어
저자에게 넘겼고, 지금은 `Drexubery/worldcrafter-demo`에서 돌아간다.

이 문서는 README, 프로젝트 페이지, arXiv 논문 HTML판, `LICENSE.txt`,
Hugging Face 모델 카드와 파일 목록, 그리고 `git clone --depth 1`로 받은 코드를
읽고 썼다.
모델과 데모는 직접 실행하지 않았다.
아래의 품질, 속도 수치는 모두 논문과 문서가 밝힌 값이다.

## 동작 방식

### 청크 단위 자기회귀 생성

WorldCrafter는 영상을 한 번에 만들지 않고 33프레임짜리 청크를
하나씩 이어 붙인다.
VAE가 시간축을 4배 압축하므로 한 청크는 잠재 공간에서 9프레임이다.
출력 해상도는 640×384로 고정되어 있고, 기본 재생 속도는 16fps다.
카메라 동작 하나가 청크 하나를 만든다.

생성기는 Helios-base에서 출발했고, VAE와 텍스트 인코더는 Wan 계열의
`AutoencoderKLWan`과 UMT5를 쓴다.
Hugging Face에 올라간 트랜스포머 설정 파일의 클래스 이름도
`HeliosTransformer3DModel`이고, 40개 층과 40개 어텐션 헤드를 쓴다.
Helios-base의 원래 입력 창에는 압축된 16프레임 구간, 2프레임 구간,
직전 잠재 프레임, 어텐션 싱크 프레임이 들어 있었다.
WorldCrafter는 이 중 압축된 16프레임 구간을 빼고,
그 자리에 압축 안 한 4프레임 분량의 메모리 토큰을 넣었다.

### 3D 인식 메모리

핵심은 메모리 인코더와 메모리 판독(readout) 모듈이다.
첫 청크를 만든 뒤부터, 지금까지 생성한 잠재 프레임과 그 카메라 자세를
메모리 인코더가 읽어 장면 표현으로 바꾼다.
이 인코더는 Meta가 공개한 신규 시점 합성(novel view synthesis) 
모델 LagerNVS의 인코더에서 출발했다.
얕은 DINO 이미지 층을 떼어 내고, VAE 잠재 프레임을 바로 받는 
패치 임베딩 층을 새로 달았다.
판독 모듈은 LagerNVS 디코더의 얕은 층으로 초기화했다.

판독은 앞으로 갈 카메라 궤적에서 뽑은 질의 자세로 이루어진다.
같은 장면 표현이라도 지금 오른쪽을 볼 것인지 뒤를 볼 것인지에 따라
다른 메모리 토큰이 나온다.
논문은 이를 두고, 요청된 시점이 다중 시점 정보를
생성기의 제한된 토큰 예산으로 압축하는 방식을 정하게 한다고 설명한다.
판독 결과는 깊이 추정이나 기하 변환 없이,
DiT의 셀프 어텐션 입력 앞에 그대로 붙는다.

인코더에 넣을 과거 프레임은 무한히 늘릴 수 없으므로 고른다.
가장 최근 잠재 프레임 하나를 고정하고, 앞으로 볼 시점들의 시야를 
가장 넓게 덮는 조합을 탐욕적으로 8개 더 고른다.
코드의 `select_trajectory_fov_history`가 이 선택을 맡는데, 수평 시야각 100도,
가까운 거리 0.1m, 먼 거리 30m의 절두체를 축마다 10개씩 샘플링해
덮이는 영역을 센다.
기존 방식처럼 시점이 비슷한 프레임 순으로 고르면 비슷한 화면만 여러 장
들어올 수 있는데, 덮는 영역 기준으로 고르면 서로 보완하는 시점이 들어온다.

메모리는 지나간 장면을, 최근 프레임 문맥은 지금 진행 중인 움직임을 맡는다.
그래서 화면 밖으로 나갔다가 돌아오는 고양이나 따라가는 자동차 같은
움직이는 피사체도 다룰 수 있다는 것이 논문의 주장이다.

### 카메라 조건

카메라 자세는 PRoPE 방식의 상대 위치 인코딩으로 넣는다.
구현은 UCPE의 병렬 카메라 어텐션 분기를 썼으며,
이 분기는 메모리와 최근 문맥에는 적용하지 않고 지금 노이즈를 걷어 내는
청크에만 적용한다.

### 학습과 증류

학습은 네 단계다.
Open-Sora-Plan 영상 76만 개로 바뀐 입력 창에 적응시키고, 카메라 분기를 학습하고,
메모리 인코더를 VAE 잠재 프레임에 맞게 예열한 뒤, 마지막에 인코더와 판독 모듈,
DiT, 카메라 분기를 함께 학습한다.
데이터는 Open-Sora-Plan, DL3DV, 합성 영상 MIND이고,
카메라 자세는 Depth Anything 3로, 캡션은 Qwen2.5-VL로 붙였다.
단계마다 GPU 16~32개를 썼다고 적혀 있다.

빠른 버전은 Helios를 따라 3단계 해상도 피라미드에 해상도마다 2번씩 
노이즈를 걷어 내는 방식으로 분포 매칭 증류(DMD)를 했다.
합성 데이터를 넣으면 피사체를 잘 따라가지만 질감이 뭉개지는 문제가 있어서,
노이즈가 큰 단계와 작은 단계를 서로 다른 데이터로 증류한 두 모델로 나눴다.
마지막 한 단계만 작은 노이즈 모델이 맡는다.
논문은 이렇게 증류한 WorldCrafter-fast가 GPU 4개 장비에서 
초당 16프레임을 낸다고 밝혔다.

## 공개 범위

### 가중치

| 모델              | 내용                                                                       | 받는 용량 |
| ----------------- | -------------------------------------------------------------------------- | --------- |
| WorldCrafter-Base | 140억 매개변수 트랜스포머, 카메라 어댑터, LoRA                             | 약 59.5GB |
| WorldCrafter-Fast | 높은 노이즈와 낮은 노이즈 두 트랜스포머, 메모리 인코더, 텍스트 인코더, VAE | 약 147GB  |

용량은 Hugging Face API의 파일 크기를 더한 값이다.
Base는 메모리 인코더, 텍스트 인코더, VAE를 Fast 폴더에서 빌려 쓰므로,
Base만 돌리려 해도 Fast를 함께 받아야 한다.
이미지에서 프롬프트를 자동으로 쓰는 기능을 쓰려면 
Qwen3-VL-4B-Instruct도 따로 받는다.

공개되지 않은 것도 있다.
학습 코드와 학습 데이터 구성 스크립트는 저장소에 없다.
프로젝트 페이지와 GN 소개 글은 이미지 여러 장을 넣어 새 시점을 만드는 기능을
보여 주지만, 공개된 CLI의 `--mode`는 `i2v`와 `t2v` 두 가지뿐이고
코드에서도 다중 이미지 입력 경로는 찾지 못했다.
논문 표에 나온 벤치마크 145장과 궤적 725개도 공개되지 않았다.

### 라이선스

`LICENSE.txt`의 자체 조건은 MIT 형식 문구에 한 줄을 더한 것이다.
학술 목적에만 쓰고, 어떤 경우에도 상업이나 프로덕션 목적으로 
쓰지 않는다는 조건이다.
GitHub는 이 라이선스를 `Other`로 표시한다.

여기에 세 가지 상류 구성 요소의 조건이 겹친다.
생성기의 출발점인 Helios-Base는 Apache-2.0이고,
메모리 인코더 코드에 들어간 VGGT는 CC-BY-NC-4.0,
LagerNVS에서 온 부분은 Meta의 FAIR Noncommercial Research License다.
즉 Tencent가 상업 사용을 허락하더라도 메모리 인코더 쪽 두 라이선스가
비상업 조건을 따로 건다.

### 요구 환경

공식 설치 안내는 Linux, Python 3.11, NVIDIA GPU를 전제로 하며,
PyTorch 2.10과 CUDA 12.8 환경을 `uv` 잠금 파일로 고정한다.
Fast 추론 코드는 CUDA가 없으면 바로 오류를 낸다.
FlashAttention 3 커널은 Hopper(SM90) GPU에서만 쓰고,
그 밖에는 FlashAttention 2나 기본 어텐션으로 내려간다.

필요한 GPU 메모리 양은 어디에도 수치로 적혀 있지 않다.
데모 안내는 NVIDIA H200 1장과 2장에서 검증했다고만 밝힌다.
2장 모드는 어텐션 질의를 나눌 뿐, GPU마다 모델 전체를 올린다.
`worldcrafter/fast/resident.py`의 설명에 따르면 Fast는 높은 노이즈와 낮은 노이즈
두 체크포인트를 모두 GPU에 상주시키는데,
하나를 BF16 모델로 올리고 다른 하나는 비트 차이를 압축해 두었다가 
단계가 바뀔 때 GPU 안에서 바꿔 쓴다.
140억 매개변수를 BF16으로 올리면 트랜스포머만 약 28GB라는 것은
계산으로 나오지만,
텍스트 인코더와 활성값까지 더한 실제 최대 사용량은 문서에 없다.
소비자용 24GB GPU에서 돌아간다는 근거는 찾지 못했다.

## 코드 구조

저장소의 파이썬 코드는 테스트를 포함해 약 1만 5천 줄이다.

| 경로                                  | 역할                                                      |
| ------------------------------------- | --------------------------------------------------------- |
| `inference.py`, `worldcrafter/cli.py` | 이미지·텍스트에서 영상을 만드는 명령줄 진입점             |
| `worldcrafter/diffusers/`             | Diffusers 형식의 파이프라인, 트랜스포머, 스케줄러         |
| `worldcrafter/repencoder/`            | 메모리 인코더, VGGT 기반 백본, 시야 기준 과거 프레임 선택 |
| `worldcrafter/ucpe/`                  | UCPE와 PRoPE 카메라 조건 어텐션                           |
| `worldcrafter/fast/`                  | 증류 모델용 두 분기 상주, 타임스텝 격자, 2GPU 병렬        |
| `worldcrafter/kernels/`               | Triton으로 쓴 RoPE, RMSNorm, 어텐션 백엔드 선택           |
| `demo/`                               | FastAPI와 웹소켓 서버, 키보드 조작 웹 화면                |
| `tools/`                              | 카메라 궤적 생성과 단위 테스트                            |

카메라 궤적은 `forward1x2`, `yaw_left30`, `orbit_left15`,
`reverse2` 같은 동작 문자열로 쓸 수 있다.
`reverseN`은 직전 N개 청크의 경로를 되짚어 가는 동작이라,
갔다가 돌아왔을 때 같은 장면이 나오는지 시험하기 좋다.
동작 문자열 대신 프레임마다 카메라→월드 행렬을 담은 `.npy` 파일을 줄 수도 있다.

데모는 `python -m demo --model-path weights/WorldCrafter-Fast`로 띄우고
`localhost:8080`에 접속한다.
W/S/A/D로 이동, 방향키로 제자리 회전, I/J/K/L로 앞쪽 한 점을 중심으로 공전한다.
한 세션만 동시에 생성할 수 있고, 인증 기능이 없으므로 
외부에 열려면 인증 프록시를 앞에 두라고 안내한다.
데모 프리셋 6개 중 5개의 ID는 `projectgenie__`로 시작한다.

## 실험 결과

논문은 직접 만든 벤치마크로 평가했다.
이미지 145장에 카메라 궤적을 5개씩 붙여 방법마다 영상 725개를 만들고,
궤적은 528~1,648프레임 길이에 처음 자리로 돌아오는 구간을 포함한다.
이미지 출처는 HappyOyster, Project Genie, 웹, GPT-Image2 생성 이미지이며,
동적 장면 83개와 정적 장면 62개다.
비교 대상은 DreamX-World, Alaya-EVOKE, HY-WorldPlay, Lyra 2.0, Echo-WM,
LingBot-World 2, Matrix-Game 3.5, SANA-WM 여덟 가지다.

| 지표                        | 가장 좋은 비교 대상  | WorldCrafter | WorldCrafter-fast |
| --------------------------- | -------------------- | ------------ | ----------------- |
| 재방문 LPIPS(낮을수록 좋음) | 0.487 (Lyra 2.0)     | 0.255        | 0.186             |
| 재방문 PSNR(높을수록 좋음)  | 14.050 (Lyra 2.0)    | 18.016       | 20.868            |
| 회전 오차(낮을수록 좋음)    | 16.145 (Lyra 2.0)    | 13.536       | 18.251            |
| VBench 종합(높을수록 좋음)  | 81.406 (Alaya-EVOKE) | 81.910       | 80.285            |

재방문 일관성은 처음 본 프레임과 돌아와서 본 프레임을 MEt3R, LPIPS, PSNR,
SSIM으로 비교했다.
네 지표 모두 WorldCrafter 두 모델이 1, 2위이고, 오히려 증류한 fast가 가장 좋다.
카메라 제어 정확도는 생성 영상에서 VGGT-Ω로 궤적을 다시 추정해 
목표 궤적과 맞춰 봤으며, Base가 세 지표 모두 1위, fast는 3위다.

절제 실험에서는 메모리 토큰 대신 과거 프레임 4장을 그대로 넣으면 
재방문 LPIPS가 0.255에서 0.497로 나빠졌다.
메모리 인코더를 얼려 두거나, 판독에서 질의 자세를 빼거나,
덮는 영역 대신 유사도로 과거 프레임을 고르는 경우도 모두 나빠졌다.
깊이 기반 공간 메모리와 비교하면, 깊이 추정과 변환에 청크당 1.346초가 드는 반면
WorldCrafter의 메모리 인코딩과 판독은 0.062초로 21.7배 빠르다.

논문이 스스로 밝힌 한계는 두 가지다.
특히 복잡하거나 긴 궤적에서는 일관성이 여전히 깨질 수 있고,
청크마다 과거를 다시 인코딩하는 데 지연이 생긴다.

## 분석

### 기억을 장면 전체가 아니라 다음 시점의 질문으로 바꿨다

월드 모델의 기억 문제에 대한 기존 답은 크게 둘이었다.
과거 프레임을 그대로 어텐션에 넣는 문맥 메모리는 시야가 넓어질수록
비용이 커지고, 몇 장만 고르면 빠뜨리는 곳이 생긴다.
깊이를 추정해 3D 점이나 메시로 만든 다음 새 시점으로 변환하는 공간 메모리는
정적인 장면에 강하지만, 움직이는 물체가 있으면 정렬이 오히려 족쇄가 된다.

WorldCrafter의 선택은 기억의 단위를 장면에서 질의로 바꾼 것이다.
장면 전체를 일관된 3D로 유지하려 하지 않고,
이번 청크가 볼 시점에 무엇이 보여야 하는지만 고정된 토큰 수로 뽑아 준다.
절제 실험에서 질의 자세 없는 판독보다 질의 자세 있는 판독이 낫다는 결과가
이 설계의 근거다.
토큰 예산이 고정되어 있을 때, 어디를 볼지 알려 주면 그 예산을 
관련 있는 정보에 쓸 수 있다는 것이다.

### 신규 시점 합성 모델을 기억 장치로 다시 쓴다

이 설계가 가능해진 배경에는 신규 시점 합성 분야의 발전이 있다.
LagerNVS 같은 모델은 여러 장의 사진에서 장면을 압축한 뒤 
새 시점의 이미지를 만들도록 학습되었으므로,
기하와 외관을 함께 담는 표현을 이미 가지고 있다.
WorldCrafter는 이 인코더를 가져와 입력층만 VAE 잠재 공간에 맞게 갈아 끼우고,
디코더 앞부분을 판독 모듈로 썼다.

논문은 VGGT처럼 기하 추정용으로 사전 학습한 표현은 외관 재현에 약하다고
지적하며 이 선택을 정당화한다.
이미지를 다시 그려야 하는 과제로 학습한 표현이 기억 장치로 더 알맞다는 논리다.
3D 재구성 연구와 영상 생성 연구가 서로의 부품을 빌려 쓰는 흐름이 
한 단계 더 진행된 셈이다.

### 연구 공개와 서비스 공개 사이에 놓인 저장소

저장소의 결은 연구 코드보다 서비스 쪽에 가깝다.
`uv` 잠금 파일, Triton 커널, 두 분기를 GPU 안에서 바꿔 쓰는 상주 구조,
웹소켓 데모 서버와 단위 테스트까지 갖췄다.
README도 인터랙티브 데모 코드와 서빙 인프라를 전부 오픈소스로 
공개한다는 점을 굵게 강조한다.

반면 학습 코드와 벤치마크는 없고, 라이선스는 상업 사용을 막는다.
누구나 써 볼 수는 있지만 재현하거나 제품에 넣을 수는 없는 형태다.
저자가 Hugging Face 팀이 만든 무료 GPU 데모를 넘겨받아 
자기 계정에서 운영하는 것도 같은 방향이다.

## 비평

### 재방문 일관성 지표는 덜 움직이는 모델을 유리하게 본다

재방문 지표에서 증류한 fast가 Base보다 좋다는 결과는 그냥 넘기기 어렵다.
보통 증류는 품질을 조금 내주고 속도를 얻는데, 여기서는 기억력이 오히려 좋아졌다.
같은 표에서 fast는 카메라 회전 오차가 18.251로 Base의 13.536보다 크다.

해석하자면, 카메라를 덜 정확히 따라가거나 장면 변화가 적으면 
처음 본 프레임과 돌아온 프레임이 더 비슷해진다.
VBench의 동적 정도(DD)에서 WorldCrafter는 96.893,
fast는 96.505로 여덟 비교 대상 모두보다 낮다.
LingBot-World 2와 Matrix-Game 3.5는 이 값이 100이다.
움직임이 적은 모델일수록 재방문 지표에서 이득을 보는 구조라면,
47.6% 개선이라는 숫자 일부는 기억이 아니라 보수적인 생성에서 왔을 수 있다.
논문은 이 상관을 따로 분리해 보지 않는다.

### 자기가 만든 벤치마크에서 자기가 이겼다

벤치마크 145장과 궤적은 저자들이 직접 골랐고, 공개되지 않았다.
궤적은 처음 자리로 돌아오는 구간을 일부러 포함하는데,
이는 정확히 WorldCrafter가 풀려는 문제다.
비교 대상 중 일부는 증류 모델로, 일부는 전체 단계 모델로 평가했고,
모든 영상을 640×384로 줄여 맞췄다.
이 해상도는 WorldCrafter의 고정 출력 해상도와 같다.

여덟 개의 비교 대상을 같은 조건으로 돌린 수고는 인정할 만하다.
그러나 벤치마크가 공개되지 않으면 다른 연구진이 같은 표를 다시 만들 수 없고,
궤적 설계가 특정 방법에 유리했는지도 따져 볼 수 없다.
`reverseN` 같은 되짚기 동작이 데모 코드에 들어 있는 것은 반가운 일이지만,
논문 표를 재현할 수 있게 해 주지는 않는다.

### 실시간이라는 말은 데이터센터 GPU 4장에 걸려 있다

논문 초록은 스트리밍 탐색을, 본문은 실시간 스트리밍 추론을 말한다.
그 근거는 GPU 4개 장비에서 초당 16프레임이라는 한 문장이며,
GPU 종류는 적혀 있지 않다.
공개 데모는 H200 1장과 2장에서 검증했다고 하는데,
이 구성에서 몇 fps가 나오는지는 밝히지 않았다.
33프레임 청크 하나가 16fps로 약 2초 분량이므로,
실시간이라면 청크 하나를 2초 안에 만들어야 한다.

받아야 할 가중치는 Fast만 147GB이고, 필요한 GPU 메모리는 
문서 어디에도 숫자로 없다.
GN 소개 글은 브라우저 데모와 서버 코드를 공개했다는 점을 앞세우지만,
그 데모를 직접 띄울 수 있는 사람은 H200급 장비를 가진 연구실로 좁혀진다.
대부분의 사람에게 실제 체험 경로는 Hugging Face의 ZeroGPU Space 하나다.

### 소개된 기능과 공개된 기능이 다르다

프로젝트 페이지는 이미지 1장, 2장, 3장에서 새 시점을 만드는 예시를 보여 주고,
GN 요약도 이를 지원 기능으로 적었다.
그러나 공개된 추론 코드는 이미지 한 장 또는 텍스트에서 
시작하는 두 모드만 받는다.
다중 이미지 신규 시점 합성은 논문 본문에도 실험이 없다.

프로젝트 페이지의 텍스트 생성 설명에는 WorldCore라는 
다른 이름이 한 번 남아 있다.
작은 흔적이지만, 공개 자료가 내부 버전과 완전히 맞춰지지 않은 채 
나왔다는 신호로 읽힌다.
사용자는 데모 영상이 아니라 `--mode` 선택지를 기준으로 기대치를 잡아야 한다.

## 인사이트

### 월드 모델의 기억은 결국 캐시 설계 문제가 된다

WorldCrafter가 하는 일을 시스템 용어로 바꾸면,
무한히 늘어나는 과거 기록에서 고정 크기 캐시를 매번 다시 채우는 일이다.
덮는 영역을 기준으로 과거 프레임 8개를 고르는 것은 캐시 교체 정책이고,
질의 자세로 토큰을 뽑는 것은 접근 패턴을 미리 아는 프리페치다.
논문의 한계로 적힌 청크마다 다시 인코딩하는 지연은,
증분 갱신이 안 되는 캐시의 전형적인 비용이다.

이렇게 보면 다음 연구의 방향도 예측할 수 있다.
논문이 제안한 자기회귀 스트리밍 메모리 인코더는 캐시를 처음부터 다시 만들지 않고
변경분만 반영하는 방식이다.
그다음에는 무엇을 오래 기억하고 무엇을 버릴지,
즉 기억의 수명 정책이 문제로 떠오를 것이다.
게임 엔진이 수십 년 동안 다룬 스트리밍과 LOD 문제가 신경망 안에서 
다시 시작되는 셈이다.

### 오픈 월드 모델의 경쟁 단위가 구성 요소의 라이선스로 옮겨 간다

WorldCrafter의 가중치는 공개되었지만, 그 안에는 Apache-2.0, CC-BY-NC-4.0,
FAIR 비상업 라이선스가 층층이 겹쳐 있다.
Tencent가 자체 조건을 풀어 준다 해도, 메모리 인코더가 LagerNVS와 VGGT에서 왔다는
사실은 남는다.
절제 실험에서 성능 향상의 중심으로 드러난 메모리 인코더가,
가장 제한적인 라이선스를 가진 부품이라는 점이 눈에 띈다.

해석하자면, 앞으로 오픈 월드 모델을 상업적으로 쓰려는 쪽은 성능표보다 부품
목록을 먼저 보게 된다.
3D 표현 학습 모델의 라이선스가 영상 월드 모델 생태계의 
상업적 상한을 정하는 구조다.
같은 아이디어를 Apache 계열 3D 인코더로 다시 학습한 파생 연구가 나온다면,
그쪽이 실제 제품에는 더 빨리 들어갈 것이다.

### 데모 입력이 경쟁 제품의 출력이라는 사실

데모 프리셋의 대부분이 `projectgenie__`로 시작하고,
벤치마크 이미지에도 Google DeepMind의 Project Genie와 HappyOyster에서 가져온
것이 들어 있다.
폐쇄형 월드 모델이 만든 화면이 오픈 월드 모델의 평가 입력이 된 것이다.
저장소의 다른 문서 `ai/world-labs-amd.md`가 다룬 World Labs처럼,
이 분야의 상용 서비스는 대부분 닫혀 있다.

이것은 기준점이 어디 있는지를 보여 준다.
오픈 연구진은 Genie 3를 직접 돌려 비교할 수 없으므로,
그 결과물의 첫 장면을 가져와 같은 출발점에서 얼마나 오래 버티는지를 본다.
해석하자면, 폐쇄형 모델의 첫 프레임 품질과 오픈 모델의 기억력이 따로 경쟁하는
구도가 당분간 이어질 것이다.

### 일관성이 해결되면 사람이 만드는 3D 장면의 역할이 바뀐다

`design/artcraft.md`는 모델이 공간을 기억하지 못하니 사람이 3D 장면을 직접
만들어 넘기는 접근을 다뤘다.
WorldCrafter가 보여 준 것은 3D 재구성을 명시적으로 하지 않고도,
돌아왔을 때 같은 장면이 나오는 수준까지 갈 수 있다는 가능성이다.
논문이 생성 영상에서 점구름을 다시 뽑아 보여 주는 것도,
결과가 3D로 일관되다는 증거를 거꾸로 제시하는 방식이다.

이 흐름이 이어지면 3D 장면은 생성의 입력이 아니라 생성 결과를 
검증하는 도구가 된다.
사람이 블로킹한 3D 장면은 카메라 경로와 배치를 지정하는 의도 표현으로 남고,
실제 외관은 모델이 채운다.
WorldCrafter의 카메라 동작 문자열과 `.npy` 궤적 입력은 그 의도 표현이 이미 어떤
모양인지 보여 주는 초기 사례다.
