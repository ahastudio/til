# ComfyUI는 노드 그래프로 이미지, 영상, 오디오, 3D 생성 워크플로를 짜는 로컬 우선 AI 엔진이다

<https://www.comfy.org/>

<https://github.com/Comfy-Org/ComfyUI>

HN 토론: <https://news.ycombinator.com/item?id=34543897> (4점, 1개 댓글)

## 소개

ComfyUI는 Comfy Org가 관리하는 GPL-3.0 오픈 소스 프로젝트이다.
README는 스스로를 콘텐츠 제작을 위한 가장 강력하고 모듈식인 AI 엔진이라
소개하고,
저장소 설명은 그래프와 노드 인터페이스를 가진 확산 모델(diffusion model) GUI,
API, 백엔드라고 적는다.
이 문서가 읽은 시점(2026-11-03)에 GitHub 저장소는 별 약 14만 5천 개, 포크 약 1만
7천 개, 언어는 Python이며
2023-01-17에 만들어졌고 마지막 푸시는 2026-11-03이었다.
열린 이슈 항목은 5,421개로 표시되는데 이 수에는 풀 리퀘스트도 들어간다.

README는 특징을 이렇게 내세운다.
- 최신 성능(state of the art)의 오픈 소스 모델을 기본으로 지원한다.
- 로컬 소비자 하드웨어에 집중한 확산 모델 추론 엔진 중 세계에서 가장 최적화된 것이라고 주장한다.
- 비동기 가중치 스트리밍(asynchronous weight streaming)으로 가장 큰 오픈 소스 모델도 VRAM 4GB와 RAM 8GB에서 비교적 빠르게 돌릴 수 있다고 한다.
- 파트너 노드(Partner nodes)로 Nano Banana, Seedance, Hunyuan3D 같은 비공개 모델에 접근한다.
- Windows, Linux, macOS에서 데스크톱 앱, 포터블 설치, 클라우드로 쓸 수 있다.
- 복잡한 워크플로를 단순한 UI로 노출하는 App Mode와 API 엔드포인트로 제작 파이프라인에 통합한다.

## 주요 기능

README의 기능 목록은 크게 네 묶음이다.
첫째, 코드 없이 이미지, 영상, 오디오, 3D, 텍스트 워크플로를 만들고 재사용하는
시각적 노드 그래프,
재사용 가능한 서브그래프, 워크플로 템플릿, App Mode, 로컬 API이다.
둘째, 비동기 대기열, 그래프 부분 재실행, VRAM과 RAM의 지능적 관리, 모델
오프로딩, 양자화 모델 지원이다.
셋째, 넓은 모델 지원이며 README는 대표 목록이라고 밝힌다.

| 분야          | 예시                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------- |
| 이미지 생성   | Stable Diffusion 1.5, SDXL, SD3.5, Flux.1, Flux.2, Qwen Image, Z-Image, HiDream, Moss Image 등 |
| 이미지 편집   | Flux Kontext, Flux.2 Klein, Qwen Image Edit, OmniGen2 등                                       |
| 영상 생성     | Wan 2.1과 2.2, LTX-Video 2와 2.3, HunyuanVideo 1.5, CogVideoX, Mochi 등                        |
| 오디오와 영상 | MiniMax H3, LTX-AV                                                                             |
| 오디오 생성   | ACE-Step 1.5, Stable Audio 3, MiniMax Music 3, Yue 2                                           |
| 3D와 비전     | Hunyuan3D 2.1, SeedVR2, SUPIR, Depth Anything 3, SAM 3과 3.1, BiRefNet 등                      |
| 텍스트 생성   | Gemma 3과 4, Qwen3, Qwen3.5, Qwen3-VL                                                          |

넷째, 체크포인트나 개별 모델, VAE, 텍스트 인코더, LoRA, ControlNet, 업스케일러를
불러오고,
인페인팅, 아웃페인팅, 마스크 합성, 모델 병합, 업스케일, 프레임 보간, 분할, 깊이
추정 같은 도구를 내장한다.
워크플로를 JSON으로 저장하고 불러올 수 있으며,
생성된 PNG를 화면에 끌어다 놓으면 사용된 시드를 포함한 전체 워크플로가
복원된다고 한다.
16비트 PNG, 32비트 EXR, 10비트 AVIF 같은 높은 비트 심도와 HDR 저장도 지원한다.

오프라인 동작도 명시한다.
핵심은 요청하지 않으면 아무것도 내려받지 않으며,
`--offline`은 선택적 유료 Comfy API 노드를 끄고 내장 기능을 오프라인으로
강제하고,
`--disable-partner-nodes`는 API 노드만 끈다고 한다.
커스텀 노드로 기능을 확장하고 `extra_model_paths.yaml`로 추가 모델 위치를
지정한다.

## 설치와 실행

가장 쉬운 방법은 Windows와 macOS용 데스크톱 앱이고 README는 신규 사용자에게 이를
권한다.
Windows 포터블 빌드는 NVIDIA GPU 또는 CPU용이며 일반 사용자에게는 권하지
않는다고 한다.
AMD, Intel용 포터블 빌드도 있고, 구형 NVIDIA 10 시리즈 이하는 CUDA 12.6과 Python
3.12 빌드를 쓰며
20 시리즈 이상에서는 쓰지 말라고 경고한다.
`comfy-cli`로 설치할 수도 있다.

```bash
pip install comfy-cli
comfy install
```

수동 설치는 Python 3.13이 가장 잘 지원되고 3.14도 동작하지만 일부 커스텀 노드에
문제가 있을 수 있다고 한다.
PyTorch는 2.7이 최소 지원이고 더 새로운 버전을 강하게 권하며,
NVIDIA 20 시리즈 이상은 CUDA 13.0 이상 빌드가 필요하다고 한다.
README는 AMD(ROCm), Intel Arc(`torch.xpu`), NVIDIA, Apple 실리콘, Huawei
Ascend NPU,
Cambricon MLU, Iluvatar Corex의 설치 방법을 각각 안내한다.
실행은 `python main.py`이다.

ComfyUI-Manager는 커스텀 노드를 설치하고 갱신하는 확장이고
`python main.py --enable-manager`로 켠다.
`--disable-manager-ui`는 UI와 엔드포인트를 끄면서 보안 점검과 예약 설치 완료
같은 백그라운드 기능은 유지한다고 한다.

### 릴리스 방식

ComfyUI는 월요일을 목표로 한 주간 릴리스 주기를 따르지만 모델 출시나 큰 변경
때문에 자주 바뀐다고 한다.
관련 저장소는 셋이다.
코어는 약 2주마다 메이저 안정 버전(예: v0.7.0)을 내고,
v0.4.0부터 패치 버전은 현재 안정 릴리스로 백포트한 수정에 쓴다.
안정 릴리스 태그 밖의 커밋은 매우 불안정해 많은 커스텀 노드를 깨뜨릴 수 있다고
경고한다.
Comfy Desktop은 최신 안정 코어로 릴리스를 만들고,
ComfyUI Frontend는 2주 이상마다 코어 저장소에 병합되며 2024-08-15부터 별도
저장소로 옮겨졌다.
최신 프런트엔드는 `--front-end-version Comfy-Org/ComfyUI_frontend@latest`로 쓸
수 있다.

### 사용 메모

README의 노트는 몇 가지 동작을 알려 준다.
출력이 있고 입력이 모두 맞는 부분만 실행되고,
이전 실행에서 바뀐 부분만 다시 실행되므로 같은 그래프를 두 번 제출하면 처음만
실행된다.
프롬프트에서 `(good code:1.2)`처럼 괄호로 강조를 바꾸고(기본 1.1),
`{day|night}`로 실행마다 무작위 선택되는 동적 프롬프트를 쓴다.
고품질 미리보기는 `--preview-method auto`이고 TAESD 디코더 파일이 필요하며,
TLS는 `--tls-keyfile`과 `--tls-certfile`로 켠다.
지원은 Discord와 Matrix 공간으로 안내하고, 프런트엔드 문제는 별도 저장소에
제기하라고 한다.

## 분석

### ComfyUI의 중심 설계는 모델 하나가 아니라 그래프로 파이프라인을 조립하는 것이다

기능 목록을 보면 이 프로젝트는 특정 모델의 UI가 아니라 입력과 출력을 가진 노드를
연결하는 실행기이다.
그래서 이미지, 영상, 오디오, 3D, 텍스트 모델을 같은 방식으로 추가하고,
그래프의 변경된 부분만 다시 실행하는 최적화도 같은 구조에서 나온다.
README가 새 모델의 지원 목록을 길게 싣고 관리되는 템플릿 라이브러리를
가리키는 것도,
모델 지원이 노드 추가라는 단위로 쪼개져 있기 때문으로 읽힌다.
이 해석은 README의 서술에서 이 문서가 정리한 것이다.

### 로컬 우선과 유료 클라우드를 한 제품에 둔다

README는 로컬 실행, 오프라인 동작(`--offline`)을 내세우면서
같은 문서에서 비공개 모델용 파트너 노드와 유료 Comfy Cloud를 안내한다.
오프라인 플래그가 선택적 유료 API 노드를 끈다는 서술은 두 모델이 한 코드 안에
공존함을 보여 준다.
로컬 하드웨어를 갖지 못한 사람을 위한 공식 유료 클라우드라고 스스로 소개한다.

## 비평

### 성능 주장은 근거가 README에 없다

README는 세계에서 가장 최적화된 확산 모델 추론 엔진이라고 하고,
VRAM 4GB와 RAM 8GB에서 가장 큰 오픈 소스 모델을 비교적 빠르게 돌린다고 쓴다.
비교 대상, 모델, 해상도, 속도 수치가 같은 문서에 없다.
“비교적 빠르게”의 기준도 적혀 있지 않다.
이 문서는 이 성능을 직접 측정하지 못했고 프로젝트의 주장으로만 전한다.

### 설치 절차가 하드웨어마다 갈라져 사용자에게 부담이 크다

NVIDIA만 해도 안정 버전과 야간 빌드, CUDA 13.0 이상 요건, 구형 GPU 전용 빌드가
따로 있고,
AMD는 리눅스와 윈도, 그리고 ROCm 버전에 따라 명령이 다르며,
일부 AMD 카드는 `HSA_OVERRIDE_GFX_VERSION` 환경 변수를 직접 설정해야 한다.
이 복잡성을 줄이려고 README가 데스크톱 앱을 먼저 권하는 것으로 보이지만,
데스크톱 앱은 Windows와 macOS만 지원한다고 적혀 있어 Linux 사용자는 수동 설치를
해야 한다.

### 릴리스 경고가 커스텀 노드 생태계의 취약성을 드러낸다

README는 안정 태그 밖의 커밋이 매우 불안정해 많은 커스텀 노드를 깨뜨릴 수
있다고 적고,
Python 3.14에서 일부 커스텀 노드에 문제가 있을 수 있다고도 한다.
핵심 저장소와 확장이 서로 다른 속도로 움직여 사용자가 호환성을 직접 맞춰야
한다는 뜻이다.
ComfyUI-Manager가 보안 점검 기능을 둔다고 한 점은 커스텀 노드가 외부 코드라는
점을 전제한다.
커스텀 노드가 임의 코드를 실행한다는 위험은 이 문서의 추론이며 README가 직접
설명하지는 않는다.

### 커뮤니티 반응은 이 저장소 주소 기준으로 거의 없다

HN에서 이 저장소의 이전 주소(`comfyanonymous/ComfyUI`)를 올린 글은 여럿 있지만 모두 점수가 낮고 댓글이 거의 없다.
이 문서가 확인한 가장 큰 스레드는 2023년의 한 건(4점, 댓글 1개)이고,
댓글은 r/stablediffusion에도 공유해 보라는 제안이어서 본문에 반영할 내용이
없었다.[^edkennedy]

## 인사이트

### 처음 쓰는 사람은 설치 방법보다 워크플로 템플릿에서 시작하는 편이 낫다

README가 가리키는 템플릿 워크플로 라이브러리는 모델별로 준비된 그래프이다.
노드를 처음부터 연결하는 대신 템플릿을 불러와 입력을 바꾸는 방식이면 학습
비용이 낮다.
PNG를 끌어다 놓으면 워크플로가 복원된다는 기능도 남이 만든 결과물을 출발점으로
삼는 데 쓸 수 있다.
이것은 README의 기능에서 이 문서가 끌어낸 사용 제안이다.

### 업데이트는 안정 태그에만 고정하는 것이 안전하다

릴리스 방식과 경고를 읽으면 실사용 환경에서는 master가 아니라 안정 릴리스
태그를 쓰고,
커스텀 노드를 추가한 뒤에는 Python과 PyTorch 버전을 README의 지원 범위 안에
두어야 한다.
버전을 올릴 때는 쓰는 커스텀 노드가 새 버전에서 동작하는지 먼저 확인한다.

### 이 프로젝트의 주장을 확인하는 관찰

같은 모델과 해상도를 4GB VRAM GPU에서 돌려 다른 UI와 생성 시간, 메모리 사용을
비교하면
“세계에서 가장 최적화되었다”는 주장을 판단할 수 있다.
비교에서 차이가 작다면 이 프로젝트의 가치는 속도보다 노드 그래프와 모델 지원
범위에 있다고 읽어야 한다.
