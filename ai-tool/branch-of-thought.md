# Branch of Thought: Claude·ChatGPT 대화에서 편집으로 갈라진 분기를 그래프로 보는 확장 프로그램

Show GN: [Branch of Thought – Claude·ChatGPT 대화의 숨은 분기를 그래프로](https://news.hada.io/topic?id=31007)

## 소개

GeekNews에 Show GN으로 올라온 개인 프로젝트다.
Claude나 ChatGPT에서 메시지를 편집하면 대화는 조용히 새 분기로 갈라지고, 이전 대화는 작은 `‹ 2/3 ›` 화살표 뒤로 묻힌다.
작성자는 돌아가고 싶은 분기를 자꾸 놓치는 것이 불편해 직접 만들었다고 한다.

확장 프로그램은 사이드 패널에 대화 전체를 분기 트리 그래프로 그린다.
대화가 어디서 갈라졌는지 한눈에 보이고 현재 경로가 강조되며, 노드를 누르면 그 버전의 메시지 전문을 질문과 답변 쌍으로 읽을 수 있다.
강조를 다른 노드로 옮겨 버려 둔 분기를 따라가거나, 노드를 끌어 배치를 바꾸거나(배치는 대화별로 유지된다), 그래프를 인터랙티브 HTML, PNG, SVG로 내보낼 수 있다.

코드는 GitHub의 `ijzereen/branch-of-thought`에 MIT 라이선스로 공개되어 있고, 2026년 7월 1일에 만들어졌다.
작성자는 웹 스토어에 올리지 않았고 앞으로도 올리지 않을 것이라며, 압축 해제 상태로 직접 로드하는 방식이라 실행 전에 코드가 정확히 무엇을 하는지 확인할 수 있다고 쓴다.
첫 브라우저 확장이라 거친 부분이 많다며 접근 방식, UX, 놓친 경계 사례에 대한 피드백을 요청했다.

## 동작 방식

### 이미 받아온 응답을 가로챈다

작성자의 설명으로는 Manifest V3 기반이고, 페이지의 MAIN world에서 도는 콘텐츠 스크립트가 브라우저가 이미 받아온 대화 데이터를 읽는다.
저장소의 `src/interceptor.js` 주석은 이것을 더 구체적으로 적는다.
MAIN world에서 돌아야 각 채팅 앱이 쓰는 바로 그 `window.fetch`와 `XMLHttpRequest`를 패치할 수 있고, 대화 응답이 지나가면 공통 형태로 정규화해 ISOLATED world의 콘텐츠 스크립트에 `CustomEvent`로 문자열 형태로 넘긴다.
월드 사이에서 객체를 직접 주고받을 때의 문제를 피하려고 문자열로 보낸다는 설명이다.

`manifest.json`은 이 두 스크립트를 `document_start`에 올린다.
가로채기 스크립트는 페이지가 첫 요청을 보내기 전에 `fetch`를 감싸야 하므로 이 시점이 필요하다.

### 두 플랫폼을 한 모양으로 접는다

작성자가 가장 까다로웠다고 꼽은 것은 Claude와 ChatGPT가 대화를 저장하는 구조가 완전히 다르다는 점이다.
ChatGPT는 `mapping` 트리를 노출하는데 Claude는 그렇지 않아서, 둘을 같은 형태로 접어 넣는 정규화기를 만들었고, 그 아래 로직은 모두 플랫폼과 무관하게 동작한다.

코드의 공통 형태는 대화 `uuid`, 플랫폼, 현재 잎 메시지 `current_leaf_message_uuid`, 그리고 각 메시지의 `uuid`, `parent_message_uuid`, 보낸 쪽(`human` 또는 `assistant`), 본문, 순서, 생성 시각의 목록이다.
Claude 응답은 `chat_messages` 배열을 이 형태로 옮긴다.
ChatGPT 응답은 `/backend-api/conversation/{id}`의 `mapping`에서 사용자와 어시스턴트 메시지만 남기고, 시스템과 도구 메시지, 화면에 숨겨진 보조 메시지, 도구 호출 경로, 추론 요약 같은 텍스트가 아닌 내용은 건너뛴다.
건너뛴 노드 때문에 끊긴 관계는 각 노드를 가장 가까운 남은 조상에 다시 잇는 방식으로 복원한다.

### 제목은 선택적으로 Haiku가 붙인다

노드 라벨은 기본적으로 메시지 원문이다.
설정에서 Anthropic API 키를 넣으면 노드마다 Claude Haiku가 한 줄 제목을 붙인다.
README는 일부러 싸게 만들었다고 설명한다.
처음에는 활성 경로만 요약하고 나머지는 마우스를 올릴 때 요약하며, 메시지는 바뀌지 않으므로 한 번만 요약해 영구히 캐시한다.
첫 오픈에 몇 센트, 그 뒤로는 무료라는 계산이다.

## 설치하기

```bash
git clone https://github.com/ijzereen/branch-of-thought
```

1. Chrome에서 `chrome://extensions`를 연다.
2. 오른쪽 위의 개발자 모드를 켠다.
3. 압축해제된 확장 프로그램을 로드를 누르고 받은 폴더를 고른다.
4. Claude나 ChatGPT를 열고 툴바 아이콘을 누르면 사이드 패널이 열린다.

그래프는 페이지를 불러올 때 대화를 읽는다.
방금 메시지를 편집하거나 보냈다면 탭을 새로 고쳐야 새 분기가 보인다.

## 트레이드오프

### 응답 가로채기는 공식 API가 없는 곳에서 가장 정확하지만 가장 약하다

이 방식의 장점은 정확성이다.
화면의 DOM을 읽어 분기를 추측하는 대신, 채팅 앱이 서버에서 받은 대화 데이터를 그대로 쓴다.
`‹ 2/3 ›` 화살표 뒤에 숨은 분기도 응답 데이터에는 모두 들어 있으므로 빠짐없이 그릴 수 있다.

대가는 취약성이다.
가로채는 대상은 공개 API가 아니라 각 앱의 내부 응답 형식이다.
ChatGPT가 `mapping` 구조를 바꾸거나 Claude가 `chat_messages`의 필드 이름을 바꾸면 정규화기가 조용히 빈 그래프를 만든다.
정규화기를 하나로 모은 설계는 이 변화를 한 곳에서 고치게 해 주지만, 변화가 일어났다는 것을 알려 주지는 않는다.

### 로컬 처리는 사실이지만 권한은 넓다

작성자는 모든 처리가 로컬에서 일어나고 서버, 분석, 텔레메트리가 없다고 쓴다.
Haiku 제목을 켜면 메시지 텍스트가 사용자의 키로 `api.anthropic.com`에 간다는 예외도 README에 명시했다.
이 설명은 코드를 읽을 수 있다는 점에서 검증 가능하다.

그러나 권한의 폭은 설명보다 넓다.
`manifest.json`의 콘텐츠 스크립트는 `claude.ai`, `chatgpt.com`, `chat.openai.com`에 더해 README가 지원한다고 말하지 않는 `gemini.google.com`에도 올라가고, MAIN world에서 그 페이지의 모든 `fetch`와 `XMLHttpRequest`를 감싼다.
대화 응답만 골라 읽도록 짜여 있더라도, 그 스크립트는 그 사이트의 모든 요청과 응답이 지나가는 자리에 있다.
웹 스토어에 올리지 않는다는 선택은 스토어 심사를 받지 않는 대신 사용자가 직접 코드를 읽으라는 뜻이고, 업데이트할 때마다 그 검토를 다시 해야 한다는 뜻이기도 하다.

### 페이지 로드 시점의 스냅샷은 단순하지만 대화 중에는 낡는다

그래프가 페이지 로드 때 받은 대화를 읽는다는 것은 구현을 단순하게 만든다.
대화 전체를 담은 응답 하나만 해석하면 된다.
하지만 메시지를 편집하는 바로 그 순간, 즉 분기가 생기는 순간에는 그래프가 따라오지 않는다.

분기를 보고 싶은 때는 대개 편집 직후다.
방금 만든 분기와 이전 분기를 비교하려면 탭을 새로 고쳐야 하고, 긴 대화에서는 그 새로 고침이 작업 흐름을 끊는다.
스트리밍 응답과 편집 요청까지 가로채 그래프를 갱신하면 이 문제는 풀리지만, 해석해야 할 응답 형식이 훨씬 많아진다.

## 함정

### Gemini 권한이 README와 어긋난다

README와 GN 글은 Claude와 ChatGPT만 지원한다고 말한다.
그런데 `manifest.json`의 호스트 권한과 콘텐츠 스크립트 대상에는 `gemini.google.com`이 들어 있다.
준비 중인 기능일 수 있지만, 설치하는 사람은 자기가 동의하는 권한이 설명보다 넓다는 것을 알아야 한다.

### 압축 해제 확장은 자동으로 업데이트되지 않는다

웹 스토어를 거치지 않으므로 업데이트는 사용자가 직접 `git pull`을 하고 확장 프로그램을 다시 불러와야 한다.
채팅 앱의 응답 형식이 바뀌어 그래프가 깨졌을 때, 저장소에 고친 버전이 올라와도 사용자는 모른 채 깨진 버전을 쓴다.
반대로 업데이트할 때는 바뀐 코드를 다시 읽어야 로컬 처리라는 약속이 유지되는지 확인할 수 있다.

### 개발자 모드 확장은 Chrome이 경고한다

압축 해제 확장을 쓰면 Chrome이 개발자 모드 확장을 끄라는 안내를 띄울 수 있고, 조직이 관리하는 브라우저에서는 개발자 모드 자체가 막혀 있을 수 있다.
업무용 브라우저에서 쓰려면 먼저 조직 정책을 확인해야 한다.

### API 키가 브라우저에 저장된다

Haiku 제목을 쓰면 Anthropic API 키가 확장 프로그램의 브라우저 저장소에 들어간다.
README는 키와 요약이 브라우저 안에만 있다고 설명한다.
같은 프로필의 다른 확장이나 기기 접근에 대한 방어는 브라우저에 맡겨지므로, 사용량 한도를 걸어 둔 별도 키를 쓰는 편이 안전하다.

## 기억할 원칙

### 대화 인터페이스의 숨은 구조는 데이터에는 있고 화면에는 없다

이 도구가 풀려는 문제는 채팅 앱이 이미 가진 정보를 보여 주지 않는다는 것이다.
두 앱 모두 대화를 트리로 저장하고 있고, 화면은 그 트리의 한 경로만 보여 준다.
편집으로 만든 분기는 사라진 것이 아니라 화살표 뒤에 접혀 있을 뿐이다.

Claude의 Cowork 통합 발표 HN 스레드에서 clumsysmurf가 Reddit이나 HN 같은 트리형 대화 구조를 원한다며 방향이 틀어진 대화를 조상이나 형제 응답에서 다시 이어 가고 싶다고 적었고,[^clumsysmurf] jobigoud가 ChatGPT에는 답마다 새 대화로 분기하는 버튼이 있다고 답한 것도[^jobigoud] 같은 문제를 가리킨다.
대화가 길어지고 여러 방향을 시도하는 작업이 늘수록, 선형 채팅 화면과 트리 구조 데이터 사이의 간격은 커진다.
그 간격을 메우는 가장 싼 방법은 이 도구처럼 화면 대신 데이터를 읽는 것이다.
