# raea: AI가 쓰는 React 코드를 내 GPU로 렌더링하는 엔진

<https://raea.io/>

<https://github.com/shinyobjectz/raea>

HN 토론: <https://news.ycombinator.com/item?id=50384366> (1점, 0개 댓글)

## 소개

raea는 Render Anything Engine의 약자로, 영상, 모션 그래픽, 3D, 게임을
React와 TypeScript 코드로 쓰고 사용자 자신의 GPU에서 렌더링하는 Rust 엔진이다.
README는 “AI에게 만들 것을 말하라”는 문장으로 시작하고,
AI가 이미 잘 쓰는 코드(React와 TypeScript)를 입력 형식으로 삼았다고 설명한다.
3D 쪽은 Rust 게임 엔진 Bevy 0.20 위에서 그려진다.

홈페이지는 같은 제품을 다르게 소개한다.
raea를 “AI 에이전트가 만들고 사람은 연출하는 창작 스튜디오”라고 부르고,
머릿속에 그린 것을 말하면 그것이 눈앞에 나타난다고 말한다.
엔진과 데스크톱 앱을 Mac, Windows, Linux용으로 내려받게 하고,
코딩 에이전트에게 설치 스크립트 주소를 붙여 넣어 맡기는 방법도 안내한다.
홈페이지는 지원 환경을 Apple Silicon Mac과 Linux x86_64로만 적는다.

저장소는 2026년 10월 18일에 만들어졌고,
2026년 11월 10일에 GitHub API로 확인한 별은 1,638개, 포크는 115개,
열린 이슈는 12개다.
최신 릴리스는 11월 9일에 나온 v0.1.0이고,
그 앞에 같은 날 나온 v0.1.0-rc1과 11월 7일의 v0.1.0-canary.3이 있다.
README는 스스로를 “카나리(canary)” 단계라고 부르며
매일 바뀌고, 깨지는 변경과 거친 부분과 문서의 빈틈이 있을 것이라고 경고한다.
지원 환경은 macOS(Apple Silicon), Linux(x86_64),
그리고 새로 추가되어 가장 덜 시험되었다는 Windows(x86_64)다.

### 설치와 첫 렌더링

설치는 `curl -fsSL https://raea.io/install | sh` 한 줄이다.
설치 스크립트는 `raea` 명령을 `~/.raea` 아래에 두고
`~/.local/bin`에 연결하며,
`~/.claude/skills`에 raea용 에이전트 스킬도 함께 넣는다고 README는 적는다.
Windows에서는 PowerShell에서 `irm https://raea.io/install.ps1 | iex`를 쓰고,
Microsoft Visual C++ 재배포 패키지와 DirectX 12 또는 Vulkan 드라이버가 필요하다.
엔진은 무료이고 계정이 필요 없다고 한다.

컴포지션(composition)은 특정 시점의 한 프레임을 그리는 React 컴포넌트다.
README의 예제는 `useCurrentFrame()`으로 현재 프레임 번호를 읽고
`interpolate`로 투명도를 0에서 1로 움직이는 “Hello” 컴포넌트이며,
`registerRoot`로 해상도 1920x1080, 30fps, 90프레임짜리 컴포지션으로 등록한다.
README는 비교 대상을 밝히지 않지만,
홈페이지는 렌더링 시간을 Remotion과 HyperFrames에 견주어 보여 준다.
`raea render hello.tsx -o hello.mp4`로 렌더링하면,
README는 Apple Silicon Mac에서 이 90프레임이 약 1초 걸린다고 적는다.
이 수치는 README의 주장이며 이번에 직접 재현하지 못했다.

### 한 파일이 여러 용도로 쓰인다

README는 같은 파일을 여러 방식으로 쓸 수 있다고 한다.
`raea play`는 게임처럼 실시간으로 재생하고,
`-o frame.png --frame 45`는 에이전트가 볼 한 프레임만 그리며,
`raea check hello.mp4`는 품질 기준선에 맞는지 검사한다.
`raea init`은 프로젝트를 시작하고 `raea --help`는 모든 명령을 보여 준다.

### 저장소의 층

작업 공간(workspace)은 순수한 부품에서 명령까지 층을 쌓은 구조다.

| 폴더       | 맡은 일                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------ |
| `core/`    | 순수 부품: 커널 언어 K(CPU에서 해석하고 WGSL로 컴파일), 이징, 도형, 글꼴, 장면과 전송 형식 |
| `gpu/`     | 하나로 공유하는 GPU 장치와 계측                                                            |
| `io/`      | 디코드와 인코드(VideoToolbox, 소프트웨어 코덱, AV1), 파일, 네트워크, npm 패키지            |
| `systems/` | 레이아웃, 캔버스, 합성, 필터, 믹싱, 음성, ONNX Runtime 기반 ML, 영상 읽기, 조명, 스플랫    |
| `runtime/` | 컴포지션 실행: macOS는 JavaScriptCore, 그 밖에서는 QuickJS, Bevy 위의 React와 HTML         |
| `engine/`  | 렌더러, 프로세스 안의 TypeScript 번들러, Bevy 플러그인 목록, `raea` 명령                   |
| `apps/`    | 명령의 동사(check, play, games, media)를 구현한 크레이트                                   |
| `sdk/`     | TypeScript SDK `raea`, 3D, 물리, 오디오, 비디오, UI 패키지, 제작 가이드, 에이전트 스킬     |
| `vendor/`  | 고쳐 쓰는 상위 크레이트(`vendor/vendor.toml`에 이유가 적혀 있다)                           |
| `tools/`   | 빌드와 릴리스 보조 도구                                                                    |

동작 명세는 Gherkin(`.feature`) 파일로 코드 옆에 둔다고 한다.

### 에이전트에서 쓰는 방법

에이전트 스킬은 별도 저장소 raea-skills에 있고, 이 저장소에는 `skills/`로
고정(pin)되어 들어 있다.
스킬 `raea`는 에이전트에게 컴포지션과 3D, 게임을 쓰고 렌더링하고 검사하는
법을 가르친다.
설치 스크립트가 이 스킬을 `~/.claude/skills`에 넣고,
다른 에이전트에는 `raea skills install --agent NAME`을 쓴다.
Claude Code 플러그인은 `/plugin marketplace add shinyobjectz/raea`
다음 `/plugin install raea@raea`로 설치하며,
`.claude-plugin/plugin.json`은 버전 0.1.0, 라이선스 FSL-1.1-ALv2를 적는다.
`raea guide`는 모든 편집이 지켜야 할 기준선과
피치, 설명 영상, 이야기, 게임, 모션, 음악, 레이아웃 가이드를 출력하고,
`raea context PROJECT`는 프로젝트를 건드리기 전에 읽을 것을 알려 준다.

## 사용하기

### 소스에서 빌드하기

필요한 것은 Rust(`rust-toolchain.toml`이 버전을 고정), bun, CMake다.
macOS는 Xcode 명령줄 도구가, Linux는 ALSA, fontconfig, udev, xkbcommon,
Vulkan 라이브러리와 NASM이 필요하다.

```sh
git clone https://github.com/shinyobjectz/raea && cd raea
cargo build --release -p raea-cli --no-default-features
for d in sdk/raea sdk/react/js sdk/react/tw; do (cd $d && bun install); done
target/release/raea render sdk/react/bench/games/pong/edit.tsx -o pong.mp4
```

`--no-default-features`는 릴리스와 같은 공개 엔진을 만든다.
기본 기능에는 호스팅 서비스 하나가 더 붙는데,
raea의 서명 서버가 콘텐츠 자격 증명(Content Credentials)에 서명하는 기능이며
이 서버는 저장소에 들어 있지 않다.

### 네트워크와 개인정보

README는 raea가 스스로는 아무것도 보내지 않는다고 적는다.
원격 측정(telemetry), 충돌 보고, 업데이트 확인이 없고,
네트워크에 닿는 것은 사용자가 요청한 것뿐이다.
컴포지션 안의 원격 URL, 처음 쓸 때 내려받는 모델,
사용자가 키를 가진 공급자에 대한 `raea gen` 단계가 그 예이며,
`RAEA_OFFLINE=1`을 주면 이 모두를 거부한다.

## 분석

### 렌더링 병목은 계산이 아니라 기다림이라는 전제

raea의 설득은 계산 능력이 이미 사용자의 책상 위에 있다는 데서 출발한다.
제작자가 쓴 글 Why we built raea는 창작자가 빠른 컴퓨터와 좋은 화면을 사 두고도
클라우드에 올리고 줄을 서서 기다리며 자기 도구를 월 단위로 빌린다고
말한다.[^why]
raea의 답은 세 가지를 함께 바꾸는 것이다.
렌더링을 로컬 GPU에서 하고, 입력 형식을 코드로 하고, 코드를 공개한다.
README가 “영상이 재생되는 시간보다 빠르게” 렌더링된다고 내세우는 것은
이 첫 번째 변화에 거는 증거다.
다만 이 수치는 README의 한 예제(90프레임)에 대한 것이고,
복잡한 3D 장면이나 긴 영상에서도 성립하는지는 글에 없다.

홈페이지는 이 주장을 비교로 바꾼다.
같은 React 장면 여섯 개(MIT 라이선스 snapcn 컴포넌트, 720p, 30fps)를
raea, Remotion, HyperFrames가 각자의 기본 설정으로 mp4로 렌더링한 시간을
M5 Pro Mac 한 대에서 2026년 11월에 세 번 재어 중앙값을 냈다고 한다.
홈페이지가 내세우는 이유는 raea가 브라우저를 화면 캡처하지 않고
자체 엔진에서 프레임마다 GPU로 그린다는 것이다.
에이전트가 변경마다 렌더링을 기다리므로, 렌더링이 빠르면 같은 시간에 더 많은
수정 라운드를 돈다는 논리다.
이번에 읽은 페이지에는 막대 그래프의 숫자가 스크립트로 그려져 있어
실제 초 단위 수치는 읽지 못했다.

### 입력을 AI가 이미 쓰는 코드로 정한 것이 핵심 설계다

영상 편집 도구는 사람이 마우스로 다루도록 설계되어 있어서,
에이전트가 쓰려면 화면을 보고 클릭하는 간접 경로를 거쳐야 한다.
raea는 입력 형식을 React와 TypeScript 소스로 바꾸고,
그려진 결과를 질의 가능한 데이터로 남긴다고 한다.
이 구조에서는 에이전트가 소스를 쓰고, 프레임 하나를 그리고, 결과를 보고,
`raea check`로 기준선을 검사하는 고리가 사람 없이 닫힌다.
README가 에이전트 스킬, Claude Code 플러그인, `raea guide`, `raea context`를
저장소 안에 함께 두는 것은 이 고리를 제품의 일부로 본다는 뜻이다.

### 검사 도구가 생성 도구만큼 비중을 갖는다

기능 목록에서 눈에 띄는 것은 검사 쪽 비중이다.
`raea check`는 잘린 글자, 낮은 대비, 안전 영역, 멈춤, 음량을 잡는다고 하고,
`raea guide`는 모든 편집이 지켜야 할 기준선을 출력한다.
AI가 만든 결과는 사람이 눈으로 고르는 비용이 병목이 되기 쉬운데,
이 프로젝트는 그 비용 일부를 기계가 하는 검사로 옮기려 한다.
어떤 검사가 실제로 잡히는지, 오탐이 얼마나 되는지는 README만으로는 알 수 없다.

## 비평

### 공개된 코드라는 말과 라이선스가 정확히 맞지 않는다

Why 글은 코드가 “공개되어 있다”고 하고 읽고, 바꾸고, 뜯어 볼 수 있다고
말한다.[^why]
라이선스는 FSL이고, 경쟁 사용은 허용 목적에서 빠진다.
경쟁 사용의 세 번째 항목은 “같거나 매우 비슷한 기능을 제공하는” 상용 제품이나
서비스이므로, 영상 렌더링을 서비스로 제공하는 사업은 범위가 넓게 읽힐 수 있다.
이 해석은 LICENSE 문구를 읽은 내 판단이며,
경계가 어디인지는 법적 해석이 필요하다.
두 해가 지나면 Apache-2.0이 된다는 약속은 장기적으로는 열려 있다는 뜻이지만,
지금 릴리스되는 버전에는 해당하지 않는다.
창작자가 클라우드 도구의 폐쇄성을 비판하며 시작한 글이라면,
자기 도구가 쓰는 라이선스의 조건도 같은 글에서 함께 말했어야 한다.

### 속도 비교는 제작사가 고른 조건에서 제작사가 쟀다

홈페이지의 비교는 장면 여섯 개, 컴퓨터 한 대, 세 번의 중앙값이다.
장면은 제3자의 MIT 컴포넌트지만 고른 것은 제작사이고,
“각자의 기본 설정”은 상대 도구가 가장 빠른 설정이라는 뜻이 아니다.
Apple Silicon의 최신 칩 한 대에서의 결과가 Linux나 Windows의 GPU,
긴 영상, 3D 장면으로 이어지는지는 같은 글에 없다.
빠른 렌더링이 더 많은 수정 라운드로 이어진다는 두 번째 주장은
렌더링 시간이 에이전트 작업의 병목일 때만 성립한다.
모델이 코드를 쓰고 고치는 시간이 렌더링보다 길다면 이득은 줄어든다.
이 반론은 비교 방법에서 나온 내 판단이다.

### 무료와 영구라는 말은 엔진에 한정된다

홈페이지는 엔진, 앱, 로컬 렌더링이 영원히 무료라고 하고,
유료 요금제는 동기화, 연결 컴퓨터, 게시, 팀 기능에 붙는다.
이 구분 자체는 분명하다.
다만 FSL의 경쟁 사용 금지와 합쳐 읽으면,
제작사의 수익원인 호스팅형 협업 서비스를 다른 이가 같은 엔진으로 만들어
팔기는 어렵다는 뜻이 된다.
“영원히 무료”는 지금의 엔진 사용에 대한 약속이고,
앞으로 나올 기능이 어느 요금제에 들어갈지는 알 수 없다.

### 카나리 단계의 약속과 플랫폼 격차

README는 매일 바뀌고 깨지는 변경이 있다고 경고한다.
저장소 생성(10월 18일)에서 v0.1.0(11월 9일)까지 3주가 안 되며,
같은 날 rc1과 정식 0.1.0이 나왔다.
Windows는 이슈 66, 67, 78이 보여 주듯 기본 흐름(재생, HTML 렌더, 3D)에서
실패가 보고된 상태다.
“Render Anything”이라는 이름과 한 줄 설치가 주는 인상과,
특정 환경에서는 실행 자체가 안 되는 현재 상태 사이의 거리를
소개 글은 줄이지 않는다.
macOS와 Linux에서의 완성도도 이번에 직접 확인하지 못했다.

### 에이전트에게 파일 시스템에 쓰는 권한을 주는 설치 방식

설치 스크립트는 `~/.raea`와 `~/.local/bin`에 쓰는 것 외에
`~/.claude/skills`에 스킬을 넣는다.
스킬은 에이전트가 따르는 지시문이므로,
이 설치는 내려받은 스크립트가 에이전트의 행동 지침을 바꾸는 일이기도 하다.
README는 `curl | sh` 형태를 그대로 권하고
체크섬은 릴리스 페이지의 압축 파일 옆에
있다고만 한다.
스킬 내용이 신뢰할 만한지는 사용자가 스크립트와 raea-skills 저장소를
읽어 확인해야 한다.
이번에는 설치 스크립트와 스킬 본문을 읽지 않았다.

### 한 명의 저자에 기대는 프로젝트라는 신호

저작권 표기가 Shane Murphy 한 사람이고,
CONTRIBUTING은 풀 리퀘스트를 사례별로만 받는다고 한다.
README에는 기능이 매우 많지만, 그것이 시험으로 뒷받침되는 정도는 보이지 않는다.
“Behaviour specs written in Gherkin”을 코드 옆에 둔다는 문장은 있으나,
이 명세가 CI에서 무엇을 통과하는지는 이번에 확인하지 못했다.
핵심 기능 수에 비해 유지 인력이 얼마인지가 이 프로젝트가 3개월 뒤에도
같은 속도로 가는지를 좌우할 것이다.

## 인사이트

### 입력 형식이 에이전트에게 읽히는 코드가 되면 도구의 경쟁축이 바뀐다

영상 편집 도구의 경쟁은 오랫동안 화면의 사용성이었다.
입력이 코드로 바뀌면 사용성의 대상이 사람이 아니라 에이전트가 되고,
경쟁축은 “에이전트가 얼마나 틀리지 않고 쓰는가”와
“틀렸을 때 얼마나 빨리 알아채는가”로 옮겨 간다.
raea가 렌더링 속도 다음으로 검사 명령과 가이드에 힘을 쏟는 것은 이 변화를
읽은 선택으로 보인다.
이것은 README의 구성에서 내가 읽어 낸 해석이다.

### 저장소 안에 스킬을 넣는 방식은 문서의 자리를 바꾼다

예전에는 도구의 사용법이 사람을 위한 문서 사이트에 있었다.
raea는 사용법을 에이전트가 읽는 스킬로 만들어 저장소에 고정하고,
설치 스크립트가 에이전트의 스킬 폴더에 복사한다.
이렇게 되면 문서의 독자가 에이전트가 되어 문서의 품질이
곧 에이전트의 작업 품질이 된다.
반대로 스킬을 업데이트하는 순간 사용자 에이전트의 행동이 바뀌므로,
버전이 고정된(pinned) 스킬을 쓸지 최신을 따라갈지가 새로운 운영 선택이 된다.

### 로컬 실행이 곧 개인정보 보호는 아니다

README는 원격 측정이 없고 `RAEA_OFFLINE=1`로 모든 네트워크를 끊을 수 있다고
한다.
이것은 클라우드 렌더링 서비스와 대비되는 강점이다.
그러나 `raea gen`은 외부 공급자에, 모델은 처음 쓸 때 내려받는 곳에 닿는다.
기본 기능으로 빌드하면 콘텐츠 자격 증명을 서명하는 호스팅 서비스가 붙는다.
사용자가 이 경계를 알고 쓰려면, 어떤 명령이 어떤 외부와 통신하는지가
한 곳에 정리되어 있어야 한다.
README는 `docs/settings.md`가 읽는 설정을 정리한다고만 말해,
통신 목록이 거기 있는지는 이번에 확인하지 못했다.

### 사람의 취향이 마지막 병목이라는 제작자의 고백

Why 글은 raea가 대신 상상해 주지 않으며 창작의 불꽃은 사용자의 것이라는 말로
끝난다.[^why]
도구가 만드는 것을 빠르게 하고 검사하는 일을 맡더라도,
무엇을 만들지 고르는 일은 사람에게 남는다.
렌더링이 1초로 줄면 시도 횟수가 늘고, 시도가 늘면 고르는 일이 병목이 된다.
이 병목을 줄이는 도구가 다음에 나올 자리라고 볼 수 있다.

## 이 문서를 읽는 방법

이 문서는 2026년 11월 10일에 읽은 README, LICENSE, CONTRIBUTING.md,
`Cargo.toml`, `.claude-plugin/plugin.json`, v0.1.0 릴리스 정보,
저장소 메타데이터와 이슈 목록, 홈페이지에 기대어 쓰였다.
raea를 설치해 렌더링하거나 게임을 만들어 보지는 않았다.
성능 수치와 기능은 모두 제작사의 주장이며,
해석이라고 표시한 문장은 이 문서의 판단이다.
