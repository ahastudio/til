# 온글 번역: 브라우저 안에서 끝내는 로컬 번역·음성 크롬 확장

<https://github.com/ledzpl/local_translator>

## 소개

웹 페이지 본문, 선택한 텍스트, YouTube 자막을 한국어로 번역하고 소리 내어 읽어주는
Manifest V3 크롬 확장 프로그램이다.
GeekNews에는 watsonpark이라는 계정으로 올라왔고, 저장소는 2026년 7월 28일에
만들어졌다.

핵심 주장은 처리 위치다.
번역과 음성 합성이 모두 브라우저 안에서 실행되며, 번역할 텍스트와 페이지 내용과
자막과 그 결과가 개발자나 모델 호스팅 서버로 전송되지 않는다.
기본 번역은 `@huggingface/transformers`와 TranslateGemma 4B를 WebGPU에서 돌리고,
WebGPU를 쓸 수 없으면 M2M100 WASM으로 자동 전환한다.

## 주요 기능

- 작은 팝업에서 지속형 사이드 패널 작업공간을 열고, 패널을 닫아도 진행 중인 수동
  번역을 다시 확인하거나 취소할 수 있다
- “페이지 안에 한국어 표시”를 누르면 현재 보이는 본문부터 번역하고, 스크롤에 맞춰
  다음 문단을 이어서 처리한다
- 원문+한국어, 한국어만, 올리면 원문 표시의 세 가지 페이지 보기 방식
- 텍스트를 선택한 뒤 우클릭 또는 `Alt+Shift+K`로 즉시 번역
- YouTube의 현재 표시 자막을 감지해 한국어 자막을 겹쳐 보여주며, 속도 우선과
  최근 자막 문맥 우선 모드를 고를 수 있다
- 사용자가 원문·한국어 쌍을 등록하는 기기 로컬 용어집
- 번역 결과의 “듣기” 버튼으로 브라우저 내 한국어 TTS 음성 재생

## 모델과 폴백 구조

이 확장의 실질적 복잡도는 모델 경로에 몰려 있다.

| 용도       | 기본                          | 폴백        | 크기                |
| ---------- | ----------------------------- | ----------- | ------------------- |
| 번역       | TranslateGemma 4B q4 (WebGPU) | M2M100 WASM | 약 3.1GB / 약 650MB |
| 번역(실험) | SMaLL-100 int8 WASM           | M2M100      | —                   |
| 음성       | Supertonic 3 (WebGPU)         | WASM        | 약 400MB            |

첫 번역 시 TranslateGemma 4B q4 약 3.1GB를 내려받는다.
WebGPU를 쓸 수 없거나 초기화·추론이 실패하면 M2M100 WASM 약 650MB를 추가로
내려받는다.
하드웨어 호환성 실패만으로 정상 가중치를 지우지는 않으며, 모델 파일은 Chrome
Cache Storage에 저장해 재사용한다.
첫 “듣기” 때는 Supertonic 3 모델과 기본 음성 스타일 약 400MB를 별도로 받는다.

폴백 판정이 꽤 정교하다.
M2M100 WebGPU가 빈 값이나 특수 토큰, 문자·숫자가 없는 비정상 결과를 만들면 그
결과를 저장하지 않고 M2M100 WASM q8로 한 번 재시도한다.
이때 같은 크롬 세션의 다음 번역도 WASM을 쓰고, 엔진 초기화나 설정 변경 후에
WebGPU를 다시 평가한다.

언어 지원 범위도 모델마다 다르다.
TranslateGemma 4B는 Google이 55개 언어용으로 설명한 품질 우선 모델이고, 팝업의
18개 원문 언어를 품질 검증 범위로 삼는다.
고정 chat template에 없는 네 언어 코드는 M2M100 WASM으로 보낸다.
M2M100과 SMaLL-100은 약 100개 언어를 다룬다.

## 데이터 경계

README가 네트워크 경계를 명시적으로 문서화한 점이 눈에 띈다.

- 번역과 TTS 추론은 브라우저 안에서 실행하며, 원격 JavaScript나 WASM을 내려받아
  실행하지 않는다. ONNX Runtime 실행 코드는 확장 패키지에서 로컬로 불러온다
- Hugging Face에는 전체 commit SHA로 고정한 모델 설정·토크나이저·가중치 파일만
  HTTPS로 요청하며, 요청 URL에 사용자 텍스트를 넣지 않는다
- 가장 최근 수동 번역 작업의 원문·결과·상태는 패널 복구를 위해
  `chrome.storage.session`에 크롬 종료나 사용자의 기록 삭제 전까지만 보관한다
- 용어집은 `chrome.storage.local`에 이 기기에만 보관한다
- 설정은 `chrome.storage.sync`에 보관될 수 있지만 페이지 본문·선택 텍스트·YouTube
  자막은 저장하지 않는다
- 대용량 모델 캐시가 일반 웹 저장소 할당량으로 삭제되지 않도록 `unlimitedStorage`를
  사용한다

라이선스는 모델별로 다르다. TranslateGemma에는 Gemma 이용약관과 금지 용도 정책이
적용되고, Supertonic 3은 OpenRAIL-M이다.
두 라이선스 전문은 배포 패키지의 `LICENSES/`에 포함된다.

## 검증 체계

개인 프로젝트치고 테스트 구성이 이례적으로 촘촘하다.
Playwright용 Chromium으로 사용자 크롬 프로필을 건드리지 않고 임시 프로필에서
확장을 검증한다.

```bash
npm run test:extension                        # MV3 서비스 워커·팝업·오프스크린·자막 오버레이
npm run test:extension:model:translategemma   # 폴백 없이 WebGPU 실행 강제
npm run test:extension:model:m2m100:wasm      # 경량 호환 경로
npm run test:extension:tts                    # 두 구간 한국어 실제 생성·재생
npm run test:extension:page-tts               # 콜드 로드 취소·재생·정지
```

각 명령은 최신 소스를 먼저 빌드해 이전 `dist`를 잘못 검사하지 않게 하고, 완료 후
임시 프로필을 제거한다.
`release:package`는 타입·단위·정적 검증, 실제 크롬에서의 TranslateGemma WebGPU,
M2M100 명시적 WASM, 전체 TTS 재생·페이지 중지, SMaLL-100 호환 경로, npm production
audit를 통과한 뒤 재현 가능한 제출 ZIP과 SHA-256, 빌드 메타데이터를 만든다.

## 분석

### 이 확장의 진짜 제품은 폴백 사슬이다

기능 목록만 보면 번역 확장이지만, README에서 가장 많은 분량을 차지하는 것은
어느 모델이 언제 실패하고 무엇으로 넘어가는지에 대한 서술이다.
WebGPU 초기화 실패, 첫 추론 실패, 빈 값이나 특수 토큰이 섞인 비정상 출력, chat
template에 없는 언어 코드 — 각각에 대해 다른 경로가 정의돼 있다.

이건 로컬 추론을 실제로 배포해 본 사람만 쓸 수 있는 문서다.
브라우저에서 모델을 돌린다는 발상 자체는 어렵지 않다. Transformers.js가 대부분을
해준다.
어려운 것은 사용자의 GPU와 드라이버와 크롬 버전이 제각각이라는 사실이다.
WebGPU는 같은 브라우저에서도 하드웨어에 따라 되기도 하고 안 되기도 하며, 되더라도
특정 연산에서 조용히 잘못된 값을 뱉기도 한다.

특히 “M2M100 WebGPU가 빈 값·특수 토큰·문자나 숫자가 없는 비정상 결과를 만들면”이라는
조건은 실측에서 나온 것으로 보인다.
추론이 예외를 던지지 않고 성공한 척하면서 쓰레기를 반환하는 상황을 겪어야만 쓸 수
있는 방어 코드다.
그리고 그 결과를 캐시에 저장하지 않고 WASM으로 재시도한다는 결정까지 명시돼 있다.

즉 이 프로젝트의 기여는 “브라우저에서 번역이 된다”를 보인 것이 아니라, 그것을
**신뢰할 수 없는 실행 환경 위에서 동작하게 만드는 데 무엇이 필요한지**를 문서로
남긴 것이다.

### 프라이버시 주장을 검증 가능한 형태로 내린 방식

“로컬에서 처리하므로 안전하다”는 주장은 흔하고 대체로 검증 불가능하다.
이 README는 그 주장을 몇 가지 확인 가능한 명제로 쪼갠다.

원격 JavaScript나 WASM을 내려받아 실행하지 않는다는 것, ONNX Runtime 코드가 확장
패키지 안에 있다는 것, Hugging Face 요청은 commit SHA로 고정된 모델 파일에
한정되고 URL에 사용자 텍스트가 들어가지 않는다는 것.

이 세 가지는 성격이 다르다.
“우리는 데이터를 안 보냅니다”는 신뢰의 문제지만, “원격 코드를 실행하지 않는다”는
확장 패키지를 열어보면 확인되고, “요청 URL에 사용자 텍스트가 없다”는 네트워크
탭으로 확인된다.
Manifest V3가 원격 코드 실행을 금지한다는 점도 이 주장을 제도적으로 뒷받침한다.

`models.lock.json` 파일이 저장소 루트에 있다는 점도 같은 맥락이다.
모델 버전을 잠가두면 어느 시점에 어떤 가중치가 내려오는지가 고정된다.
프라이버시 주장에서 모델 파일 자체가 바뀌는 것은 흔히 놓치는 구멍인데, 이 프로젝트는
그것을 잠금 파일로 다룬다.

다만 한 가지는 여전히 신뢰의 영역에 남는다.
`chrome.storage.sync`에 설정이 올라간다는 것은 그 내용이 구글 계정을 통해 동기화된다는
뜻이다.
README는 여기에 페이지 본문·선택 텍스트·자막은 저장하지 않는다고 명시했지만, 그건
코드를 읽어야 확인되는 종류의 약속이다.

### 개인 프로젝트에 이 정도 릴리스 파이프라인이 붙은 이유

`release:package` 하나가 하는 일을 보면 상용 제품의 릴리스 절차에 가깝다.
타입 검사, 단위 테스트, 정적 검증, 실제 크롬에서의 다섯 가지 모델 경로 스모크
테스트, npm production audit, 재현 가능한 ZIP, SHA-256, 빌드 메타데이터.

이 밀도의 배경에는 배포 대상이 있다.
크롬 웹 스토어 심사는 확장 프로그램에 대해 권한 사용 근거와 개인정보처리방침 공개
URL을 요구하며, 원격 코드 실행 여부를 특히 본다.
`docs/STORE_LISTING.md`, `docs/RELEASE_CHECKLIST.md`, `PRIVACY_POLICY.md`가
저장소에 있는 것은 그 심사를 겨냥한 구성이다.

`store:assets`가 1280×800 스크린샷과 440×280 프로모션 이미지를 자동 생성하고 UI
hash 매니페스트를 기록한다는 부분도 흥미롭다.
스토어 제출용 이미지를 수작업으로 만들지 않고 실제 UI 레이아웃에서 뽑아내며,
UI가 바뀌면 hash로 감지되게 해두었다.
스크린샷이 실제 화면과 어긋나는 흔한 문제를 빌드 단계에서 막은 것이다.

## 비평

### 3.1GB를 내려받게 하는 확장의 현실성

기본 경로가 요구하는 것을 합산해 보면 만만치 않다.
TranslateGemma 4B q4 약 3.1GB, 음성을 쓰면 Supertonic 3과 음성 스타일 약 400MB,
WebGPU가 실패하면 M2M100 WASM 약 650MB가 더 붙는다.
최악의 경우 4GB를 넘는다.

브라우저 확장 프로그램의 통상적인 기대와 어긋난다.
사용자는 확장을 “가볍게 하나 깔아보는 것”으로 생각하고, 실제로 대부분의 번역 확장은
수백 KB다.
설치 직후 첫 번역에서 3.1GB 다운로드가 시작되는 경험은 상당한 이탈 지점이 된다.

저자 본인도 이 문제를 인지하고 있다.
GeekNews 글에서 16GB RAM 머신에서만 테스트했다며 성능 피드백을 요청했다.
4B 모델을 q4로 양자화해도 브라우저 안에서 돌리려면 실질적으로 여유 있는 GPU 메모리가
필요하고, 그 조건을 만족하지 못하는 기기에서는 WASM 폴백으로 떨어진다.
그러면 3.1GB를 받아놓고 650MB를 더 받아 성능이 낮은 경로로 동작하는 상황이 된다.

여기서 설계상의 긴장이 드러난다.
품질 우선 모델을 기본값으로 둔 것은 첫인상을 좋게 만들지만, 실패했을 때의 비용도
기본값이 떠안는다.
가벼운 M2M100을 기본으로 하고 원하는 사용자만 TranslateGemma를 받게 하는 편이
이탈을 줄일 텐데, README는 이 선택에 대한 설명을 하지 않는다.

### 로컬 처리의 이점이 이 사용 사례에서 얼마나 큰가

프라이버시가 이 프로젝트의 핵심 판매 논리다.
그런데 실제 사용 시나리오를 놓고 보면 그 이점의 크기가 균일하지 않다.

웹 페이지 본문 번역을 생각해 보자. 그 페이지는 공개된 웹 문서다.
이미 인터넷에 공개된 텍스트를 번역 서버에 보내는 것이 어떤 위험인지는 분명하지
않다.
YouTube 자막도 마찬가지다. 공개 영상의 공개 자막이다.
로컬 처리의 이점이 뚜렷한 것은 사이드 패널에 사용자가 직접 붙여넣는 텍스트 —
사내 문서나 개인 메일 같은 것 — 정도다.

그 용도라면 3.1GB 모델을 브라우저에 상주시키는 것보다 로컬에서 Ollama 같은 것을
돌리거나 회사 내부 번역기를 쓰는 편이 자연스럽다.
브라우저 확장이라는 형태와 프라이버시라는 가치가 겨냥하는 사용자층이 완전히
겹치지는 않는다.

프라이버시 외의 실질적 이점은 따로 있다.
오프라인 동작, API 비용 없음, 사용량 제한 없음, 요청 지연 없음 같은 것들이다.
README는 이 중 어느 것도 앞세우지 않고 “전송하지 않는다”에 집중한다.
가장 검증하기 쉬운 주장을 고른 것으로 보이지만, 결과적으로 도구의 실제 강점이
덜 드러난다.

### 라이선스 공백이 배포 계획과 충돌한다

저장소 파일 목록에 `LICENSE`가 없다.
`LICENSES/` 디렉터리와 `THIRD_PARTY_NOTICES.md`는 있는데, 이건 사용한 모델과
의존성의 라이선스를 담은 것이고 프로젝트 자체의 라이선스가 아니다.

라이선스가 없는 저장소는 기본적으로 모든 권리가 저작자에게 있다.
읽을 수는 있어도 포크하거나 수정본을 배포할 수 없다.
GeekNews에 Show GN으로 올려 피드백을 요청하면서 기여 경로를 열어두지 않은 셈이다.

이건 단순 누락으로 보이지만 이 프로젝트에서는 좀 더 성가신 문제가 된다.
TranslateGemma는 Gemma 이용약관과 금지 용도 정책을 따르고, Supertonic 3은
OpenRAIL-M이다.
OpenRAIL-M은 사용 제한 조항을 포함하는 라이선스라 재배포 시 그 조항을 함께
전달해야 한다.
README도 “모델별 이용 제한·재배포 조건은 제출 전에 반드시 확인해야 한다”고 스스로
경고한다.

여러 라이선스가 얽힌 상태에서 프로젝트 자체의 라이선스가 정해지지 않았다는 것은,
스토어 제출 준비를 이만큼 해놓고 정작 배포 권한 구조는 정리하지 않았다는 뜻이다.
릴리스 체크리스트에 SHA-256 생성까지 넣은 프로젝트에서 이 공백은 눈에 띈다.

### 검증의 촘촘함과 사용자 수의 괴리

이 프로젝트에는 여덟 종류의 크롬 스모크 테스트가 있다.
TranslateGemma WebGPU 강제 경로, M2M100 WebGPU, M2M100 WASM, SMaLL-100, TTS 두
구간 생성, 페이지 TTS 콜드 로드 취소·재생·정지.
그런데 저장소 스타는 0개다.

이 대비를 두 가지로 읽을 수 있다.
하나는 이 테스트들이 실제로 필요했다는 것이다. 앞서 본 폴백 사슬의 복잡도를 보면
수동으로 매번 확인하는 것이 불가능하고, 모델 경로마다 다르게 깨지므로 자동화가
유일한 방법이었을 수 있다.

다른 하나는 검증이 사용자 없이도 쌓이는 종류의 작업이 됐다는 것이다.
Reccoo에서 문서가 그랬듯, 테스트도 생성 비용이 내려가면 실제 필요와 무관하게
늘어난다.
어느 쪽인지는 밖에서 판단하기 어렵지만, 판단의 근거가 되던 신호 — “이만큼
테스트를 짰다면 그만큼 진지한 프로젝트다” — 가 약해진 것은 분명하다.

정작 사용자가 알고 싶은 것은 다른 데 있다.
16GB RAM 머신에서만 테스트했다는 저자의 고백이 여덟 개의 스모크 테스트보다
중요한 정보다.
자동화 테스트는 저자의 기기 한 대에서 돌아간 것이고, 이 프로젝트에서 가장 큰
불확실성인 하드웨어 다양성은 그 테스트가 커버하지 못하는 영역이다.

## 인사이트

### 브라우저가 모델 배포 채널이 되면 캐시가 전쟁터가 된다

이 확장에서 조용히 중요한 결정 하나가 `unlimitedStorage` 권한 사용이다.
대용량 모델 캐시가 일반 웹 저장소 할당량 때문에 삭제되지 않도록 하기 위한 것이다.

이 한 줄이 가리키는 문제는 앞으로 커진다.
브라우저 저장소는 원래 쿠키와 캐시와 IndexedDB 정도를 담도록 설계됐고, 용량이
부족하면 브라우저가 알아서 정리하는 것이 기본 동작이다.
그런데 로컬 AI가 확산되면 사이트와 확장마다 수 GB짜리 가중치를 캐시에 올려두려
한다.
번역 확장이 3.1GB, 요약 확장이 2GB, 이미지 도구가 1.5GB를 각각 들고 있는 상황이
되면 브라우저의 저장소 관리 모델이 무너진다.

지금은 `unlimitedStorage`로 개별 확장이 예외를 얻는 방식이지만, 이 권한을 요구하는
확장이 흔해지면 권한의 의미가 사라진다.
사용자는 자기 디스크에서 무엇이 얼마나 차지하는지 알 수 없게 되고, 브라우저는
어느 것을 지워야 할지 판단할 근거가 없다.

더 흥미로운 것은 중복이다.
여러 확장이 같은 기반 모델을 쓰더라도 각자 자기 캐시에 별도로 받는다.
Hugging Face에서 같은 commit SHA의 같은 파일을 두 번 받아 두 번 저장하는 것이다.
운영체제 수준의 패키지 매니저가 공유 라이브러리 문제를 풀었던 것처럼, 브라우저에도
모델 공유 계층이 필요해지는 지점이 온다.
그때 등장할 규격이 프라이버시 경계를 어떻게 다룰지가 이 확장이 지금 세운 “전송하지
않는다”는 약속의 미래를 결정한다.

### WebGPU의 조용한 오작동이 새로운 신뢰 문제를 만든다

이 프로젝트에서 가장 인상적인 대목은 M2M100 WebGPU가 “빈 값·특수 토큰·문자나 숫자가
없는 비정상 결과”를 만들 때를 처리하는 코드다.
예외가 아니라 **그럴듯하지 않은 성공**을 감지해야 한다는 것이다.

이건 전통적인 소프트웨어 오류 처리와 성격이 다르다.
API 호출이 실패하면 상태 코드가 오고, 파일이 없으면 예외가 난다.
GPU 커널이 특정 하드웨어에서 잘못된 값을 계산하면 아무 신호도 없다. 그냥 다른
숫자가 나올 뿐이고, 그 숫자는 토큰으로 디코딩되어 문장처럼 보이는 무언가가 된다.

번역에서는 이 문제가 그나마 감지 가능하다. 빈 문자열이나 특수 토큰 범벅은
휴리스틱으로 걸러진다.
하지만 미묘하게 틀린 번역 — 문법적으로 멀쩡하고 의미만 어긋난 결과 — 은 걸러지지
않는다.
그리고 로컬 추론의 전제상 사용자는 원문을 읽지 못해서 번역을 쓰는 것이므로,
틀린 것을 알아챌 수 없다.

이 조합이 앞으로의 로컬 AI에서 반복될 구조다.
클라우드 추론은 제공자가 하드웨어를 통제하므로 이 문제를 사용자에게 노출하지
않는다. 문제가 생기면 제공자가 그 기기를 빼면 그만이다.
로컬 추론은 실행 환경이 사용자 소유의 검증되지 않은 하드웨어이고, 개발자는 그것을
관측할 수도 통제할 수도 없다.
결국 “출력이 그럴듯한가”를 실행 시점에 판정하는 층이 필수가 되는데, 그 판정을
어디까지 할 수 있는지가 로컬 AI 신뢰도의 상한을 정한다.

### 크롬 확장이라는 형태가 로컬 AI의 배포 창구가 되는 이유

로컬에서 모델을 돌리는 도구는 보통 데스크톱 앱이나 CLI로 나온다.
그런데 이 프로젝트는 크롬 확장을 골랐고, 이 선택에는 앞서 Reccoo에서 본 문제에
대한 답이 들어 있다.

데스크톱 앱은 코드 서명이 필요하다. 서명이 없으면 SmartScreen과 Gatekeeper가 막고,
서명에는 돈과 절차가 든다.
크롬 확장은 그 문제를 스토어 심사로 대체한다. 심사는 까다롭지만 무료이고, 통과하면
설치 시 경고가 뜨지 않는다.
개인 개발자에게는 진입 비용이 훨씬 낮은 경로다.

WebGPU와 WASM이 이 선택을 가능하게 만든 기술적 조건이다.
몇 년 전이라면 브라우저에서 4B 모델을 돌린다는 발상 자체가 성립하지 않았다.
지금은 브라우저가 GPU 접근과 네이티브에 가까운 실행을 제공하므로, 로컬 추론의
런타임으로 브라우저를 쓸 수 있다.

이 조합이 만드는 결과는 배포 형태의 재편이다.
“로컬에서 돌아가는 AI 도구”의 상당수가 네이티브 앱이 아니라 브라우저 확장이나
웹앱으로 나오게 된다.
사용자 입장에서는 설치 마찰이 낮아지는 이득이 있지만, 대가도 있다. 그 도구들이
전부 크롬의 정책 아래 놓인다는 것이다.
구글이 확장의 권한이나 저장소 정책을 바꾸면 로컬 AI 도구 생태계 전체가 영향을
받는다.
Manifest V2에서 V3로의 전환이 광고 차단 확장에 무엇을 했는지 기억한다면, 이 의존이
가벼운 것이 아님을 알 수 있다.
로컬 처리를 내세워 서버 의존을 없앤 도구가 플랫폼 의존은 그대로 안고 있는 셈이다.
