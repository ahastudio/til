# getdeck: AI 에이전트가 새로 그리지 않고 골라 쓰는 슬라이드 레이아웃 카탈로그

<https://getdeck.co>

Show GN: [getdeck - 슬라이드 레이아웃을 내 템플릿으로 저장하고 웹에서 고치는 서비스](https://news.hada.io/topic?id=36644)

## 소개

getdeck은 슬라이드 레이아웃 서비스이며, 홈페이지의 저작권 표시는 DoDraft다.
홈페이지 첫 화면은 이를 AI 에이전트가 덱(deck)을 만드는 데 쓰는 슬라이드
레이아웃이라고 소개한다.
홈페이지는 44개 테마, 254개 레이아웃, 둘을 곱한 11,176개 조합을 보여 주고,
편집 가능한 PPTX로 내보낼 수 있다고 말한다.
GeekNews의 Show GN 글은 2026년 11월 5일 decksmith 계정이 올렸다.[^gn-topic]
이 글은 AI가 만든 발표자료를 팀에 돌려 확인받는 흐름을 소개한다.
마음에 드는 장을 골라 내 템플릿으로 저장하고, 웹에서 글자와 이미지를 고치고,
팀원에게 검토를 요청하며, 확인이 끝나면 웹에서 바로 발표하거나 PPTX로
내려받는다는 것이다.[^gn-topic]

getdeck 자신의 설명은 조금 다르다.
소개 페이지는 getdeck을 1920×1080 크기의 HTML 슬라이드 레이아웃과 CSS 테마의
라이브러리라고 정의한다.[^what-is]
모든 레이아웃은 열어서 렌더링하고 고칠 수 있는 파일이며,
에이전트가 처음부터 슬라이드를 쓰는 대신 레이아웃을 가져가도록 MCP 서버도
제공한다고 한다.[^what-is]
이 문서는 getdeck의 사이트와 하위 페이지 네 곳(소개, MCP 연결, 요금,
변경 내역)을 읽고 정리했으며, 서비스에 가입하거나 PPTX 내보내기와 MCP 연결을
직접 해 보지는 못했다.
성능이나 품질에 관한 서술은 모두 제작사의 주장으로 적는다.

## 동작 방식

### 레이아웃과 테마는 서로 다른 파일이다

소개 페이지에 따르면 레이아웃은 1920×1080 무대 위에서 무엇이 어디에 들어가고
얼마나 들어가는지를 정하는 HTML 파일 하나다.[^what-is]
테마는 색, 글꼴, 질감을 정하는 CSS 파일 하나이며,
HTML은 색 이름을 쓰지 않고 CSS는 위치를 쓰지 않는다고 한다.[^what-is]
그래서 테마를 바꾸면 모든 레이아웃이 따라 바뀌고,
254개 레이아웃과 44개 테마의 모든 조합이 그대로 쓸 수 있는 슬라이드가 된다는
설명이다.[^what-is]

레이아웃은 색이나 글꼴을 직접 쓰지 않고 CSS 변수를 읽는다.
모든 테마는 33개 변수를 모두 정의해야 하고,
변수 이름은 색이 아니라 역할을 가리킨다고 소개 페이지는 설명한다.[^what-is]
예를 들어 `--sl-accent`는 파랑이 아니라 강조색이며,
테마가 바뀌어도 레이아웃이 의도한 위계가 유지된다는 것이다.[^what-is]

### 에이전트는 슬롯 목록이 있는 마크다운 파일 하나를 받는다

레이아웃을 복사하면 명세, 레이아웃 HTML, 테마 CSS, 기본 CSS,
변수 명세가 담긴 `layout.md` 하나를 받는다고 한다.[^what-is]
이 가운데 슬롯(slot) 목록이 가장 큰 역할을 하며,
예로 제목 칸이 약 40자를 담는다는 정보를 주어 에이전트가 글을 상자에 맞춰 쓰도록
한다는 설명이다.[^what-is]
요금 페이지는 슬롯별 글자 수 제한의 예로 제목 25자, 수치 8자를 든다.[^pricing]
두 페이지의 예시 숫자가 다르며, 어느 레이아웃의 값인지는 어느 페이지에도 적혀
있지 않다.

### MCP로 연결하면 목록 조회부터 덱 제안까지 대화 안에서 한다

MCP 연결 페이지가 알려 주는 엔드포인트는 `https://getdeck.co/api/mcp`이고,
연결 명령에는 `gd_`로 시작하는 키를 담은 `Authorization: Bearer` 헤더가
들어간다.[^mcp]
소개 페이지는 도구가 여섯 개이고, 레이아웃 검색, 테마 검색, 레이아웃 가져오기,
테마 가져오기, 덱 제안, 여러 슬라이드를 한 파일로 합치기라고 설명한다.[^what-is]
덱 제안은 파일을 쓰기 전에 미리보기 링크를 돌려주며,
사용자가 승인하거나 고친 뒤에야 에이전트가 파일을 쓴다고 한다.[^what-is]
덱 제안과 슬라이드 합치기는 Pro이고 검색과 가져오기는 무료라고 소개 페이지는
밝힌다.[^what-is]

## 요금

요금 페이지의 제목은 “고르는 것은 무료,
맡기는 것은 Pro”라는 뜻의 문장이다.[^pricing]
요금제는 세 가지다.

| 요금제 | 가격                       | 핵심 기능                                                                       |
| ------ | -------------------------- | ------------------------------------------------------------------------------- |
| Free   | 0달러                      | 레이아웃 254개와 테마 44개 검색, 레이아웃 무제한 다운로드, 슬롯별 글자 수 제한  |
| Pro    | 월 9.99달러, 7일 무료      | My Templates, 웹 편집기, PPT 가져오기, 덱 구성, PPTX 내보내기                   |
| Team   | 좌석당 월 12달러, 최소 2석 | Pro의 모든 기능, 구성원 초대, 검토 요청과 슬라이드 고정 댓글, 감사 로그, 사용량 |

세 행의 값은 모두 요금 페이지에서 읽었다.[^pricing]
요금 페이지는 카드를 등록하면 7일 동안 Pro를 무료로 쓸 수 있고,
체험이 끝나기 전에 취소하면 청구되지 않는다고 적는다.[^pricing]

## 분석

### 에이전트에게 설명서가 아니라 검사 가능한 계약을 준다

소개 페이지는 getdeck의 발상이 Google Stitch가 에이전트에게 주는 DESIGN.md에서
왔다고 말하고, 한 가지 차이를 든다.[^what-is]
슬라이드는 고정 크기에서 렌더링되어야 하므로 설명만 하는 파일로는 부족하고
검사까지 되어야 한다는 것이다.[^what-is]
이 차이가 제품의 중심이다.
디자인 시스템을 말로 설명하면 에이전트가 이를 해석해야 하지만,
슬롯 목록과 33개 변수는 해석이 아니라 채우기의 대상이다.

제작사는 이 계약이 지켜지는지 자동으로 검사한다고 설명한다.
각 레이아웃을 여러 테마에서 1920×1080으로 렌더링한 뒤 기하(geometry)를 읽어 다섯
가지를 확인한다고 한다.[^what-is]
캔버스 밖으로 나간 내용, 컨테이너에 잘린 글자, 푸터를 침범한 내용,
겹치면 안 되는 요소의 겹침, 다른 요소 뒤에 숨은 요소다.[^what-is]
실패한 레이아웃은 고치거나 게시하지 않는다는 것이 제작사의 설명이다.[^what-is]

### 검사 항목은 깨지지 않음을 확인하고 좋은 슬라이드임을 확인하지는 않는다

다섯 가지 검사는 모두 넘침과 충돌처럼 렌더링 결과에서 측정할 수 있는 결함이다.
슬라이드가 청중에게 읽히는지, 레이아웃이 내용에 맞는지는 이 목록에 없다.
제작사도 이 서비스가 레이아웃과 스타일만 다루고,
무엇을 어떤 순서로 쓸지는 사용자의 몫이라고 적는다.[^what-is]
따라서 getdeck이 줄이는 것은 에이전트 결과물이 규격 밖으로 무너지는 일이며,
내용이 빈약한 덱을 낫게 만들지는 않는다.

### 카탈로그가 빠르게 커졌고 제품의 범위도 함께 커졌다

변경 내역에 따르면 2026년 9월 4일 레이아웃은 156개였다.[^updates]
10월 27일에는 250개와 테마 44개가 되었다.[^updates]
내 계산으로는 약 7~8주 만에 94개가 늘었다.
소개 페이지는 이만한 크기의 카탈로그가 평균으로 쏠리기 쉬워서 계속 측정해야
한다고 적었다.[^what-is]
이 증가 속도는 검사 자동화가 그 약속을 지킬 수 있는지 시험하는 조건이 된다.

범위의 변화도 변경 내역에서 읽힌다.
9월에는 주제를 말하면 덱을 구성하는 기능과 PPTX 다운로드가 들어왔다.[^updates]
10월에는 이미지와 텍스트 상자 추가, 레이아웃 요소 선택과 이동,
편집한 pptx 다시 가져오기가 Pro 기능으로 추가되었다.[^updates]
11월 4일에는 팀원 초대, 템플릿 공유, 검토 요청과 슬라이드 댓글을 담은 Team
요금제가 나왔다.[^updates]
레이아웃 라이브러리로 시작한 제품이 웹 편집기와 협업 도구로 넓어지는 흐름이지만,
소개 페이지는 여전히 PowerPoint의 대체물이 아니라고 말한다.[^what-is]

## 비평

### Show GN 글이 소개하는 검토 기능은 글이 말한 요금제에 없다

Show GN 글은 직접 써 볼 방법으로 템플릿 저장, 편집, 발표, PPTX를 가입 후 7일 체험으로 써 볼 수 있고 이후는 Pro라고 안내한다.[^gn-topic]
그런데 글이 앞세운 팀원의 슬라이드별 댓글과 요청 승인은 요금 페이지에서 Team
요금제에만 있는 기능이다.[^pricing]
변경 내역도 검토 요청과 슬라이드 댓글을 Team 요금제 출시와 함께
적는다.[^updates]

글이 말한 7일 체험이 Team의 검토 기능까지 포함하는지는 내가 읽은 페이지에서
확인되지 않는다.
요금 페이지의 체험 안내는 Pro를 7일 동안 무료로 쓰는 것이라고 적는다.[^pricing]
Team은 좌석당 월 12달러에 최소 2석이므로 검토를 시험하려면 적어도 월 24달러의
요금제가 필요할 수 있다는 것이 내 계산이다.
홍보 글의 중심 장면이 상위 요금제에 있다면, 체험 범위를 먼저 확인해야 한다.

### 편집 가능한 PPTX라는 약속은 레이아웃의 만드는 방식과 부딪힌다

홈페이지는 편집 가능한 PPTX를 제목에 내세운다.
그런데 레이아웃 설명을 보면 도넛 차트와 게이지는 CSS conic-gradient로,
선 차트와 분해도는 SVG로 그린다고 한다.
이런 요소가 PPTX에서 도형이나 차트 객체가 되는지,
그림으로 들어가는지는 내가 읽은 페이지에 적혀 있지 않다.

변경 내역은 PPTX에 글꼴이 항상 포함되고,
PowerPoint에서 고친 파일을 다시 가져오면 바뀐 부분만 반영되어 웹 편집 내용을
덮어쓰지 않는다고 적는다.[^updates]
이는 양방향 왕복을 지원한다는 주장이며,
차트나 겹친 요소가 있는 레이아웃에서도 성립하는지는 제시되지 않았다.
PPTX를 최종 산출물로 삼는 팀이라면 차트 레이아웃 하나를 내보내 PowerPoint에서
열어 보기 전에는 이 약속을 믿을 근거가 없다.

### 품질 주장에 수치가 없다

제작사는 실패한 레이아웃을 고치거나 버린다고 하지만 몇 개를 검사해서 몇 개가
실패했는지는 밝히지 않는다.[^what-is]
소개 페이지는 레이아웃을 여러 테마에서 렌더링한다고만 적으므로,
조합 11,176개 전부가 검사 대상인지 일부 표본인지는 알 수 없다.[^what-is]
소개 페이지가 일반 에이전트의 결과를 평균이라고 비판한 말은,
얼마나 덜 평균적인지를 보여 주는 측정이 있어야 같은 무게를 갖는다.

## 인사이트

### 에이전트가 쓸 디자인은 설명이 아니라 입력 형식으로 줘야 한다

getdeck이 슬롯 목록에 칸마다 글자 수를 적는 방식은 에이전트의 실패를 사후 수정이
아니라 사전 제약으로 바꾼다.
글을 쓴 뒤 줄이는 것이 아니라 처음부터 칸에 맞춰 쓰게 하는 것이다.
이 접근은 슬라이드에만 해당하지 않고, 에이전트에게 결과물의 형식을 지키게 하려는
다른 영역에도 같은 형태로 적용될 수 있다는 것이 내 추론이다.

여기서 생기는 2차 효과는 덱 전체의 응집성이다.
레이아웃 하나가 규격을 지켜도 열 장이 하나의 이야기가 되는지는 계약에 들어
있지 않다.
요금 페이지는 덱 구성과 조립 규칙을 Pro 기능으로 둔다.[^pricing]
그 기능이 이야기의 흐름까지 다루는지는 읽은 페이지로는 알 수 없다.

### 생성 다음에 남는 어려운 일은 검토이고 승인은 내용의 버전에 묶여야 한다

Show GN 글은 승인한 뒤에 내용이 바뀌면 다시 검토를 요청하라고 알려 준다고 소개한다.[^gn-topic]
일부 코드 리뷰 도구에서 새 커밋이 들어오면 기존 승인을 무효로 하는 방식과
같은 구조다.
에이전트가 슬라이드를 빠르게 만들수록 사람이 확인하고 책임지는 과정이 상대적으로
큰 일이 되므로, 승인이 어느 내용에 대한 것인지를 기록하는 장치가 필요해진다.

이 제품이 덱 생성이 아니라 검토 흐름을 Show GN 글의 앞에 세운 것은 같은 판단을
반영한다.
다만 승인이 어떤 단위(슬라이드, 덱 전체)의 어떤 변경에 무효가 되는지는
글에 없다.
작은 오타 수정에도 재검토를 요구하면 승인이 형식이 되고,
요구하지 않으면 승인된 내용이 바뀐다.

### 요금은 콘텐츠가 아니라 에이전트의 자율성에 매겨져 있다

요금 페이지가 내세우는 구분은 직접 고르는 것은 무료이고 에이전트에게 맡기는 것은
유료라는 점이다.[^pricing]
레이아웃 다운로드는 무제한이고, 주제를 주면 순서와 테마를 정해 주는 덱 구성이
Pro다.[^pricing]
템플릿 자체는 누구나 가져갈 수 있으므로 값을 치르는 대상은 선택과 조립을
대신하는 편의다.

이 구조에는 긴장이 있다.
무료 레이아웃을 다른 에이전트에 직접 붙여 넣으면 같은 일을 할 수 있으므로 Pro의
가치는 편의가 얼마나 큰지에 달려 있다.
GeekNews의 같은 글 하단에는 마크다운 슬라이드 변환 서비스 등 비슷한 도구가 관련
글로 나열되어 있다.[^gn-topic]
선택지가 늘수록 getdeck이 내세울 수 있는 것은 레이아웃 수보다 검사 결과의 신뢰와
협업 기능이다.

### 도입 전에 확인할 것은 세 가지다

첫째는 PPTX 내보내기다.
차트가 들어 있는 레이아웃 하나를 내보내 PowerPoint에서 열어 도형이 편집되는지
확인한다.
편집되지 않는다면 홈페이지가 내세우는 편집 가능한 PPTX는 이 용도에
해당하지 않는다.

둘째는 검토 기능이 어느 요금제에 있는지다.
체험 기간에 슬라이드 댓글과 요청 승인이 열리는지 가입 화면에서 확인하고,
열리지 않으면 Team의 최소 2석 요금을 기준으로 비용을 계산한다.
셋째는 MCP 키와 템플릿 데이터가 서비스에 있다는 점이다.
MCP 연결에 키가 필요하고,[^mcp] 저장한 템플릿과 이미지는 서비스 안에 남으므로,
서비스가 사라질 때 가져갈 수 있는 형태가 PPTX와 레이아웃 HTML뿐인지 확인한다.
