## 소개

Godot는 2D와 3D 게임, 크로스 플랫폼 프로젝트, XR 작업을 만드는
무료 오픈소스 게임 엔진이다.
홈페이지는 당신의 무료 오픈소스 게임 엔진이라는 문장으로 시작하고,
2D와 3D 게임, 크로스 플랫폼 프로젝트, 심지어 XR 아이디어까지 개발하라는 문구가
이어진다.
라이선스는 MIT이고, 저작권 표기는 2007년부터 Juan Linietsky와 Ariel Manzur,
그리고 기여자들로 되어 있다.
2014년에 소스가 공개되었고, GitHub 저장소 `godotengine/godot`는
2014년 1월 4일에 만들어졌다.

2026년 10월 8일 기준 홈페이지가 내려받기로 내세우는 최신 안정판은 4.7.2다.
4.7은 2026년 6월 18일에 나왔고, 4.7.1(7월 14일)과 4.7.2(8월 18일)가
유지보수 릴리스로 이어졌다.
구버전 계열인 3.x도 8월 22일에 3.6.3 유지보수 릴리스가 나와 아직 관리되고 있다.
다음 기능 릴리스인 4.8은 9월 29일 dev 7에서 기능 동결에 들어갔다.

GitHub API로 확인한 저장소 지표는 다음과 같다.

| 항목                                         | 값         |
| -------------------------------------------- | ---------- |
| 스타                                         | 118,227    |
| 포크                                         | 26,969     |
| 열린 이슈(PR 제외)                           | 13,389     |
| 열린 PR                                      | 5,479      |
| 기능 제안 저장소 `godot-proposals` 열린 이슈 | 6,481      |
| 주 언어                                      | C++        |
| 마지막 푸시                                  | 2026-10-07 |

이 문서는 홈페이지와 기능 페이지, 4.7 릴리스 페이지,
4.7.2와 4.8 dev 7 릴리스 글, 거버넌스와 라이선스 페이지,
Godot Foundation 사이트와 비전 문서, 개발 기금 페이지, 콘솔 지원 페이지,
우선순위 페이지, 쇼케이스, Asset Store, 2026년 성장 통계와 기여 정책 글을
읽고 정리했다.
엔진을 직접 설치해 실행해 보지는 않았다.

## 주요 기능

### 노드와 씬으로 짜는 구조

기능 페이지가 가장 먼저 내세우는 것은 씬 중심 설계다.
게임은 노드라는 작은 블록으로 만들고,
노드를 묶어 더 크고 재사용 가능한 씬을 만든다.
씬에 스크립트를 붙여 기본 동작을 바꾸고,
상속보다 조합과 노드 계층으로 게임 로직을 드러내라는 것이 엔진의 권장 방식이다.
캐릭터나 데이터 구조는 리소스라는 스크립트 가능한 객체로 정의해
편집기에서 노드에 바로 연결한다.
기능 페이지는 Godot 편집기 자체가 이 GUI 시스템으로 만든 앱이라는 점을
GUI 시스템의 사례로 든다.

### 언어 선택

| 방식            | 성격                                                               |
| --------------- | ------------------------------------------------------------------ |
| GDScript        | Python 등에서 영감을 받은 내장 언어, 선택적 정적 타입, 엔진과 밀착 |
| C#              | .NET 전용 실행 파일로 제공, 데스크톱과 모바일만 지원               |
| GDExtension     | 엔진을 다시 컴파일하지 않고 C++ 등으로 확장하는 공식 API           |
| 엔진 모듈       | 엔진 소스에 직접 모듈을 추가해 빌드                                |
| 커뮤니티 바인딩 | Rust, Nim, Python, JavaScript 등                                   |

홈페이지는 C# 지원이 Godot 4.2 기준으로 데스크톱과 모바일에만 있다고 밝히고,
웹에서 C#을 돌리려면 Godot 3를 쓰라고 안내한다.
4.8 dev 7에서는 .NET 빌드의 최소 요구 버전이 .NET 8에서 10으로 올라간다.

### 2D, 3D, XR

2D는 3D 엔진 위에 얹은 것이 아니라 전용 렌더링 파이프라인을 따로 가진다.
픽셀 단위 좌표계와 2D 전용 노드, 타일 맵 편집기를 제공한다.
3D는 저사양 기기를 위한 OpenGL 기반 렌더러와 Vulkan, Direct3D 12,
Metal 렌더러를 함께 갖추고, Blender 파일을 직접 가져오거나
glTF와 FBX를 쓸 수 있다.
고정 프레임으로 게임 화면을 녹화하는 Movie Maker 모드도 있다.
XR은 OpenXR과 WebXR을 엔진에 내장했고, 편집기 자체가 여러 헤드셋에서 실행된다.

### 배포 대상

데스크톱, 모바일, 웹으로 내보낼 수 있고,
SSH로 대상 기기에 바로 배포해 디버깅할 수 있다.
콘솔은 공식 지원하지 않고 제3자 업체를 거친다.
이 부분은 뒤의 콘솔 절에서 따로 다룬다.

## 최근 릴리스: 4.7과 4.8

### 4.7이 더한 것

4.7 릴리스 페이지의 부제는 Lights, Camera, Action!이다.
페이지는 Godot 4의 첫 몇 릴리스가 안정성에 집중했고 점차 다듬기와 사용성
개선으로 옮겨 가 4.6에서 정점을 찍었다고 설명한 뒤,
4.7이 그 방향을 이어 간다고 말한다.
300명이 넘는 기여자가 1,600개가 넘는 PR을 보냈다.

| 영역     | 주요 변경                                                                   |
| -------- | --------------------------------------------------------------------------- |
| 렌더링   | HDR 출력(Windows, macOS, iOS, visionOS, Wayland), 사각형 광원 `AreaLight3D` |
| 셰이더   | 텍스트 셰이더 연산을 입력하는 즉시 편집기 안에서 미리 보기                  |
| GUI      | 컨테이너 배치를 깨지 않고 `Control` 노드를 이동, 회전, 확대하는 오프셋 변환 |
| 텍스처   | 텍스처에 직접 그리는 `DrawableTexture2D`                                    |
| 편집기   | 2D 씬 페인터, 3D 정점 스냅, 트랙볼 회전, MeshLibrary 편집기                 |
| 입력     | 내장 `VirtualJoystick` 노드, 자이로 조준, iOS 컨트롤러를 SDL3로 교체        |
| 내보내기 | 필요한 플랫폼의 내보내기 템플릿만 내려받기                                  |
| Android  | Android 편집기만으로 게임을 내보내고 출시하는 GABE 정식판, 화면 속 화면     |
| XR       | Android XR과 Steam Frame 첫날 지원, Vulkan 서브샘플 이미지                  |
| 생태계   | 기존 Asset Library를 대체하는 Asset Store 통합                              |

페이지 말미에는 성장 수치가 나온다.
Steam에는 2026년 들어 700개가 넘는 Godot 게임이 새로 올라왔고,
이는 2025년 한 해 1,200여 개의 절반을 반년도 안 되어 넘긴 것이다.
itch.io에는 매주 1,000개가 넘는 Godot 게임이 올라온다고 한다.

### 4.7.2와 4.8 dev 7

4.7.2는 39명의 기여자가 57개 수정을 보낸 유지보수 릴리스다.
Windows에서 폴링 속도가 높은 마우스를 움직일 때 생기던 성능 문제 수정이
들어 있고, 이전 4.7.1과 알려진 비호환은 없다고 밝혔다.

4.8 dev 7은 기능 동결을 알린 스냅숏으로, 80명이 182개 수정을 보냈다.
GDScript 심볼 이름 바꾸기가 실험 기능으로 들어왔고,
물리 질의 결과를 재사용 가능한 객체에 받아 매 호출의
딕셔너리 할당을 피하는 API가 추가되었다.
이 API는 Juan Linietsky가 Godot 4.0 무렵 제안한 할당 없는 API 논의의
연장이라고 글은 설명한다.
iOS와 Android에 AccessKit 기반 스크린 리더 지원이 들어갔고,
글은 접근성이 모든 개발자의 최우선이어야 한다고 적는다.

## 조직과 돈

### 재단은 엔진을 소유하지 않는다

Godot Foundation은 Stichting Godot라는 이름으로 등록된 네덜란드 비영리 재단이다.
2022년 8월 23일에 설립되었고, 그 전까지 Godot는 Software Freedom Conservancy의
회원 프로젝트였다.
거버넌스 페이지는 재단이 상표, 계약, 은행 계좌를 Godot를 대신해 보유하지만,
엔진 소스의 저작권은 모든 기여자가 함께 갖는다고 밝힌다.
그리고 Godot는 어떤 회사도 팔거나 살 수 없다고 적는다.

재단을 이끄는 이사회는 창립자 Ariel Manzur와 Juan Linietsky를 포함한 10명이다.
이사회는 자금과 기관 차원의 결정을 하고,
기술 결정은 영역별 담당자(area owner)와 기술 리더십 위원회(TLC)가 한다.
TLC는 모든 병합에 최종 권한을 갖지만, 실제로는 이 권한을 쓸 일이 드물다고
페이지는 설명한다.
큰 작업은 `godot-proposals` 저장소에서 실제 프로젝트의 문제와 사용 사례를
바탕으로 먼저 논의하라고 권한다.

### 생태계 참여자에게 거는 조건

재단의 생태계 비전 문서는 Godot로 사업하는 사람과 회사를 생태계 참여자(GEP)로
정의하고 몇 가지를 분명히 한다.
누구도 Godot를 소유하거나 통제한다고 말해서는 안 된다.
GEP가 만든 기능이 업스트림에 들어간다는 보장도,
Godot가 GEP의 상품과 경쟁하는 기능을 만들지 않는다는 보장도 없다.
후원이나 기여는 커뮤니티 구성원으로 공개적으로 참여할 권리 이상을 주지 않는다.

2026년 6월에는 엔진 비전 문서도 처음 글로 정리되었다.
게임을 만드는 사람을 위한 도구, 작은 규모에서 중간 규모 팀이 전문가 품질의
게임을 출시하는 최고의 도구가 되겠다는 목표를 적었다.
크고 깨지기 쉬운 엔진보다 작고 단단한 엔진이 낫고,
흔한 요구만 기본으로 다루며 나머지는 플러그인과 확장에 맡긴다고 했다.
유료 등급이나 프리미엄 버전은 없을 것이고,
사람들이 가진 오래된 저사양 하드웨어 지원을 새 기능 때문에 희생하지 않는다는
원칙도 들어 있다.

### 기금 규모

개발 기금 페이지가 보여 주는 수치는 다음과 같다.

| 항목             | 값          |
| ---------------- | ----------- |
| 올해 일회성 기부 | 238,010유로 |
| 월 정기 후원     | 35,419유로  |
| 회원             | 1,828명     |
| 기업 후원사      | 23곳        |

홈페이지의 기업 후원사 목록에는 W4 Games, JetBrains,
Slay the Spire 2의 개발사 Mega Crit, Arm, DeNA, Re-Logic, Sentry 등이 있다.
재단 사이트는 Godot 프로젝트가 전적으로 개인과 단체의 기부로 운영된다고 밝힌다.

Clay John이 2026년 5월에 쓴 성장 통계 글은 이 돈의 흐름이
사용자 증가를 따라가지 않는다고 털어놓는다.
웹사이트 내려받기는 릴리스마다 대략 200만 회 선에 이르고,
Steam의 Godot 게임 출시 수는 지수적으로 늘고 있으며,
커뮤니티 규모는 지난 몇 년 사이 두 배가 되었다.
그런데 2023년 9월 기금을 연 뒤 월 수입은 크게 변하지 않았다.
글은 새 사용자가 재단을 돈이 필요 없는 자리 잡은 회사로 보거나,
Godot를 큰 엔진의 무료 대안으로만 본다는 가설을 들었다.
기부를 늘리는 최선의 방법은 기부를 요청하는 것이었으니
앞으로 더 자주 요청하겠다고도 적었다.

## 생태계

### 콘솔은 제3자에게 맡긴다

콘솔 지원 페이지는 공식 콘솔 이식을 하지 않는 이유를 라이선스에서 찾는다.
콘솔은 비밀 유지 계약과 전용 SDK, 승인된 하드웨어가 필요한 닫힌 플랫폼인데,
MIT로 공개된 엔진은 그런 제약을 담을 수 없다는 것이다.
그래서 콘솔용 내보내기 템플릿은 공식 SDK로 빌드해
승인된 개발자끼리만 비공개로 나눈다.
W4 Games는 Nintendo Switch, Xbox Series X/S, PlayStation 5용 미들웨어
이식판을 판매하고,
RAWRLAB Games, Lone Wolf Technology, Pineapple Works 같은 이식 업체도
목록에 있다.
페이지는 이 목록이 품질을 보장하지 않으니 직접 비교하라고 덧붙인다.

### Asset Store

4.7과 함께 Asset Library를 대체하는 Asset Store가 들어왔다.
2026년 5월의 소개 글은 원래 재단이
에셋 스토어를 직접 운영할 계획이 없었다고 밝힌다.
그런데 어느 외부 스토어가 재단의 공식 스토어인지 사용자가 헷갈렸고,
일부 스토어는 Kenney의 무료 에셋을 유료로 팔기도 했다.
기존 Asset Library는 별도 계정 체계를 쓰고 에셋을 직접 호스팅하지도 않았다.
새 스토어는 Godot 공용 계정을 쓰고 리뷰와 평점, 게시자 분석,
버전별 내려받기를 지원한다.
지금은 베타로 무료 에셋만 올릴 수 있고,
로드맵에서 가장 기대되는 항목이 에셋 판매다.
기존 Asset Library는 구버전 엔진을 위해 남겨 두되 곧 읽기 전용이 된다.

### 쇼케이스

쇼케이스 페이지에는 Slay the Spire 2, Brotato, Buckshot Roulette,
Cassette Beasts, Dome Keeper, Cruelty Squad, Halls of Torment,
Blender Studio의 DOGWALK 같은 게임과 픽셀 아트 편집기 Pixelorama,
지도 제작 도구 Dungeondraft 같은 앱이 올라 있다.
Slay the Spire 2는 2026년 3월 앞서 해보기로 나왔고,
개발사 Mega Crit은 기업 후원사이기도 하다.

## 기여 정책의 전환

2026년 6월 30일 재단은 기여 정책을 바꾼다고 발표했다.
글은 몇 년 동안 PR이 너무 많아 감당하지 못했고,
열린 PR 수가 커뮤니티의 농담거리가 되었다고 인정한다.
원인은 자격 있는 리뷰어가 적고 리뷰가 힘든 일이라는 데 있었는데,
AI 생성 기여가 늘면서 PR을 만드는 비용은 내려가고 리뷰 비용과 인력은 그대로라
더는 무시할 수 없게 되었다.
글은 AI 기여가 사기를 꺾는다고도 적는다.
리뷰는 지루하지만 미래의 메인테이너를 가르친다는 보람이 있는데,
피드백이 기계에 흡수될 뿐이라면 여가를 리뷰에 쓸 이유를 찾기 어렵다는 것이다.

바뀌는 규칙은 다음과 같다.

| 규칙                                | 내용                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------- |
| 새 기여자의 기능 추가와 큰 리팩터링 | 메인테이너의 명시적 허락 없이는 금지, 병합된 PR이 3개 이하면 새 기여자 |
| 자율 AI 에이전트와 바이브 코딩      | 금지, 이미 GitHub 저장소에서 자동 차단 대상                            |
| AI로 상당한 분량의 코드 생성        | 금지, 코드 완성이나 정규식 같은 사소한 보조만 허용                     |
| AI 사용 공개                        | 어떤 형태로든 썼다면 PR 토론에 밝혀야 함                               |
| 사람 사이 소통의 AI 생성 텍스트     | 금지, 사람이 쓴 원문의 기계 번역은 허용                                |
| 병합 전 사람의 리뷰와 승인          | 기존 관행을 명문화                                                     |

글은 AI 도구가 매일 바뀌니 보수적으로 접근하되
상황에 따라 다시 평가하겠다고 맺는다.

## 분석

### 엔진의 경쟁력은 기능표보다 소유 구조에서 나온다

Godot 홈페이지와 기능 페이지는 노드 시스템, 전용 2D, XR을 앞세우지만,
이 엔진이 다른 엔진과 가장 다른 점은 기능이 아니라 누구의 것이냐다.
라이선스는 MIT이고, 저작권은 기여자 전원에게 흩어져 있으며,
상표와 계좌를 가진 재단은 엔진을 소유하지 않는다고 스스로 밝힌다.
이 구조에서는 어느 회사가 재단을 사들여도
이미 공개된 엔진의 조건을 바꿀 수 없다.

이 점이 무게를 갖는 것은
상용 엔진의 가격 정책이 개발자에게 위험이 될 수 있다는 것을
업계가 한 번 겪었기 때문이다.
홈페이지를 올린 2023년 9월 HN 스레드에서 fnordpiglet은
Unity 라이선스 변경 소식과 관련해
두 엔진의 차이가 얼마나 되는지 물었다.[^fnordpiglet]
4.7 릴리스의 Lobste.rs 스레드에서 hoistbypetard는 Unity의 가격 변경 시도가
Godot에 관심과 기여자 양쪽으로 큰 힘을 주었다고 보았고,
자신도 다음 게임 잼에서는 Godot를 쓸 생각인데 그 이유 중 하나가
사용자를 배신할 듯한 발표들이었다고 적었다.[^hoistbypetard]
그러나 2022년 HN 스레드에서 terrycody는 반대 방향의 걱정을 했다.[^terrycody]
지금 Godot를 배웠는데 언젠가
Unity나 Unreal이 엔진을 공개하면 어떻게 되느냐는 것이다.
이 질문은 Godot를 고르는 이유가 기술보다 조건에 있을 때 생기는 불안을 보여 준다.

### 재단 문서들은 회사가 개입하는 길을 미리 막는다

생태계 비전 문서는 법률 문서처럼 읽히지만 실제 목적은 분명하다.
W4 Games 같은 회사가 Godot 위에서 사업을 하고 투자를 받는 상황에서,
어느 회사도 Godot의 방향을 좌우한다고 말하지 못하게 하는 것이다.
후원은 영향력을 사지 못하고, 업스트림 반영도 보장하지 않으며,
Godot는 GEP의 사업과 경쟁하는 기능을 만들 수 있다고 미리 적어 둔다.

4.7에 내장된 `VirtualJoystick`과 재단이 직접 운영하게 된 Asset Store는
이 조항이 말뿐이 아님을 보여 준다.
가상 조이스틱은 원래 커뮤니티 애드온이 채우던 자리였고,
에셋 스토어는 itch.io 등 외부 스토어에 맡기던 영역이었다.
재단은 모호함과 혼란을 이유로 이 영역에 들어왔다.

### 성장 지표와 재정 지표가 서로 다른 이야기를 한다

4.7 페이지와 성장 통계 글은 출시 게임 수, 내려받기 수,
게임 잼 점유율로 성장을 보여 준다.
그런데 같은 글이 기금의 월 수입이 2023년 이후 크게 변하지 않았다고 털어놓는다.
월 35,419유로는 유럽 기준으로
숙련 엔진 개발자 몇 명의 인건비에 해당한다는 것이 필자의 추정이다.
4.7.2 글도 Godot가 자원봉사자와 소수의 유급 기여자로 유지된다고 적는다.

이 차이는 기여 정책 글과 바로 이어진다.
열린 PR이 5,479개, 열린 이슈가 13,389개, 기능 제안이 6,481개 쌓여 있는데,
이것을 처리할 리뷰어는 기부로 고용한 몇 명과 자원봉사자뿐이다.
사용자가 늘수록 요구와 기여는 늘지만 리뷰 역량은 돈을 따라가므로 늘지 않는다.
AI 기여 금지는 이 병목이 한계에 닿았다는 신호로 읽힌다.

### 기여 정책은 코드가 아니라 사람을 지키려는 규칙이다

기여 정책 글의 논리는 AI 코드가 나쁘다는 데 있지 않다.
글이 내세우는 근거는 책임과 육성이다.
코드를 고칠 수 있는 사람이 책임져야 하고,
리뷰가 미래의 메인테이너를 키우는 과정이어야 한다는 것이다.
새 기여자는 버그 수정과 문서로 신뢰를 쌓은 다음에 큰 기능에 손대라는 규칙도
같은 뿌리에서 나온다.

Lobste.rs에서 cceckman은 이 규칙이 어떤 팀에든 좋은 원칙이라고 했다.[^cceckman]
새로 들어온 사람은 직급과 상관없이 첫 작업으로
모든 것을 다시 설계하지 않는다는 것이다.
speednoisemovement는 그러려면 메인테이너가 입문용 버그 목록을 늘 채워 두고
그 다음 단계로 가는 길을 만들어야 한다고 덧붙였다.[^speednoisemovement]
viccuad는 바로 그 입문용 버그 목록이 찾기 쉽고 자동화하기 쉬워 나쁜 AI 기여를
끌어들인다고 지적했다.[^viccuad]
HN에서 Fraterkes는 리뷰가 새 기여자를 가르칠 기회라는 대목이
주니어 자리의 미래와 맞닿아 있다고 보았다.[^Fraterkes]

## 비평

### 홈페이지는 콘솔과 C#의 공백을 너무 가볍게 다룬다

홈페이지는 모든 플랫폼에 출시하라고 말하고,
콘솔도 제3자 퍼블리셔를 통해 지원한다고 한 줄로 덧붙인다.
그러나 콘솔 지원 페이지를 읽으면 그 한 줄 뒤에 개발자 등록, 승인,
비공개 가격의 개발 키트, 등급 심사, 유료 미들웨어나 이식 업체 계약이 있다.
상용 엔진은 이 비용의 상당 부분을 라이선스 안에 흡수하지만,
Godot를 쓰는 작은 팀은 그것을 따로 산다.
무료라는 말은 엔진에는 맞지만 콘솔 출시까지의 경로 전체에는 맞지 않는다.

C#도 비슷하다.
홈페이지의 C# 안내는 Godot 4.2 기준이라고 적혀 있는데, 최신판은 4.7.2다.
웹에서 C#을 쓰려면 3.x로 돌아가라는 안내가 몇 년째 남아 있다는 것은
Unity에서 넘어오는 C# 개발자에게 웹 배포가 여전히 막혀 있다는 뜻이다.
기능 페이지의 .NET 안내도 웹 지원은 언젠가 추가될 것이라는 말에 그친다.

### 작고 단단한 엔진이라는 비전과 릴리스의 방향이 엇갈린다

비전 문서는 크고 깨지기 쉬운 엔진보다 작고 단단한 엔진이 낫고,
흔하지 않은 요구는 플러그인에 맡긴다고 했다.
그런데 4.7 릴리스 페이지의 기능 목록은 HDR 출력, 사각형 광원, 화면 속 화면,
자이로 조준, 텍스처 그리기, 가상 조이스틱까지 넓게 퍼져 있다.
HN에서 quicekuru는 가상 조이스틱이 꼭 엔진에 있어야 하는지,
에셋 스토어에 둬도 되지 않느냐고 물었다.[^quicekuru]
반면 lynndotpy는 씬 페인팅을 GameMaker 사용자가 Godot에서 가장 아쉬워하던
기능이라며 반겼다.[^lynndotpy]

두 반응은 비전 문서의 기준이 실제로는
판단을 대신해 주지 못한다는 것을 보여 준다.
어떤 기능이 흔한 요구인지는 누가 묻느냐에 따라 다르고,
비전 문서도 개별 변경을 평가하는 도구가 아니라고 스스로 밝힌다.
엔진이 커질수록 작게 유지하겠다는 원칙과 계속 넓어지는
기능 목록 사이의 긴장은 커질 것이다.
우선순위 페이지가 헤드리스 명령줄 내보내기의 신뢰성, 성능 디버깅 도구,
디퍼드 렌더러, 텍스처 스트리밍처럼 대규모 프로젝트에 필요한 기반 작업을 여전히
바람 목록에 올려 두고 있다는 점도 같은 긴장을 보여 준다.

### 기여 정책은 병목을 줄이지만 원인을 없애지는 않는다

기여 정책 글은 리뷰어 부족을 스스로 인정한다.
그러나 새 규칙은 들어오는 PR의 양을 줄일 뿐, 리뷰어를 늘리지는 않는다.
리뷰어가 부족한 이유는 성장 통계 글이 보여 주듯
사용자 증가가 재정으로 이어지지 않기 때문인데, 정책은 이 부분을 다루지 않는다.

강제할 방법도 분명하지 않다.
AI 사용 공개 의무는 정직한 기여자에게만 부담을 주고,
AI로 만들었지만 사람이 쓴 것처럼 다듬은 코드는 걸러지지 않는다.
HN 토론에서 ivorius는 메인테이너들이 이미 과거 기여의 질을 보고 리뷰하며,
신뢰받는 기여자에게 AI 사용을 허용하자는 안도 논의되었지만
반대할 이유가 더 많았다고 전했다.[^ivorius]
즉 이 정책은 기계적 판별이 아니라 메인테이너의 판단에 기대고 있고,
그 판단력이 바로 부족한 자원이다.

반대편의 비판도 근거가 약하다.
charlie90은 AI로 엔진과 편집기 도구를 만드는 것이 쉬워져
일주일이면 자기 게임에 필요한 Godot 기능을 넘어설 수 있다며
이 정책을 큰 실수라고 했다.[^charlie90]
이에 jplusequalt는 자신이 일하는 폐쇄형 3D 엔진도 40만 줄이 넘는다며,
초보자가 Claude나 Codex로 그것을 1년 안에 재현할 수 없다고
반박했다.[^jplusequalt]
uyzstvqs는 AI 사용을 허용하는 포크 Redot이 이미 있다고 소개했는데,[^uyzstvqs]
정책이 틀렸다면 그런 포크가 앞서갈 것이므로
이 논쟁은 결국 결과로 판가름 날 것이다.

### MIT 라이선스는 사용자를 지키지만 프로젝트를 지키지는 않는다

2022년 HN 스레드에서 flutas는
Tesla가 차량 시각화에 Godot를 쓴다고 전했고,[^flutas]
AdmiralAsshat는 MIT 라이선스라서 큰 회사가 쓰더라도
수정 사항을 돌려줄 법적 의무가 없다고 지적했다.[^AdmiralAsshat]
홈페이지와 거버넌스 문서는 MIT가 사용자에게 주는 자유를 강조하지만,
그 자유가 재정 문제와 어떻게 이어지는지는 말하지 않는다.

성장 통계 글이 든 가설 가운데
새 사용자가 Godot를 큰 엔진의 무료 대안으로 본다는 것이 있다.
이것은 사용자 탓이 아니라,
MIT 라이선스와 이 엔진이 고른 포지셔닝의 자연스러운 결과다.
같은 스레드에서 Aeolun은
Godot가 금전적 유인과 마켓플레이스를 찾지 못한 것이 오히려 장점이며,
사랑으로 만든 몇 안 되는 성공 사례라고 했다.[^Aeolun]
그로부터 4년 뒤 재단은 에셋 판매를 로드맵의 가장 기대되는 항목으로 올렸다.
사랑만으로는 리뷰어를 고용할 수 없다는 것을 재단 스스로 받아들인 셈이다.

## 인사이트

### 오픈소스 엔진의 진짜 병목은 코드가 아니라 리뷰다

AI가 코드를 만드는 비용을 낮추자 Godot에서 가장 비싼 자원이 무엇인지 드러났다.
HN에서 SwtCyber는 AI가 업계에서 가장 비싼 자원 하나를 우연히 찾아냈는데,
그것은 본업이 끝난 저녁에 오픈소스를 관리하는 사람들의 자유 시간이라고
썼다.[^SwtCyber]
코드를 쓰는 사람은 거의 무한히 늘 수 있지만,
그 코드가 엔진 전체와 어떻게 맞물리는지 판단하는 사람은 늘지 않는다.

이것은 Godot만의 문제가 아니라, 기여가 쉬워질수록
모든 대형 오픈소스 프로젝트가 맞닥뜨릴 구조다.
리뷰 역량이 일정하면, 기여 비용이 0에 가까워질수록
프로젝트는 입구에서 마찰을 다시 만들 수밖에 없다.
Godot가 선택한 마찰은 병합된 PR 3개라는 신뢰 단계와 사람이 썼다는 서약이다.
이 마찰이 진짜 신규 기여자까지 막는지, 아니면 걸러 내는 역할만 하는지는
한두 해 뒤 신규 메인테이너 수를 보면 알 수 있을 것이다.

### Blender의 길을 가지만 Blender의 수익 구조는 아직 없다

Lobste.rs에서 zipy124는
Godot가 게임 개발계의 Blender가 될 가능성이 크다고 했다.[^zipy124]
비교는 들어맞는 부분이 많다.
둘 다 상용 도구가 지배하던 분야에서 무료 오픈소스로 출발했고,
재단이 기부로 개발자를 고용하며,
상용 도구의 가격 정책에 대한 반발이 성장을 거들었다.

하지만 필자가 아는 Blender는 대형 기업 후원과 자체 영화 프로젝트로
개발 인력을 키웠고, 앞의 기금 수치로 보면 Godot는 아직 그 단계에 이르지 못했다.
Blender Studio가 Godot로 DOGWALK를 만들어 쇼케이스에 올라 있다는 점은
두 프로젝트가 이미 서로를 참고하고 있다는 신호다.
2023년 HN 스레드에서 kelseyfrog가 Blender의 오픈 무비처럼 Godot도
오픈 게임 프로젝트를 하면 어떠냐고 물은 것도 같은 맥락이다.[^kelseyfrog]
Godot가 Blender의 위치에 오르려면 사용자 수가 아니라
기업 후원의 규모와 지속성이 따라와야 한다.
Mega Crit처럼 Godot로 큰 성공을 거둔 스튜디오가
후원사로 올라선 것이 그 출발점이 될 수 있다.

### 기여자가 흩어질수록 비전은 문서로 남겨야 한다

재단은 2026년 6월 엔진 비전을 처음으로 글로 정리하면서,
그동안 비전은 창립자들의 머릿속에 있었고 기여자들은
대화로 그것을 배웠다고 설명했다.
같은 시기에 기여 정책이 바뀌고 생태계 비전 문서가 회사의 영향력을 제한했다.
세 문서는 모두 기여자와 회사가 늘어
대화만으로는 방향을 공유할 수 없게 된 프로젝트의 대응이다.

Lobste.rs에서 muvlon은 4.7의 주요 기능마다 기여자 이름이 모두 다르다는 점이
믿음직하다고 했다.[^muvlon]
예전에는 Godot가 대부분 Juan Linietsky의 작업이었다는 것이다.
기여자가 다양해지면 엔진은 한 사람에게 덜 의존하지만,
무엇을 넣고 무엇을 뺄지에 대한 감각도 흩어진다.
문서화된 비전은 이 감각을 대신하려는 시도이고,
앞으로 기능 논쟁이 비전 문서의 문장을 근거로 벌어지게 될 것으로 보인다.

### 텍스트 기반 씬 파일은 엔진이 막은 AI를 사용자 쪽에서 반긴다

AI 기여 금지 스레드에서 maiybe는
이 정책이 Godot의 느린 쇠퇴로 이어질 것이라 예상하면서도,
역설적으로 지금 AI 보조 코딩에 가장 좋은 엔진은 Godot라고 했다.[^maiybe]
씬 파일이 일반 텍스트라서 모델이 설계하고, 스크린숏을 보고,
반복하는 흐름이 잘 돌아간다는 것이다.

이 점은 정책과 묘한 대조를 이룬다는 것이 필자의 해석이다.
Godot 엔진 자체에는 AI가 쓴 코드를 받지 않지만,
Godot로 게임을 만드는 사람은 AI와 가장 잘 맞는 엔진을 쓰는 셈이다.
엔진 내부의 품질은 사람이 지키고, 엔진 위의 생산성은 AI가 끌어올리는
분업이 자리 잡는다면,
오픈소스 인프라와 그 위의 응용이 AI를 대하는 방식이 갈라지는
하나의 모델이 될 수 있다.
