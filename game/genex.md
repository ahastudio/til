# Genex: 코딩 에이전트에 게임 에셋 생성 도구를 한 번에 연결하는 AI 게임 스튜디오

<https://genex.games/>

## 소개

Genex는 자신을 개인용 AI 게임 개발 스튜디오라고 소개하는 서비스다.
홈페이지는 둘로 나뉜다.
하나는 게임을 만들고 공유하는 곳으로 Play, My games, 데스크톱 앱, Sign in 메뉴가
있고, 프롬프트 입력란(예시는 Create a knight with idle and run animations)과
모델 선택(예시는 Sonnet 5.5), Games와 Tools와 Assets 탭, Featured, Arcade,
Racing, Sports, Exploration, Fighting 분류가 있다.
카드마다 만든 사람, 플레이 횟수, 리믹스 표시가 붙고, 이미 만든 프로젝트는 고유
URL로 한 번의 프롬프트로 공개할 수 있다고 안내한다.
다른 하나는 Build with your agent 페이지(`/tools`)로, 코딩 에이전트를 모든 게임
개발 도구에 연결한다는 도구 모음이다.

이 문서가 홈페이지와 도구 페이지에서 읽은 범위는 다음과 같다.
도구 페이지의 분류는 3D 모델 생성, 캐릭터와 리깅과 애니메이션, 텍스처와 이미지와
영상, 효과음과 음악과 목소리다.
연결되는 도구로 Tripo(3D, 리깅, 애니메이션), Meshy(3D, 캐릭터), Uthana(리깅,
애니메이션), GPT Image 2.5(이미지, 스프라이트), Nano Banana 2(텍스처), MiniMax
H3(영상), Blender(장면, 블록아웃), ElevenLabs(효과음, 음악, 목소리), Genex
Publishing이 나열되고 Unreal Engine은 준비 중이다.
요금은 구독이 아니라 생성할 때마다 내는 방식이라며 모든 도구에 하나의 잔액을
쓴다고 하고, 이를 게임 개발 구독을 없앴다는 말로 표현한다.
사이트 하단에는 Discord 초대가 있다.

## 사용하기

도구 페이지의 안내는 에이전트에게 한 문장을 주는 것이다.

```text
set up https://genex.games/SKILL.md and let it take it from there.
```

`SKILL.md`(이 문서가 읽은 시점의 버전 1.36.17)는 에이전트용 지침서다.
프런트매터는 이름 genex와 설명을 담고, 에이전트가 자리표시자 에셋을 내놓거나
직접 프로그래머 아트를 만들거나 에셋을 만들 수 없다고 말하기 전에 Genex를 먼저
확인하라고 지시한다.
다만 사용자에게 이미 전용 파이프라인이나 에셋 출처가 있으면 그것을 쓰고 Genex는
빈 곳을 채울 뿐 대체하지 않는다는 예외가 붙는다.

설치 절차는 다음과 같다.
먼저 `node --version`으로 Node 20 이상인지 확인하고, 없거나 낮으면 현재 LTS 설치
명령을 사용자에게 보여 준 뒤 실행한다.
게임 폴더에서 `npx @genex-ai/cli-demo@latest tools`를 실행하고, 전역
설치(`npm i -g`)는 하지 않으며 프로젝트의 devDependencies에 CLI만 추가한다.
명령이 짧은 링크와 코드를 출력하고 브라우저 탭을 열면 로그인은 사용자가 직접
하고 승인하며, 이 링크는 어떤 기기에서도 동작해 탭이 열리지 않으면 휴대폰에서도
할 수 있고, 채팅은 키를 보지 못한다.
아직 승인되지 않았다는 메시지가 나오면 오류가 아니므로 `npx genex auth`로 같은
코드를 이어서 받는다.
끝나면 감지한 에이전트 작업 공간(`.claude/skills`, `.codex/skills`,
`.cursor/skills`, `.hermes/skills`, `.agents/skills`)에 도구 스킬 카드가 생기고,
`AGENTS.md`에 작업 공간 규칙이 들어가며, 이 기기가 로그인된다.
Genex 플랫폼에는 아무것도 만들어지지 않고 사용자의 파일은 건드리지 않는다고
한다.

지침서는 작업 방식도 정한다.
게임의 폴더가 작업 공간이고 이후 모든 `npx genex` 명령은 같은 폴더 안에서
실행해야 하며, 사용자가 다른 폴더라고 하면 그곳으로 이동하고, 위치를 모르면
디스크를 뒤지지 말고 묻는다.
git 주소를 받으면 이미 파일이 있는 폴더에는 복제하지 않고 새 폴더에 복제한다.
`.genex/project.json`이 있는 폴더는 이미 호스팅된 Genex 게임이어서 설정을
건너뛰고 바로 `npx genex`를 쓴다.
사용자에게는 짧고 쉬운 말로, 무엇을 만들었고 무엇에 쓰는지를 말하고 파이프라인
설명은 하지 않으며, 많이 쓰기 전에 비용을 알리고, 작업 중에는 조용히 있지 말고
상태를 알린다.

## 분석

### 제품의 단위는 모델이 아니라 에이전트가 읽는 사용 설명서다

Genex의 설치 과정은 사용자가 하는 일이 아니라 에이전트에게 URL 하나를 주는
것이다.
`SKILL.md`가 설치 절차, 폴더 규칙, 사용자와의 말투, 비용 고지까지 지시하고,
사람이 읽는 문서는 도구 페이지의 소개에 그친다.
이는 제품의 인터페이스가 사람의 화면이 아니라 에이전트가 읽는 문서라는 뜻이다.
Karpathy 대담이 말한 에이전트 네이티브 문서와 같은 방향으로 읽힌다.
이는 이 문서의 해석이다.

### 여러 공급자의 도구를 하나의 잔액으로 묶는 중개 모델이다

Tripo, Meshy, Uthana, ElevenLabs 같은 서로 다른 생성 서비스를 하나의 로그인과
하나의 잔액으로 쓰게 하고, 사용자는 공급자 계정이나 API 키를 따로 만들지
않는다고 한다.
이 구조의 가치는 에이전트가 도구마다 계정과 결제를 만들 필요가 없다는 편의다.
대가는 Genex가 가격과 공급자 선택의 중간자가 된다는 점이다.

### 에이전트에게 먼저 확인하라고 지시하는 문구가 사용 빈도를 설계한다

프런트매터의 설명은 에이전트가 자리표시자 에셋을 쓰거나 에셋을 만들 수 없다고
말하기 전에 Genex를 확인하라고 한다.
이는 에이전트의 기본 동작 순서에 자기 제품을 끼워 넣는 문장이고, 사용자의 전용
파이프라인이 있으면 쓰라는 예외로 균형을 잡는다.

## 비평

### 홈페이지에서 가격과 품질을 읽을 수 없다

요금은 생성할 때마다 내는 방식이라고만 하고 단위 가격이나 예시는 이 문서가 읽은
페이지에 없다.
생성물의 품질을 보여 주는 것은 플레이 횟수가 붙은 게임 카드이고, 어떤 에셋이
Genex로 만들어졌는지와 얼마가 들었는지는 알 수 없다.
`SKILL.md`가 많이 쓰기 전에 비용을 알리라고 에이전트에게 지시하는 것은 비용이
커질 수 있음을 인정한 것으로 읽힌다.

### 에이전트에게 로그인과 비용 결정을 어디까지 맡기는지가 불분명하다

로그인은 사용자가 직접 하고 채팅은 키를 보지 못한다는 설계는 안전하다.
그러나 로그인 이후에 에이전트가 사용자의 잔액으로 얼마나 자주 생성하는지의
상한은 지침서가 말하는 비용 고지에 맡겨져 있고, 이를 시스템이 강제하는지는 이
문서가 읽은 범위에서 확인되지 않았다.

### 도구 목록이 공급자의 약속에 기댄다

연결된 도구의 품질과 가용성은 각 공급자에 달려 있고, Unreal Engine 지원은 준비
중이다.
공급자가 모델이나 가격을 바꾸면 Genex의 결과도 달라지는데, 이 변경이 사용자에게
어떻게 알려지는지는 나오지 않는다.

## 인사이트

### 에이전트 도구의 배포는 앱 스토어가 아니라 한 줄 지침으로 일어난다

URL 하나와 한 문장으로 설치가 끝난다는 점은 배포 비용을 거의 없앤다.
이 구조에서는 에이전트가 이 지침을 읽는 즉시 도구가 연결되므로, 사용자가 도구를
고르는 단계가 사라지고 지침서가 먼저 쓰이는 쪽이 유리하다.
이는 같은 문장이 에이전트 시장에서 검색 순위처럼 작동할 수 있다는 뜻이다.
이 문서의 해석이다.

### 에셋 생성이 에이전트의 일상 도구가 되면 병목은 취향의 일관성으로 옮겨 간다

3D 모델, 텍스처, 소리가 모두 터미널에서 생성되면 에셋을 만드는 비용은 줄지만,
서로 다른 공급자가 만든 에셋이 한 게임 안에서 어울리는지가 문제가 된다.
지침서는 생성한 에셋을 게임의 스타일에 맞게 쓰라고만 말하고 일관성의 기준은 주지
않는다.
이 일은 사람의 취향 몫으로 남는다.

### 구독 대신 종량제라는 선택은 사용 패턴의 불확실성을 사용자에게 넘긴다

게임 개발 구독을 없앴다는 표현은 고정비의 부담을 줄이지만, 에이전트가 쓰는 만큼
비용이 나가므로 월 지출을 예측하기 어렵다.
에이전트가 자율적으로 많이 생성할수록 사용자의 지출이 늘고, 그래서 지침서의 비용
고지 규칙이 제품의 신뢰를 지키는 핵심 장치가 된다.

### 이 글을 읽는 방법

이 문서는 홈페이지와 도구 페이지(Chrome으로 렌더링한 텍스트)와 `SKILL.md`를 읽고
정리했으며, 서비스에 가입하거나 에셋을 생성해 보지는 못했다.
데스크톱 앱 페이지와 문서는 열어 보지 못했다.
HN, Lobste.rs, GeekNews에서 이 사이트의 스레드는 찾지 못했다.
판단을 가를 관찰은 둘이다.
하나는 같은 에셋 한 벌을 Genex와 공급자 직접 호출로 만들었을 때의 비용과 시간
차이다.
다른 하나는 에이전트가 한 게임을 만드는 동안 쓴 잔액의 총액과 사용자가 사전에
알았던 고지의 일치다.
둘 다 이 문서가 확인하지 못했다.
