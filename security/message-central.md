# Message Central: 싱가포르 U2opia의 OTP·메시징 API와 문서가 서로 어긋나는 지점

<https://www.messagecentral.com/>

## 소개

Message Central은 SMS, WhatsApp, RCS, 음성 AI, eKYC를
한 콘솔에서 파는 CPaaS(Communication Platform as a Service)다.
홈페이지 제목은 SMS, WhatsApp, OTP, RCS API를 내건 CPaaS 플랫폼이고,
첫 화면 문구는 Twilio보다 최대 40% 싸다는 비교와 190개국 이상, 통신사 직접 연결,
OTP에는 발신자 ID(Sender ID) 등록이 필요 없다는 약속이다.
AWS Marketplace의 Buy with AWS로도 살 수 있다.

### 운영 주체

약관과 개인정보처리방침을 보면 서비스를 운영하는 회사는
싱가포르 법인 U2opia Mobile Pte. Ltd.다.
개인정보처리방침은 이 회사가 Message Central이라는 브랜드로
서비스를 소유하고 운영한다고 밝히고, 주소는 싱가포르 Sim Lim Tower다.
약관(2026년 8월 31일 개정)의 준거법은 싱가포르 법이고,
분쟁은 30일 협의를 거친 뒤 싱가포르 국제중재센터(SIAC) 중재로 간다.
FAQ가 보여 주는 OTP 문자 템플릿 끝에도 Powered by U2opia가 붙고,
WhatsApp 발신자 이름은 MessageCentral by U2opia Mobile이다.
홈페이지에서는 회사 이름이 거의 드러나지 않으므로,
계약 상대방은 약관에서 확인해야 한다.

### 제품군

| 제품        | 하는 일                                       |
| ----------- | --------------------------------------------- |
| VerifyNow   | SMS·WhatsApp OTP 발송과 검증, 대체 채널 발송  |
| MessageNow  | 거래성·광고성 SMS 발송, 양방향 SMS            |
| WhatsAppNow | WhatsApp Business API 브로드캐스트, 상담, OTP |
| RCSNow      | 이미지, 버튼, 캐러셀을 넣는 RCS 메시지        |
| P2A AuthNow | 사용자가 보내는 MO SMS로 번호를 확인하는 인증 |
| VoiceNow    | 음성 AI 에이전트                              |
| eKYC Now    | 신분증과 얼굴 대조 기반 본인 확인             |

이 문서는 인증과 직접 관련된 VerifyNow를 중심으로 본다.
P2A AuthNow는 새 Android 기기가 바이너리 MO SMS를 현지 번호로 보내고,
그 번호가 단축·장문 번호를 거쳐 기업에 전달되면,
기업이 그 정보로 번호를 확인하는 흐름이라고 설명한다.
사용자가 문자를 보내는 쪽이라는 점에서 `security/octomo-mo-sms-auth.md`의
OCTOMO와 같은 MO 방식이다.

## 채널과 가격

### SMS OTP

VerifyNow 가격 페이지는 종량제(pay-as-you-go)이고,
국가별 SMS 요금만 내며 검증 건당 요금은 0달러라고 적는다.
국가별 표는 세 쪽에 걸쳐 있고, 확인한 단가 몇 개는 다음과 같다.

| 국가       | SMS OTP 단가(USD)      |
| ---------- | ---------------------- |
| 미국       | 0.0087                 |
| 인도       | 0.00332 (30 paise INR) |
| 브라질     | 0.0097                 |
| 영국       | 0.054                  |
| 한국       | 0.0711516              |
| 일본       | 0.1209936              |
| 나이지리아 | 0.00683                |
| 파키스탄   | 0.5709                 |
| 잠비아     | 0.7502                 |

같은 OTP 한 건이 나라에 따라 100배 넘게 차이 난다.
가입하면 시험용으로 1,000 크레딧을 주고,
홈페이지는 이를 OTP 1,000건 무료로 표현한다.

### WhatsApp OTP

WhatsApp OTP는 Facebook Business Manager 없이 쓸 수 있다고 내세운다.
WhatsAppNow 가격표는 Meta의 대화 단가라며 마케팅, 유틸리티,
인증(OTP) 세 열을 보여 준다.
인증 열과 SMS OTP 단가를 나란히 두면 다음과 같다.

| 국가       | SMS OTP   | WhatsApp 인증 |
| ---------- | --------- | ------------- |
| 미국       | 0.0087    | 0.016065      |
| 영국       | 0.054     | 0.042602      |
| 한국       | 0.0711516 | 0.036176      |
| 나이지리아 | 0.00683   | 0.034153      |

WhatsApp OTP 페이지는 SMS만 쓸 때보다 인증 비용을 최대 60% 줄인다고 하지만,
이 표로 보면 한국과 영국에서는 WhatsApp이 싸고,
미국과 나이지리아에서는 SMS가 싸다.
VerifyNow의 WhatsApp OTP 단가가 WhatsAppNow 표와 같은지는 확인하지 못했다.

### 결제와 환불

결제는 지갑을 충전하는 선불이고, 신용카드나 인도의 UPI로 낸다.
FAQ는 유효기간 팩으로 산 크레딧은 기간이 지나면 사라진다고 적는다.
약관상 지갑 크레딧은 대체로 환불되지 않고,
무료 OTP·SMS 크레딧을 포함한 판촉 크레딧은 환불, 양도, 현금화가 모두 안 된다.
환불은 결제됐는데 지갑에 반영되지 않은 경우처럼 예외적인 경우에만,
결제일로부터 7일 안에 요청할 수 있다.
청구서 이의는 발행일로부터 15일 안에 제기하지 않으면 승인한 것으로 본다.
계약에 최소 월 사용액이 있으면 덜 써도 그 금액을 내고,
남은 약정은 다음 달로 넘어가지 않는다.
U2opia의 배상 한도는 직전 12개월 동안 낸 요금이다.

## VerifyNow API 동작

### 토큰 발급

모든 호출은 `https://cpaas.messagecentral.com` 아래에 있다.
먼저 `GET /auth/v1/authentication/token`에 `customerId`와 `key`를 넘겨
토큰을 받는다.
`key`는 계정 비밀번호를 Base64로 인코딩한 값이고,
문서 예시는 이것을 쿼리 문자열에 넣는다.
`scope`는 처음에 `NEW`이고, `country`와 `email`은 선택이다.
SDK 문서는 이 `authToken`이 24시간 유효하고 갱신할 수 있다고 적는다.
이후 요청에는 `authToken` 헤더로 넣는다.

### 발송

```bash
curl --location --request POST \
  'https://cpaas.messagecentral.com/verification/v3/send?countryCode=91&flowType=SMS&mobileNumber=9999999999' \
  --header 'authToken: <토큰>'
```

`flowType`은 채널이고 `otpLength`는 4에서 8 사이(기본 4)다.
응답의 `data`에는 `verificationId`, `transactionId`,
그리고 `timeout` 값 `"60"`이 들어 있다.
OTP는 서비스가 직접 만들고, 문자 본문은 승인된 고정 템플릿이다.
기업이 바꿀 수 있는 것은 템플릿 속 브랜드 이름뿐이고,
그것도 한 번 충전한 뒤에야 바꿀 수 있다.
발신자 ID는 인도에서 UTOMOB, 미국에서 승인된 10DLC 번호,
그 밖의 나라에서 U2InFO로 고정된다.
홈페이지가 말하는 발신자 ID 등록이 필요 없다는 약속은,
곧 U2opia의 공용 발신자와 공용 템플릿을 빌려 쓴다는 뜻이다.

### 검증

`GET /verification/v3/validateOtp`에 `verificationId`와 `code`를 넘긴다.
성공하면 `verificationStatus`가 `VERIFICATION_COMPLETED`로 온다.
응답 코드표에서 인증 흐름에 걸리는 것은 다음과 같다.

| 코드 | 이름                   | 뜻                                      |
| ---- | ---------------------- | --------------------------------------- |
| 506  | REQUEST_ALREADY_EXISTS | 같은 번호에 진행 중인 요청이 있음       |
| 700  | VERIFICATION_FAILED    | 검증 실패                               |
| 702  | WRONG_OTP_PROVIDED     | 틀린 코드                               |
| 703  | ALREADY_VERIFIED       | 이미 검증됨                             |
| 705  | VERIFICATION_EXPIRED   | 만료 뒤 입력                            |
| 800  | MAXIMUM_LIMIT_REACHED  | 그 번호의 하루 한도 도달(SDK 문서 설명) |

틀린 코드를 몇 번까지 받아 주는지,
한 번호의 하루 한도가 몇 건인지는 문서에 숫자가 없다.

### 만료와 재발송

FAQ에 따르면 재발송 간격은 기본 60초, 최소 20초, 최대 300초이고,
콘솔의 Validity Time 값으로 바꾼다.
Validity Time을 30초로 두면 30초 뒤에 재발송이 열린다는 예시로 보아,
코드 유효시간과 재발송 대기시간이 한 값에 묶여 있는 것으로 읽힌다.
발송 응답의 `timeout` 60은 이 기본값과 맞는다.
검증이 끝난 번호에는 대기 없이 바로 다음 OTP를 보낼 수 있다.
FAQ는 이와 별도로 SMS 재시도 알고리즘이 계속 돈다고 적지만,
그 재시도가 과금되는지는 밝히지 않는다.

### 대체 채널(fallback)

대체 채널 페이지는 기업이 채널 우선순위를 정하면,
첫 채널이 실패할 때 다음 채널로 성공할 때까지 넘어간다고 설명한다.
그러나 실제로 쓸 수 있는 순서는 SDK 문서가 가장 구체적으로 적는다.
지원하는 대체 경로는 SMS에서 WhatsApp으로 가는 것 하나이고,
WhatsApp에서 다른 채널로 가는 경로는 향후 출시 예정이다.
SDK에서는 `isFallbackEnable`을 `true`로 줄 때만 켜지고 기본값은 `false`다.
REST API 문서에는 대체 채널을 켜는 파라미터가 따로 없다.
SMS가 무엇을 기준으로 실패로 판정되는지, 몇 초를 기다린 뒤 넘어가는지,
두 채널 요금이 모두 나가는지도 적혀 있지 않다.

### 모바일 SDK

Android `.aar`와 iOS `.xcframework` 1.0.0이 2025년 2월에 처음 공개됐고,
둘 다 샌드박스나 모의 시험을 지원하지 않는다.
SDK 호출은 `VerifyNowSDK.verify` 하나이고,
인자로 국가 코드, 번호, `customerId`, `authToken`, `isFallbackEnable`,
콜백을 받는다.
결과는 앱의 콜백으로 `verified: true`가 돌아오는 구조다.
SDK FAQ는 SDK가 OTP 생성, 발송, 검증, 대체 채널,
재시도를 모두 처리해 백엔드 로직을 쓸 필요가 없다고 홍보한다.
Android는 SMS Retriever API로 문자를 자동으로 읽는다.

## 홈페이지와 문서가 어긋나는 곳

같은 회사의 페이지끼리 숫자와 약속이 맞지 않는 곳이 많다.

| 항목           | 한쪽 주장                                   | 다른 쪽 주장                                    |
| -------------- | ------------------------------------------- | ----------------------------------------------- |
| 검증 수수료    | 가격 페이지: 검증 건당 0달러                | VerifyNow FAQ: 검증되면 검증 수수료를 청구      |
| Twilio 대비    | 홈페이지·FAQ: 40% 저렴                      | 개요: 건당 0.03달러 고정, 33% 저렴              |
| 절감률         | 개요: 0.05달러 대 0달러, 91% 절감           | Twilio 비교표: 양쪽 모두 0.03달러               |
| 대체 채널      | 홈페이지: SMS, WhatsApp, 음성               | 대체 채널 페이지: SMS, WhatsApp, RCS            |
| 실제 대체 경로 | 위 두 페이지: 성공할 때까지 다음 채널       | SDK 문서: SMS에서 WhatsApp으로만                |
| 발송 채널      | API 파라미터표: SMS/WHATSAPP/RCS/SAUTH      | 발송 설명: 지금은 SMS나 WhatsApp만              |
| 커버리지       | 홈페이지 상단·가격: 190개국 이상            | 홈페이지 통계: 150개국, SDK 문서: 200개국 이상  |
| 가용성         | 홈페이지: 99.9% 가용성, 예고 없는 장애 없음 | 약관: SLA 없이는 무중단을 보장하지 않음         |
| 전송 보장      | 대체 채널 페이지: 100% 보장된 인증          | 약관: 모든 메시지의 전달과 속도를 보장하지 않음 |
| iOS 지원       | SDK 릴리스 노트: iOS 16 이상                | SDK 기능표: iOS 12 이상                         |
| Android 지원   | 릴리스 노트: 7.0 이상으로 추정              | 기능표: 6.0 이상                                |

Twilio 비교 페이지의 고객 만족도 4.1 대 1.1은 출처 자리가 비어 있다.
여러 페이지에 `+50`이라는 자리표시자가 그대로 남아 있고,
WhatsApp OTP 페이지에는 무료로 X건을 준다는 문구가 채워지지 않은 채 있다.
API 문서 표는 필드 설명이 한 칸씩 밀려 `customerId`의 설명이 국가 코드,
`langid`의 설명이 휴대폰 번호로 되어 있다.
응답 필드 이름도 API 문서는 `smCLI`와 `verficationId`,
개요 예시는 `smsCLI`로 서로 다르다.
iOS SDK의 대체 채널 설명은 USSD가 실패하면 검증이 실패한다고 적는데,
VerifyNow 어디에도 USSD 인증은 없다.
다른 제품 문서를 옮겨 오다 남은 흔적으로 보인다(해석).

Hacker News에서는 aisha_mc 계정이 2024년 1월부터 8월까지
인증이나 SMS를 묻는 여러 스레드에 Message Central을 권하는 댓글을 남겼다.[^aisha_mc]
프로필에 소속은 적혀 있지 않다.

## 함정

### 계정 비밀번호가 쿼리 문자열로 오간다

토큰 API는 계정 비밀번호를 Base64로 바꿔 쿼리 문자열에 넣으라고 한다.
문서는 이를 Base64 암호화라고 부르지만,
Base64는 인코딩일 뿐이라 누구나 되돌릴 수 있다.
쿼리 문자열은 프록시, 로드밸런서, APM 도구의 접근 로그에 남기 쉬우므로,
토큰 발급은 서버에서만 하고 그 URL이 로그에 찍히지 않게 막아야 한다.
FAQ는 Postman에서 `base64encode.org`에 비밀번호를 붙여 넣어 인코딩하라고 하는데,
운영 비밀번호로는 따르지 않는 편이 낫다.

### SDK를 문서대로 쓰면 계정 토큰이 앱에 들어간다

모바일 SDK는 `customerId`와 `authToken`을 앱에서 넘기게 되어 있다.
이 토큰은 24시간짜리 계정 토큰이라, 앱을 뜯어보거나 통신을 가로챈 사람이
그 시간 동안 같은 계정으로 아무 번호에나 OTP를 보낼 수 있다(해석).
검증 결과도 앱의 콜백으로 돌아오므로, 서버가 그 결과를 그대로 믿으면
조작된 클라이언트가 `verified: true`를 보내는 것을 막을 수 없다.
문서는 SDK 결과를 서버에서 다시 확인하는 방법을 설명하지 않는다.
SDK를 쓰더라도 토큰은 서버가 짧게 발급해 내려주고,
최종 판정은 서버가 `validateOtp`나 별도 조회로 다시 확인하는 구조가 안전하다.

### 문자 펌핑 비용은 고객이 진다

약관은 계정을 통한 모든 요금과 최종 사용자의 행위에 고객이 책임진다고 적는다.
인위적이거나 조작된 트래픽 생성은 금지 행위로 두고,
의심 트래픽은 U2opia가 바로 막을 수 있다고만 한다.
읽은 페이지 어디에도 SMS 펌핑(AIT)을 막는 국가 허용 목록이나
이상 트래픽 탐지 기능 설명은 없다.
번호당 하루 한도(800)가 유일하게 보이는 장치인데 그 숫자도 공개되어 있지 않다.
`security/ait-fraud.md`가 다루는 공격은 번호 입력 칸만 있으면 성립하므로,
가입 화면 앞에 봇 차단과 국가 제한을 직접 둬야 한다.
단가가 0.5달러를 넘는 나라가 표에 여럿 있다는 점을 생각하면,
국가 제한은 비용 관리이기도 하다.

### 공용 발신자는 평판도 공유한다

UTOMOB, U2InFO 같은 공용 발신자와 고정 템플릿을 쓰면 등록 절차는 건너뛰지만,
사용자 화면에는 내 서비스가 아니라 U2opia의 발신자가 뜬다.
같은 발신자를 쓰는 다른 고객이 스팸이나 사기에 쓰면,
통신사 필터링의 영향을 함께 받을 수 있다(해석).
약관도 전달이 스팸 필터와 발신자 ID 요건의 영향을 받을 수 있다고 적는다.
템플릿을 직접 쓰려면 VerifyNow가 아니라
MessageNow로 자기 발신자를 등록해야 한다.

### 무료 크레딧과 남은 잔액은 돌려받지 못한다

시험용 1,000 크레딧은 환불 대상이 아니고,
유효기간 팩 잔액은 기간이 지나면 사라진다.
환불 요청 기한이 결제일로부터 7일이라,
큰 금액을 충전한 뒤 시험을 오래 하다 보면 돌이킬 수 없게 된다.
처음에는 소액만 충전해 실제 국가별 도달률과 청구 내역을 확인하는 편이 낫다.
