# Nemotron 3.5 Transcribe와 Granary v2: 프롬프트로 조정하는 오픈 음성 인식 모델과 그 데이터

원문: [NVIDIA Nemotron 3.5 Transcribe and Granary v2: Intelligent Multilingual Transcription You Can Prompt and Adapt](https://huggingface.co/blog/nvidia/nemotron-transcribe-granary)

HN 토론: <https://news.ycombinator.com/item?id=50275128> (121점, 20개 댓글)

GN 토론: <https://news.hada.io/topic?id=36196>

## 요약

NVIDIA가 2026년 10월 28일 Hugging Face 블로그에 올린 글이다.
Nemotron 3.5 Transcribe는 녹음된 음성을 쓸모 있는 글로 바꾸는 오픈
가중치 모델이고
Hugging Face와 ModelScope에서 받을 수 있다.
하나의 체크포인트가 전사(transcription), 화자 구분(diarization), 번역,
오디오 질의응답을 맡고, 글은 40개 언어를 전사하고 그중 31개를 영어와 오가며
번역하고 13개 언어에서 화자를 구분한다고 쓴다.
최대 한 시간 길이의 녹음과 최대 여덟 명의 화자를 다루고,
자연어 지시(프롬프트)로 출력을 조절하고, 오디오를 처리할 위치를 고르고,
도메인 어휘와 억양에 맞춰 적응시킬 수 있다고 한다.
글은 이 모델이 녹음된 오디오용이고 실시간 스트리밍용이 아니라고 밝힌다.

구조는 음성 인코더에 하이브리드 Mamba–Transformer 전문가 혼합(MoE) 언어 모델을
붙인 것이다.
전체 300억 개 파라미터 중 토큰마다 약 40억 개만 활성화된다.
화자 구분은 Sortformer의 화자 단서가 음향 특징과 함께 언어 모델에 들어가서,
뒤 단계에서 화자를 단어에 붙이는 대신 생성하는 동안 발화마다 화자를 표시한다.

글이 내세우는 성적은 여러 평가에 걸쳐 있다.
Hugging Face Open ASR 리더보드 영어 부문에서 API 모델을 뺀 오픈 가중치 중 평균
단어 오류율(WER) 5.33퍼센트로 1위이다.
같은 리더보드의 다국어(일곱 개 언어) 평균 WER은 4.62퍼센트,
장문은 10.98퍼센트이며,
글은 모델 카드의 비교에서 오픈 가중치 중 가장 낮다고 적는다.
Artificial Analysis의 음성 인식 순위에서는 AA-WER 2.8퍼센트로 오픈
가중치 중 공동
1위이고, 같은 점수의 모델은 활성 파라미터가 24B라고 한다.
David AI의 21개 언어 화자 구분 순위에서는 화자 구분 오류율(DER) 18.26퍼센트로
가장 낮고, NVIDIA의 전용 모델 Nemotron 3 Diarization이 18.38퍼센트로
뒤를 잇는다.
VoiceArena의 14개 시스템 비교에서는 cpWER 32.4퍼센트로 1위이다.
처리량은 예정된 NVFP4 양자화 버전으로 RTX PRO 6000 Blackwell 한 장에서
100시간의 오디오를 3분 안에 처리했다고 한다.
다만 30초짜리 클립을 높은 동시성으로 돌린 측정이다.

글의 후반부는 데이터와 적응이다.
Granary v2는 NeMo Curator로 만든 다국어 음성 데이터의 공개
매니페스트와 재사용할 수
있는 정제 파이프라인이다.
매니페스트는 48개 언어, 16개 원천 코퍼스,
463,062시간이고 Granary v1의 25개 언어에서
늘었다.
글은 이 숫자가 데이터셋 공개분에 대한 것이지 Transcribe의 전체 학습
혼합이나 샘플링
비율이 아니라고 밝힌다.
같은 발화에 세 가지 전사 형태를 만든다.
텍스트 정규화된 축자 전사, 역텍스트 정규화(ITN)에 말 더듬음을 남긴 것,
말 더듬음을 뺀 것이다.
의료 사례 연구에서는 프롬프트에 영어와 라틴 문자를 명시해 WER을 30.8퍼센트에서
23.8퍼센트로 낮추고, 미세조정으로 11.8퍼센트까지 낮췄다고 한다.
화자를 나눠 따로 둔 평가 클립에서는 최선의 프롬프트 기준 22.44퍼센트가
12.17퍼센트로, 상대 45.8퍼센트 줄었다.

## 분석

### 하나의 모델이 여러 일을 하는 대가는 전용 모델과의 거리이다

글의 첫 설계 판단은 전사, 화자 구분, 번역, 질의응답을 하나의 체크포인트에
넣는 것이다.
장점은 같은 녹음에서 지시만 바꿔 다른 출력을 얻는다는 것이다.
단점은 각 일에서 전용 모델과 비교될 때 드러난다.
글이 보인 화자 구분 결과에서 Transcribe의 DER 18.26퍼센트는 전용 모델
Nemotron 3 Diarization의 18.38퍼센트보다 0.12퍼센트포인트 낮다.
통합 모델이 앞섰다는 서술은 맞지만, 차이는 작아서 전용 모델과 사실상 비슷하다고
읽는 편이 안전하다.
이 문서의 해석으로는 통합의 가치는 성능 우위가 아니라 파이프라인을 줄이는
데 있다.
전사 모델에 화자 구분 모델을 붙여 시간 정렬하는 두 단계가 한 번의 생성으로
줄어든다.

### 프롬프트가 출력 형식을 정하려면 학습 데이터에 그 형식이 있어야 한다

글은 프롬프트로 조절하는 모델에는 형식이 명확한 학습 목표가 필요하다고 쓴다.
Granary v2가 같은 발화에 세 가지 전사를 만드는 이유다.
예시는 “I paid, uh, twenty-five euros.”(축자), “I paid, uh, €25.”(ITN,
말 더듬음 포함),
“I paid €25.”(ITN, 말 더듬음 제외)이다.
모델이 프롬프트로 축자와 정돈된 전사를 오갈 수 있는 것은 학습에서 두 형식이 모두
정답으로 주어졌기 때문이다.
따라서 이 모델의 프롬프트 조절은 마법이 아니라 데이터 설계의 결과이고,
학습 목표에 없는 형식(예: 어떤 언어의 특정 표기 관례)은 프롬프트로
요청해도 잘 나올
이유가 없다.

### 적응은 프롬프트에서 미세조정으로 올라가는 단계이다

글이 권하는 순서는 프롬프트 먼저, 미세조정 나중이다.
개발 세트에서 언어, 문자, 전사 형식을 지정하는 프롬프트부터 시험하고,
남는 도메인 오류에는 대표 음성과 명시적 쓰기 목표를 짝지어 NeMo Speech로
미세조정한다.
의료 사례의 단계별 결과는 이 순서가 비용 대비 효과의 순서이기도 함을 보여 준다.
프롬프트만으로 7.0퍼센트포인트(30.8에서 23.8)가 줄고,
미세조정은 합성 음성 약 153시간, 억양 있는 영어 29시간, 의료 녹음 63시간으로
GB300 한 장에서 약 14 GPU 시간이 걸렸다고 글은 적는다.
이 수치는 글이 밝힌 대로 한 사례의 값이고, 다른 도메인에서 같은 비율을 기대할
근거는 아니다.

## 비평

### 순위의 범위를 좁히는 조건이 많다

글의 순위 서술에는 한정어가 붙어 있다.
Open ASR 리더보드 영어 1위는 API 모델을 뺀 오픈 가중치 중에서이다.
다국어는 일곱 개 언어의 평균이고, 글이 말하는 40개 언어 전체가 아니다.
Artificial Analysis의 2.8퍼센트는 공동 1위이고,
전체 모델 차트에서 널리 쓰이는 몇몇 상용 음성 API를 앞선다고 하지만
어느 API인지는
글에 없다.
David AI의 순위에서는 결합 부문에서 오픈 가중치 중 1위이고 전체 2위이다.
화자 구분과 VoiceArena에서 1, 2위를 모두 NVIDIA의 모델이 차지한다는 서술은
NVIDIA가 같은 문제에 여러 모델을 갖고 있다는 뜻이기도 하다.
이 한정어들은 글이 정직하다는 증거이지만, 독자가 한 줄만 읽으면 오해하기 쉽다.

### 의료 사례의 62퍼센트와 45.8퍼센트는 다른 시험의 값이다

글은 의료 사례에서 미세조정이 모델의 기본 상태보다 약 62퍼센트 적은
오류를 낸다고
쓴다.
그러나 이 수치는 프롬프트와 체크포인트를 고르는 데 쓴 855개 클립을 포함한
전체 테스트에서의 값이고, 글이 직접 지적하듯 더 깨끗한 시험은 따로 둔 2,764개
클립의 결과이다.
그 값은 최선의 프롬프트 기준 22.44퍼센트에서 12.17퍼센트로 상대
45.8퍼센트 감소이다.
같은 사례 안에서 두 수치가 다른 기준(기본 상태 대 프롬프트 최적화, 전체 대 보류
세트)이라서 크기가 달라진다.
일반 영어의 LibriSpeech test-clean은 1.54퍼센트에서 1.69퍼센트로 올라 상대 약
10퍼센트 나빠졌고, 글은 이를 약간의 상승이라고 쓴다.
브랜드 의약품명의 정확 일치는 의료 전문 모델이 여전히 앞선다고 글이 인정하고,
다음 단계로 임상의가 브랜드명을 말하는 실제 녹음을 든다.

### 처리량 수치는 아직 없는 버전으로 쟀다

100시간을 3분 안에 처리했다는 수치는 예정된 NVFP4 양자화 버전으로 쟀다.
지금 받을 수 있는 체크포인트가 아니다.
글은 클립이 30초이고 동시성이 높다는 조건도 밝힌다.
한 시간짜리 녹음 하나의 지연 시간과는 다른 측정이다.
지금 쓸 수 있는 방법은 vLLM이나 SGLang-Omni이고,
로컬 배포용 NeMo-Speech.cpp는 곧 나온다고만 한다.
따라서 처리량이 중요한 독자는 지금의 체크포인트로 직접 재야 한다.

### 사용자의 보고는 순위와 다른 이야기를 한다

HN의 사용자 보고는 적고 일화적이지만 순위와 결이 다르다.
mewse-hn은 Parakeet과 비교해 이 모델이 더 느리고 무겁고 오류율이 높았다고
썼다.[^mewse-hn]
그는 4비트 양자화로 돌린 것이라 완전한 정확도가 아닐 수 있다고 단서를 달았고,
내장 번역은 Parakeet의 전사를 클라우드 LLM에 넘기는 것보다
나빴으며,[^mewse-hn-translation]
애니메이션 한 편 전체에서는 주제가의 영어 단어에 혼란을 일으켜 세 번 크게
실패했다고 했다.[^mewse-hn-anime]
xpct는 최근 Nemotron 3를 써 봤는데 괜찮지만 표준 어휘의 데이터에서도 몇 문장마다
오류를 낸다고 했고, jiehong은 Parakeet이나 Qwen ASR이 더 낫다고
동의했다.[^xpct][^jiehong]
xpct가 쓴 것은 이 글의 모델이 아니라 이전의 Nemotron 3이므로 직접 비교는 아니다.
이 보고들은 리더보드가 재는 영어의 공개 테스트 세트와 실제 사용 환경이
다르다는 점을
보여 줄 뿐이고, 어느 쪽이 맞는지는 같은 입력으로 돌려 봐야 안다.

### 실시간이 안 된다는 한계는 용도를 좁힌다

글은 이 모델이 녹음된 오디오용이고 스트리밍이 아니라고 밝힌다.
solarkraft는 이 점이 아쉽다며, 독일어에 영어 용어와 브랜드명이 섞인
말을 잘 알아듣는
Nemotron Streaming으로 받아쓰기 문제가 거의 해결되었다고 했다.[^solarkraft]
받아쓰기와 실시간 자막 같은 가장 흔한 개인 용도가 이 모델의 범위 밖이다.
이 한계는 모델의 결함이 아니라 설계의 선택이고,
글이 이 선택의 이유(긴 문맥, 화자 구분, 번역의 통합)를 서술하지는 않는다.

## 인사이트

### 프롬프트에 따라 값이 달라지는 모델은 같은 모델로 비교할 수 없다

글의 사례에서 프롬프트 한 줄이 WER을 30.8퍼센트에서 23.8퍼센트로 7.0퍼센트포인트
바꿨다.
같은 글에서 1위와 다음 순위의 차이는 화자 구분 DER이 0.12퍼센트포인트,
AA-AgentTalk WER이 0.5퍼센트포인트(1.8 대 2.3), VoiceArena cpWER이
1.8퍼센트포인트(32.4 대 34.2)이다.
프롬프트가 바꾸는 폭이 이 순위 차이보다 클 수 있다는 뜻이다.
단위가 다른 평가이므로 직접 견줄 수는 없지만 크기의 감을 준다.
이 문서의 해석으로는 프롬프트로 조절하는 음성 모델의 비교는 프롬프트까지 정해서
해야 의미가 있고, 리더보드가 어떤 프롬프트를 썼는지가 숫자만큼 중요하다.
글은 이 점을 의료 사례에서만 보이고 리더보드의 프롬프트는 설명하지 않는다.
이 가설을 뒤집는 관측은 같은 모델을 여러 프롬프트로 리더보드에서 돌려도 순위가
바뀌지 않는 경우이다.

### 합성 음성은 어휘를, 실제 녹음은 발음과 환경을 가르친다

의료 사례의 데이터 설계는 쓰기 목표와 말하기 형태를 분리한다.
HbA1c가 정답 글자이고 합성기에는 “H B A one C”를 보낸다.
여러 TTS 목소리가 소리의 다양성을 넓히고 실제 녹음이 억양과 녹음 조건을 더한다.
글은 한 번의 모델 통과로 검색이나 후처리 없이 고정된 관례 프롬프트를
쓴다고 쓴다.
이 문서의 해석으로는 이 설계가 도메인 적응의 비용 구조를 바꾼다.
글자를 만드는 일(텍스트와 목록)은 싸고 합성할 수 있지만,
의료 전문 모델이 여전히 앞서는 브랜드명 정확 일치는 실제 발화를 요구한다고 글이
인정한다.
그러면 합성 데이터로 얻는 이득은 어휘의 철자까지이고,
화자와 발음의 변이는 실제 데이터에 기대어야 한다.
글이 권하는 실제 라벨 클립 100개 이상이 체크포인트 선택용으로 필요하다는 조언은
이 한계를 반영한다.

### 비교의 축이 전체 파라미터에서 활성 파라미터로 옮겨 간다

글은 Artificial Analysis의 정확도 대 활성 파라미터 도표에서 이 모델이
오픈 가중치의
파레토 경계에 있다고 쓰고, 같은 2.8퍼센트에 활성 파라미터 약 4B 대
