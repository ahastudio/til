# OpenMAIC: 주제나 문서를 넣으면 AI 교사와 AI 반 친구가 수업을 진행하는 오픈소스 교실

<https://github.com/THU-MAIC/OpenMAIC>

GN 토론: <https://news.hada.io/topic?id=37017>

## 소개

OpenMAIC(Open Multi-Agent Interactive Classroom)은 THU-MAIC 조직이 공개한
오픈소스 플랫폼이다.
저장소 설명은 “한 번의 클릭으로 몰입형 멀티 에이전트 학습 경험을 얻는다”이다.
주제를 적거나 자료를 붙이면 슬라이드, 퀴즈, 상호작용 시뮬레이션, 프로젝트 기반
학습(PBL)을 만들고, AI 교사와 AI 반 친구가 음성으로 설명하고 화이트보드에 그림을
그리며 토론한다고 README는 소개한다.
2026년 3월 11일에 만들어졌고, 2026년 11월 12일 GitHub API 기준으로 별 43,327개,
포크 6,678개, 열린 이슈와 풀 리퀘스트 198개이며 라이선스는 MIT다.
마지막 푸시는 11월 11일이다.
README 상단에는 JCST 2026에 실린 논문 “From MOOC to MAIC” 배지가 있다.[^jcst]
이 논문은 제목, 저자, 게재 정보만 확인했고 본문과 실험은 읽지 않았다.

## 무엇을 만드는가

### 수업 생성 파이프라인

입력은 주제 설명이나 PDF, Word, PowerPoint, 스프레드시트, 텍스트, 이미지,
오디오, 비디오 자료다.
고전적인 두 단계 파이프라인은 먼저 AI가 구조화된 강의 개요(outline)를 만들고,
개요의 각 항목을 하나의 장면(scene)으로 확장한다.
장면의 종류는 슬라이드, 퀴즈, 상호작용 모듈, PBL 활동이다.

- **슬라이드:** 음성 해설, 스포트라이트, 레이저 포인터 애니메이션을 곁들인다.
- **퀴즈:** 단일·복수 선택과 단답형을 실시간 AI 채점으로 다룬다.
- **상호작용 시뮬레이션:** HTML 기반 실험, 예를 들어 물리 시뮬레이터나 순서도다.
- **PBL:** 역할을 고르고 AI 에이전트와 마일스톤과 결과물이 있는 프로젝트를 한다.

v0.2.0에서 들어온 Deep Interactive Mode는 3D 시각화, 시뮬레이션, 게임, 마인드맵,
브라우저 안의 온라인 프로그래밍을 더한다.
AI 교사가 화면을 직접 조작해 핵심 영역을 강조하거나 힌트를 주는 방식이다.
더 완성도 높은 교육용 UI 생성은 별도 저장소 MAIC-UI를 안내한다.

### 멀티 에이전트 상호작용

README가 꼽는 상호작용은 네 가지다.
에이전트가 먼저 토론을 시작하는 교실 토론, 서로 다른 성격의 에이전트가
화이트보드와 함께 토론하는 원탁 토론, 자유 질문에 슬라이드나 다이어그램으로
답하는 Q&A, 방정식을 단계별로 풀고 순서도를 그리는 공유 화이트보드다.

### 에이전트 워크벤치

v1.0.0에서 대화형 강의 제작 에이전트인 워크벤치가 들어왔다.
세션은 데이터베이스에 저장되어 워커가 재시작해도 이어지고, 실행 중에 추가 지시를
받으며, 재생 가능한 이벤트 기록을 대화 화면으로 스트리밍한다.
에이전트는 불투명한 덩어리를 고치는 대신 검증되는 도구로 일한다.
커리큘럼 계획, 코스와 폴더 만들기, 장면 하나만 원자적으로 고치기, 페이지 생성과
복제와 재정렬, 자료 업로드와 추출, 이미지와 영상과 음성 생성, `.pptx` 가져오기가
그 예다.
내장 스킬은 24개이며 커리큘럼 계획, 심층 조사, 강의 스타일, 슬라이드 제작, PPTX
가져오기 등을 다룬다.
사용자가 만든 스킬은 소유자별로 저장된다.

워크벤치는 기본으로 꺼져 있고 다음 환경 변수로 켠다.

```env
NEXT_PUBLIC_WORKBENCH_ENABLED=true
OPENMAIC_AGENT_RUNTIME_ENABLED=true
```

`skills/openmaic/`의 스킬 패키지는 SKILL.md 형식이라 OpenClaw, Codex, DeepSeek,
WorkBuddy 같은 에이전트 환경에서 불러 쓸 수 있다고 한다.
Feishu, Slack, Telegram 같은 메신저에서 교실을 만들고, 모든 단계에서 사용자
확인을 받는다고 README는 설명한다.

### 내보내기

- `.pptx`: 이미지, 차트, LaTeX 수식이 있는 편집 가능한 슬라이드이며 상호작용과
  퀴즈와 PBL 장면은 “온라인으로 열기” 버튼과 QR 코드가 있는 자리 표시 슬라이드가
  된다.
- Resource Pack: PPTX에 상호작용 장면별 독립 웹 페이지를 더한다.
- 오프라인 HTML: 네트워크 없이 해설과 자막, 퀴즈까지 재생하는 파일 하나다.
- 교실 ZIP: 코스 구조와 미디어를 담아 다른 배포판으로 옮긴다.

## 설치와 운영

필요한 것은 Node.js 22.19 이상, pnpm 10 이상, PostgreSQL 16이다.
코스가 서버에 저장되므로 `DATABASE_URL`이 없으면 서버가 시작하지 않는다.

```bash
git clone https://github.com/THU-MAIC/OpenMAIC.git
cd OpenMAIC
pnpm install
cp .env.example .env.local
cp openmaic.example.yml openmaic.yml
pnpm db:up
pnpm dev
```

모델 설정은 `openmaic.yml`에서 한다.
공급자(provider)와 “슬롯(slot)”, 곧 개요, 슬라이드 내용, 음성 합성, 웹 검색 같은
AI 용도별로 모델을 지정한다.
지원 공급자는 OpenAI, Anthropic, Gemini, DeepSeek, Qwen, Kimi, Bedrock, Ollama와
로컬 Lemonade, FunASR 등이고 OpenAI 호환 API도 쓸 수 있다.
Docker Compose는 앱과 PostgreSQL 두 컨테이너이며 `127.0.0.1:3000`에서만 열린다.
다른 기기에 공개하려면 `ACCESS_CODE`를 설정하라고 README가 경고하는데, 설정하지
않으면 같은 포트에 닿는 누구나 라이브러리 전체를 소유하고 지우고 고칠 수 있다고
한다.

1.2.0부터 코스 생성이 요청보다 오래 사는 서버 프로세스에서 돌아가므로 Vercel
같은 서버리스 호스트는 지원하지 않는다.
MP4 영상 내보내기는 Chromium과 FFmpeg이 필요해 별도 `render-service` 컨테이너로
돌리며, `video-export` 프로파일로 켠다.

## 상태와 공개 방식

- 2026년 3월 v0.1.0부터 11월 10일 v1.5.0 릴리스 후보까지 8개월 동안 릴리스가
  20개 넘게 이어졌다.
- 6월 v0.3.0에서 MIT로 재라이선스되었다.
- v1.0.1부터 v1.1.3까지 한 달 안에 보안 릴리스가 연달아 나왔다.
SSRF와 DNS 리바인딩 수정, 코스 문서에 살균된 슬라이드 HTML만 싣는 조치, Next.js
  원격 코드 실행 패치 등이 README의 릴리스 소개에 적혀 있다.
- v1.3.0(지식 베이스)과 v1.4.0(PBL v3)은 되돌릴 수 없는 일방향 업그레이드다.
- 라이선스는 MIT지만 번들된 `packages/mathml2omml`은 LGPL-3.0 이상이다.

## 분석

### 이 프로젝트의 핵심 주장은 “교육 콘텐츠 제작”이 아니라 “교실 경험”이다

슬라이드나 퀴즈를 만드는 도구는 많다.
OpenMAIC이 차별점으로 내세우는 것은 생성된 자료를 AI 교사와 반 친구가 진행한다는
점이다.
README의 “멀티 에이전트”는 제작 도구가 아니라 수업 진행 방식을 가리킨다.
논문 제목이 “MOOC에서 MAIC로”인 것도 같은 방향이다.
온라인 공개 강좌(MOOC)를 에이전트가 상호작용하며 진행하는 수업으로 바꾸겠다는
구상으로 읽힌다.
다만 이 문서는 논문 본문을 읽지 않았으므로 구상의 근거는 README와 제목에서만
읽었다.

### 장면 단위 구조가 편집과 내보내기를 가능하게 한다

수업이 개요에서 장면으로 쪼개지고, 장면은 스테이지 DSL로 표현되어 에이전트
도구가 한 장면만 원자적으로 고친다.
장면마다 개정 번호가 데이터베이스에서 증가해 화면이 바뀐 장면만 다시 가져온다.
이 구조 덕분에 PPTX, 오프라인 HTML, ZIP 같은 서로 다른 형식으로 같은 코스를
내보낼 수 있다.
상호작용 장면은 PPTX에서 자리 표시 슬라이드가 되므로, 내보내기가 모든 것을
보존하지는 않는다.
이는 README가 스스로 밝힌 한계다.

### 설정이 많고 모델 의존이 크다

README는 모든 양식(생성 삽화, 해설, 영상, 웹 검색, 웹 가져오기)을 켜 둘 때 가장
좋다고 권하고 토큰 플랜 하나로 여러 기능을 설정하는 예를 든다.
즉 품질이 사용자가 연결하는 모델과 서비스에 달려 있다.
프로젝트가 제공하는 것은 조율 계층이고, 수업의 질을 만드는 부분은 외부 모델이다.

## 비평

### “한 번의 클릭”이라는 홍보와 설치 요구 사이의 간격이 크다

저장소 설명과 하이라이트는 한 번의 클릭을 약속하지만 직접 운영하려면 Node.js
22.19, pnpm 10, PostgreSQL 16, 두 개의 설정 파일, 모델 키가 필요하다.
스킬의 호스팅 모드는 open.maic.chat에서 접근 코드를 받아 설치 없이 교실을
만든다고 README는 적는데, 그 경우에는 입력한 자료가 누구의 서버에 남는지가
문제가 된다.
이 문서가 읽은 README에는 호스팅 모드의 데이터 보관 정책 설명이 없다.

### 학습 효과를 보여 주는 근거가 README에 없다

README는 기능 목록과 사용 사례(“30분 안에 Python을 처음부터 가르쳐 줘”,
“보드게임 Avalon 하는 법”)를 보여 줄 뿐, 이 교실로 배운 사람이 얼마나 배웠는지는
말하지 않는다.
AI가 만든 슬라이드와 퀴즈가 사실에 맞는지, 실시간 AI 채점이 정확한지를 검증한
수치도 없다.
논문이 이 평가를 다룰 가능성은 있지만 이 문서는 논문 본문을 읽지 않아 확인할 수
없다.
별 43,327개는 관심의 크기이지 교육 효과의 증거가 아니다.

### 보안 이력이 운영 위험의 크기를 보여 준다

한 달 사이의 연속된 보안 릴리스와 Next.js 원격 코드 실행 패치 언급은, 이 앱이
외부 URL을 가져오고 모델 응답으로 만든 HTML을 렌더링하며 임의의 공급자에
연결하는 구조라는 점과 맞는다.
취약점을 고치고 공개한 점은 긍정적이지만, 공개 배포를 계획한다면 기본이 열려
있다는 README 자신의 경고(`ACCESS_CODE`가 없으면 전체 접근 가능)를 그대로
받아들여야 한다.
일방향 업그레이드가 반복되는 것도 운영자에게는 롤백 계획이 필요하다는 뜻이다.

### 변화가 너무 빠르다

20개 넘는 릴리스가 8개월 안에 나왔고 11월에만 v1.3.1부터 v1.5.0 후보까지 다섯 번
나왔다.
빠른 개선은 활발함의 신호지만 설정 이름과 저장 방식이 바뀌어 기존 배포판이
이전을 요구받는다는 비용이기도 하다.
README는 레거시 환경 변수 일부가 여전히 동작하지만 `MODEL_ROUTES`는 슬롯으로
옮겨야 한다고 적는다.

## 인사이트

### 에이전트 교실의 병목은 생성이 아니라 검증이다

슬라이드, 퀴즈, 시뮬레이션을 몇 분 만에 만들 수 있게 되면 교사의 일은 만드는
것에서 확인하는 것으로 옮겨 간다.
OpenMAIC의 도구 구조(장면 하나를 원자적으로 고치고, 장면 미리보기를 렌더링해
눈으로 확인하는 도구)는 이 검토 단계를 지원하지만, 수업 내용의 사실 검증은
사용자 몫이다.
AI가 교사 역할을 맡는 순간 틀린 설명은 한 번의 오류가 아니라 수강생 전체에게
퍼지는 오류가 된다.
따라서 이런 도구를 쓰는 조직이 먼저 정할 것은 모델 선택이 아니라 누가 생성된
수업을 승인하는가다.
이는 이 문서의 제안이다.

### 에이전트 스킬이 제품의 배포 채널이 되고 있다

이 저장소는 `skills/openmaic/`로 OpenClaw, Codex, DeepSeek, WorkBuddy에서 불러
쓰는 스킬을 함께 제공한다.
교실 생성 기능이 앱 안의 화면이 아니라 메신저 대화나 IDE 안에서 호출되는 것이다.
사용자는 제품의 사이트를 방문하지 않고 에이전트에게 “이걸 가르쳐 줘”라고 말하며,
제품은 그 뒤에서 작업 큐와 결과 링크를 돌려주는 백엔드가 된다.
이 방향이 일반화되면 제품 경쟁은 화면 설계보다 에이전트가 호출하기 쉬운
형태인지로 옮겨 간다.
이는 이 문서의 해석이며 README는 이를 주장하지 않는다.

### 결론을 바꿀 관찰

- 학습 성과를 대조군과 비교한 평가가 공개되어 AI 교실이 기존 온라인 강의보다
  낫다고 나오면, 효과의 근거가 없다는 비평이 약해진다.
- 호스팅 모드의 데이터 보관과 접근 정책이 문서화되면, 자료를 올리는 부담에 대한
  우려가 줄어든다.
- 몇 달 동안 하위 호환을 깨는 변경이 멈추고 보안 릴리스가 줄어든다면, 운영
  위험에 대한 평가가 개선된다.
