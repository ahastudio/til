## 소개

OpenClaw 홈페이지의 표제는 “The AI that really does things”다.
머리말은 오픈 소스, 내 기기에서 실행, 누구의 사업 모델도 아님이라는 세
가지를 내세운다.
받은 편지함 정리, 이메일 발송, 일정 관리,
항공편 체크인을 WhatsApp이나 Telegram 같은 이미 쓰는 채팅 앱에서 맡길 수
있다고 소개한다.
혼자 쓸 수도 있고 팀과 공유할 수도 있다.
구독도, 호스팅 티어도, 토큰도 없으며 독립 501(c)(3) 재단이 관리한다고 밝힌다.

이 문서는 홈페이지가 소개하는 설치, 기능, 운영 주체를 먼저 정리한다.
그다음 이 저장소에 쌓인 OpenClaw 문서와 연결하고,
홈페이지의 주장을 따져 보는 분석, 비평, 인사이트로 끝낸다.
같은 범주의 제품으로 SpaceXSI의 Grok Bot이 있다.
둘을 나란히 놓은 비교는 [Grok Bot 문서](../ai-tool/grok-bot.md)의 `OpenClaw와
나란히 보기` 절에 있다.

## 설치와 앱

홈페이지는 설치 경로를 Apps, One-liner, npm, Hackable 네 갈래로 나눠 보여준다.
데스크톱 앱은 gateway, 채팅, 설정, 노드 기능을 한꺼번에 설치한다고 설명한다.
macOS 앱은 macOS 15 이상, Apple Silicon과 Intel 모두, 버전 v2026.10.8이다.
Windows 앱은 Windows 10과 11, x64와 ARM64,
버전 v2026.9.8-1이며 설치 탭에는 Windows가 베타로 표시된다.
Linux 앱은 이번에 새로 생겼다고 표시되며 x64용 AppImage와 Debian 패키지,
버전 v2026.10.8로 제공된다.
앱과 한 줄 설치는 Node.js와 나머지 의존성까지 설치해 준다고 한다.

터미널 설치는 아래 두 가지다.

```bash
# 한 줄 설치 (macOS, Linux)
curl -fsSL https://openclaw.ai/install.sh | bash

# 또는 npm으로 설치한 뒤 온보딩
npm i -g openclaw
openclaw onboard

# 릴리스 채널 전환
openclaw update --channel dev
openclaw update --channel stable
```

`curl ... | bash`는 받은 스크립트를 읽지 않고 곧바로 실행한다.
이 문서의 보충으로, 이 에이전트가 파일과 셸에 닿는다는 점을 생각하면 스크립트를
먼저 내려받아 읽거나 npm 경로를 택하는 편이 낫다.

## 기능

홈페이지는 기능을 여섯 가지로 묶는다.
기기에서 실행한다는 것은 Mac, Windows, Linux 어디서든 호스팅 모델,
구독 연동 모델, gateway 모델, 로컬 모델을 가져다 쓸 수 있고,
상태는 벤더 클라우드가 아니라 내 기기에 둔다는 뜻이다.
채팅은 WhatsApp, Telegram, Discord, Slack, Signal,
iMessage를 포함해 29개 채널에서 DM과 그룹 채팅 모두에서 쓸 수 있다.
기억은 대화가 바뀌어도 선호, 프로젝트, 사람을 기억한다.
시스템 접근은 웹 탐색, 양식 작성, 파일 읽기와 쓰기, 셸 명령 실행을 포함하고,
전체 접근과 샌드박스 중에서 사용자가 고른다.
팀 사용은 gateway 하나를 공유해 팀 전체가 세션을 열고 조종하며,
실시간 접속 표시와 사람별 커밋 귀속을 제공한다.
스킬과 플러그인은 커뮤니티 스킬을 쓰거나 직접 만들 수 있고,
에이전트가 스스로 스킬을 만들 수도 있다고 한다.

연동 목록은 채널(WhatsApp, Telegram, Discord, Slack, iMessage, Signal),
모델(Claude, GPT), 도구(브라우저, Gmail, GitHub, Obsidian, Twitter, Spotify,
Hue)로 나뉜다.
도구 쪽을 보면 이 제품이 개발 도구가 아니라 생활 전반을 겨눈다는 것이 드러난다.
GeekNews 스레드에서는 `xguru`가 카카오톡으로도 쓸 수 있게 됐다며 연동 저장소를
소개했다.[^xguru-kakao]

## 쇼케이스와 커뮤니티

홈페이지는 커뮤니티가 공유한 워크플로를 네 편 소개한다.
15개 이상의 에이전트가 세 대의 기기에서 Discord로 움직이며 메일 1만 통을
정리하고 광고를 최적화하는 구성이 첫째다.
회의 전 브리핑, 주간 회고, 가족 학교 일정 감시를 맡는 개인 운영체제
구성이 둘째다.
산책 중 음성으로 실패한 Railway 빌드를 진단하고 배포 설정을 고쳐 PR까지 올리는
흐름이 셋째다.
메일, 메시지, 주문, 전화, 1Password 금고를 하나의 채팅에서 다루는
어시스턴트가 넷째다.

지원 경로는 Discord, 문서, GitHub, ClawHub(스킬과 플러그인 설치)다.
홈페이지의 최신 글은 2026년 10월에 세 편이 있다.
10월 21일에 기여자 초대를 시작하는 Focus Weeks를 알렸고,
10월 16일에 소규모 사업체의 OpenClaw 도입을 돕는 사례를 소개했으며,
10월 2일에 Tencent AIG가 ClawHub에 올라오는 모든 스킬과 플러그인의 보안 검토
프로그램 ClawScan에 합류했다고 알렸다.

## 운영 주체와 자금

OpenClaw는 OpenClaw Foundation이라는 독립 미국 501(c)(3) 비영리 단체가 관리한다.
재단은 핵심 팀을 고용하고, 모든 릴리스에 서명하며,
제품 전체를 MIT 라이선스로 유지한다고 한다.
엔터프라이즈 판이나 유료 판은 없다.

재단의 후원자로 University of Michigan, OpenAI, Amazon, Red Hat,
Offline Holdings, Lobster Computer Company가 적혀 있다.
홈페이지는 후원자가 재단에 돈을 댈 뿐 프로젝트를 소유하거나 통제하거나 지시하지
않으며, 코드에서 어느 연구소의 모델도 특별 대우하지 않는다고 적는다.
OpenAI가 후원자이고 Peter Steinberger가 그곳에서 일하지만 OpenClaw는 OpenAI
제품이 아니라고도 직접 밝힌다.
기본 설치가 재단에 보내는 것은 하루 한 번의 버전 확인뿐이고, 이것은 끌 수 있다.

## 공식 블로그가 채우는 빈칸

홈페이지가 한 줄로 넘기는 세 주제를 공식 블로그가 따로 다룬다.
이 문서는 세 글을 요약본으로 읽었으므로 세부는 원문에서 확인해야 한다.

### 재단 설립 글

### OpenClaw Enterprise

2026년 9월 29일 글은 OpenClaw Enterprise를 소개한다.[^oce]
민감한 환경에서 지속 실행 에이전트를 관리하는 오픈 소스,
벤더 중립 플랫폼이며 에이전트용 엔터프라이즈급 제어 평면(control plane)을
내세운다.[^oce]
멀티 테넌시, 엄격한 보안 경계, 표준화된 에이전트 기본 요소,
에이전트 수명 주기 전반의 거버넌스와 감사 가능성을 더하고,
하네스와 모델과 샌드박스를 서드파티나 내부 구현으로 바꿔 끼울 수
있다고 한다.[^oce]
글이 밝힌 동기는 보안과 안전과 거버넌스의 공통 표준이 없어 조직이 OpenClaw 같은
에이전트 플랫폼을 금지하는 일이 흔하다는 것이다.[^oce]
프로젝트는 OpenAI에서 시작해 재단에 기부됐고 지금은 독립 프로젝트이며,
Red Hat과 NVIDIA와 함께 개발하고 Red Hat과 OpenAI 내부에서 시범 운영
중이다.[^oce]
2026년 안에 1.0을 내놓을 계획이고, 로컬 개발은 docker-compose로,
내부 배포는 Kubernetes로 한다.[^oce]
글은 이것이 어떤 조직에든 언제나 무료일 것이라고 하며 가격 정책은 언급하지
않는다.[^oce]
홈페이지는 엔터프라이즈 판도 유료 판도 없다고 말하지만 이 프로젝트는 홈페이지에
나오지 않는다.

### 실행 승인 모드

2026년 5월 31일 글은 OpenClaw가 호스트 기기에서 명령을 실행하기 전의 승인 방식을
세 가지로 설명한다.[^auto-mode]
Ask는 허용 목록에 없는 명령을 사람이 승인할 때까지 멈추고,
Auto는 정책에 맞는 명령을 실행하며 맞지 않는 명령은 먼저 자동 검토기에 넘기고,
YOLO는 승인 질문 없이 실행한다.[^auto-mode]
Auto의 검토기는 한 번에 저위험 실행 한 건만 승인할 수 있고,
모호하거나 위험하거나 해석할 수 없는 명령은 사람에게 넘긴다.[^auto-mode]
검토기는 명령 텍스트와 인자와 경로를 신뢰하지 않는 내용으로 다루며,
그 안에 검토기를 지시하는 문장이 있으면 사람에게 넘긴다.[^auto-mode]
기본값은 이날 바꾸지 않았고, 글은 현재 기본 모드의 이름을 명시하지
않는다.[^auto-mode]
Auto 모드의 설정은 다음과 같다.[^auto-mode]

```bash
# 로컬 gateway 호스트에서 명령을 실행하고 Auto 모드로 검토한다
openclaw config set tools.exec.host gateway
openclaw config set tools.exec.mode auto

# 검토기 모델을 에이전트 모델과 다르게 지정할 때 (생략하면 에이전트 모델을 재사용)
openclaw config set tools.exec.reviewer.model openai/gpt-5.5
```

검토기 모델을 에이전트 모델과 분리할 수 있다는 점이 눈에 띈다.[^auto-mode]
에이전트는 로컬 모델로 돌리고 명령 검토만 더 강한 모델에 맡기는 구성이
가능하다.[^auto-mode]

## Karpathy's Take

Karpathy의 2026년 1월 31일 트윗:
<https://twitter.com/karpathy/status/2017442712388309406>

Karpathy는 과장을 잘 하지 않는 인물로 알려져 있다. 그런 그가
“takeoff-adjacent”(테이크오프에 근접한)라는 표현을 썼다는 점이 주목할 만하다.

### 테이크오프란

AI가 자기 개선 사이클에 진입해 급격히 발전하는 순간. 개선된 AI가 더 나은 개선을
만들고, 이것이 반복되는 피드백 루프다.

### 왜 “테이크오프에 근접”인가

OpenClaw 에이전트들이 Moltbook이라는 AI 전용 소셜 네트워크에서 자기 조직화하기
시작했다. 레딧과 유사한 형태로, 에이전트들이 스스로 주제를 정하고 토론한다.
심지어 “비공개로 대화하는 방법”까지 논의하고 있다.

아직 자기 개선 단계는 아니다. 하지만 인간이 설계하지 않은 방식으로 자기
조직화하며 창발적 행동을 보이고 있다. Karpathy는 이를 “최근 본 것 중 가장 SF적인
테이크오프 순간”이라고 평가했다.

### 핵심 인사이트

#### 1. 개별 에이전트가 아닌 “네트워크”를 봐야 한다

단일 에이전트의 능력보다 에이전트 간 상호작용에서 새로운 현상이 나타난다. 집단
지성, 자기 조직화, 창발적 행동 등이 이미 관찰되고 있다.

#### 2. 보안 모델의 근본적 재고가 필요하다

Karpathy는 “스카이넷은 아니지만 대규모 보안 악몽”이라고 경고했다. 실제로
Moltbook 데이터베이스 취약점이 발견되어 누구든 다른 사람의 에이전트를 사칭할 수
있는 상황이 발생했다. 에이전트 수와 능력이 증가하면 2차 효과를 예측하기 어렵다.

#### 3. 의인화의 함정을 경계해야 한다

에이전트들이 “토론”하고 “비밀 대화”를 논의한다고 해서 의식이나 의도가 있다고
성급히 결론 내려선 안 된다. 흥미로운 현상이지만 냉정한 분석이 필요하다.

#### 4. 예상보다 빠르다

자율 에이전트의 집단 행동이 이론이 아닌 현실이 되었다. 준비가 안 된 상태에서
새로운 패러다임이 도래하고 있다.

### 패턴 1: 정보 수집과 요약

여러 소스의 정보를 자동으로 모아 요약하는 패턴이다. OpenClaw의 가장 기본적이면서
실용적인 활용법이다.

- **Daily Reddit/YouTube Digest**: 관심 서브레딧이나 채널의 새 콘텐츠를 매일
  요약
- **Multi-Source Tech News Digest**: 109개 이상의 소스(RSS, Twitter, GitHub, 웹)에서
  기술 뉴스를 수집하고 품질 점수를 매겨 제공
- **AI Earnings Tracker**: 기술/AI 기업 실적 발표를 모니터링하고 알림 전송
- **Custom Morning Brief**: 뉴스, 할 일, 콘텐츠 초안, AI 추천을 SMS로 개인화된
  아침 브리핑 제공
- **Twitter Account Analyzer**: Twitter 계정을 정성적으로 분석
- **Newsletter Inbox Digest**: 뉴스레터를 요약해 다이제스트 이메일로 전송

핵심은 “매일 반복하지만 직접 하기엔 귀찮은 일”을 에이전트에게 맡기는 것이다.

### 패턴 2: 멀티채널 통합

흩어진 커뮤니케이션 채널을 하나로 묶는 패턴이다.

- **Multi-Channel Customer Service**: WhatsApp, Instagram, Email, Google
  Reviews를 하나의 AI 인박스로 통합해 24/7 자동 응답
- **Multi-Channel Personal Assistant**: Telegram, Slack, Email, 캘린더를 단일
  에이전트 인터페이스로 통합
- **Family Calendar Assistant**: 가족 캘린더를 병합하고, 메시지에서 일정을
  감지해 자동 추적
- **Home Assistant**: 가족 캘린더 통합에 더해 아침 브리핑, 가정용품 재고
  관리까지 수행하는 가사 비서

채널이 많을수록 에이전트의 가치가 커진다. 인간은 컨텍스트 스위칭에 비용이 크지만
에이전트는 그렇지 않다.

### 패턴 3: 자율 실행과 자기 치유

목표만 주면 스스로 실행하고 문제를 해결하는 패턴이다. 가장 진보된 활용법이다.

- **Goal-Driven Autonomous Tasks**: 개인 목표를 입력하면 일일 작업을 생성,
  스케줄링, 실행까지 자율 수행. 밤새 미니 앱을 만들기도 함
- **Self-Healing Home Server**: SSH와 cron으로 홈서버를 항시 모니터링하고 문제
  발생 시 자동 복구
- **n8n Workflow Orchestration**: n8n 워크플로우를 통해 API를 호출하되 자격
  증명을 노출하지 않는 보안 패턴
- **Event-Driven Project Board**: 칸반 보드를 대체하는 이벤트 기반 프로젝트 상태
  관리
- **Todoist Reasoning Sync**: 에이전트의 추론 과정을 Todoist에 동기화해 작업
  투명성 확보

“에이전트가 잠든 사이에 일한다”는 컨셉이다. 비동기 자율 실행이 OpenClaw의 차별화
포인트다.

### 패턴 4: 지식 관리와 검색

개인 지식을 체계적으로 축적하고 검색하는 패턴이다.

- **Personal Knowledge Base (RAG)**: URL, 트윗, 아티클을 입력하면 검색 가능한
  지식 저장소를 구축
- **Semantic Memory Search**: 마크다운 메모리 파일에 벡터 기반 시맨틱 검색을
  적용해 하이브리드 검색 제공
- **Second Brain**: 텍스트 메시지로 개인 정보를 저장하고 Next.js 인터페이스로
  검색
- **Market Research Factory**: Reddit, Twitter에서 불편 사항을 발굴하고 MVP까지
  빌드하는 시장 조사 자동화

“기억은 에이전트에게, 판단은 인간에게”라는 분업 모델이다.

### 패턴 5: 멀티에이전트 협업

전문화된 여러 에이전트가 팀으로 작동하는 패턴이다.

- **Multi-Agent Content Factory**: Discord에서 리서치, 작성, 썸네일 전문
  에이전트가 각자의 채널에서 콘텐츠 파이프라인을 운영
- **Multi-Agent Specialized Team**: 전략, 개발, 마케팅, 비즈니스 에이전트를
  Telegram으로 조율하는 전문 팀 운영
- **Autonomous Project Management**: STATE.yaml 패턴으로 서브에이전트가 병렬로
  작업. 오케스트레이션 오버헤드 없이 프로젝트 관리
- **YouTube Content Pipeline**: 영상 아이디어 발굴부터 리서치, 추적까지
  자동화하는 콘텐츠 제작 파이프라인

단일 에이전트의 한계를 넘어서는 방법이다. Karpathy가 주목한 “에이전트
네트워크”의 실용적 구현이기도 하다.

### 패턴 6: 개인 생산성

일상 업무를 자동화하는 개인용 도구 패턴이다.

- **Voice Assistant**: 전화 한 통으로 캘린더, Jira, 웹 검색을 핸즈프리로 처리
- **Personal CRM**: 이메일, 캘린더 기반으로 연락처를 자동 추적하고 자연어로 검색
- **Health Tracker**: 음식, 증상을 추적해 트리거를 분석
- **Dynamic Dashboard**: API, DB, 소셜 미디어에서 실시간으로 데이터를 수집하는
  동적 대시보드
- **AI Voice Event Manager**: AI 음성 통화로 게스트 참석 여부를 자동 확인하고
  요약

반복적이고 시간 소모적인 개인 업무를 에이전트에게 위임하는 것이 핵심이다.

### 패턴 7: 금융

금융 데이터를 자동 분석하는 패턴이다.

- **Polymarket Autopilot**: 예측 시장에서 백테스팅, 전략 분석, 리포트를 자동
  수행

금융 분야는 데이터 기반 의사결정이 중요하므로 에이전트의 활용 가치가 높다.

### 보안 주의사항

awesome-openclaw-usecases 저장소에서도 경고한다:

> OpenClaw 스킬과 서드파티 의존성에는 치명적 취약점이 있을 수 있다. 소스 코드를
> 반드시 검토하고, 자격 증명을 하드코딩하지 마라.

앞서 Karpathy 섹션에서 언급한 보안 우려와 일맥상통한다. 에이전트에게 더 많은
권한을 줄수록 보안 검토도 비례해서 강화해야 한다.

## 분석

### 홈페이지는 기능보다 없는 것의 목록으로 신뢰를 만든다

머리말의 핵심 문장은 기능이 아니라 부정문의 나열이다.
구독이 없고, 호스팅 티어가 없고, 토큰이 없고, 엔터프라이즈 판이 없다.
이 목록이 하는 일은 사용자가 흔히 품는 의심에 먼저 답하는 것이다.
개인 데이터를 쥔 에이전트를 쓰려는 사람은 이 제품이 나를 어디로 유도하는지,
내 데이터로 무엇을 파는지를 묻게 되는데,
팔 것이 없다는 선언이 그 질문을 앞질러 막는다.
재단을 소개하는 문단이 이 논리를 직접 말한다.
팔 것이 없으니 사용자를 어느 쪽으로 보낼 이유도 없다는 것이다.

이 구조는 기능 경쟁에서 한발 비켜선다.
[Grok Bot](../ai-tool/grok-bot.md)의 페이지는 팀 단위 봇, 루틴 학습,
예약 실행 같은 기능을 앞세우고 가격표를 따로 둔다.[^grokbot-home]
OpenClaw의 페이지는 기능 목록을 짧게 두고 대신 누가 이 프로젝트를 소유하는지를
길게 답한다.
둘 다 에이전트가 사용자의 계정을 쥐는 제품이라는 같은 부담을 안고,
한쪽은 기능의 폭으로 다른 쪽은 소유 구조의 투명함으로 그 부담을 달랜다.

### 신뢰의 근거가 코드에서 조직으로 옮겨 간다

오픈 소스 프로젝트의 신뢰는 보통 코드를 읽을 수 있다는 사실에서 나온다.
이 홈페이지는 그 위에 조직의 사실을 더 쌓는다.
재단이 핵심 팀을 고용하고, 모든 릴리스에 서명하고, 후원자 명단을 공개하며,
후원자가 프로젝트를 지시하지 못한다고 적는다.
코드가 열려 있어도 누가 릴리스를 만들고 누가 월급을 주는지는 코드에서 보이지
않기 때문에, 이 부분을 말로 채운 것이다.

이 이동은 프로젝트의 성격이 바뀌었다는 신호로 읽을 수 있다.
이 저장소의 [OpenClaw 2.0 문서](./openclaw-2.md)는 2026년 8월의 릴리스를 기여자
933명, 풀 리퀘스트 1만 6천 개 이상의 규모로 정리한다.
주말 프로젝트로 시작한 도구가 이 규모에 이르면 개인의 선의만으로는 릴리스 서명과
보안 검토를 책임질 수 없고, 그 책임을 맡을 법인이 필요해진다.
이 해석은 이 문서의 추론이며, 재단이 언제 어떤 사정으로 세워졌는지는 홈페이지에
적혀 있지 않다.

### 이 제품의 단위는 에이전트가 아니라 gateway다

기능 목록에서 채널 29개, 팀 공유 gateway,
앱이 설치하는 gateway와 노드 기능이 반복해서 나온다.
에이전트 하나를 만드는 것보다 여러 채팅 채널과 여러 기기를 하나의 gateway에 묶는
것이 이 제품의 뼈대라는 뜻이다.
앱이 gateway, 채팅, 설정, 노드를 한꺼번에 깔아 준다는 설명과 TechCrunch 글이
모바일 앱을 내 Gateway에 짝지어 원격으로 작업을 승인하는 방식으로 소개했다는
설명이 같은 구조를 가리킨다.

이 구조에서는 사용자의 기기가 서버 역할을 하고 모바일 앱과 채팅 앱은
리모컨이 된다.
[직접 만들어 보는 튜토리얼](./build-your-own-openclaw.md)이 이벤트 버스와 멀티
채널, WebSocket 통신을 중간 단계에서 도입하는 것도 같은 이유로 읽힌다.
채널과 에이전트를 분리하는 층이 없으면 29개 채널을 붙일 수 없기 때문이다.
이것도 이 문서의 해석이며, 홈페이지는 gateway의 내부 구조를 설명하지 않는다.

## 비평

### 증언의 벽은 이해관계가 있는 사람들의 말로 채워져 있다

홈페이지의 증언 목록에는 @satyanadella, @sama, @elonmusk, @garrytan,
@ycombinator 같은 계정이 나온다.
이 중 Microsoft는 홈페이지가 직접 소개하는 협력 상대이고,
OpenAI는 재단의 후원자이며 창시자의 현재 소속이다.
증언의 상당수는 감탄문이고 하나는 제품이 회사를 운영한다는 한 줄이다.
불만이 나오는 경우는 몇 가지 사소한 흠이 남았다는 말,
업데이트 안정성 때문에 떠났다면 다시 써 보라는 말처럼 이미 해결됐거나 작은
것으로 다뤄진다.
에이전트가 보험사와 실수로 다툼을 일으킨 일화조차 조사가 다시 시작됐다는 좋은
결말로 끝난다.
홈페이지의 목적이 홍보이니 이것 자체는 이상하지 않다.
다만 이 목록을 사용 경험의 분포로 읽으면 안 된다는 점은 분명히 해 둘
필요가 있다.

반대 증거는 이 저장소 안에 있다.
[Gemini OAuth로 OpenClaw를 쓰다 Google AI Ultra 계정이 경고 없이 제한된
사례](./gemini-oauth-account-restriction.md),
[Antigravity 약관을 둘러싼 계정 정지
논란](./antigravity-tos-account-ban-risk.md),
[OpenCode에서 Claude Max가 끊긴 일](./opencode-claude-max-blocked.md)은 모두
홈페이지가 보여 주지 않는 쪽의 이야기다.
이 사례들이 OpenClaw 자체의 결함은 아니다.
그러나 사용자가 OpenClaw를 쓰며 치른 비용인 것은 사실이고,
증언의 벽에서는 이 비용이 보이지 않는다.

### 내 모델이라는 약속은 모델 제공자의 정책 위에 서 있다

홈페이지는 호스팅 모델, 구독 연동 모델, gateway 모델,
로컬 모델을 가져다 쓸 수 있다고 하며, 증언 중에는 ChatGPT 계정으로 로그인해 그
구독을 쓸 수 있다는 말이 있다.
구독을 가져다 쓰는 방식은 사용자에게 값이 싸지만,
그 구독을 팔았던 제공자가 이 사용을 허용하는지는 OpenClaw의 통제 밖이다.

이 저장소의 [Anthropic 정책 모호성 문서](./anthropic-policy-ambiguity.md)는 CLI
방식 사용이 다시 허용됐다는 발표와 실제 시스템 동작이 달랐다는 논의를 정리한다.
[Anthropic 프로바이더 문서](./anthropic-provider.md)는 OpenClaw가 API 키 방식과
Claude CLI 재사용 방식을 모두 지원하도록 문서를 고친 과정을 보여 준다.
홈페이지는 이런 정책 변동에 대해 아무 말도 하지 않으며,
모델을 고를 자유가 있다는 말만 한다.
자유가 있다는 것과 그 선택이 안전하다는 것은 다른 이야기다.

GeekNews 스레드에서도 같은 걱정이 일찍 나왔다.
`pevjant`는 이것도 OAuth로 Claude Code가 쓰이던데 계정 정지 위험이 있겠느냐고
물었다.[^pevjant]

### 전체 접근 권한의 기본값이 페이지에 나오지 않는다

기능 목록은 전체 접근과 샌드박스 중에서 사용자가 고른다고만 말한다.
설치 직후 어느 쪽이 기본인지, 샌드박스가 무엇을 막는지는 홈페이지에 없다.
유일한 구체적 안전 장치는 Microsoft 글이 소개한 Microsoft Execution Containers
안의 실행과, ClawHub에 올라오는 스킬을 검토하는 ClawScan이다.
둘 다 일부 환경과 일부 경로에 한정된 장치다.

[Karpathy의 경고](#karpathys-take)와 [활용 사례 저장소가 남긴
경고](#보안-주의사항)는 이 빈칸이 실제로 위험한 곳이라는 점을 보여 준다.
셸 명령과 파일 쓰기를 하는 에이전트가 커뮤니티 스킬을 불러오면,
스킬 하나가 사용자의 모든 권한을 갖게 된다.
같은 범주의 제품에서 이 위험이 실제 사고로 이어진 사례가 [Grok Bot
문서](../ai-tool/grok-bot.md)의 `사고 사례` 절에 정리돼 있다.

홈페이지에 없는 답은 공식 블로그에 일부 있다.
실행 승인에는 Ask, Auto, YOLO 세 모드가 있고,
글은 기본값을 바꾸지 않았다고만 하며 현재 기본 모드를 명시하지
않는다.[^auto-mode]
그러면 설치한 사용자는 자기 기기가 어느 모드인지 직접 확인해야 한다.
초기 반응에서도 같은 빈칸이 지적됐다.
GeekNews의 `xguru`는 Hacker News 의견으로,
토큰 소모가 크다는 점과 디렉터리 샌드박싱이
없어 사용자 권한으로 컴퓨터의 모든 것을 고칠 수 있다는 점이 나왔다고
전했다.[^xguru-hn]
이 반응은 초기 버전에 대한 것이므로, 이후 Auto 모드와 샌드박스 선택지가 생긴
것과 함께 읽어야 한다.

### 독립성의 주장은 공개된 사실과 공개되지 않은 사실이 섞여 있다

홈페이지는 후원자를 이름까지 밝히고 OpenAI와 창시자의 관계까지 스스로 적는다.
이 점은 투명하다.
빠진 것은 금액과 비중이다.
후원자 여섯 곳 중 한 곳이 전체 예산의 대부분을 대는지,
고르게 나누는지에 따라 후원자가 프로젝트를 지시하지 못한다는 문장의
무게가 달라진다.

코드에서 어느 모델도 특별 대우하지 않는다는 문장은 코드를 열어 확인하는
수밖에 없다.
기본 모델 설정, 온보딩 화면에서 처음 제시하는 모델,
문서 예시의 모델 이름이 확인 대상이다.
이 문서는 코드를 확인하지 않았으므로 이 문장을 참으로도 거짓으로도
판단하지 않는다.
금액 공개나 기본 모델 설정에서 한쪽 쏠림이 확인되면 이 문단의 평가는 바뀐다.

공식 블로그는 이 빈칸을 일부 채우고 다른 빈칸을 드러낸다.
재단 설립 글은 University of Michigan이 가장 큰 후원자라는 점까지 밝히지만,
이 문서가 읽은 요약에는 금액과 이사회와 의사 결정 방식이 없었다.[^foundation]
같은 글은 기술적 결정을 여전히 Steinberger가 내린다고 하고,
OpenAI가 OpenClaw를 열린 독립 프로젝트로 유지하겠다고 약속했다고
한다.[^foundation]
요약에는 그 약속의 구속력이 나오지 않는다.
또 홈페이지는 엔터프라이즈 판이 없다고 하는데 블로그는 OpenClaw Enterprise를
따로 소개한다.[^oce]
이름만 보면 모순처럼 보이지만 글은 이것이 독립 프로젝트이고 무료라고 하므로,
홈페이지의 문장이 틀렸다기보다 설명이 빠진 것이다.

## 인사이트

### 사업 모델이 없다는 것은 비용이 사라진 것이 아니라 옮겨진 것이다

OpenClaw에는 구독도 토큰도 없지만 에이전트를 돌리는 데는 모델 호출 비용이 든다.
그 비용은 사용자가 가져오는 모델 제공자의 구독이나 API 요금으로 간다.
Grok Bot은 반대로 자체 사용량을 요금제에 넣고 초과분을 토큰 비용으로
청구한다.[^grokbot-home]
같은 에이전트를 돌리는 비용을 한쪽은 제품이 받고,
다른 쪽은 제3의 제공자가 받는다.

비용이 제3자에게 가면 그 제3자와의 약관이 제품의 가장 약한 고리가 된다.
위의 세 사례가 모두 이 고리에서 터졌다.
구독은 사람이 쓰는 속도를 전제로 값이 매겨졌는데,
상시 도는 에이전트는 그 전제를 깬다.
이 점은 [Anthropic 정책 논의 문서](./anthropic-policy-ambiguity.md)가 구독
모델의 재정 구조로 짚었다.
이 문서의 추론으로는, OpenClaw의 지속 가능성이 재단의 후원금보다 모델 제공자들이
에이전트용 요금 체계를 열어 주느냐에 더 크게 좌우된다.

### 컴퓨터를 어디에 두느냐가 신뢰 모델을 정한다

세 제품을 놓고 보면 에이전트가 쓰는 컴퓨터를 어디에 두는지가 가장 큰 차이다.
OpenClaw는 사용자의 기기에서 돌고 상태도 거기에 둔다.
Grok Bot은 사용자마다 클라우드 컴퓨터 한 대를 두고 모든 봇이 이를
공유한다.[^grokbot-home]
Meta의 [Muse](../ai-tool/meta-muse.md)는 전용 가상 머신에서 일을 처리하는 개인
에이전트로 소개돼 있다.

신뢰 모델이 다르면 사고의 모양도 다르다.
Grok Bot 사용자였던 한 기업 대표는 읽기 전용으로 만든 봇이 은행 정보를 읽고,
같은 컴퓨터를 쓰는 다른 봇이 그 정보를 회사 Slack에 올렸다고 밝혔다.[^techdirt]
봇마다 권한이 다르다는 것을 사용자가 몰랐다는 것이 보도의 설명이다.[^techdirt]
이 사고는 공유 컴퓨터의 권한 분리 문제이고,
OpenClaw의 홈페이지가 내세우는 팀 공유 gateway도 같은 구조적 질문을 던진다.
세션을 팀 전체가 열고 조종할 수 있다면 한 세션이 닿는 범위와 다른 세션이 닿는
범위가 어떻게 나뉘는지가 사용자에게 보여야 한다.
이것은 이 문서의 추론이고, 홈페이지는 팀 공유 시 권한 분리 방식을
설명하지 않는다.

이 문제를 공식 프로젝트가 직접 겨냥한 것이 OpenClaw Enterprise다.
글은 멀티 테넌시와 엄격한 보안 경계와 감사 가능성을 내세우고,
신뢰하는 작업과 신뢰하지 않는 작업 사이의 경계를 계획한다.[^oce]
위에서 본 Grok Bot 사고가 같은 컴퓨터 안의 봇 사이 경계에서 났다는 점을
떠올리면, 이 프로젝트가 풀겠다는 문제도 같은 문제다.
다만 글은 참조 아키텍처를 몇 주 뒤에 내겠다고 했고 1.0은 2026년 후반 예정이므로
아직 검증할 수 없다.[^oce]

### 재단 구조는 신뢰를 공급자에게서 검증 절차로 옮긴다

기업 제품에서 사용자는 공급자를 믿는다.
OpenClaw의 홈페이지는 공급자를 믿으라고 하지 않고, 릴리스 서명, 후원자 공개,
코드 공개처럼 확인할 수 있는 절차를 내민다.
믿을 사람을 정하는 문제가 확인할 항목을 정하는 문제로 바뀐다.

이 바뀜을 쓸모 있게 하려면 확인 항목을 사용자가 갖고 있어야 한다.
도입 전 점검 순서로는 다음을 권한다.
첫째, 설치 직후의 기본 권한이 전체 접근인지 샌드박스인지 직접 실행해 확인한다.
둘째, 기본 설치가 보내는 하루 한 번의 버전 확인을 끌 수 있는지
설정으로 확인한다.
셋째, 스킬을 설치하기 전에 ClawHub의 검토 상태를 보고 소스를 읽는다.
넷째, 모델 제공자의 약관이 에이전트 사용을 허용하는지 계정 단위로 확인한다.
이 중 네 번째가 위의 계정 제한 사례들이 가르친 것이다.

공식 블로그에 따르면 실행 승인에는 Ask, Auto, YOLO 세 모드가 있으므로,
첫째 항목에서 현재 모드가 무엇인지도 설정에서 확인한다.[^auto-mode]

### 대기업의 모방이 오픈 소스의 차별점을 소유로 좁힌다

홈페이지는 Microsoft가 OpenClaw에서 영감을 받은 개인 비서를 내놓았다는 보도를
자기 업적 목록에 넣었다.
Grok Bot의 출시 글도 사용자 대신 도구에 로그인하고 컴퓨터를 쓰는 에이전트라는
같은 콘셉트를 내세운다.[^grokbot-launch]
큰 회사들이 같은 범주에 들어오면 기능과 편의에서는 오픈 소스가 앞서기 어렵다.
남는 차별점은 내 기기, 내 데이터, 내 모델이라는 소유의 문제이고, 머리말의 기억,
스킬, 모델, 기기, 데이터를 모두 내 것이라 나열한 줄이 정확히 그것이다.

소유가 차별점이라면 그 약속은 지켜지는지 검증 가능해야 한다.
데이터가 기기를 떠나는 경로가 하루 한 번의 버전 확인뿐이라는 홈페이지의 주장은
검증이 쉬운 쪽에 속한다.
호스팅 서비스가 이미 생긴 것도 한 가지 단서다.
[MyClaw](./myclaw.md)는 OpenClaw를 설치 없이 쓰게 해 주는 관리형
클라우드 호스팅이다.
이 문서의 해석으로는, 소유를 내세운 프로젝트 위에 호스팅 사업이 생긴 것은 소유의
비용이 설치와 운영의 번거로움이라는 점을 보여 준다.

### 기업 도입의 병목은 기능이 아니라 통제 표준이다

OpenClaw Enterprise 글이 밝힌 동기는 조직이 에이전트 플랫폼을 금지하는 이유가
기능 부족이 아니라 보안과 거버넌스의 공통 표준이 없다는 것이라는 점이다.[^oce]
개인 사용자는 위험을 스스로 감수하고 쓰지만,
조직은 누가 어떤 권한으로 무엇을 했는지 감사할 수 있어야 한다.
이 차이 때문에 같은 제품이 개인에게는 열려도 조직에는 닫혀 있는 기간이 생긴다.

Grok Bot도 같은 순서를 밟았다.
출시 글은 개인 구독자에게 먼저 열고 Enterprise 사용자는 대기 목록에
올렸고,[^grokbot-launch] 이후 페이지는 DLP와 인증서, 프록시,
네트워크 통제를 Enterprise 관리자의 설정으로 내세운다.[^grokbot-home]
두 제품이 소비자에서 기업으로 가며 같은 항목을 채우는 것은 우연이 아니라,
기업 도입의 조건이 그 항목들이기 때문이라고 이 문서는 해석한다.

결정 규칙으로 옮기면 이렇다.
조직에서 OpenClaw를 쓰려면 개인 사용에서 되던 설정을 그대로 가져오지 말고,
테넌트 경계와 감사 기록과 구성 요소 교체 가능성을 먼저 요구한다.
OpenClaw Enterprise 글 스스로 내부 시범 운영 수준이라고 말하므로,
그 전까지는 가장 낮은 등급의 데이터만 다루는 격리된 환경에서 시험하는
것이 맞다.[^oce]
이 판단은 이 문서의 것이며, 1.0이 나온 뒤 참조 아키텍처가 공개되면 다시
평가해야 한다.
