# All Claw: 상시 실행형 AI 에이전트 'Claw'를 계보와 근거로 분류한 디렉터리

<https://allclaw.org/>

## 소개

All Claw는 기억하고 계획하고 도구를 쓰며 한 번의 프롬프트를 넘어 계속 일하는
에이전트, 이른바 Claw를 모아 비교하는 디렉터리입니다.
운영자는 스스로를 독립 디렉터리라고 소개하고,
능력과 계보와 검증된 근거로 항목을 정리한다고 말합니다.
홈의 집계로는 전체 104개 항목 가운데 48개가 Claw로 분류되어 있습니다.
사이트는 에이전트 목록(Claws), 생태계 지도(Ecosystem), 비교(Compare),
가이드와 블로그, 제출(Submit) 메뉴로 나뉩니다.
이 문서는 사이트의 공개 페이지를 읽어 정리한 것이고,
개별 항목의 내용이 맞는지는 각 프로젝트의 원문에서 확인하지 않았습니다.

## Claw의 기준

사이트는 Claw를 상시 실행되고 기억과 상태를 유지하며 여러 단계의 행동을 스스로
고르고 도구와 연결된 환경을 쓰는 에이전트로 정의합니다.
포함 검사에서 보는 신호는 지속 실행, 자율 실행, 도구 사용, 기억 또는 상태,
예약 작업 또는 하트비트, 브라우저와 쉘과 컴퓨터 접근, 먼저 말을 거는 소통,
여러 단계 목표, 스킬과 플러그인과 MCP입니다.
모든 신호가 필요하지는 않지만 대부분을 충족해야 하고,
지속 실행과 자율 행동은 핵심이어야 합니다.
사이트는 Claw가 아닌 예로 한 번에 한 질문만 답하는 챗봇,
판단 루프가 없는 워크플로, AI 에이전트라는 이름만 붙인 제품,
지속성이 없는 코딩 보조 도구, 검색 노출용으로 넣은 비교 제품을 듭니다.
이 정의의 근거로 사이트는 NVIDIA가 프롬프트로 움직이는 에이전트와 상시 자율
에이전트를 구분한 설명과 2026년 Claw-SWE-Bench 논문의 용어 사용을 듭니다.
사이트도 이것이 업계 공통 정의의 증거는 아니고 용어가 한 제품의 이름보다 넓다는
근거일 뿐이라고 인정합니다.

## 분류 축

항목은 두 단계로 나뉩니다.
먼저 일곱 가지 생태계 계층 중 어디에 속하는지 정하고,
Claw 에이전트는 계보와 실행 방식 같은 속성으로 다시 나눕니다.

| 구분          | 내용                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------- |
| 생태계 계층   | Claw 에이전트, 프레임워크와 런타임, 호스팅과 클라우드, 스킬과 확장, 인프라, 보안, 연구와 벤치마크 |
| 계보(lineage) | 독립, OpenClaw 기반, OpenClaw에서 영감, OpenClaw 호환, 멀티 하니스, 벤더 제작, 연구, 알 수 없음   |
| 에이전트 종류 | 개인, 클라우드, 기업, 코딩, 연구, 기기, 멀티 에이전트, 특수 목적, 자동화                          |
| 실행 위치     | 로컬, 클라우드, 하이브리드, 기기                                                                  |
| 자율성        | 보조, 자율, 상시 실행                                                                             |
| 기타 필터     | 오픈소스 여부, 모델(Claude, GPT, Gemini, Kimi, MiMo, Nemotron, 로컬 모델), 인터페이스             |

계보 축에서 OpenClaw는 여러 계보 중 하나로 다뤄집니다.
사이트는 OpenClaw를 큰 가문이지만 범주의 경계는 아니라고 설명하고,
계보는 출신을 말할 뿐 Claw 자격을 정하지 않는다고 적습니다.

## 계층별 규모

홈의 계층별 항목 수는 다음과 같습니다.

| 계층                | 항목 수 | 사이트의 설명                                                                |
| ------------------- | ------- | ---------------------------------------------------------------------------- |
| Claw 에이전트       | 40      | 기억하고 계획하고 도구를 쓰며 프롬프트 너머로 일하는 자율 에이전트           |
| 프레임워크와 런타임 | 8       | Claw급 에이전트를 만들고 운영하는 하니스와 런타임                            |
| 호스팅과 클라우드   | 9       | Claw를 24시간 켜 두는 관리형 플랫폼과 클라우드                               |
| 스킬과 확장         | 15      | 스킬, 플러그인, MCP 서버, 커넥터                                             |
| 인프라              | 27      | 기억, 브라우저, 샌드박스, 오케스트레이션, 게이트웨이, 관측, 에이전트 간 통신 |
| 보안                | 1       | 샌드박싱, 권한 통제, 자격 증명 보호, 감사, 스캐너                            |
| 연구와 벤치마크     | 4       | 벤치마크, 평가, 데이터셋, 기술 연구                                          |

여섯 계층의 합은 104로 홈의 전체 항목 수와 같습니다.
생태계 지도 페이지는 Claw 에이전트를 OpenClaw 가문 20개, 독립 22개,
벤더와 멀티 하니스 6개로 나누어 합이 48이 됩니다.
홈의 Claw 에이전트 계층은 40개인데 48개가 Claw로 분류된 이유는,
호스팅과 스킬 계층에 놓인 항목 중에도 Claw 표시가 붙은 것이 있기 때문으로
읽힙니다.
이 해석은 이 문서의 추정입니다.

## 항목 페이지가 알려 주는 것

항목 페이지에는 검증 날짜, 생태계 계층, 계보, 실행 위치, 자율성, 제공자, 가격,
오픈소스 여부와 라이선스, 유지보수 상태, 설치 방법, 지원 플랫폼, 모델,
인터페이스가 정리되어 있습니다.
Claw 신호는 항목마다 어떤 것이 문서에서 확인됐는지가 표시됩니다.
보안 신호는 정보 제공용이고 보안 인증이 아니라고 페이지가 밝힙니다.
검증 출처는 보통 해당 프로젝트의 공식 문서나 저장소입니다.
예를 들어 [QwenPaw](qwenpaw.md)는 개인용 Claw로, 계보는 벤더 제작,
실행은 하이브리드, 자격 증명 필요 표시가 붙었고 검증일은 2026년 8월 14일입니다.
사이트는 이 프로젝트가 CoPaw라는 이전 이름에서 바뀌었다는 점도 적습니다.

## 비평

### 독립 디렉터리라는 소개와 호스팅 판매의 관계가 설명되지 않는다

사이트는 후원과 검증을 분리하고 비교 평가는 편집 의견이지 유료 순위가 아니며
후원 항목은 따로 표시한다고 말합니다.
그런데 환불 정책 페이지는 All Claw 인스턴스 접근권, API 토큰, 구독,
API 크레딧을 판매하는 호스팅 서비스를 전제로 쓰였습니다.
디렉터리가 호스팅 계층(9개 항목) 같은 경쟁 영역을 함께 분류하면서 자기 호스팅
상품도 파는 것이라면, 그 관계와 이해 충돌을 다루는 규칙이 사이트의 소개나 기준
페이지에는 보이지 않습니다.
환불 정책 문서만으로는 그 상품이 디렉터리 운영자의 것인지 단정할 수 없고,
이 문서가 확인한 범위는 거기까지입니다.

### 검증됨이라는 표시가 최신성까지 보장하지는 않는다

Verified는 공식 출처에서 분류 근거를 확인했다는 뜻이고 품질이나 안전의 보증이
아닙니다.
QwenPaw의 검증일은 8월 14일인데, 그 프로젝트의 README에는 그 이후 9월 3일,
9월 10일, 10월 15일 릴리스가 적혀 있습니다.
빠르게 바뀌는 프로젝트일수록 검증일 이후에 기능과 보안 구성이 달라졌을 수
있습니다.
항목 페이지의 유지보수 상태와 가격 같은 필드는 검증 시점의 값입니다.

### 범주의 경계가 운영자의 판단에 달려 있다

Claw라는 용어는 한 제품의 브랜드에서 번져 나왔고,
사이트도 업계 공통 정의가 없다고 인정합니다.
그래서 포함 여부는 신호를 대부분 충족하는지라는 편집 판단으로 정해지고,
어떤 신호가 몇 개 충족되어야 하는지의 수치 기준은 공개되어 있지 않습니다.
같은 이유로 48이라는 숫자는 생태계의 크기가 아니라 이 사이트의 분류 기준에 맞은
항목의 수로 읽어야 합니다.
SmallClaw처럼 이름에 Claw가 들어가도 문서가 부족해서 검증된 목록에서 빠진 항목이
있다는 설명은, 기준이 이름이 아니라 문서 근거에 있다는 것을 보여 줍니다.

### 보안이 중요하다면서 보안 계층의 항목이 하나뿐이다

생태계 지도는 보안을 한 계층으로 세우고 샌드박싱, 권한 통제, 자격 증명 보호,
감사, 스캐너를 그 범위로 적습니다.
항목 수는 104개 중 1개이고, 인프라 계층의 27개 안에 샌드박스가 함께 들어
있습니다.
분류 위치가 이렇게 나뉘면 보안 도구를 찾는 사용자는 두 계층을 모두
뒤져야 합니다.
보안 소식은 블로그가 다루는데, 2026년 3월에는 npm 패키지 axios가 탈취되어
OpenClaw 포크가 영향을 받은 사건을 설명하는 글이 올라왔습니다.
이 글의 내용은 이 문서가 사실 확인을 하지 않았습니다.

## 인사이트

### 1. 후보를 좁히는 용도로 쓴다

계보, 실행 위치, 자율성, 오픈소스 여부, 모델, 인터페이스로 거를 수 있어서,
어떤 Claw를 쓸지 고를 때 후보 목록을 만드는 출발점으로 알맞습니다.
호스팅을 고를 때는 [MyClaw](myclaw.md)처럼 OpenClaw를 관리형으로 돌려 주는
서비스가 호스팅 계층에 따로 모여 있는지 보는 용도로 쓸 수 있습니다.

### 2. 도입 전에는 원문으로 되돌아간다

검증일, 유지보수 상태, 가격은 모두 시점의 값이므로 최종 판단 전에 해당
프로젝트의 저장소와 최신 릴리스를 직접 확인합니다.
보안 신호가 인증이 아니라는 단서를 그대로 받아들여,
권한과 샌드박스 구성은 프로젝트의 문서와 설정에서 따로 확인합니다.

### 3. 이 사이트에 대한 판단을 바꿀 관찰

운영자가 호스팅 상품과 디렉터리의 관계, 후원 항목의 표시 방식,
분류에서 항목이 빠지거나 들어오는 기준의 수치를 공개하면 신뢰의 근거가
늘어납니다.
반대로 후원이나 자사 상품과 연결된 항목이 같은 조건의 다른 항목보다 높게
소개되는 사례가 확인되면 독립 디렉터리라는 소개는 약해집니다.
