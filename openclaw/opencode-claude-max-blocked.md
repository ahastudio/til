# Claude Max가 OpenCode에서 끊긴 밤

<https://github.com/anomalyco/opencode/issues/7410>

HN 토론: <https://news.ycombinator.com/item?id=46549823> (625점, 513개 댓글)

GN 토론: <https://news.hada.io/topic?id=25702>

## 경위

2026년 1월 9일 새벽 2시 20분(UTC), piotryordanov가 OpenCode 저장소에 이슈를 올렸다.
조금 전부터 Claude Max 사용이 멈췄고 오류가 뜨며 재연결해도 같다는 내용이다.
OpenCode 1.1.8, macOS.
이 이슈는 386개 댓글과 420개 반응을 모았고, 결국 `not_planned`로 닫혔다.

첫 2분 만에 같은 증상 보고가 쏟아졌다.
iloveicedgreentea는 한 시간 전까지 잘 되던 것이 안 된다고, Claude 상태 페이지는 정상이며 OAuth 플러그인을 쓴 GPT 5.2는 작동한다고 적었다.
Naomarik은 즉시 플랜을 100달러로 낮췄고, 몇 분 뒤 아예 구독을 취소했다고 수정했다 — Claude Code를 10분 써 봤는데 자기가 쓰던 워크플로와 OpenCode가 준 가시성에는 쓸 수 없더라는 것이다.

원인 규명은 커뮤니티가 빠르게 해냈다.
OpenCode 메인테이너 thdxr는 30분도 안 되어 아마 막힌 것 같고 지금 조사할 시간은 없지만 OpenCode를 특정해 막았을 가능성이 있다고 적었다.
jander99는 스코프가 바뀐 것을 발견했다 — 새로 띄운 OpenCode와 `claude`가 만드는 토큰이 다르고, `user:sessions:claude_code`라는 낯선 스코프가 있다는 것이다.
kandotrun이 이를 확인했다 — Claude Code를 재시작하니 `user:sessions:claude_code` 토큰이 생성됐고, 최신 Claude Code 실행 전에는 `user:inference`와 `user:profile`뿐이었다는 것이다.
popododo0720은 이 스코프가 Claude Code 세션을 다른 클라이언트와 분리하기 위해 추가된 것으로 보인다고 정리했다.

차단은 스코프만이 아니었다.
harshav167이 올린 PR 설명이 실제 집행 방식을 드러낸다 — Anthropic이 Claude Code OAuth 토큰에 대해 강제하는 요청 서명 불일치를 고치는 것으로, `/v1/messages`에 `?beta=true`를 붙이고(Claude Code는 그렇게 하는데 OpenCode는 안 했다), User-Agent를 `claude-cli/...`로 맞추고, OAuth에서 `fine-grained-tool-streaming`을 베타 목록에서 뺀다는 것이다.
HN의 outlier99는 더 단순한 진단을 내놨다 — 비-Claude Code 클라이언트를 막은 게 아니라 OpenCode가 쓰는 특정 도구 이름을 막았을 뿐이라는 것이다.
Sewer56도 표준 도구 이름의 소문자만 매칭하므로 도구 이름을 대문자로 시작하게 바꾸면 우회된다고 적었다.

우회는 그날 새벽에 완성됐다.
사고 발생 약 4시간 만에 `opencode-anthropic-auth`에 수정이 병합됐고, deveworld가 게시 전 임시 방편(저장소를 클론해 로컬 플러그인으로 지정하고 `OPENCODE_DISABLE_DEFAULT_PLUGINS=true`로 실행)을 공유했다.
이후 몇 주간 이슈는 성격이 바뀌어, 플러그인 버전 지정과 설정 팁을 주고받는 창구가 됐다.

뒤이어 다른 문제가 드러났다.
Cyb3rDudu는 통합 OAuth로도 작동하지만 OpenCode가 Claude Max 토큰을 훨씬 빨리 태워서 처음으로 대기 메시지를 봤다고 적었고, ilbarone87도 같은 것을 관찰했다.
cedws는 Claude Code가 효율을 위해 Haiku와 Opus를 자동으로 오가는 반면 OpenCode에는 그 자동 모드가 없어 보인다고 추정했다.
Christopher-R-Perkins가 구체적으로 확인해 주었다 — Claude Code의 Explore 에이전트는 Haiku를, statusline-setup은 Sonnet을, Claude Code Guide는 Haiku를 쓰고 나머지가 상속받는다는 것이다.
cantalupo555는 `opencode.json`에 `small_model`을 `anthropic/claude-haiku-4-5`로 지정하는 해법을 공유했다.
dearkafka는 이것이 완전히 예상된 동작이라고 정리했다 — 네이티브 Claude Code가 캐시된 토큰에 더 의존하기 때문에 부분적으로 “더 멍청”하고, 그것이 그들이 이따금 OpenCode를 쓰는 Max 계정을 차단하는 이유라는 것이다.

## 분석

### 차단의 실제 표면은 인증이 아니라 요청 지문이었다

이 사건이 기술적으로 흥미로운 이유는 차단이 여러 층에서 동시에 일어났기 때문이다.
새 OAuth 스코프 `user:sessions:claude_code`가 추가된 것이 한 층이고, User-Agent와 베타 플래그와 도구 이름으로 요청 지문을 판별한 것이 다른 층이다.

두 층의 성격이 완전히 다르다.
스코프는 인증 체계의 정식 변경이며 클라이언트가 흉내 낼 수 없다 — 토큰 발급 시점에 서버가 결정하기 때문이다.
반면 요청 지문은 전부 클라이언트가 보내는 값이므로 원리적으로 흉내 낼 수 있고, 실제로 4시간 만에 흉내 냈다.

kzhrv가 이 구조를 정확히 짚는다[^kzhrv].
불편하지만 언제나 해결 가능하다 — 클라이언트 쪽은 프로토콜 수준에서 상대 클라이언트가 하는 일을 1:1로 복제할 수 있기 때문이다.
Anthropic 모델과 OpenCode를 계속 붙이려고 패치한 Bun 저장소까지 유지해야 하는 지점에 이르면 의심스러워지겠지만, 그 전까지는 재현 가능하다는 것이다.
그리고 해결할 수 없는 것은 하나뿐이라고 덧붙인다 — 그들이 자기 클라이언트를 쓰지 않는다는 이유로 사람을 차단하기 시작하는 것.

이 지적은 몇 주 뒤 구글 Antigravity 사건에서 그대로 현실이 됐다.
지문 차단은 우회되고 계정 차단은 우회되지 않으며, 그래서 공급자는 결국 후자로 옮겨 간다.

### 구독 가격이 논쟁 전체를 결정한다

dfabulich가 배경을 가장 간명하게 정리한다[^dfabulich].
Anthropic의 월 200달러 Claude Code 구독은 종량제 API보다 훨씬 싸고, 한 달 Claude Code를 쓰면 API로는 1000달러가 넘었을 만큼의 토큰을 쓰기 쉽다는 것이다.
왜 구독자에게 그런 유리한 가격을 주는지는 모르겠지만, 그들은 그 구독으로 OpenCode CLI가 아니라 Claude Code CLI를 쓰기를 정말로 원하며, OpenCode 사용자에게는 5배 이상일 수 있는 API 가격을 내게 하고 싶다는 것이다.

marco-kretz는 이를 경제 논리로 정리한다[^marco-kretz].
명백히 생태계 락인을 향한 또 한 걸음이고, 구독은 API 대비 훨씬 높은 요청량을 주며 Max 5x 등급 100달러로 API였다면 수백 달러 값어치를 받는다는 것이다.
현재의 시장 우위와 열기를 지렛대 삼아 사용자를 묶는 것이고, 자기들의 강점을 서드파티와 나눌 유인이 없으며, 경제적으로는 완벽히 말이 되지만 사용자 관점에서는 최악이라고 적는다.

misternugget의 질문이 더 날카롭다[^misternugget].
Amp에서 일하는 엔지니어로서, 이렇게 오래 걸려서야 단속한 것이 매우 놀랍다는 것이다 — 처음부터 약관 위반이었고, 작년 3월에 Claude Code 구독의 높은 사용 한도를 다른 애플리케이션에서 쓸 수 있느냐고 물었을 때도 안 된다는 답을 받았다고 한다.
그렇다면 문제는 무엇이 바뀌었느냐이며, 새 투자 라운드나 회계연도 말이나 IPO 준비냐고 묻는다.
그리고 또 하나 놀라운 것은 대부분의 사람이 토큰의 실제 원가와 Anthropic이 Claude Code 헤비 유저에게 얼마나 손해를 보는지 모른다는 사실이라고 덧붙인다.

### 도구 품질이 이 사건의 숨은 변수다

이 이슈에서 반복해서 나오는 정서는 가격 불만이 아니라 도구 선호다.

dboon은 이것이 Anthropic에게 이례적인 실책이라고 본다[^dboon].
불편한 진실은 OpenCode의 엔지니어링이 Claude Code보다 훨씬 앞서 있다는 것이며, Claude Code가 훌륭한 도구인 것은 맞지만 그것은 CLI의 엔지니어링이 아니라 밑에 있는 모델의 마법 덕분이라는 것이다.
OpenCode 팀은 HTML/CSS의 상당 부분과 TypeScript 생태계를 지원하는 커스텀 TUI 백엔드를 만들었고(OpenCode에 묶이지 않은 범용 TUI 렌더러다), 제품을 클라이언트/서버로 설계해 에이전트 부분을 TUI와 따로 쓸 수 있게 했으며, TUI를 범용 클라이언트로 구현했기 때문에 웹 뷰까지 만들 수 있었다는 것이다.

Naomarik의 반응 — Claude Code를 쓰는 건 석기시대로 돌아가는 것 같다 — 도 같은 평가다.
ChaseRensberger는 Anthropic 구독을 취소하고 OpenCode Zen에 돈을 내기 시작했다며, OpenCode가 충분히 더 나은 제품이라 열 배 값을 내고서라도 쓰겠다고 적었다[^chase].
Draiken은 아예 반대 효과를 보고한다 — OpenCode를 몰랐는데 이제 써 보고 아마 쓰게 될 것 같다는 것이다[^draiken].

이 정서가 중요한 이유는 락인 전략의 전제를 무너뜨리기 때문이다.
락인은 자사 클라이언트가 충분히 좋을 때 작동하고, 그렇지 않으면 사용자를 묶는 게 아니라 밀어낸다.
JimmaDaRustla는 더 냉정하다 — Claude Code는 코딩 어시스턴트로서 평범하지도 않고 형편없으며 조금이라도 쓸 만한 것은 밑에 있는 모델 때문이고, 구독이 무엇을 위한 것이라 말하든 개발자에게 값어치 있는 것은 그 AI와 API뿐이라는 것이다[^jimma].

## 비평

### 이슈 스레드가 사건 기록으로는 훌륭하고 판단 자료로는 편향돼 있다

386개 댓글의 상당수가 “same”이라는 한 단어다.
그 자체가 정보다 — 사고 규모와 즉시성을 보여준다.
그러나 이 스레드에서 여론을 읽으면 판단이 왜곡된다.

여기 모인 사람들은 정의상 OpenCode 사용자이고, 자기 워크플로가 방금 끊긴 상태이며, 새벽 두 시다.
solssak의 “공황 발작이 올 것 같다”는 반응이 그 상태를 보여준다.
같은 사건에 대해 Claude Code만 쓰는 사용자 — 즉 Anthropic 사용자 다수 — 는 아무 일도 겪지 않았고 이 스레드에 오지 않았다.

이슈 작성자 본인이 스레드에서 가장 균형 잡힌 말을 남긴 것이 아이러니다.
piotryordanov는 기술적으로 이것은 Anthropic과 무관하며 Max 플랜을 Anthropic 도구 바깥에서 지금처럼 쓸 수 있게 되어 있었다고 보지 않는다고 적었다.
ariane-emory가 즉시 반박한다 — Claude Code 플랜을 비-Claude Code 도구에서 쓰는 것이 약관 위반이라는 사실이 Anthropic과 무관하다면 누구와 관련이 있느냐, 그 약관을 쓴 것도 그것을 집행하기로 한 것도 Anthropic이며 다른 누구도 그렇게 하지 않았다는 것이다.

이 짧은 교환이 이 사건 논쟁의 축소판이다.
“규칙이 그러니 어쩔 수 없다”와 “그 규칙을 만든 것이 그들이다”는 서로를 반박하지 않는다 — 하나는 정당성에 대한 진술이고 다른 하나는 책임에 대한 진술이기 때문이다.

### 집행 방식이 정책보다 더 큰 반발을 샀다

정책 자체를 옹호하는 목소리는 많다.
weird-eye-issue는 Claude Code 구독이 다른 소프트웨어에서 작동하면 안 되고 이것은 완전히 공정하다고 적는다[^weird-eye].
oldhead는 제목이 오해를 부른다고 지적한다 — 여전히 자기 Anthropic API 키로 OpenCode에서 Claude를 쓸 수 있고, 더 이상 못 하는 것은 문서화되지 않은 API를 리버스 엔지니어링해 Claude Code 클라이언트인 척하며 구독 계정의 OAuth 토큰을 쓰는 것이라는 것이다[^oldhead].
그러면서도 오픈소스 하네스의 경쟁 시장을 원하는 사람에게는 정말 나쁜 일이라고 덧붙인다 — BYOK 토큰은 Anthropic 공식 클라이언트가 아닌 것을 쓸 때 상당한 웃돈을 뜻하기 때문이다.

반발의 핵심은 정책이 아니라 시점과 통지였다.
minimaxir가 이를 짚는다 — 이런 자격증명 재사용이 늘 회색 지대인 것은 놀랍지 않지만, 뻔히 예상되는 소동을 두고 목요일 밤에 아무 경고 없이 배포한 것은 이상하다는 것이다[^minimaxir].

이 지적이 정당한 이유는 대안이 명백했기 때문이다.
스코프 변경을 예고하고, 유예 기간을 주고, 오류 메시지에 이유를 적는 것 — 셋 다 정책을 조금도 약화시키지 않으면서 사고를 예방한다.
실제로 사용자들이 처음 몇 시간 동안 한 일은 로그아웃과 재로그인, 토큰 폐기와 재발급 같은 무의미한 시도였고, 그 시간은 오류 메시지 한 줄이면 절약될 수 있었다.

### 구독 취소가 실제 대응이 됐다는 사실을 양쪽 다 과소평가한다

이 스레드와 HN에서 놀라운 것은 취소 보고의 밀도다.
Naomarik, planet_1649c, ewoodrich, ChaseRensberger, lemming이 모두 같은 날 취소를 보고했다.

lemming의 계산이 특히 구체적이다[^lemming].
이것이 늘 해킹이었고 약관 위반이었다는 점은 인정하지만, 자신은 Claude Code로 했을 바로 그 일을 자기가 더 좋아하는 다른 하네스에서 하려고 매달 Anthropic에 돈을 내 왔으며, 그들이 이 조치로 달성한 것은 자신이 더 이상 돈을 내지 않게 된 것뿐이라는 것이다.
그리고 토큰당 가격이 OpenAI 대비 정말 비싸고 OpenAI 모델 결과를 더 좋아한다고, 다만 매우 느릴 뿐이라고 덧붙인다.

이 이탈이 Anthropic에게 손실인지 이득인지는 계산에 달려 있다.
misternugget이 짚은 대로 헤비 유저는 구독가보다 훨씬 많은 비용을 발생시키므로, 이들이 떠나는 것은 단기 재무로는 개선이다.
그러나 sergiotapia는 z.ai 코딩 플랜으로 옮겨 GLM 4.7로 복잡한 변경을 했더니 정말 잘 되더라며 Anthropic을 갱신하지 않을 것 같고 오픈 모델이 변곡점에 도달했다고 적는다[^sergiotapia].
brainless도 GLM이나 Grok Code로 요즘 더 많은 일을 하고 있으며 크고 작은 모델을 섞어 쓰는 것이 답이라고 본다[^brainless].

떠난 사용자가 대안에서 만족하면 돌아오지 않고, 그 대안이 충분히 좋다는 발견을 공개적으로 공유한다.
비용이 많이 드는 사용자를 쳐내는 것과 가장 영향력 있는 사용자를 경쟁자에게 보내는 것은 같은 행동의 두 얼굴이다.

### 같은 회사가 반대 방향으로도 문을 열어 두었다

articunoJones가 스레드에서 짚은 사실이 이 정책의 일관성을 흔든다[^articuno].
OpenCode를 포크해서 Anthropic의 Agent SDK를 쓰면 되며, Agent SDK는 기존 Claude Code 인증에 얹힐 수 있다는 것이다.

즉 Anthropic은 구독 자격증명으로 프로그래밍 방식 접근을 하는 것 자체를 막은 것이 아니라, 자기들이 승인한 경로로만 하게 만든 것이다.
그렇다면 문제는 “구독은 대화형 사용을 위한 것”이라는 서사와 맞지 않는다 — SDK로 무한히 자동화할 수 있기 때문이다.
실제 기준은 사용 방식이 아니라 클라이언트의 정체성이며, 그 기준은 남용 방지보다 통제에 가깝다.

wahnfrieden은 경쟁사와의 대비를 든다[^wahnfrieden].
OpenAI는 ChatGPT 구독으로 브라우저 자동화를 통해 5.2 Pro에 프로그래밍적·에이전트적으로 접근하게 해 주는 프로젝트에 이름을 얹었고, Karpathy를 비롯한 리더들이 X에서 그 기능을 칭찬했다는 것이다.
그것이 그렇게 환영받는 일이라면 웹사이트를 스크립트로 다루어 Codex 요금 한도 같은 것을 우회하는 다른 방법들은 무엇이겠느냐고 반문한다.

이 대비가 시사하는 것은 정책의 정당성이 기술이 아니라 전략에서 나온다는 점이다.
같은 행위가 한 회사에서는 락인 위협이고 다른 회사에서는 생태계 확장이며, 그 차이는 누가 시장 선두이고 누가 추격자인지에서 온다.

## 인사이트

### 클라이언트 정체성 확인은 군비 경쟁이고 공급자가 이기는 방법은 하나뿐이다

이 사건의 시간표가 모든 것을 말한다.
차단 배포에서 우회 병합까지 약 4시간이었다.

이유는 구조적이다.
서버가 클라이언트를 식별하는 데 쓸 수 있는 것은 클라이언트가 보내는 값들뿐이고, 그 값들은 전부 위조 가능하다.
User-Agent, 베타 플래그, 도구 이름, 시스템 프롬프트 — mcast가 언급한 “You are Claude Code, Anthropic's official CLI for Claude”라는 문자열까지 포함해 전부 문자열이다[^mcast].
차단 규칙을 정교하게 만들수록 공식 클라이언트와 완벽히 같아지도록 흉내 내면 되고, 완벽히 같아진 요청은 원리적으로 구별할 수 없다.

그래서 공급자에게 남는 유일한 승리 조건은 요청이 아니라 계정을 보는 것이다.
사용 패턴이 이상하면 그 계정을 끊는 것 — kzhrv가 유일하게 해결 불가능하다고 지목한 그 방법이다.
그리고 이 방법은 정확도가 낮으므로 반드시 오탐을 낳는다.

여기서 나오는 일반 원칙은 이렇다.
클라이언트 신원에 의존하는 정책은 집행 불가능하고, 집행하려 하면 정책이 행동 감시로 변질되며, 행동 감시는 무고한 사용자를 친다.
정말로 사용 방식을 제한하고 싶다면 신원이 아니라 관측 가능한 자원 — 요청 속도, 동시성, 캐시 미스율 — 을 기준으로 삼아야 하고, 그 기준은 공개할 수 있어 사용자가 스스로 지킬 수 있다.

### 캐시 전략이 하네스의 실제 원가를 결정한다

이 이슈에서 몇 주 뒤에 드러난 사실이 처음의 논쟁보다 중요하다.
같은 구독으로 OpenCode를 쓰면 Claude Code보다 한도가 훨씬 빨리 소진된다.

Christopher-R-Perkins가 밝힌 구조 — Claude Code가 Explore에 Haiku, statusline에 Sonnet, 가이드에 Haiku를 쓰고 나머지가 상속한다 — 가 그 차이의 절반이다.
나머지 절반은 dearkafka가 짚은 캐시다 — 네이티브 Claude Code는 캐시된 토큰에 더 의존하기 때문에 부분적으로 “더 멍청”하며, 그것이 그들이 OpenCode를 쓰는 Max 계정을 이따금 차단하는 이유라는 것이다.

이 관찰은 논쟁의 도덕적 구도를 바꾼다.
“같은 구독인데 왜 다른 도구는 안 되느냐”는 물음에 대해, 실제로 같은 구독이 아니었다는 답이 있는 것이다.
같은 작업량에 대해 서버 비용이 몇 배 다르다면 그것은 정책 차별이 아니라 원가 차이이며, cantalupo555가 공유한 해법 — `small_model`을 Haiku로 지정하는 것 — 은 그 차이를 사용자가 스스로 줄일 수 있음을 보여준다.

여기서 실무적 판단 기준이 나온다.
에이전트 하네스를 고를 때 비교해야 할 것은 기능 목록이 아니라 모델 라우팅과 캐시 전략이다.
어떤 하위 작업에 어떤 크기의 모델을 쓰는지, 프롬프트 접두부가 얼마나 안정적인지, 대화 기록을 어떻게 재구성하는지가 같은 작업의 실질 비용을 몇 배 가른다.
그리고 이것들은 대개 문서화되지 않으므로, 새 하네스를 도입할 때 초기 며칠간 사용량을 실측하는 것이 유일한 확인 방법이다.

### 미끼 상품은 사용처를 통제할 수 있을 때만 미끼로 남는다

dfabulich와 marco-kretz가 각각 지적한 가격 구조가 이 사건의 뿌리다.
구독은 API의 5분의 1 값인데, 그 차액은 사용자를 Claude Code 생태계에 묶어 두는 값으로 지불된 것이다.

그런데 이 계산은 사용처를 통제할 수 있을 때만 성립한다.
통제가 실패하면 회사는 락인 없이 할인만 제공하는 셈이 되고, 그것은 그냥 손실이다.
그래서 통제 실패가 확인되는 순간 회사는 반드시 둘 중 하나를 해야 한다 — 통제를 강화하거나 할인을 없애거나.

Anthropic은 전자를 골랐고, 그 선택의 실질 결과는 통제 강화가 아니라 4시간짜리 서비스 중단과 대규모 이탈이었다.
후자를 골랐다면 — 구독가를 올리거나 구독의 토큰 한도를 낮추거나 서드파티 사용을 명시적으로 유료화했다면 — 같은 재무 목표를 달성하면서 사용자에게 선택권을 남길 수 있었다.
Mithrillion의 관찰이 그 대안을 암시한다[^mithrillion].
수많은 에이전트 하네스가 Anthropic 모델 쪽으로 편향되게 튜닝되어 있어서 Claude가 우위를 갖는 것처럼 보이는데, 현재 정책은 사람들이 Claude에 우선 최적화된 워크플로와 도구와 프롬프트를 쓰는 것을 오히려 막을 것이라는 것이다.

이 지적이 아프다.
서드파티 하네스가 Claude에 맞춰 최적화되는 것은 공짜로 얻는 생태계 자산인데, 그것을 차단하면 자산이 경쟁 모델 쪽으로 재배치된다.
sergiotapia와 brainless가 GLM으로 옮겨 만족했다는 보고가 그 재배치의 첫 사례이며, 하네스가 진짜로 모델 중립이 되면 무엇이 남는지 보자는 Mithrillion의 말은 위협이 아니라 예보에 가깝다.

### 새벽에 배포한 정책 변경은 정책이 아니라 사고로 기억된다

이 사건에서 Anthropic이 잃은 것의 대부분은 정책 때문이 아니라 배포 방식 때문이다.

목요일 밤에 예고 없이, 오류 메시지에 이유를 적지 않고, 공식 채널의 안내 없이 배포했다.
그 결과 사용자들은 자기 설정이 망가진 줄 알고 로그아웃과 재로그인과 토큰 폐기를 반복했고, 그 몇 시간의 혼란이 이 이슈의 첫 100개 댓글이다.
정책 자체를 옹호하는 사람들조차 이 부분은 옹호하지 않는다.

배포 관점에서 보면 이것은 하위 호환을 깨는 변경을 릴리스 노트 없이 내보낸 것과 같다.
차이는 이 경우 영향받는 클라이언트가 자사 것이 아니라 서드파티라는 점인데, 바로 그래서 통지가 더 중요했다 — 그들은 변경 사실을 알 다른 경로가 없기 때문이다.

여기서 나오는 원칙은 API 운영 전반에 적용된다.
의도적으로 서드파티를 끊는 변경일수록 통지가 더 필요하다.
통지 없이 끊으면 사용자는 그것을 정책 집행이 아니라 장애로 경험하고, 장애로 경험된 정책은 정당성과 무관하게 신뢰를 깎는다.
그리고 그 순간 만들어진 이슈 스레드는 386개 댓글과 함께 검색 결과에 영구히 남아, 이후 몇 년간 이 회사를 평가하려는 사람들이 가장 먼저 읽는 문서가 된다.
