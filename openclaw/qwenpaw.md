# QwenPaw: 내 컴퓨터나 클라우드에 설치해 여러 채팅 앱으로 부르는 개인용 AI 비서

<https://github.com/agentscope-ai/QwenPaw>

HN 토론: <https://news.ycombinator.com/item?id=47591580> (2점, 1개 댓글)

## 소개

QwenPaw는 AgentScope 팀이 만든 오픈소스 개인 AI 비서이고,
라이선스는 Apache-2.0입니다.
저장소는 2026년 2월 24일에 만들어졌고 11월 5일에도 커밋이 올라오며,
별은 37,385개입니다.
이름은 Qwen Personal Agent Workstation의 줄임말이라고 README가 설명합니다.
저장소는 이전에 CoPaw라는 이름으로 불렸고,
HN에는 그 이름으로 올라온 글이 있습니다.[^ekzhu]
그 글은 2B, 4B, 9B 크기의 개인 비서용 모델을 함께 내놓았다는 점을
앞세웠습니다.[^ekzhu]
프로젝트가 스스로 내세우는 특징은 세 겹 기억, 로컬 모델 내장,
커널 수준 샌드박스, 여러 에이전트의 병렬 실행, 여러 채팅 채널 연결입니다.
이 문서의 설명은 README에서 가져온 것이고, 직접 설치해 돌려 본 결과가 아닙니다.

## 설치하고 실행하기

설치 경로는 README에 일곱 가지가 나옵니다.
Python 3.11 이상 3.14 미만이 있으면 `pip`로 설치하고,
그렇지 않으면 설치 스크립트나 Docker, 데스크톱 앱을 씁니다.

```bash
pip install qwenpaw
qwenpaw init --defaults
qwenpaw app
```

실행하면 `http://127.0.0.1:8088/`에서 콘솔이 열리고,
설정의 모델 항목에서 제공자와 API 키를 고릅니다.
`qwenpaw`만 입력하면 같은 에이전트를 쓰는 전체 화면 터미널 UI가 열리고,
기억과 스킬과 MCP 도구와 세션은 콘솔과 공유됩니다.
저장소 폴더에서 `qwenpaw .`를 실행하면 코딩 모드로 시작합니다.

Docker는 `agentscope/qwenpaw` 이미지를 받아 `127.0.0.1:8088`으로만 포트를 열고,
데이터와 비밀값과 백업을 각각 다른 볼륨에 둡니다.
호스트의 Ollama에 붙으려면 컨테이너 안에서 `localhost`가 컨테이너 자신을
가리키므로 `host.docker.internal` 주소를 쓰라고 README가 안내합니다.
그 밖의 경로로는 알리바바 클라우드 ECS 원클릭 배포, AgentScope Platform,
ModelScope Studio가 있습니다.
데스크톱 앱은 베타이며 Windows 10 이상과 macOS 14 이상을 지원하고,
첫 실행에 10~60초가 걸릴 수 있습니다.

## 로컬 모델

클라우드 LLM을 쓸 때만 API 키가 필요하고,
로컬 모델만 쓰면 키가 필요 없다고 README는 말합니다.
로컬 실행 방법은 세 가지입니다.

| 백엔드                   | 설명                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| QwenPaw Local(llama.cpp) | 내장되어 있고 웹 화면에서 내려받습니다. 하드웨어에 맞는 QwenPaw-Flash를 추천합니다. |
| Ollama                   | Ollama 서비스를 따로 실행해야 하고, 컨텍스트 길이를 32k 이상으로 설정해야 합니다.   |
| LM Studio                | LM Studio를 설치하고 로컬 서버를 켜야 합니다.                                       |

QwenPaw-Flash는 Q4와 Q8 양자화판이 ModelScope와 Hugging Face에 올라와
있다고 합니다.

## 보안 계층

README는 다섯 겹의 보안 계층을 설명합니다.

- **샌드박스**: macOS는 Seatbelt, Linux는 Bubblewrap과 Landlock, Windows는 AppContainer로 쉘 명령을 제한된 파일 시스템 안에서 실행합니다.
- **Tool Guard**: 모든 도구 호출을 실행 전에 YAML 규칙으로 검사해 명령 주입, 경로 우회, 리버스 쉘, 난독화 공격을 찾습니다. 승인 수준은 STRICT, SMART, AUTO, OFF에서 고릅니다.
- **File Guard**: Tool Guard와 따로 동작하며 비밀값 폴더와 `~/.ssh` 같은 민감한 경로를 기본으로 막습니다.
- **Skill Scanner**: 스킬을 켜기 전에 프롬프트 주입, 하드코딩된 비밀값, 데이터 유출을 검사하고 차단, 경고, 끄기 모드와 허용 목록을 지원합니다.
- **Access Policy**: 기능 호출마다 허용, 거부, 사람 승인 요청을 선언적으로 정하고, 도구 단위와 호출 출처까지 구분합니다.

## 릴리스 흐름

README의 소식란은 2026년 7월 24일 v2.0.1부터 10월 15일 v2.2.2까지 석 달도 안
되는 사이에 다섯 번의 릴리스를 적었습니다.
그 사이에 미니 앱 플랫폼(PawApp), 통합 파일 작업 공간, 컴퓨터 사용 기능,
여러 사용자가 쓰는 자체 호스팅 허브, 메일과 데이터 기능,
에이전트별 모델 라우팅이 차례로 들어갔습니다.
로드맵은 릴리스 평가 순위 공개, 핵심이 아닌 구성 요소를 플러그인으로 떼어 내기,
결정 모델 연동, UI와 UX 개선을 진행 중이라고 적었습니다.

## 비평

### 보안 계층은 설계 설명이고 검증 결과가 아니다

위험한 명령은 실행 전에 막는다는 문장은 README에 있지만,
그 차단율을 보여 주는 시험이나 외부 점검 결과는 README에 없습니다.
Tool Guard의 승인 수준에 AUTO와 OFF가 있다는 점은 보호가 설정에 달렸다는 뜻이고,
기본값이 무엇인지 README는 말하지 않았습니다.
채팅 앱에서 들어온 메시지로 에이전트를 움직이는 구조에서는 샌드박스 바깥의 도구
호출 경로가 더 중요한데, 그 부분의 검증도 확인할 수 없습니다.

### 데이터가 내 컴퓨터에 남는다는 약속에는 조건이 붙는다

로컬에 배포하면 데이터가 컴퓨터에 남고 제3자 호스팅이나 업로드가 없다고 README는
말합니다.
하지만 같은 README가 클라우드 LLM을 쓰려면 API 키를 넣으라고 안내하므로,
클라우드 모델을 고르면 대화가 그 제공자로 나갑니다.
약속이 온전히 맞는 경우는 로컬 모델만 쓰는 구성이고,
README는 이 조건을 다른 자리에 나누어 적었습니다.
또 `qwenpaw init`은 사용 환경 정보를 익명으로 보내고,
`--defaults`로 실행하면 수집에 자동으로 동의한 것으로 처리된다고 README가
밝힙니다.
수집 항목은 버전, 설치 방식, 운영체제, 파이썬 버전, CPU 구조, GPU 유무입니다.

### 설치 경로가 보안 계층의 취지와 어긋나는 대목이 있다

설치 스크립트는 내려받은 내용을 바로 쉘에 넘기는 형태이고,
macOS 앱은 공증을 받지 않았습니다.
README는 막힌 앱을 여는 방법으로 격리 속성을 지우는 명령까지 적으면서 이 방법이
덜 안전하다고 스스로 경고합니다.
에이전트의 위험한 명령을 실행 전에 막는 도구가 정작 사용자에게는 검증되지 않은
설치 방법을 권하는 셈이라, 설치 경로는 Docker나 소스 빌드처럼 확인이 가능한 쪽을
고르는 편이 낫습니다.

### 빠르게 넓어진 범위를 프로젝트도 부담으로 본다

석 달 사이 다섯 번의 릴리스에서 기능 영역이 계속 늘었고,
로드맵의 첫머리에는 핵심이 아닌 구성 요소를 플러그인으로 떼어 설치와 실행 비용을
줄이는 일이 있습니다.
이는 설치 크기와 실행 비용이 문제가 되었다는 뜻으로 읽힙니다.
별 37,385개는 관심의 크기를 말할 뿐 이 소프트웨어의 안정성이나 보안 수준을
말하지 않습니다.
README가 말하는 쓰임새를 실제 업무에 쓸 수 있는지는 직접 설치해 확인해야 하고,
이 문서는 그 확인을 하지 않았습니다.

## 인사이트

### 1. 도입 전에 확인할 것

- 클라우드 모델을 쓸지 로컬 모델만 쓸지부터 정합니다. 그에 따라 데이터가 나가는 범위가 달라집니다.
- Tool Guard의 기본 승인 수준과 File Guard의 기본 보호 경로를 설치 후 직접 확인합니다.
- 채널(채팅 앱)을 붙인 에이전트에 어떤 권한을 줄지 Access Policy로 먼저 좁힙니다.
- `qwenpaw init --defaults`는 수집 동의를 포함하므로, 원하지 않으면 대화형으로 실행해 거절합니다.

### 2. 이 주장을 확인하는 관찰

보안 계층이 실제로 막는다는 주장은, 같은 환경에서 명령 주입과 스킬 안의 악성
지시를 일부러 넣었을 때 계층별로 얼마나 차단되는지 공개될 때 강해지거나
약해집니다.
로컬 모델의 쓸 만함은 2B부터 35B-A3B까지 크기별로 같은 업무를 맡겼을 때의
성공률이 나와야 판단할 수 있고, README에는 그 수치가 없습니다.
