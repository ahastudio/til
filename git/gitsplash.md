# GitSplash: 다중 계정 Git 클라이언트

<https://github.com/Greenpoison/GitSplash>

## 소개

GitSplash는 여러 GitHub 계정에 걸쳐 여러 저장소를 관리하는 사람을 위한 데스크톱 Git 클라이언트이다. 저장소 설명은 다중 계정 GitHub 저장소 관리자라고 한다.
이 문서는 `README.md` 전문, 저장소 목록, 릴리스 목록, 라이선스 첫 부분, GitHub API 수치를 읽었다. 소스 코드는 열지 않았고 직접 설치해 써 보지도 않았다.
설명은 모두 저장소의 주장이다.
저장소에 등록된 홈페이지가 없다. GitHub API의 홈페이지 필드가 비어 있고, README와 패키지 설정, 개발자 프로필에도 프로젝트 사이트 주소가 없어서 저장소 주소만 적었다.

GitHub API로 읽은 시점(2026년 11월 18일)의 수치는 별 2개, 포크 0개, 열린 이슈 0개, 언어 TypeScript, 생성일 2026년 7월 30일, 마지막 푸시 2026년 9월 22일이다.
README는 현재 베타이며 가끔 거친 부분이 있다고 밝힌다. 최신 릴리스는 v1.0.97-beta(2026년 9월 22일)이고 Windows x64 설치 파일(.exe)만 있다.

기술 스택은 Tauri 2, React 19, Rust이다. 지원 플랫폼은 Windows이다.

주요 기능은 다음과 같다.

- 분기와 이력: 끌어서 순서를 바꾸고 pick, reword, squash, fixup, drop을 고르는 시각적 대화형 리베이스(충돌 시 일시 정지와 재개), 다른 브랜치의 커밋을 고르고 순서를 바꿔 적용하는 시각적 대화형 체리픽, 체크아웃과 이전 브랜치 복귀, 충돌 감지가 있는 병합, 기능과 릴리스와 핫픽스 브랜치를 한 번에 시작하고 끝내는 Gitflow 도우미, 커밋 그래프에서 브랜치 숨기기와 단독 보기, 레인 렌더링 커밋 그래프.
- 작업 트리: 헝크 단위 스테이징이 있는 diff 뷰어와 커밋 작성기, 블록 단위로 ours, theirs, 둘 다, 직접 수정을 고르는 병합 충돌 해결기(바이너리는 파일 단위), 파일 이력과 blame, 빠른 수정을 위한 내장 파일 편집기, 워크트리(목록, 추가, 제거, 정리)와 서브모듈 상태와 갱신.
- 다중 계정과 보안: 계정마다 전용 SSH 키 쌍과 `~/.ssh/config` 호스트 별칭을 만들고 계정에 지정할 때 원격 주소를 자동으로 바꾼다. 브라우저 기반 계정 로그인(`gh auth login --web`)을 쓴다. SSH 또는 GPG 커밋 서명을 계정에 지정된 모든 저장소에 소급 적용한다. 비밀로 보이는 파일을 찾고 암호가 걸린 AES 암호화 묶음으로 내보내는 비밀 스캐너가 있다.
- 생산성: 저장소 묶음 전체에 한 번에 가져오기와 풀을 하고 저장소별 진행을 실시간으로 보여 준다. `Ctrl+K` 명령 팔레트와 전역 단축키, 스테이징과 커밋과 체크아웃과 병합의 한 번 클릭 실행 취소와 다시 실행이 있다.
- GitHub 연동: `gh` CLI를 통해 계정별로 풀 리퀘스트를 목록, 생성, 병합한다.
- 화면: 그룹으로 묶은 저장소의 ahead/behind와 깨끗함/변경됨 상태를 보는 대시보드, 모든 브랜치의 커밋을 펼쳐 확대하는 Repo History 화면이 스크린샷으로 소개된다.
- 설치와 빌드: 설치 파일은 Node.js나 Rust 없이 설치된다고 한다. 소스에서 빌드하려면 Windows 10과 11, Node.js 18 이상, Rust, GitHub CLI(`gh`), GPG(GPG 서명을 쓸 때만)가 필요하고 `npm install`과 `npm run tauri dev`로 실행한다.
- 라이선스: MIT에 Commons Clause를 더한 것이다. README는 쓰고, 포크하고, 고치는 것은 자유이지만 돈을 받고 팔 수 없다고 설명하고 라이선스 파일의 조건은 소프트웨어의 판매를 제3자에게 유료로(호스팅과 지원 서비스 포함) 제공하는 권리를 허락하지 않는다고 한다. GitHub는 이를 `NOASSERTION`(기타)으로 표시한다.

## 분석

### 중심 주장은 계정이 여럿이어도 저장소를 한곳에서 다룬다는 것이다

README의 첫 문장이 이 도구의 대상(여러 GitHub 계정에 걸친 여러 저장소)을 밝힌다.
계정마다 SSH 키와 호스트 별칭을 만들어 원격 주소를 자동으로 바꾸고, 커밋 서명도 계정에 맞춰 소급 적용하는 구성은 개인 계정과 회사 계정을 오가는 사용자의 번거로움을 겨냥한 것으로 읽힌다.
이는 README의 서술을 이 문서가 정리한 것이다.

### 고급 Git 작업을 시각화하는 쪽에 기능이 많다

대화형 리베이스와 체리픽의 끌어서 정렬, 헝크 단위 스테이징, 병합 충돌의 블록 단위 해결, 레인 커밋 그래프는 명령줄에서 번거로운 작업을 시각적으로 옮긴 것이다.
같은 영역의 다른 클라이언트와 기능이 겹치지만, 다중 계정 관리와 Gitflow 도우미, 비밀 스캐너를 한 앱에 넣은 점이 이 도구의 구성이다. 이 문서는 다른 클라이언트와 기능을 같은 기준으로 비교하지 않았다.

## 비평

### 초기 프로젝트라서 근거가 거의 없다

별 2개, 생성한 지 넉 달 남짓, 베타 버전이다. 사용 후기와 독립된 평가를 읽지 못했다.
마지막 푸시가 9월 22일이므로 그 이후 두 달간 갱신이 없다. 유지 계획은 README에 없다.

### 플랫폼과 의존 범위가 좁다

README의 플랫폼 배지는 Windows뿐이고 릴리스도 Windows x64용 설치 파일 하나이다.
계정 로그인과 풀 리퀘스트가 `gh` CLI에 의존하므로 GitHub 외의 서비스(GitLab, Bitbucket)는 읽은 범위에서 지원 서술이 없다.

### 라이선스가 오픈소스 정의와 다르다

MIT에 Commons Clause를 더한 조건은 판매를 막는 제한이어서, 널리 쓰이는 오픈소스 정의에 맞는 라이선스로 보기 어렵다.
README는 무료로 쓰고 고칠 수 있다고 설명하지만 회사에서 서비스에 쓰거나 지원 서비스에 곁들이는 경우는 조항을 확인해야 한다.
이 문서는 법률 해석을 하지 않았고 라이선스 전문을 읽지 못했다.

### 보안 기능의 신뢰는 확인되지 않았다

SSH 키 생성과 `~/.ssh/config` 수정, 모든 저장소에 소급 서명 적용, 비밀 스캐너와 암호화 묶음은 민감한 작업을 자동으로 한다.
이 도구가 어떻게 키를 저장하고 설정을 수정하는지는 소스를 읽어야 알 수 있고 이 문서는 읽지 못했다.
공개된 릴리스 바이너리는 서명 파일(`.sig`)이 함께 있지만, 그 서명의 검증 방식은 확인하지 못했다.

### 외부 반응

HN에서는 이 저장소 주소와 도구 이름으로 검색한 결과 이 도구의 글이 없었다(이름이 비슷한 다른 프로젝트의 글만 있었다).
Lobste.rs에서는 `gitsplash`로 검색한 결과가 0건이었다.
GeekNews에서는 `GitSplash`로 검색한 결과 이 프로젝트의 토픽이 없었다(대조 쿼리는 정상이었다).

## 인사이트

### 가져갈 것은 여러 계정의 키와 서명을 한곳에서 정리하는 구성이다

계정마다 SSH 키와 호스트 별칭, 서명 키를 분리하는 방식은 도구와 무관하게 쓸 수 있는 습관이다.
개인과 회사 계정을 오가면 커밋 작성자와 서명 키가 섞이는 사고가 생기므로 계정별로 키와 설정을 나누는 구성의 목록으로 참고할 수 있다.
이는 이 문서의 적용이다.

### 자동으로 키와 설정을 만지는 도구는 백업과 범위부터 확인한다

`~/.ssh/config`와 원격 주소를 자동으로 바꾸는 도구는 문제가 생겼을 때 되돌리기가 어렵다.
사용 전에 설정 파일을 백업하고 어떤 저장소에 영향을 주는지 확인한다.

### 확인할 관찰

이 프로젝트의 주장을 가를 관찰은 세 가지이다.
릴리스 바이너리와 소스가 일치하는지,
키와 설정을 다루는 코드의 안전성,
개발이 이어지는지와 다른 플랫폼 지원 계획이다.
셋 모두 이 문서가 확인하지 못했다.
