# Gittyup: Qt로 만든 Git 클라이언트

<https://murmele.github.io/Gittyup>

<https://github.com/Murmele/Gittyup>

HN 토론: <https://news.ycombinator.com/item?id=42865141> (3점, 0개 댓글)

## 소개

Gittyup은 Git 이력을 이해하라는 문구를 내세우는 그래픽 Git 클라이언트이다.
README는 GitAhead 클라이언트의 연속이라고 하고, 프로젝트 사이트의 변경 기록은 v1.0.0(2021년 11월 18일)을 GitAhead 포크의 첫 버전이라고 적는다.
유지 관리자는 Murmele이다.
`gittyup.org`는 이 문서를 쓸 때 DNS가 풀리지 않았다.
저장소의 홈페이지 필드는 `murmele.github.io/Gittyup`이어서 그 사이트를 읽었다.
직접 설치해 써 보지 않았고 소스 코드와 개발 빌드, Flathub와 Homebrew 페이지는 열지 못했다.
설명은 모두 프로젝트의 주장이다.

GitHub API로 읽은 시점(2026년 11월 19일)의 수치는 별 2,329개, 포크 188개, 열린 이슈와 풀 리퀘스트 368개, 라이선스 MIT, 언어 C++, 생성일 2019년 8월 25일, 마지막 푸시 2026년 11월 3일이다. GitHub API는 이 저장소를 포크 노드로 표시하지 않고 GitAhead와의 관계는 설명으로만 적혀 있다.
최신 릴리스는 `gittyup_v2.0.0`(2025년 11월 30일)이고 릴리스 본문은 비어 있으며 첨부는 Linux AppImage와 Flatpak뿐이다. 사이트와 README는 Windows와 macOS 바이너리를 `releases/latest`에서 받는다고 적지만 이 릴리스에는 붙어 있지 않다.

사이트와 README가 소개하는 내용은 다음과 같다.

- 화면: 단일 브랜치 커밋 목록, 전체 화면 이력과 diff(`Ctrl+M`), 여러 저장소 탭, blame과 시간선, 트리 보기이다.
- 스테이징: 줄 단위로 체크하거나 텍스트를 고르고 `S`와 `U`로 스테이징과 해제, `R`로 되돌린다.
- 커밋과 충돌: 커밋 수정, 리베이스 충돌 해결과 계속, 파일 전체 병합 충돌 해결, 바이너리 충돌(v1.2.0)이 있다.
- 기타: 커밋 별표, 태그 템플릿, 커밋 메시지 템플릿, Gitea 인스턴스 지원, 사용자 단축키, 단일 인스턴스 모드, 8개 언어이다.
- 2.0.0의 내용: Qt6로 전환, libgit2 갱신, 첫 부모 기준 커밋 필터, SHA-256 저장소 지원이다.
- 기술: Qt 6.4 이상, Scintilla(diff와 텍스트 보기), libgit2, cmark, libssh2, OpenSSL이다. 빌드는 C++11 컴파일러와 CMake 3.19 이상이 필요하다.
- 플랫폼과 설치: Linux, Windows, macOS이다. Flatpak(README가 가장 쉬운 방법이라고 함), Arch의 AUR, macOS의 Homebrew cask를 안내한다.
- 라이선스: MIT이다.

## 분석

### 중심 주장은 GitAhead의 연속이라는 것이다

프로젝트는 GitAhead가 멈춘 자리에서 Qt6와 새 libgit2로 이어 가는 유지 관리 포크이다.
Gitember나 GitComet처럼 새로 시작한 프로젝트와 다른 출발점이다. 이는 이 문서의 관찰이다.

### 이력 이해에 기능을 모았다

시간선이 있는 blame, 첫 부모 필터, 별표 커밋은 이력을 읽는 데 쓰는 기능이다.
스테이징과 충돌 해결은 기본 수준을 갖춘다. 이는 사이트의 서술을 이 문서가 정리한 것이다.

## 비평

### 릴리스가 오래되었고 배포가 불완전하다

최신 안정 릴리스가 약 1년 전이고 저장소 활동은 계속된다.
릴리스 본문이 비어 있고 Windows와 macOS 바이너리가 첨부되지 않아 사이트의 안내와 어긋난다.

### 열린 이슈와 풀 리퀘스트가 많다

368개 중 이슈 342개와 풀 리퀘스트 26개이다. 처리 우선순위는 읽은 범위에 없다.
유지 관리자가 한 명으로 보이는 점이 위험이다. 이는 이 문서의 해석이다.

### 도메인 혼선이 있다

`gittyup.org`가 이 문서를 쓸 때 열리지 않았고 HN 검색에서 같은 주소는 다른 프로젝트(Tup 빌드 시스템과 Gittup 배포판)의 글만 나왔다.
공식 사이트는 `murmele.github.io/Gittyup`로 보인다.

### 외부 반응

HN에는 저장소 글이 한 건(3점, 댓글 없음) 있다. 2022년 Fork 글에서 한 사용자가 Gittyup을 오픈소스의 성숙한 대안으로 들었다.[^skrowl]
Lobste.rs에는 `gittyup.org` 도메인의 글이 없었다.
GeekNews에서는 `Gittyup`으로 검색해 결과가 없었다(대조 쿼리는 정상이었다).

## 인사이트

### 가져갈 것은 중단된 프로젝트를 이어 가는 포크의 조건이다

라이선스가 MIT여서 이어 가기가 가능했고, 새 툴킷(Qt6)과 의존성 갱신이 이어진 이유로 읽힌다. 도구를 고를 때 유지 관리자의 수와 릴리스 주기를 함께 본다. 이는 이 문서의 적용이다.

### 배포 파일을 설치 전에 확인한다

릴리스에 플랫폼별 바이너리가 붙었는지 확인하고, 없으면 Flatpak이나 Homebrew 같은 다른 경로를 쓴다.

### 확인할 관찰

이 프로젝트의 주장을 가를 관찰은 세 가지이다.
Windows와 macOS 바이너리의 최신 배포 위치,
유지 관리자 구성과 이슈 처리 속도,
큰 저장소에서의 성능이다.
