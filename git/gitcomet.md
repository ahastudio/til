## 소개

GitComet은 Rust로 처음부터 끝까지 만든 오픈소스 Git GUI 클라이언트이다. 핀란드 회사 AutoExplore Oy가 개발한다고 한다.
이 문서는 프로젝트 사이트(`gitcomet.dev`)의 전문, 저장소 `README.md` 앞부분과 에디션 절, GitHub API 수치, HN 글과 댓글을 읽었다.
기능별 문서(`docs/`), 소스 코드, 변경 기록은 열지 않았고 직접 설치해 써 보지도 않았다.
설명과 수치는 모두 프로젝트의 주장이다.

GitHub API로 읽은 시점(2026년 11월 18일)의 수치는 별 1,042개, 포크 67개, 열린 이슈 92개, 라이선스 AGPL-3.0, 언어 Rust, 생성일 2026년 1월 20일, 마지막 푸시 2026년 11월 18일이다. 최근 릴리스는 v0.3.4(2026년 11월 10일)이다.
사이트는 별 1,000개 목표를 달성해 1,028개였다고 적고 있다. 저장소의 홈페이지 필드는 `gitcomet.dev`이다.

시작 이유는 Chromium 같은 거대한 코드베이스에서 기존 도구가 반응성과 기능을 잃는 데 대한 불만이었다고 README가 밝힌다. 사이트는 이를 가장 빠른 오픈소스 Git GUI라는 문구로 내세운다.

기능은 다음과 같다.

- 속도: smol, gix(Gitoxide), gpui로 만들어 빠른 동작을 내세운다. 사이트는 Rust 전용 구현이라고 소개한다.
- 정밀한 스테이징: 파일, 헝크, 한 줄 단위로 diff 여백에서 바로 스테이징하고 한 가지 생각만 커밋한다.
- 로컬 우선: 저장소가 기기에 남고 계정, 동기화, 업로드가 필요 없다. 개인과 상업 모두 무료이다.
- 오픈소스 에디션: Git 원격과 풀과 푸시, 브랜치 범위 풀, 백그라운드 자동 가져오기, 워크트리, 브랜치, 이력, 베어 저장소 열람과 변환, 다중 저장소 작업 공간과 창, 통합과 나란히 보기 diff, 한 줄 스테이징, Difftastic, 2자와 3자 병합 도구, 대화형 리베이스, 체리픽, blame, 스태시, 서브모듈, 내장 편집기와 터미널, 사용자 테마, Git LFS(상태, 내용 받기, 잠금, 추적), git-annex가 있다.
- Difftastic(0.3.1에 새로 들어옴): 줄이 아니라 코드 구조를 비교해 바뀐 토큰만 강조한다. 감싸기나 재포맷 때문에 작은 수정이 묻히는 문제를 줄인다고 한다. 서식만 바뀐 경우 구문 변경 없음으로 알린다.
- 대화형 리베이스: 커밋을 오른쪽 클릭해 끌어서 순서를 바꾸고 pick, reword, squash, fixup, drop을 고르며 범위를 합칠 때 결과 메시지를 미리 본다.
- 도구로 쓰기: `git difftool`과 `git mergetool`의 독립 도구로 쓸 수 있다. `gitcomet setup`과 `gitcomet uninstall`이 전역 또는 `--local` 설정을 쓰고 지운다(`--dry-run` 지원). 헤드리스(알고리즘만)와 GUI 변형을 모두 등록하고 화면이 있으면 GUI를 쓴다.
- 지원 환경: Linux, Windows, macOS의 x86-64와 ARM64이다. Linux는 Wayland, X11, WSLg를 지원한다. 로컬 Git 2.53 이상이 필요하고 더 오래된 Git에서는 알림이 뜨며 저장소 유지 관리 같은 최신 기능이 꺼진다.
- 설치: GitHub 릴리스, Homebrew cask, Microsoft Store, apt 저장소(Debian과 Ubuntu), Fedora RPM(Fedora 42 이상, glibc 2.35 이상이라 RHEL 9 계열은 불가), AUR, Gentoo GURU, Nix, AppImage가 있다. Windows 설치 파일은 서명되었고 macOS 디스크 이미지는 공증되었다고 한다.

유료 에디션 GitComet Pro는 다음과 같다.

- 별도 데스크톱 앱이며 오픈소스의 모든 기능에 더해 GitHub, GitLab, Azure DevOps, Bitbucket, Gitea, Forgejo에서 풀 리퀘스트 검토, 댓글, 승인, 병합을 한다(서비스에 따라 기능이 다르다).
- 코딩 에이전트 세션(Claude Code, Codex, OpenCode, Copilot CLI)을 History의 커밋 옆에 상태와 함께 보여 주고, 세션을 앞으로 가져오거나 재개 명령을 복사하거나 그 위치의 터미널을 연다.
- 선택적 AI: 자기 제공자나 로컬 모델로 커밋 메시지, 설명, 변경 노트, 풀 리퀘스트 설명을 만든다. 기본은 꺼져 있고 켜면 무엇을 어느 제공자에게 보내는지 툴팁이 말한다.
- 프로젝트와 프로젝트별 Git 신원, 여러 계정 동시 연결이 있다.
- 요금: 개인 월 4유로(연 결제, 부가세 별도, 개인 또는 상업 작업에 다섯 대까지), 조직 사용자당 월 4유로(연 결제, 최소 2좌석, 팀 관리와 SSO). 자격 증명은 운영체제 키체인에 남고 풀 리퀘스트와 병합은 데스크톱에서 서비스로 직접 간다고 한다. Pro 서비스는 계정과 라이선스를 다룬다.

사이트에는 뉴스레터 구독 안내와 사용자 설문 링크도 있다.

## 분석

### 중심 주장은 큰 저장소에서도 반응하는 로컬 우선 클라이언트라는 것이다

시작 이유가 대형 코드베이스의 응답성이고, 구현이 Rust와 gix 기반이며, 로컬 우선과 무료와 AGPL을 함께 내세운다.
성능에 대한 구체적 수치는 읽은 범위에 없고 속도는 구현 기술 선택과 문구로 서술된다.
이는 프로젝트의 서술을 이 문서가 정리한 것이다.

### 오픈소스 본체와 유료 에디션의 경계가 에이전트와 풀 리퀘스트에 있다

무료 에디션은 로컬 Git 작업 전반을 갖추고, Pro는 풀 리퀘스트 검토와 코딩 에이전트 세션 표시, AI를 더한다.
앞서 읽은 다른 Git 클라이언트들이 무료 층을 사용 목적이나 저장소 종류로 가르는 것과 달리 이 제품은 연동 기능(포지, 에이전트, AI)으로 가른다는 것이 이 문서의 관찰이다. 이 문서는 제품들을 같은 기준으로 비교하지 않았다.

### 에이전트 시대의 이력 보기를 앞세운다

History에 에이전트 세션을 커밋 옆에 보여 주는 기능은 코딩 에이전트가 만든 변경을 사람이 추적하게 하려는 구성으로 읽힌다.
오픈소스 에디션의 이력에서는 에이전트 체크포인트와 다른 도구의 참조(ref)를 숨긴다고 README가 적는다. 이 구분은 에이전트가 저장소에 남기는 흔적이 늘어난 상황에 대한 대응으로 보인다. 이는 이 문서의 해석이다.

## 비평

### 속도 주장은 제작자의 서술이고 독립 측정이 없다

가장 빠른 오픈소스 Git GUI라는 문구는 사이트와 README에서 비교 수치나 방법을 읽지 못했다.
HN 글에서 제출자는 Chromium 저장소를 1초 안에 열고, 50MB 파일을 구문 강조와 함께 끊김 없이 비교하며, 메모리를 수백 MB 안에 유지한다고 썼다.[^havunen]
이 값은 제작자가 직접 한 주장이며 이 문서가 재현하지 못했고, 다른 클라이언트와의 비교는 없다.

### 초기 프로젝트라 열린 이슈가 많다

저장소는 올해 1월에 생겼고 버전 0.3대이며 열린 이슈가 92개이다.
HN에서 제출자는 출시 당일 macOS 서명 빌드에 문제가 있어 Apple 개발자 ID를 주문했다고 밝혔다.[^havunen2]
지금은 README가 macOS 디스크 이미지가 공증되었다고 쓴다.
독립된 사용 후기는 HN 글에 댓글이 거의 없어 읽지 못했다.

### 에디션 구분의 이해관계

오픈소스 본체가 AGPL이고 Pro는 별도 클라이언트로 판매된다.
README는 오픈소스가 개인과 상업 사용 모두 무료라고 하지만 AGPL 조건(서비스로 제공할 때의 소스 공개 등)은 사용 방식에 따라 확인해야 한다. 이 문서는 법률 해석을 하지 않았다.
Pro의 연동과 AI 기능이 오픈소스 쪽에 어떤 방식으로 공개될지는 README에 없다.

### 환경 요구 사항

로컬 Git 2.53 이상이 필요하고 RHEL 9 계열에서는 RPM을 설치할 수 없다.
이 제약은 도구를 도입할 때 확인할 항목이다.

### 외부 반응

HN에는 같은 사이트로 올라온 Show HN이 두 건(10점 댓글 없음, 3점 댓글 2개)이고 댓글은 모두 제출자의 것이다.
Lobste.rs에서는 `gitcomet`으로 검색한 결과가 0건이었다.
GeekNews에서는 `GitComet`과 설명 표현으로 검색한 결과 이 프로젝트의 토픽이 없었다(대조 쿼리는 정상이었다).
그래서 이 프로젝트의 주장은 독자의 검토를 거의 거치지 않았다.

## 인사이트

### 가져갈 것은 에이전트가 남기는 참조를 이력에서 구분하는 문제의식이다

코딩 에이전트가 저장소에 체크포인트와 도구 참조를 남기면 일반 이력이 어지러워질 수 있다.
이 도구는 오픈소스 에디션에서 이를 숨기고 Pro에서 세션을 커밋 옆에 보여 주는 방식으로 다룬다.
자기 저장소에서 에이전트가 남긴 참조를 어떻게 다루는지 점검하는 기준으로 쓸 수 있다. 이는 이 문서의 적용이다.

### difftool과 mergetool로 쓰는 방식은 부분 도입의 길이다

전체 클라이언트로 갈아타지 않고 `git difftool`과 `git mergetool`의 대안으로만 설치해 써 볼 수 있다.
`--dry-run`과 `uninstall`이 있어 설정을 되돌리기 쉽다는 점이 시험하기 좋은 조건이다.

### 확인할 관찰

이 도구의 주장을 가를 관찰은 세 가지이다.
Chromium급 저장소에서 다른 클라이언트와 같은 조건으로 잰 속도와 메모리 비교,
열린 이슈가 줄고 안정 버전으로 가는지,
Pro 기능이 오픈소스 본체의 방향에 영향을 주는지이다.
셋 모두 이 문서가 확인하지 못했다.
