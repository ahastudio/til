# gitg: GNOME의 Git 저장소 보기 도구

<https://gitlab.gnome.org/GNOME/gitg>

<https://github.com/GNOME/gitg>

## 소개

gitg는 GNOME이 만드는 Git 저장소 보기용 GUI 클라이언트이다.
GitHub README는 이를 Git 이력을 보기 위한 작고 빠르고 편리한 도구라고 하며 저장소를 관리하고 작업을 커밋하는 몇 가지 유틸리티도 제공한다고 적는다.
직접 설치해 써 보지 않았고 GitLab README 본문과 릴리스 페이지(렌더링되지 않음), 프로젝트 문서 사이트는 열지 못했다.
위키는 폐쇄되어 새 위치를 안내하며(마지막 표시 2024년 10월 23일) 별도 프로젝트 사이트가 읽은 범위에 없었다.
기본 저장소는 GitLab이고 GitHub는 읽기 전용 미러이다.
설명은 모두 프로젝트의 주장이다.

읽은 내용은 다음과 같다.

- 기능: 최근 저장소 개요, 저장소 이력 보기, 파일 보기, 커밋을 구성하는 스테이징 영역과 커밋 대화상자, 저장소 추가와 복제, 사용자 정보 설정, GNOME Shell 통합, 명령줄 옵션이다.
- 설치: Flathub(`org.gnome.gitg`), 소스 tarball(`meson --prefix=/usr build`, `ninja -C build`, `sudo ninja -C build install`), git 복제 후 같은 빌드, 개발용 Flatpak 매니페스트이다.
- 버전: 최신은 50(2026년 7월 1일 태그)이다. 이전에 보이는 태그는 v44(2023년 8월 3일), v41(2021년 12월 27일)이며 그 앞은 2016년에서 2019년의 3.x 시리즈이다.
- 라이선스: GPL-2.0 이상이다.
- 프로젝트 수치: GitLab 페이지에서 커밋 3,747개, 브랜치 47개, 태그 56개이고 생성일 2018년 5월 22일이다. GitHub 미러는 별 219개, 포크 29개이다.
- 언어: Vala와 GTK로 보이지만(`vapi/`, `libgitg/`, `meson.build`) 언어 표시는 읽은 범위에서 확인되지 않았다.
- 기여 정책: README는 대규모 언어 모델과 챗봇이 생성한 기여(코드, 문서, 이슈, 삽화)를 받지 않는다고 적는다.

## 분석

### 중심 주장은 작고 빠른 이력 시각화이다

README의 우선순위는 이력 시각화이고 관리 기능은 부차적이다.
앞서 정리한 클라이언트들이 병합 도구와 이슈 연동까지 내세우는 것과 범위가 다르다.

### GNOME 생태계 안의 앱이다

위키, 이슈, 번역, 포럼이 GNOME의 인프라(GitLab, l10n, Discourse)에 있고 배포가 Flathub 중심이다.
독립 제품이라기보다 데스크톱 환경의 부속 도구라는 위치로 읽힌다. 이는 이 문서의 해석이다.

## 비평

### 유지 관리의 속도가 느려 보인다

읽은 태그는 2021년의 v41, 2023년의 v44, 2026년의 50으로 간격이 길다. 위키는 폐쇄되어 있다.
이 간격이 안정이라는 뜻인지 개발 속도가 낮다는 뜻인지는 읽은 페이지에서 판단할 수 없다. 커밋 활동의 날짜는 확인하지 못했다.

### 문서와 사용 후기가 부족하다

위키는 보관 상태이고 GitLab 페이지는 README 본문을 담지 못했다. 독립된 사용 후기를 읽지 못했다.
Windows와 macOS 지원은 흔적만 있다.

### 기여 정책이 일부 사용자에게 장벽이다

LLM이 생성한 기여를 받지 않는 정책은 프로젝트의 선택이며 문서에 이유가 적혀 있는지는 읽은 범위에 없다.

### 외부 반응

HN에는 이 저장소 주소로 올라온 글이 없었다.
Lobste.rs에서는 `gitg` 검색 결과 4건이 모두 다른 글이었다. 한 건은 오래된 Krita 빌드 글이다.
GeekNews에서는 `gitg`로 검색한 결과 2건이 모두 다른 주제였다(대조 쿼리는 정상이었다).

## 인사이트

### 가져갈 것은 범위를 좁힌 도구의 장점이다

이력 보기에 집중하면 작고 빠르게 유지하기 쉽다. 필요한 기능이 이력 시각화뿐이라면 큰 클라이언트 대신 이런 도구가 맞을 수 있다. 이는 이 문서의 적용이다.

### 배포 경로를 먼저 확인한다

Flathub가 가장 쉬운 경로이고 배포판 패키지의 버전은 뒤처질 수 있다. 쓰려는 버전이 50인지 확인한다.

### 확인할 관찰

이 프로젝트의 주장을 가를 관찰은 세 가지이다.
최근 커밋 활동과 이슈 처리 속도,
Windows와 macOS 빌드의 실제 지원,
큰 저장소에서의 이력 보기 속도이다.
