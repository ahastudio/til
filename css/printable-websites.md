# 웹사이트는 인쇄할 수 있어야 한다: 12pt와 검은 링크로 시작하는 인쇄용 CSS

원문: [Websites Should Be Printable](https://brennenputh.me/blog/printable-websites/)

HN 토론: <https://news.ycombinator.com/item?id=50241664> (289점, 181개 댓글)

Lobste.rs 토론: <https://lobste.rs/s/olnqh2/websites_should_be_printable> (66점, 17개 댓글)

GN 토론: <https://news.hada.io/topic?id=36049>

## 요약

Brennen Puth가 2026년 10월 24일에 쓴 블로그 글이다.
그는 요즘 인쇄한 논문을 많이 읽는다고 시작한다.
노트북으로 읽는 것도 좋아하지만 인쇄물에 표시를 하며 읽는 쪽이 몰입이 잘 되고,
화이트보드 앞에서 인쇄물을 보고 있으면 중요한 일을 하고 있다는 기분도 든다는
것이다.
그래서 자기가 쓰는 글도 같은 방식으로 읽을 수 있게 하고 싶었다.

자기 사이트를 아무 조치 없이 인쇄해 보니 내용은 모두 나오지만 결과가 좋지
않았다.
글자가 두 단계쯤 크고, 머리글은 인쇄하면 보기 흉하고, 링크의 파란색이 흑백
인쇄에서는 회색으로 흐려졌다.
그는 CSS의 인쇄용 선택자로 이를 고쳤고, 글에 실린 스니펫은 다음과 같다.

```css
.onlyPrint {
  display: none;
}
@media print {
  .noPrint {
    display: none;
  }
  .onlyPrint {
    display: inline;
  }
  p,
  ol {
    font-size: 12pt;
  }
  h3, h4 {
    font-size: 13pt;
  }
  h2 {
    font-size: 14pt;
  }
  h1 {
    font-size: 16pt;
  }
  .giallo {
    border: 3px solid black;
  }
  .giallo-l {
    font-size: 11pt;
  }
  a {
    color: black !important;
  }
}
```

그의 설명은 이렇다.
`onlyPrint` 클래스는 인쇄물에만 나타나는 요소에 붙이며, 지금은 부제목에 저자
표기를 넣는 데 쓴다.
`noPrint`는 인쇄물에서 뺄 요소에 붙이며, 머리글이 인쇄하면 정말 흉해서 거기에
붙였다.
글자 크기는 화면의 가변 크기 글자가 종이에서는 이상해 보이므로 12pt로 맞추고
제목은 조금 더 크게 했다.
`giallo`는 코드 블록 조정이며, 코드 블록이 한 덩어리로 나오려 하고 쪽 경계에서
나뉘지 않아 여전히 가장 보기 흉하다고 그는 쓴다.
파란 링크는 화면에서는 좋지만 흑백에서는 보기 흉하므로 본문과 같은 색으로
바꿨다.

끝으로 그는 이 작업이 오전 한나절을 썼고 자기 사이트는 복잡하지 않은데도
그랬다고 털어놓는다.
인쇄하는 사람이 얼마나 되는지도 의심스럽고 자기 혼자일 수도 있다고 쓴다.
그래도 사이트가 글뿐이라면 독자가 선호하는 매체로 읽게 해 주는 것은 나쁠 게
없다고 하며, 좋은 소프트웨어로 가는 길은 소프트웨어 엔지니어가 사용자에게 베푸는
친절로 포장되어 있다는 문장으로 맺는다.
글 중간과 끝에는 10월 26일자 수정 메모가 있다.
Lobste.rs와 HN에서 받은 피드백으로 CSS를 단순화하는 중이라고 하고, 글이 두 사이트의 첫 화면에 올랐다는 사실을 친구가 알려 줬다고 쓴다.

## 분석

### 글의 논거는 편익이 아니라 친절이다

글은 인쇄가 왜 필요한지를 통계나 사례로 증명하지 않는다.
저자는 자기 습관에서 출발하고, 인쇄하는 사람이 자기뿐일 수도 있다고 인정한다.
논거는 비용 대비 효용이 아니라 글만 있는 사이트라면 독자가 선호하는 매체로 읽게
해 주는 것이 친절이라는 태도다.

이런 구조의 글은 반박하기도 어렵고 설득하기도 어렵다.
인쇄가 우선순위가 낮다는 반론은 비용의 언어로 말하고, 글은 윤리의 언어로 말하기
때문이다.
그래서 댓글의 논쟁이 서로 어긋나게 진행된 것은 자연스럽다.

### 해법은 작아야 한다는 것이 이 글이 남긴 실용적 메시지다

스니펫은 길지 않다.
숨기고, 글자 크기를 정하고, 링크 색을 바꾸는 세 가지가 핵심이다.
저자는 이 정도에도 한나절이 걸렸다고 말한다.
이는 인쇄 스타일이 쉬운 작업이 아니라는 뜻이 아니라, 무엇을 할지 모르는 상태에서
시행착오에 쓴 시간이라는 뜻으로 읽힌다.
이는 이 문서의 해석이다.

그의 수정 메모가 이를 뒷받침한다.
피드백을 받고 스타일시트를 가능한 한 단순하게 줄이는 중이라고 했으므로, 처음
올린 스니펫이 이미 과했다는 것을 본인이 인정한 셈이다.

### 인쇄는 PDF로 저장하는 일을 포함한다

HN 댓글 곳곳에서 인쇄는 종이만이 아니라 PDF 저장을 뜻했다.
이 글도 인쇄 선택자 하나로 종이와 PDF 양쪽에 같은 결과를 준다는 점에서 이 범위를
암묵적으로 포함한다.
인쇄 스타일의 수요를 종이로만 세면 실제보다 작게 보인다는 것이 이 지점에서
나온다.

## 비평

### 글이 보여 주는 CSS는 화면 쪽의 결함을 가리지 못했다

글이 올라오자 가장 먼저 지적된 것은 인쇄가 아니라 화면이었다.
Lobste.rs의 chrismorgan은 `code`에 배경색 `#1e1e1e`를 주면서 글자색을 지정하지 않으면 안 된다고 짚었다.
대부분이 접하는 라이트 모드에서 인라인 코드가 거의 검은 바탕에 검은 글씨로
나오는데, 저자가 이를 놓친 것이 이해되지 않는다는 것이다.[^chrismorgan]
HN의 Good4boothee도 같은 증상을 알렸다.[^Good4boothee]
저자 bputh는 라이트 모드를 추가한 뒤 거의 시험하지 않았다고 인정했다.[^bputh]

인쇄가 중요하다는 글이 정작 화면의 가장 기본적인 가독성에서 흔들린 것은 논증의
신뢰도에 영향을 준다.
글이 말하는 친절이 사용자의 환경을 시험하는 습관에서 나온다면, 가장 흔한 환경인
라이트 모드를 시험하지 않았다는 것은 그 습관이 아직 없다는 뜻이다.
인쇄 스타일의 수요를 논하기 전에 이 확인이 먼저 있어야 했다.

### 인쇄 스타일은 되도록 쓰지 않는 쪽이 기본이라는 반론을 다루지 않는다

chrismorgan은 인쇄용 스타일시트를 되도록 쓰지 않는 것이 기본 원칙이어야 한다고
썼다.
대개 별도 스타일 없이도 그럭저럭 출력되고, 잘못 손대면 오히려 망치기 쉽다는
이유다.
`onlyPrint`는 `noPrint`로 지운 정보를 보충할 뿐이어서 거의 정당화되기 어렵고,
스타일시트를 쓰지 않는 소비자에서는 정보가 중복될 수 있다고도
했다.[^chrismorgan]
이 반론은 저자가 만든 두 클래스를 정면으로 겨냥한다.

HN의 beej71은 같은 방향에서 인쇄용 글꼴과 글자 크기를 바꾸는 데 동의하지 못했다.
사용자는 자기 환경의 기본 글자 크기를 정해 두었고, 사이트가 다시 키우면 이중으로
커질 수 있다는 것이다.[^beej71]
kccqzy는 브라우저가 글자 크기 설정을 기억하므로 사용자가 직접 조정하는 것이
맞다고 맞섰고,[^kccqzy] cycomachead는 기본값이 좋아야 하며 설정 변경을
요구해서는 안 된다고 했다.[^cycomachead]
저자의 12pt는 이 논쟁의 한가운데에 있는 선택인데, 글은 이 논쟁이 있다는 것을
다루지 않는다.

### 링크가 인쇄물에서 죽는 문제를 놓쳤다

흑백 인쇄에서 링크 색이 흐려진다는 문제를 풀려고 링크를 검은색으로 바꾸면 링크가
링크로 보이지 않는다.
JulianSildenLanglo는 자기 사이트의 인쇄 미리보기에서 모든 링크가 죽어 있는 것을
보고, 해법으로 주소를 옆에 두는 방법, 숨겨 두었다가 인쇄 때만 보이게 하는 방법,
각주 번호와 끝 목록을 쓰는 방법을 꼽았다.[^JulianSildenLanglo]
저자는 PDF에서 링크가 작동하지 않을 수 있다는 점을 생각하지 못했다고
답했다.[^bputh]
vbernat은 이 중 각주 방식이 주소를 링크 뒤에 붙이는 CSS 요령보다 낫다고 보고
자기 사이트에 적용했다.[^vbernat]

저자의 해법은 색을 지우는 방향이고, 댓글의 해법은 정보를 옮기는 방향이다.
종이에서 링크의 가치는 누를 수 있다는 데 있지 않고 어디로 가는지 알려 주는 데
있다.
이 구분은 글이 가장 먼저 다뤘어야 했다.

## 인사이트

### 인쇄 가능성은 수요가 아니라 시스템 구조가 결정한다

nkrisc는 차량 매물 사이트에서 일할 때 사용자가 매물 페이지를 인쇄해 부엌
식탁에서 비교한다는 이야기를 계속 들었는데, 새로 개편한 React 페이지가 엉망으로
인쇄되어도 우선순위가 낮아 UX 디자이너와 개발자가 짝을 지어 직접 고쳐야 했다고
썼다.[^nkrisc]
저자는 인쇄하는 사람이 자기뿐일 수도 있다고 했지만, 이 증언은 수요가 있어도
조직의 우선순위 구조에서 밀린다는 것을 보여 준다.

여기서 이차 효과가 생긴다.
인쇄할 수 있는지는 사이트의 만든 방식에 크게 좌우된다.
Lobste.rs의 ryan-duve는 동적 DOM 대신 순수 HTML로 만든 취미 요리 사이트가 우연히 인쇄가 잘 되고, 열 살 아이가 화면 없이 부엌에서 따라 할 수 있어 가치가 크다고 썼다.[^ryan-duve]
HN의 adrian_b는 자바스크립트의 과용 때문에 저장 기능이 쓸모없어져 인쇄가 사실상
유일한 저장 수단이 되었다고 짚었다.[^adrian_b]
따라서 인쇄 가능성은 별도의 기능이라기보다 문서 구조를 유지하고 있다는 증상이다.
이는 이 문서의 해석이다.

### 인쇄 스타일은 사용자 요구가 아니라 기록 요구의 대리 지표다

HN의 dofm은 처음부터 인쇄할 수 있게 만들면 사용자가 PDF 다운로드를 요구하는 일이
대개 사라지고, 사용자는 대체로 인쇄가 되는 것만으로도 기적으로 여기므로 쪽
나눔이 어긋나는 정도의 문제는 용서한다고 썼다.[^dofm]
바꿔 말하면 인쇄가 필요한 순간은 영수증, 약관, 분쟁 가능성이 있는 문서처럼
기록이 필요한 때다.

이 용도는 종이를 읽는 취향과 구분된다.
저자는 읽기 취향에서 출발했지만, 댓글은 기록과 증빙이라는 용도를 보여 준다.
기록이 목적이면 인쇄의 품질 기준은 보기 좋음이 아니라 빠짐없이 나오는지다.
이 관점에서는 저자의 12pt와 검은 링크보다 쪽 나눔과 링크 주소 보존이 중요하다.

### 표준이 오래 미완이면 해법은 폴리필과 요령으로 흩어진다

lopsotronic은 CSS 인쇄용 쪽 매체 사양이 20년 가까이 초안 상태라고 짚으며, 이
사양이 브라우저에 들어가는 순간 PDF 생태계가 사라질 것이라고 썼다.[^lopsotronic]
swiftcoder는 이 글의 사이트를 맥 Safari와 Chrome에서 인쇄하니 쪽이 네 장으로
나뉘며 스크린샷이 둘째 쪽으로 밀려난다고 보고했고, 쪽 나눔 해석이 브라우저마다
다르다고 했다.[^swiftcoder]
저자가 코드 블록이 쪽 경계에서 나뉘지 않는다고 호소한 것도 같은 구조에서 나온다.

이 상황은 오래 미완이던 표준 주변에 개인의 요령이 쌓이는 낯익은 패턴이다.
요령은 브라우저에 따라 다르게 작동하므로 시험 비용이 따라붙고, 그 비용이 인쇄
스타일이 항상 우선순위에서 밀리는 이유를 보강한다.
인쇄 가능한 웹은 표준이 완성되기 전까지 개별 사이트의 시험 습관에 의존한다.
이는 이 문서의 해석이다.

### 독자가 직접 고치는 길도 있다

GeekNews의 xguru는 GeekNews의 토픽, 아티클, 위클리가 인쇄용 스타일을 지원한다고
알렸다.
메뉴와 입력창을 빼고 문서 형태로 출력하며, 상단에 글 정보와 원문으로 가는 QR
코드를 넣고, 본문 링크는 번호를 붙인 참고 링크로 정리해 URL과 QR 코드를 각주에
제공한다고 한다.
댓글과 참고 링크는 각각 새 페이지에서 시작해 필요한 구간만 골라 인쇄할 수 있다는
설명도 있다.[^xguru]
이 설명은 앞서 댓글들이 제기한 링크 문제에 대한 구체적인 해법의 한 사례다.
unsure4000은 이 기능의 소스 공유 계획을 물었고,[^unsure4000] humblebee는 접근성
면에서 유용해 보인다고 했다.[^humblebee]

### 이 글을 읽는 방법

이 글은 사실의 주장이 아니라 취향과 태도의 표명이어서 반증이 아니라 조건을 달아
읽는 것이 맞다.
인쇄 스타일이 가치가 있는 곳은 기록이 필요한 문서나 글 중심 사이트이고, 그렇지
않은 곳은 마케팅 페이지처럼 화면 경험이 본질인 사이트다.
판단을 가를 관찰은 둘이다.
하나는 사이트의 접속 기록에서 인쇄 이벤트가 얼마나 일어나는지이고, 다른 하나는
인쇄 스타일을 넣은 뒤 쪽 나눔과 링크 정보가 브라우저별로 유지되는지다.
이 문서는 둘 다 확인하지 못했다.
