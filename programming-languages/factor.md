# Factor 개요: 스택, word, quotation으로 읽는 연결형 언어

원문: [Factor Overview – Re: Factor](https://re.factorcode.org/2026/10/factor-overview.html)

HN 토론: <https://news.ycombinator.com/item?id=49968522> (4점, 0개 댓글)

GN 토론: <https://news.hada.io/topic?id=34902>

## 소개

Re: Factor 블로그가 2026년 10월 4일에 올린 Factor 언어 개요다.
공식 안내서(guided tour)가 언어와 라이브러리를 소개한다면, 이 글은 일상적인 문법, 제어 흐름, combinator, 주요 라이브러리를 코드 중심으로 보여 주는 것을 목표로 한다.
프로그래밍 경험은 있지만 스택 기반 언어는 처음 쓰는 독자를 상정한다.

글의 순서는 이렇다.
Hello, world와 실행 방법에서 시작해 값과 스택, 리터럴, 스택 섞기, word 정의, 산술, quotation, 조건문을 다룬다.
이어서 combinator(`dip`, `keep`, `bi` 계열, `curry`, `fry`), 반복과 재귀, 지역 변수, 시퀀스, 해시테이블과 집합, 튜플, 구조체, 제네릭 word, 믹스인과 싱글턴, 동적 변수, 오류 처리, 메타프로그래밍, 메모이제이션이 나온다.
끝부분은 파일, JSON, 정규식, HTTP, 날짜, 난수, 스레드, C 호출, 테스트와 탐색 도구다.
글의 조언은 앞의 몇 절(스택, word 정의, quotation, 제어 흐름, 시퀀스)을 먼저 익히고 나머지는 필요할 때 돌아오라는 것이다.

이 문서는 글의 전부를 옮기지 않고, 처음 읽는 사람이 Factor 코드를 읽는 데 필요한 구조를 정리한다.
이 환경에는 Factor가 설치돼 있지 않아서, 아래 코드는 원문의 설명과 규칙을 바탕으로 쓴 것이고 직접 실행해 보지는 못했다.

## 동작 방식

### 값은 스택에 쌓이고 word가 소비한다

Factor의 리터럴은 값을 데이터 스택에 올리고, word는 스택 위의 입력을 꺼내 쓰고 출력을 올린다.
코드는 왼쪽에서 오른쪽으로 실행된다.
`2 3 + 4 * .`은 2와 3을 더하고 4를 곱해 20을 출력한다.
`.`은 객체 하나를 소비해 출력하고, `print`는 문자열 하나를 소비해 출력한다.
함수 인자 주위에 괄호가 없다는 점이 가장 먼저 낯선 부분이다.
인자를 먼저 스택에 올리고 그다음에 word를 부른다.

공백이 문법을 이룬다.
`2 3 +`는 토큰 세 개이고 `2+3`은 토큰 하나라서 그 이름의 word가 있어야 한다.
`number>string`, `empty?`, `set-at`은 모두 평범한 word 이름이다.
끝의 `?`는 관례상 술어를 뜻하고, `>`는 변환 이름에 자주 나오며, 끝의 `!`는 값을 바꾸는 변형(`append!`)을, `*`는 다른 형태를 뜻하는 경우가 많다.
이 문자들은 연산자가 아니라 이름의 일부다.

### 스택 효과는 문서이자 검사 대상이다

word는 `:`로 시작해 `;`로 끝낸다.
정의 옆의 `( 입력 -- 출력 )`이 스택 효과다.
이름은 값을 설명할 뿐 변수를 묶거나 타입을 정하지 않는다.
글에 따르면 컴파일러가 스택 효과를 검사하며, 분기마다 효과가 맞는지도 본다.
명시적 `return`은 없고 word가 끝나면 실행이 끝난다.
값이 여러 개 나오는 word는 그냥 스택에 여러 값을 남긴다.

```factor
USING: kernel math prettyprint ;
IN: scratchpad

: square ( n -- n-squared ) dup * ;
: neighbors ( n -- below above ) dup 1 - swap 1 + ;

5 square .          ! 25
5 neighbors . .     ! 6, 그다음 4
```

스택 섞기(stack shuffling) word로 `dup`, `drop`, `swap`, `over`, `nip`, `rot`이 있다.
글은 대부분의 Factor 코드가 짧은 정의와 combinator로 명시적인 섞기를 줄인다고 말한다.

### quotation과 combinator

대괄호로 묶은 `[ 1 + ]`는 quotation이고, 실행 가능한 코드를 값으로 든 것이다.
`call`이 quotation을 실행한다.
quotation을 입력으로 받는 word를 combinator라고 부른다.
`if`는 조건 하나와 quotation 둘을 소비해, 조건이 참이면 첫 quotation을, `f`이면 두 번째를 부른다.
논리값에서는 오직 `f`만 거짓이다.
0, 빈 문자열, 빈 배열은 모두 참이다.

글은 값을 숨기거나 보존하는 `dip`과 `keep`, 여러 quotation을 한 입력이나 여러 입력에 적용하는 `bi` 계열을 소개한다.

```factor
USING: kernel math prettyprint ;

10 20 [ 2 * ] dip + .           ! 40: 10만 두 배로 하고 20을 되돌려 더한다
5 [ 1 + ] [ 2 * ] bi . .        ! 10, 그다음 6: 같은 입력에 quotation 둘을 적용한다
3 4 [ 2 * ] bi@ . .             ! 8, 그다음 6: 입력마다 같은 quotation을 적용한다
```

`curry`는 값을 quotation 앞에 묶고, `compose`는 두 quotation을 이어 붙인다.
`fry` 어휘가 제공하는 `'[ _ + ]` 같은 템플릿은 `_` 자리에 값을 넣는다.
글은 combinator를 직접 만들 때 입력 quotation에 스택 효과를 달고 `inline`으로 선언해야 컴파일러가 호출 지점에서 효과를 추론한다고 설명한다.

### 지역 변수, 시퀀스, 객체

이름이 알고리즘을 읽기 쉽게 만들 때는 `locals`를 불러 `::`로 word를 정의한다.
입력이 어휘적 변수가 되고, `:>`는 계산한 값에 이름을 묶는다.
시퀀스(배열, 벡터, 문자열 등)는 공통 프로토콜을 공유해 `map`, `filter`, `reduce`가 모두에 통한다.
`make`와 `,`, `%`로 값을 모으면서 시퀀스를 만들 수 있다.

튜플(`TUPLE:`)은 이름 있는 슬롯이 있는 클래스다.
`C:`는 `boa`로 생성자를 정의하고, `name>>`은 슬롯을 읽고 `>>age`는 슬롯을 쓰면서 튜플을 돌려줘 연쇄 갱신이 된다.
제네릭 word는 맨 위 입력의 클래스로 메서드를 고른다(`GENERIC:`, `M:`).
믹스인(`MIXIN:`, `INSTANCE:`)은 서로 무관한 타입을 묶는 열린 집합이고, 싱글턴은 상태 없는 유일한 인스턴스다.
구조체(`STRUCT:`)는 C 메모리 배치를 따르는 레코드이며, 일반적인 Factor 레코드에는 튜플을, C 호환 메모리가 필요할 때 구조체를 쓰라고 글은 정리한다.

## 확인하기

글은 모든 예제를 리스너(listener), 곧 대화형 REPL에서 돌려 보라고 권한다.
터미널 리스너는 `./factor -run=listener`로 시작한다.
`IN: scratchpad`는 실험용 정의를 리스너의 작업 어휘에 둔다.
한 줄 실행은 `./factor -e="\"Hello, world!\" print"`로, 파일은 `./factor hello.factor`로 실행한다.

```factor
USING: io ;
IN: hello

: main ( -- )
    "Hello, world!" print ;

MAIN: main
```

`hello.factor`에 위를 저장하고 `./factor hello.factor`를 실행하면 `Hello, world!`가 출력된다고 글은 설명한다.
어휘 검색 경로에 있으면 `./factor -run=hello`로도 실행한다.

테스트는 `tools.test`로 쓴다.
기대하는 스택 결과를 배열로 적는다.

```factor
USING: kernel math tools.test ;

{ 5 } [ 2 3 + ] unit-test
{ 25 } [ 5 dup * ] unit-test
[ 1 0 / ] must-fail
```

개발 환경에서는 `\ map help`로 문서를 열고, `\ square see`로 정의를 보고, `[ 1000000 [ ] times ] time`으로 시간을 잰다.
글은 이런 탐색 도구가 Factor의 학습 흐름의 일부라고 소개한다.

## 함정

- 공백을 빼먹으면 토큰이 합쳐진다.
  `2+3`은 덧셈이 아니라 하나의 이름이다.
- 리터럴 컬렉션을 word 안에서 바꿀 때는 `clone`으로 복사본을 만든 뒤 바꿔야 한다.
  공유된 리터럴을 직접 바꾸면 안 된다.
  `clone`은 얕은 복사라서 안의 객체는 여전히 공유된다.
- 해시테이블의 `at`은 없는 키와 값이 `f`인 키를 구분하지 못한다.
  구분하려면 존재 여부를 함께 돌려주는 `at*`를 쓴다.
- 문자열의 길이는 보이는 글자 수가 아니라 코드 포인트의 수다.
- 스레드는 협력적으로 스케줄되고, 새 스레드는 빈 데이터 스택으로 시작한다.
  입력은 `curry`로 quotation에 직접 실어 보내야 한다.
- 메모이제이션(`MEMO:`)은 순수 계산에 맞는다.
  캐시된 가변 결과는 공유 객체라서 호출자가 바꾸면 문제가 된다.
- 외부 C 메모리(FFI)는 수명을 직접 관리해야 할 수 있다.

## 체크리스트

- 모르는 word를 만나면 스택 효과를 먼저 읽고 스택에 무엇이 남는지 따라가는가.
- 스택 섞기가 세 단계를 넘어가면 combinator나 지역 변수로 바꿀 수 있는지 보는가.
- quotation을 받는 word를 직접 정의할 때 입력 quotation에 스택 효과를 달고 `inline`으로 선언했는가.
- 논리 판단에서 0과 빈 컬렉션이 참이라는 점을 확인했는가.
- 해시테이블 조회에서 값이 `f`일 수 있으면 `at*`를 쓰는가.
- 공유될 수 있는 리터럴을 바꾸기 전에 `clone`했는가.

## 기억할 원칙

### 스택 효과를 먼저 읽는다

이 언어에서 가장 믿을 만한 정보는 word 옆의 스택 효과다.
이름이 낯설어도 효과를 보면 무엇을 소비하고 무엇을 남기는지 알 수 있다.
코드를 읽을 때 변수의 이름을 따라가는 대신, 스택 한 줄을 머릿속에 그리며 따라가는 습관이 이 언어의 읽기다.

### 명시적인 섞기보다 짧은 정의와 combinator로 쓴다

글이 반복해서 말하는 요령은 정의를 짧게 쪼개고, `dip`, `keep`, `bi`처럼 값의 흐름을 이름으로 드러내는 word를 쓰는 것이다.
스택이 길어지면 지역 변수를 쓰면 되므로, 스택만으로 모든 것을 해결해야 한다는 압박은 필요 없다.
