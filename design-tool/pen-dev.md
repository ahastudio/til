## 소개

pen.dev는 스스로를 대담한 아이디어를 만드는 에이전트 캔버스(an agentic canvas
for building bold ideas)라고 부르는 디자인 도구다.
웹사이트, 모바일 앱, 소셜과 마케팅 그래픽을 캔버스 위에서 에이전트와 함께
설계하고 손으로 다듬는다고 소개한다.
이전 이름은 Pencil이었고, 홈페이지에는 pencil.dev가 이제 pen.dev라는
문구가 있다.
HN에는 2025년 9월 30일에 Cursor용 디자인 모드로 올라온 글이 있고,
2026년 9월 17일에는 Pen.dev라는 제목의 글이 올라왔다.
이 문서는 이름이 바뀐 정확한 날짜를 확인하지 못했다.

회사는 High Agency Inc.이고, 푸터에 a16z speedrun의 후원을 받는다고 적혀 있다.
문서 사이트의 첫 화면은 2026년 10월 13일에 마지막으로 고쳐졌다고
표시한다.[^pen-docs]
이 문서는 홈페이지, 문서 사이트의 몇 페이지, 가격 페이지를 읽고 썼으며,
도구를 직접 설치해 써 보지는 못했다.

이 문서가 pen.dev를 따로 다루는 이유는 `design-tool/open-pencil.md`가 그린 차세대
캔버스 구도에서 pen.dev만 소스 공개를 밝히지 않은 상용 도구이기 때문이다.
오픈소스인지, 무료인지, 유료인지, 비싼지의 질문이 이 구도에서 가장 날카롭게
갈리는 지점이 pen.dev다.

## 제품 구성

홈페이지는 에이전트가 캔버스에서 직접 디자인하고 사람이 손으로
다듬는다고 설명한다.
기존 웹사이트와 앱을 편집 가능한 레이어로 가져오는 길이 셋이고, 내장 브라우저,
Chrome 확장, HTML 가져오기다.
도구는 펜, 이미지 벡터화, 배경 제거, 컴포넌트, 변수, 그라디언트, 셰이더, 마스킹,
flex 레이아웃, 슬라이드를 갖추고, 내보내기는 PNG, JPEG, WEBP, PDF,
HTML과 CSS와 Tailwind다.
홈페이지는 맞춤 WebGL 파이프라인 덕분에 수천 개의 레이어에서도 이동과 확대와
편집이 부드럽다고 밝히지만, 수치와 측정은 싣지 않는다.
공유는 링크로 하고, 헤드리스 CLI도 있다.
Figma와 Sketch에서 익힌 단축키가 같게 동작한다고 하고,
Figma의 `.fig` 파일을 레이아웃과 스타일과 이미지와 함께 가져온다고 한다.

문서 사이트는 시작하기(설치, 인증, AI 연동, 첫 디자인), 핵심 개념 15가지,
디자인과 코드, 문제 해결, 개발자용 두 항목(`.pen` 형식,
CLI)으로 이루어진다.[^pen-docs]
핵심 개념에는 `.pen` 파일, 코드로서의 디자인, 에이전트와 스킬, 변수, 컴포넌트,
슬롯, 캔버스 위의 코드, 디자인 라이브러리, 소규모 디자인 시스템 만들기,
가져오기와 내보내기, 공유, 슬라이드가 있다.[^pen-docs]
사용 방식은 IDE 안에서 쓰는 것, 독립 데스크톱 앱,
헤드리스 CLI의 셋이다.[^pen-docs]
Cursor와 VS Code용 확장이 있고 OpenVSX에도 올라 있다고 홈페이지가 밝힌다.

### `.pen` 형식은 에이전트가 읽는 JSON 트리다

`.pen` 파일은 HTML이나 SVG처럼 객체 트리를 기술하는 JSON이고 주석도
허용한다.[^pen-format]
모든 객체에 고유한 `id`와 `type`이 있으며 무한한 2D 캔버스 위에 놓이고,
자식의 위치는 부모에 상대적이다.[^pen-format]
레이아웃은 `layout`, `justifyContent`, `alignItems` 같은 flexbox 방식이고,
채움은 색, 그라디언트, 이미지, 셰이더, 메시 그라디언트를 쓸 수
있다.[^pen-format]
노드 종류는 `rectangle`, `ellipse`, `polygon`, `path`, `frame`, `group`, `text`,
`note`, `prompt`, `context`, `icon`, 그리고 `script`(자바스크립트로 자식을
생성), `browser`(실제 웹페이지), `ref`(컴포넌트 인스턴스)다.[^pen-format]
`prompt`와 `context`가 노드 종류에 들어 있다는 점이 눈에 띄며,
디자인 문서 안에 에이전트에게 주는 지시와 맥락이 데이터로 함께 저장된다는
뜻으로 읽힌다.
`reusable: true`가 컴포넌트이고 `ref`가 인스턴스이며,
최상위 `variables`와 `themes`가 디자인 토큰과 테마 축을 담는다.[^pen-format]

스키마는 문서의 `version` 필드로 식별하고 현재 `"2.21"`이다.[^pen-format]
문서는 스스로를 살아 있는 문서라고 부르며 형식을 깨는 변경의 권리를 남겨
둔다.[^pen-format]
오래된 형식은 열 때 변환되고 저장하면 변환된 형식으로 써지므로 다른 버전으로
열기 전에 원본을 보관하라고 한다.[^pen-format]
직렬화된 ID와 참조를 손으로 고치지 말고 pen.dev나 MCP 도구,
CLI의 대화형 모드로 고치라고 권한다.[^pen-format]

### AI 연동은 내장 에이전트와 외부 MCP 클라이언트 두 갈래다

내장 에이전트는 데스크톱 앱에서 `.pen` 문서를 열고 모델을 고른 뒤 에이전트
작성기에 요청하는 방식이다.[^pen-ai]
외부 MCP 클라이언트는 실행 중인 데스크톱 앱이나 IDE 호스트에 붙으며,
문서는 Claude Code, ChatGPT, Codex 설정을 소개한다.[^pen-ai]
연결 순서는 앱이나 IDE 확장을 설치하고 `.pen` 파일을 열고 설정의 MCP에서
클라이언트를 켠 뒤 클라이언트를 다시 시작해 MCP 서버 목록에 `pencil`이 보이는지
확인하는 것이다.[^pen-ai]
서버 이름이 아직 `pencil`로 남아 있다는 점이 이름 변경의 흔적이다.
외부 클라이언트는 stdio로 MCP 서버와 통신하고,
서버는 macOS와 Linux에서는 유닉스 소켓,
Windows에서는 명명된 파이프로 실행 중인 앱에 닿는다.[^pen-ai]

MCP 도구는 `get_style`, `read_skill`, `get_app_state`, `execute`가 표준이고,
`browser`는 서버가 데스크톱 앱을 대상으로 할 때만,
`spawn_agents`는 `-enable_spawn_agents`로 시작했을 때만 있다.[^pen-ai]
도구가 여섯 개뿐이라는 점이 open-pencil의 100개가 넘는 도구와 대비된다.
`execute` 하나가 `.pen` 문서를 조작하는 스크립트 실행 통로일 가능성이 있지만,
이 문서는 그 내용을 확인하지 못했다.
문서는 홈페이지가 말하는 WebMCP를 AI 연동 페이지에서 다루지 않는다.[^pen-ai]

### CLI와 인증은 계정 중심이다

CLI는 `npm install -g @pen.dev/cli`로 설치하고 Node.js 22.19 이상이 필요하며,
데스크톱 앱과 같은 편집 엔진을 GUI 없이 돌린다고 한다.[^pen-cli]
`pen`은 프롬프트로 에이전트를 돌려 `.pen` 파일을 고치고 PNG, JPEG, WEBP,
PDF로 내보내며, `pen interactive`는 `execute`와 `get_app_state` 같은 MCP 도구를
직접 부르는 셸이다.[^pen-cli]
CI에서는 `PEN_CLI_KEY`와 에이전트 API 키를 환경 변수로 주고,
CLI 키는 조직 단위이며 웹앱의 개발자 키 메뉴에서 만든다.[^pen-cli]

인증 페이지에 따르면 이메일 코드나 비밀번호로 로그인하고,
데스크톱 모델 선택기의 pen.dev Pro로 표시된 모델이 계정을 쓰고,
CLI는 `pen login`과 `pen status`를 쓴다.[^pen-auth]
설정의 에이전트 메뉴에서 OpenAI, Anthropic, Google Gemini,
GitHub Copilot 같은 공급자를 API 키나 기존 CLI 설정이나 구독 로그인으로
연결하며, 사용자 정의 엔드포인트는 데스크톱에서만 된다.[^pen-auth]
이 페이지는 키가 어디에 저장되고 어떻게 전송되는지,
pen.dev 서버로 가는 데이터가 무엇인지, 오프라인에서 쓸 수 있는지를 적지
않는다.[^pen-auth]

## 가격과 한도

가격 페이지는 네 단계다.[^pen-pricing]

| 항목                          | Free   | Pro             | Ultra           | Enterprise     |
| ----------------------------- | ------ | --------------- | --------------- | -------------- |
| 가격                          | $0     | 사용자당 월 $16 | 사용자당 월 $48 | 협의           |
| 디자인하는 동안 MCP 도구 호출 | 무제한 | 무제한          | 무제한          | 무제한         |
| 이미지와 SVG 생성(월)         | 25     | 350             | 750             | 적혀 있지 않음 |
| 에이전트와 디자인하는 날(월)  | 5일    | 매일            | 매일            | 적혀 있지 않음 |
| 병렬 에이전트                 | 1      | 최대 3          | 최대 6          | 적혀 있지 않음 |

무료 단계에는 로컬 우선 편집기와 로컬 `.pen` 파일, 컴포넌트, 변수, 테마,
스크립트, 셰이더, HTML과 코드 가져오기와 내보내기, CLI와 헤드리스 편집기,
Unsplash 이미지, 공유와 스냅숏과 버전과 댓글, 개인과 공유 작업 공간,
개인 개발자 키가 들어 있다.[^pen-pricing]
호스팅 모델(MiniMax, GLM, Qwen, DeepSeek)은 별도 구독이나 API 키 없이 쓸 수
있고, 무료는 제한된 사용량, Pro는 포함된 모델 크레딧,
Ultra는 더 많은 크레딧이다.[^pen-pricing]
모든 요금제에서 자기 에이전트 구독이나 API 키(Claude Code, Codex,
Cursor 등)를 연결할 수 있다.[^pen-pricing]
다만 이 경우에도 에이전트와 디자인하는 날은 요금제 한도에 계속 계산되고,
공급자의 청구와 한도도 따로 적용되며, 포함된 모델 크레딧은 쓰지
않는다.[^pen-pricing]
Anthropic이 서드파티 도구에서의 구독 사용을 막았다는 공지는
`claude/third-party-subscription-block.md`가 다룬다.
자기 구독을 연결하는 경로 가운데 어느 것이 그 범위에 걸리는지는 이 문서가
확인하지 못했다.
Pro는 조직 개발자 키, 구성원과 역할 관리, 중앙 청구, 사용량 추적을 더하고,
Ultra는 팀 전체의 공유 사용량 풀과 구성원 역할이 있는 팀 작업 공간을
더한다.[^pen-pricing]
월간과 연간 전환이 있고 연간은 20% 할인이라고 하지만,
표시된 가격이 어느 쪽 기준인지는 페이지에서 확인하지 못했다.[^pen-pricing]

### 무료의 의미가 네 가지로 갈린다

pen.dev의 무료는 하나가 아니다.
첫째, 편집기와 `.pen` 파일, CLI는 무료 단계에서 제한 없이 쓸 수 있다.
둘째, MCP 도구 호출은 모든 단계에서 무제한이다.
셋째, 에이전트로 디자인하는 날은 무료 단계에서 월 5일로 막힌다.
넷째, 자기 키를 가져와도 이 날수 한도가 풀리지 않는다.
이 문서의 해석으로는 가격 장벽이 편집기가 아니라 에이전트가 일하는 날에 놓여
있고, 자기 모델 비용을 직접 내는 사용자에게도 같은 장벽이 적용된다.
이는 같은 쪽의 오픈소스 도구들과 갈리는 지점이다.
open-pencil과 ZSeven의 README와 문서에는 에이전트 사용 일수 한도가
적혀 있지 않다.

## 오픈소스인가

문서에서 확인한 범위에서 pen.dev는 앱, CLI, 스키마의 라이선스를 밝히지 않는다.
`.pen` 형식 문서는 라이선스나 오픈소스 상태를 적지 않았고,[^pen-format] CLI
문서도 마찬가지다.[^pen-cli]
홈페이지의 오픈소스 관련 문구는 `.pen` 스키마를 완전히 공개했다는 것뿐이다.
스키마 공개와 도구의 소스 공개는 다른 문제이고,
형식을 깨는 변경의 권리를 남겨 둔 문서의 태도는 형식이 도구의 사정에 따라 움직일
수 있다는 뜻이다.
오픈소스 여부가 필수 조건이라면 이 문서가 확인한 근거로는 pen.dev는
해당되지 않는다.

반면 형식의 공개는 실제 효과를 낸다.
open-pencil은 지원되는 `.pen` 문서를 열고 로드맵은 `.pen`을 편집하고 저장하는
형식으로 만들겠다고 적으며, ZSeven은 `.pen`에서 UIKit를 가져오고 내보낸다.
상용 도구의 형식이 오픈소스 쪽의 가져오기 대상이 되는 모양이다.
이 모양은 pen.dev에게도 이익이 될 수 있다.
형식이 다른 도구에서도 읽힐수록 `.pen`이 사실상의 교환 형식으로 자리를 잡고,
수익은 에이전트 사용에서 얻기 때문이다.
다만 이 해석을 뒷받침하는 pen.dev 쪽의 직접 진술은 없다.

## 사각 구도 속 자리

네 도구와 기준선(Figma)을 돈과 개방성의 축으로 나란히 놓으면 pen.dev의
위치가 보인다.
전체 비교표는 `design-tool/open-pencil.md`의 「돈과 라이선스가 갈리는 지점」에 있다.
pen.dev는 Figma의 가격(Professional 전체 좌석 월 $16)과 같은 값의 Pro를
내놓으면서 MCP 도구 호출을 무제한으로 풀고, `.fig`를 가져오게 하고,
에이전트 병렬 수를 요금제로 판다.[^figma-pricing][^pen-pricing]
Figma의 MCP 서버는 무료 플랜에서 월 20회,
Professional에서 일 200회와 분당 10회로 제한된다는 점과
대비된다.[^figma-pricing]
Penpot은 무료 Professional과 편집자당 월 $7의 Unlimited(월 $175 상한)를 두고
서버를 직접 띄우는 길을 열어 두며,[^penpot-pricing] open-pencil과 ZSeven은 MIT
라이선스이고 요금이 없다.
이 가운데 pen.dev만 소스 공개를 밝히지 않고,
에이전트 사용 일수와 병렬도를 요금제의 축으로 삼는 것도 이 표에서는
pen.dev뿐이다.

## 분석

### 모델이 아니라 에이전트 사용에 값을 매긴다

pen.dev의 가격표에서 한도가 걸린 항목은 이미지와 SVG 생성 횟수,
에이전트와 디자인하는 날, 병렬 에이전트 수, 모델 크레딧이다.[^pen-pricing]
편집기 기능, MCP 호출, 문서 수, 파일 저장은 제한이 없다.
이 구성은 디자인 도구의 전통적인 좌석과 문서 한도 과금과 다르다.
Figma는 좌석 종류(Full, Dev, Collab)에 값을 매기고 MCP 호출을 한도로
둔다.[^figma-pricing]
pen.dev는 같은 질문, 곧 에이전트가 디자인 도구를 얼마나 쓰게 할 것인가를 반대로
풀어서, 호출은 열고 에이전트의 노동 일수와 병렬도에 값을 매긴다.
이 문서의 해석으로는 에이전트가 사용자의 대리인이라는 모델에서 과금의 단위가
사람 좌석에서 에이전트의 일로 옮겨 가는 한 사례다.

### 로컬 우선과 계정 중심이 한 제품에 같이 있다

무료 단계는 로컬 우선 편집기와 로컬 `.pen` 파일이라고 소개되지만,[^pen-pricing]
인증 페이지는 이메일 로그인과 작업 공간과 개발자 키를 전제로 하고,[^pen-auth]
데이터가 어디로 가는지 밝히지 않는다.
open-pencil은 개인정보 페이지에서 하루 한 번의 익명 신호와 네트워크 접속 목록을
항목별로 적었는데,[^os-privacy] pen.dev에는 같은 수준의 공개가 이 문서가 읽은
범위에 없다.
로컬 우선이라는 말을 쓰는 도구들 사이에서 그 말이 보증하는 범위를 비교하려면 이
항목이 필요하다.

### 형식 안정성의 약속은 약하다

`.pen`은 스키마 버전이 2.21까지 올라왔고,
문서는 형식을 깨는 변경이 있을 수 있다고 미리 밝힌다.[^pen-format]
저장하면 변환된 형식으로 써지므로 다른 버전의 앱으로 열면 되돌릴 수 없다고
경고한다.[^pen-format]
다른 도구가 `.pen`을 읽고 쓸 때 이 불안정성은 직접 비용이다.
open-pencil의 로드맵이 `.pen`을 일급 저장 대상으로 삼겠다고 적은 만큼,
스키마의 변화 속도가 오픈소스 도구들의 유지 부담이 된다.[^os-roadmap]

## 비평

### 오픈소스 구도에 포함시키는 일 자체가 도전이다

세 오픈소스 도구와 pen.dev를 같은 지도에 놓으면 pen.dev의 공개 범위가 모호하다.
스키마를 공개했다고는 하지만 도구의 소스, 라이선스, 데이터 흐름은 문서에 없다.
사용자가 오픈소스를 이유로 고르는 상황이라면 pen.dev는 비교 대상이 아니라
기준선에 가깝다.
이 문서는 pen.dev의 소스 저장소를 찾지 못했고,
몇 가지 키워드로 한 GitHub 검색에서도 확인하지 못했다.
저장소가 없다는 단정은 하지 않으며, 문서와 홈페이지가 밝히지 않았다는
범위로만 쓴다.

### 가격 표의 빈칸이 가장 중요한 질문에 걸려 있다

Pro와 Ultra의 모델 크레딧 양, Enterprise의 한도,
표시된 가격이 월간인지 연간인지는 가격 페이지에서 확인되지 않는다.[^pen-pricing]
자기 키로 연결해도 날수 한도가 계속 계산된다는 조건은 BYOK 사용자에게
가장 큰 변수다.
에이전트로 하루 종일 일하는 사용자는 무료 단계의 월 5일 한도에 곧바로 닿고,
팀이 Pro로 올라야 한다.
이 문서가 계산한 팀 비용은 이 빈칸 때문에 모델 비용을 뺀 정가 기준이다.

### 홍보 문구의 성능과 속도 주장은 수치가 없다

홈페이지는 수천 개의 레이어가 부드럽다고 쓰지만 측정 환경도 수치도 없다.
HN 스레드에서 sarelta는 Claude Code와 Figma를 함께 쓰는 것이 필요하다고 하면서 Figma MCP를 그냥 쓰는 것과 성능을 비교하면 어떻겠느냐고 물었다.[^sarelta]
이 질문에 답하는 자료는 이 문서가 읽은 범위에 없다.
jannesblobel은 모든 것이 Git에 있고 디자인이 코드 옆에 놓여 버전과 기록과 협업을
개발자 도구로 다룬다는 점이 눈에 띈다고 적었다.[^jannesblobel]
다만 이 말이 pen.dev의 문서에 있는 Git 연동 기능에 대한 서술인지 `.pen`이
JSON이라는 점에서 나온 추론인지는 구분되지 않는다.
이 문서는 pen.dev 문서에서 Git 연동 기능을 확인하지 못했다.

## 인사이트

### 오픈소스냐 무료냐 유료냐는 한 축이 아니라 네 칸의 표다

이 구도에서 도구를 고르는 사람이 묻는 질문은 서로 다른 네 가지다.
소스가 공개되어 있는가, 돈을 내지 않고 쓸 수 있는가, 돈을 낸다면 얼마인가,
그 돈이 무엇에 값을 매기는가다.
이 네 칸을 나란히 놓으면 도구마다 다른 답이 나온다.

| 도구                | 소스 공개                   | 무료로 쓸 수 있는 것                             | 돈이 들어가는 곳                            | 돈이 매겨지는 단위              |
| ------------------- | --------------------------- | ------------------------------------------------ | ------------------------------------------- | ------------------------------- |
| Figma(기준선)       | 아니오                      | Starter, MCP 월 20회                             | 좌석 월 $3~$90, AI 크레딧                   | 좌석 종류와 MCP 호출 한도       |
| Penpot              | 예(MPL-2.0)                 | Professional(구성원 8명, 저장 10GB), 셀프 호스팅 | Unlimited 편집자당 월 $7, Enterprise 월 $25 | 편집자 수, 저장 용량, 운영 항목 |
| open-pencil         | 예(MIT, Cloud만 Apache-2.0) | 전부(Cloud는 준비 중)                            | 자기 AI 공급자의 토큰                       | 모델 사용량                     |
| ZSeven-W/openpencil | 예(MIT)                     | 전부                                             | 자기 AI 공급자의 토큰                       | 모델 사용량                     |
| pen.dev             | 밝히지 않음(스키마만 공개)  | 편집기, CLI, MCP 무제한, 에이전트 월 5일         | Pro 월 $16, Ultra 월 $48                    | 에이전트 일수와 병렬도          |

표의 Figma와 pen.dev와 Penpot 칸은 각 가격 페이지의
정가이고,[^figma-pricing][^pen-pricing][^penpot-pricing] 이 문서가 결제를 시험한
것이 아니다.
오픈소스 두 도구의 모델 비용은 공급자와 모델에 따라 다르며,
`design-tool/open-pencil.md`가 정리한 호환성 표에서 가장 싼 권장 모델은 입출력 100만
토큰당 0.15~0.35유로 수준이다.[^os-byok]

### 열 명짜리 팀의 한 달 정가는 $0에서 수천 달러까지 갈린다

팀의 규모를 하나 정해 어림해 본다.
이 계산은 이 문서의 가정이며, 설계자 다섯과 개발자 다섯 모두 편집 권한이
필요하고, 모델 비용과 세금과 연간 할인을 제외한 정가라는 조건이다.

| 도구 / 요금제                 | 계산                        | 한 달 합계(USD) |
| ----------------------------- | --------------------------- | --------------- |
| Figma Professional            | Full 5명 $16 + Dev 5명 $12  | $140            |
| Figma Organization(연간 청구) | Full 5명 $55 + Dev 5명 $25  | $400            |
| Figma Enterprise(연간 청구)   | Full 5명 $90 + Dev 5명 $35  | $625            |
| pen.dev Pro                   | 10명 $16                    | $160            |
| pen.dev Ultra                 | 10명 $48                    | $480            |
| Penpot Unlimited              | 편집자 5명 $7(월 $175 상한) | $35             |
| Penpot Enterprise             | 구성원 10명 $25             | $250            |
| Penpot Private Server         | 연 $50,000                  | 약 $4,167       |
| open-pencil, ZSeven           | 라이선스 비용 없음          | $0              |

Penpot Unlimited가 편집자 수 기준이라는 점은 가격 페이지에서 단위가 정의되지
않아 개발자를 편집자로 셀지에 따라 값이 달라진다.[^penpot-pricing]
같은 정가로 Figma Professional과 pen.dev Pro는 비슷한 규모이고,
Figma는 좌석 종류로 값을 나누며 pen.dev는 모든 사용자에게 같은 값을 받는다.
이 문서의 해석으로는 라이선스 비용만 보면 오픈소스 쪽이 가장 싸고,
그 차이를 메우는 것은 운영 부담과 성숙도다.
Penpot의 Private Server는 연 $50,000로 이 표에서 가장 비싼 칸이므로 비싸냐는
질문의 답은 사용 방식에 달려 있다.

### 가장 비싼 비용은 정가가 아니라 에이전트가 일한 날수에 걸린다

가격표를 훑으면 두 가지 종류의 돈이 보인다.
사람이 앉는 좌석 비용과 에이전트가 일하는 사용량 비용이다.
pen.dev는 앞의 것을 낮추고 뒤의 것에 한도를 두며,
Figma는 좌석을 크게 나누고 MCP 호출을 막으며,
오픈소스 두 도구는 라이선스를 풀고 모델 사용량은 사용자의 공급자 청구로 넘긴다.
에이전트에게 디자인의 큰 몫을 맡기는 팀이라면 비용의 대부분이 후자에서
나올 것이다.
이 문서의 해석으로는 선택의 기준을 좌석 가격이 아니라 한 달에 에이전트가 만드는
화면의 수와 그 화면당 토큰이나 날수로 옮겨 가야 한다.

시험은 같은 과제 한 가지를 정해 네 도구에서 에이전트에게 열 번 시키고,
각각의 비용(정가 + 토큰)과 수정 횟수를 기록하는 것이다.
pen.dev에서는 무료 단계의 5일 한도가 며칠 만에 소진되는지도 함께 센다.
결과가 도구마다 갈리면 팀에서 가장 자주 하는 작업에 맞춰 고르면 된다.
이 문서는 그 비교를 하지 못했다.

### 승부는 `.pen`이 교환 형식이 되느냐에서 갈릴 수 있다

pen.dev가 오픈소스가 아니어도 `.pen`이 오픈소스 도구들에서 읽히면 pen.dev는
판을 키운다.
open-pencil이 `.pen`을 편집 가능한 저장 형식으로 삼는 날,
`.pen` 문서가 상용 도구와 무료 도구에서 모두 편집되는 첫 형식이 된다.
이때 pen.dev의 방어선은 형식이 아니라 에이전트 사용 경험, 호스팅 모델,
병렬 에이전트다.
반대로 스키마가 깨지는 변경을 자주 하면 오픈소스 쪽의 유지 부담이 커지고,
형식은 사실상 pen.dev가 통제하는 자산이 된다.
이 가설을 뒤집는 관측은 오픈소스 도구들이 `.pen` 지원을 접거나 pen.dev가
스키마를 라이선스와 함께 정식으로 고정하는 경우다.
