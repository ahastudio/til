# Paper: HTML과 CSS 위에 만든, 에이전트와 함께 쓰는 디자인 캔버스

<https://paper.design/>

## 소개

Paper는 팀과 에이전트와 코드와 데이터를 하나의 디자인 공간에 연결하는 디자인
도구다.
홈페이지는 스스로를 에이전트와 함께 제품을 내는 팀을 위한 연결된 캔버스라고
부르고, 웹 표준 위에 만들어 번역 과정에서 잃는 것이 없다고 한다.
브라우저 버전과 데스크톱 앱이 있고,
데스크톱 앱은 macOS(ARM만), Windows(x64), Linux를 지원한다.[^downloads]
에이전트를 연결하는 MCP와 셰이더 효과 라이브러리 Paper Shaders,
글꼴 Paper Mono를 함께 공개한다.

홈페이지가 내세우는 흐름은 세 가지다.
첫째, 디자인에서 코드로 가고 다시 디자인으로 돌아온다.
에이전트가 코드베이스와 캔버스 사이에서 디자인 토큰과 스타일과 컴포넌트를
동기화하고, 캔버스가 HTML/CSS라서 내보낸 결과가 곧 코드라고 한다.
둘째, 실제 콘텐츠와 데이터로 디자인한다.
파일, CMS, 데이터베이스를 에이전트가 레이어에 연결하게 하고, 캔버스에서 고친
문구를 에이전트가 코드베이스로 보낸다.
셋째, 반복 작업을 에이전트에게 넘긴다.
반응형 레이아웃, 스타일 변형, 일관성 점검을 맡기고 사람은 사람만 할 수 있는
결정에 집중한다는 것이 anti-slop이라는 표현의 뜻이다.

이 문서는 홈페이지와 MCP 문서, 요금제, Figma 비교, 시리즈 A 발표 페이지를 읽고
썼으며 제품을 직접 써 보지는 않았다.
제품 성능에 대한 서술은 모두 Paper 쪽의 주장이다.

## 동작 방식

### 캔버스가 HTML/CSS라서 에이전트가 번역 없이 읽고 쓴다

Paper의 근본 선택은 렌더링 엔진으로 HTML과 CSS를 쓰는 것이다.
시리즈 A 발표는 이것이 에이전트에게 자연어에 가까운 형식이고, 독립 벤치마크에서
Paper의 에이전트 흐름이 다른 디자인 도구보다 빠르고 정확하고 토큰을 적게 쓴다고
주장한다.[^series-a]
MCP 문서도 같은 논리로, LLM이 HTML과 CSS를 이미 잘 이해하므로 다른 디자인
도구보다 대체로 더 정확하고 빠르고 토큰 효율이 좋다고 쓴다.[^mcp]
이 벤치마크의 내용과 조건은 이 문서가 확인하지 못했다.

Figma 비교 페이지는 차이를 구체화한다.
Paper는 sRGB와 Display P3를 요소마다 섞어 쓰고 `oklch()`, `display-p3`, 헥스를
한 파일에서 함께 쓸 수 있다고 한다.[^figma]
Figma는 파일 전체 토글이어서 한 파일에서 색 공간을 섞을 수 없고, 색 선택기도
HSB와 HSL이라 색조마다 지각이 일정하지 않다고 서술한다.[^figma]
테두리, 그림자, 블러 같은 속성도 Figma에서는 추상화돼 CSS로 옮겨야 하는 반면
Paper는 실제 CSS 스타일과 필터와 셰이더 효과를 쓴다고 한다.[^figma]
이는 경쟁 제품에 대한 Paper의 설명이며 Figma 쪽 확인은 하지 못했다.

### 에이전트 연결은 MCP 서버와 CLI다

Paper Desktop을 열면 MCP 서버가 백그라운드에서 시작되고 에이전트를 연결하는
Paper CLI가 설치된다.[^mcp]
편집기의 연결 대화상자에서 에이전트를 고르면 설정이 추가된다.
문서가 지원 대상으로 든 것은 Claude(앱 확장과 Claude Code), Codex,
Cursor(마켓플레이스 플러그인), OpenCode, Antigravity, GitHub Copilot 앱, VS
Code이고, 그 밖의 에이전트는 stdio 방식의 수동 설정이다.[^mcp]
Claude Code용은 터미널에서
`claude plugin marketplace add paper-design/agent-plugins`로 플러그인 저장소를
추가한 뒤 설치하는 방식이다.[^mcp]

### 요금은 도구 호출 횟수로 갈린다

무료 요금제는 편집자와 보기 전용을 합쳐 팀 전체를 무제한으로 초대할 수 있고,
주당 MCP 도구 호출 100회와 제한된 이미지 생성, 최대 이미지 25 MB를
포함한다.[^pricing]
Pro는 편집자 한 명당 월 20달러(연 결제 시 16달러)이며 주당 MCP 도구 호출 100만
회, 이미지 생성 100배, 동영상 내보내기, 최대 이미지 100 MB를 더한다.[^pricing]
조직 요금제는 Pro에 SAML과 SSO, 관리자 통제, 맞춤 계약, 전담 지원을
더한다.[^pricing]
에이전트 연동이 핵심 가치인 제품에서 무료 요금제의 주당 100회는 사실상 체험용
한도로 읽힌다.

## 비평

### 에이전트 효율이 더 낫다는 주장은 독립 검증을 요구한다

Paper의 근거는 HTML/CSS가 LLM에 친숙하다는 논리와 독립 벤치마크라는 한 줄이다.
발표문은 독립 벤치마킹의 결과를 말할 뿐 결과와 조건을 보여 주지 않고,[^series-a]
MCP 문서도 대체로라는 한정어를 단다.[^mcp]
HTML/CSS 캔버스가 에이전트에게 유리하다는 가설은 그럴듯하지만, 속도와 정확도와
토큰 사용량이 어떤 작업에서 얼마나 차이 나는지가 있어야 비교가 성립한다.
반대로 HTML/CSS의 표현력이 디자이너가 쓰는 도구의 자유도(자유 형태, 벡터 작업)를
제한하는지는 홈페이지가 다루지 않는다.

### 성장 지표는 회사의 서술이다

시리즈 A 발표는 Paper Desktop 출시 뒤 한 달에 ARR이 25배가 됐고, 수천 팀이
요금을 내며, Ramp의 빠르게 성장하는 회사 목록에서 4개월 연속 상위에 올랐다고
적는다.[^series-a]
총 투자는 3,850만 달러이고 Accel과 ICONIQ가 주도했다고 한다.[^series-a]
후기도 Lovable, Ramp, Vercel 관계자의 말이 인용되는데, 이들은 투자자나 고객으로
얽힌 사람들이다.[^series-a]
25배라는 증가율은 기준 규모를 밝히지 않으면 크기를 알 수 없다.

### 무료 한도와 에이전트 연동 사이의 긴장

주당 도구 호출 100회는 에이전트가 한 번의 디자인 작업에서 여러 번 호출하는
흐름을 몇 번 돌리면 소진될 수 있다.[^pricing]
얼마나 많은 호출이 한 화면을 만드는 데 드는지는 요금제 페이지에 없다.
무료로 시작해 팀을 모두 초대하게 하고 에이전트 사용량으로 Pro 전환을 유도하는
구조로 읽히며, 이 해석은 이 문서의 추정이다.

### 비교 페이지는 상대 제품의 최신 기능을 반영하지 않을 수 있다

Figma 비교는 Figma의 캔버스를 proprietary WebGL 형식이라고 규정하고, 개발자와
에이전트가 이를 번역해야 한다고 쓴다.[^figma]
페이지 아래에는 비교 대상 중 하나인 Pencil과의 비교 링크가 따로 있다.
경쟁사의 기능 변화는 빠르고, 이 페이지가 쓰인 시점과 갱신 주기는 알 수 없다.
비교 표는 Paper가 고른 항목(색 공간, 색 모델, CSS 스타일)에서만 Paper가 앞선다는
점에서 선택적이다.

## 인사이트

### 디자인 파일 형식의 선택이 곧 에이전트 전략이다

Paper는 에이전트 시대의 디자인 도구 경쟁을 형식의 문제로 푼다.
캔버스가 HTML/CSS이면 코드 내보내기가 번역이 아니라 복사에 가깝고, 코드에서
디자인으로 돌아오는 방향도 같은 형식으로 열린다.
시리즈 A 발표가 CI 파이프라인이 시각적 차이를 담은 캔버스를 만들고 사용자
하네스가 Paper를 내장하는 미래를 말하는 것도 이 형식 위에서만 가능한
이야기다.[^series-a]
다른 접근은 별도의 문서 형식(JSON 같은 독자 포맷)을 정하고 거기서 코드를 만드는
것인데, 이는 번역 규칙을 도구가 관리해야 한다는 부담을 진다.
이 두 접근의 우열은 결과물의 충실도와 에이전트 비용의 측정으로만 가려진다.

### 웹 표준에 묶이는 대가는 웹에 속하지 않는 디자인이다

HTML/CSS는 웹과 웹 기반 앱에는 완벽하게 맞지만, 네이티브 모바일 UI나 인쇄물,
일러스트레이션의 자유 형태는 그 표현력 안에 들어가지 않을 수 있다.
홈페이지의 사례와 설명은 모두 웹 앱 화면을 중심으로 한다.
이는 이 문서의 추론이며, 홈페이지는 웹 외 용도를 언급하지 않는다.
Paper가 덱, 다이어그램, 화이트보드로 쓰임새를 넓힌다고 말하는 것은 이 한계를
의식한 확장일 수 있다.[^series-a]

### 이 글을 읽는 방법

디자인 도구를 고르는 팀이라면 먼저 두 가지를 시험할 수 있다.
무료 요금제에서 실제 화면 하나를 에이전트로 만들면 주당 한도의 몇 퍼센트가
쓰이는지, 만든 화면의 내보낸 코드가 코드베이스의 기존 컴포넌트와 얼마나
맞는지다.
이 제품의 주장을 가를 관찰은 두 가지다.
독립 벤치마크의 조건과 결과가 공개되는지, 코드에서 디자인으로 돌아오는 동기화가
대형 코드베이스에서 유지되는지다.
둘 다 확인되지 않으면 HTML/CSS 캔버스의 이점은 설계 논리로만 남는다.
