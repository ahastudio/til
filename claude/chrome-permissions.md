# Claude in Chrome 권한: 세 가지 승인 모드와 모드로 풀리지 않는 경계

원문: [Claude in Chrome permissions guide | Claude Help Center](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide)

## 소개

Claude in Chrome에서 Claude가 무엇에 접근하고 무엇을 할 수 있는지를 정하는 방법을 설명하는 Anthropic 도움말이다.
2026년 8월 12일에 갱신되었다.
Claude in Chrome은 Pro, Max, Team, Enterprise의 모든 유료 요금제에서 쓸 수 있고, Claude Cowork와 Claude Code 안에서, 그리고 Chrome 브라우저의 베타로 제공된다.

사이드 패널이 어떤 경험으로 돌아가는지는 요금제마다 다르다.
Max와 Team에서는 사이드 패널이 Claude Cowork 세션으로 돌아가고, Pro에는 앞으로 몇 주에 걸쳐 같은 방식이 배포된다.
Enterprise에서는 관리자가 클라우드의 Cowork를 켠 뒤부터 Cowork 세션으로 돌아가고, 그 전까지는 기존(classic) 경험을 쓴다.
이 구분이 중요한 이유는 뒤에서 보듯 같은 모드 이름이라도 두 사이드 패널에서 동작이 다르기 때문이다.

문서가 제시하는 계약은 여러 겹의 권한 체계다.
사용자가 고르는 권한 모드가 한 겹, 사이트별 허용이 또 한 겹, 모드와 무관하게 늘 사용자 확인을 요구하는 행동이 한 겹, 어떤 설정으로도 풀리지 않는 금지 행동이 마지막 겹이다.
Team과 Enterprise에서는 관리자의 허용 목록과 차단 목록이 그 위에 얹힌다.
문서는 사용하기 전에 브라우저 기반 AI의 위험을 다룬 별도 문서 “Use Claude in Chrome Safely”를 먼저 읽으라고 권한다.

## 동작 방식

### 세 가지 권한 모드

확장 프로그램의 사이드 패널이나 Claude Desktop의 채팅 입력란에 있는 드롭다운에서 세 모드 중 하나를 고른다.

| 모드                                   | 예전 이름          | 행동 전 확인                  | 자동 안전 검사 |
| -------------------------------------- | ------------------ | ----------------------------- | -------------- |
| 수동 승인(Manually approve)            | Ask before acting  | 매 행동마다 사용자에게 묻는다 | 명시 없음      |
| 자동 승인(Automatically approve)       | 없음               | 필요할 때만 묻는다            | 매 행동마다    |
| 모든 승인 건너뛰기(Skip all approvals) | Act without asking | 묻지 않는다                   | 없음           |

Cowork 사이드 패널의 기본값은 자동 승인이다.
다른 모드로 바꾸면 사이드 패널은 그 선택을 다음 세션에도 유지한다.

### 수동 승인은 사이드 패널마다 다르게 동작한다

기존 사이드 패널에서는 Claude가 프롬프트로부터 계획을 먼저 세운다.
계획에는 접근할 웹사이트 목록과 따라갈 접근 방식이 들어 있고, 사용자가 “Approve plan”을 누르면 Claude는 그 범위 안에서 스스로 움직인다.
계획을 거절하려면 “Make changes”를 누르고 다시 프롬프트를 준다.
Claude는 계획에 적힌 사이트만 쓰므로, 추가 사이트 접근은 따로 수동 승인해야 하고, 계획에서 벗어날 때는 먼저 허락을 구한다.
계획을 승인한 뒤에도 파일 다운로드나 민감한 정보 입력 같은 행동 앞에서는 다시 묻는다.

Cowork 사이드 패널에서는 승인할 계획이 없다.
Claude가 원하는 것을 확인하려고 질문을 한두 개 할 수는 있지만, 곧바로 작업을 시작하고 행동마다 승인을 요청한다.
선택지는 이 사이트에서 모두 허용(Allow all for this website), 이번만 허용(Allow this time only), 거부(Deny) 세 가지다.

두 방식의 차이는 승인의 단위다.
기존 패널은 작업 전체를 계획 한 번으로 승인하고, Cowork 패널은 행동 하나하나 또는 사이트 하나를 단위로 승인한다.

### 자동 승인은 차단과 전환을 반복한다

자동 승인에서 Claude는 단계마다 멈추지 않는 대신, 각 행동을 데이터 유출(data exfiltration)이나 프롬프트 주입(prompt injection) 같은 기준으로 검사하고 위험하다고 판단한 것을 자동으로 막는다.
행동이 막히면 Claude는 더 안전한 방법을 찾거나 사용자에게 직접 묻는다.
막히는 일이 계속되면 단계마다 허락을 구하는 방식으로 되돌아간다.

문서는 이 안전 검사를 출시 전에 외부 보안 전문가와 함께 위험한 행동을 몰래 통과시키려는 시험으로 광범위하게 검증했다고 밝힌다.
동시에 완벽한 방어는 없고 어떤 모드도 사용자의 판단을 대신하지 않는다고 적는다.
돈, 사용자 명의로 보내는 메시지, 중요한 파일처럼 실제 결과가 따르는 작업에서는 곁에서 지켜보거나 수동 승인으로 돌아가라고 권한다.
검사가 배경에서 추가로 돌기 때문에, 자동 승인은 다른 모드보다 사용량 한도를 더 많이 쓴다.

### 모든 승인 건너뛰기에는 검사가 없다

이 모드에서 Claude는 묻지 않고, 행동을 자동으로 검사하는 장치도 없다.
문서는 작업에 관여하는 모든 행동, 커넥터, 파일, 앱을 완전히 믿을 때만 쓰라고 한다.

### 사이트 단위 권한

어떤 웹사이트에서는 Claude가 모든 행동에 승인을 요구한다.
그런 사이트로 이동하면 확장 프로그램 사이드 패널, Claude Cowork, Claude Code에 “New permissions required” 안내가 뜨고, 페이지에 접근하거나 행동하기 전에 허락을 구한다.

| 선택지                                                     | 범위           | 문서의 평가                                   |
| ---------------------------------------------------------- | -------------- | --------------------------------------------- |
| 이 행동 허용(Allow this action)                            | 행동 하나      | 확장 프로그램에서 가장 안전한 선택            |
| 이 사이트에서 항상 허용(Always allow actions on this site) | 사이트 전체    | 완전히 믿는 사이트에만, 의도치 않은 행동 가능 |
| 거부(Decline)                                              | 이번 행동 거절 | 다른 방법을 시도하거나 작업을 건너뛴다        |

항상 허용을 골라도 세 가지는 따로 확인을 받는다.
파일 다운로드, 민감할 수 있는 정보를 페이지에 입력하는 것, 권한 부여(authorization)다.

### 모드와 무관한 두 겹

권한 모드가 무엇이든 Claude가 명시적 허락을 받아야 하는 행동이 있다.
권한 설정 변경, 권한 부여, 민감할 수 있는 정보의 웹사이트 입력이다.

그리고 권한과 상관없이 금지되는 행동이 있다.
구매나 금융 거래, 계정 생성, 민감한 신용카드·신분증 정보 처리, 신뢰할 수 없는 출처의 파일 다운로드, 영구 삭제(휴지통 비우기, 이메일·파일·메시지 삭제), 투자·재무 조언, 금융 거래나 투자 실행, 시스템 파일 수정, 이메일이나 웹 콘텐츠에 담긴 지시 수행이다.
기존 사이드 패널 절은 여기에 봇 인증 우회와 프롬프트 주입 위험을 시사하는 특정 행동도 덧붙인다.

## 설정하기

### 모드 고르기

사이드 패널이나 Claude Desktop의 채팅 입력란 드롭다운에서 모드를 고른다.
Cowork 사이드 패널은 자동 승인으로 시작하고, 바꾼 모드를 다음 세션에도 기억한다.
그래서 한 번 모든 승인 건너뛰기로 바꿔 두면 다음 작업도 그 모드로 시작한다는 점을 기억해야 한다.

### 사이트 권한 관리하기

확장 프로그램 아이콘을 누르고, 사이드 패널 오른쪽 위의 점 세 개 메뉴에서 “Extension settings”를 고르면 Permissions 페이지가 열린다.
여기서 할 수 있는 일은 세 가지다.

- “Your approved sites”에서 항상 허용 상태인 사이트를 확인한다.
- 특정 웹사이트의 권한을 회수한다.
- 권한 이력을 본다.

### 조직 단위 통제

Team과 Enterprise 관리자는 허용 목록(allowlist)으로 Claude가 승인된 사이트에만 접근하게 하고, 차단 목록(blocklist)으로 사용자 권한과 무관하게 특정 사이트 접근을 막을 수 있다.
Claude로 어떤 사이트에 접근할 수 없다면 조직이 제한했을 수 있으므로 관리자에게 문의하거나 “Claude in Chrome admin controls” 문서를 본다.

## 트레이드오프

### 수동 승인은 안전하지만 승인 피로를 만든다

수동 승인은 모든 행동을 사람이 보는 유일한 모드다.
그러나 행동 하나하나를 묻는 구조는 작업이 길어질수록 승인 요청을 쌓고, 사람은 결국 내용을 읽지 않고 허용을 누르게 된다.
이 상태의 수동 승인은 안전장치가 아니라 클릭 의식이다.

Cowork 패널의 이 사이트에서 모두 허용은 이 피로를 줄이는 탈출구다.
하지만 그 선택은 사실상 그 사이트에 한해 모든 승인 건너뛰기로 바꾸는 것과 비슷하다.
확인이 사라지는 대신, 그 사이트 안에서 Claude가 무엇을 하든 보호 행동 세 가지를 빼고는 묻지 않는다.

기존 패널의 계획 승인은 다른 방식의 절충이다.
작업 시작 전에 사이트 목록과 접근 방식을 한 번 보면 되므로 피로는 적다.
대신 승인 시점에 계획이 담지 못한 세부 행동, 즉 어떤 버튼을 누르고 어떤 값을 입력하는지는 보지 못한다.
계획이 정한 사이트 경계는 강하지만, 그 사이트 안의 행동 경계는 약하다.

### 자동 승인은 판단을 분류기에 넘기고 사용량으로 값을 치른다

자동 승인의 장점은 속도와 검사가 함께 있다는 것이다.
모든 승인 건너뛰기와 달리 모든 행동이 실행 전에 검사된다.
대가는 두 가지다.

첫째는 사용량이다.
배경 검사가 추가로 돌기 때문에 같은 작업이 다른 모드보다 사용량 한도를 더 많이 쓴다.
긴 브라우저 작업을 자주 하는 사용자에게는 이 차이가 한도에 닿는 시점을 앞당긴다.

둘째는 설명 가능성이다.
수동 승인에서는 사람이 무엇을 허용했는지 안다.
자동 승인에서 행동이 통과하거나 막힌 이유는 사용자가 보는 화면에 드러나지 않을 수 있고, 문서도 그 기준을 데이터 유출과 프롬프트 주입 같은 예시로만 설명한다.
막힌 행동은 눈에 띄지만, 통과된 행동이 왜 안전하다고 판단되었는지는 남지 않는다.

### 모든 승인 건너뛰기는 신뢰의 범위를 사용자에게 계산하게 한다

모든 승인 건너뛰기의 조건은 관여하는 모든 행동, 커넥터, 파일, 앱을 완전히 믿는 것이다.
브라우저 작업에서 이 조건은 거의 성립하지 않는다.
사용자가 믿는 것은 대개 자기가 연 사이트이지, 그 사이트가 보여 주는 댓글, 광고, 메일 본문, 검색 결과가 아니다.

프롬프트 주입은 바로 그 신뢰하지 않은 콘텐츠를 통해 들어온다.
이 모드에서는 콘텐츠에 숨은 지시를 걸러 줄 자동 검사도, 행동을 멈춰 세울 사람도 없다.
남는 방어는 금지 행동 목록뿐이고, 그 가운데 이메일이나 웹 콘텐츠의 지시를 수행하지 않는다는 항목이 사실상 유일한 주입 방어가 된다.

## 함정

### 두 목록이 서로 다른 행동을 적고 있다

문서에는 사용자 확인을 요구하는 목록이 두 개 있다.
항상 허용에서도 묻는 보호 행동은 파일 다운로드, 민감한 정보 입력, 권한 부여다.
모드와 무관하게 묻는 행동은 권한 설정 변경, 권한 부여, 민감한 정보 입력이다.

두 목록의 차이는 파일 다운로드와 권한 설정 변경이다.
파일 다운로드는 모드와 무관한 목록에 없으므로, 모든 승인 건너뛰기에서 신뢰할 수 있는 출처의 다운로드가 확인 없이 진행되는지는 문서만으로 알 수 없다.
신뢰할 수 없는 출처의 다운로드는 금지 목록에 있지만, 무엇이 신뢰할 수 없는 출처인지 누가 판단하는지도 적혀 있지 않다.

### 금지 목록을 누가 집행하는지 쓰여 있지 않다

금지 행동은 권한과 무관하게 막힌다고 되어 있다.
그런데 모든 승인 건너뛰기에서는 행동을 자동으로 검사하는 장치가 없다고 같은 문서가 말한다.
두 문장을 함께 읽으면, 이 모드에서 금지 목록을 지키는 것은 별도 검사기가 아니라 Claude 자신의 판단이라고 추론할 수 있다.

이 추론이 맞다면 금지 목록은 모델이 지키는 규칙이지 시스템이 강제하는 경계가 아니다.
프롬프트 주입은 정확히 모델의 판단을 흔드는 공격이므로, 가장 위험한 모드에서 가장 중요한 방어가 공격받는 바로 그 지점에 놓인다.
문서가 이 구분을 명시하지 않으므로, 금지 목록을 방화벽처럼 믿고 모든 승인 건너뛰기를 켜는 것은 위험하다.

### 모드는 세션을 넘어 남는다

Cowork 사이드 패널은 바꾼 모드를 다음 세션에도 유지한다.
신뢰하는 사이트 하나를 위해 모든 승인 건너뛰기로 바꿨다가 되돌리지 않으면, 다음에 전혀 다른 사이트에서 시작하는 작업도 검사 없이 돈다.
항상 허용한 사이트도 Permissions 페이지에서 회수하기 전까지 남는다.

### 같은 모드 이름, 다른 동작

수동 승인은 기존 패널에서는 계획 한 번의 승인이고, Cowork 패널에서는 행동마다의 승인이다.
Enterprise는 관리자가 클라우드 Cowork를 켜는 순간 사용자가 아무것도 바꾸지 않아도 사이드 패널의 동작이 바뀐다.
팀 안내 문서에 수동 승인이면 계획을 확인하라고 적어 두었다면, 전환 뒤에는 그 안내가 맞지 않는다.

### 자동 승인이 조용히 수동으로 바뀔 수 있다

자동 승인에서 막히는 일이 계속되면 단계마다 허락을 구하는 방식으로 돌아간다.
자리를 비운 사이 끝나리라 기대한 작업이, 돌아와 보면 첫 승인 요청에서 멈춰 있을 수 있다.
반대로 막힘이 잦다는 것은 작업 대상 페이지에 의심스러운 콘텐츠가 있다는 신호일 수도 있으므로, 그때 쌓인 승인 요청은 평소보다 꼼꼼히 봐야 한다.

## 확인하기

설정이 의도대로인지 확인하는 순서다.

1. 사이드 패널이나 Claude Desktop의 채팅 입력란 드롭다운에서 현재 모드를 확인한다. Cowork 패널이라면 지난 세션의 선택이 남아 있을 수 있다.
2. 확장 프로그램 아이콘, 점 세 개 메뉴, “Extension settings” 순으로 Permissions 페이지를 열고 “Your approved sites”의 항상 허용 사이트를 확인한다.
3. 더 이상 쓰지 않는 사이트의 권한을 회수한다.
4. 권한 이력에서 기억하지 못하는 허용이 있는지 본다.
5. Team이나 Enterprise라면 접근이 막힌 사이트가 조직 차단 목록 때문인지 관리자에게 확인한다.

## 체크리스트

- 돈, 사용자 명의의 메시지, 중요한 파일이 걸린 작업을 수동 승인으로 돌리고 있는가?
- 모든 승인 건너뛰기를 쓴 뒤 모드를 다시 바꿔 두었는가?
- “Your approved sites”에 있는 모든 사이트가 지금도 완전히 믿는 사이트인가?
- 사용자 생성 콘텐츠(댓글, 메일, 게시판)가 있는 사이트에 항상 허용을 주지 않았는가?
- 자동 승인의 추가 사용량을 감수할 만큼 작업이 긴가, 아니면 수동 승인으로 충분한가?
- 팀 안내 문서가 지금 쓰는 사이드 패널(기존 또는 Cowork)의 동작과 맞는가?

## 기억할 원칙

### 승인의 단위를 고르는 것이 모드를 고르는 것이다

세 모드와 사이트별 선택지를 나란히 놓으면, 결국 고르는 것은 사람이 무엇을 한 번에 승인하느냐다.
계획 하나, 행동 하나, 사이트 하나, 아니면 아무것도 아닌 것이다.
단위가 클수록 편하지만, 승인할 때 보지 못한 행동이 그만큼 많아진다.

그래서 모드를 고를 때는 얼마나 편한가보다 이 작업에서 내가 보지 않고 넘어가도 되는 행동이 무엇인가를 물어야 한다.
그 답이 없다면 승인 단위를 줄여야 한다.

### 모델이 지키는 규칙과 시스템이 강제하는 경계를 구분한다

문서의 여러 겹 가운데 어떤 것은 사용자 인터페이스가 강제하고, 어떤 것은 분류기가 판단하며, 어떤 것은 모델이 스스로 지킨다.
문서는 이 셋을 같은 목록 형식으로 적지만, 공격을 받을 때 버티는 정도는 다르다.

브라우저 에이전트에서 공격은 대부분 페이지 콘텐츠를 통해 모델의 판단을 흔드는 방식으로 온다.
따라서 모델의 판단에만 기대는 경계는 가장 약한 경계로 취급하고, 중요한 작업에서는 사람이 보는 승인이나 조직의 허용 목록처럼 모델 바깥의 층을 하나 더 둔다.
