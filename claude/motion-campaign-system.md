# 모션 디자인 캠페인 시스템: 영상 한 편이 아니라 생산 공정을 만든다

트윗: [How to Build an Automated Motion Design System that Generates $$$](https://twitter.com/e1genqq/status/2110016031917855006)

## 소개

eigen(@e1genqq)이 2026년 10월 13일에 올린 Twitter Article로,
읽는 데 14분이 걸린다고 적혀 있다.
저자는 자신을 200곳이 넘는 단골 고객을 둔 모션 스튜디오의 시각 효과 감독(Visual
Effects Supervisor)이라고 소개하는데, 이는 글 안의 자기 소개이며
확인하지 못했다.
글의 주장은 Claude Opus 5.5가 코드로 영상을 그리는 능력을 이용해 브리프 하나에서
완성 영상 여러 편을 뽑는 공정을 만들 수 있고, 그것이 사업이 될 수 있다는 것이다.

Opus 5.5는 2026년 9월 22일에 공개되었다.[^opus-release]
저자는 그 뒤 코딩 에이전트로 만든 정교한 모션 영상이 퍼졌다고 말하며,
가장 흥미로운 사례로 @twoclipping이 올린 영상을 든다.
그 트윗은 이 영상이 전부 코드이고 After Effects는 쓰지 않았다고 적는다.

글이 설명하는 핵심 기제는 다음과 같다.
모델은 일반적인 AI 영상을 생성하지 않고, 프레임마다 그리는 코드를 쓴다.
`seek(t)`라는 함수가 어떤 시각에 무엇이 보일지 정하고,
브라우저가 프레임을 그리고, FFmpeg가 그것을 MP4로 만든다.
애니메이션이 수식으로 정의되므로 영상 생성 모델로 다시 만들지 않고도 타이밍, 색,
글자, 움직임을 고칠 수 있다.

목표 산출물은 SaaS 창업자가 웹사이트, 로고, 브랜드 색, 스크린샷,
제품 설명을 보냈을 때 25초 제품 영상 하나에서 시작해 훅(hook) 3개,
화면 비율 3개(9:16, 1:1, 16:9), 행동 유도 문구(CTA) 2개를 곱한 18개의 내보내기를
얻는 것이다.
저자는 이것이 서로 다른 18편이 아니라 소재, 형식,
CTA의 쓸 만한 조합 18개라고 선을 긋는다.

구성은 여섯 부분이다.
브리프 컴파일러는 고객 정보를 구조화된 데이터로 바꾼다.
장면 엔진은 데이터를 애니메이션 지시로 바꾼다.
렌더러는 특정 시각의 프레임을 만든다.
품질 관리자는 납품 전에 문제를 찾는다.
변형 생성기는 훅, 형식, CTA를 바꾼다.
납품 시스템은 결과물을 묶는다.

## 동작 방식

### 애니메이션은 시간의 함수이다

글은 애니메이션이 이전에 일어난 사건의 순서가 아니라 시간의 함수여야
한다고 말한다.
30 FPS에서 25초 영상은 750프레임이고, 프레임 번호 f의 시각은 t = f / 30이다.
렌더러가 그 시각의 상태를 그리라고 요청하면 코드는 0번부터 599번까지 렌더링하지
않고도 600번 프레임을 만들 수 있어야 한다.

그러려면 이전 프레임에 대한 의존, 통제되지 않는 무작위성,
렌더링 중의 타이머 기반 CSS 전환, 앞선 일 때문에만 존재하는 애니메이션 상태가
모두 없어야 한다.
글의 캔버스 예제에서 진행 막대는 `ease((t - 3) / 2)`로 계산된다.
이 식을 직접 계산하면 `seek(3)`에서 0, `seek(4)`에서 0.875, `seek(5)`에서 1이다.
글은 `seek(4)`에서 “부분적으로 채워진다”고 쓰는데,
이 값이 절반이 아니라 87.5%라는 점은 이징(easing)이 앞쪽에 몰려 있기 때문이다.

### 데이터와 애니메이션 코드를 분리한다

저자가 가장 과소평가된 부분으로 꼽는 것이 입력의 구조화이다.
영상 설명을 문단으로 주고 곧바로 애니메이션을 시키면 실험에는 되지만 고객이 여럿이면 불안정해진다.
그래서 창작 입력을 `campaign.json` 같은 파일에 두고,
이 파일이 영상에 무엇이 들어가는지를 말하고 애니메이션 시스템이 그것이 어떻게
나타나는지를 정하게 한다.
텍스트, 자산, 브랜드, CTA를 바꿔도 애니메이션 엔진을 다시 쓰지 않아야
한다는 것이다.

### 렌더 전에 검증한다

비싼 렌더가 시작되기 전에 모든 캠페인이 몇 가지 검사를 통과해야 한다고
글은 말한다.
참조한 자산이 모두 있는지, 글꼴이 로드되는지,
CTA가 컴포넌트에 비해 너무 길지 않은지, 주장이 고객에게 승인된 것인지를 본다.
제품이 전환율을 240% 높인다고 주장하더라도 시스템이 그 통계를 만들어 내서는 안
되고, 승인된 고객 정보에서 와야 한다.

## 구현하기

### 도구 구성

글이 고르는 스택은 작다.
코딩 에이전트로 Claude Opus 5.5, 확장 가능한 렌더링에 Remotion,
브라우저 제어에 Playwright, 인코딩에 FFmpeg를 쓴다.
HyperFrames는 HTML, CSS, 미디어, 탐색 가능한(seekable) 애니메이션으로 결정적
영상을 만드는 선택 사항이다.
저자의 선택은 재사용 가능한 상업용 템플릿을 Remotion으로 만들고 `seek(t)`는 직접
실험하며 이해하는 것이다.

Remotion은 React 컴포넌트로 영상을 렌더링하고,
같은 구성(composition)에 다른 데이터를 넘길 수 있다.
저장소는 2020년에 만들어졌고 2026-11-01 기준 별 69,593개이다.[^remotion-api]
공식 에이전트 스킬 저장소 `remotion-dev/skills`는 2026년 1월에 만들어졌고 같은
날 별 6,007개이다.[^skills-api]
HyperFrames는 HeyGen이 만든 저장소로 Apache-2.0 라이선스이며 2026년 3월에
만들어졌다.[^hyperframes-api]

### 캠페인 파일과 검증기

글이 든 가상 제품 Nova의 캠페인 파일은 길이, 브랜드, 자산, 장면 시간표,
변형 수를 담는다.
아래는 글의 예에 CTA 목록과 승인된 주장을 더해 이 문서가 만든 검증기이며,
글에 있는 코드가 아니다.
자산 존재, 장면 시간표의 빈틈, CTA 길이,
승인되지 않은 주장을 확인하고 내보내기 수와 프레임 수를 출력한다.

```python
import json, sys
from pathlib import Path

MAX_CTA_CHARS = 18   # 9:16 버튼에서 86px 글자가 넘치지 않는 길이로 정한 값
FPS = 30

def validate(path):
    root = Path(path).parent
    c = json.loads(Path(path).read_text())
    errors = []
    for name, rel in c["assets"].items():
        if not (root / rel).is_file():
            errors.append(f"missing asset {name}: {rel}")
    scenes = c["scenes"]
    if scenes[0]["start"] != 0 or scenes[-1]["end"] != c["duration"]:
        errors.append("scenes must cover 0..duration")
    for a, b in zip(scenes, scenes[1:]):
        if a["end"] != b["start"]:
            errors.append(f"gap or overlap between {a['id']} and {b['id']}")
    for cta in c["ctas"]:
        if len(cta) > MAX_CTA_CHARS:
            errors.append(f"CTA too long: {cta!r}")
    if len(c["ctas"]) != c["variants"]["ctas"]:
        errors.append("variants.ctas does not match the ctas list")
    for claim in c["claims"]:
        if not claim.get("approved"):
            errors.append(f"unapproved claim: {claim['text']!r}")
    v = c["variants"]
    total = v["hooks"] * len(v["formats"]) * v["ctas"]
    print(f"{v['hooks']} hooks x {len(v['formats'])} formats x {v['ctas']} CTAs"
          f" = {total} exports, {c['duration'] * FPS} frames each")
    return errors

if __name__ == "__main__":
    errs = validate(sys.argv[1])
    for e in errs:
        print("FAIL", e)
    sys.exit(1 if errs else 0)
```

이 검증기를 글의 Nova 예에 맞춘 파일로 돌리면 `3 hooks x 3 formats x 2 CTAs = 18
exports, 750 frames each`가 출력되고 종료 코드 0으로 끝난다.
`approved`를 `false`로 바꾸면 `FAIL unapproved claim`이 나오고 종료
코드 1로 끝난다.
두 결과 모두 이 문서가 직접 돌려 확인했다.

### 렌더와 인코딩

글의 렌더 단계는 Chromium에서 애니메이션을 열고,
글꼴과 자산이 로드되길 기다리고, `window.seek(frame / fps)`를 호출하고,
캔버스를 캡처해서 이미지 순서를 FFmpeg에 넘기는 것이다.
인코딩은 번호가 붙은 PNG 프레임에 다음 명령을 쓴다.

```bash
ffmpeg -framerate 30 -i frames/%05d.png -c:v libx264 -crf 18 -pix_fmt yuv420p output.mp4
```

저자는 운영에서는 수천 장의 중간 PNG를 저장하지 말고,
디버깅이 필요한 경우가 아니면 프레임을 스트리밍하거나 Remotion의 렌더링 API를
쓰는 편이 효율적이라고 덧붙인다.

### 움직임을 비싸 보이게 하는 네 가지

글이 애니메이션 라이브러리에 넣겠다고 하는 기법은 네 가지이다.
첫째, 닫힌 형태(closed-form)의 스프링이다.
프레임별로 적분하는 스프링은 이전 프레임에 의존하므로,
목표가 여러 번 바뀌는 속성에는 변화마다 스프링 응답을 더하는 `value(t) = initial
+ Σ(targetChange × springResponse(t − changeTime))` 방식을 쓴다.
둘째, 움직이는 탭 표시줄의 앞쪽 가장자리와 뒤쪽 가장자리를 서로 다른 스프링
값으로 움직여 늘어났다가 자리 잡게 한다.
셋째, 컨테이너의 움직임과 글자의 움직임을 분리해서 글자가 겹치는 것을 막는다.
넷째, 소리를 타임라인의 일부로 다뤄 비트와 오디오 최고점에 시각 사건을 붙인다.

## 확인하기

### 접촉 시트가 정말 한 장으로 나오는가

글은 FFmpeg로 일정 간격의 프레임을 뽑아 한 장의 검토 이미지로 만드는
명령을 제시한다.
다음은 그 명령을 시험하기 위한 합성 영상(`testsrc2`)에 적용한 것이다.

```bash
ffmpeg -f lavfi -i "testsrc2=size=1080x1920:rate=30:duration=25" \
  -c:v libx264 -pix_fmt yuv420p out.mp4
ffmpeg -i out.mp4 -vf "fps=1,scale=270:-1,tile=5x5" -frames:v 1 contact.png
ffprobe -v error -select_streams v -show_entries stream=width,height \
  -of csv=p=0 contact.png
ffprobe -v error -count_frames -select_streams v \
  -show_entries stream=nb_read_frames -of csv=p=0 out.mp4
```

이 문서가 이 명령을 FFmpeg 9.0.1로 돌렸을 때 접촉 시트는 1350×2400이고 원본은
750프레임이었다.
세로 1080×1920 영상을 너비 270으로 줄이면 높이가 480이고,
5열 5행이면 1350×2400이 맞다.
글이 덧붙이듯 일정 간격 표본만으로는 두 표본 사이에서 일어나는 깨진 전환을 놓칠
수 있으므로 전환 직전과 직후 프레임도 따로 뽑아야 한다.

### 닫힌 형태의 스프링 합산이 시뮬레이션과 같은가

글의 합산 공식은 스프링이 선형(질량, 감쇠, 강성이 일정)일 때 성립한다.
아래 스크립트는 목표가 세 번 바뀌는 감쇠 진동자를 4차 룽게-쿠타(RK4)로 직접
적분한 값과 합산 공식을 비교한다.

```python
import math

w, z = 12.0, 0.5                   # 고유 진동수, 감쇠비 (미달 감쇠)
wd = w * math.sqrt(1 - z * z)

def step(t):                        # 단위 계단 입력에 대한 응답
    if t < 0:
        return 0.0
    return 1 - math.exp(-z * w * t) * (
        math.cos(wd * t) + z * w / wd * math.sin(wd * t))

changes = [(0.0, 1.0), (0.6, -0.4), (1.1, 0.9)]   # (시각, 목표 변화량)

def closed(t):
    return sum(d * step(t - tc) for tc, d in changes)

def target(t):
    return sum(d for tc, d in changes if t >= tc)

def f(t, x, v):
    return v, w * w * (target(t) - x) - 2 * z * w * v

x = v = t = 0.0
dt = 1e-4
worst = 0.0
while t < 3:
    k1 = f(t, x, v)
    k2 = f(t + dt / 2, x + dt / 2 * k1[0], v + dt / 2 * k1[1])
    k3 = f(t + dt / 2, x + dt / 2 * k2[0], v + dt / 2 * k2[1])
    k4 = f(t + dt, x + dt * k3[0], v + dt * k3[1])
    x += dt / 6 * (k1[0] + 2 * k2[0] + 2 * k3[0] + k4[0])
    v += dt / 6 * (k1[1] + 2 * k2[1] + 2 * k3[1] + k4[1])
    t += dt
    worst = max(worst, abs(x - closed(t)))
print(f"max |simulated - closed-form| = {worst:.2e}")
```

이 스크립트를 돌렸을 때 최대 차이는 약 `9.8e-05`였고 이는 적분 오차의 크기이다.
따라서 선형 스프링에서는 합산 공식이 프레임 간 상태 없이 같은 값을 준다.
비선형 스프링이나 목표에 따라 계수가 달라지는 스프링에는 이 확인이
적용되지 않는다.

## 트레이드오프

### 생성 코드를 재사용하면 일관성은 얻지만 새로움은 잃는다

글은 Claude에게 줄 프롬프트를 소개한 절의 끝에서 진지한 상업 시스템이라면
에이전트가 캠페인마다 브랜드 컴포넌트를 마음대로 다시 디자인하게 두지
말라고 조언한다.
검토된 재사용 템플릿을 모아 두고 모델이 고르고 설정하게 하면 결과를
예측할 수 있다.
대가는 모델이 매번 새로운 시각 해법을 내놓지 못한다는 점이고,
이는 모션 디자인의 가치가 되는 부분을 템플릿 설계자에게 옮기는 일이다.

### 변형을 곱셈으로 늘리면 검토가 곱셈으로 늘어난다

18개 내보내기는 렌더 비용뿐 아니라 검토 대상도 18배로 만든다.
글의 품질 관리 순서는 스토리보드, 타이밍, 휴대폰 크기, 브랜드와 사실 정확도,
전체 영상과 소리의 다섯 단계이고, 에이전트가 검사한 시각, 발견한 문제,
고친 내용, 남은 우려를 보고서로 요구하며 납품 전 사람의 승인을 둔다.
이 순서를 18개에 모두 사람이 하면 변형으로 얻은 시간 절약이 사라지고,
자동 검사에만 맡기면 모델의 시각 판단이 완벽하다고 가정하는 셈이 된다.
글은 이를 알고 있어서 자동화하되 모델의 판단을 맹신하지 말라고 하지만,
18개를 얼마나 표본 검사할지는 정하지 않는다.

### 레이아웃을 형식마다 계산하면 서사는 지키고 코드는 늘어난다

세로 영상과 가로 영상은 같은 픽셀 좌표를 공유하면 안 된다는 것이 글의 주장이다.
세로에서는 인터페이스를 쌓고 가로에서는 나란히 놓는 식으로 대상 구성에서
레이아웃을 계산해야 한다.
이는 반응형 웹 디자인과 같은 구조이지만,
장면마다 형식별 제약을 따로 쓰게 되어 템플릿 하나의 코드량이 형식
수만큼 늘어난다.

## 함정

### 확인하지 않은 시각 평가를 믿는 것

글은 렌더된 결과를 검사하지 않은 에이전트가 “애니메이션이 훌륭해 보인다”고
말하는 것을 믿지 말라고 한다.
이 함정은 에이전트가 코드를 읽고 결과를 상상해 보고하는 경우에 생긴다.
보고서에 검사한 시각이 없으면 검사하지 않은 것으로 취급해야 한다.

### 한 번의 프롬프트라는 서사

글은 한 번에 끝난 사례만 보고 기대하지 말라는 반례를 든다.
수채화 단편 영화를 올린 @mablesjoseph의 제작자가 모델 호출 163번과 몇 시간의
작업을 보고했다는 것이다.
이 숫자는 글의 서술이며, 글에 삽입된 트윗에서는 이 숫자가 보이지 않아 이 문서가
확인하지 못했다.
삽입된 트윗은 한 번에 완벽하게 나오지는 않고 좋은 지원 프로젝트가
필요하다고 말한다.

### 라이선스를 확인하지 않고 렌더링 서비스를 파는 것

글은 Remotion이 개인과 3명 이하 팀에게 무료 상업 이용을 허용하지만 더 큰 팀과
일부 자동화 구성에는 다른 요건이 있다고 말한다.
Remotion의 라이선스 문서는 무료 대상을 개인, 직원 3명 이하의 영리 조직,
비영리 조직, 상업적으로 쓰기 전에 적합성을 평가하는 사람으로 적고,
그 밖의 조직은 회사 라이선스가 필요하다고 한다.[^remotion-license]
같은 문서는 Remotion 5.0에서 라이선스가 조금 바뀔 것이라고 예고하고,
Remotion 코드를 복사하거나 고쳐서 자기 파생물을 판매하는 것을
금지한다.[^remotion-license]
글이 말한 “일부 자동화 구성”에 대한 요건은 이 문서가 읽은 라이선스 문서에서 찾지
못했고, FAQ는 열어 보지 않았다.
고객의 로고, 영상, 글꼴, 효과음, 음악에 대한 권리도 자동화가 면제해 주지
않는다는 글의 경고는 그대로 유효하다.

## 비평

### “$$$”라는 제목은 본문이 뒷받침하지 않는다

제목은 수익을 약속하지만 본문의 수익 계산은 가정이다.
750달러짜리 패키지 두 개가 총 매출 1,500달러라는 계산은 세금, 소프트웨어,
컴퓨팅, 오디오 라이선스, 영업 시간, 수정에 들어가는 비용을 빼기 전의 숫자라고
글이 밝히고, 시장 가격이나 보장된 수익이 아니라고도 쓴다.
글에 고객을 확보한 경로나 실제로 판 사례,
한 편당 모델 호출 비용은 나오지 않는다.
저자가 제시하는 “측정할 지표” 목록(첫 디자인에 걸린 시간, 변형 하나당 시간,
렌더링과 API 비용, 수정 요청, 납품 오류, 재구매 고객)은 맞지만,
저자 자신의 수치는 하나도 없다.

### 가장 강한 증거가 가격을 떨어뜨리는 쪽을 가리킨다

글이 사업 가능성의 증거로 삽입한 사례 가운데 Tony Dinh의 트윗은 1년 전에는 이런
영상에 1,000달러 넘게 냈는데 지금은 Opus 5.5로 30분 안에 만들었다고 말한다.
이 사례는 능력의 증거이지만, 같은 사실이 납품물의 가격이 내려가고 있다는
증거이기도 하다.
고객이 직접 30분 안에 만들 수 있는 것을 750달러에 파는 모델은 고객의 능력이
오르는 속도와 경쟁해야 한다.
글은 이 긴장을 다루지 않고, 결과물이 아니라 공정을 판다는 방향으로만 나아간다.

### 이 글이 증명하는 것은 기술의 가능성이지 시장의 존재가 아니다

저자 스스로 삽입한 예들이 모든 사람이 즉시 수익 사업을 만들 수 있음을 증명하지
않는다고 인정한다.
그럼에도 본문의 제안(유료 패키지의 구성, 가격,
첫 단계)은 시장이 있다는 전제 위에 쓰였다.
이 결론을 바꿀 관찰은 한 가지이다.
같은 공정으로 실제 고객에게 유료 납품을 몇 건 한 기록,
곧 매출과 비용과 수정 횟수가 나오면 전제가 시험된다.

## 기억할 원칙

### 입력을 거부하는 시스템이 틀린 영상을 아름답게 만드는 시스템보다 낫다

글에서 가장 옮겨 쓸 만한 문장은 생산 시스템이 잘못된 입력은 거부해야 하고,
잘못된 정보를 담은 아름다운 영상을 만들어서는 안 된다는 것이다.
승인된 주장만 쓰고 자산이 없으면 멈추는 검증은 영상뿐 아니라 에이전트가 만드는
모든 산출물의 기본 구조가 된다.
입력 검증이 렌더 앞에 있으면 비싼 단계를 지나서 틀린 것을 발견하는 일이 없다.

### 프레임이 시간의 순수 함수이면 검사와 병렬화가 같은 성질에서 나온다

임의의 시각을 바로 그릴 수 있다는 성질은 글이 말한 대로 수정 가능성을 주고,
이 문서의 해석으로는 두 가지를 더 준다.
어느 시각의 프레임이든 골라 검사할 수 있으므로 접촉 시트와 전환 직전 직후
표본이 값싸진다.
프레임이 서로 의존하지 않으므로 프레임 범위를 여러 작업자에게 나누어 맡기고
실패한 구간만 다시 돌릴 수도 있다.
이 두 번째는 글에 없는 추론이며 이 문서가 시험하지 않았다.
