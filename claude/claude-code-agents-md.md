# Claude Code가 AGENTS.md를 읽기 시작했다

트윗: [We're adding support for AGENTS.md to Claude Code](https://twitter.com/trq212/status/2101009392611278961)

HN 토론: <https://news.ycombinator.com/item?id=49760187> (715점, 270개 댓글)

## 요약

Anthropic의 Thariq가 2026년 9월 18일에 올린 트윗으로 발표된 변경이다.
Claude Code 2.1.277부터 폴더에 `CLAUDE.md`가 없으면 `AGENTS.md`를 찾아 쓰며,
이 동작은 `/config`에서 바꿀 수 있다.

후속 트윗이 더 중요한 내용을 담고 있다.
`AGENTS.md` 지원이 Claude Code mods 위에 구현되었다는 것이다.
mods는 Claude Code 하네스를 사용자가 고칠 수 있게 만드는 예정된 방식이고,
이번 기능은 그 위에 얹힌 내장 mod이며,
앞으로는 프로젝트 지침을 읽는 방식 자체를 사용자가 직접 만들 수 있게 된다.

즉 발표의 표면은 파일 이름 하나를 더 읽는다는 것이지만,
실질은 지침 로딩이 엔진의 고정 기능에서 교체 가능한 플러그인으로 옮겨 갔다는 것이다.

## 네 가지 모드

mod의 소스가 공개되어 있어 동작을 정확히 확인할 수 있다.
옵션 하나인 `instructionFiles`가 네 값을 가진다.

| 값                        | 동작                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------- |
| `claude-md`               | 오늘까지처럼 엔진이 `CLAUDE.md`만 읽는다. 플러그인은 아무것도 더하지 않는다             |
| `claude-md-or-agents-md`  | 기본값. 프로젝트에 자체 지침 파일이 없을 때만 `AGENTS.md`를 대신 읽는다                 |
| `claude-md-and-agents-md` | 트리 위아래의 모든 `AGENTS.md`를 `CLAUDE.md` 옆에 함께 읽는다                           |
| `managed-only`            | 프로젝트와 개인의 지침 파일을 컨텍스트에서 빼고 조직의 관리 파일과 엔진 메모리만 남긴다 |

기본값의 조건이 생각보다 까다롭다.
자체 지침 파일이 있는지는 엔진이 컨텍스트를 위해 무엇을 불러왔는지로 판정한다.
루트에서 작업 디렉터리까지 어느 경로에든 `CLAUDE.md`나 `.claude/CLAUDE.md`나 `CLAUDE.local.md`가 있으면
프로젝트 전체를 엔진에 맡기고 플러그인은 빠진다.
반면 조직의 관리 파일, 개인의 `~/.claude/CLAUDE.md`, `.claude/rules` 파일,
추가된 디렉터리의 `CLAUDE.md`는 이 판정에 들어가지 않는다.
중첩 탐색이 그것들을 보지 못하기 때문이다.

함께 읽는 모드에서는 중복 방지가 들어 있다.
`CLAUDE.md`가 이미 `@`로 가져온 파일이거나 링크인 파일은 두 번 읽지 않으며,
경로로 먼저 비교하고 그다음 내용으로 비교한다.

## 하위 디렉터리와 Read

모노레포에서 중요한 부분은 `Read` 훅이다.
파일을 읽을 때 루트와 그 파일 사이에 있는 디렉터리들의 `AGENTS.md`가 붙는다.
엔진이 중첩된 `CLAUDE.md`에 대해 하는 것과 같은 방식이며,
같은 디렉터리의 `CLAUDE.md`가 그 자리를 차지하고 있으면 붙지 않는다.
붙는 형식도 엔진과 바이트 단위로 같다.

세션 루트는 살아 있는 값으로 읽는다.
`/cd`나 호스트의 디렉터리 변경이나 워크트리 이동을 따라가며,
루트가 바뀌면 이미 전달한 파일 집합과 대체 여부 판정을 처음부터 다시 시작한다.
각 파일은 에이전트 루프와 대화당 한 번만 붙고,
압축이나 `/clear` 뒤 컨텍스트가 다시 계산되면 그 횟수도 초기화된다.

`Agent` 도구가 시작하는 포크는 부모의 프롬프트 접두부를 공유하므로
부모 루프에 이미 전달된 중첩 파일을 포크 루프로 복사하고 다시 붙이지 않는다.
다만 `/fork`나 `/subtask`로 만드는 포크는 아직 해당 이벤트를 일으키지 않아 빈 집합에서 시작한다.

## 설정하기

내장 플러그인이므로 `/config`의 “Project instructions” 행에서 네 값을 고르면 된다.
직접 쓰려면 사용자 설정에 이렇게 넣는다.

```json
{
  "pluginConfigs": {
    "agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}
```

주의할 점이 몇 가지 있다.
프로젝트의 `.claude/settings.json`은 플러그인 옵션을 위해 읽지 않는다.
값을 바꾸면 모듈이 다시 로드되고, 그다음에 엔진이 만드는 컨텍스트부터 새 모드가 적용된다.
네 값 밖의 값을 손으로 적으면 한 번 알려 주고 기본값으로 읽는다.

옵션 이름이 한 번 바뀌었다는 점도 기록되어 있다.
처음에는 `projectInstructions`였고 값이 `claude`, `agents-fallback`, `both`, `none`이었다.
옛 키에 저장된 값은 당분간 존중되며 각각 새 값으로 대응된다.
다만 `none`은 `managed-only`로, `claude`는 `claude-md`로 읽히고,
네 값 밖의 값은 `claude-md`로 읽혀 아무것도 더하지 않는다.
기본값으로 읽히지 않는다는 점이 중요하다.

`/plugin`에서 이 플러그인을 끌 수 있고, 끄면 엔진은 `CLAUDE.md`만 읽는다.
`disableAllHooks`나 `--bare` 같은 설정은 내장 플러그인을 끄지 못한다.

## 무엇을 기록하는가

로그에 대한 서술이 이 문서에서 눈여겨볼 부분이다.
개수와 닫힌 선택지만 기록하며 경로와 파일 내용은 남기지 않는다.
모든 행은 텔레메트리 플러그인을 통해 나가므로 그 플러그인이 없으면 흔적 없이 사라진다.

플러그인이 `$`에서 호출하는 것도 목록으로 제한되어 있다.
`fs.ancestors`, `session.root`, `session.cwd`, `env.get`, `ui.log`,
그리고 텔레메트리 관련 호출이 전부다.

## 분석

### 파일 이름 문제가 아니라 하네스 확장 지점의 문제였다

`AGENTS.md`를 읽는 일 자체는 기술적으로 사소하다.
그래서 지연이 더 눈에 띄었고 비판의 표적이 되었다.
그런데 실제로 출시된 것은 파일 이름 하나가 아니라
프로젝트 지침 로딩을 담당하는 교체 가능한 플러그인이다.

이 구분이 중요한 이유는 앞으로의 변경 비용이 달라지기 때문이다.
지침을 읽는 방식이 엔진에 고정되어 있으면 새 규칙마다 본체를 고쳐야 하지만,
훅으로 열려 있으면 조직이나 개인이 자기 규칙을 얹을 수 있다.
README가 조직이 앞에 둔 플러그인이 이 플러그인 위에 앉아 파일에 대한 최종 결정권을 갖는다고 명시한 것도 같은 맥락이다.

다만 이 설명은 지연의 이유가 되지 못한다.
확장 지점을 만드는 동안 심볼릭 링크 한 줄로 되는 일을 사용자가 계속 해야 했다는 사실은 그대로 남는다.

### 기본값이 대체가 아니라 양보로 설계되었다

기본값인 `claude-md-or-agents-md`는 `CLAUDE.md`가 있으면 `AGENTS.md`를 아예 보지 않는다.
두 파일을 함께 쓰려면 사용자가 모드를 바꿔야 한다.

이 선택은 기존 사용자의 동작을 바꾸지 않겠다는 원칙에서 나왔을 것이다.
그러나 실제 상황에서는 어색한 결과를 만든다.
여러 에이전트를 함께 쓰는 팀은 대개 두 파일을 모두 갖고 있고,
그 경우 기본값에서는 여전히 `AGENTS.md`가 무시된다.

HN에서 bryanhogan이 지적한 기존 우회법이 이 지점에서 여전히 유효하다.
`CLAUDE.md`에 `@AGENTS.md` 한 줄만 넣는 방식이며, 그는 이번 변경도 좋은 변화라고 덧붙였다.[^bryanhogan]
bengt는 한 걸음 더 나아가 그 방식이 지금도 더 낫다고 주장한다.
예전에는 심볼릭 링크를 썼지만 `@AGENTS.md` 아래에 Claude 전용 지시를 덧붙이는 구성이 최선이라는 것이다.[^bengt]

### 경쟁 압력이 먼저였다

HN의 반응에서 가장 자주 반복된 것은 이 변경이 선의가 아니라 압력의 결과라는 진단이다.

throwaw12은 커뮤니티를 돕고 싶어서가 아니라 커뮤니티가 화가 났고
다른 하네스로 사용자를 잃고 있었기 때문이라고 적었다.[^throwaw12]

Astra가 Codex 쪽으로 큰 이동을 만들어 낸 것이 항복을 끌어냈다고 본다.
그리고 몇 달 지나면 대부분이 이 소동을 잊을 테니 결과적으로는 버틴 것이 이득이었을지도 모른다고 씁쓸하게 덧붙인다.[^deaux]

### 읽는 것과 따르는 것은 다르다

더 깊은 비판은 boorang이 제기했다.

그 끝에 이 컨텍스트가 작업과 관련이 있을 수도 없을 수도 있으니
매우 관련 있지 않다면 반응하지 말라는 문구가 붙는다는 것이다.
그는 Codex가 `AGENTS.md`를 훨씬 잘 따르며,
Claude Code는 이 문구로 사용자들이 `CLAUDE.md`를 필수 지시로 받아들이지 않게 밀어냈다고 본다.
관련 버그는 계획 없음으로 닫혔고, 시스템 프롬프트를 최근 분석한 바로는

### 설정이 지침을 덮어쓰는 구조에 대한 불만

경험이 엇갈린다는 사실 자체가 이 층위의 동작이 예측 가능하지 않다는 증거다.

## 인사이트

### 공용 이름은 표준이 아니라 협상의 결과다

`AGENTS.md`는 표준화 기구가 정한 것이 아니라 여러 도구가 같은 이름을 쓰기 시작하면서 생긴 관행이다.
그 관행에 마지막으로 합류한 쪽이 시장에서 가장 강한 위치에 있던 도구였다는 사실이
이 사건의 구조를 설명한다.

전용 이름을 유지하는 것은 사용자가 다른 도구로 옮길 때 마찰을 만든다.
그 마찰이 이득인 동안에는 유지되고, 사용자가 그 마찰 때문에 떠나기 시작하면 철회된다.
그러므로 공용 이름 지원 여부는 기술적 판단이 아니라 그 시점의 교섭력을 드러내는 지표다.

이 관점은 다음 항목을 예측하는 데도 쓰인다.
스킬 디렉터리, 훅 규격, 도구 정의 형식처럼
아직 각자의 이름을 쓰는 영역이 다음 교섭 대상이며,
그 순서는 사용자가 어느 마찰을 가장 크게 느끼는지에 따라 정해질 것이다.

### 컨텍스트에 넣는 것과 지시로 대우하는 것을 분리해서 봐야 한다

이번 발표는 어떤 파일을 컨텍스트에 넣을지를 바꿨고, 그 파일을 어떻게 대우할지는 바꾸지 않았다.
시스템 리마인더에 관련 없으면 반응하지 말라는 문구가 붙어 있는 한,
파일 이름이 무엇이든 그 내용은 참고 자료로 제시된다.

이 구분은 에이전트에게 규칙을 주는 모든 상황에 적용된다.
규칙이 지켜지지 않을 때 물어야 할 질문은 둘이다.
그 내용이 컨텍스트에 실제로 들어갔는가와,
들어간 뒤 어떤 틀로 감싸여 제시되었는가다.
전자는 로그로 확인할 수 있지만 후자는 대개 확인할 수 없으며,
그래서 같은 파일이 도구마다 다르게 지켜진다.

### 설정과 문서가 같은 것을 두고 다툴 때는 설정이 이긴다

`settings.json`의 값이 `CLAUDE.md`의 문장을 덮어쓴다는 관찰은
사람이 쓴 지침과 기계가 읽는 설정이 같은 결정을 다룰 때 무엇이 우선하는지를 보여 준다.
설정은 명시적이고 파싱 가능하며 기본값을 갖지만,
문서는 해석되어야 하고 관련성 판정을 거친다.

그러므로 반드시 지켜야 하는 항목은 문서가 아니라 설정으로 표현해야 한다.
문서에 적은 규칙은 모델이 읽고 판단하는 대상이고,
설정에 적은 값은 하네스가 실행하는 대상이다.
둘의 내용이 어긋났을 때 사용자가 겪는 혼란은
규칙이 무시되었다는 형태로 나타나지만 실제 원인은 층위의 차이에 있다.
