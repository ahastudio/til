# Claude Code 데이터 사용: 계정 유형이 학습과 보존 기간을 정하고, 환경 변수 몇 개가 외부 전송을 정한다

<https://code.claude.com/docs/en/data-usage>

HN 토론: <https://news.ycombinator.com/item?id=49056689> (15점, 1개 댓글)

## 소개

Anthropic의 Claude Code 공식 문서 가운데 데이터 사용 페이지는 세 가지를 답한다.
내 대화가 모델 학습에 쓰이는가, 얼마나 오래 보관되는가,
Claude Code가 모델 호출 말고 어디로 무엇을 보내는가이다.
이 문서는 그 페이지의 규칙을 계정 유형별로 정리하고,
실제로 무엇을 끄고 무엇을 확인해야 하는지를 적는다.
규칙은 모두 Anthropic이 문서에서 밝힌 정책이며,
이 문서가 서버 쪽 동작을 직접 시험해 확인한 것은 아니다.

## 동작 방식

### 학습에 쓰이는가는 계정 유형이 정한다

개인 계정(Free, Pro, Max, Ultra)은 사용자가 선택하는 구조이다.
설정이 켜져 있으면 Claude Code에서 한 대화도 새 모델 학습에 쓰인다고 Anthropic이 밝힌다.
상용 계정(Team, Enterprise, API, 서드파티 플랫폼, Claude Gov)은
상용 약관에 따라 Claude Code로 보낸 코드와 프롬프트로 생성형 모델을 학습하지 않는다.
단, 고객이 Development Partner Program처럼 데이터를 제공하는 경로를 직접 택했다면 예외이다.
이 프로그램은 조직 관리자만 가입할 수 있고,
Anthropic 직접 API에서만 열려 있으며 Amazon Bedrock이나 Google Cloud 사용자에게는 없다.

### 보존 기간은 학습 허용 여부와 계약이 정한다

| 계정                        | 보존 기간                      |
| --------------------------- | ------------------------------ |
| 개인, 학습 허용             | 5년                            |
| 개인, 학습 불허             | 30일                           |
| 상용(Team, Enterprise, API) | 기본 30일                      |
| 상용, ZDR 계약              | 응답을 돌려준 뒤 저장하지 않음 |

개인 계정의 설정은 claude.ai의 개인정보 설정 화면에서 언제든 바꿀 수 있다.
같은 5년이라도 의미가 다르다.
학습을 허용한 개인 계정은 모델 개발과 안전 개선을 위해 5년 보관되고,
`/feedback`으로 보낸 대화는 계정 유형과 무관하게 5년 보관된다.

### 로컬에는 평문 대화록이 남는다

Claude Code 클라이언트는 세션 대화록을 홈 디렉터리의 `~/.claude/projects/` 아래에
평문으로 저장하고, 기본 30일 뒤에 지운다.
기간은 `cleanupPeriodDays` 설정으로 바꾼다.
Claude Desktop이나 Cowork에서 시작했거나 마지막으로 이어 간 세션의 대화록은
이 한도에서 기본적으로 빠진다.
서버 쪽 보존 정책과 별개의 사본이므로,
서버에서 지워도 로컬 파일은 남는다는 점을 따로 관리해야 한다.
이 30일 삭제는 놀라움을 사는 지점이기도 하다.
이 페이지가 HN에 올라온 글의 제목은 Claude Code가 30일 뒤 기기의 대화 기록을 지운다는 내용이고,
달린 댓글은 하나뿐인데 `cleanupPeriodDays`를 9999로 두라는 설정 한 줄이었다.[^bam]
큰 값을 넣으면 평문 대화록이 그만큼 오래 로컬에 남는다는 뜻이므로,
기록을 오래 쓰고 싶은 마음과 로컬 노출을 줄이고 싶은 마음 사이에서 기간을 정해야 한다.

### 클라우드 세션은 서버가 대화록을 가진다

Anthropic이 운영하는 가상 머신에서 도는 클라우드 세션은
저장소를 격리된 VM에 복제하고, 나중에 돌아올 수 있도록 대화록을 서버에 저장한다.
GitHub 자격 증명은 서버에 암호화되어 저장되고 VM에는 들어가지 않으며,
VM의 GitHub 통신은 Anthropic 프록시가 서버 쪽에서 자격 증명을 붙여 전달한다.
외부로 나가는 모든 통신은 감사 기록과 악용 방지를 위한 보안 프록시를 지난다.
개별 클라우드 세션은 언제든 지울 수 있고, 지우면 세션의 이벤트 데이터가 영구히 사라진다.
Remote Control 세션은 실행이 내 기기에서 일어나므로 로컬 흐름을 따르지만,
연결된 동안에는 기기 사이에 대화를 동기화하려고 대화록이 서버에도 저장된다.

### 전송 중과 저장 중의 암호화

모델과 주고받는 프롬프트와 출력은 TLS 1.2 이상으로 전송된다.
저장 중 암호화는 모델 제공자가 정한다.

| 제공자                      | 저장 중 암호화                                     |
| --------------------------- | -------------------------------------------------- |
| Anthropic API               | 디스크 수준 AES-256, ZDR을 켜면 서버에 남기지 않음 |
| Amazon Bedrock              | AWS 관리 키로 AES-256, 고객 관리 키는 KMS로 가능   |
| Google Cloud Agent Platform | Google 관리 키, 고객 관리 키(CMEK) 가능            |
| Microsoft Foundry           | 호스팅 방식에 따라 다름                            |

Foundry는 Azure에서 호스팅하는 배포라면 프롬프트와 응답이 Azure 안에 머물고,
사용량 메타데이터와 Anthropic 안전 시스템이 표시한 내용만 Anthropic으로 나간다.
Anthropic에서 호스팅하는 배포는 Anthropic 인프라로 라우팅된다.

## 외부로 나가는 것

### 두 가지 운영 텔레메트리

| 종류      | 내용                                                                                  | 끄는 법                     |
| --------- | ------------------------------------------------------------------------------------- | --------------------------- |
| 지표      | 지연, 안정성, 사용 패턴. 코드와 프롬프트와 파일 경로는 포함하지 않음                  | `DISABLE_TELEMETRY=1`       |
| 오류 보고 | Claude Code 내부의 오류 메시지와 스택 트레이스. 비밀과 경로와 이메일은 전송 전에 가림 | `DISABLE_ERROR_REPORTING=1` |

지표는 Anthropic과 서드파티 로깅 인프라로, 오류 보고는 서드파티 오류 추적 서비스로 간다.
오류 보고는 네 조건이 모두 맞을 때만 켜진다.
Pro, Max, Ultra 구독으로 로그인했고, Claude Code가 v2.1.198 이상이며,
Claude API에 직접 연결되고, 조직에 ZDR이나 HIPAA 계약이 없을 때이다.
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`를 설정하면 필수가 아닌 통신이 한꺼번에 꺼진다.

### `/feedback`은 대화 기록과 코드를 보낸다

`/feedback`을 실행하면 코드를 포함한 대화 기록의 사본이 Anthropic으로 가고,
`/bug`와 `/share`도 같은 경로를 쓴다.
전송 전에 현재 세션만, 또는 같은 프로젝트의 지난 24시간이나 7일치 다른 세션까지
포함할지를 고른다.
데이터는 TLS로 전송되어 Google Cloud Storage에 저장되고,
선택에 따라 공개 저장소에 GitHub 이슈가 만들어진다.
보고서는 5년 보관된다.
끄려면 `DISABLE_FEEDBACK_COMMAND=1`을 설정한다.
Claude가 초안을 만들어 대기열에 올리는 방식도 같은 경로와 보존 기간을 쓰지만,
사용자가 보내기를 고르기 전에는 아무것도 전송되지 않는다고 문서가 적는다.
Bedrock 같은 서드파티 제공자나 Anthropic 자격 증명이 없을 때는 서버로 보내지 않고
`~/.claude/feedback-bundles/`에 로컬 파일로 쓴다.
이 경우 알려진 API 키와 토큰 패턴은 가린 뒤 저장하고,
그 파일을 Anthropic 담당자나 지원 요청에 직접 첨부해야 비로소 데이터가 기기를 떠난다.

### 세션 품질 설문은 두 단계이다

“How is Claude doing this session?” 질문에 응답하거나 닫는 것은 평점만 기록한다.
그 뒤에 따로 뜨는 “Anthropic이 대화록을 봐도 되는가” 질문이 별개의 두 번째 단계이다.
Yes를 고르면 대화록, 서브에이전트 대화록, 디스크의 원본 세션 로그가 Anthropic으로 올라간다.
알려진 API 키와 토큰 패턴은 올리기 전에 가리지만,
소스 코드와 파일 내용과 나머지 대화는 그대로 올라간다.
올라간 대화록은 최대 6개월 보관되고 학습 설정에 영향을 주지 않으며 학습에 쓰이지 않는다.
No와 “Don't ask again”은 아무것도 보내지 않는다.
설문은 `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1`로 끄고,
`feedbackSurveyRate`에 0과 1 사이의 확률을 넣어 빈도만 줄일 수도 있다.

### WebFetch는 호스트 이름을 먼저 보낸다

WebFetch 도구는 URL을 가져오기 전에 호스트 이름을 `api.anthropic.com`으로 보내
Anthropic이 관리하는 차단 목록과 대조한다.
전체 URL과 경로와 페이지 내용은 보내지 않는다.
통과한 호스트 이름은 5분 동안 캐시되고, 차단되거나 실패한 호스트는 다음 요청에서 다시 확인한다.
이 검사는 모델 제공자와 무관하게 돌며 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`로도 꺼지지 않는다.
`api.anthropic.com`이 막힌 네트워크에서는 WebFetch가 실패하므로,
도메인을 허용하거나 설정에서 `skipWebFetchPreflight: true`를 쓴다.
검사를 끄면 차단 목록 없이 모든 URL을 가져오려 하므로 `WebFetch` 권한 규칙과 함께 써야 한다.

### 제공자별 기본값

| 서비스               | Claude API  | Bedrock, Vertex, Foundry, AWS 플랫폼 |
| -------------------- | ----------- | ------------------------------------ |
| 지표                 | 기본 켜짐   | 기본 꺼짐                            |
| 오류 보고            | 조건부 켜짐 | 기본 꺼짐                            |
| `/feedback` 보고     | 기본 켜짐   | 기본 꺼짐(로컬 파일)                 |
| 세션 품질 설문       | 기본 켜짐   | 기본 켜짐                            |
| WebFetch 도메인 검사 | 기본 켜짐   | 기본 켜짐                            |

서드파티 제공자에서도 꺼지지 않는 것이 둘 있다.
설문과 WebFetch 검사이다.
호스트 플랫폼이 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`를 설정하면
서드파티 제공자에서도 지표가 기본 켜짐이 되고 표준 옵트아웃을 따른다.
공식 플러그인 마켓플레이스의 자동 설치는 따로
`CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL`로 끈다.

## 값 정하기

### 개인 계정이라면 학습 설정부터 정한다

개인 계정에서 정할 값은 학습 허용 여부 하나이다.
허용하면 보존이 5년이 되고, 불허하면 30일이 된다.
이 선택은 Claude Code로 한 일의 코드와 프롬프트에도 적용된다.
회사 코드를 개인 구독으로 다룬다면 이 설정이 곧 회사 코드의 운명을 정한다.
그래서 업무 코드는 상용 계약 계정으로 옮기거나, 적어도 학습을 불허로 두는 것이 문서가 허용하는 가장 안전한 쪽이다.

### 외부 전송을 줄이려면 변수를 한꺼번에 설정한다

| 목표                       | 설정                                         |
| -------------------------- | -------------------------------------------- |
| 필수가 아닌 통신 전부 끄기 | `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` |
| 지표만 끄기                | `DISABLE_TELEMETRY=1`                        |
| 오류 보고만 끄기           | `DISABLE_ERROR_REPORTING=1`                  |
| `/feedback` 끄기           | `DISABLE_FEEDBACK_COMMAND=1`                 |
| 설문만 끄기                | `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1`      |
| WebFetch 검사 끄기         | `skipWebFetchPreflight: true`(settings)      |

이 값들은 `settings.json`에도 넣어 저장소에 함께 두면 팀이 같은 설정을 쓸 수 있다.
다만 `DISABLE_TELEMETRY`나 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`는
기능 플래그 평가도 같이 꺼서 Remote Control을 쓸 수 없게 만들 수 있다.
`DISABLE_ERROR_REPORTING`은 그렇지 않다.

### 서버에 아무것도 남기지 않으려면 ZDR이다

ZDR(Zero Data Retention)은 Claude for Enterprise의 자격을 갖춘 계정에 주어진다.
켜지면 프롬프트와 응답은 실시간으로 처리되고,
응답을 돌려준 뒤에는 법적 의무나 악용 대응이 필요한 경우를 빼면 저장되지 않는다.
표준 Enterprise 플랜에는 포함되지 않고 관리자 설정에서 켤 수 없으며,
조직마다 Anthropic 계정 팀이 따로 켠다.
새 조직을 만들면 같은 계정 아래라도 ZDR이 자동으로 적용되지 않는다.[^zdr]

ZDR이 보호하는 것은 ZDR 조직으로 인증한 요청뿐이다.
개발자가 개인 계정이나 다른 조직의 API 키로 로그인하면 그 세션은 보호받지 못한다.
이를 막으려면 관리형 설정의 `forceLoginMethod`와 `forceLoginOrgUUID`로
로그인을 조직으로 제한한다.[^zdr]

## 트레이드오프

### ZDR을 켜면 쓸 수 없는 기능이 생긴다

서버에 대화를 남기지 않는 계약은 서버가 대화를 가져야 하는 기능과 양립하지 않는다.
ZDR 조직에서는 백엔드에서 다음 기능이 막힌다.
클라우드 세션, Chat과 Cowork 통합, Claude Tag, Claude Code의 Artifacts,
Claude Docs, `/feedback`과 `/bug`와 `/share`, Remote Control이다.
클라이언트 화면에 보이더라도 쓰면 조직 정책이 허용하지 않는다는 오류가 난다.
문서는 앞으로 프롬프트와 응답을 저장해야 하는 기능이 새로 나오면 그것도 막힐 수 있다고 적는다.[^zdr]
따라서 ZDR은 한 번 정하고 잊는 설정이 아니라,
새 기능이 나올 때마다 그 기능이 서버에 무엇을 남기는지를 따져야 하는 계약이다.

모델 제약도 있다. Fable 5.2, Fable 5.1, Fable 5는 기본적으로 데이터 보존을 요구하는
Covered Models이므로, ZDR 조직이나 워크스페이스에서 쓸 수 있는지는
Claude Code가 아니라 Covered Models 정책이 정한다.
쓸 수 없는 조직에서는 `/model` 선택기에서 빠지거나 비활성으로 보이고
서버가 요청을 거부한다.[^zdr]

### 보호받지 못하는 것도 남는다

ZDR이어도 claude.ai 채팅, Cowork, Artifacts, 분석 대시보드의 메타데이터,
계정과 좌석 같은 관리 데이터, 서드파티 도구와 MCP 서버가 처리한 데이터는
표준 보존 정책을 따른다.
분석 대시보드는 프롬프트와 응답은 저장하지 않지만 계정 이메일과 사용 통계는 모은다.
정책 위반으로 표시된 세션의 입력과 출력은 ZDR에서도 최대 2년 보관될 수 있다.[^zdr]
“아무것도 남지 않는다”는 말은 모델 추론 호출에 한정된 약속이다.

### 로컬 평문 대화록이 서버 정책의 바깥에 있다

서버 정책이 아무리 엄격해도 `~/.claude/projects/`의 평문 대화록은 로컬에 남는다.
ZDR 계약도 이 파일을 지우지 않는다.
기기가 도난당하거나 백업이 외부로 나가면 서버 정책과 무관하게 코드와 대화가 노출된다.
`cleanupPeriodDays`로 기간을 줄이고, 민감한 작업 뒤에는 세션을 직접 지우는 것이 문서가 제공하는 수단이다.

## 함정

- 설문의 Yes는 가볍게 누르는 확인이 아니다.
  대화록 전체와 원본 세션 로그가 올라가고, 소스 코드와 파일 내용은 가려지지 않는다.
- 서드파티 제공자를 쓰면 텔레메트리가 꺼진다는 말을 설문과 WebFetch 검사까지로 넓히면 틀린다.
  둘은 제공자와 무관하게 돈다.
- `DISABLE_TELEMETRY`를 켠 뒤 Remote Control이 사라졌다면 기능 플래그 평가가 꺼진 탓일 수 있다.
- `/feedback`의 기본값은 현재 세션만이지만, 선택 화면에서 지난 7일치 다른 세션까지 고를 수 있다.
  다른 프로젝트가 아니라 같은 프로젝트의 세션이다.
- 개인 계정의 학습 설정은 설문의 대화록 업로드와 별개이다.
  업로드한 대화록은 학습 설정에 영향을 주지 않는다고 문서가 적는다.
- 상용 계정에서 학습하지 않는다는 약속과 보존하지 않는다는 약속은 다르다.
  상용 기본값은 30일 보존이고, 저장하지 않는 것은 ZDR뿐이다.

## 체크리스트

- [ ] 어떤 계정으로 로그인했는지 확인한다. 개인인가, 상용인가, 제공자 직접 연결인가.
- [ ] 개인 계정이라면 학습 허용 설정을 확인한다.
- [ ] 업무 코드를 개인 구독으로 다루고 있지 않은지 확인한다.
- [ ] 조직이라면 `forceLoginOrgUUID`로 ZDR 조직 로그인을 강제했는지 확인한다.
- [ ] `~/.claude/projects/`의 보관 기간을 `cleanupPeriodDays`로 정했는지 확인한다.
- [ ] 텔레메트리, 오류 보고, `/feedback`, 설문을 각각 끌지 정했는지 확인한다.
- [ ] 방화벽이 `api.anthropic.com`을 막는다면 WebFetch 검사를 어떻게 처리할지 정했는지 확인한다.
- [ ] ZDR을 쓴다면 막히는 기능 목록이 팀의 작업 방식과 충돌하지 않는지 확인한다.

## 비평

### 문서가 정책의 경계를 한 페이지에 모으지 않는다

학습, 보존, 전송, 암호화의 규칙이 계정 유형과 제공자와 기능에 따라 갈라져 있다.
개인과 상용, 직접 API와 Bedrock, 로컬과 클라우드, 설문과 `/feedback`의 조합이 많아서
자기 상황에 해당하는 값을 찾으려면 여러 표와 문단을 오가야 한다.
이 문서가 표를 다시 만든 이유도 그 때문이다.
공식 문서의 서술은 정책을 정확히 적지만 읽는 사람이 자기 조합을 직접 풀어야 한다.

### 보증의 범위가 서버 쪽에 한정된다

문서가 주는 보증은 Anthropic의 서버 쪽 행동에 대한 약속이다.
서드파티 오류 추적 서비스와 로깅 인프라가 누구인지, 그곳의 보존 기간이 얼마인지는
이 페이지에 적혀 있지 않다.
지표와 오류 보고가 “서드파티”로 간다고만 하므로, 외부 전송을 평가해야 하는 조직은
다른 문서나 계약에서 그 답을 찾아야 한다.
이 문서도 그 경로를 열어 보지 않았다.

### 검증할 수 있는 방법이 거의 없다

정책이 말하는 대로 동작하는지를 사용자가 확인할 수단은 제한된다.
전송 내용은 TLS로 암호화되어 있어 네트워크 수준에서 내용을 볼 수 없고,
서버의 보존과 학습은 외부에서 관찰할 수 없다.
ZDR 같은 계약은 감사 기록과 신뢰 센터 자료에 기대는 구조이다.
따라서 이 페이지는 정책 선언이며 검증된 사실이 아니라는 점을 문서가 스스로 구분하지 않는다.

## 기억할 원칙

### 데이터 정책은 계정과 제공자의 곱으로 읽는다

같은 Claude Code라도 어떤 계정으로, 어떤 제공자를 거쳐, 어떤 기능을 쓰느냐에 따라
학습, 보존, 전송의 규칙이 달라진다.
설정을 바꾸기 전에 현재 조합을 먼저 알아내야 한다.

### 서버 정책과 로컬 파일은 따로 관리한다

서버에서 보존하지 않는다는 약속과 내 기기에 평문 대화록이 남는다는 사실은 서로 무관하다.
둘 다 정해야 데이터 경계를 정했다고 말할 수 있다.

### 끄는 변수는 부작용까지 같이 읽는다

텔레메트리를 끄면 기능 플래그 평가가 꺼져 일부 기능이 사라질 수 있다.
외부 전송을 줄이는 설정은 어떤 기능과 맞바꾸는지를 확인한 뒤에 넣는다.
