# Claude Code 플러그인 공식 개요: 무엇을 한 단위로 묶고, 무엇을 감수하나

원문: [Plugins overview - Claude Code Docs](https://code.claude.com/docs/en/plugins/overview)

## 소개

Claude Code 공식 문서의 플러그인 개요 페이지다.
Claude Code 플러그인은 스킬, 에이전트, 훅,
MCP 서버 같은 구성 요소를 담은 디렉터리이고,
Claude Code가 한 단위로 설치하고 불러온다.
대부분의 플러그인은 마켓플레이스에서 오며,
마켓플레이스는 플러그인 목록과 각 플러그인을 가져올 위치를 적은 카탈로그다.

문서는 헷갈리기 쉬운 경계도 먼저 긋는다.
claude.ai 채팅이나 Cowork의 플러그인은 claude.com 쪽 문서가 따로 다루고,
VS Code와 JetBrains에서 Claude Code를 쓰게
하는 확장은 Claude Code 플러그인이 아니다.

바로 써 보려면 터미널 세션에서 `/plugin`을 열고 Discover 탭에서 설치한다.
플러그인의 한 종류인 mod는 [mods 개요](mods-overview.md)에 따로 정리되어 있다.

## 구성 요소

플러그인은 구성 요소의 디렉터리이고,
보통 `.claude-plugin/plugin.json` 매니페스트가 있다.
매니페스트는 플러그인의 이름을 정하고 버전, 설명 같은 메타데이터를 더한다.

| 구성 요소 | 무엇인가                                                                             | 플러그인을 불러오면                                       |
| --------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| 스킬      | 필요할 때 Claude가 읽는 `SKILL.md` 지시. 명령으로도 실행할 수 있다                   | `skills/review/SKILL.md`가 `/my-plugin:review`로 실행된다 |
| 에이전트  | Claude가 일을 넘길 수 있는 서브에이전트 정의                                         | `agents/reviewer.md`가 서브에이전트가 된다                |
| 훅        | 매 편집 뒤처럼 수명 주기의 지점마다 Claude Code가 실행하는 명령                      | `hooks/hooks.json`의 훅이 이벤트마다 돈다                 |
| 훅 모듈   | JavaScript 함수로 쓴 훅. 창을 그리고 명령을 더할 수 있다. 이것이 있으면 mod라 부른다 | 세션 안에서 함수가 돈다                                   |
| MCP 서버  | 플러그인이 켜져 있는 동안 Claude Code가 연결하는 도구 서버                           | `.mcp.json`이 Claude에게 도구를 준다                      |

## 플러그인이 필요한가

스킬, 서브에이전트, 훅, MCP 서버는 플러그인 없이도 따로 쓸 수 있다.
예를 들어 `~/.claude/skills/`에 둔 스킬은 이 컴퓨터의 모든 프로젝트에서 쓰인다.

플러그인이 필요한 것은 여러 구성 요소를 한 단위로 묶고 싶을 때다.
남이 만든 설정을 명령 하나로 받아 마켓플레이스에서 업데이트받고 싶거나,
내 설정을 동료에게 주거나 여러 프로젝트에 깔거나 버전을 붙여 배포하고 싶을 때다.

## 켜 두기만 해도 생기는 비용

켜진 플러그인은 그것을 쓰는 세션만이 아니라 모든 세션의 일부가 된다.

- **컨텍스트와 사용량**: Claude가 스스로 부를 수 있는 스킬, 에이전트, 명령은
  이름과 설명이 매 턴 Claude의 컨텍스트에 들어간다.
  플러그인을 전혀 쓰지 않는 세션에서도 이 토큰은 사용량에 잡히고 컨텍스트 창을 차지한다.
  스킬과 에이전트의 본문은 쓸 때만 불러온다.
- **프로세스**: 플러그인의 MCP 서버는 켜진 세션마다 함께 돌고, 훅은 이벤트마다 실행된다.
- **권한**: 플러그인이 실행하는 것은 사용자 권한으로 실행된다.

비용은 단계마다 확인할 수 있다.

| 시점                | 확인 방법                                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| 설치 전             | `/plugin`의 Marketplaces 탭에서 플러그인 열기. 공식 마켓플레이스는 Context cost 추정치를 보여 준다 |
| 설치 후             | 플러그인 비용 측정 문서로 영향을 읽고, Installed 탭의 Not used recently 묶음에서 안 쓰는 것 찾기   |
| 지우지 않고 멈출 때 | `/plugin`에서 끄거나 `claude plugin disable`                                                       |

## 마켓플레이스

마켓플레이스는 `.claude-plugin/marketplace.json` 파일이
있는 저장소나 디렉터리다.
호스팅된 상점이 아니라 카탈로그이고,
한 번 추가한 뒤 `commit-commands@claude-plugins-official`처럼 이름으로 설치한다.
claude.com/marketplace의 Claude Marketplace는 웹사이트이며
`/plugin marketplace add`로 추가하는 마켓플레이스와 다르다.

Claude Code는 대화형 터미널 세션을 처음 시작할 때
관리 정책이 막지 않는 한 Anthropic의 공식 마켓플레이스를 추가한다.
Anthropic의 커뮤니티와 데모 마켓플레이스는 자동으로 추가하지 않는다.

이름에 따라 세 등급으로 나뉜다.
Claude Code는 공식과 커뮤니티 이름을
`github.com/anthropics/` 저장소에서 온 마켓플레이스에만 허용한다.

| 등급     | 예                                                             |
| -------- | -------------------------------------------------------------- |
| 공식     | `claude-plugins-official`, 데모용 `claude-code-plugins`        |
| 커뮤니티 | `claude-community`                                             |
| 제3자    | 그 밖의 모든 마켓플레이스. 동료나 조직이 만든 것도 여기 속한다 |

등급과 상관없이 설치한 플러그인은 사용자 권한으로 코드를 실행할 수 있다.
조직은 관리 설정으로 마켓플레이스를 허용하거나 막고,
플러그인을 강제로 설치하고, 세션 한정 불러오기를 끌 수 있다.
개발 중인 플러그인은 마켓플레이스 없이 `--plugin-dir`로 폴더에서 바로 불러온다.

## 설치 범위

| 범위     | 누구에게 켜지나                                                                         |
| -------- | --------------------------------------------------------------------------------------- |
| 사용자   | 이 컴퓨터의 모든 프로젝트에서 나에게                                                    |
| 프로젝트 | 커밋된 `.claude/settings.json`으로 이 저장소에서 일하는 모두에게. 각자 설치는 해야 한다 |
| 로컬     | 이 저장소에서 나에게만                                                                  |

터미널, 데스크톱 앱의 로컬 세션, VS Code 확장은 같은 설정 파일을 읽으므로
사용자 범위로 설치한 플러그인은 세 곳 모두에서 쓰인다.
반면 claude.ai/code의 브라우저 세션을 포함한 클라우드 세션은
로컬 설정의 플러그인을 불러오지 않는다.

설치한 플러그인이 실제로 쓰이려면 세 층에 모두 있어야 한다.
설정에는 추가한 마켓플레이스와 켜진 플러그인이 적혀 있고,
`~/.claude/plugins/`에는 내려받아 설치한 파일이 있으며,
세션은 시작할 때나 플러그인을 다시 불러올 때 그것을 읽는다.

## 함정

- 플러그인을 많이 켜 두면 쓰지 않는 세션에서도 스킬과 에이전트의 설명이 매 턴 컨텍스트를 차지한다. 안 쓰는 것은 지우지 않더라도 끈다.
- 프로젝트 범위는 설정만 공유한다. 동료가 각자 설치하지 않으면 그 플러그인은 그 사람에게 없다.
- 클라우드 세션에서 로컬에 설치한 플러그인이 보이지 않는 것은 정상이다.
- “공식”처럼 보이는 이름이라도 `github.com/anthropics/` 저장소가 아니면 공식 등급이 아니다. 공식 등급이어도 코드는 내 권한으로 돈다.
- claude.ai나 Cowork에 설치한 플러그인은 불러오는 구성 요소가 다르다.

## 체크리스트

- [ ] 구성 요소 하나뿐이라면 플러그인 없이 따로 두는 편이 낫지 않은가
- [ ] 설치 전에 Marketplaces 탭에서 Context cost를 확인했는가
- [ ] 마켓플레이스의 등급과 출처 저장소를 확인했는가
- [ ] 설치 범위(사용자, 프로젝트, 로컬)를 의도대로 골랐는가
- [ ] Installed 탭의 Not used recently 묶음을 가끔 정리하는가

## 기억할 원칙

### 플러그인은 묶음이고, 묶음은 늘 켜져 있다

플러그인의 가치는 여러 구성 요소를 한 번에 설치하고 함께 업데이트하는 데 있다.
그러나 같은 성질 때문에 켜 둔 플러그인은 쓰지 않는 세션에서도
컨텍스트, 프로세스, 권한을 차지한다.
플러그인을 고를 때는 기능보다 “늘 켜 둘 만한가”를 먼저 묻는 편이 낫다.
