# Skillry Opus 5.5 영상 갤러리: 입소문 난 코드 영상과 프롬프트, 그리고 다시 만든 결과

<https://skillry.dev/ai-videos/opus-5-5>

## 소개

Skillry는 AI 에이전트용 스킬(Skill)을 모아 파는 사이트이고, 이 페이지는 그 안의 “Opus 5.5 videos” 갤러리다.
페이지 설명은 사람들이 Claude Opus 5.5로 만들어 입소문이 난 영상을 모았으며, 각 영상에 원본 프롬프트와 라이브 리메이크를 붙였다는 한 문장이다.
2026년 9월 22일 Opus 5.5가 나온 뒤 Twitter를 채운 코드 렌더링 영상 유행을, 게시물 단위로 정리한 색인이라고 보면 된다.

2026년 9월 말 기준으로 갤러리에는 영상 24개가 있다.
분류는 23개가 Explainers(설명 영상), 1개가 3D scenes이며, 길이는 22초에서 1분 사이다.
각 카드에는 원본 게시물의 첫 문장과 작성자 핸들, 그리고 영상이 쓴 기술 태그가 붙는다.
태그를 세어 보면 Three.js와 Canvas가 각각 13개, GLSL이 12개, SVG와 Web Audio가 각각 6개이고, GSAP, CSS, Physics가 2개씩, WebGL과 AI image가 1개씩이다.

사이트 상단에는 모든 프리미엄 스킬을 월 9.99달러에 쓸 수 있다는 Pro 요금제 배너가 걸려 있다.
갤러리는 그 판매의 입구 역할을 한다.

## 구성

### 목록 페이지

목록은 카드 격자다.
카드마다 분류와 길이, 원본 게시물의 본문 일부, 작성자 핸들, 기술 태그가 있고, 누르면 상세 페이지로 간다.
목록 상단에는 Compare 항목이 있다.

### 상세 페이지

상세 페이지 하나는 네 부분으로 되어 있다.
첫째는 영상 비교다.
원본 게시물의 영상과 Skillry 계정(@skillry_dev)이 다시 만든 리메이크를 나란히 놓고, “Play both”로 동시에 재생하며, 원본 게시물로 가는 링크가 있다.

둘째는 “이런 영상을 에이전트로 만들기”라는 스킬 추천이다.
해당 스킬을 설치하고 에이전트에게 비슷한 영상을 요청하라는 안내와 함께, 무료 또는 유료 영상 스킬 네 개가 설치 수와 함께 나온다.
예컨대 @arthurkatcher의 코딩 에이전트 설명 영상 페이지에는 “Velocity-Matched UI Sting”, “Agent-Chorus Capability Reel” 같은 스킬이 붙어 있었다.

셋째는 프롬프트다.
복사 버튼이 있지만, 작성자가 프롬프트를 공개하지 않은 경우에는 “작성자가 프롬프트의 일부를 공유했다”는 안내와 함께 원본 게시물의 본문이 그대로 들어간다.
@arthurkatcher 페이지의 프롬프트 칸에는 Claude Code에 메시지 하나를 보내 14분이 걸렸고 워크플로는 댓글에 있다는 게시물 문장이 들어 있었다.
반면 @koldo2k의 무한 줌 영상처럼 원본 게시물 자체가 장면 목록과 스타일까지 적은 프롬프트 전문인 항목도 있다.

넷째는 같은 분류의 다른 영상 목록이다.

## 수록 작품에서 보이는 경향

### 영상보다 브라우저에서 도는 프로그램이 많다

갤러리의 분류는 영상이지만, 상당수는 녹화된 인터랙티브 페이지다.
@konstantinsaifo의 Raptor 3 로켓 엔진과 핵융합로는 브라우저에서 분해하고 조작할 수 있는 페이지이고,
@StefanoStraus의 엔진은 화면 녹화이며 실제는 브라우저에서 실시간으로 돈다고 밝힌다.
블랙홀 중력 렌즈(@Voxyz_ai), 카메라 렌즈 실험실(@chudry223), 분자 궤도(@explorations_iq)도 같은 부류다.
Three.js와 GLSL 태그가 가장 많은 것은 이 때문이다.

### 한 프롬프트라는 말과 실제 과정이 다르다

카드의 문구는 대개 “프롬프트 하나”를 강조하지만, 일부 작성자는 과정을 구체적으로 적는다.
@Voxyz_ai는 첫 버전은 프롬프트 하나였지만 이후 에이전트 세 개(검토자 두 명과 수정자 한 명)가 세 라운드를 돌며 다듬었고, 전체 5시간 28분에 API 가격 기준 90달러가 들었다고 적었다.
@kgonia7은 지구의 언덕에서 관측 가능한 우주까지 줌 아웃하는 영상에 약 3시간, 출력 토큰 662,769개, 캐시 읽기 1억 2,560만 토큰이 들었고 API 환산 비용이 약 54.52달러였다고 밝혔다.
@NathanWilbanks_는 GPU 유체 시뮬레이션 불꽃을 만들면서 모델이 자기 렌더링을 약 40번 비평했다고 적었다.

반대편에는 정말 짧은 사례도 있다.
@hunzai는 medium 설정에 한 줄 프롬프트로 “생태계로서의 나무” 설명 영상을 오디오까지 만들었다고 했고,
@StefanoStraus는 앞선 실험이 만든 프레임워크를 재사용해 15분이 안 걸렸다고 했다.
@StephanFerraro는 빈 저장소에서 수정 없이 약 21분 만에 테스트 23개가 모두 통과하는 3D 물 시뮬레이션을 만들었다고 했다.

### 소리를 코드로 만든다

Web Audio 태그가 붙은 항목들은 음악과 효과음도 코드로 합성한다.
@iniyanai의 기계식 키보드 설명 영상은 음악을 코드로 쓰고 실제 스위치 녹음을 비트로 쓰며 모든 컷을 비트에 맞췄고,
@Rakhsh_Tech는 현, 피리, 북, 방울, 물방울 소리를 물리 연산으로 만들었다.
@DemitiyaGeekzen의 등왕각 중추절 영상은 고쟁을 Karplus-Strong 현 진동 모델로 합성했다고 적는다.

### 도구 조합

HyperFrames(@Miguel07Code), GSAP(@arthurkatcher, @moguzbulbul), WebGPU 물리 해석기(@nybobs의 11만 개 강체) 같은 조합이 보인다.
@garmdotcom은 OpenRouter API 키를 넣는 것을 잊었는데, Opus가 외부 이미지 생성 없이 모두 직접 만들어 추가 비용이 0달러였다고 적었다.
외부 생성 모델 없이 코드만으로 끝나는 경우가 대부분이라는 뜻이다.

## 활용하기

### 프롬프트를 볼 때

상세 페이지의 프롬프트 칸이 실제 프롬프트인지 게시물 본문인지 먼저 확인한다.
“작성자가 프롬프트의 일부를 공유했다”는 안내가 있으면 그 칸은 게시물의 홍보 문구이고, 실제 지시는 원본 게시물의 답글이나 작성자가 링크한 곳에 있다.
프롬프트 전문이 있는 항목은 대개 결과물의 장면 목록, 스타일, 금지 사항을 구체적으로 적는다.
이런 항목을 골라 구조를 비교하는 것이 가장 쓸모 있다.

### 리메이크를 볼 때

원본과 리메이크를 동시에 재생해 두 영상의 차이를 본다.
리메이크는 Skillry가 자기 스킬로 다시 만든 결과이므로, 같은 주제를 다른 하네스로 만들면 무엇이 달라지는지 보여 주는 대조군이 된다.
다만 리메이크에 쓴 정확한 입력과 설정은 페이지에 나오지 않으므로, 차이가 스킬 때문인지 프롬프트 때문인지는 구분할 수 없다.

### 직접 따라 할 때

작성자가 비용과 시간을 밝힌 항목을 기준으로 기대치를 잡는다.
한 줄 프롬프트로 끝난 사례는 30초 안팎의 설명 영상이 많고, 3D 장면이나 물리 시뮬레이션은 몇 시간과 수십 달러가 든 사례가 많다.
갤러리가 권하는 스킬을 설치할 수도 있지만, 그 전에 스킬의 설치 수와 무료 여부, 그리고 스킬이 어떤 렌더링 방식(Canvas, SVG, Three.js)을 전제하는지 확인한다.

## 비평

### 원본 프롬프트라는 약속을 항목마다 지키지는 않는다

페이지의 첫 문장은 모든 영상에 원본 프롬프트가 붙어 있다고 말한다.
하지만 확인한 상세 페이지에서 프롬프트 칸은 게시물 본문으로 채워져 있었고, 작성자가 일부만 공유했다는 안내가 붙어 있었다.
“14분, 메시지 하나”라는 문장은 결과에 대한 자랑이지 지시가 아니다.

이 차이는 작지 않다.
이 유행에서 가장 자주 반복된 오해가 바로 “프롬프트 하나”라는 말이고, 실제로는 긴 지시서와 스킬 폴더와 여러 차례의 비평 루프가 뒤에 있는 경우가 많았다.
프롬프트 칸에 홍보 문구를 넣고 그것을 프롬프트라고 부르면, 갤러리가 그 오해를 교정하는 대신 되풀이한다.
공개되지 않은 항목은 프롬프트 칸을 비워 두고 원본 게시물의 답글을 가리키는 편이 정직하다.

### 선별된 성공만 모인다

갤러리는 입소문이 난 영상을 모은다.
입소문이 났다는 것은 결과가 인상적이었다는 뜻이고, 같은 프롬프트로 시도했지만 밋밋한 결과를 얻은 수많은 시도는 여기 없다.
Opus 5.5 출시 직후 “내 한 프롬프트 영상은 평범했다”는 불평이 많았던 것을 생각하면, 이 갤러리가 보여 주는 것은 모델의 평균이 아니라 분포의 위쪽 꼬리다.

리메이크가 이 편향을 일부 보정할 수 있다.
같은 주제를 다시 만들었을 때 원본에 가깝다면 재현성이 있다는 뜻이기 때문이다.
하지만 리메이크는 스킬을 파는 쪽이 자기 스킬로 만든 것이므로, 재현이 잘 안 된 사례를 싣거나 실패한 리메이크를 공개할 유인은 약하다.

### 영상과 인터랙티브 페이지를 같은 분류에 넣는다

갤러리의 3분의 1가량은 브라우저에서 조작하는 인터랙티브 페이지를 녹화한 것이다.
이런 결과물은 시간의 함수로 프레임을 그리는 모션 그래픽 영상과 만드는 방법이 다르다.
인터랙티브 페이지는 상태와 입력 처리가 중요하고, 영상은 결정론적 렌더링과 타이밍이 중요하다.

두 가지를 모두 “영상”으로 묶으면, 따라 하려는 사람이 어떤 하네스를 준비해야 하는지 구분하기 어렵다.
기술 태그가 어느 정도 힌트를 주지만, Three.js 태그만으로는 그것이 녹화된 페이지인지 렌더링된 영상인지 알 수 없다.
결과물의 형태, 곧 렌더링 영상인지 인터랙티브 페이지의 녹화인지를 태그로 따로 표시하면 갤러리의 쓸모가 커진다.

## 기억할 원칙

### 결과를 볼 때는 과정의 비용을 함께 찾아라

이 갤러리에서 가장 가치 있는 정보는 영상 자체가 아니라, 일부 작성자가 스스로 밝힌 시간과 토큰과 비용이다.
5시간 28분과 90달러, 3시간과 54.52달러, 비평 40번, 그리고 15분과 한 줄 프롬프트가 같은 갤러리에 나란히 있다.
결과물만 보면 이 차이가 보이지 않는다.

그래서 AI로 만든 결과물을 참고할 때는 결과의 품질보다 그 결과에 든 과정을 먼저 찾아야 한다.
과정이 공개되지 않은 결과는 따라 할 수 있는 기준이 아니라 가능성의 증명일 뿐이다.
따라 할 기준은 과정과 비용까지 밝힌 사례에서 찾는 편이 안전하다.
