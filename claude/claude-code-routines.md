# Claude Code 예약 작업(루틴)은 프롬프트, 저장소, 커넥터를 한 번 저장해 클라우드에서 트리거로 실행한다

원문: [Automate work with scheduled tasks - Claude Code Docs](https://code.claude.com/docs/en/routines)

HN 토론: <https://news.ycombinator.com/item?id=47768133> (720점, 413개 댓글)

GN 토론: <https://news.hada.io/topic?id=28533>

## 소개

Anthropic의 Claude Code 문서 중 클라우드 예약 작업(scheduled tasks)을 다루는
페이지입니다.
문서는 이 기능이 연구 프리뷰(research preview)이며 동작, 한도,
API 형태가 바뀔 수 있다고 밝힙니다.
예전 이름은 루틴(routine)이고, 웹 주소, CLI 별칭,
API 경로 등에 아직 남아 있다고 합니다.

예약 작업은 프롬프트, 저장소 하나 이상,
커넥터(connector) 묶음을 한 번 저장해 두고 자동으로 실행하는 Claude Code
설정입니다.
Anthropic이 관리하는 클라우드 인프라, 또는 조직의 자체 호스팅 환경에서
실행되므로 노트북이 꺼져 있어도 동작합니다.
Pro, Max, Ultra, Team, Enterprise 요금제에서 쓸 수 있고,
웹의 `claude.ai/code/routines` 또는 CLI의 `/schedule`로 만들고 관리합니다.

한 작업에는 트리거(trigger)를 하나 이상 붙입니다.

| 트리거 | 실행 시점                                                                | 비고                       |
| ------ | ------------------------------------------------------------------------ | -------------------------- |
| 스케줄 | 매시간, 매일, 매주 같은 반복 또는 미래의 특정 시각 한 번                 | 프리셋 또는 크론 식        |
| API    | 작업 전용 엔드포인트에 베어러 토큰(bearer token)으로 HTTP POST를 보낼 때 | 웹에서만 추가·관리         |
| GitHub | 저장소의 풀 리퀘스트, 릴리스, 이슈 이벤트                                | Claude GitHub 앱 설치 필요 |

트리거는 섞어 쓸 수 있습니다.
문서의 예는 한 PR 리뷰 작업이 매일 밤 돌고, 배포 스크립트에서도 호출되고,
새 PR마다 반응하는 경우입니다.
스케줄 없이 API 또는 GitHub 트리거만 가진 작업도 가능하며,
이런 작업은 다음 실행 시각이 없습니다.

같은 기능이 아닌 로컬 대안도 문서가 언급합니다.
데스크톱 예약 작업과 `/loop`는 클라우드가 아니라 내 컴퓨터에서 일정을 돌립니다.

## 동작 방식

예약 작업은 실행마다 새 Claude Code 클라우드 세션을 시작하는 자율 실행입니다.
세션은 셸 명령을 실행하고, 스킬(skill)을 쓰며, 포함된 커넥터를 호출합니다.
작업을 만들 때 권한 모드는 고르지 않습니다.

- **프롬프트의 지위**: 트리거가 발동하면 세션은 저장된 프롬프트를 과제로 받아 수행합니다. 대화 중간에 들어온 신뢰할 수 없는 내용으로 다루지 않습니다. 그렇다고 이 프롬프트가 실행 중 행동에 대한 승인이나 동의 역할을 하지는 않습니다.
- **소유권**: 예약 작업은 개인 claude.ai 계정에 속하며 팀원과 공유되지 않습니다. 실행은 계정의 사용량 한도를 쓰고, 연결된 GitHub 신원이나 커넥터로 한 일은 내 이름으로 남습니다.
- **접근 범위**: 선택한 저장소, 환경(environment)의 네트워크 접근과 변수, 포함한 커넥터가 정합니다. 문서는 각각을 작업에 필요한 만큼으로 좁히라고 권합니다.
- **저장소**: 실행마다 선택한 저장소를 모두 clone하고, 기본 브랜치에서 시작합니다. 변경은 `claude/` 접두사 브랜치에 push합니다. PR 이벤트로 시작되고 그 저장소가 첫 번째 저장소이면 PR의 head 커밋에서 시작합니다.
- **GitHub 연결 끊김**: 연결이 없거나 만료되면 최대 72시간 동안 실행을 건너뛰고, 그 안에 다시 연결하면 자동으로 재개됩니다. 72시간이 지나면 작업이 꺼지고 다시 켜야 합니다.
- **허용 브랜치**: 어느 브랜치에 push할 수 있는지는 GitHub의 브랜치 보호 규칙이나 룰셋으로 제한합니다. 연결한 GitHub 접근이 우회할 수 있는 규칙은 막지 못합니다.

## 만들기

### 웹에서

웹에서는 다음 순서입니다.

1. `claude.ai/code/routines`에서 새 작업 대화상자를 엽니다.
2. 이름과 프롬프트를 씁니다. 프롬프트는 자율 실행이므로 자기완결적이어야 하고,
무엇을 할지와 성공 기준을 분명히 적어야 합니다.
3. 트리거를 고릅니다. 여러 개를 섞으려면 `+`를 누릅니다.
4. 고급 설정에서 저장소를 하나 이상 고릅니다.
5. 클라우드 환경을 고릅니다. 환경은 네트워크 접근, 환경 변수,
설정 스크립트를 정하며, 설정 스크립트 결과는 캐시됩니다.
6. 모델과, 모델이 지원하면 effort 수준을 고릅니다.
7. 커넥터를 검토합니다. 연결된 커넥터가 기본으로 모두 포함되므로 필요 없는 것은
뺍니다. 포함된 커넥터는 실행 중 쓰기도 할 수 있습니다.
8. 만들기를 누릅니다. 바로 실행하려면 상세 페이지의 `Run now`를 누릅니다.

화면 구성은 계정마다 다를 수 있습니다.
문서는 버튼이 `New routine`으로 보이거나 전체 페이지 폼이 열리는 경우,
데스크톱 앱의 Local·Cloud 메뉴가 나오는 경우를 따로 안내합니다.
`Create with Claude`를 고르면 채팅으로 설명해 작업을 만들 수도 있습니다.

### CLI에서

세션에서 `/schedule`을 실행하면 대화로 만듭니다.
설명을 함께 줄 수 있습니다.

```text
/schedule daily PR review at 9am
/schedule clean up feature flag in one week
```

`/routines`는 같은 명령의 별칭입니다.
CLI로 만든 작업은 스케줄 트리거를 가지며,
API 트리거는 웹에서만 붙일 수 있습니다.
GitHub 트리거는 웹에서 붙이거나 CLI에서 Claude에게 요청해 붙이는데,
CLI 방식은 Claude Code v2.1.225 이상이 필요합니다.
`/schedule list`, `/schedule update`, `/schedule run`으로 관리하고,
실행 이력을 물어보는 기능은 v2.1.227 이상이 필요합니다.

## 트리거 설정

### 스케줄

- 정각에 맞추면 몇 분 늦게 시작할 수 있으므로, 시작 시각에 가깝게 하려면 9:07처럼 몇 분 지난 시각을 고르라고 합니다.
- 프리셋에 없는 주기는 만든 뒤 편집 대화상자에서 `Custom`을 골라 크론 식을 넣습니다. 한 시간에 한 번보다 자주 도는 식은 거부됩니다.
- 프리셋은 로컬 시간대로 입력합니다. 크론 식은 필드 다섯 개만 쓰면 UTC입니다. 예를 들어 `0 9 * * 1-5`는 평일 UTC 9시입니다. `CRON_TZ=` 접두사가 있으면 그 시간대로 씁니다.
- 일회성 실행은 한 번 돌고 스스로 꺼지며, 웹에서 `Completed`로 표시됩니다. 다시 돌리려면 편집 대화상자에서 일회성 항목을 골라 새 시각을 저장합니다.
- CLI에서는 자연어로 시각을 말하면 Claude가 절대 시각으로 풀어 확인한 뒤 저장합니다.

### API

API 트리거는 작업 전용 HTTP 엔드포인트를 줍니다.
웹에서 편집 대화상자의 트리거 행에서 `+`로 API를 고르고,
`Fire URL`을 복사한 뒤 `Generate token`으로 토큰을 만듭니다.
토큰은 한 번만 보이므로 알림 도구의 시크릿 저장소 같은 안전한 곳에 둡니다.
토큰은 작업마다 따로이며 그 작업만 호출할 수 있고,
`Regenerate`로 교체하면 이전 토큰은 즉시 효력을 잃습니다.
`Delete token`은 API 트리거 자체를 없앱니다.

```bash
curl -X POST https://api.anthropic.com/v1/claude_code/routines/trig_01ABCDEFGHJKLMNOPQRSTUVW/fire \
  -H "Authorization: Bearer sk-ant-oat01-xxxxx" \
  -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{"text": "Sentry alert SEN-4521 fired in prod. Stack trace attached."}'
```

작업 ID와 토큰은 문서의 자리표시자입니다.
성공하면 세션 ID와 세션 URL이 든 JSON이 돌아오고,
URL을 열어 실행을 지켜볼 수 있습니다.

`text` 필드는 선택이며 알림 본문이나 실패 로그 같은 실행별 맥락을 넣는 곳입니다.
값은 파싱되지 않는 자유 텍스트이므로 JSON을 보내도 문자열로 전달됩니다.
이 값은 `<routine-fire-payload>` 블록에 감싸져 신뢰할 수 없는 데이터로 표시되어
전달되고, 작업의 프롬프트가 허용하지 않으면 그 안의 지시를 따르지 않습니다.
따라서 프롬프트가 이 페이로드를 명시적으로 참조해야 합니다.
문서의 예는
`Investigate the alert described in the routine-fire-payload block`입니다.
이 엔드포인트는 `experimental-cc-routine-2026-04-01` 베타 헤더로 제공되며,
문서는 요청·응답 형태와 한도가 바뀔 수 있고 변경은 새 날짜의 베타 헤더 뒤에서
나오며 직전 두 버전은 계속 동작한다고 합니다.
`/fire`는 claude.ai 사용자에게만 제공되고 Claude Platform API에 포함되지
않습니다.

### GitHub

GitHub 트리거는 연결된 저장소에서 맞는 이벤트가 생기면 새 세션을 시작합니다.
세션은 이벤트 사이에 재사용되지 않으므로 PR이 두 번 갱신되면 독립된 세션이 둘
생깁니다.
Claude GitHub 앱이 해당 저장소에 설치되어 있어야 하고,
웹은 없으면 설치를 안내합니다.
CLI에서 `/web-setup`을 실행해도 저장소 접근만 주어질 뿐 앱 설치나 웹훅 전달은
켜지지 않습니다.
웹훅 이벤트에는 작업별, 계정별 시간당 상한이 있고 초과분은 창이 초기화될 때까지
버려집니다.

| 이벤트       | 발동 시점                                                |
| ------------ | -------------------------------------------------------- |
| Pull request | PR이 열림, 닫힘, 지정, 라벨, 동기화 등 갱신될 때         |
| Release      | 릴리스가 생성, 게시, 편집, 삭제될 때                     |
| Issue        | 이슈가 열림, 편집, 닫힘, 재오픈, 라벨, 지정 등 갱신될 때 |

PR 트리거에는 필터를 붙일 수 있고 모든 조건이 맞아야 발동합니다.
필드는 작성자, 제목, 본문, 베이스 브랜치, 헤드 브랜치, 라벨, 초안 여부,
병합 여부입니다.
연산자는 같음, 포함, 시작함, 목록 중 하나, 목록에 없음, 정규식 일치입니다.
정규식은 필드 전체에 일치해야 하므로 제목에 `hotfix`가 들어간 PR을 잡으려면
`.*hotfix.*`로 씁니다.
단순 부분 문자열이면 `contains`를 쓰면 됩니다.

## 운영과 권한

### 권한 프롬프트

Anthropic 클라우드에서 시작된 실행 세션은 자동 모드(auto mode)가 쓸 수 없는
경우가 아니면 자동 모드로 시작합니다.
자동 모드에서는 분류기 모델이 승인을 기다릴 행동을 허용하거나 막습니다.
다음 경우에는 실행이 멈추고 답을 기다립니다.

- 자동 모드에서도 묻는 행동, 예를 들어 ask 규칙에 맞는 행동
- 막힘이 자동 모드의 반복 차단 임계값에 이르렀을 때

자동 모드를 쓸 수 없으면 시작한 권한 모드를 유지합니다.
대기 중인 프롬프트는 상세 페이지에서 해당 실행을 열어 답합니다.

### 환경과 네트워크

기본(Default) 환경은 Trusted 네트워크 접근으로, 패키지 레지스트리,
클라우드 제공자 API, 컨테이너 레지스트리,
흔한 개발 도메인의 기본 허용 목록만 통과시킵니다.
목록 밖 호스트 요청은 `403`과 `x-deny-reason: host_not_allowed`로 실패합니다.
커넥터 트래픽은 Anthropic 서버를 거치므로 허용 도메인을 추가할 필요가 없습니다.
도메인을 늘리려면 환경 설정에서 `Network access`를 `Custom`으로 바꾸고
`Allowed domains`에 넣으며, 기본 목록을 유지하려면 해당 체크박스를 켭니다.
전체 개방은 `Full`입니다.
조직 공유 환경은 읽기 전용이므로 Owner가 관리자 설정에서 바꿉니다.
환경 변수는 그 환경을 쓰는 누구에게나 보이므로,
Anthropic 호스팅 환경에서 API 키는 네트워크 시크릿(network secrets)으로
두라고 합니다.

### 커넥터

커넥터는 claude.ai 계정의 통합이며, 로컬에서 `claude mcp add`로 추가한 MCP
서버는 목록에 나오지 않습니다.
그런 서버를 쓰려면 `claude.ai/customize/connectors`에서 커넥터로 추가하거나,
저장소 하나짜리 작업이면 커밋된 `.mcp.json`에 선언합니다.
프로젝트의 스레드로 도는 작업은 후자를 쓸 수 없고 커넥터로 추가해야 합니다.

### 실행 이력

상세 페이지의 이력에서 실행을 열면 일반 세션처럼 변경을 검토하고 PR을 만들고
대화를 이어갈 수 있습니다.
상태는 성공, 실패, 취소 세 가지이며, 이는 세션이 어떻게 끝났는지를 말할 뿐
프롬프트가 요구한 일을 해냈다는 뜻이 아닙니다.
차단된 네트워크 요청이나 빠진 커넥터 도구는 행이 아니라 대화 기록에 나타나므로
기록을 읽어야 합니다.
성공한 실행의 세션을 보관(archive)하면 상태가 취소로 바뀝니다.

### 아티팩트

자동 모드의 실행은 분류기가 허용하면 아티팩트(artifact)를 묻지 않고 게시합니다.
새 아티팩트는 공유 전까지 나만 볼 수 있습니다.
페이지를 계속 최신으로 유지하는 작업이라면 이미 게시한 아티팩트를 작업에 지정해
주라고 합니다.

## 한도

구독 사용량은 대화형 세션과 같은 방식으로 줄어듭니다.
이와 별개로 시작 방식마다 시간당 한도가 있고, 어느 것도 초과 사용이 없습니다.

| 동작                                    | 한도         | 집계 대상                      | 초과 시                 |
| --------------------------------------- | ------------ | ------------------------------ | ----------------------- |
| 스케줄 실행(일회성 포함)                | 시간당 100회 | 계정                           | 한도가 풀릴 때까지 대기 |
| `Run now`, API 호출, 일회성 작업 재실행 | 시간당 30회  | 작업별로 셋이 하나의 횟수 공유 | 한도가 풀릴 때까지 실패 |
| `Run now`와 일회성 작업 재실행          | 시간당 100회 | 계정                           | 같음                    |
| API 호출                                | 시간당 100회 | 계정, `Run now`와 별도 집계    | 같음                    |

구독 사용량 한도에 걸리면 사용 크레딧이 켜진 조직은 종량 초과로 계속 돌릴 수
있고, 아니면 창이 초기화될 때까지 실행이 거부됩니다.
구독이 일시 중지되면 예약 작업도 보류되며, 다시 활성화된 뒤 직접 켜야 합니다.

## 함정

- **`/schedule`이 `Unknown command`로 나온다**: Console API 키, 클라우드 제공자(Bedrock 등) 로그인, 로그아웃 상태, 클라우드 세션 안, 조직 정책으로 클라우드 세션이 꺼진 경우, Owner가 예약 작업을 끈 경우, 사용자 지정 역할에 권한이 없는 경우가 원인으로 나열됩니다. `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `apiKeyHelper`가 설정되어 있으면 claude.ai 로그인보다 우선하므로 먼저 지워야 합니다. 이 경우에도 웹에서는 만들고 관리할 수 있습니다.
- **조직에서 꺼져 있다**: Team과 Enterprise의 Owner가 `Organization settings > Capabilities > Remote sessions`의 토글을 켜야 합니다. 꺼지면 기존 작업도 멈추고 새 작업도 못 만듭니다. 사용자 지정 역할을 쓰는 Enterprise는 `Remote sessions` 항목의 예약 작업 권한도 필요합니다.
- **`The last run` 경고**: 이력 아래 경고는 첫 열에서 찾아 그 행의 조치를 따릅니다. 동시 세션 한도 도달은 나중에 `Run now`로 충분하고, 환경을 찾을 수 없다는 경고는 편집 대화상자에서 `Unavailable environment`인 환경을 바꿔 저장합니다. 저장소나 브랜치를 쓸 수 없다는 경고는 GitHub에서 시작 브랜치와 접근 권한을 확인합니다. 설정이 받아들여지지 않았다는 경고는 어느 설정인지 표시되지 않으므로 이름, 프롬프트, 모델, 저장소, 환경, 커넥터, 트리거를 하나씩 봐야 합니다. 일시적 문제와 실패는 `Run now`로 재시도하며, 실패한 실행은 열 세션이 없습니다.
- **정각 시작**: 정각 지정은 늦게 시작할 수 있습니다.
- **크론의 UTC**: 필드 다섯 개짜리 크론 식은 UTC입니다.
- **API 페이로드를 프롬프트가 참조하지 않으면**: `text`는 비활성 맥락으로만 취급됩니다.

### HN 댓글에서 나온 사용 경험과 우려

HN 스레드는 이 페이지가 `Claude Code Routines`라는 제목이던 출시 시점에 달린 것입니다.
댓글이 가리키는 수치와 화면은 지금의 문서와 다를 수 있습니다.

- **쓸모를 본 사례**: eranation은 사내 도구 피드백 Slack 채널을 훑어 이슈를 열고 쉬운 것은 고쳐 PR 링크로 답하게 했고, GitHub 활동, Slack, 이메일을 모은 일일 요약도 만들었다고 합니다.[^eranation-use] 같은 사람이 꼽은 문제는 Slack 커넥터 연결이 자주 끊기고, 비공개 패키지 저장소에 접근하지 못하며, GitHub MCP로 릴리스 노트 같은 단순한 수정도 못 한다는 점입니다.[^eranation-bugs]
- **잠금(lock-in) 우려**: joshstrange는 모델과 기능이 약해지거나 기능이 중단될 수 있다는 점을 들어, 하네스와 모델은 쓰되 플랫폼에는 올라타지 않겠다고 합니다.[^joshstrange] 반대로 이 기능은 GitHub Actions와 크게 다르지 않다는 반응도 있습니다.[^dbbk]
- **구독 약관의 모호함**: andai는 `claude -p`를 크론으로 돌리는 것은 괜찮고 자기 텔레그램 봇에 붙이는 것은 약관 위반이라고 이해했는데, 구독으로 쓰면서 API 호출이 있는 이 기능은 어떻게 되느냐고 묻습니다.[^andai] 답글에서 약관 설명이 모호하다는 불만이 이어졌고, 이 스레드에서 공식 답은 확인되지 않습니다.
- **팀 공유**: taw1285는 개인 Max 구독 네 명이 이 작업을 같이 관리하는 방법을 묻고, 답글은 팀 요금제가 구독 과금으로 나온다고 말합니다.[^hallway] 문서는 작업이 개인 계정 소유이고 팀원과 공유되지 않는다고 하므로, 협업 용도는 계정 구조부터 확인해야 합니다.
- **실패를 알아채는 문제**: MyUltiDev는 `/fire` 응답이 시작 사실만 알려 주므로, 세션이 끝난 뒤 하류(CD 파이프라인 등)가 조용히 실패하는 경우를 작업이 어떻게 알아챌지 문서가 다루지 않는다고 지적합니다.[^myulti] 문서가 성공 표시는 세션이 끝난 방식일 뿐이라고 한 것과 같은 문제입니다.
- **한도**: haukem은 하루 15회 상한이 PR 5~20건을 모두 리뷰하기에 낮다고 썼습니다.[^haukem] 현재 문서의 한도는 시간당 단위이므로 이 수치는 스레드 시점의 값으로 보입니다.
- **대안**: summarity는 비슷한 트리거와 추가 보안 통제를 제공하는 GitHub의 Agentic Workflows를 함께 보라고 권합니다.[^summarity]

## 기억할 원칙

- 프롬프트는 자기완결적으로 쓰고 성공 기준을 적습니다. 실행 중에는 물어볼 사람이 없다고 가정합니다.
- 저장소, 환경, 커넥터는 작업에 필요한 것만 남깁니다. 기본으로 전부 포함된다는 점이 출발점입니다.
- 성공 표시는 세션이 끝난 방식일 뿐입니다. 결과는 실행 기록을 열어 확인합니다.
- 외부 입력(`text`)을 받는 작업은 프롬프트가 그 입력을 어떻게 다룰지 명시합니다.
- 연구 프리뷰이므로 API 헤더 날짜와 한도는 문서를 다시 확인합니다.
