# Neural Flappy: CSS가 신경망 추론을 하는 플래피 버드 실험실

<https://github.com/veuler/flappynn>

## 소개

Neural Flappy(저장소 이름 flappynn)는 플래피 버드를 로컬에서 돌리며,
새의 점프 판단을 신경망으로 내리는 실험 저장소다.
특이한 점은 추론을 JavaScript가 아니라 CSS가 한다는 것이다.
학습한 가중치를 `model.css`로 내보내고, 가중합과 ReLU, 시그모이드를 모두
CSS `calc()`로 계산한다.
새의 물리는 JavaScript가 맡고, 학습은 Python의 CPU용 PyTorch가 맡는다.

저장소는 Veysel Nantu가 2026년 10월 9일에 처음 공개했고,
글을 쓰는 시점에 커밋은 두 개, 별은 10개다.
라이선스는 PolyForm Noncommercial 1.0.0이다.
README는 이를 OSI 오픈소스가 아닌 소스 공개(source-available)라고 분명히 적고,
개인적·비상업적 실험만 허용한다.

로컬 서버 하나에 실험실 두 개가 붙는다.

| 실험실 | 주소                | 입력 → 은닉 → 출력 | 학습 방법                 |
| ------ | ------------------- | ------------------ | ------------------------- |
| 6→16→1 | `/`(`lab-616.html`) | 6 → 16 ReLU → 1    | 사람 기록 모방, PPO       |
| 5→16→1 | `/lab-516.html`     | 5 → 16 ReLU → 1    | 사람 기록 모방, 진화 탐색 |

README가 가장 공들여 설명하는 것은 숫자 자체보다 그 숫자의 출처다.
아키텍처(모양), 가중치(저장된 숫자), 무작위 초기화(새로 뽑은 숫자)를
따로 구분하고, 번들된 모델 파일마다 어떤 종류의 가중치인지 라벨을 붙인다.
테스트를 통과했다는 것은 계약이 지켜졌다는 뜻일 뿐
실력을 인증하지 않는다는 식의 단서가 문서 곳곳에 있다.

## 동작 방식

### 게임 세계는 JavaScript가 소유한다

화면은 480×640이고, 중력은 1500px/s², 점프는 수직 속도를 −440px/s로 만든다.
물리는 120Hz로 진행하고, 신경망에는 50ms마다 묻는다.
점프가 받아들여지면 100ms 동안은 다음 점프가 적용되지 않는다.
보통 난이도의 파이프는 180px/s로 움직이고,
어려움 난이도는 점수 1점마다 목표 속도를 1%씩 올려 270px/s(1.5배)까지 높인다.
실제 속도는 2초에 걸쳐 그 목표에 다가간다.

입력은 정규화한 값이다.
새 높이 `y/640`, 수직 속도 `vy/1200`, 다음 파이프까지 거리 `distance/600`,
틈 높이 `gapY/640`, 수평 속도 `speed/270`이 다섯 개이고,
6입력 모델은 그다음 파이프의 틈 높이를 하나 더 받는다.

### 추론 한 번의 경로

1. JavaScript가 현재 상태를 정규화해 `--bird-y`, `--velocity-y` 같은 CSS 사용자 정의 속성에 `setProperty`로 쓴다.
2. 브라우저가 `model.css`의 규칙대로 은닉 유닛마다 `--h1-z: calc(...)`로 가중합을 구하고, `max(0, ...)`로 ReLU를 적용한다.
3. 출력 로짓을 같은 방식으로 더한 뒤 `calc(1 / (1 + exp(-1 * z)))`로 점프 확률을 만든다.
4. JavaScript가 `--jump-probability`와 은닉값, 로짓을 읽어 임계값(기본 0.50)과 비교하고 점프를 결정한다.

중간값을 숫자로 다루게 하는 열쇠는 `@property`다.
은닉 유닛과 출력마다 `syntax: "<number>"`로 등록해 두어야
브라우저가 그 속성을 문자열이 아니라 숫자로 계산한다.
그래서 이 실험은 `@property` 숫자 등록과 `calc()` 안의 `exp()`를 지원하는
최신 브라우저를 요구한다.
페이지는 시작할 때 `--nn-probe: calc(1 / (1 + exp(-1)))`를 계산해
0.7310585786300049와 1e-4 이내인지 확인한다.
이 검사가 실패하면 추론을 멈추며, JavaScript로 대신 계산하는 대체 경로는 없다.

결과를 읽는 쪽에도 결정이 하나 들어 있다.
`css-numbers.js`는 먼저 `computedStyleMap()`(CSS Typed OM)으로
숫자를 그대로 읽고, 지원하지 않는 브라우저에서만 `getComputedStyle`의 문자열을 엄격하게 파싱한다.
주석은 문자열 직렬화가 유효숫자를 잃을 수 있다고 이유를 적는다.
아래 확인하기 절의 실험에서
Chrome 154는 실제로 문자열을 소수 여섯 자리로 잘랐다.

### 학습은 Python이 하고, CSS는 학습에 끼지 않는다

학습과 학습 재생은 Python 정책의 출력을 쓴다.
CSS는 저장된 모델로 플레이할 때만 쓰인다.
PPO는 학습 중에 값 추정을 위한 비평자(critic) 네트워크 6 → 64 tanh → 1을
따로 두지만, 비평자는 CSS 파일에 들어가지 않는다.
Python은 학습을 마치면 가중치 JSON, CSS 묶음, 메타데이터를 내보낸다.

## 실행하기

README는 Windows만 지원한다고 명시한다.
학습 서비스가 Python을 `.venv\Scripts\python.exe`에서만 찾기 때문에,
다른 운영체제의 `bin/python` 가상 환경은 찾지 못한다.
Node.js 20 이상(24.11.0에서 시험)과
64비트 Python 3.11(3.11.9에서 시험)이 필요하고, GPU는 필요 없다.

```powershell
git clone https://github.com/veuler/flappynn.git
cd flappynn
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm start   # npm 의존성이 없어 npm install은 필요 없다
```

서버는 `127.0.0.1:3030`에만 붙고, 학습 API는 `localhost`와 `127.0.0.1`에서,
그리고 페이지 출처가 그 호스트와 같을 때만 응답한다.
HTML 파일을 직접 열면 ES 모듈과 모델 파일을 HTTP로 가져오지 못해
동작하지 않는다.
테스트는 `npm test`(Node 내장 테스트 러너)와
`npm run test:ml`(Python `unittest`)로 돌린다.

### 학습 경로 셋

- 사람 기록 모방: 직접 플레이하며 입력과 점프 여부를 기록하고, 난이도마다 서로 다른 시드 2개 이상에서 200개 이상의 표본을 모은 뒤 학습한다. Adam을 쓰고, 프레임이 아니라 시드 단위로 학습·검증을 나누며, 검증 성능이 멈추면 조기 종료한다. 기록은 페이지 메모리에만 있으므로 새로 고치기 전에 JSON으로 내려받아야 한다.
- 진화 탐색(5→16→1 전용): 113개 파라미터에 엘리트 보존 가우시안 탐색을 5분, 10분, 15분 동안 돌린다. 검증 시드 8개로 체크포인트를 고르고, 시드 1~20은 탐색에서 뺀다.
- PPO(6→16→1 전용): Fast 모드는 환경 32~512개를 CPU 한 번의 배치 시뮬레이션으로 돌리고, Live 모드는 환경 하나를 게임 속도로 돌린다. 보상은 파이프 통과 +1, 충돌 −1, 생존 1초당 +0.02이고, 한 판은 시뮬레이션 시간 600초에서 끊는다. 이 상한에 닿으면 죽음으로 치지 않고 비평자 값으로 부트스트랩한다.

### 승격 규칙

모방 학습과 진화 탐색은 같은 승격 규칙을 쓴다.
먼저 CSS 계산이 Python 참조와 일치하는지(패리티)와
Python 시뮬레이터와 브라우저 CSS 플레이가 일치하는지를 확인한다.
그다음 시드 1~20에서 각각 최대 180초씩 기존 모델과 후보를 겨룬다.

| 조건          | 기준                                                                |
| ------------- | ------------------------------------------------------------------- |
| 평균          | 올라야 하고, 새 평균이 기존보다 5% 이상 높아야 한다                 |
| 중앙값        | 떨어지면 안 된다                                                    |
| P10           | 기존 P10의 90% 이상을 유지해야 한다                                 |
| 심한 퇴보     | 기존의 절반 미만이면서 10점 이상 잃은 시드는 최대 하나까지 허용한다 |
| 기존 점수가 0 | 0과 같아도 통과가 아니다, 반드시 나아져야 한다                      |

모두 통과하면 후보가 자동으로 설치된다.
통과하지 못해도 “Use candidate permanently”로 퇴보를 감수하고 저장할 수 있다.
PPO는 점수가 올랐다고 자동 설치하지 않는다.
“Verify CSS policy”로 계산을 검증한 뒤 “Save policy”를 눌러야 하고,
설치에 실패하면 작업 디렉터리에 둔 이전 슬롯 사본으로 되돌린다.

## 트레이드오프

### CSS 추론은 대체 경로를 일부러 없앴다

JavaScript로 같은 신경망을 계산하는 대체 경로가 있었다면
`exp()`를 지원하지 않는 브라우저에서도 게임이 돌아갔을 것이다.
저장소는 그 길을 택하지 않았다.
대체 경로가 있으면 화면의 새가 CSS로 날고 있는지 JavaScript로 날고 있는지
겉으로 구분할 수 없고, 실험의 주장 자체가 흐려지기 때문이다.
그 대가로 브라우저 지원 범위가 좁아지고,
프로브가 실패하면 AI 플레이는 아예 불가능하다.

이 선택이 남기는 어려움은 검증 비용이다.
같은 가중치를 PyTorch와 CSS 두 곳에서 계산하므로,
두 계산이 같다는 것을 매번 따로 증명해야 한다.
저장소가 패리티 페이지, 참조 입력 묶음, 1e-4 허용 오차, SHA-256로 검사하는
모델 바이트, 줄바꿈 변환을 막는 `.gitattributes`까지 두는 이유가 여기 있다.
번들된 `lookahead-616`의 `browser-parity.json`과 `parity-inputs.json`은 각각
2.6MB, 3.0MB로, 6.8KB인 `model.css`보다 수백 배 크다.

### 학습과 플레이의 정책이 다르다

PPO는 학습 중 정책 확률에서 행동을 표본 추출하지만,
저장된 CSS 플레이는 고정 임계값 0.50으로 결정한다.
같은 가중치라도 학습 중 평균 점수와 저장 후 점수가 다를 수 있다.
README도 이 점을 적는다.
확률적 정책을 결정적으로 바꾸면 보통은 더 안정적이지만,
학습이 탐색 덕에 넘던 상황을 결정적 정책이 넘지 못하는 경우도 생긴다.
화면의 학습 평균(최근 100판)은 승격용 20시드 벤치마크와 다른 숫자라,
둘을 섞어 읽으면 안 된다.

### 고정된 20시드는 비교 기준이지 시험이 아니다

시드 1~20을 고정해 두면
기존 모델과 후보를 같은 코스에서 공정하게 비교할 수 있다.
대신 같은 시드로 실행과 임계값 조정을 반복할수록
그 20개 코스에 맞춘 모델이 승격된다.
README 스스로 이 반복이 독립적인 최종 시험을 만들지 않는다고 경고하고,
진화 탐색의 검증 시드도 이미 체크포인트 선택에 쓰였다고 적는다.
새 시드를 매번 뽑으면 과적합은 줄지만 비교의 분산이 커지고,
20개보다 많은 시드를 쓰면 승격 한 번이 그만큼 느려진다.
공정한 비교, 낮은 과적합, 빠른 승격을 작은 실험에서 한꺼번에 가질 수는 없다.

## 함정

- README가 첫 줄에서 링크하는 `src/models/lookahead-616/model.css`는 6→16→1 모델이지만, 실제로 쓰이는 것은 그 일부다. 은닉 유닛 9~16번은 가중치와 편향이 모두 0이어서 ReLU 출력이 항상 0이고, 수평 속도와 그다음 파이프 틈 높이 열도 모든 유닛에서 0이다. 이 파일은 README가 `warm-start-lookahead`라고 라벨을 붙인, 5입력 모델을 옮긴 출발점이라 실질적으로는 4입력 8은닉 신경망이다.
- 같은 이유로 보통 난이도 기본 모델은 파이프 속도를 보지 않는다. README는 이 파일을 “학습된 파이프 속도 활용이 아니라 출발점”이라고 적는다. 어려움 난이도의 속도 변화에 반응하는 모델을 원하면 직접 학습해야 한다.
- 번들된 PPO 정책은 어려움 난이도 하나뿐이다. 새로 받은 저장소에서 보통 난이도의 저장된 RL 정책은 선택할 수 없고, 무작위 가중치에서 시작해 검증하고 저장해야 한다.
- 무작위 초기화로 모방 학습을 시작해도 저장된 기준 모델 파일이 있어야 한다. 승격 비교에 쓰기 때문이다. 기준 파일을 지우면 모방 학습은 시작하지 못한다.
- 기록은 탭마다 따로지만 학습 작업과 저장 파일은 서버 하나를 공유한다. 서비스마다 작업은 하나만 돌고, 한 탭에서 모델을 설치하면 다른 탭이 불러오는 모델도 바뀐다.
- 번들 슬롯에 저장하면 추적되는 가중치와 CSS 파일이 바뀌어 `git diff`에 나타난다. 의도치 않게 새 정책을 공개하지 않으려면 저장 전에 슬롯을 확인해야 한다.
- 패리티 검사는 은닉값, 로짓, 확률의 산술이 일치한다는 증거일 뿐, 잘 난다는 증거가 아니다. README도 이를 분명히 구분한다.

## 확인하기

CSS가 신경망 한 층을 계산하는지는 저장소 없이도 확인할 수 있다.
아래 파일을 `nn.html`로 저장해 최신 Chrome에서 열면 된다.
입력 하나, 은닉 유닛 하나, 시그모이드 출력 하나짜리 축소판이다.
같은 규칙과 코드를 Chrome 154의 페이지에 넣어 실행해 보았다.

```html
<!doctype html>
<style>
  /* 숫자로 등록해야 calc() 결과가 숫자로 계산되고 읽힌다 */
  @property --h { syntax: "<number>"; inherits: false; initial-value: 0; }
  @property --p { syntax: "<number>"; inherits: false; initial-value: 0; }
  .nn {
    --x: 0;
    --h: max(0, calc(var(--x) * 2 - 1));                 /* ReLU(2x - 1) */
    --p: calc(1 / (1 + exp(-1 * (var(--h) * 3 - 1))));  /* sigmoid(3h - 1) */
  }
</style>
<div class="nn" id="nn"></div>
<pre id="out"></pre>
<script>
  const el = document.getElementById('nn');
  const rows = [];
  for (const x of [0, 0.5, 1, 2]) {
    el.style.setProperty('--x', String(x));
    const typed = el.computedStyleMap().get('--p').value;          // 원래 정밀도
    const text = getComputedStyle(el).getPropertyValue('--p');     // 직렬화된 문자열
    rows.push(`x=${x} p=${typed} text=${text}`);
  }
  document.getElementById('out').textContent = rows.join('\n');
</script>
```

Chrome 154에서 x가 1일 때 Typed OM은 0.8807970779778823을,
`getComputedStyle`은 `0.880797`을 돌려주었다.
x가 0과 0.5일 때는 ReLU가 0을 내므로 둘 다 sigmoid(−1)인 0.2689414213699951이다.
저장소가 Typed OM을 먼저 쓰고 문자열은 대체 경로로만 남긴 이유가 이 차이다.

저장소 전체는 Windows에서만 위 실행하기 절의 명령으로 돌릴 수 있고,
그 부분은 직접 실행하지 않았다.

## 기억할 원칙

### 계산 장소를 옮기면 검증할 대상이 둘로 늘어난다

이 실험의 핵심 주장은 CSS가 신경망을 계산한다는 것이지만,
저장소의 상당 부분은 그 계산이 PyTorch와 같다는 것을 증명하는 데 쓰인다.
모델을 학습한 곳과 실행하는 곳이 다르면,
둘 사이의 일치는 저절로 주어지지 않고 산출물로 만들어 지켜야 한다.
서버 모델을 모바일이나 브라우저로 옮기는 실제 작업에서도 같은 비용이 든다.

### 숫자에는 출처 라벨을 붙인다

README는 같은 모양의 가중치 파일이라도 warm-start, 모방, PPO를 구분해 적고,
“이 라벨은 실력 인증이 아니다”라고 덧붙인다.
그 라벨이 없었다면 6→16→1이라는 이름만 보고
여섯 입력을 모두 학습한 모델이라고 오해했을 것이다.
모델 파일을 공유할 때는 모양보다 출처를 먼저 적는 편이 안전하다.
