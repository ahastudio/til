## 소개

`cargo clippy-html`은 Rust의 린터 Clippy가 낸 진단을 rustdoc 스타일의 정적 HTML 보고서로 만드는 Cargo 하위 명령이다.
이 문서는 `README.md` 전문, 저장소 목록, GitHub API 수치, 샘플 보고서 사이트의 첫 화면, GeekNews Show GN 토픽을 읽었다.
소스 코드와 `docs/` 문서, 로드맵은 열지 않았고 직접 설치해 써 보지도 않았다.
설명은 모두 저장소의 주장이다.

GitHub API로 읽은 시점(2026년 11월 18일)의 수치는 별 0개, 포크 0개, 열린 이슈 0개, 라이선스 Apache-2.0(README는 MIT와 Apache-2.0 중 선택이라고 적는다), 언어 Rust, 생성일 2026년 10월 27일, 마지막 푸시 2026년 11월 18일이다.
GitHub 저장소의 홈페이지 필드는 비어 있다. 위 사이트 주소는 GeekNews 토픽이 소개한 것이며, 열어 보니 이 도구가 자기 자신을 검사해 만든 샘플 보고서였다.

핵심 기능은 이렇다.

- 사용법: Cargo 프로젝트에서 `cargo clippy-html --open`을 실행하면 기본으로 `<Cargo target directory>/clippy-html/index.html`에 보고서를 만든다. 빌드에는 Rust 1.88 이상이 필요하고 소스에서 `cargo install --path . --locked`로 설치한다고 한다. 설치 용도로 배포된 패키지(crates.io)는 README에 없다.
- 보고서 구성: 린트, 범주, 소스 파일로 찾아볼 수 있다. 개요 페이지는 Clippy가 성공했는지, 진단 수집이 끝났는지, 패키지별 개수와 중복 병합 전후 개수를 보여 준다. 소스 페이지에서는 파일 트리나 줄 링크로 발견 사항에 가고, 주된 범위와 부수 범위를 배경색으로 구분하며, Clippy의 제안을 통합 diff로 볼 수 있다. 패치 복사 단추가 제안 전체(여러 파일의 수정 포함)를 복사하고 Clippy가 부여한 적용 가능성(applicability)을 보여 준다.
- 검색과 접기: 린트 이름, 경로, 메시지, 범주를 대소문자 구분 없이 모든 단어로 검색한다. 탭마다 최대 100건과 전체 개수를 보여 준다. 요약 모드로 진단 세부를 접을 수 있다. 단축키(`S`나 `/`로 검색, `?` 도움말, `-`로 접기, `+`나 `=`로 펼치기)와 테마(밝음, 어둠, Ayu, 시스템)가 있다.
- JavaScript 없이도 동작하는 범위: 기본 페이지, 링크, 구문 색, diff, 개별 진단 접기. 검색, 설정, 전체 요약 제어, 패치 복사는 JavaScript가 필요하다.
- 인자 전달: 첫 `--` 뒤는 Cargo Clippy로, 둘째 `--` 뒤는 rustc와 Clippy로 간다. `--fix`와 `--message-format`은 구조화된 진단이 필요하고 소스를 건드리지 않는 실행이어야 해서 거절한다. `--offline`을 `--` 앞에 두면 내장 범주 표를 쓰고, 뒤에 두면 Cargo가 로컬 의존성만 쓴다.
- 범주 표: Clippy 진단 링크가 하나의 문서 버전을 가리키면 온라인 범주 표를 기본으로 가져오고, 버전을 못 찾거나 가져오지 못하거나 검증에 실패하면 내장 표를 쓴다. 일치하지 않는 린트는 Unknown으로 둔다. 범주 조회는 심각도와 종료 상태를 바꾸지 않는다.
- 메타데이터: `--metadata <FILE>`로 린트 코드, 심각도, 범주로 거를 수 있는 JSON 색인을 쓴다.
- 안전한 출력: 임시 디렉터리에서 보고서를 만들고 검사한 뒤 대상을 교체하며, `.clippy-html-owned` 표식이 있는 기존 보고서만 교체하고 프로젝트, 패키지, target, 빌드 루트를 보호한다. 동시 쓰기는 잠금으로 막는다. Clippy가 실패해도 보고서를 쓸 수 있고 Clippy의 0이 아닌 종료 상태를 보존하며 불완전한 수집을 따로 표시한다.
- 호스팅과 주의: 보고서 디렉터리 전체를 정적 호스트에 올릴 수 있고 상대 링크로 하위 경로에서도 서비스된다. 보고서가 작업 영역 소스와 로컬 경로를 담을 수 있으므로 공유나 Pages 업로드 전에 검토하라고 한다.

샘플 보고서는 `cargo-clippy-html` 0.1.0이 자기 자신을 `--all-targets`와 `-W clippy::pedantic`로 검사한 결과이다. 읽은 시점의 첫 화면은 Clippy 실행 성공(종료 0), 진단 수집 완료, 고유 발견 75건(오류 0, 경고 75), 원 메시지 112건이라고 표시했다.

## 분석

### 중심 주장은 터미널 출력 대신 탐색 가능한 문서를 준다는 것이다

Clippy의 진단은 터미널에 긴 텍스트로 나온다.
이 도구는 같은 진단을 rustdoc처럼 린트, 범주, 파일로 찾아보고 제안을 diff로 검토하게 한다.
정적 HTML이라 CI 산출물이나 Pages로 팀에 공유하기 쉬운 형태이다.
이는 README의 서술을 이 문서가 정리한 것이다.

### 설계가 신중한 쪽에 있다

`--fix`를 거절하고, 출력 교체 전에 임시 디렉터리에서 검사하고, 표식이 있는 보고서만 교체하고, 실패해도 종료 상태를 보존하는 방식은 도구가 사용자의 파일이나 CI 신호를 건드리지 않으려는 선택으로 읽힌다.
JavaScript가 없을 때 되는 기능과 안 되는 기능을 구분해 적은 것도 같은 성격이다. 이는 이 문서의 해석이다.

## 비평

### 아직 사용 근거가 없다

저장소는 2026년 10월 말에 생겼고 별, 포크, 이슈가 모두 0이다. 설치는 소스 빌드가 안내된 유일한 방법이다.
GeekNews 토픽에는 댓글이 없었다. 독립적인 사용 후기나 대규모 프로젝트에서의 동작은 읽지 못했다.
샘플 보고서도 이 도구 자신의 코드에 대한 것이어서 큰 작업 영역이나 오래된 코드베이스에서의 성능은 알 수 없다.

### 비슷한 목적의 기존 수단과의 비교가 README에 없다

Clippy의 JSON 출력을 읽는 도구와 에디터 통합, CI의 주석 기능이 이미 있지만 README는 이들과의 차이를 설명하지 않는다.
이 문서도 그 도구들을 열어 비교하지 못했다. 이 도구의 고유한 점은 정적 HTML 보고서와 탐색 구조이다.

### 보고서 공유의 위험

README가 스스로 밝히듯 보고서에는 작업 영역 소스와 로컬 경로가 들어갈 수 있다.
공개 Pages에 올릴 때 비공개 코드가 새지 않도록 하는 일은 사용자의 몫이다.

### 외부 반응

GeekNews의 Show GN 토픽에는 댓글이 없었다.
HN에서는 저장소 주소와 도구 이름으로 검색한 결과 이 도구의 글이 없었다.
Lobste.rs에서는 `clippy-html`로 검색한 결과가 0건이었다.

## 인사이트

### 가져갈 것은 린트 결과를 사람이 둘러볼 수 있는 산출물로 남기는 습관이다

CI에서 린트가 실패하면 로그를 거슬러 올라가야 하는 팀은 많다.
진단을 범주와 파일로 탐색하고 제안을 diff로 검토하게 하는 형태는 린트 부채를 줄이는 작업을 나눌 때 유용할 수 있다.
다만 이 도구가 팀 규모에서 그 효과를 내는지는 시험해야 안다. 이는 이 문서의 적용이다.

### 공유하는 정적 보고서는 소스와 경로를 포함하는지 먼저 본다

README의 주의는 모든 코드 분석 보고서에 해당한다.
보고서를 외부에 올리기 전에 소스 조각과 경로가 들어 있는지 검토하는 절차를 CI에 넣을 수 있다.

### 확인할 관찰

이 도구의 주장을 가를 관찰은 세 가지이다.
큰 작업 영역에서의 보고서 생성 시간과 크기,
Clippy 버전이 바뀔 때 범주 표와 제안 처리가 유지되는지,
crates.io 같은 정식 배포와 사용자 수가 생기는지이다.
셋 모두 이 문서가 확인하지 못했다.
