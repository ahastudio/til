# Rust 1.100.0 출시

원문: [Announcing Rust 1.100.0](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)

HN 토론: <https://news.ycombinator.com/item?id=50472038> (904점, 321개 댓글)

GN 토론: <https://news.hada.io/topic?id=37070>

## 요약

2026년 11월 12일 Rust 릴리스 팀이 낸 Rust 1.100.0 발표 글이다. 기존 사용자는 `rustup update stable`로 올린다.
이번 릴리스는 약 10년을 끈 never 타입과 사용자 정의 할당자 API의 핵심이 안정화되고, Cargo에 미사용 의존성 경고와 의존성 쿨다운 기능이 들어간 것이 중심이다. 글은 구체적인 변경 기록과 Cargo, Clippy 변경 기록을 링크한다. 이 문서는 발표 글을 읽었고 링크된 변경 기록은 열지 못했다.

- never 타입(`!`): 약 10년, 다섯 번의 안정화 시도 실패 끝에 안정화되었고 프로젝트 목표 하나가 끝났다고 한다. `!`는 발산하는 식(`return`, `break`, `std::process::exit`)의 타입이며 어떤 타입으로도 강제 변환된다. 이제 `!`를 어디서든 이름으로 쓸 수 있어 `Result<T, !>`를 받아 `Ok(v)`만 꺼내는 `infallible_unwrap` 같은 함수를 쓸 수 있다. `Infallible`은 `!`의 별칭이 된다. 호환성 변경으로, 2024 이전 에디션(2015, 2018, 2021)에서 never 타입 대체 규칙이 `()`에서 `!`로 바뀌어 2024 에디션과 같아진다. 눈에 띄는 일은 드물지만 제네릭 반환 함수의 결과를 무시하는 경우 등에 영향을 줄 수 있고 컴파일러가 더 많은 코드를 도달 불가로 표시할 수 있다. 미래 호환 경고가 앞서 나갔고 영향받는 공개 크레이트에는 수정이 나왔다고 한다.
- 할당자 API: `allocator_api`의 핵심(`Allocator` 트레이트, `Global`, `System`)이 안정화되어 당분간 `Vec`과 `Box`에 사용자 정의 할당자를 쓸 수 있다. Allocators 1.0 프로젝트 목표의 토대이고 API 표면과 더 많은 컬렉션과 포인터 형식의 지원은 남아 있다. `Box::new_in`, `Vec::new_in`, `Vec::with_capacity_in` 등이 함께 안정화된다.
- `DropGuard`: `core::mem::DropGuard`는 값과 클로저를 감싸 스코프를 벗어나면 클로저를 실행한다. `DropGuard::dismiss`로 클로저 없이 값을 되돌릴 수 있고 이름 충돌을 피하려고 메서드가 아닌 연관 함수이다. 예는 벡터에 파싱한 값을 넣다가 실패하면 길이를 되돌리는 롤백이다.
- 영 크기 타입 생성: `unsafe fn std::mem::conjure_zst`가 영 크기 타입(ZST)의 값을 만드는 권장 방법이다. `()`를 변환하거나 `MaybeUninit`을 쓰는 방식을 대신한다.
- Cargo의 미사용 의존성 경고: 새 린트 `cargo::unused_dependencies`가 기본 `warn`으로 들어간다. 의존성을 쓸 수 있는 모든 빌드 대상을 빌드해야 나타나므로 `cargo check --bin foo`만으로는 경고가 없고 `dev-dependencies`는 검사하지 않는다.
- Cargo 캐시 충돌 감소: `build-dir`의 구성 해시를 일관되게 적용하고 디렉터리를 파일 형식이 아니라 빌드 단계별로 구성해 해시를 파일 이름에서 상위 디렉터리로 옮겼다. git 워크트리 사이에서 `build-dir`을 공유할 때의 재빌드 오류와 혼란을 줄이며 옛 배치를 우회하던 빌드 스크립트나 테스트가 깨질 수 있다고 경고한다.
- 의존성 쿨다운(`min-publish-age`): 너무 최근에 게시된 버전을 건너뛰는 의존성 해석이 안정화되었다. `.cargo/config.toml`의 `[registry]`에 `global-min-publish-age = "3 days"`처럼 둔다. 한 번만 덮어쓰려면 `CARGO_RESOLVER_INCOMPATIBLE_PUBLISH_AGE=allow`와 `cargo update clap --precise 4.6.9` 같은 명령을 쓴다. 인덱스에 `pubtime`이 없는 버전은 막지 않고 `cargo install`은 최소 경과 시간을 무시하므로 버전을 고정해야 하며, 쿨다운은 공급망 방어의 전부가 아니라고 글이 적는다.
- 안정화된 API: `bool::toggle`, `Box::take`와 `Box::map`, `Rc::map`, `Arc::map`, `str::trim_prefix`와 `trim_suffix`, `Vec::from_fn`, `UnsafeCell::replace`, `impl Default for Once`, `os::windows::process::CommandExt::show_window` 등이다.

글에는 플랫폼 지원 변경 절이나 공헌자 명단이 없고 「기타 변경」도 링크로만 안내한다.

## 분석

### 중심 주장은 오래 끈 두 기능이 한 릴리스에서 끝났다는 것이다

never 타입과 할당자는 각각 수년의 안정화 작업이 쌓인 기능이고 글은 이를 프로젝트 목표의 완료로 소개한다.
HN에서 Rust 핵심 개발자 steveklabnik은 오랜 장기 기능이 마침내 들어온 기념비적 릴리스라고 평했다.[^steveklabnik]
이는 발표의 서술을 이 문서가 정리한 것이다.

### 공급망 방어가 Cargo의 일급 기능이 된다

쿨다운은 새로 올라온 악성 버전을 일정 기간 해석에서 빼는 방식이다. HN에서 한 사용자는 이 기능과 `cargo install`이 기본으로 크레이트의 잠금 파일을 쓰도록 바뀐 점을 이번 릴리스에서 꼽았다.[^nirinor]
쿨다운이 `cargo install`에는 적용되지 않는 이유를 묻자 Cargo 개발자 epage는 MSRV 인식 해석기에서 정한 선례(옛 버전이 조용히 설치되는 것을 피하려는 사용성과 일관성)를 설명했다.[^epage-install]
`pubtime`이 없는 버전이 있는 이유는 레지스트리 규격에 몇 릴리스 전에야 추가되어 모든 레지스트리의 갱신을 보장할 수 없어서라고 답했다.[^epage-pubtime]

### 언어 기능이 일상 코드 패턴에 이름을 준다

`DropGuard`를 두고 HN에서는 Go의 `defer`와 같다는 반응이 있었고, 건너뛸 수 있는 `defer`라는 점이 안전 코드를 정리해 준다는 의견이 있었다.[^levkk][^groxx]
never 타입이 무엇인지 모르겠다는 질문에는 타입을 값의 집합으로 보면 값이 없는 빈 집합이라는 설명이 달렸다.[^xirdus]

## 비평

### 성능과 컴파일 시간 이야기가 빠져 있다

HN에서 한 사용자는 컴파일이 오래 걸리고 매일 `cargo clean`으로 90GB의 임시 파일을 치워야 한다며 컴파일러가 빨라졌는지 물었다. epage는 컴파일 속도와 빌드 디렉터리 크기가 상충할 수 있다며 이번 릴리스의 점진적 개선과 미사용 의존성 린트가 낭비를 줄이는 쪽이라고 답했다.[^jadbox][^epage-compile]
발표 글에는 컴파일 시간의 수치가 없다.

### 안정화 범위가 일부이다

할당자 API는 `Vec`과 `Box`에서 쓰이는 핵심만 안정화되었고 더 많은 컬렉션과 포인터 형식은 남았다.
HN에서 한 사용자는 메모리가 부족한 상황에서도 돌아가는 시스템 프로그래밍을 위해 오래 기다린 릴리스라고 했지만, 다른 사용자는 `try_reserve`가 이미 1.57에서 안정화되었고 사용하는 크레이트가 써야 한다고 짚었다.[^ashvardanian][^iknowstuff]
`Result::into_ok`와 `into_err`가 never 타입과 같은 릴리스에 못 들어온 것은 컷오프를 간발의 차로 놓쳐 1.101에 실린다는 설명이 있었다.[^nobodynada]

### 쿨다운의 한계가 크다

글이 인정하듯 `pubtime`이 없는 버전은 막지 못하고 `cargo install`은 우회하며 완전한 방어가 아니다. 격리와 탐지 같은 후속 작업은 계획 단계이다.

### 이름과 API의 필요가 논의된다

HN에서 `bool::toggle`이 `x = !x`보다 나은 이유를 묻는 질문이 나왔고 글에 설명은 없다.[^jacksontheel] 안정 ABI를 원한다는 의견에는 제네릭이 있어 호출 규약만 고정해서는 부족하다는 답이 달렸다.[^joshtriplett]
발표 글이 미사용 의존성 린트가 기존 도구(machete, shear)를 대체하는지는 다루지 않는다.[^jtwaleson]

### 외부 반응

HN 글 제목은 「Rust 1.100」이고 처음에는 릴리스 노트 링크로 올라왔다가 발표 글 주소로 바뀌었다.
Lobste.rs에서는 `rust 1.100` 검색이 2,008건의 관련 없는 결과를 돌려줘 이 글의 유무를 판단하지 못했다. 이 문서는 없다고 단정하지 않는다.
GeekNews 토픽에는 HN 의견을 옮긴 GN⁺ 블록만 있고 이용자 댓글이 없었다.

## 인사이트

### 가져갈 것은 의존성 쿨다운을 프로젝트 설정에 넣는 일이다

`global-min-publish-age`를 3일처럼 두면 갓 올라온 버전이 잠금에 들어오는 것을 늦출 수 있다. 팀의 `.cargo/config.toml`에 두고, `cargo install`로 받는 도구는 버전을 고정한다. 이는 이 문서의 적용이다.

### 올리기 전에 호환성 변경을 점검한다

2024 이전 에디션에서는 never 타입 대체가 `()`에서 `!`로 바뀌고 `build-dir` 배치가 달라진다. 빌드 스크립트가 옛 배치에 기대는지, 의존성이 영향받는지 CI에서 먼저 시험한다.

### 확인할 관찰

이 발표의 주장을 가를 관찰은 세 가지이다.
자기 프로젝트에서 미사용 의존성 경고가 잡는 규모,
`build-dir` 변경 뒤의 재빌드 횟수와 디스크 사용량,
할당자 API의 컬렉션 확대 시점이다.
셋 모두 이 문서가 확인하지 못했다.
