# 카카오, ‘카나나-2’ 경량 모델 4종 오픈소스 공개

<https://huggingface.co/kakaocorp/kanana-2-1.3b-base>

GN 토론: <https://news.hada.io/topic?id=32124>

## 소개

카카오가 자체 언어 모델 계열 ‘카나나-2(Kanana-2)’의 경량 모델 4종을
오픈소스로 공개했다.
30억(3B) 파라미터 베이스 모델과, 이를 캐스케이드 프루닝(cascade pruning)과
증류(distillation)로 압축한 13억(1.3B) 파라미터 모델을 각각 베이스와
인스트럭션 튜닝(instruction-tuned) 버전으로 나눠 총 4종을 배포했다.

1.3B 모델은 1024토큰 슬라이딩 윈도우 어텐션과 풀 어텐션을 3:1 비율로 섞은
하이브리드 레이어 구조를 채택해 최대 32,768토큰 컨텍스트를 지원하면서도
32K 컨텍스트 기준 KV 캐시 메모리 사용량을 약 72.7% 줄였다.
새로 만든 한국어 토크나이저는 이전 버전 대비 한국어 처리 효율을 30% 이상
개선했다.

모델은 TPU 클러스터에서 사전 학습을 마친 뒤 지도 미세조정(SFT)과 강화
학습(RL)을 거쳤으며, 사전 학습과 사후 학습 어느 단계에서도 카카오 사용자
데이터를 사용하지 않았다고 밝히고 있다.
한국어 벤치마크에서 KMMLU 44.17점, HAE-RAE Bench 75.34점을 기록했고,
일반·수학·코딩 벤치마크에서도 경쟁력 있는 성능을 보인다고 설명한다.
라이선스는 카카오가 자체 제정한 KananaOpenLicense이며, `trust_remote_code=True`
옵션과 Transformers 4.57 이상 버전이 필요하다.
vLLM, SGLang, Docker를 이용한 배포를 공식 지원한다.

## 분석

### 압축과 하이브리드 어텐션의 결합이 갖는 의미

1.3B 모델은 3B 모델을 처음부터 새로 학습한 것이 아니라 캐스케이드 프루닝과
증류로 만들어졌다.
이는 큰 모델의 지식을 작은 구조에 옮겨 담는 방식으로, 처음부터 소형
모델을 학습시키는 것보다 품질 손실을 줄이는 접근으로 알려져 있다.
여기에 슬라이딩 윈도우와 풀 어텐션을 3:1로 섞은 하이브리드 구조를 더해
KV 캐시를 72.7% 줄인 점이 눈에 띈다.
파라미터 수를 줄이는 최적화와 어텐션 구조 자체를 바꾸는 최적화를 함께
적용했다는 점에서, 단순히 모델을 작게 만드는 것을 넘어 서빙 비용 구조
자체를 겨냥한 설계로 읽힌다.

### 한국어 토크나이저 개선이 갖는 실질적 효과

토크나이저 효율이 30% 개선됐다는 수치는 단순한 벤치마크 점수가 아니라
실제 운영 비용과 직결된다.
같은 한국어 문장을 더 적은 토큰으로 표현할 수 있으면 추론 비용과
지연 시간이 함께 줄어들고, 동일한 컨텍스트 윈도우 안에 더 많은 정보를
담을 수 있다.
다국어 범용 토크나이저를 그대로 쓰는 해외 모델 대비, 한국어에 특화된
토크나이저를 자체 제작해 배포하는 것은 국내 기업이 가질 수 있는 실질적인
차별점 중 하나다.

### 사용자 데이터 미사용 명시가 신호하는 것

카카오는 사전 학습과 사후 학습 모두에서 자사 사용자 데이터를 사용하지
않았다고 명시적으로 밝히고 있다.
이는 카카오톡 같은 서비스에서 수집되는 방대한 데이터를 학습에 활용했을
것이라는 외부의 의심을 사전에 차단하려는 의도로 보인다.
동시에 이 발표는 향후 사용자 데이터를 활용한 모델이 별도로 존재하거나
계획되어 있을 가능성을 배제하지 않는다는 점에서, 공개 모델과 내부 서비스용
모델 사이에 선을 긋는 커뮤니케이션 전략으로도 읽을 수 있다.

## 비평

### 경량 모델 공개가 곧 기술 리더십을 뜻하지는 않는다

3B와 1.3B급 경량 모델은 온디바이스 및 저비용 추론 시장을 겨냥한 것이지,
최전선 성능 경쟁을 위한 모델이 아니다.
GeekNews 댓글에서 xguru[^xguru]는 “매번 해외 모델들만 보다가 국내 모델들
보니 반갑다”면서도 핵심 팀원들이 더 적극적으로 나서주면 좋겠다는 아쉬움을
함께 표현했는데, 이는 경량 모델 공개 자체보다 그 이상의 기술적 존재감을
기대하는 반응으로 읽힌다.
대형 플래그십 모델 없이 경량 모델만 오픈소스로 내놓는 전략은 커뮤니티
관심을 끄는 데는 효과적이지만, 그것이 곧 최상위 모델 개발 역량을
입증하는 것은 아니다.

### 벤치마크 수치만으로는 실사용 품질을 판단하기 어렵다

모델 카드가 제시하는 KMMLU 44.17점, HAE-RAE 75.34점 같은 수치는 같은
파라미터 규모의 다른 한국어 모델과 나란히 놓고 비교해야 의미가
드러난다.
문서 자체에는 동급 모델과의 직접 비교표가 제공되지 않아, 이 점수가
실제로 경쟁력 있는 수준인지, 아니면 평균적인 수준인지 독자가 스스로
다른 자료를 찾아 대조해야 한다.
경량화를 강조하는 발표일수록 압축으로 인한 품질 저하 폭을 원본 3B
모델과 나란히 제시하는 것이 설득력을 높이는데, 이 비교가 충분히
전면에 드러나 있지 않다.

### KananaOpenLicense는 표준 오픈소스 라이선스가 아니다

MIT나 Apache 2.0 같은 널리 검증된 라이선스 대신 카카오가 자체 제정한
KananaOpenLicense를 사용한다는 점은 상용 이용이나 재배포 조건에 제약이
있을 가능성을 시사한다.
많은 국내외 기업이 “오픈소스”라는 표현을 쓰면서도 실제로는 상업적
이용을 제한하는 커스텀 라이선스를 채택하는 경우가 흔하다.
이 문서만으로는 라이선스의 구체적 제약 조건을 알 수 없으므로, 실제
도입을 고려하는 개발자라면 “오픈소스 공개”라는 문구를 그대로 받아들이지
말고 라이선스 원문을 반드시 확인해야 한다.

## 인사이트

### 경량화 경쟁은 클라우드 종속에서 벗어나려는 흐름의 일부다

KV 캐시를 70% 이상 줄이고 1GB 안팎으로 실행 가능한 모델을 공개하는
흐름은 카카오만의 시도가 아니라 업계 전반에서 동시에 나타나고 있다.
이는 단순한 기술 트렌드가 아니라, AI 서비스를 제공하는 기업들이
클라우드 GPU 임대 비용에 대한 구조적 부담에서 벗어나려는 움직임으로
해석할 수 있다.
자체 인프라나 저사양 서버에서 돌릴 수 있는 모델을 확보하는 것은
장기적으로 API 호출 비용에 종속되지 않는 협상력을 만든다.
이런 관점에서 경량 모델 공개 경쟁은 향후 몇 년간 대형 모델 경쟁 못지않게
치열해질 가능성이 크다.

### 자체 토크나이저 제작은 언어별 AI 주권 논의로 이어진다

한국어 특화 토크나이저를 별도로 제작해 배포하는 시도는, 한국어 처리
효율이 다국어 범용 토크나이저를 채택한 해외 모델에 계속 의존해서는
안 된다는 문제의식과 맞닿아 있다.
이는 비영어권 국가들이 자국어 AI 인프라를 자체적으로 확보하려는 더
넓은 흐름, 이른바 “언어 주권(linguistic sovereignty)” 논의의 한
사례로 볼 수 있다.
토크나이저 하나의 개선이 사소해 보일 수 있지만, 장기적으로는 언어별
AI 생태계의 자립도를 가늠하는 지표가 될 수 있다.

### 압축 모델의 대중화는 원본 모델의 상업적 위치를 흔든다

3B 원본 모델과 1.3B 압축 모델을 함께 공개하는 방식은, 압축 기술이
충분히 성숙하면 대형 모델 하나만 잘 만들어도 다양한 크기의 파생
제품군을 손쉽게 파생시킬 수 있음을 보여준다.
이는 향후 모델 개발사들이 여러 크기의 모델을 각각 처음부터 학습시키는
대신, 최상위 모델 하나에 투자를 집중하고 나머지는 압축과 증류로
해결하는 전략으로 수렴할 가능성을 시사한다.
결과적으로 “몇 종의 모델을 공개했는가”보다 “원본 모델의 품질과 압축
기법의 완성도”가 모델 생태계 경쟁력을 가르는 핵심 지표가 될 수 있다.
