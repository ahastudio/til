# NVIDIA PAIR: 집 안의 여러 기기에 추론을 분산하는 로컬 라우터

<https://github.com/NVIDIA/Personal-AI-Router>

HN 토론: <https://news.ycombinator.com/item?id=49553090> (4점, 1개 댓글)

## 소개

NVIDIA Personal AI Router(PAIR)는
같은 네트워크에 있는 호환 컴퓨터 그룹을 위한 로컬 추론 라우터다.
Apache License 2.0으로 공개되어 있고 별 1.3천 개를 받았다.
참여 노드를 발견하고, 지원되는 추론 엔진을 관리하며,
애플리케이션과 에이전트에 Ollama 호환·OpenAI 호환 프록시 엔드포인트를 제공한다.
독립적인 요청은 엔진 가용성, 모델 가용성, 현재 부하에 따라
적격 노드로 라우팅된다.

PAIR는 멀티 에이전트 애플리케이션 같은 동시 로컬 워크로드에 유용하다.
설정된 클라이언트·모델 소스·엔진·노드가 모두 로컬일 때,
프롬프트와 응답은 로컬 네트워크 안에 머무르도록 설계되었다.

핵심 한계가 명확히 명시되어 있다.
PAIR는 각 독립 요청을 하나의 노드로 라우팅하며,
GPU 메모리를 풀링하거나, 여러 GPU를 더 큰 논리 GPU로 합치거나,
하나의 모델을 여러 기기에 샤딩하거나,
진행 중인 하나의 추론 요청을 노드들 사이에 분할하지 않는다.

## 명세

지원 운영체제는 Windows 11, Linux, macOS이며,
셋 모두에서 x64와 arm64를 지원한다(Windows on ARM은 실험적).
설치 파일은 Windows `.exe`, Linux `.deb`, macOS `.dmg`로 제공되고,
Windows·Linux·macOS 노드를 함께 묶을 수 있다.
추론 엔진은 Ollama와 LM Studio를 지원한다.

사용 흐름은 데스크톱 애플리케이션 중심이다.
GitHub 릴리스에서 빌드를 내려받아 설치한 뒤,
UI에서 추론 엔진(Ollama 또는 LM Studio)을 설치하고 모델을 추가한 다음,
OpenAI 호환 엔드포인트로 요청을 보낸다.

```bash
curl http://127.0.0.1:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen4:12b","messages":[{"role":"user","content":"In one sentence, what does a router do?"}]}'
```

여러 기기를 묶으려면 한 기기가 여섯 자리 PIN을 표시하고
다른 기기가 클러스터 초대 모달에 그 PIN을 입력한다.
구조적으로 PAIR는 노드 발견 메커니즘, 엔진 관리,
Ollama·OpenAI 호환 프록시 엔드포인트,
가용성·부하 기반 라우팅 로직,
PIN 기반 신뢰 부트스트랩, 클러스터 네트워킹으로 이루어진다.
제거 시 애플리케이션 삭제와 데이터 삭제를 분리해,
모델 가중치는 엔진 저장 디렉터리에 남긴다.

## 분석

### PAIR의 정체성은 라우터이지 클러스터가 아니다

PAIR가 스스로 가장 강조하는 것은 하지 않는 일의 목록이다.
GPU 메모리를 풀링하지 않고, 모델을 샤딩하지 않고,
하나의 추론을 나누지 않는다.
이 부정의 명세가 프로젝트의 정체성을 규정한다.
PAIR는 여러 기기를 하나의 큰 GPU로 만드는 분산 추론 시스템이 아니라,
독립 요청들을 여러 독립 기기에 분배하는 부하 분산기다.

이 구별이 중요한 이유는 사용자의 기대를 정확히 잡아 주기 때문이다.
집 안의 기기 여러 대를 묶는다고 하면
많은 사람이 더 큰 모델을 돌릴 수 있으리라 기대한다.
PAIR는 그것을 명시적으로 부정한다.
HN에서 florianherrengt가 정리했듯,
기기를 추가하면 병렬 처리량은 늘지만
더 큰 모델을 돌리게 해 주지는 않는다.[^florianherrengt]
이것은 성능의 축이 모델 크기가 아니라 동시 요청 수임을 뜻한다.

이 설계 선택은 기술적 현실을 반영한다.
모델을 여러 기기에 샤딩하는 텐서 병렬은
기기 간 고속 인터커넥트를 요구하며,
가정용 이더넷에서는 지연이 추론을 마비시킨다.
PAIR가 요청 단위 라우팅에 그친 것은
가정 네트워크의 대역폭·지연 제약 안에서
실용적으로 가능한 것만 취한 결과다.

### Ollama·OpenAI 호환 프록시가 채택 장벽을 없앤다

PAIR의 영리한 지점은 새 API를 만들지 않은 것이다.
Ollama 호환과 OpenAI 호환 엔드포인트를 제공하므로,
기존에 그 API를 쓰던 애플리케이션과 에이전트는
코드를 바꾸지 않고 엔드포인트 주소만 PAIR로 돌리면 된다.
`127.0.0.1:11434`라는 Ollama 기본 포트를 그대로 쓴 것도 이 의도다.

이 선택이 중요한 이유는 라우터를 투명하게 만들기 때문이다.
애플리케이션은 자기가 단일 로컬 모델과 대화하는지
여러 기기에 분산된 클러스터와 대화하는지 알 필요가 없다.
PAIR는 그 사이에 끼어들어 요청을 적절한 노드로 보낼 뿐이다.
이 투명성 덕에 기존 로컬 LLM 생태계 전체가
수정 없이 PAIR의 잠재적 사용자가 된다.

PIN 기반 신뢰 부트스트랩도 같은 저마찰 철학을 따른다.
여섯 자리 PIN을 한쪽이 보여 주고 다른 쪽이 입력하는 방식은
인증서 관리나 계정 설정 없이 기기를 묶게 한다.
이것은 가정용 도구가 갖춰야 할 단순함이며,
동시에 로컬 네트워크라는 신뢰 경계를 전제로 한 선택이기도 하다.

## 비평

### 프라이버시 약속에는 조건이 붙어 있다

PAIR는 프롬프트와 응답이 로컬 네트워크에 머문다고 내세운다.
그러나 이 약속에는 모든 클라이언트·모델 소스·엔진·노드가 로컬일 때라는
조건이 붙어 있다.
이 조건은 쉽게 깨질 수 있다.
모델을 내려받을 때, 엔진을 업데이트할 때,
혹은 한 노드라도 원격 모델 소스를 참조하도록 설정되면
데이터의 로컬성은 보장되지 않는다.

이 조건성이 중요한 이유는 프라이버시 마케팅의 흔한 공백이기 때문이다.
사용자는 로컬에 머문다는 문구를 무조건적 약속으로 읽기 쉽지만,
실제로는 사용자가 모든 구성 요소를 로컬로 유지할 책임을 진다.
NVIDIA가 이 조건을 명시한 것은 정직하지만,
일반 사용자가 그 조건을 항상 충족하도록 관리할 수 있는지는 다른 문제다.
프라이버시가 기본값이 아니라 올바른 설정의 결과라면,
그것은 취약한 프라이버시다.

또한 이 도구가 NVIDIA GeForce RTX와 특정 하드웨어를 요구한다는 점도
florianherrengt가 짚었다.
RTX 20 시리즈 이상, RTX PRO, DGX Spark,
Apple M4 이상에서만 동작한다는 것이다.[^florianherrengt]
프라이버시를 지향하는 로컬 도구가 특정 벤더의 최신 하드웨어에 묶여 있다면,
그 프라이버시는 그 하드웨어를 살 수 있는 사람에게만 열린다.

### NVIDIA의 전략적 동기가 도구의 중립성과 긴장한다

PAIR가 Apache 2.0 오픈소스이고 로컬 프라이버시를 내세우지만,
이 도구를 만든 주체가 GPU 판매사 NVIDIA라는 사실은
그 동기를 다시 보게 한다.
집 안의 유휴 컴퓨터를 개인 AI 데이터센터로 묶는다는 서사는
사용자가 더 많은 NVIDIA GPU를 갖출 이유를 만든다.

이 동기가 문제가 되는 이유는 도구의 설계 방향을 편향시킬 수 있기 때문이다.
PAIR가 요청 병렬화에 집중하고 모델 샤딩을 하지 않는 것은
기술적 이유도 있지만,
여러 기기를 묶어 하나의 큰 모델을 돌리게 하면
개별 기기의 GPU를 덜 사도 되는 방향이 될 수 있다.
반대로 요청 병렬화는 각 기기가 온전한 모델을 돌려야 하므로
더 많은 고사양 GPU 수요를 만든다.
이 해석이 과도할 수 있지만,
하드웨어 판매사가 만든 무료 도구의 인센티브는 항상 검토 대상이다.

The Verge가 이 도구를 유휴 컴퓨터를 개인 AI 데이터센터로 잇는다고 보도한 것도
이 서사를 증폭한다.
개인 데이터센터라는 표현은 매력적이지만,
실제 PAIR는 데이터센터의 핵심인 자원 풀링을 하지 않는다.
마케팅 서사와 기술적 실체 사이의 이 간극은
사용자가 도구의 실제 능력을 오해하게 만들 수 있다.

## 인사이트

### 가정용 추론의 병목은 연산이 아니라 인터커넥트다

PAIR가 모델 샤딩을 포기하고 요청 라우팅에 그친 결정은
가정용 분산 추론의 근본 제약을 드러낸다.
여러 기기의 GPU를 합쳐 큰 모델을 돌리지 못하는 이유는
연산 능력이 부족해서가 아니라
기기를 잇는 네트워크가 느리기 때문이다.
데이터센터가 InfiniBand나 NVLink로 GPU를 잇는 것과 달리,
가정은 이더넷과 Wi-Fi에 묶여 있다.

이 통찰이 중요한 이유는 가정용 AI의 확장 경로를 규정하기 때문이다.
개인이 여러 기기를 사도 더 큰 모델을 못 돌린다면,
가정용 로컬 AI의 성장은 단일 기기의 GPU 메모리에 갇힌다.
PAIR가 늘려 주는 것은 모델의 크기가 아니라 동시성이므로,
멀티 에이전트처럼 여러 작은 모델을 병렬로 돌리는 워크로드에만 이득이 있다.
이것은 가정용 AI가 큰 모델 하나가 아니라
작은 모델 여럿의 협업으로 갈 수밖에 없는 구조적 이유를 시사한다.

두 번째 차수의 효과는 이것이 클라우드와 로컬의 분업을 고착시킨다는 점이다.
큰 모델은 인터커넥트가 빠른 데이터센터에,
작은 모델 병렬 워크로드는 가정에 남는다.
PAIR는 이 분업의 가정 쪽을 최적화하는 도구이며,
역설적으로 큰 모델을 로컬에서 돌리려는 꿈은
네트워크 물리학이 막고 있음을 확인시킨다.

### 유휴 자원 활용이라는 오래된 꿈이 AI에서 되살아난다

집 안의 유휴 컴퓨터를 묶는다는 PAIR의 발상은
SETI@home이나 그리드 컴퓨팅의 오래된 꿈을 되풀이한다.
쓰이지 않는 연산 자원을 모아 큰 일을 하자는 생각은
분산 컴퓨팅의 역사만큼 오래되었다.
PAIR는 그것을 가정 규모로, AI 추론이라는 새 워크로드에 적용한다.

이 반복이 새로운 프레임을 주는 이유는
왜 이런 시도가 늘 부분적 성공에 그쳤는지를 상기시키기 때문이다.
그리드 컴퓨팅이 임의 작업에 널리 쓰이지 못한 이유는
작업을 독립적으로 쪼갤 수 있을 때만 효율적이었기 때문이다.
PAIR가 정확히 같은 자리에 선다.
독립 요청은 잘 분배하지만 하나의 큰 작업은 못 나눈다.
유휴 자원 활용의 근본 한계,
곧 조율 비용이 이득을 넘어서는 지점은 AI에서도 그대로 남는다.

세 번째 차수의 효과는 이것이 개인 컴퓨팅의 재집중화를 부른다는 점이다.
클라우드로 흩어졌던 연산이 프라이버시와 비용 이유로
다시 가정으로 돌아오려 한다.
Dreeve가 데이터를 로컬로 되찾으려 했듯,
PAIR는 추론을 로컬로 되찾으려 한다.
그러나 둘 다 같은 교훈을 준다.
로컬로의 회귀는 통제를 주는 대신
데이터센터가 규모로 풀던 문제를 개인이 다시 떠안게 한다.
PAIR의 경우 그 문제는 인터커넥트이며,
개인은 그것을 살 수 없다.

### 오픈소스와 하드웨어 판매의 결합이 새로운 해자를 만든다

PAIR가 Apache 2.0으로 공개되었다는 사실과
NVIDIA 하드웨어에 묶여 있다는 사실의 조합은
플랫폼 전략의 한 패턴을 보여 준다.
소프트웨어는 개방하되 그것이 자사 하드웨어에서 가장 잘 돌게 하는 것이다.
코드는 누구나 볼 수 있지만,
그 가치를 온전히 누리려면 NVIDIA GPU가 필요하다.

이 패턴이 중요한 이유는 오픈소스 해자의 진화를 보여 주기 때문이다.
과거의 해자는 독점 소프트웨어였다.
이제 소프트웨어는 무료로 열고,
그 소프트웨어가 전제하는 하드웨어 생태계가 해자가 된다.
CUDA가 그랬듯 PAIR도 NVIDIA 하드웨어의 가치를 높이는 무료 도구다.
오픈소스라는 사실이 이 하드웨어 종속을 가리는 역할을 한다.

이 통찰의 함의는 무료 오픈소스 도구를 평가할 때
그것이 무엇을 파는 회사에서 왔는지를 봐야 한다는 것이다.
PAIR가 나쁜 도구라는 뜻이 아니라,
그 무료성의 대가가 하드웨어 생태계로의 유인이라는 것이다.
사용자가 얻는 편익은 진짜이지만,
그 편익이 특정 벤더의 최신 GPU를 사도록 부드럽게 이끈다는 점은
도구를 채택할 때 함께 셈해야 할 숨은 비용이다.
