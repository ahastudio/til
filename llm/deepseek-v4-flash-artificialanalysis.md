# DeepSeek V4 Flash 0731, Artificial Analysis 벤치마크로 본 저비용 추론 모델

> DeepSeek V4 Flash 0731 (max) - Intelligence, Performance & Price Analysis

<https://artificialanalysis.ai/models/deepseek-v4-flash>

HN 토론: <https://news.ycombinator.com/item?id=49120299> (535점, 291개 댓글)

## 명세

DeepSeek V4 Flash 0731(Reasoning, Max Effort)은 DeepSeek이 2026년
7월 31일 공개한 추론(reasoning) 모델이다. Artificial Analysis
Intelligence Index에서 50/100점을 기록해 101개 평가 모델 중 3위에
올랐으며, 비교 대상 모델군의 중앙값(25점)을 크게 웃도는 성적이다.

가격은 입력 토큰 100만 개당 0.14달러, 출력 토큰 100만 개당 0.28달러다.
특히 캐시 적중(cache hit) 가격이 100만 토큰당 0.003달러로, 이는 101개
모델 중 1위이자 정가 대비 98% 할인에 해당한다. Intelligence Index
전체 평가를 실행하는 데 든 총비용은 72.02달러였으며, 가격 경쟁력
순위는 101개 모델 중 22위다.

기술 사양으로는 100만 토큰 컨텍스트 윈도(약 A4 용지 1,500쪽 분량)를
지원하고, 총 파라미터 2,840억 개 중 실제로 추론에 관여하는 활성
파라미터는 130억 개인 MoE(Mixture of Experts) 아키텍처를 채택했다.
입력과 출력 모두 텍스트만 지원하며 이미지 등 멀티모달 입력은
지원하지 않는다.

모델 가중치는 MIT 라이선스로 공개되어 있으며 Hugging Face에서 내려받을
수 있다. 평가 과정에서 출력 토큰을 2억 1,000만 개나 생성했는데, 이는
평가 대상 100개 모델의 중앙값에 비해 “매우 장황한(verbose)” 수준으로
분류되었다. 현재 이 모델을 제공하는 API 제공업체는 1곳뿐이며, 출력
속도(초당 토큰 수)는 데이터가 제공되지 않았다.

## 분석

### 지능 지수와 가격이 함께 만드는 위치 선정

이 모델의 핵심 서사는 단순히 “성능이 좋다”가 아니라 “성능 대비 압도적으로
싸다”는 조합에 있다. Intelligence Index 3위라는 최상위권 성적을
캐시 적중 기준 100만 토큰당 0.003달러라는, 사실상 다른 모델과
비교 자체가 무의미할 정도로 낮은 가격에 제공한다. 활성 파라미터를
130억 개로 억제한 MoE 구조가 이 조합을 가능하게 하는 기술적
기반이다. 전체 파라미터 2,840억 개 중 극히 일부만 활성화함으로써
학습·서빙 비용을 낮추면서도, 추론 시 “Max Effort” 모드로 사고
과정을 늘려 지능 지수를 끌어올리는 전략이다. 즉 이 모델은 파라미터
수가 아니라 라우팅 효율성과 캐시 재사용을 통해 경제성을 만들어낸
사례로 봐야 한다.

### 캐시 가격 1위라는 지표가 가리키는 것

캐시 적중 가격이 정가 대비 98% 할인이라는 수치는 단순한 비용 절감을
넘어, 이 모델이 반복적인 프롬프트 패턴—예컨대 긴 시스템 프롬프트나
동일한 컨텍스트를 반복 참조하는 에이전트 워크플로—에 특화된 방식으로
설계되었음을 시사한다. 캐시 가격을 이렇게까지 낮게 책정한 것은
DeepSeek이 자사 모델의 실사용 패턴을 단발성 질의응답이 아니라
장문 컨텍스트를 반복 재사용하는 에이전트형 사용 사례로 상정하고
있다는 신호로 읽을 수 있다. 100만 토큰이라는 큰 컨텍스트 윈도 역시
이 가설과 맞물린다.

### “장황함”이라는 특성이 갖는 이중적 의미

평가 중 2억 1,000만 개의 출력 토큰을 생성했다는 사실은 액면 그대로
보면 비효율처럼 보이지만, 추론 모델의 맥락에서는 다르게 해석될 수
있다. Max Effort 설정에서 사고 사슬(chain of thought)을 길게
전개하는 것은 종종 Intelligence Index 같은 벤치마크 점수를
끌어올리는 데 기여한다. 문제는 이 장황함이 실사용 환경에서는 그대로
비용과 지연시간(latency)으로 전가된다는 점이다. 낮은 토큰 단가가
장황한 출력량으로 상쇄될 가능성을 벤치마크 페이지의 가격 정보만
보고는 가늠하기 어렵다.

HN 사용자 WhitneyLand는 이 상쇄 효과를 구체적인 수치로 보여준다.
같은 작업을 완료하는 데 Gemini Flash 3.6보다 약 3.6배 많은
토큰이 필요하다는 것이다.[^whitneyland] 즉 토큰 단가만 보면
저렴해 보여도, 작업당 실제 비용을 계산하면 그 격차가 상당 부분
줄어들 수 있다는 뜻이다. 낮은 가격표와 실제 작업 비용 사이의
간극은 이 페이지가 강조하는 지표만으로는 드러나지 않는다.

### 정보 공백이 만드는 평가의 한계

출력 속도 데이터가 제공되지 않았다는 점, API 제공업체가 단 1곳뿐이라는
점은 이 모델의 실사용 준비도(production readiness)에 대한 중요한
정보가 비어 있음을 보여준다. 벤치마크 페이지는 지능과 가격이라는
두 축에서는 풍부한 데이터를 제공하지만, 실제 서비스 환경에서
중요한 지연시간, 가용성, 공급자 다양성 같은 축에서는 공백이
크다. 이는 이 페이지 하나만으로 모델의 전체 그림을 판단할 수 없다는
뜻이다.

## 비평

### 단일 지수로 “3위”를 말하는 것은 서로 다른 능력을 뭉갠다

Intelligence Index라는 단일 점수로 101개 모델 중 3위라는 서열을
매기는 방식은 코딩, 수학, 추론, 지식 등 성격이 전혀 다른 능력들을
하나의 숫자로 뭉뚱그린다. 실제로 어떤 세부 벤치마크(예: 코드 생성,
수학 문제 풀이, 장문 이해)에서 강점을 보이고 어떤 영역에서
약한지는 이 페이지의 요약 정보만으로는 알 수 없다. 이런 지수는
비교를 단순화해주는 대신, 특정 용도—예컨대 코딩 에이전트로 쓸지,
문서 요약에 쓸지—를 결정해야 하는 실사용자에게는 오히려 판단을
흐리게 만들 위험이 있다. “3위”라는 숫자가 주는 신뢰감은 세부
분포를 가린 결과일 수 있다.

이 우려는 페이지 자체의 내부 일관성 문제로도 확인된다. HN
사용자 fillskills는 같은 페이지 안에서 상단 요약 카드에 표시된
지능 순위(2위)와 하단 차트에 표시된 순위가 서로 다르다고
지적했다.[^fillskills] 단일 지수가 서로 다른 능력을 뭉갠다는
구조적 문제 이전에, 그 지수를 표시하는 페이지 자체가 내부적으로
일관되지 않은 숫자를 보여주고 있다는 것이다. 이는 이 페이지의
수치를 인용할 때 어느 시점, 어느 위치의 숫자를 기준으로 삼았는지
함께 밝혀야 함을 시사한다.

### 가격 경쟁력 순위 22위는 “저렴함”이라는 인상과 어긋난다

캐시 가격이 1위라는 점이 부각되면서 이 모델 전체가 “가장 저렴한
축”에 속한다는 인상을 주지만, 정작 종합 가격 경쟁력 순위는 101개
모델 중 22위에 그친다. 이는 캐시 적중이라는 특정 사용 패턴에서만
압도적 우위를 보일 뿐, 캐시가 걸리지 않는 일반적인 단발성 호출
비용은 그렇게까지 저렴하지 않다는 뜻이다. 벤치마크 페이지가 “캐시
가격 1위”라는 수치를 앞세우는 방식 자체가, 평균적인 사용자의
실제 비용 경험과는 괴리가 있는 지표를 선택적으로 강조하는 것일 수
있다.

### 평가 비용 72달러라는 수치는 재현성 없이 홀로 서 있다

전체 평가에 72.02달러가 들었다는 정보는 흥미롭지만, 이 수치가 다른
모델의 평가 비용과 비교했을 때 높은지 낮은지에 대한 맥락이 이
페이지 안에 없다. 2억 1,000만 개라는 장황한 출력 토큰 수를 감안하면
이 평가 비용은 오히려 낮은 편일 수도 있고, 반대로 캐시를 적극
활용한 결과로 실제 무캐시 환경보다 저평가된 수치일 수도 있다.
단일 숫자를 맥락 없이 제시하는 것은 독자가 스스로 비교 기준을
만들어야 하는 부담을 떠넘기는 것과 같다.

### API 제공업체 1곳이라는 사실이 갖는 리스크는 페이지에서 다뤄지지 않는다

오픈 웨이트 모델임에도 API로 제공하는 업체가 단 1곳뿐이라는 사실은
공급망 리스크를 뜻한다. 그 한 곳의 가격 정책이 바뀌거나, 속도가
저하되거나, 서비스가 중단되면 이 모델을 API로 사용하는 워크로드는
즉시 영향을 받는다. 가중치가 MIT 라이선스로 공개되어 있어 이론적으로는
직접 호스팅이 가능하지만, 2,840억 개의 총 파라미터를 자체 인프라에서
운용하는 것은 웬만한 조직에는 현실적인 선택지가 아니다. 벤치마크
페이지는 이런 운영상의 취약점을 수치로 드러내지 않는다.

### 벤치마크 점수의 신뢰도 자체가 검증되지 않았다

HN 사용자 storus는 더 근본적인 의문을 던진다. 이전 V4 프리뷰
모델들이 환각(hallucination)과 기억 유지 문제를 겪었던 이력을
언급하며, 이번 점수가 실제 능력 향상을 반영하는 것인지, 아니면
벤치마크 자체에 최적화된 "벤치맥싱(benchmaxxing)" 결과인지
지켜봐야 한다고 지적했다.[^storus] 벤치마크 페이지가 제시하는
숫자는 표준화된 절차를 거쳤다는 점에서 신뢰를 주지만, 그 절차가
측정하는 대상과 실사용에서 중요한 신뢰성(reliability) 사이에는
여전히 검증되지 않은 간극이 남아 있다.

## 인사이트

### 캐시 가격 최적화는 모델 설계가 벤치마크가 아니라 워크로드 형태를 겨냥하기 시작했다는 신호다

전통적으로 모델 경쟁은 “같은 프롬프트에 더 똑똑한 답을 내놓는가”를
중심으로 벌어졌다. 하지만 캐시 적중 가격을 98% 할인까지 밀어붙이는
설계는 경쟁의 축이 “단일 질의의 지능”에서 “반복되는 컨텍스트를
얼마나 값싸게 재사용하게 해주는가”로 옮겨가고 있음을 보여준다.
이는 에이전트가 도구 정의, 시스템 프롬프트, 대화 이력을 매 호출마다
다시 처리해야 하는 현재의 LLM API 설계가 만들어낸 경제적 압력의
결과다. 앞으로 모델 제공업체 간 경쟁은 파라미터 수나 벤치마크
점수뿐 아니라, 캐시 아키텍처와 재사용 정책 같은 인프라 계층에서도
벌어질 가능성이 크다. 이는 모델을 고르는 기준이 점점 “지능”에서
“워크로드 적합성”으로 이동하고 있다는 더 큰 흐름의 한 단면이다.

### MoE의 활성 파라미터 대 총 파라미터 비율은 소비자에게 잘못된 직관을 심어줄 수 있다

2,840억 개 총 파라미터 중 130억 개만 활성화된다는 구조는
비율로 보면 약 4.6%에 불과하다. 이런 극단적인 희소성(sparsity)은
서빙 비용을 낮추는 데는 효과적이지만, 동시에 “이 모델은 사실상
130억 파라미터 모델과 비슷한 수준일 것”이라는 오해를 낳기 쉽다.
실제로는 전체 파라미터에 저장된 지식과 전문성의 폭이 추론 품질에
기여하고, 활성 파라미터 수는 연산 비용에만 직접 대응한다. 이
구분을 이해하지 못하면 소비자는 가격과 지능 사이의 관계를
잘못 추정하게 되고, 이는 향후 MoE 모델이 늘어날수록 벤치마크
페이지들이 “파라미터 수” 하나만으로 모델을 비교하는 관행 자체를
재검토해야 한다는 압력으로 이어질 것이다.

### 벤치마크 사이트 자체가 모델 선택의 병목이 되는 순환 구조가 만들어지고 있다

Artificial Analysis 같은 제3자 벤치마크 사이트가 지능 지수, 가격,
속도를 하나의 페이지에 표준화해 제공하면서, 모델 제공업체들은
점점 더 이 사이트의 지표를 최적화 목표로 삼게 될 유인을 갖는다.
캐시 가격을 극단적으로 낮춰 “1위” 배지를 얻는 전략이나, Max
Effort 모드로 추론 시간을 늘려 Intelligence Index를 끌어올리는
전략 모두, 벤치마크 사이트의 평가 방법론에 맞춰 모델의 실제
운영 방식을 조정한 결과일 가능성이 있다. 이는 검색엔진 최적화(SEO)가
콘텐츠 제작 관행을 바꿔놓았던 것과 유사한 구조적 패턴이다. 즉
독립적으로 존재해야 할 평가 지표가 시장 참여자들의 행동을
역으로 형성하는 지표 조작(Goodhart's law)의 초기 징후로 읽을 수
있으며, 이런 벤치마크 페이지를 참고할 때는 “무엇이 측정되는가”뿐
아니라 “무엇이 측정을 위해 최적화되었는가”를 함께 의심할 필요가
있다.

### 아키텍처 변경 없는 성능 향상은 사전학습 이후 최적화 여지가 아직 크다는 신호다

HN 사용자 kamranjon과 1saadcodes는 이 모델의 점수 향상이 구조
변경 없이 추가 파인튜닝만으로 이루어졌다는 점에 주목했다.[^kamranjon]
더 많은 데이터와 연산, 시간을 투입한 후속 학습(post-training)만으로
이 정도 도약이 가능했다는 사실은, 업계가 사전학습(pretraining) 단계의
스케일링에 집중하는 동안 사후 학습 단계에 남아 있는 최적화 여지를
과소평가해 왔을 가능성을 시사한다. 이는 이 벤치마크 페이지가
보여주는 “3위”라는 결과를 파라미터 규모나 아키텍처 혁신의 산물로
해석하면 원인을 잘못 짚는 것이라는 뜻이다. 오히려 같은 아키텍처를
가진 더 작은 모델들에도 같은 수준의 후속 학습 투자가 이루어진다면
비슷한 도약이 재현될 수 있다는 예측으로 이어진다. 이는 향후 모델
경쟁이 새로운 아키텍처 발명보다 후속 학습 파이프라인의 정교함
쪽으로 무게중심을 옮길 수 있다는 뜻이며, 벤치마크 페이지의 순위표만
보고 아키텍처 우위를 추정하는 습관 자체를 재고해야 한다는 함의를
갖는다.
