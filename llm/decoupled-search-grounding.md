# DoorDash는 모델에 내장된 검색을 공유 게이트웨이로 분리해 질의 의도 이해의 검색 비용을 98% 넘게 줄였다고 말한다

원문: [How DoorDash Reduced LLM Search Costs by 98% Without Losing Accuracy - DoorDash](https://careersatdoordash.com/blog/how-doordash-reduced-llm-search-costs-by-98-without-losing-accuracy/)

GN 토론: <https://news.hada.io/topic?id=36733>

## 요약

DoorDash의 엔지니어 Amardeep Kumar, Emmanuel Aboah Boateng, Siddarth Kodwani,
Kyle MacDonald가 2026년 10월 29일에 올린 엔지니어링 글이다.
감사 인사에는 GenAI Platform 팀의 Swaroop Chitlur와 NV 팀의 Sudeep Das가 있다.
DoorDash의 질의 의도 이해(query intent understanding,
QIU) 시스템은 카탈로그와 웹의 증거로 모호한 마켓플레이스 검색어를 해석한다.
글은 이 시스템을 위해 분리된 검색 그라운딩(Decoupled Search Grounding,
DSG)을 만들었다고 소개하고, QIU 평가에서 DSG가 모델 내장(native) 검색의 정확도와
같거나 조금 높으면서 검색 비용을 98% 넘게 줄였다고 말한다.

예시는 450 north라는 검색어다.
그라운딩이 없는 모델은 이것을 식당으로 분류했고,
카탈로그 증거와 웹 검색은 수제 맥주 양조장임을 알아냈으며 시스템은 의도를
주류(Alcohol)로 풀었다.
이 구분이 하위 검색을 식당 결과가 아니라 알맞은 재고로 보낸다는 설명이다.

글이 문제로 꼽은 것은 모델 제공자의 API 안에서 검색이 일어나면 검색 결정이
제공자 안에 머문다는 점이다.
저자들은 검색 제공자를 고르고, 여러 응용에서 증거를 재사용하고,
검색 깊이를 조절하고, 검색 비용과 지연을 추론 모델과 따로 재야 했다고 쓴다.
그래서 문제를 세 가지로 나눈다.
통제는 모델과 검색 백엔드 사이에 이음매가 없어 모델을 바꾸거나 공급자의 가격
변화에 대응하려면 모델 연동을 건드려야 한다는 것이다.
재사용은 두 에이전트가 같은 질문을 하면 검색을 두 번 사는데 질의를 가로챌 곳이
없다는 것이다.
관측 가능성과 계약 안전은 질의별 비용과 지연이 보이지 않고,
검색을 켜면 엄격한 출력 계약이 깨진다는 것이다.

출력 계약이 깨지는 현상을 글은 검색이 유도한 장황함이라고 부른다.
많은 LLM 호출은 출력이 JSON으로 파싱되거나 열거형과 맞춰지거나 불리언으로 읽히는
중간 단계라서, 프롬프트가 최종 답만 내라고 분명히 시킨다.
검색이 없으면 모델이 따르지만 모델 내장 검색을 켜면 자주 따르지 않는다.
두 건물의 높이를 비교하라는 질문에서 내장 검색은 Based on the search results로
시작하는 245자를 돌려주었고, DSG는 Yes.라는 세 글자를 돌려주었다.
둘 다 정답이지만 파싱되는 것은 하나뿐이라고 한다.
HotpotQA에서 Claude Sonnet 4의 내장 검색 답은 답만 내라는 명시적 지시를 78.1%의
경우 설명으로 시작해 어겼고, DSG에서는 같은 양상이 보이지 않았다고 쓴다.
저자들은 증거가 생성 흐름 안이 아니라 구조화된 도구 응답으로 돌아오기 때문이라고
설명한다.

구조는 에이전트, 추론 모델, 교체 가능한 검색 백엔드 레지스트리 사이에 놓인다.
백엔드는 Serper, BrightData, Firecrawl, Exa, Tavily이고,
모델 내장 검색도 같은 인터페이스 뒤의 한 제공자로 등록할 수 있다.
게이트웨이는 Model Context Protocol(MCP)과 호환되는 하나의 인터페이스를 모든
에이전트에게 준다.
글이 주장하는 성질은 다음과 같다.
추론 모델을 바꿔도 그라운딩 정책은 움직이지 않는다.
제공자 선택, 대체 순서, 캐시 정책, 검색 깊이가 코드가 아니라 설정이 된다.
한 플랫폼 팀이 모든 에이전트의 그라운딩을 한꺼번에 조정한다.
캐시의 온기가 워크로드마다 초기화되지 않고 쌓인다.

검색 요청 하나의 생명주기는 일곱 단계다.
질의를 정규화해 사소하게 다른 표현이 같은 캐시 항목에 닿게 하고,
정확 캐시를 확인해 맞으면 제공자를 부르지 않고 바로 돌려주고,
의미 캐시를 확인해 임베딩이 충분히 비슷하면 이전 결과를 재사용하고,
두 캐시가 모두 빗나갔을 때만 제공자 대체 사슬을 따라가며 시간 초과와 오류는
자동으로 다음 제공자로 넘기고,
응답을 제목과 URL과 요약문의 공통 스키마로 정규화하고,
두 캐시 계층에 제공자별로 나누어 쓰되 수명(TTL)은 답이 얼마나 빨리
낡는지에 맞추고,
출력 계약을 보존하도록 구조화된 도구 응답을 돌려준다.
모든 단계가 어느 갈래를 탔는지, 제공자, 지연, 비용 같은 원격 측정을 남긴다.
새 HTTP 제공자는 엔드포인트, 요청 템플릿, 응답 매핑,
비용 메타데이터를 담은 YAML 어댑터로 붙이며 애플리케이션 코드를 바꾸지 않는다.

평가는 다섯 모델(GPT-4o, GPT-4o-mini, Gemini 2.5 Flash, Gemini 2.5 Pro,
Claude Sonnet 4)과 공개 질의응답 벤치마크 셋,
그리고 전자상거래 QIU 운영 워크로드에서 했다.
공개 벤치마크에서 DSG 구성은 정확도 83%에서 86%로 내장 검색의 87.7%에 근접하며
비용은 대략 10배에서 30배 낮다.
BrightData를 쓴 DSG는 내장 검색과 1.6점 이내이고 비용은 약 11배 낮다.
Serper를 쓴 DSG는 검색 없음을 분명히 앞서는 가장 싼 구성이며 1,000건에 70센트
미만이다.
최신성에 민감한 FreshQA에서는 다섯 모델 모두에서 내장 검색이 DSG를 앞섰고,
글은 이를 백엔드가 라우팅 결정이어야 하며 내장 검색도 같은 인터페이스 뒤의
선택지여야 한다는 근거로 쓴다.

QIU는 일반 비식품 소매 질의 7,988건과 합성 롱테일 질의 2,335건으로 평가했다.
정확도는 최종 해석된 의도를 잰다.
추론 모델이 Gemini Flash일 때 결과는 다음과 같다.

| 평가 세트                  | 내장 검색 정확도와 1,000건당 비용 | DSG 정확도와 1,000건당 비용 |
| -------------------------- | --------------------------------- | --------------------------- |
| 소매, 일반 비식품(N=7,988) | 93.40%, 7.90달러                  | 93.90%, 0.110달러           |
| 롱테일, 합성(N=2,335)      | 87.62%, 10.37달러                 | 87.79%, 0.146달러           |

글은 보고된 비용이 검색 제공자의 요금만이고 모델 추론은 제외한다고 밝힌다.
내장 검색의 기준선은 구글 검색 그라운딩이 통합된 Gemini Flash이며,
가장 강한 내장 통합 가운데 하나라고 쓴다.

캐시는 냉각과 온기 두 번의 통과로 쟀다.

| 통과 | 캐시 적중률 | 1,000건당 검색 비용 | 평균 지연 |
| ---- | ----------- | ------------------- | --------- |
| 냉각 | 6.2%        | 0.7385달러          | 4,570ms   |
| 온기 | 99.4%       | 0.0045달러          | 1,465ms   |

글은 지연이 68% 줄고 검색 비용이 99% 넘게 줄었다고 쓴다.
검색 깊이도 변수로 쟀다.
SimpleQA에서 세 모델의 평균 정확도는 결과 2개에서 6개로 늘리면 78.7%에서 84.9%로
6.2점 오르고, 10개로 더 늘리면 0.6점만 더해 85.5%가 된다.

글의 비교표는 내장 검색이 더 나쁜 것이 아니라 다른 지점이라고 말한다.
내장 검색은 정확도가 강하고 특히 최신성에 민감한 질의에서 강하고 비용이 모델
호출에 묶여 있으며 지연이 제공자에게 맡겨져 불투명하다.
DSG는 공개 질의응답에서 거의 동률이고 운영에서는 같거나 낫고,
비용을 조절할 수 있고, 반복 질의 재사용(정확 캐시와 의미 캐시)을 쓰고,
제공자에 중립이고, 구조화된 도구 경계로 형식 어긋남이 훨씬 적다고 한다.

한계로 글은 세 가지를 든다.
안정성, 지연, 데이터 품질을 제3자 공급자에 의존하게 되며 가격이 바뀌면 측정한
균형이 달라지므로 남는 것은 가격이 아니라 인터페이스다.
다단계 추론은 한 번 찾는 질의보다 이득이 적다. HotpotQA에서 어느 쪽 검색이든
이득이 크지 않았고 깊은 추론에는 반복 검색 루프가 필요해 보인다.
검색이 유도한 장황함은 완화될 뿐 해결되지 않았고,
이를 체계적으로 잡으려면 게이트웨이에 계약 인식 검증기가 필요하다.
다음 계획은 질의마다 깊이와 제공자를 학습하는 적응형 라우팅,
계약 인식 출력 검증, 다단계 워크로드를 위한 반복 검색이다.

## 분석

### 글의 핵심은 검색을 모델의 기능이 아니라 정책으로 다루는 이음매다

글이 문제를 세는 방식은 비용이 아니라 이음매의 부재다.
모델과 검색 백엔드가 한 API 호출 안에 묶여 있으면 모델을 바꿀 때마다 검색이 같이
바뀌고, 검색 공급자의 가격이 바뀔 때마다 모델 연동을 건드려야 한다.
DSG는 이 둘 사이에 인터페이스를 두고 제공자 선택, 대체 순서, 캐시 정책,
검색 깊이를 설정으로 끌어올린다.
그래서 98%라는 비용 수치보다 글이 내세우는 것은 인터페이스다.
한계 항목에서 저자들이 남는 결과는 가격이 아니라 인터페이스라고 쓴 것도
같은 이유다.
공급자 가격은 바뀌는 값이고 이음매는 그대로 남는 구조라는 뜻이다.

### 모델 내장 검색은 출력 계약을 흔든다는 관찰이 일반화될 수 있다

가장 눈에 띄는 관찰은 검색을 켜면 모델의 행동이 바뀐다는 것이다.
설명 없이 답만 내라는 지시를 검색 없이는 따르던 모델이 검색을 켜면 근거를 말하며
시작한다.
Claude Sonnet 4의 HotpotQA 수치 78.1%는 이것이 드문 오류가 아니라 기본 동작에
가깝다는 것을 보여 준다.
글은 증거를 생성 흐름 안이 아니라 도구 응답으로 돌려주는 것이 완화책이라고
하는데, 이는 검색 말고도 생성 흐름에 텍스트를 끼워 넣는 모든 기능에 해당하는
설계 원칙이다.
모델의 출력은 파서가 기대하는 모양을 유지하고,
외부 정보는 별도의 구조화된 채널로 들어와야 한다는 것이다.
다만 글은 DSG에서 같은 현상의 수치를 제시하지 않고 보이지 않았다고만 쓴다.

### 비용 절감은 서로 다른 두 기전에서 나온다

글의 비용 수치는 두 종류다.
하나는 내장 검색을 범용 검색 제공자로 바꾸는 것이고 표 1의 98% 감소가 이에
해당하는 것으로 읽힌다.
다른 하나는 캐시이며 표 2의 온기 통과가 1,000건당 0.0045달러까지 내려가는 것이
이에 해당한다.
두 기전은 독립이어서 합치면 더 큰 감소가 가능하지만,
글은 표 1의 DSG 비용이 캐시 적중을 포함하는지 밝히지 않는다.
표 1의 소매 비용(1,000건당 0.110달러)이 표 2의 냉각 통과(0.7385달러)보다 낮은
것도 같은 질문을 남긴다.
두 표의 워크로드와 제공자 구성이 같은지 글이 설명하지 않아서 이 문서는 이 차이를
풀지 못했다.

## 비평

### 98%는 검색 요금만의 감소이고 전체 비용의 감소가 아니다

표 1의 비용은 글이 직접 밝히듯 검색 제공자의 요금이며 모델 추론은 제외한다.
DSG는 모델이 도구를 호출하고 증거를 도구 응답으로 다시 읽는 구조라서 모델 입력
토큰과 왕복이 달라질 수 있는데, 그 차이는 이 비교에 들어 있지 않다.
게이트웨이를 운영하는 비용, 의미 캐시가 쓰는 임베딩 비용,
텔레메트리 저장 비용도 글에 없다.
따라서 98%는 검색 요금 항목의 감소이고,
질의 하나를 처리하는 전체 비용이 얼마나 줄었는지는 글에서 알 수 없다.
검색 요금이 전체 비용의 대부분이면 의미가 크고, 아니라면 줄어든 비중이 작다.

### 정확도가 같다는 주장은 운영 세트의 작은 차이에 기댄다

제목의 정확도를 잃지 않았다는 말은 QIU 운영 평가에 근거한다.
소매 세트에서 DSG는 93.90%, 내장 검색은 93.40%로 0.5점 차이다.
이 문서의 계산으로는 N이 7,988건이므로 약 40건에 해당한다.
롱테일 세트의 0.17점 차이는 N이 2,335건에서 약 4건이다.
글은 같거나 조금 높다고 쓰며 신뢰 구간이나 유의성 검정을 싣지 않았다.
이 정도 차이는 같다는 결론에는 충분하지만 더 높다는 결론은 뒷받침하지 못한다.

공개 벤치마크에서는 사정이 다르다.
DSG 구성의 83%에서 86%는 내장 검색의 87.7%보다 낮다.
이 문서의 계산으로는 가장 높은 구성이 글이 말한 1.6점 이내이고 가장 낮은 구성은
약 4.7점 아래다.
FreshQA에서는 다섯 모델 모두에서 내장 검색이 앞섰다.
그러므로 정확도를 잃지 않았다는 말은 한 운영 워크로드에 대한 것이고,
일반적으로는 적은 비용으로 비슷한 정확도라는 말이 더 정확하다.
글도 결론에서 그라운딩을 항상 분리해야 한다는 뜻은 아니라고 선을 긋는다.

### 운영 평가의 질의가 최신성을 시험하지 않는다

글은 최신성에 민감한 질의에서 내장 검색이 낫다고 인정한다.
그런데 마켓플레이스의 질의는 새로 문 연 가게나 새 상품처럼 최신성이 중요한
경우가 많을 수 있다.
운영 평가의 두 세트는 일반 비식품 소매 질의와 합성 롱테일 질의이며,
롱테일이 실제 질의가 아니라 합성이라는 점도 글에 적혀 있다.
이 평가가 최신성을 어느 정도 포함하는지는 글에서 알 수 없다.
의미 캐시의 수명을 답이 낡는 속도에 맞춘다고 하지만,
그 속도를 어떻게 분류하는지, 낡은 결과가 나가는 비율이 얼마인지는 측정이 없다.

### 99.4%라는 적중률은 같은 질의를 다시 돌린 결과로 읽힌다

표 2의 냉각 통과는 적중률 6.2%이고 온기 통과는 99.4%다.
온기 통과는 냉각 통과가 채운 캐시로 같은 질의를 다시 돌린 것으로 읽힌다.
이 구성에서 99.4%는 반복이 많은 워크로드의 상한에 가깝고,
실제 운영에서 질의가 얼마나 반복되는지에 달려 있다.
비교표는 이 수치를 반복 질의 재사용의 항목으로 내세우는데,
일반 운영의 적중률로 읽으면 과장이다.
의미 캐시가 비슷한 임베딩의 이전 결과를 재사용하는 것은 450 north와 비슷한 다른
질의에 잘못된 결과를 돌려줄 위험이 있는데, 잘못된 적중의 비율도 글에 없다.

### 지연의 비교가 없다

비교표는 지연을 내장 검색은 제공자가 관리해 불투명하고 DSG는 작업과 제공자에
따라 다르고 캐시로 최적화할 수 있다고 쓴다.
두 방식의 지연 수치를 나란히 두지 않는다.
DSG의 냉각 통과 평균 지연이 4,570ms이고 온기가 1,465ms인 것이 글의 유일한
지연 수치다.
내장 검색의 지연이 얼마인지 알 수 없어서,
검색을 분리하는 것이 지연을 늘리는지는 이 글로 가릴 수 없다.

### 시험한 모델이 이미 한 세대 앞선 것들이다

글은 다섯 모델을 프런티어 모델이라고 부르는데,
이 문서를 쓰는 2026년 11월 7일 기준으로 GPT-4o, Gemini 2.5,
Claude Sonnet 4는 [Claude Opus 5.5](./claude-opus-5-5.md) 같은 더 새 모델이 나온
뒤의 이전 세대다.
검색이 유도한 장황함이 새 모델에서도 같은 크기로 일어나는지는 이 글로 알
수 없다.
글의 핵심 구조(분리된 이음매)는 모델 세대와 무관하게 성립하지만,
78.1% 같은 수치는 시험한 모델의 값이다.

## 인사이트

### 오래가는 것은 가격이 아니라 인터페이스라는 저자들의 판단이 이 글의 가장 이전 가능한 부분이다

저자들은 한계 항목에서 공급자 가격이 바뀌면 측정한 균형이 달라지므로 오래 남는
결과는 인터페이스라고 쓴다.
검색 공급자가 여럿이고 가격이 자주 바뀌는 시장에서는 특정 공급자를 고르는 것보다
공급자를 바꿀 수 있는 구조가 더 가치가 크다는 뜻이다.
이 판단은 검색 말고도 모델 공급자, 임베딩,
벡터 저장소처럼 시장이 빨리 바뀌는 모든 외부 의존에 적용된다.
같은 회사의 [에이전트-도구 접근 게이트웨이](../mcp/doordash-agent-gateway.md)도
도구 호출 주변의 공통 층을 플랫폼으로 만든 사례이고,
두 글에는 Siddarth Kodwani가 저자로 들어 있다.
이 글의 게이트웨이가 그 글의 게이트웨이와 같은 것인지는 글에 적혀 있지 않다.

### 생성 흐름 바깥으로 증거를 빼는 것이 계약을 지키는 방법이다

글의 가장 구체적인 발견은 검색이 모델의 행동을 바꾼다는 것이다.
지시를 따르던 모델이 검색을 켜면 따르지 않는다는 것은,
기능을 켜는 일이 모델의 다른 속성에 영향을 준다는 뜻이다.
이를 막는 구조는 모델이 낸 출력과 외부 정보가 섞이지 않게 별도 채널로
받는 것이다.
이 방식은 모델을 입력에서 출력으로 가는 함수로 보고 외부 정보를 인자로 주는
것과 닮았다.
다만 글이 인정하듯 이것은 완화이고 해결이 아니다.
도구 응답을 읽은 모델의 최종 답이 여전히 장황할 수 있어서 게이트웨이의 계약 인식
검증기가 다음 과제로 남는다.

### 검색 깊이는 숨은 기본값에서 조절 값으로 바뀌고, 최적점이 보인다

내장 검색은 몇 개의 결과를 읽는지가 제공자의 기본값에 숨어 있다.
DSG는 이를 설정으로 끌어내서 SimpleQA에서 깊이 2에서 6까지 6.2점이 오르고 6에서
10까지는 0.6점만 오른다는 것을 보였다.
이 곡선은 깊이를 늘리는 이득이 6 근처에서 꺾인다는 것을 보여 준다.
깊이가 비용과 지연에 어떻게 비례하는지는 글에 없어서 6이 최적점이라고 말할
수는 없다.
그래도 깊이를 질의마다 학습하는 적응형 라우팅이 다음 계획에 들어 있는 것은 이
곡선의 결과로 읽힌다.

### 결론을 바꿀 관찰

전체 비용(모델 추론, 게이트웨이 운영, 임베딩을 포함한 질의당 비용)이 공개되면
98%가 얼마나 큰 절감인지 가려진다.
같은 비교를 최신 세대 모델로 했을 때 정확도와 장황함의 수치가 어떻게 나오는지
알려지면 일반성이 시험된다.
실제 질의 흐름에서 의미 캐시의 적중률과 잘못된 적중의 비율이 공개되면 99.4%의
의미가 정해진다.
최신성이 중요한 운영 질의에서 DSG와 내장 검색을 비교하는 결과가 나오면 라우팅
결정이 어떤 질의에서 갈리는지 드러난다.
