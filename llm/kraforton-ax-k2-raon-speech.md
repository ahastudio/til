# 크래프톤, 21B 한영 이중언어 음성 AI 모델 'A.X K2 Raon-Speech' 공개

<https://huggingface.co/KRAFTON/A.X-K2-Raon-Speech-21B-A3B/blob/main/README_ko.md>

GN 토론: <https://news.hada.io/topic?id=32125>

## 소개

A.X K2 Raon-Speech는 크래프톤이 공개한 한국어/영어 이중언어 음성 언어 모델이다.
전체 파라미터는 21.2B이며 실제 추론 시 활성화되는 파라미터는 3.5B 수준의
MoE(Mixture of Experts) 구조를 취한다.
SK텔레콤이 공개한 A.X K2 Light 백본을 기반으로,
크래프톤이 독자적으로 학습시킨 AuT 음성 인코더와 Mimi 신경망 코덱을 결합해
음성 이해와 생성을 하나의 모델 안에서 처리하도록 설계했다.

아키텍처는 128개의 라우팅 전문가(routed experts)를 가진 48층 텍스트 백본,
317M 파라미터 규모의 음성 인코더, 24kHz에서 동작하는 96M 파라미터 코덱으로
구성된다.
최대 131,072 토큰의 컨텍스트 윈도우를 지원하며,
2,048개 항목의 코드북을 가진 32개의 quantizer를 사용해 음성을 이산 토큰으로
표현한다.

## 주요 기능

- **통합 멀티모달 처리**: STT(음성 인식), TTS(음성 합성), SpeechQA, SpokenQA,
  턴 기반 대화를 하나의 모델에서 처리한다.
- **감정 인지**: 감정과 억양 같은 준언어적(paralinguistic) 요소를 포착해
  자연스러운 응답을 생성한다.
- **음성 조건화(voice conditioning)**: ECAPA 임베딩을 활용해
  화자 참조 음성을 선택적으로 입력받아 TTS 출력을 조건화할 수 있다.
- **연속 TTS(continuation TTS)**: 참조 음성의 운율(prosody)을 자연스럽게
  이어받아 확장하는 오디오를 생성한다.

## 성능

30B 파라미터 이하의 공개 음성 모델 중
LibriSpeech, KsponSpeech를 포함한 46개 벤치마크에서
한국어 1위(점수 0.72), 영어 3위(점수 0.75)를 기록했다.
다만 BF16 가중치 기준 약 42.4GB에 달해 80GB 이상의 GPU 메모리가 필요하며,
transformers 4.57.1 이상과 vLLM-Omni의 특정 브랜치 구성을 요구한다.
라이선스는 CC BY-NC 4.0으로, 연구 및 비상업적 프로토타입 용도로만 사용이
허용되고 상업적 활용은 제한된다.

## 분석

### 게임 회사가 음성 AI를 만드는 이유

크래프톤은 배틀그라운드로 알려진 게임 회사지만,
이번 발표는 게임 산업 바깥에서도 화제를 모았다.
게임 회사가 텍스트 백본을 직접 학습하는 대신 SK텔레콤의 A.X K2 Light를
가져와 음성 인코더와 코덱만 독자 개발한 구조는,
크래프톤이 전체 언어 모델 파이프라인이 아니라
자사가 강점을 가질 수 있는 음성 인터랙션 계층에 집중했다는 신호로 읽힌다.
GeekNews 댓글에서도 게임 회사의 음성 AI 개발 자체를 의외로 받아들이는
반응이 있었는데[^wocks3254],
이는 크래프톤이 인터랙티브 NPC, 실시간 음성 대화형 게임 캐릭터 등
게임 내 활용을 염두에 두고 이 기술을 축적하고 있을 가능성을 시사한다.

### 백본 재사용이라는 전략적 선택

A.X K2 Light를 백본으로 채택한 결정은 단순한 기술적 편의가 아니라
국내 파운데이션 모델 생태계가 형성되고 있음을 보여주는 사례다.
SK텔레콤이 백본을 공개하고 크래프톤이 그 위에 음성 모듈을 얹는 구조는,
미국 빅테크의 폐쇄형 파운데이션 모델 전략과 달리
국내 기업들이 각자의 강점(통신사의 대규모 언어 모델 학습 인프라,
게임 회사의 실시간 인터랙션 노하우)을 조합하는 분업 구조를 시도하고
있다는 뜻이다.
이 접근은 처음부터 21B 전체를 학습하는 것보다 자원 효율적이지만,
동시에 백본의 한계(예: 텍스트 중심 사전학습에서 비롯된 편향)를
그대로 물려받는다는 제약도 안고 있다.

### 벤치마크 순위의 이면

한국어 1위, 영어 3위라는 결과는 “30B 이하 공개 모델”이라는 조건이 붙어
있다는 점을 주의 깊게 봐야 한다.
상용 비공개 모델이나 더 큰 파라미터 규모의 모델과 비교한 순위가 아니며,
46개 벤치마크의 구성이 공개되지 않은 상태에서 종합 점수(0.72, 0.75)만으로
실제 사용성을 판단하기는 어렵다.
그럼에도 GeekNews 댓글들은 공개된 샘플 음성의 자연스러움에 놀라움을
표했는데[^ligion][^skageektp],
이는 벤치마크 수치보다 실제 청취 경험이 대중적 반응을 더 크게
좌우한다는 점을 보여준다.

## 비평

### 42.4GB라는 장벽은 “공개”의 의미를 축소시킨다

모델 가중치를 공개했다는 사실만으로 접근성이 보장되지는 않는다.
80GB 이상의 GPU 메모리를 요구하는 모델은 사실상 기업이나 대학 연구실
수준의 컴퓨팅 자원을 가진 주체만 실행할 수 있다.
개인 개발자나 소규모 스타트업이 이 모델을 직접 구동해 실험하기는
현실적으로 어려우며,
결국 “공개 모델”이라는 표현이 실제로 의미하는 접근성의 폭은
매우 좁다.
경량화 버전이나 양자화된 체크포인트가 함께 제공되지 않았다는 점은
이 모델이 커뮤니티 생태계 확산보다는 기술력 과시와 연구 공유에 방점을
찍고 있다는 인상을 준다.

### CC BY-NC 4.0은 크래프톤의 독점 활용 의도를 감춘다

비상업적 라이선스로 공개했다는 점은 얼핏 개방적으로 보이지만,
실제로는 크래프톤이 상업적 활용 권리를 독점하겠다는 선언에 가깝다.
연구자들은 자유롭게 실험하고 논문을 쓸 수 있지만,
정작 이 모델을 게임이나 서비스에 통합해 수익을 창출하는 길은
크래프톤 자신에게만 열려 있다.
이는 오픈소스 생태계에 기여하는 것이 아니라
외부 연구 커뮤니티의 검증과 피드백을 무상으로 흡수하면서
상업적 우위는 그대로 유지하는 전략에 가깝다.
“공개”라는 프레이밍이 실제 라이선스 조건의 배타성을 가리는 효과를
내고 있다.

### 벤치마크 순위 서술은 비교 대상의 비대칭을 감춘다

“30B 이하 공개 모델 중 한국어 1위”라는 표현은 매우 구체적인 조건절 안에서만
성립하는 순위다.
만약 상용 API 기반 모델이나 더 큰 모델까지 포함했을 때도 이 순위가
유지되는지는 모델 카드만으로 알 수 없다.
조건을 좁혀 1위를 만드는 방식은 벤치마크 마케팅에서 흔히 쓰이는 수법이며,
모델 카드가 이 조건을 명시했다는 점에서 완전히 기만적이라 할 수는 없지만,
독자가 조건절을 걷어내고 “한국어 음성 AI 1위”로 받아들이기 쉽다는 점에서
서술의 책임은 여전히 남는다.

## 인사이트

### 음성 AI는 게임 산업의 다음 UX 전장이 될 수 있다

크래프톤이 음성 인코더와 코덱을 자체 개발했다는 사실은
단순한 기술 시연을 넘어 실제 제품 로드맵을 암시한다.
실시간 음성 대화가 가능한 NPC, 감정을 인지하고 반응하는 게임 캐릭터는
텍스트 기반 챗봇형 NPC보다 몰입도가 훨씬 높다.
만약 이런 기술이 실제 게임에 통합된다면,
게임 산업의 경쟁 축이 그래픽이나 물리 엔진에서
캐릭터와의 음성 인터랙션 품질로 옮겨갈 가능성이 있다.
이는 게임 회사들이 왜 점점 더 많은 자원을 언어/음성 모델 연구에
투입하는지를 설명하는 더 큰 흐름의 일부로 볼 수 있다.

### 백본 공유 생태계는 국내 AI 산업의 새로운 분업 모델을 예고한다

SK텔레콤의 백본을 크래프톤이 재사용하는 구조는
과거 반도체 산업에서 파운드리와 팹리스가 분업했던 방식과 유사한 패턴을
AI 모델 생태계에서 재현하고 있다.
대규모 사전학습이라는 자본 집약적 작업은 통신사나 대기업이 맡고,
도메인 특화 모듈(음성, 이미지, 특정 산업 지식)은 각 분야 전문 기업이
얹는 구조가 자리 잡는다면,
한국의 AI 산업은 미국처럼 소수 빅테크가 전체 스택을 독점하는 구조 대신
여러 기업이 계층별로 특화하는 구조로 발전할 수 있다.
다만 이 구조가 지속되려면 백본 제공자와 모듈 개발자 사이의 라이선스,
수익 배분 관계가 명확히 정립되어야 하는데,
현재 공개된 정보만으로는 이 관계가 어떻게 설계되어 있는지 알 수 없다.

### 비상업 라이선스는 오픈 생태계와 폐쇄 전략 사이의 회색지대를 만든다

CC BY-NC 4.0 같은 라이선스는 완전한 오픈소스도, 완전한 폐쇄 모델도 아닌
중간 지대를 만들어낸다.
이 방식은 기업이 연구 커뮤니티의 검증과 홍보 효과는 누리면서
상업적 리스크(경쟁사의 무단 활용, 수익 잠식)는 회피할 수 있게 해준다.
문제는 이런 라이선스가 늘어날수록,
“오픈 모델”이라는 표현 자체가 실제로는 매우 다양한 접근 권한 스펙트럼을
가리는 모호한 용어가 된다는 점이다.
사용자와 개발자 커뮤니티는 앞으로 모델을 평가할 때
단순히 “공개냐 아니냐”가 아니라
“어떤 조건에서 누구에게 열려 있는가”를 훨씬 세밀하게 따져야 하는
상황에 놓이게 될 것이다.
