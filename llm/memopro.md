# memopro: 메모리보다 큰 모델을 결과 변화 없이 정해진 메모리 안에서 실행하는 라이브러리

<https://github.com/imhyensuk/memopro>

Show GN: [memopro - 메모리보다 큰 LLM, 데이터 등의 작업을 결과 변화 없이 정해진 메모리 안에서 실행하는 Python/Rust 라이브러리](https://news.hada.io/topic?id=35584)

## 소개

memopro는 메모리보다 큰 언어 모델, 비전 모델,
데이터 작업을 정해진 메모리 상한 안에서
결과가 달라지지 않게 실행하는 Python·Rust 라이브러리다. 8GB에서 16GB 정도의
노트북이나 작은 GPU에서는 모델이나 데이터가 메모리보다 크면
작업이 메모리 부족(OOM)으로 멈춘다.
README는 기존 해결책에 각각 대가가 있다고
정리한다. 4비트 같은 양자화는 메모리를 줄이지만 출력과 정확도가 바뀌고,
운영체제 스왑은 결과는 같지만 사용량을 제한할 수 없고
디스크에 많이 쓰며 심하면 시스템 전체가 멈춘다.
모델별 오프로딩 도구는 특정 모델이나 작업에만 쓸 수 있다.

memopro가 택한 방법은 메모리 대신 시간을 쓰는 것이다.
지금 쓰지 않는 데이터를 메모리에서 비우고 필요할 때 되돌리는데,
되돌리는 방법은 무손실만 쓴다.
모델 가중치는 원본 파일에서 다시 읽고 해시로 검증하며,
그 밖의 데이터는 무손실 압축한다.
저장소는 2026년 9월 25일에 만들어졌고 알파 단계다.
라이선스는 MIT 또는 Apache-2.0 중 선택할 수 있다.

## 보장하는 것

README가 내세우는 보장은 세 가지다.
첫째는 결과 불변이다.
생성과 추론의 출력은 메모리를 충분히 쓴 일반 실행과 비트 단위로 같고,
학습 손실은 예산과 관계없이 같다고 한다.
단 일반 PyTorch 학습과는 계산 순서의 차이로 마지막 자리가 다를 수 있다고 적는다.
변경 기록(0.1.7)을 보면 이 학습 손실 문구는 수정을 거쳐 바로잡은 것이다.
둘째는 메모리 상한이다.
지킬 수 없는 예산은 시작 전에 거부하고,
코드를 고치지 않은 프로그램이 압축 후에도 상한을 넘으면 실행 중에 경고한다.
셋째는 디스크 쓰기가 없다는 것이다.
스왑 파일이나 캐시 파일을 만들지 않으므로 SSD 수명을 줄이지 않는다.

## 사용하기

설치는 `pip install memopro`가 기본이고,
LLM 기능은 `pip install "memopro[llm]"`로
PyTorch, Transformers, PEFT를 함께 받는다.
Python 3.11 이상과 PyTorch 2.4 이상이 필요하다. macOS(Apple silicon)와
NVIDIA GPU가 있는 Linux에서 전체 기능을 쓸 수 있고,
Linux CPU는 GPU 기능을 뺀 전체,
Windows는 `memopro run`의 페이징을 뺀 기본 기능만 지원한다.

핵심 호출은 네 가지다.

| 호출                                      | 하는 일                                                       |
| ----------------------------------------- | ------------------------------------------------------------- |
| `memopro.finetune(model, texts, budget=)` | 메모리보다 큰 LLM의 16비트 LoRA 학습, 결과는 표준 PEFT 어댑터 |
| `memopro.generate(model, prompt, draft=)` | 작은 초안 모델로 속도를 높여도 출력은 큰 모델 단독과 같음     |
| `memopro run --budget 1GB script.py`      | 기존 NumPy·PyTorch 스크립트를 수정 없이 상한 안에서 실행      |
| `memopro check MODEL`                     | 실행 전에 모델이 예산에 들어가는지 진단                       |

예산은 `"auto"`(측정한 여유 메모리에서 10%를 뺀 값, 기본값),
`"6GB"`, `"50%"` 같은 형식으로 준다.
프로세스 전체에 상한을 거는 `memopro.enable(budget=...)`과
버퍼를 직접 맡기는 `memopro.rt.Runtime`도 있다.

## 측정 결과와 한계

저자가 보고한 측정은 이렇다.
환경은 Apple M1 8GB와 NVIDIA T4 16GB다.

| 작업                          | 환경          | 결과                                              |
| ----------------------------- | ------------- | ------------------------------------------------- |
| Qwen2.5-7B LoRA 학습          | Apple M1, 8GB | 예산 2.5GiB, `batch=4`에서 15.5토큰/초            |
| Mistral-7B LoRA 학습          | NVIDIA T4     | 예산 4GiB, 약 43토큰/초                           |
| Qwen2.5-7B 생성(`draft` 사용) | Apple M1, 8GB | 8.95초/토큰에서 2.37초/토큰으로, 출력 동일        |
| Qwen2.5-3B LoRA 학습          | Apple M1, 8GB | 20토큰/초, mlx-tune은 메모리 부족으로 실행 불가   |
| 1.5B~3.8B 모델                | NVIDIA T4     | 일반 실행 대비 학습 1.00~1.03배, 생성 1.06~1.35배 |
| NumPy·scikit-learn 스크립트   | Linux         | 필요 메모리의 50~75% 상한에서 1.1~3.4배 시간      |

README는 한계도 적어 두었다.
메모리를 크게 넘는 모델은 저장 장치 읽기 속도에 묶여 매우 느리다.
T4에서 14B 16비트 LoRA는 약 1토큰/초다.
정렬이나 조인처럼 무작위 접근이 많은 데이터 작업은 크게 느려질 수 있다.
Apple GPU에서는 `finetune`이나 `stream_model`을
다른 MPS 연산보다 먼저 불러야 한다.
알파 버전이라 API가 바뀔 수 있다.
README는 모델이 메모리에 들어가면 Unsloth나 mlx-tune이 훨씬 빠르고,
정확도 손실이 괜찮다면 QLoRA나 llama.cpp가 낫다고 직접 말한다.

## 분석

### 재현 가능성을 제약으로, 속도를 변수로 둔 설계다

memopro의 설계 원칙은 기여 지침에 한 줄로 적혀 있다.
무손실 원칙을 지키고, 결과를 바꾸는 방식은 기본값이 될 수 없다.
이 제약이 나머지를 정한다.
양자화는 빠르지만 결과를 바꾸므로 기본 선택지에서 빠지고,
남는 변수는 시간뿐이다.

이 선택은 사용 대상을 좁힌다.
README가 꼽는 대상은 양자화 없는 기준선 실험이나
재현성이 필요한 비교 실험, 교육과 개인 학습이다.
속도가 중요한 서비스 추론은 대상이 아니다.
저자는 memopro를 아예 돌릴 수 없던 크기를 다루거나
양자화 없는 기준선이 필요할 때 쓰는 도구라고 소개한다.

### 가중치는 다시 읽고 나머지는 압축하는 비대칭

메모리에서 비우는 데이터의 종류에 따라 방법이 갈린다.
모델 가중치는 읽기 전용이라 원본 파일이 곧 사본이다.
메모리에서 버리고 필요할 때 파일에서 다시 읽으면 되고,
해시로 검증하면 손상도 잡는다.
활성값이나 옵티마이저 상태처럼 계속 바뀌는 데이터는 원본이 없으므로
무손실 압축으로 줄인다.

디스크 쓰기가 없다는 보장은 이 비대칭 덕분에 가능하다.
읽기 전용 데이터는 버려도 쓰기가 필요 없고,
바뀌는 데이터는 디스크 대신 메모리 안에서 압축한다.
바뀐 페이지를 디스크에 쓰는 운영체제 스왑과 다른 점이다.

### 작은 초안 모델로 읽기 횟수를 나눈다

메모리를 넘는 모델의 생성에서 병목은 연산이 아니라 가중치를 읽는 횟수다.
토큰 하나를 만들 때마다 모든 가중치를 한 번 거쳐야 하기 때문이다.
`draft` 옵션은 작은 모델이 여러 토큰을 미리 제안하고
큰 모델이 이를 한 번에 검증하게 해서
한 번의 가중치 읽기를 여러 토큰이 나눠 쓰게 한다.
출력은 큰 모델 단독과 같고 측정에서는 토큰당 시간이 8.95초에서 2.37초로 줄었다.

## 비평

### 속도가 실용 범위를 정한다

가장 두드러진 수치는 생성 속도다.
초안 모델을 써도 Qwen2.5-7B 생성은 토큰당 2.37초이고,
이는 초당 0.4토큰을 조금 넘는 수준이다.
대화나 에이전트처럼 응답을 기다리는 용도에는 쓸 수 없다.
같은 환경에서 학습은 초당 15.5토큰이다.
토큰 100만 개를 한 번 훑는 데 약 18시간이 걸린다는 계산이다.

따라서 이 도구의 가치는 불가능했던 일을 가능하게 하는 데 있지
실용적인 속도를 내는 데 있지 않다.
README도 같은 입장이지만,
소개 글의 8GB 맥북에서 7B 모델을 돌린다는 서술만 읽은 독자는
이 속도를 가늠하기 어렵다.

### 비트 단위 동일이라는 주장은 조건이 붙는다

README는 결과 불변 주장의 범위를 정직하게 한정한다.
학습 손실은 예산에 관계없이 같지만
일반 PyTorch 학습과는 마지막 자리가 다르다고 적는다.
변경 기록을 보면 이 문구는 처음에 더 강했다가 고쳐졌다.

여기서 주장이 어디까지인지 가늠할 수 있다.
생성과 추론의 출력이 일반 실행과 같다는 점은 저자의 시험에서 확인됐다.
다른 하드웨어, 스레드 수, 라이브러리 버전에서도 같은지는 알 수 없다.
사용자가 직접 확인하려면 예산을 바꿔 가며 같은 입력의 출력 해시를 비교하면 된다.
연구용 기준선이라는 용도는 결과 불변에 근거하므로
도입 전에 이 확인을 해 볼 가치가 있다.

### 측정은 저자 환경의 보고이고 저장소는 어리다

측정은 저자가 Apple M1 8GB와 NVIDIA T4에서 직접 돌린 것이다.
원시 결과는 저장소의 `docs/research/data/`에 있다고 하지만
독립적인 재현은 확인되지 않았다.
저장소는 만들어진 지 약 3주이고 알파 단계이며,
GitHub의 별은 이 글을 쓸 때 한 개였다.

API가 바뀔 수 있다는 점도 README가 인정한다.
따라서 현재 용도는 실험과 학습에 한정하는 것이 맞고,
파이프라인에 넣는다면 버전을 고정하고 출력 해시로 회귀를 감시해야 한다.

## 인사이트

### 성능은 연산이 아니라 한 번의 전체 읽기 비용이 정한다

측정 결과를 설명하는 단순한 모델이 있다. 7B 모델의 16비트 가중치는
약 14GB다. 70억 개의 파라미터에 파라미터당 2바이트를 곱한 값이다.
토큰 하나를 만들려면 이 가중치를 한 번 읽어야 하므로
저장 장치가 초당 몇 GB를 읽느냐가 곧 속도의 상한이다.

초안 없이 토큰당 8.95초가 걸린 것은 이 읽기 비용과 규모가 맞고,
초안으로 2.37초가 된 것은 한 번의 읽기로 평균 약 3.8토큰을 확정했다는 뜻이다.
이 추정은 이 글의 계산이며 저장 장치 속도는 알 수 없다.
이 모델로 자기 환경을 가늠해 볼 수 있다.
가중치 크기를 저장 장치의 연속 읽기 속도로 나누면
토큰당 시간의 하한이 나오고,
이 값이 허용 범위를 넘으면 도구로 해결할 수 없다.

### 페이지 교체의 재발견이다

메모리가 모자라면 덜 쓰는 것을 내보내고
필요할 때 되돌린다는 발상은 가상 메모리의 오래된 원리다.
memopro의 구조는 그 구성 요소와 일대일로 대응한다.
파일에 원본이 있는 읽기 전용 데이터는 쓰기 없이 버릴 수 있는 페이지이고,
바뀌는 데이터는 내보내려면 쓰기가 필요한 페이지다.
후자를 디스크 대신 메모리 안에서 압축하는 것은
압축 메모리 방식과 같은 선택이다.

memopro에서는 교체 정책이 모델의 구조를 안다는 점이 다르다.
운영체제는 어떤 페이지를 다음에 쓸지 모르지만
신경망은 층의 순서대로 가중치를 쓴다는 것이 알려져 있다.
이 지식을 이용해 미리 읽어 오면 범용 스왑에는 없는 이점이 생긴다.
저장소가 선읽기 실험을 따로 보관해 둔 것에서도 이 이점을 짐작할 수 있다.

### 시간으로 메모리를 사는 환율을 클라우드와 비교해야 한다

memopro는 메모리를 시간으로 바꾸는 도구이므로
그 환율이 다른 선택지보다 나은지를 따져야 한다.
토큰 100만 개의 학습에 18시간이 걸린다면
같은 일을 시간당 요금을 내는 클라우드 GPU에서 하는 것과 비교할 수 있다.
T4에서 Mistral-7B가 초당 43토큰이라면 같은 100만 토큰이 약 6.5시간이다.

어느 쪽이 나은지는 사용자의 상황에 달려 있다.
이미 가진 노트북이 있고 시간이 비용이 아니라면 memopro가 낫고,
시간이 비용이거나 반복 실험이 많다면 대여가 낫다.
도입 전에 한 번의 학습에 걸리는 시간을 재고
같은 작업의 대여 비용과 견주는 것으로 충분하다.
무료이고 재현 가능하다는 이점이 진짜로 필요한 사람은
양자화가 결과를 바꾸는 것을 용납할 수 없는 연구자다.
