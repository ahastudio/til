## 소개

Sebastian Raschka가 2026-10-24에 Ahead of AI에 올린 글이다.
자신의 책 『Build a Reasoning Model (From Scratch)』에 딸린 강의 영상 8편, 약 11시간을 한곳에 모아 소개한다.
사전학습된 작은 Qwen3 모델(0.6B)에서 출발해 평가, 추론 시점 확장, 강화학습, 증류를 Python과 PyTorch로 직접 구현하는 구성이다.
저자는 지난해의 「Coding LLMs from the Ground Up」 강좌의 후속편이라고 부르면서, 앞 강좌를 보지 않아도 된다고 적는다.

글은 영상 목록 앞에 짧은 개념 정리를 하나 둔다.
추론 모델은 일반 LLM에 검증 가능한 보상을 쓰는 강화학습 후처리(필요하면 추론 시점 확장 기법)를 더해 어려운 문제를 풀게 만든 것이고, 에이전트 하네스 안에서 엔진 역할을 한다는 설명이다.
하네스는 맥락 관리와 도구 접근을 맡는 소프트웨어 틀이다.
저자는 요즘 LLM 대부분이 추론 모델이거나 추론 모드를 제공한다고 덧붙인다.

이 노트는 소개 글을 비평하지 않고, 강좌를 어떤 순서와 기대치로 따라가면 되는지를 정리한다.
영상 자체는 보지 않았고, 글에 적힌 영상별 주제와 HN 토론을 근거로 쓴다.

## 동작 방식

### 강좌는 한 가지 장치를 두 번 쓴다

8편의 흐름에서 가장 눈에 띄는 설계는 3편의 검증기다.
검증기는 모델 답에서 최종 답을 뽑고, 정규화하고, 수학적으로 같은지 확인한다.
저자는 이 검증기를 먼저 MATH-500 평가에 쓰고, 뒤에서 강화학습의 보상 신호로 다시 쓴다고 설명한다.
평가 도구가 곧 학습 신호가 된다는 점이 이 강좌의 줄기다.

| 편  | 주제                                        | 가중치    | 핵심 장치                             |
| --- | ------------------------------------------- | --------- | ------------------------------------- |
| 1   | LLM, 추론 모델, 에이전트의 관계와 환경 설정 | 해당 없음 | uv, CUDA 또는 Apple Silicon 확인      |
| 2   | Qwen3 0.6B 불러오기, 생성, KV 캐시          | 고정      | 스트리밍 생성기, torch.compile        |
| 3   | 검증기와 MATH-500 평가                      | 고정      | 답 추출, 정규화, 동치 검사            |
| 4   | 추론 시점 확장: 샘플링과 자기 일관성        | 고정      | temperature, top-p, 다수결            |
| 5   | 추론 시점 확장: 점수 매기기와 자기 개선     | 고정      | 로그 확률, 비판과 수정 루프           |
| 6   | 강화학습: RLVR용 GRPO 구현                  | 갱신      | 그룹 응답, 상대 보상                  |
| 7   | 강화학습: 추적, 클리핑, KL 항               | 갱신      | 엔트로피, 정책 비율 클리핑, 형식 보상 |
| 8   | 추론 모델 증류                              | 갱신      | 교사 답변(DeepSeek R1), 지도 학습     |

가중치 열은 글의 설명에서 읽은 것이다.
4편과 5편은 모델 가중치를 건드리지 않고 답을 낫게 만드는 방법이고, 6편부터 가중치를 바꾼다.

### 가중치를 고정한 채 답을 낫게 하는 방법

4편은 같은 프롬프트에서 다양한 답을 뽑는 방법(temperature scaling, 다항 샘플링, top-p 필터링)을 먼저 구현한다.
그 위에 여러 답의 최종 답을 다수결로 묶는 자기 일관성을 올리고, 정확도와 추가 연산량의 맞교환을 잰다.
5편은 같은 프롬프트의 후보 답에 점수를 매기는 함수를 만든다.
토큰과 시퀀스의 로그 확률, 그리고 모델이 답을 비판하고 고쳐 쓰는 자기 개선 루프가 여기 들어가고, 로그 확률은 뒤의 강화학습에서 다시 쓰인다고 글은 적는다.

### 가중치를 바꾸는 두 갈래

6편은 그룹 상대 정책 최적화(GRPO)를 단순화해 구현한다.
응답을 그룹으로 만들고, 검증기로 점수를 매기고, 그룹 안의 상대 보상으로 가중치를 갱신한다.
글은 이를 사람 피드백 기반 강화학습(RLHF)과 비교하는 논의가 같은 편에 들어 있다고 소개한다.

7편은 같은 학습 루프를 열어 지표를 늘린다.
엔트로피와 이점 통계, 정책 비율 클리핑, KL 손실 항, 형식 보상을 하나씩 더하고, 이것들이 실제로 도움이 되는지 로그로 확인한다.
KL 항을 다루는 대목에는 보상 해킹 논의와 단순화한 KL 식의 한계가 함께 있다고 글은 적는다.

8편은 다른 길을 연다.
더 크고 강한 교사 모델의 답으로 작은 모델을 지도 학습하는 증류다.
글은 소프트 증류와 하드 증류, 온폴리시와 오프폴리시 증류를 비교하고, 교사 답은 DeepSeek R1로 만든다고 적는다.

## 확인하기

글이 말하는 4편과 6편의 핵심을 외부 패키지 없이 작은 장난감으로 확인할 수 있다.
첫째, 한 번에 맞힐 확률이 낮아도 다수결 표본이 늘면 정확도가 오른다.
둘째, 그룹의 상대 보상은 그룹 평균을 기준으로 정답은 양수, 오답은 음수가 된다.
이 코드는 실제 Qwen3나 검증기가 아니라, 개념의 산수만 보여 주는 모의 실험이다.

```python
import math
import random
from collections import Counter

random.seed(0)


def sample_answer(p_correct, n_wrong=5):
    # 한 번 샘플링: 정답은 p_correct, 오답은 n_wrong개에 고르게 흩어진다
    if random.random() < p_correct:
        return "정답"
    return f"오답{random.randrange(n_wrong)}"


def majority(answers):
    # self-consistency: 최종 답의 다수결 (동률이면 먼저 나온 답)
    return Counter(answers).most_common(1)[0][0]


def accuracy(p, n, trials=20000, n_wrong=5):
    hit = sum(majority([sample_answer(p, n_wrong) for _ in range(n)]) == "정답"
              for _ in range(trials))
    return hit / trials


print("샘플 수별 다수결 정확도 (한 번에 맞힐 확률 p = 0.4)")
for n in (1, 3, 5, 11, 21):
    print(f"  n={n:>2}: {accuracy(0.4, n):.3f}")

print("오답이 한 가지로 몰리면 (n_wrong = 1)")
for n in (1, 5, 21):
    print(f"  n={n:>2}: {accuracy(0.4, n, n_wrong=1):.3f}")


def group_advantages(rewards):
    # 그룹 안의 상대 보상: 평균을 뺀다 (표준편차로 나누는 변형도 흔하다)
    mean = sum(rewards) / len(rewards)
    return [r - mean for r in rewards]


rewards = [1, 0, 0, 1, 0, 0, 0, 1]      # 검증기가 채점한 8개 응답
adv = group_advantages(rewards)
print("보상:", rewards)
print("이점:", [round(a, 3) for a in adv])
print("이점 합:", round(sum(adv), 10))
print("모두 정답인 그룹의 이점:", group_advantages([1, 1, 1, 1]))
```

실제로 실행한 출력은 다음과 같다.

```text
샘플 수별 다수결 정확도 (한 번에 맞힐 확률 p = 0.4)
  n= 1: 0.397
  n= 3: 0.466
  n= 5: 0.578
  n=11: 0.754
  n=21: 0.902
오답이 한 가지로 몰리면 (n_wrong = 1)
  n= 1: 0.393
  n= 5: 0.318
  n=21: 0.176
보상: [1, 0, 0, 1, 0, 0, 0, 1]
이점: [0.625, -0.375, -0.375, 0.625, -0.375, -0.375, -0.375, 0.625]
이점 합: 0.0
모두 정답인 그룹의 이점: [0.0, 0.0, 0.0, 0.0]
```

읽는 법은 세 가지다.
오답이 여러 갈래로 흩어지면 다수결이 정답을 밀어 올려 n=21에서 0.902까지 오른다.
오답이 한 갈래로 몰리면 같은 다수결이 거꾸로 작동해 n=21에서 0.176으로 떨어진다.
그룹의 이점은 합이 0이고, 그룹 전체가 맞으면 모든 이점이 0이라서 그 그룹에서는 배울 신호가 없다.

이 실험은 글이 설명한 개념의 산수를 확인할 뿐이다.
실제 GRPO가 표준편차로 나누는지, 어떤 형태의 클리핑을 쓰는지는 책과 영상을 열어 확인하지 않았다.

## 트레이드오프

### 다수결은 추론 비용을 정확도와 맞바꾼다

4편에서 저자는 후보를 늘릴수록 정확도와 연산량이 함께 오르는 맞교환을 직접 잰다고 적는다.
위의 모의 실험은 그 구조를 단순하게 보여 준다.
n을 5에서 21로 늘리면 연산은 네 배 이상 들고, 정확도는 0.578에서 0.902로 오른다.
다만 오른다는 보장이 아니라 조건부다.
오답이 한곳에 몰리는 문제에서는 표본을 늘릴수록 틀린 답이 더 단단해진다.

### 평가 도구를 보상으로 쓰면 도구의 허점이 학습의 허점이 된다

3편의 검증기는 평가에도, 6편 이후의 보상에도 쓰인다.
평가에서는 검증기가 틀려도 숫자가 조금 틀어질 뿐이다.
보상으로 쓰이면 모델이 검증기의 허점을 학습할 수 있다.
7편이 KL 항을 다루면서 보상 해킹을 논의하고, 형식 보상을 정답 여부에 조건부로 건다고 한 것은 이 문제를 의식한 구성으로 읽힌다.
다만 이 해석은 영상 소개 글에서 읽은 것이고, 해당 대목의 논의 내용을 확인하지는 못했다.

### 재현할 수 있는 규모와 현실의 규모 사이에는 간격이 있다

글은 0.6B 모델이면 일부 실습이 CPU에서 되고 학습은 GPU가 훨씬 실용적이라고 적는다.
이 선택은 학습 효과와 재현 가능성을 얻는 대신, 프런티어 모델과 같은 현상이 작은 모델에서도 나타나는지를 보장하지 못한다.
글의 Substack 댓글란에는 작은 모델이 일반 노트북에서 실제 추론 이득을 보일 수 있느냐는 독자 질문이 있었고, 이 노트는 그 답을 확인하지 못했다.

## 함정

### 이 글의 추론 모델 정의는 하나의 정의이다

HN의 thrw045는 글의 정의, 곧 추론 모델은 일반 LLM에 RLVR 후처리와 선택적 추론 시점 확장을 더한 것이라는 문장에 의문을 제기했다.
OpenAI의 o1이 나왔을 때 핵심 특징은 여러 경로를 시도해 가장 좋은 것을 고르는 것이었고, RLVR은 그 뒤에 더해졌다는 것이 아니냐는 질문이다.[^thrw045]
글에는 이 질문에 대한 답이 없고, 이 스레드에도 답글이 달리지 않았다.
정의가 어떻든 강좌의 구성은 추론 시점 확장(4, 5편)과 강화학습(6, 7편)을 둘 다 다루므로 실습에는 영향이 없다.
다만 이 용어를 남에게 설명할 때는 글의 정의가 저자의 설명 틀이라는 점을 알고 쓰는 편이 안전하다.

### “처음부터”는 사전학습까지를 뜻하지 않는다

HN의 hypfer는 진짜로 자기 모델을 만들 사람에게 영상 강의는 부족하고, 아니라면 이 형식이 최선인지 모르겠으며, 개인 브랜드의 수익화에 가깝다고 적었다.[^hypfer]
이에 danielmarkbruce는 회사에서 모델을 사후학습하는 사람으로서 저자의 LLM 책에서 다른 어떤 자료보다 많이 배웠다고 답했다.[^danielmarkbruce]
이 논쟁의 한 축은 “from scratch”라는 표현이 무엇을 약속하느냐다.
강좌는 사전학습된 모델에서 출발하므로, 새 모델을 처음부터 사전학습하는 방법이 아니라 평가와 사후학습을 처음부터 구현하는 강좌다.

### 이 강좌가 끝나도 곧바로 쓸 수 있는 건 아니다

HN의 gradus_ad는 이런 만들어 보기 안내서가 10년 전의 CPU 직접 만들기 안내서와 같아서 흥미롭지만 실용성이 없다고 적었다.[^gradus_ad]
danielmarkbruce는 오픈소스 모델을 가져다 계속 학습시킬 수 있으니 CPU와는 다르다고 반박했다.[^danielmarkbruce-cpu]
같은 스레드에서 kadoban은 이 강좌로 얻는 실용적인 일로 작거나 중간 크기의 모델을 자기 데이터로 사후학습하는 것을 들었고, LoRA를 찾아보라고 했다.[^kadoban]
fantispug도 큰 기초 모델을 처음부터 학습할 때만 연산이 문제이고, 4B 미만 모델의 미세 조정은 흔한 GPU로 된다고 적었다.[^fantispug]
댓글들은 강좌 자체보다 그 다음 단계의 경로를 가리킨다.
이 노트가 확인한 것은 댓글의 주장이고, 각 경로의 난이도나 비용은 확인하지 못했다.

### 작은 규모의 학습은 목표가 다르다

libraryofbabel은 처음부터 만드는 튜토리얼의 목적은 쓸 만한 LLM을 학습하는 능력이 아니라, 스택의 한 단계 아래를 직접 만들어 보며 위층의 세부를 이해하는 것이라고 적었다.[^libraryofbabel]
작성자는 RLVR을 예로 들었다.
2025년과 2026년에 LLM이 프로그래밍과 수학을 잘하게 된 훈련 기법이어서, 이 강좌에서 실제로 수학 문제용 RL 학습을 해 보면 LLM 능력에 대한 논의의 근거가 생긴다는 주장이다.
이 평가는 댓글 작성자의 것이고, RLVR이 그 개선의 원인이라는 사실은 이 노트가 확인하지 못했다.

miki123211은 ML이 CS보다 생물학이나 물리학, 법에 가깝다고 주장하며, 저렴한 노트북과 의지만으로는 ML을 배울 수 없다고 적었다.[^miki123211]
같은 스레드의 potsandpans는 주장만 있고 이유가 없으며 끝의 비유가 이상하다고 되물었다.[^potsandpans]
이 강좌는 CPU와 노트북에서 시작하도록 설계되었다고 글이 밝히므로, 이 주장과는 겨냥하는 목표가 다르다.
“너무 작아서 현실과 다르다”는 반론과 “이해가 목적이다”라는 답은 같은 질문에 대한 답이 아니라는 점을 구분해서 읽어야 한다.

## 체크리스트

- 영상 1편을 보기 전에 Python과 PyTorch로 텐서 연산을 할 수 있는가.
- 책의 해당 장을 먼저 읽고, 영상과 코드를 같이 따라간 뒤 연습문제를 풀 계획인가.
- 학습 중심 실습(6편 이후)을 돌릴 GPU 또는 원격 GPU 환경이 있는가.
- 3편의 검증기를 평가용과 보상용으로 두 번 쓴다는 점을 이해하고 있는가.
- 4편의 다수결이 오답이 한곳에 몰리는 문제에서는 실패할 수 있음을 알고 있는가.
- 이 강좌가 신규 사전학습이 아니라 평가와 사후학습을 구현하는 강좌임을 알고 시작하는가.
- 글의 영상 소개와 실제 영상 내용이 같은지 직접 확인했는가.

## 기억할 원칙

### 평가기는 보상기가 될 수 있고, 그때 허점이 학습된다

이 강좌의 줄기는 검증기 하나를 평가와 강화학습에 함께 쓰는 것이다.
측정 도구를 학습 신호로 쓰는 순간, 도구가 틀리는 방식을 모델이 배운다.
평가의 정확도와 학습의 보상은 같은 도구여도 요구 수준이 다르다.

### 표본을 늘리는 것과 가중치를 바꾸는 것은 다른 투자다

4, 5편의 추론 시점 확장은 가중치를 바꾸지 않고 요청마다 연산을 더 쓴다.
6편 이후는 연산을 학습에 한 번 쓰고 가중치에 남긴다.
질문마다 비용을 내느냐, 한 번에 내느냐가 두 갈래의 본질적인 차이이고, 어느 쪽이 맞는지는 요청량과 문제의 종류에 달려 있다.
