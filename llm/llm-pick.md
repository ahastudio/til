# AI 뭐쓰지?는 요금제와 작업을 고르면 가성비 기준 모델 조합을 계산해 주는 개인 프로젝트다

<https://llm-pick.pages.dev/>

Show GN: [AI 뭐쓰지?](https://news.hada.io/topic?id=36447)

## 소개

AI 뭐쓰지?는 kazikai가 만든 정적 웹사이트다.
만든이는 페이지 아래에 본인이 쓰려고 만들었고 비상업 개인 프로젝트라고 적는다.
사이트는 하려는 작업과 쓰는 서비스·요금제를 고르면
어떤 모델을 어떤 조합과 추론 강도(reasoning effort)로 쓰면 좋은지
가성비, 나 돈많아!!, 제일 싸게의 세 가지로 알려 준다고 소개한다.

빌드 과정이 없고, 브라우저가 `data/models.json`과 `data/status.json`을 읽어
화면에서 계산하는 구조다.
앱 코드의 첫 주석도 이 데이터 파일을 수집기가 만든 산출물이라고 적는다.
이 문서가 읽은 시점(2026-11-03)에 `status.json`은 2026-11-02 21:42 UTC에
갱신되었고,
모델 33개와 이전 모델(legacy) 21개를 담고 있었다.

## 사용 방법

사용자는 세 가지를 고른다.
첫째, 구독이냐 종량제냐이다.
월정액이나 포함 사용량이 있는 앱, Copilot, Cursor, Antigravity는 구독으로,
API 직접 호출과 Bedrock은 종량제로 분류한다.
구독이라도 초과분이나 외부 모델은 따로 과금될 수 있다고 안내한다.

둘째, 작업이다.
앱 코드에 정의된 작업은 일반 질문, 개발 업무(기존 코드), 코드 리뷰, 디버깅,
새로 만들기, 에이전트 실행 모델, 분석·기획, 문서·보고서, SQL·데이터, 대량 처리의
열 가지이다.
작업마다 질문 1개, 작업 1건, PR 1건처럼 기준 단위가 정해져 있다.

셋째, 서비스와 요금제이다.
앱 코드가 지원하는 도구는 API·Bedrock, GitHub Copilot, Cursor, Claude, ChatGPT,
Gemini 앱,
Antigravity이다.
같은 서비스 안에서 개인과 조직 요금제를 고르고, 무료 플랜도 비교할 수
있다고 한다.

결과의 세 가지 추천은 사이트가 이렇게 정의한다.

| 추천        | 정의                                                   |
| ----------- | ------------------------------------------------------ |
| 가성비      | 1등 점수에서 10점 넘게 안 떨어지는 조합 중 제일 싼 것  |
| 나 돈많아!! | 계산한 점수가 가장 높은 조합                           |
| 제일 싸게   | 1등에서 20점 안쪽이고 너무 약한 모델을 뺀 제일 싼 조합 |

기본 추천은 가성비이고, 나머지 둘은 비교로 같이 보여 준다.
단계마다 모델과 강도를 바꿔 비용과 점수를 나란히 볼 수 있고,
서비스·요금제별 비교표에는 한 요금제의 세 추천이 한 표에 나온다.

## 추천 계산 방식

사이트가 밝힌 계산은 세 가지 재료로 이루어진다.
점수는 BenchLM 리더보드의 코딩, 에이전트, 추론, 지식 점수를 작업별 비중으로
섞는다.
토큰 사용량과 강도별 품질은 Artificial Analysis의 실측을 쓴다.
같은 일에 모델마다 쓰는 토큰이 최대 수십 배까지 다르므로
단가만 보면 틀린다는 것이 사이트의 설명이다.
비용은 API 가격표와 GitHub Copilot 가격표(플랜 포함 크레딧까지)에서 계산한다.

쓸 수 있는 모델, 강도, 조합(단독, 설계에서 구현, 초안에서 검증 등)을 전부 계산해
위 기준에 따라 세 개를 고른다고 한다.

앱 코드를 보면 작업마다 기본 토큰량이 “Opus 5.5 · 높음”이 쓸 양이라는 가정으로
정해져 있고,
작업마다 강도를 낮췄을 때 품질이 깎이는 정도도 가정값이다.
예를 들어 개발 업무의 입력은 360K 토큰, 출력은 48K 토큰으로 놓여 있다.

## 데이터 출처와 갱신

점수는 BenchLM.ai의 데이터(CC BY-NC 4.0), 토큰 사용량과 강도별 지능은 Artificial
Analysis,
가격은 LiteLLM, OpenRouter, GitHub Docs에서 가져온다고 적는다.
12시간마다 리더보드, 가격, 토큰 실측과 각 도구의 공식 자료를 확인한다고 한다.
Cursor, Antigravity, Copilot은 읽을 수 있는 공식 표의 지원 모델 등을 갱신하고,
앱 구독 문서는 변경을 감지해 확인 필요로 표시한다.
표를 확인하지 못하면 기존 값을 유지하고 마지막 확인 상태를 서비스 아래에
보여 준다.

이 문서가 읽은 `status.json`에서 ChatGPT 구독 문서는 “공식 문서 변경 감지 —
요금제 설정 확인 필요”로
표시되어 있었다.
사이트가 자동으로 못 맞춘 항목은 화면의 “확인 필요”에 따로 모이고,
이름 불일치나 구독·Copilot 플랜은 설정 파일에 한 줄을 추가해 고친다고 안내한다.

## 분석

### 이 사이트의 핵심은 단가가 아니라 작업당 비용을 비교하는 것이다

모델 가격표는 100만 토큰당 단가를 보여 주지만,
같은 일을 끝내는 데 쓰는 토큰은 모델마다 다르다.
사이트는 작업 1건에 드는 토큰량을 가정하고 거기에 모델별 사용량 차이를 반영해
작업 1건당 예상 비용으로 바꿔 보여 준다.
이 변환이 사이트가 이름 그대로 답하려는 질문,
곧 내 상황에서 어떤 모델이 효율적이냐에 필요한 단계이다.

### 세 추천은 점수 허용 폭의 차이다

가성비와 제일 싸게는 둘 다 가장 싼 조합을 고르되,
1등 점수에서 허용하는 하락이 10점이냐 20점이냐가 다르다.
나 돈많아!!는 허용 폭이 0이다.
세 추천은 결국 한 점수 축 위에서 허용 폭을 달리한 것이며,
사용자가 고르는 것은 품질을 얼마나 양보할지이다.
이 해석은 사이트의 정의를 풀어 쓴 것이다.

## 비평

### 작업별 토큰량과 강도 민감도는 만든이의 가정이다

사이트도 작업당 토큰량, 다시 시키는 비용, 설계를 강한 모델이 맡는 효과가
가정이 들어간 추정치이고 실제는 쓰는 방식에 달라진다고 밝힌다.
가정은 추천 카드의 “계산 가정 보기”에 적혀 있다고 한다.
이 문서는 그 화면은 열어 보지 않았고 앱 코드의 값만 확인했다.
따라서 같은 모델 순위가 나와도 내 작업이 가정과 다르면 비용 순서가 바뀔 수 있다.

### 구독의 남은 한도는 계산하지 않는다

사이트가 직접 적은 한계다.
구독은 실제 잔여 한도를 계산하지 않고,
API 환산 비용은 같은 작업을 API 표준 요금으로 돌린다고 가정한 참고 금액이며
실제 구독료, 한도, 추가 결제액과 다르다.
구독자가 궁금한 것은 이번 달 포함량 안에서 어떤 모델이 낫냐인데,
이 값은 사이트가 아직 답하지 못하는 부분이다.
Copilot만 플랜 포함 크레딧으로 한 달에 몇 건이 되는지 표시한다고 한다.

### 점수는 공개 벤치마크이고 허용 폭의 근거는 적혀 있지 않다

점수는 BenchLM의 공개 점수이며 사내 코드나 특정 도구 안의 체감과 다를 수 있다고
사이트가 인정한다.
10점과 20점이라는 허용 폭이 왜 그 값인지, 점수 1점이 비용이나 품질로 무엇인지는
이 문서가 읽은 화면과 코드에 설명이 없다.
작업별 카테고리 비중(예: 코드 리뷰는 코딩 0.7, 추론 0.3)도 같은 상태이다.

### 한 사람이 운영하고 일부 요금제는 수동 확인이 필요하다

만든이가 개인이고 구독 문서는 변경 감지만 하며 세부 모델 버전과 요금제는 수동
확인이라고 한다.
이 문서가 읽은 시점에도 ChatGPT 항목이 확인 필요 상태였다.
자동 갱신이 12시간 주기이므로 요금 변경이 반영되기 전에 본 값은 낡았을 수 있다.

## 인사이트

### 결과를 그대로 믿기보다 가정 두 개를 자기 값으로 바꿔 보는 것이 쓸모 있다

이 도구에서 가장 자기 상황과 어긋나기 쉬운 값은 작업당 토큰량과 허용 점수
폭이다.
현재 쓰는 도구에서 작업 1건에 실제로 쓰는 토큰을 한두 번 재 보고,
사이트의 가정(개발 업무 입력 360K, 출력 48K)과 크게 다르면 추천 비용도 그만큼
달라진다고 봐야 한다.
이것은 이 문서의 사용 제안이다.

### 이 도구의 가치는 모델 이름보다 토큰 사용량 차이를 눈에 보이게 하는 것이다

사이트가 모델마다 같은 일에 쓰는 토큰이 최대 수십 배 다르다고 한 점은
가격표만 비교하던 독자에게 비용 판단의 기준을 하나 더 준다.
그 수치의 근거인 Artificial Analysis 자료는 이 문서가 열어 보지 않았으므로,
수십 배라는 말은 사이트의 서술로만 전한다.

### 이 사이트의 추천을 확인하는 방법

같은 작업을 추천된 조합과 지금 쓰는 조합으로 각각 몇 건 돌려
작업당 실제 비용과 수정 횟수를 비교한다.
추천이 더 싸지만 수정 횟수가 크게 늘어난다면 점수 허용 폭이 내 작업에는 너무
넓은 것이다.
